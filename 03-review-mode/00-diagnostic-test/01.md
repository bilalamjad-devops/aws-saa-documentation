A solution is required to route requests to the hosted services based on URL paths.

Which option will meet this requirement with the LEAST amount of setup?

- Provision a Network Load Balancer (NLB) using the AWS Load Balancer Controller.
- Provision a NGINX Ingress controller.
- `Provision an Application Load Balancer (ALB) using the AWS Load Balancer Controller.`
- Use an AWS Lambda function to proxy requests to EKS.

## Q1 — EKS + URL Path Routing

### The key requirement

The important phrase is:

> **“route requests to the hosted services based on URL paths”**

For example:

```text
example.com/orders   → Orders service
example.com/users    → Users service
example.com/payments → Payments service
```

This is **Layer 7 / application-level routing**.

### Which AWS load balancer does that?

| Load Balancer | Layer | Can route based on URL path? |
| ------------- | ----- | ---------------------------- |
| **ALB**       | L7    | ✅ Yes                        |
| **NLB**       | L4    | ❌ No                         |
| NGINX Ingress | L7    | ✅ Yes                        |
| Lambda        | —     | ❌ Not appropriate            |

So we immediately know **ALB** is the relevant AWS load balancer.

Then the question adds:

> **“with the LEAST amount of setup”**

For EKS, the **AWS Load Balancer Controller** can provision/manage an ALB from Kubernetes Ingress resources.

Therefore:

**✅ Provision an Application Load Balancer (ALB) using the AWS Load Balancer Controller.**

---

### Why NLB is wrong

NLB works primarily at **Layer 4**:

```text
IP + Port
```

For example:

```text
10.0.1.20:443 → target
10.0.1.30:443 → target
```

It doesn't understand application-level paths like:

```text
/orders
/users
/payments
```

That's ALB territory.

### Why NGINX Ingress is not the best answer

NGINX Ingress **can absolutely perform path-based routing**.

The issue is **least amount of setup**.

If AWS Load Balancer Controller can directly create/manage an AWS ALB for your EKS Ingress, adding and managing NGINX introduces another component.

So:

**NGINX = technically works, but more setup.**

### Why Lambda is wrong

Lambda isn't a natural replacement for an EKS ingress/load balancer.

You would be building additional proxy logic unnecessarily.

---

## 🧠 Exam memory

Remember this simple rule:

```text
ALB → Layer 7 → HTTP/HTTPS → URL/path/host routing
NLB → Layer 4 → TCP/UDP/TLS → IP/port routing
```

And for EKS:

```text
Kubernetes Ingress
       ↓
AWS Load Balancer Controller
       ↓
      ALB
       ↓
EKS Services/Pods
```

### One important distinction

Don't memorize:

> "AWS Load Balancer Controller = ALB only"

It can work with both **ALB and NLB**.

Instead remember:

**Ingress/path-based HTTP routing → ALB**

**Service/network-level L4 routing → NLB**

---

**Correct: Provision an Application Load Balancer (ALB) using the AWS Load Balancer Controller. ✅**
