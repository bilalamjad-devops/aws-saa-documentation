16. Question

Category: CSAA – Design High-Performing Architectures

A company is storing its financial reports and regulatory documents in an Amazon S3 bucket. To comply with the IT audit, they tasked their Solutions Architect to track all new objects added to the bucket as well as the removed ones. It should also track whether a versioned object is permanently deleted. The Architect must configure Amazon S3 to publish notifications for these events to a queue for post-processing and to an Amazon SNS topic that will notify the Operations team.

Which of the following is the MOST suitable solution that the Architect should implement?


- Create a new Amazon SNS topic and Amazon MQ. Add an S3 event notification configuration on the bucket to publish s3:ObjectAdded:* and s3:ObjectRemoved:* event types to SQS and SNS.
- Create a new Amazon SNS topic and Amazon MQ. Add an S3 event notification configuration on the bucket to publish s3:ObjectCreated:* and ObjectRemoved:DeleteMarkerCreated event types to SQS and SNS.
- `Create a new Amazon SNS topic and Amazon SQS queue. Add an S3 event notification configuration on the bucket to publish s3:ObjectCreated:* and s3:ObjectRemoved:Delete event types to SQS and SNS.`
- Create a new Amazon SNS topic and Amazon SQS queue. Add an S3 event notification configuration on the bucket to publish s3:ObjectCreated:* and ObjectRemoved:DeleteMarkerCreated event types to SQS and SNS.

Is question mein **Amazon S3 Event Notifications**, **SQS vs Amazon MQ**, aur **S3 Object Versioning Event Types** ka concept test ho raha hai.

---

## 1. What Is Being Tested Here? (Core Exam Concepts)

Is question mein AWS 2 core mechanisms test kar raha hai:

1. **Target Messaging Services (SQS vs Amazon MQ):**
* Amazon S3 Event Notifications natively **Amazon SQS**, **Amazon SNS**, aur **AWS Lambda** ko event publish kar sakti hain.
* **Amazon MQ** ek managed message broker service hai (ActiveMQ/RabbitMQ ke liye), lekin S3 Event Notifications natively Amazon MQ par direct publish **nahi** kar sakti. Is ke liye Amazon SQS standard native target hai.


2. **S3 Object Removed Event Types (`Delete` vs `DeleteMarkerCreated`):**
* **`s3:ObjectRemoved:Delete`:** Jab kisi non-versioned object ko delete kiya jaye **ya versioned bucket mein kisi specific version ID ko PERMANENTLY delete kiya jaye**, toh yeh event fire hota hai.
* **`s3:ObjectRemoved:DeleteMarkerCreated`:** Jab bina version ID specify kiye delete request bheji jati hai, toh S3 object ko permanent delete karne ke bajaye ek *Delete Marker* bana deta hai. Requirement mein specific hai: **"track whether a versioned object is permanently deleted"**, is liye `s3:ObjectRemoved:Delete` event type zaroori hai.



---

## 2. Correct Option Explanation

#### ✅ **Create a new Amazon SNS topic and Amazon SQS queue. Add an S3 event notification configuration on the bucket to publish s3:ObjectCreated:* and s3:ObjectRemoved:Delete event types to SQS and SNS.**

* **Why it works:**
1. **SQS + SNS Integration:** S3 natively SNS topic (for Ops team alerts) aur SQS queue (for post-processing) par directly messages push kar sakta hai.
2. **Correct Event Selection:** `s3:ObjectCreated:*` naye objects add hone par triggers karta hai, aur `s3:ObjectRemoved:Delete` permanent deletion events ko track karta hai.



---

## 3. Incorrect Options Breakdown (Elimination Strategy)

| Option | Why It Fails the Exam Requirement |
| --- | --- |
| **Amazon MQ + `s3:ObjectAdded:*` / `s3:ObjectRemoved:***` | **Two Technical Errors:** S3 Event Notifications direct Amazon MQ par publish nahi kar saktin. Event name `s3:ObjectCreated:*` hota hai, `s3:ObjectAdded:*` naam ki koi event configuration exist nahi karti. |
| **Amazon MQ + `DeleteMarkerCreated**` | Amazon MQ invalid target hai. DeleteMarkerCreated permanent deletion ko nahi balki soft deletion (delete marker) ko indicate karta hai. |
| **Amazon SQS + `DeleteMarkerCreated**` | **`DeleteMarkerCreated`** event type tab trigger hota hai jab simple DELETE command se soft delete marker create ho. Question specific permanent deletion ki baat kar raha hai, jis ke liye `s3:ObjectRemoved:Delete` sahi event type hai. |

---

## 4. Exam Decision Matrix (S3 Event Notifications Cheat Sheet)

* **S3 Event Native Destinations:** $\rightarrow$ **Amazon SNS, Amazon SQS, AWS Lambda**
* **Track Permanent Object Deletion:** $\rightarrow$ **`s3:ObjectRemoved:Delete`**
* **Track Soft Deletion (Delete Marker):** $\rightarrow$ **`s3:ObjectRemoved:DeleteMarkerCreated`**
* **Track All Object Creations:** $\rightarrow$ **`s3:ObjectCreated:*`**
