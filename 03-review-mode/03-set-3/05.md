5. Question

Category: CSAA – Design High-Performing Architectures

A document sharing website is using AWS as its cloud infrastructure. Free users can upload a total of 5 GB of data, while premium users can upload as much as 5 TB. The application uploads the user files, which can have a max file size of 1 TB, to an Amazon S3 Bucket. The developers initially tried using an S3 presigned URL for each upload, but that alone doesn’t solve the challenges of transferring such large files.

In this scenario, what is the best way for the application to upload the large files to S3?

- Use S3 Transfer Acceleration
- `Use Multipart Upload`
- Use AWS DataSync
- Use a single PUT request to upload the large file

### 🎯 What is being tested?

**Uploading very large files to Amazon S3 efficiently.**

### ✅ Correct answer

**Use S3 Multipart Upload**

### 🔑 Key concept

**Multipart Upload** breaks a huge file into smaller parts and uploads those parts **independently and in parallel**.

For example:

**1 TB file → Part 1 + Part 2 + Part 3 + ... → S3 → assemble into one object**

Benefits:

* Better performance for large files
* Parts can be uploaded in parallel
* Failed parts can be retried without restarting the entire upload
* Designed specifically for **large objects**

### ❌ Why others are wrong

* **S3 Transfer Acceleration** ❌ → speeds up transfers over long geographic distances using CloudFront edge locations, but doesn't replace Multipart Upload for handling huge files.
* **AWS DataSync** ❌ → mainly for transferring data between **on-premises storage and AWS**, not end-user website uploads.
* **Single PUT request** ❌ → inefficient for a 1 TB upload and doesn't provide the resilience of multipart upload.

### 🔥 Exam shortcut

> **Very large file → S3 Multipart Upload**

**Multipart = split → upload parts → retry failed parts → combine**

Also remember: **Presigned URL + Multipart Upload** can be used together. A presigned URL provides secure temporary upload access; Multipart Upload handles the **large-file transfer**.
