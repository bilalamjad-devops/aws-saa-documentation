26. Question

Category: CSAA – Design Cost-Optimized Architectures

A solutions architect is managing an application that runs on a Windows EC2 instance with an attached Amazon FSx for Windows File Server. To save cost, management has decided to stop the instance during off-hours and restart it only when needed. It has been observed that the application takes several minutes to become fully operational which impacts productivity.

How can the solutions architect speed up the instance’s loading time without driving the cost up?

- Disable the Instance Metadata Service to reduce the things that need to be loaded at startup.
- Migrate the application to a Linux-based EC2 instance.
- `Migrate the application to an EC2 instance with hibernation enabled.`
- Enable the hibernation mode on the EC2 instance.

Yes — your understanding is **correct**. There is an important distinction here.

### 🔑 What is EC2 Hibernation?

Normally when you stop an EC2 instance:

**RAM is cleared** ❌

So when you start it again:

`Start → OS boots → application starts → ready`

This can take several minutes.

With **hibernation**:

**RAM contents are saved to the EBS root volume** before the instance stops.

Then:

`Start → RAM restored → application continues`

So the application can become operational **much faster**.

### Your question: Can we enable hibernation on an existing EC2?

**No.** ❌

You **cannot simply turn on hibernation for an already-created EC2 instance**.

You need to **launch the instance with hibernation enabled** (assuming the instance type/OS/root volume supports it).

So:

> **Existing instance → cannot enable hibernation afterward**

> **Launch new instance → enable hibernation → use it**

### ✅ Correct answer

**Migrate the application to an EC2 instance with hibernation enabled.**

### 🔥 Exam shortcut

**Stop/start takes long because OS + application must reload → Hibernation saves RAM → faster resume.**

And yes, **hibernation is different from normal Stop** because the instance's memory state is preserved.
