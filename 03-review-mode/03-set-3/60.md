60. Question

Category: CSAA – Design Cost-Optimized Architectures

A company has established a dedicated network connection from its on-premises data center to AWS Cloud using AWS Direct Connect (DX). The core network services, such as the Domain Name System (DNS) service and Active Directory services, are all hosted on-premises. The company has new AWS accounts that will also require consistent and dedicated access to these network services.

Which of the following can satisfy this requirement with the LEAST amount of operational overhead and in a cost-effective manner?

- Set up another Direct Connect connection for each and every new AWS account that will be added.
- Set up a new Direct Connect gateway and integrate it with the existing Direct Connect connection. Configure a VPC peering connection between AWS accounts and associate it with Direct Connect gateway.
- Create a new AWS VPN CloudHub. Set up a Virtual Private Network (VPN) connection for additional AWS accounts.
- `Create a new Direct Connect gateway and integrate it with the existing Direct Connect connection. Set up a Transit Gateway between AWS accounts and associate it with the Direct Connect gateway.`



### 🎯 What is being tested?

**Connecting multiple AWS accounts to one on-premises Direct Connect.**

### ✅ Correct answer

**Create a Direct Connect Gateway + use Transit Gateway, then associate the Transit Gateway with the Direct Connect Gateway.**

### 🔑 Key concept

Think:

**On-premises → Direct Connect → DX Gateway → Transit Gateway → Multiple AWS VPCs/accounts**

* **Direct Connect Gateway (DXGW)** → lets you connect multiple VPCs across accounts/Regions through a DX connection.
* **Transit Gateway (TGW)** → central hub for connecting multiple VPCs/accounts.
* Avoids creating a new DX connection for every account → **less operational overhead + cost-effective**.

### ❌ Why others?

* **New DX per account** → expensive and operationally heavy.
* **VPC Peering** → doesn't scale well as the number of accounts/VPCs grows.
* **VPN CloudHub** → VPN-based architecture, unnecessary when DX already exists.

### 🔥 Exam shortcut

**Multiple AWS accounts/VPCs + existing Direct Connect → DX Gateway + Transit Gateway.**


---

Is question mein **Hybrid Cloud Networking (Direct Connect + Multi-Account VPC Connectivity)** aur **Least Operational Overhead** ka core concept test ho raha hai.

Aayein requirements ko Roman Urdu mein simple steps mein analyze karte hain:

---

## 1. Requirement Breakdown

1. **Existing Architecture:** On-premises data center se AWS tak **AWS Direct Connect (DX)** ka dedicated link pehle se majood hai.
2. **Current On-Prem Services:** DNS aur Active Directory on-premises hosted hain.
3. **New Challenge:** Multiple new AWS accounts (VPCs) ko inhi on-prem core services tak dedicated aur consistent access chahiye.
4. **Goal:** Solution **cost-effective** honi chahiye aur **LEAST operational overhead** (kam se kam mehnat/management) ke sath implement honi chahiye.

---

## 2. Technical Solution Architecture

```
[ On-Prem Data Center ] (DNS / Active Directory)
          │
          ▼  (AWS Direct Connect Link)
 ┌─────────────────────────────────┐
 │   Direct Connect Gateway (DXGW) │
 └────────────────┬────────────────┘
                  │
                  ▼
 ┌─────────────────────────────────┐
 │   AWS Transit Gateway (TGW)     │  ◄── Centralized Hub for Multi-Account / Multi-VPC
 └─┬──────────────┬──────────────┬─┘
   │              │              │
   ▼              ▼              ▼
[ Account A ]  [ Account B ]  [ Account C ]
  (VPC A)        (VPC B)        (VPC C)

```

1. **Direct Connect Gateway (DXGW):** Direct Connect connection ko AWS side par terminate/integrate karta hai taake cross-region ya multi-VPC connectivity mil sake.
2. **AWS Transit Gateway (TGW):** Centralized cloud router ki tarah kaam karta hai. Yeh hazaron VPCs (alag alag AWS accounts ke) ko aapas mein aur Direct Connect ke sath ek hi hub se connect kar deta hai. Is se full-mesh VPC peering jaisi complex routing aur overhead khatam ho jati hai.

---

## 3. Correct Option Explanation

#### ✅ **Create a new Direct Connect gateway and integrate it with the existing Direct Connect connection. Set up a Transit Gateway between AWS accounts and associate it with the Direct Connect gateway.**

* **Why it works:** Existing Direct Connect link ko Direct Connect Gateway se associate kiya jata hai, aur phir AWS Transit Gateway ke zariye tamam new AWS accounts/VPCs ko centralized tareeqe se connect kar diya jata hai. Yeh least operational overhead ke sath scaled multi-account hybrid routing provide karta hai.

---

## 4. Incorrect Options Breakdown (Elimination Strategy)

| Option | Why It Fails the Exam Requirement |
| --- | --- |
| **Set up another Direct Connect connection for each account...** | Extremly expensive aur time-consuming hai. Multiple physical Direct Connect lines lay karna cost-effective bilkul nahi hai. |
| **...Configure a VPC peering connection... associate with DX gateway** | **Technical Impossibility:** Direct Connect Gateway transitive routing support nahi karta (VPC A $\rightarrow$ VPC B $\rightarrow$ DXGW path kaam nahi karta). VPC Peering over DXGW scales horribly for multiple accounts. |
| **Create a new AWS VPN CloudHub...** | Direct Connect ki bajaye Public Internet-based VPN connections add karta hai jo dedicated performance requirement ko meet nahi karta. |

---

## 5. Exam Decision Matrix (Hybrid Networking Cheat Sheet)

* **Connect multiple AWS accounts/VPCs to 1 Direct Connect link with LEAST overhead:** $\rightarrow$ **Direct Connect Gateway + AWS Transit Gateway**
* **Interconnect 2 VPCs directly (No transitive routing needed):** $\rightarrow$ **VPC Peering**
* **Backup connection for AWS Direct Connect over Public Internet:** $\rightarrow$ **AWS Site-to-Site VPN**
