29. Question

Category: CSAA – Design Resilient Architectures

You are automating the creation of EC2 instances in your VPC. Hence, you wrote a python script to trigger the Amazon EC2 API to request 50 EC2 instances in a single Availability Zone. However, you noticed that after 20 successful requests, subsequent requests failed.

What could be a reason for this issue and how would you resolve it?

- By default, AWS allows you to provision a maximum of 20 instances per Availability Zone. Select a different Availability Zone and retry the failed request.
- `There is a vCPU-based On-Demand Instance limit per region which is why subsequent requests failed. Just submit the limit increase form to AWS and retry the failed requests once approved.`
- By default, AWS allows you to provision a maximum of 20 instances per region. Select a different region and retry the failed request.
- There was an issue with the Amazon EC2 API. Just resend the requests and these will be provisioned successfully.

### 🎯 What is being tested?

**EC2 On-Demand vCPU limits**

### ✅ Correct answer

**There is a vCPU-based On-Demand Instance limit per Region, which is why subsequent requests failed. Just submit the limit increase form to AWS and retry the failed requests once approved.**

### 🔑 Key concept

EC2 quotas are generally based on **vCPUs**, not simply “20 instances per AZ/Region.”

Example:

* Request 50 instances
* Each instance uses several vCPUs
* You exceed the account's **On-Demand vCPU quota**
* New launches fail

### 🔥 Exam shortcut

**EC2 launch requests suddenly fail → check EC2 vCPU-based quotas.**

❌ Not a fixed 20-instance-per-AZ limit.
❌ Not a fixed 20-instance-per-Region limit.

Is question mein **AWS Service Quotas / Limits (specifically EC2 On-Demand Instance Limits)** ka concept test ho raha hai.

Aayein samajhte hain ke pehle kya hota tha aur ab AWS EC2 limits kaise kaam karti hain.

---

## 1. Core Concept: EC2 Service Quotas & Limits

AWS har Region mein accounts ke liye **Service Quotas (Limits)** apply karta hai taake resources ka missuse na ho aur unexpected charges se bacha ja sake.

* **vCPU-based Limits (Modern AWS Standard):**
AWS pehle per-instance count limit rakhta tha, par ab **vCPU-based On-Demand Instance Limits** use karta hai. Pehle standard accounts par default limit typically 20 vCPUs (ya standard instances) ki hoti thi.
* **How to Increase Limits?**
Jab aap default limit hit karte hain, toh additional requests fail ho jati hain. Is ko resolve karne ke liye aap ko **AWS Service Quotas** console se limit increase request submit karni padti hai. Once approved, aap additional instances launch kar sakte hain.

---

## 2. Correct Option Explanation

#### ✅ **There is a vCPU-based On-Demand Instance limit per region which is why subsequent requests failed. Just submit the limit increase form to AWS and retry the failed requests once approved.**

* **Why it works:**
AWS On-Demand EC2 limits Regional vCPU-based quotas par kaam karti hain. Jab script 20 instances request karti hai aur account ki default quota hit ho jati hai, toh aage ki API requests fail hone lagti hain. Standard resolution **Service Quotas / Limit Increase request** submit karna hai.

---

## 3. Incorrect Options Breakdown (Elimination Strategy)

| Option | Why It Fails the Exam Requirement |
| --- | --- |
| **Max 20 instances per AZ limit...** | EC2 limits **AZ-level par nahi, balki Region-level par** hoti hain. Different AZ select karne se limit change nahi hogi. |
| **Max 20 instances per Region... select different region** | Commercial applications ke liye doosra region select karna solution nahi hai. Recommended operational fix Service Quota limit increase request bhejni hai. |
| **Issue with EC2 API... just resend** | API issue nahi hai, yeh soft limit breach hai. Retrying without increasing limits will fail again. |

---

## 4. Exam Decision Matrix (AWS Limits Cheat Sheet)

* **EC2 Instance Launch Limit Exceeded:** $\rightarrow$ **Submit Service Quota / Limit Increase Request**
* **Scope of EC2 On-Demand Quotas:** $\rightarrow$ **Regional (vCPU-based)**
* **EC2 Reserved Instance / Spot Instance Quotas:** $\rightarrow$ **Managed separately via Service Quotas**
