57. Question

Category: CSAA – Design High-Performing Architectures

A Solutions Architect working for a startup is designing a High Performance Computing (HPC) application which is publicly accessible for their customers. The startup founders want to mitigate distributed denial-of-service (DDoS) attacks on their application.

Which of the following options are not suitable to be implemented in this scenario? (Select TWO.)

- Use AWS Shield and AWS WAF.
- Use an Application Load Balancer with Auto Scaling groups for your EC2 instances. Prevent direct Internet traffic to your Amazon RDS database by deploying it to a new private subnet.
- `Use Dedicated EC2 instances to ensure that each instance has the maximum performance possible.`
- Use an Amazon CloudFront service for distributing both static and dynamic content.
- `Add multiple Elastic Fabric Adapters (EFA) to each EC2 instance to increase the network bandwidth.`

Is question mein **DDoS Mitigation Best Practices vs HPC / Security Misconceptions** ka core concept test ho raha hai.

Notice karein ke question mein poocha gaya hai: **"Which of the following options ARE NOT SUITABLE to be implemented in this scenario?"** (Yaani hume wo **DO (2) options** select karni hain jo DDoS attack mitigation ke liye bilkul bekaar / useless hain).

Aayein options ko Roman Urdu mein simple steps mein analyze karte hain.

---

## 1. Requirements & Core Objective

1. **Workload:** High Performance Computing (HPC) web application jo Internet-facing (publicly accessible) hai.
2. **Goal:** Distributed Denial-of-Service (DDoS) attacks ko mitigate / block karna.
3. **Question Constraint:** Un do options ko pehchanna jo DDoS mitigation ke liye **NOT SUITABLE** hain.

---

## 2. Technical Evaluation of Options

### Suitable DDoS Mitigation Strategies (Eliminate these):

* **AWS Shield & AWS WAF:** Direct DDoS defense tools hain (Layer 3/4 & Layer 7 protection).
* **CloudFront + ALB + Auto Scaling:** Edge locations par attack absorb karta hai (CloudFront) aur backend capacity scale-out kar ke traffic spikes handle karta hai (ALB + ASG).
* **Database in Private Subnet:** Direct internet access block karta hai taake DB par direct DDoS attack na ho sake.

### Unsuitable Options (Select these TWO):

#### ❌ **1. Use Dedicated EC2 instances to ensure that each instance has the maximum performance possible.**

* **Why it is NOT suitable for DDoS:** Dedicated instances single-tenant hardware provide karte hain compliance/licensing ke liye. Yeh DDoS attack mitigation mein **kisi kisam ka koi security benefit nahi dete**.

#### ❌ **2. Add multiple Elastic Fabric Adapters (EFA) to each EC2 instance to increase the network bandwidth.**

* **Why it is NOT suitable for DDoS:** EFA specialized network devices hain jo HPC node-to-node inter-process communication (MPI/NCCL) ki **latency kam karne** ke liye hote hain. EFA public DDoS traffic block ya filter karne ke liye nahi hote.

---

## 3. Correct Options (Select TWO)

#### ✅ **Use Dedicated EC2 instances to ensure that each instance has the maximum performance possible.**

#### ✅ **Add multiple Elastic Fabric Adapters (EFA) to each EC2 instance to increase the network bandwidth.**

* **Reason:** Yeh dono features hardware/compute performance aur internal HPC node networking ke liye hain; in ka **DDoS attack mitigation se koi talluq nahi hai**.

---

## 4. Exam Decision Matrix (AWS DDoS Mitigation Cheat Sheet)

* **Layer 3/4 (Infrastructure) DDoS Protection:** $\rightarrow$ **AWS Shield Standard / Advanced**
* **Layer 7 (Application) DDoS & SQLi/XSS Protection:** $\rightarrow$ **AWS WAF**
* **Edge Attack Absorption & Global Caching:** $\rightarrow$ **Amazon CloudFront**
* **Inter-Node Low-Latency HPC Networking (Not for Security):** $\rightarrow$ **Elastic Fabric Adapter (EFA)**
