32. Question

Category: CSAA – Design Resilient Architectures

An aerospace engineering company recently adopted a hybrid cloud infrastructure with AWS. One of the responsibilities of the Solutions Architect is to launch an Amazon VPC with both public and private subnets for Amazon EC2 instances and database instances. The architecture must ensure each subnet is properly defined within the assigned VPC CIDR block.

Which of the following statements are true regarding VPC subnets? (Select TWO.)

- `Each newly created subnet is, by default, linked to the main route table of the VPC.`
- EC2 instances in a private subnet can communicate with the Internet only if they have an Elastic IP.
- Each subnet spans 2 Availability Zones.
- The allowed block size in VPC is between a /16 netmask (65,536 IP addresses) and /27 netmask (32 IP addresses).
- `Each subnet maps to a single Availability Zone.`

### 🎯 What is being tested?

**VPC subnet basics**

### ✅ Correct answers

**1. Each newly created subnet is, by default, linked to the main route table of the VPC.**

**2. Each subnet maps to a single Availability Zone.**

### 🔑 Key concepts

* **Main route table** → new subnets automatically use it unless you explicitly associate another route table.
* **Subnet = one AZ** → A subnet cannot span multiple AZs.

### ❌ Others

* **Private subnet + Elastic IP** → EIP doesn't make a private subnet Internet-connected. It needs a **NAT Gateway** for outbound Internet access.
* **Subnet spans 2 AZs** → ❌ One subnet = one AZ.
* **/16 to /27** → ❌ The VPC CIDR range is `/16` to `/28` (IPv4); `/28` is the smallest allowed VPC subnet size.

### 🔥 Exam shortcut

**Subnet = single AZ**
**New subnet → main route table by default**

**Span** means **“cover or extend across.”**

So:

> **A subnet cannot span multiple AZs**

means:

👉 **One subnet cannot extend across 2 or more Availability Zones.**

Example:

```text
VPC
├── Subnet A → AZ-1
├── Subnet B → AZ-2
└── Subnet C → AZ-3
```

Each subnet belongs to **one AZ only**.

## 1. Core AWS VPC Subnet Rules (Core Concepts)

1. **Subnet and AZ Mapping:**
* Ek AWS Subnet hamesha **sirf ek single Availability Zone (AZ)** ke andar hi exist kar sakta hai. Subnet kabhi bhi 2 ya us se ziyada AZs par span nahi ho sakta.


2. **Default Route Table Association:**
* Jab aap koi naya Subnet banate hain, toh AWS usay automatically VPC ki **Main Route Table** ke sath associate/link kar deta hai (jab tak aap manually custom route table na banayein).


3. **VPC CIDR Block Sizes:**
* VPC CIDR block range **`/16` (65,536 IPs)** se lekar **`/28` (16 IPs)** tak allow hoti hai (question option mein `/27` galat likha hua hai).



---

## 2. Correct Options Explanation (Select TWO)

#### ✅ **Each newly created subnet is, by default, linked to the main route table of the VPC.**

* **Why it works:** System behavior hai. Custom route table explicitly attach na karne par har naya subnet pehle se mojood Main Route Table ke sath automatically associate ho jata hai.

#### ✅ **Each subnet maps to a single Availability Zone.**

* **Why it works:** VPC level par CIDR poore region par hoti hai, lekin jab aap Subnet create karte hain, toh aap ko mandatory taur par ek **Single Availability Zone (AZ)** specify karna padta hai.

## 3. Incorrect Options Breakdown (Elimination Strategy)

| Option | Why It Fails the Exam Requirement |
| --- | --- |
| **EC2 in private subnet can communicate with Internet ONLY if Elastic IP...** | **False.** Private subnet instances ko outbound Internet access dene ke liye **NAT Gateway / NAT Instance** zaroori hota hai. Direct Elastic IP public subnet instances par hoti hai. |
| **Each subnet spans 2 Availability Zones.** | **False.** Subnets are AZ-specific. Woh 1 se ziyada AZs par spread nahi ho sakte. |
| **Allowed block size is between /16 and /27...** | **False.** AWS VPC ka allowed CIDR block range **`/16` to `/28**` hota hai (`/27` nahi). |

---

## 4. Exam Decision Matrix (VPC Subnets Cheat Sheet)

* **Subnet AZ Boundary:** $\rightarrow$ **1 Subnet = 1 Availability Zone (AZ)**
* **New Subnet Default Routing:** $\rightarrow$ **Associated with Main Route Table**
* **Allowed VPC Netmask Range:** $\rightarrow$ **`/16` (Max 65,536 IPs) to `/28` (Min 16 IPs)**
* **Private Subnet Outbound Internet:** $\rightarrow$ **NAT Gateway (in Public Subnet)**
