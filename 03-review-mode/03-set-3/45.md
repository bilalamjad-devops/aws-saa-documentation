45. Question

Category: CSAA – Design Resilient Architectures

A production MySQL database hosted on Amazon RDS is running out of disk storage. The management has consulted its solutions architect to increase the disk space without impacting the database performance.

How can the solutions architect satisfy the requirement with the LEAST operational overhead?

- Increase the allocated storage for the DB instance.
- Modify the DB instance storage type to Provisioned IOPS.
- `Modify the DB instance settings and enable storage autoscaling.`
- Change the default_storage_engine of the DB instance’s parameter group to MyISAM.

Is question mein **Amazon RDS Storage Management**, **Zero-Downtime Storage Scaling**, aur **Operational Overhead Minimization** ka concept test ho raha hai.

Aayein har requirement ko step-by-step Roman Urdu mein analyze karte hain:

---

## 1. Core Requirements Breakdown

1. **Problem:** Amazon RDS par hosted MySQL database ki disk space khatam hone wali hai.
2. **Goal 1 (Performance):** Storage space ko barhana hai bina database performance ko impact kiye.
3. **Goal 2 (Operational Overhead):** Requirements ko **LEAST operational overhead** (sab se kam manual effort aur zero downtime) ke sath poora karna hai.

---

## 2. Technical Concept: RDS Storage Auto Scaling

* **Automated & Serverless Expansion:** RDS Storage Auto Scaling enable karne par AWS database storage utilization ko continuously monitor karta hai.
* **Automatic Scaling Threshold:** Jab free available storage capacity **10% se kam** ho jati hai aur yeh condition kam se kam 5 minutes tak rehti hai, toh RDS storage ko automatically scale-up (expand) kar deta hai.
* **Zero Downtime & Zero Performance Impact:** Storage scaling online hoti hai, jis se database par na koi downtime aata hai aur na hi performance lag hoti hai.
* **Least Operational Overhead:** System administrator ya engineer ko storage thresholds set kar ke manual intervention ya periodic manual resizing karne ki zaroorat nahi padti.

---

## 3. Correct Option Explanation

#### ✅ **Modify the DB instance settings and enable storage autoscaling.**

* **Why it works:** Storage Auto Scaling enable karne se RDS disk space fulfill hone par automatically capacity increase kar deta hai. Is mein zero manual monitoring required hoti hai (Least Operational Overhead) aur DB performance uninterrupted rehti hai.

---

## 4. Incorrect Options Breakdown (Elimination Strategy)

| Option | Why It Fails the Exam Requirement |
| --- | --- |
| **Increase allocated storage for DB instance** | Manual allocation se storage toh barh jayegi, lekin is mein **Manual Operational Overhead** shamil hai (aap ko bar bar free space dekhte hue manually size barhana padega). |
| **Modify storage type to Provisioned IOPS** | Storage type change karne se I/O performance speed change hoti hai, disk volume size expand nahi hota. Operational overhead bhi zyada hota hai. |
| **Change default_storage_engine to MyISAM** | MyISAM legacy non-ACID engine hai jo crash recovery support nahi karta (InnoDB preferred hota hai). Storage capacity issue handle karne ke liye DB storage engine badalna galat hai. |

---

## 5. Exam Decision Matrix (Amazon RDS Scaling Cheat Sheet)

* **Prevent RDS Out-of-Space errors automatically (Zero Overhead):** $\rightarrow$ **Enable Storage Auto Scaling**
* **Increase Read Performance across regions:** $\rightarrow$ **RDS Read Replicas**
* **High Availability & Automatic Failover across AZs:** $\rightarrow$ **RDS Multi-AZ Deployment**

### 🎯 What is being tested?

**RDS Storage Autoscaling**

### ✅ Correct answer

**Modify the DB instance settings and enable Storage Autoscaling.**

### 🔑 Key concept

RDS **Storage Autoscaling** automatically increases allocated storage when the database is running low on disk space.

```text
Storage getting low
       ↓
RDS Storage Autoscaling
       ↓
Storage automatically increases
```

This avoids manually monitoring and modifying storage.

### ❌ Others

* **Increase allocated storage** → manual intervention.
* **Provisioned IOPS** → improves I/O performance, doesn't automatically increase storage.
* **MyISAM** → MySQL storage engine; unrelated to disk expansion.

### 🔥 Exam shortcut

**RDS running out of storage + least operational overhead → Storage Autoscaling.**
