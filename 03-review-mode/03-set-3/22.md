22. Question

Category: CSAA – Design High-Performing Architectures

A Solutions Architect needs to deploy a mobile application that collects votes for a singing competition. Millions of users from around the world will submit votes using mobile phones. These votes must be collected and stored in a highly scalable and highly available database, which will be queried for real-time ranking. The database is expected to undergo frequent schema changes throughout the voting period.

Which of the following combinations of services should the architect use to meet this requirement, with read capacity units (RCU) that scale for live rankings?

- Amazon Relational Database Service (Amazon RDS) and Amazon MQ
- Amazon DocumentDB (with MongoDB compatibility) and Amazon AppFlow
- `Amazon DynamoDB and AWS AppSync`
- Amazon Aurora and Amazon Cognito

No problem — for SAA, you don't need to deeply learn AppSync right now.

### 🔑 AWS AppSync — simple meaning

**AWS AppSync = managed API service for applications.**

It helps mobile/web applications **get and update data from backend services**, especially with **real-time data**.

Think:

**Mobile App → AppSync API → DynamoDB**

For this question:

* **DynamoDB** = database that handles millions of votes
* **AppSync** = API layer that lets the mobile app interact with the database and supports real-time updates

### 🔥 SAA exam clue

When you see:

> **Mobile/web app + real-time data + DynamoDB**

Think:

**AWS AppSync**

Don't confuse it with DynamoDB itself — **AppSync is not a database.**

### 🎯 What is being tested?

**Massive scale + frequent schema changes + real-time reads.**

### ✅ Correct answer

**Amazon DynamoDB and AWS AppSync**

* **DynamoDB** → highly scalable, highly available NoSQL database.
* **Flexible schema** → easy to handle frequent schema changes.
* **RCUs** → can scale read capacity for real-time rankings.
* **AppSync** → provides API layer for the mobile application and real-time data capabilities.

### 🔥 Exam shortcut

> **Millions of requests + NoSQL + flexible schema + scalable reads → DynamoDB**

**DynamoDB = scale + flexible schema**
**AppSync = API / real-time application data**
