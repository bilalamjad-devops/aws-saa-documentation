28. Question

Category: CSAA – Design Secure Architectures

A company hosted a web application on a Linux Amazon EC2 instance in the public subnet that uses a non-default network ACL. The instance uses a default security group and has an attached Elastic IP address. The network ACL is configured to block all inbound and outbound traffic. The Solutions Architect must allow incoming traffic on port 443 to access the application from any source.

Which combination of steps will accomplish this requirement? (Select TWO.)


- In the Network ACL, update the rule to allow both inbound and outbound TCP connection on port 443 from source 0.0.0.0/0 and to destination 0.0.0.0/0
- `In the Security Group, add a new rule to allow TCP connection on port 443 from source 0.0.0.0/0`
- In the Security Group, create a new rule to allow TCP connection on port 443 to destination 0.0.0.0/0
- In the Network ACL, update the rule to allow outbound TCP connection on port 32768 - 65535 to destination 0.0.0.0/0
- `In the Network ACL, update the rule to allow inbound TCP connection on port 443 from source 0.0.0.0/0 and outbound TCP connection on port 32768 - 65535 to destination 0.0.0.0/0`

Is question mein **Stateful Security Groups vs Stateless Network ACLs (NACLs)** aur **Ephemeral Ports** ka core concept test ho raha hai.

Aayein pehle Security Groups aur NACLs ke kaam karne ke tarike ko samajhte hain.

---

## 1. What Is Being Tested Here? (Core Exam Concepts)

```
┌─────────────────────────────────────────────────────────────────────────┐
│                   SECURITY GROUPS vs NETWORK ACLs (NACLs)               │
├──────────────────────────┬──────────────────────────────────────────────┤
│ Security Groups          │ Network ACLs (NACLs)                         │
├──────────────────────────┼──────────────────────────────────────────────┤
│ • Stateful               │ • Stateless                                  │
│ • Return traffic automatically│ • Return traffic must be EXPLICITLY allowed  │
│   allowed.               │   in Outbound rules using Ephemeral Ports.  │
│ • Evaluates all rules    │ • Evaluates rules in numerical order         │
│   before deciding.       │   (lowest number first).                     │
└──────────────────────────┴──────────────────────────────────────────────┘

```

1. **Security Groups (Stateful):**
* Jab Inbound Traffic allow hota hai (e.g., Port 443 allow kar diya), toh return response traffic automatically allow ho jata hai. Outbound rule ki alag se zaroorat nahi hoti.


2. **Network ACLs / NACLs (Stateless):**
* **Inbound Traffic:** Client ka browser Port 443 par connect karega $\rightarrow$ **Inbound Allow: TCP Port 443 from 0.0.0.0/0**.
* **Outbound Return Traffic:** Linux OS response waapis bhejte waqt Client ke temporary port par response bhejta hai. In temporary ports ko **Ephemeral Ports (Port 1024 - 65535 or 32768 - 65535)** kehte hain. Is liye NACL mein outbound ephemeral ports ko allow karna zaroori hai!



---

## 2. Correct Options Explanation (Select TWO)

#### ✅ **In the Security Group, add a new rule to allow TCP connection on port 443 from source 0.0.0.0/0**

* **Why it works:** Security Group stateful hota hai. Inbound port 443 allow karne se application traffic receive karegi aur stateful nature ki waja se response traffic automatically bahar chala jayega.

#### ✅ **In the Network ACL, update the rule to allow inbound TCP connection on port 443 from source 0.0.0.0/0 and outbound TCP connection on port 32768 - 65535 to destination 0.0.0.0/0**

* **Why it works:** NACL stateless hota hai. Client request **Inbound Port 443** par aati hai, aur response response client ke random **Outbound Ephemeral Port range (32768 - 65535 for Linux)** par jaata hai. Both rules must be explicitly configured.

---

## 3. Incorrect Options Breakdown (Elimination Strategy)

| Option | Why It Fails the Exam Requirement |
| --- | --- |
| **NACL: Allow both inbound/outbound on port 443** | **Common Trap:** Response traffic outbound port 443 par nahi jata, balki client ke *ephemeral port* (e.g. 52312) par jata hai. Outbound port 443 rakhne se connection block ho jayega. |
| **SG: Create rule to allow TCP port 443 to destination 0.0.0.0/0** | Yeh Security Group ka Outbound rule hai. External clients se traffic receive karne ke liye **Inbound Rule** zaroori hai. |
| **NACL: Update rule to allow outbound TCP port 32768 - 65535...** | Yeh option incomplete hai kyunke is mein **Inbound Port 443** allow karne ka zikr nahi hai. Combined inbound + outbound rule zaroori hai. |

---

## 4. Exam Decision Matrix (Security Group vs NACL Cheat Sheet)

* **Stateful Firewall (EC2 Instance level):** $\rightarrow$ **Security Group**
* **Stateless Firewall (Subnet level):** $\rightarrow$ **Network ACL (NACL)**
* **NACL Return Traffic Rule:** $\rightarrow$ **Must allow Outbound Ephemeral Ports (1024-65535 / 32768-65535)**

### 🎯 What is being tested?

**Security Group + Network ACL are both blocking traffic.**

### ✅ Correct answers

**1.** In the Network ACL, allow:

* **Inbound TCP 443** from `0.0.0.0/0`
* **Outbound TCP 32768–65535** to `0.0.0.0/0`

**2.** In the Security Group, allow:

* **Inbound TCP 443** from `0.0.0.0/0`

### 🔑 Key concept

**Security Group = stateful**
→ If inbound 443 is allowed, return traffic is automatically allowed.

**Network ACL = stateless**
→ Must explicitly allow **return traffic** too.
→ Client's response uses **ephemeral ports (32768–65535)**.

Flow:

`Internet → NACL inbound 443 → SG inbound 443 → EC2`

Return:

`EC2 → NACL outbound 32768–65535 → Internet`

### 🔥 Exam shortcut

**NACL = stateless → allow both directions.**
**SG = stateful → return traffic automatically allowed.**
