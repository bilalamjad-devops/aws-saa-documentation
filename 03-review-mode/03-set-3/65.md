65. Question

Category: CSAA – Design Resilient Architectures

A FinTech startup deployed an application on an Amazon EC2 instance with attached Instance Store volumes and an Elastic IP address. The server is only accessed from 8 AM to 6 PM and can be stopped from 6 PM to 8 AM for cost efficiency using Lambda with the script that automates this based on tags.

Which of the following will occur when the EC2 instance is stopped and started? (Select TWO.)

- The ENI (Elastic Network Interface) is detached.
- `The underlying host for the instance is possibly changed.`
- The Elastic IP address is disassociated with the instance.
- There will be no changes.
- `All data on the attached instance-store devices will be lost.`

### 🎯 What is being tested?

**What happens to EC2 resources during Stop → Start.**

### ✅ Correct answers

1. **The underlying host for the instance is possibly changed.**

   * Stop/start can move the instance to a different physical host.

2. **All data on the attached instance-store devices will be lost.**

   * Instance Store is **ephemeral**.
   * Stop → Start = instance-store data is lost.

### 🔑 Important

* **ENI** → remains attached.
* **Elastic IP** → remains associated (unlike an auto-assigned public IPv4).
* **EBS data** → persists through stop/start.

### 🔥 Exam shortcut

**EC2 Stop → Start:**

* New underlying host? → **Possibly yes**
* Instance Store data? → **LOST**
* ENI? → **Stays**
* Elastic IP? → **Stays**


16-September-2026

Is question mein **EC2 Instance Lifecycle (Stop/Start behavior)** aur **Instance Store Volumes vs Elastic IP (EIP)** ka core behavior test ho raha hai.

Aayein requirements ko Roman Urdu mein simple steps mein analyze karte hain:

---

## 1. Scenario Breakdown

* **Workload:** Amazon EC2 instance jisse **Instance Store volumes** attached hain aur **Elastic IP (EIP)** assigned hai.
* **Action:** Instance ko **Stop** kiya gaya aur phir subah **Start** kiya gaya.
* **Goal:** Pehchanna ke Stop/Start process ke dauran EC2 instance ke sath **kya do (2) cheezein hongi**.

---

## 2. Technical Evaluation of EC2 Stop/Start Behavior

1. **Instance Store Volumes (Ephmeral/Temporary Storage):**
* Instance Store volumes underlying physical host drive par hote hain.
* Jab aap instance ko **Stop** karte hain, toh instance terminate nahi hota lekin underlying physical host se hypervisor release ho jata hai. Is waqt **Instance Store ka tamam data paka delete/lost ho jata hai**.


2. **Underlying Host Migration:**
* Jab instance dobara **Start** hota hai, toh AWS hypervisor usay kisi bhi doosre hardware rack/host par place kar sakta hai. Is waja se **underlying host hardware change ho sakta hai**.


3. **Elastic IP & ENI Behavior:**
* Static/Public IP (jo AWS detaa hai) stop hone par release ho jata hai, lekin **Elastic IP (EIP)** instance aur primary **ENI** ke sath **associated hi rehta hai** (detach nahi hota).



---

## 3. Correct Options (Select TWO)

#### ✅ **All data on the attached instance-store devices will be lost.**

* **Why it works:** Instance Store volumes non-persistent/ephemeral hote hain; Stop/Start ya Termination par un ka data zaye ho jata hai.

#### ✅ **The underlying host for the instance is possibly changed.**

* **Why it works:** Instance ko stop karne se host hardware release ho jata hai; restart karne par AWS placement engine usay new hardware host allocate kar sakta hai.

---

## 4. Incorrect Options Breakdown (Elimination Strategy)

| Option | Why It Fails the Exam Requirement |
| --- | --- |
| **The ENI is detached.** | Primary Elastic Network Interface (ENI) stop/start cycle ke dauran instance se attached rehta hai. |
| **The Elastic IP address is disassociated...** | Elastic IP static rehta hai aur stop hone par bhi instance se associated rehta hai (jab tak aap manually disassociate na karein). |
| **There will be no changes.** | Instance store data lost ho jata hai aur host hardware change ho jata hai, is liye changes hoti hain. |

---

## 5. Exam Decision Matrix (EC2 Lifecycle Cheat Sheet)

* **Data persistent across Instance Stop/Start:** $\rightarrow$ **EBS Volumes**
* **Data lost on Instance Stop/Start:** $\rightarrow$ **Instance Store (Ephemeral) Volumes**
* **Public IP retained across Stop/Start:** $\rightarrow$ **Elastic IP (EIP)**
* **Auto-assigned Public IP retained across Stop/Start?:** $\rightarrow$ **NO (Released on Stop)**
