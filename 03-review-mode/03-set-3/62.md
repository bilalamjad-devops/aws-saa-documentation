62. Question

Category: CSAA – Design Secure Architectures

A solutions architect is writing an AWS Lambda function that will process encrypted documents from an Amazon FSx for NetApp ONTAP file system. The documents are protected by an AWS KMS customer key. After processing the documents, the Lambda function will store the results in an S3 bucket with an Amazon S3 Glacier Flexible Retrieval storage class. The solutions architect must ensure that the files can be decrypted by the Lambda function.

Which action accomplishes the requirement?


- Attach the kms:decrypt permission to the Lambda function’s resource policy. Add a statement to the AWS KMS key’s policy that grants the function’s resource policy ARN the kms:decrypt permission.
- Attach the kms:decrypt permission to the Lambda function’s execution role. Add a statement to the AWS KMS key’s policy that grants the function’s ARN the kms:decrypt permission.
- Attach the kms:decrypt permission to the Lambda function’s resource policy. Add a statement to the AWS KMS key’s policy that grants the function’s execution role the kms:decrypt permission.
- `Attach the kms:decrypt permission to the Lambda function’s execution role. Add a statement to the AWS KMS key’s policy that grants the function’s execution role the kms:decrypt permission.`

Aap ne bilkul sahi pakda hai, bas ek choti si correction: File pehle se decrypted nahi hai, file **Encrypted (Locked)** hai!

Sawal ka poora matlab yeh hai:

1. **File Encrypted hai:** File par KMS ki security lock lagi hui hai.
2. **Lambda usay kholna (Decrypt karna) chahta hai:** Taake Lambda us file ka data parh kar process kar sake.
3. **Requirement:** Is file ko open/decrypt karne ke liye Lambda ko **`kms:Decrypt` permission** deni padegi.

---

### Permissions Kahan Kahan Deni Hain?

AWS ke security rules ke mutabiq, yeh permission **DO (2) jagah** deni hoti hai:

1. **Lambda ke Execution Role par:** Role ko batana padta hai ke *"Aap ko KMS key se file decrypt karne ki ijazat hai."* (`kms:Decrypt` policy attach karni hoti hai).
2. **KMS Key Policy ke andar:** KMS Key par likhna padta hai ke *"Yeh Lambda Execution Role meri key use karke file decrypt kar sakta hai."*

Isi waja se **Option 4** sahi answer hai!

Is question mein **AWS IAM Execution Roles**, **Lambda Permissions**, aur **AWS KMS Key Policies** ka combination test ho raha hai.

Aayein rules aur core mechanics ko Roman Urdu mein systematically dekhte hain:

---

## 1. Requirement Breakdown

1. **Workload:** AWS Lambda function FSx for NetApp ONTAP se **AWS KMS Customer Managed Key (CMK)** dwara encrypted documents read/decrypt karta hai.
2. **Goal:** Lambda function ke paas `kms:Decrypt` ki sahi permissions hon taake encrypted files decrypt ho sakein.
3. **Core Concept:** KMS Customer Key se decryption allow karne ke liye **Dono side permissions (IAM Policy + Key Policy)** zaroori hoti hain.

---

## 2. Technical Concepts (IAM Execution Role vs Resource Policy)

```
┌─────────────────────────────────┐                       ┌─────────────────────────┐
│     AWS Lambda Function         │                       │      AWS KMS Key        │
│  (Uses Execution Role ARN)      │                       │     (Key Policy)        │
├─────────────────────────────────┤                       ├─────────────────────────┤
│ Attached IAM Policy:            │ ─── kms:Decrypt ────► │ Statement Grants:       │
│ Grants kms:Decrypt Permission   │                       │ Execution Role ARN      │
└─────────────────────────────────┘                       └─────────────────────────┘

```

1. **Lambda Execution Role (Identity-based Policy):**
* Lambda function jab doosri AWS services (S3, KMS, Logs) se baat karta hai, toh woh ek **IAM Execution Role** assume karta hai.
* Is `Execution Role` par `kms:Decrypt` permission ka hona zaroori hai. *(Lambda functions par KMS access ke liye resource policies use nahi hotin).*


2. **AWS KMS Key Policy (Resource-based Policy):**
* KMS Customer Managed Keys par ek **Key Policy** lagi hoti hai jo define karti hai ke kis identity/role ko key access karne ka haq hai.
* Key policy mein Lambda ke **Execution Role ARN** ko explicit `kms:Decrypt` allow karna zaroori hai.



---

## 3. Correct Option Explanation

#### ✅ **Attach the kms:decrypt permission to the Lambda function’s execution role. Add a statement to the AWS KMS key’s policy that grants the function’s execution role the kms:decrypt permission.**

* **Why it works:** Cross-service permissions ke liye IAM Execution Role par `kms:Decrypt` allow hona chahiye aur KMS Key Policy mein bhi wahi Execution Role Principal ke taur par granted hona chahiye.

---

## 4. Incorrect Options Breakdown (Elimination Strategy)

| Option | Why It Fails the Exam Requirement |
| --- | --- |
| **Attach permission to Lambda resource policy... grants resource policy ARN...** | Lambda functions par KMS permissions ke liye Resource Policy attach nahi ki jaati; Execution Role use hota hai. Moreover, resource policy ka koi ARN nahi hota. |
| **...grants the function’s ARN the kms:decrypt permission** | Key policy Principal mein direct Lambda function ka ARN nahi balki Lambda ke **Execution Role ka ARN** specify kiya jata hai. |
| **Attach to Lambda resource policy... grants execution role...** | Fails because `kms:Decrypt` identity policy Lambda ke **Execution Role** par honi chahiye, Lambda ki resource policy par nahi. |

---

## 5. Exam Decision Matrix (AWS KMS Permissions Cheat Sheet)

* **Lambda accessing KMS Encrypted Resources:** $\rightarrow$ **Permissions on Execution Role + Grant to Execution Role in KMS Key Policy**
* **KMS Key shared across different AWS accounts:** $\rightarrow$ **Account-level IAM Policy + KMS Key Policy cross-account Principal statement**
