48. Question

Category: CSAA – Design Resilient Architectures

A company plans to host a web application in an Auto Scaling group of Amazon EC2 instances. The application will be used globally by users to upload and store several types of files. Based on user trends, files that are older than 2 years must be stored in a different storage class. The Solutions Architect of the company needs to create a cost-effective and scalable solution to store the old files yet still provide durability and high availability.

Which of the following approach can be used to fulfill this requirement? (Select TWO.)

- Use a RAID 0 storage configuration that stripes multiple Amazon EBS volumes together to store the files. Configure the Amazon Data Lifecycle Manager (DLM) to schedule snapshots of the volumes after 2 years.
- `Use Amazon S3 and create a lifecycle policy that will move the objects to S3 Glacier after 2 years.`
- Use Amazon EFS and create a lifecycle policy that will move the objects to EFS-IA after 2 years.
- Use Amazon EBS volumes to store the files. Configure the Amazon Data Lifecycle Manager (DLM) to schedule snapshots of the volumes after 2 years.
- `Use Amazon S3 and create a lifecycle policy that will move the objects to S3 Standard-IA after 2 years.`

Exactly — the important part of this question is **recognizing the clues**, not memorizing every paragraph.

## 1. RAID — what is it?

**RAID = combining multiple disks/volumes together.**

For example:

```text
EBS 1 ─┐
EBS 2 ─┼──→ RAID
EBS 3 ─┘
```

There are different RAID levels.

### RAID 0 = performance

```text
File
 ↓
┌─────────┐
│ RAID 0  │
└─────────┘
 ↓    ↓    ↓
EBS1 EBS2 EBS3
```

The data is **striped** across multiple disks.

➡️ Faster performance
➡️ **No redundancy**

If one disk fails, you can lose the data.

### RAID 1 = mirroring

```text
        File
         ↓
    ┌────┴────┐
    ↓         ↓
  EBS 1      EBS 2
    │          │
    └─ same ───┘
```

The same data is copied to both disks.

➡️ Redundancy
➡️ Better protection
➡️ Less usable storage

### For the exam

Just remember:

> **RAID 0 = striping = performance**
> **RAID 1 = mirroring = redundancy**

But **RAID is not the answer here** because the requirement is scalable, durable, globally accessible file storage. That's a strong **S3** use case.

---

# 2. What is DLM?

**DLM = Amazon Data Lifecycle Manager.**

It mainly helps automate the lifecycle of **EBS snapshots**.

For example:

```text
EBS Volume
    ↓
DLM
    ↓
Create snapshots automatically
    ↓
Delete old snapshots automatically
```

You might say:

> "Create an EBS snapshot every day and keep it for 30 days."

DLM can automate that.

### Exam clue

If you see:

> **EBS + automatic snapshots + schedule**

Think:

➡️ **DLM**

But don't confuse it with **S3 Lifecycle**.

---

# 3. S3 Lifecycle = the important clue here

This question says:

> "files that are **older than 2 years** must be stored in a **different storage class**."

🚨 That's the big clue.

When you see:

> **Objects/files + age + move to another storage class**

Think:

➡️ **S3 Lifecycle Policy**

Example:

```text
Upload
  ↓
S3 Standard
  ↓
30 days
  ↓
S3 Standard-IA
  ↓
2 years
  ↓
S3 Glacier
```

S3 automatically moves objects between storage classes according to your lifecycle rule.

---

# 4. Why S3?

Look at the requirements:

| Requirement             | Best clue        |
| ----------------------- | ---------------- |
| Files/objects           | **S3**           |
| Global users            | **S3**           |
| Highly scalable         | **S3**           |
| High durability         | **S3**           |
| Older than 2 years      | **Lifecycle**    |
| Different storage class | **S3 Lifecycle** |
| Cost-effective          | **IA / Glacier** |

So your brain should immediately go:

> **Files + scalable + durable + storage class transition = S3 Lifecycle**

---

# 5. Why TWO answers?

They give two possible S3 destinations:

### Option 1

**S3 → Glacier after 2 years**

Good for data that is rarely accessed.

```text
S3 Standard
     ↓
  2 years
     ↓
S3 Glacier
```

### Option 2

**S3 → Standard-IA after 2 years**

Good when data is accessed less frequently but still needs relatively quick access.

```text
S3 Standard
     ↓
  2 years
     ↓
S3 Standard-IA
```

Both satisfy the requirement.

---

# 6. Why EFS is wrong?

The question says **2 years**.

EFS Lifecycle Management doesn't support waiting 2 years for this transition; its lifecycle transition maximum is much shorter.

So:

> **EFS + 2 years → ❌**

Don't overthink EFS here.

---

# 7. The most important exam pattern

When you see:

> **"older than X days/months/years"**

ask:

### "Are they talking about objects moving between storage classes?"

If yes:

**S3 Lifecycle Policy**.

Examples:

```text
30 days → Standard-IA
90 days → Glacier Instant Retrieval
180 days → Glacier Flexible Retrieval
365 days → Deep Archive
```

The exact transition depends on the requirements.

---

## 🧠 Your notes

You can write just this:

> **S3 Lifecycle Policy:** Automatically moves S3 objects to different storage classes based on age/access patterns → saves cost.

> **DLM:** Automates lifecycle of **EBS snapshots**.

> **RAID 0:** Stripes data across multiple disks → higher performance, **no redundancy**.

> **RAID 1:** Mirrors data across disks → redundancy.

### One-line exam shortcut:

**S3 objects + age + storage-class transition = S3 Lifecycle.**
**EBS + snapshots + automation = DLM.**
