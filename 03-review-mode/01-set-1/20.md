20. Question

Category: CSAA – Design Resilient Architectures

There was an incident in a production environment where user data stored in an Amazon S3 bucket was accidentally deleted by a Junior DevOps Engineer. The issue was escalated to management, and after a few days, an instruction was given to improve the security and protection of AWS resources.

What combination of the following options will protect the S3 objects in the bucket from both accidental deletion and overwriting? (Select TWO.)

- `Enable Versioning`
- Provide access to S3 data strictly through pre-signed URL only
- Enable S3 Intelligent-Tiering
- `Enable Multi-Factor Authentication Delete`
- Disallow S3 Delete using an IAM bucket policy

Yes 👍 This one is **easy once you remember what Versioning and MFA Delete do**.

### The problem

A Junior DevOps Engineer accidentally:

* deleted an S3 object
* or overwrote an existing object

The company wants **protection + ability to recover**.

### 1. Versioning = keep old versions

Suppose you have:

```text
report.pdf → Version 1
```

Someone accidentally uploads a new `report.pdf`.

Without versioning:

```text
report.pdf → Version 2
❌ Version 1 is gone
```

With versioning:

```text
report.pdf
   ├── Version 1
   └── Version 2
```

So you can recover Version 1.

Same thing with deletion.

If someone deletes:

```text
report.pdf
```

S3 doesn't immediately destroy the previous version. A delete marker is created, so you can recover the object.

**Mental shortcut:**

> **Versioning = "Keep my previous versions so I can recover."**

---

### 2. MFA Delete = extra protection for permanent deletion

Versioning alone isn't enough for the strongest protection.

An authorized person could still permanently delete a particular object version.

**MFA Delete** says:

> "Before permanently deleting an object version, prove that you also have MFA."

So:

```text
Normal credentials
       +
MFA
       ↓
Permanent deletion
```

This makes accidental/destructive deletion much harder.

---

### Therefore:

**Versioning + MFA Delete**

```text
          S3 Bucket
             │
       ┌─────┴─────┐
       │            │
   Versioning    MFA Delete
       │            │
   Recovery      Extra protection
```

### Important distinction for your SAA exam

| Feature                              | Purpose                                                                      |
| ------------------------------------ | ---------------------------------------------------------------------------- |
| **S3 Versioning**                    | Recover from accidental deletion/overwrite                                   |
| **MFA Delete**                       | Require MFA for permanent deletion/versioning changes                        |
| **S3 Intelligent-Tiering**           | Automatically moves objects between storage tiers to save cost               |
| **Pre-signed URL**                   | Temporary access to a specific S3 object                                     |
| **Bucket/IAM policy denying Delete** | Prevents deletion altogether, but isn't the intended recovery mechanism here |

So whenever you see:

> **"Accidental deletion or overwrite + recover the objects"**

Think:

**S3 Versioning**.

And if they add:

> **"Extra protection against permanent deletion"**

Think:

**MFA Delete**.
