32. Question

Category: CSAA – Design Secure Architectures

A company has 3 DevOps engineers that are handling its software development and infrastructure management processes. One of the engineers accidentally deleted a file hosted in Amazon S3 which has caused disruption of service.

What can the DevOps engineers do to prevent this from happening again?

- Create an IAM bucket policy that disables delete operation.
- `Enable S3 Versioning and Multi-Factor Authentication Delete on the bucket.`
- Use S3 Infrequently Accessed storage to store the data.
- Set up a signed URL for all users.

Yes, this one is easy. 👍

### Core concept

The problem is:

> **Engineer accidentally deletes an S3 file → how can we recover/prevent permanent deletion?**

Use:

**S3 Versioning + MFA Delete**

### Versioning

Without versioning:

```text
file.txt
   ↓
DELETE
   ↓
❌ Gone
```

With versioning:

```text
file.txt
 ├── Version 1
 ├── Version 2
 └── Version 3

DELETE current version
        ↓
Old version still exists ✅
```

So **Versioning = recovery from accidental deletion/overwrite.**

### MFA Delete

Adds an extra protection layer for **permanent deletion of object versions** and changing the versioning state.

Think:

> **Versioning = keep previous copies**
> **MFA Delete = extra authentication before permanently deleting versions**

### Exam shortcut 🧠

**Accidental S3 deletion → Versioning**

**Need stronger protection against permanent deletion → MFA Delete**

And don't confuse this with:

* **Signed URL** → controlled access
* **S3 storage classes** → cost/storage optimization
* **IAM policies** → permissions/access control
