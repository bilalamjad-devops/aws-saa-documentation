
30. Question

Category: CSAA – Design High-Performing Architectures

A Docker application, which is running on an Amazon ECS cluster behind a load balancer, is heavily using Amazon DynamoDB. The application requires improved database performance by distributing the workload evenly and utilizing the provisioned throughput efficiently. Currently, the table’s write capacity units (WCU) are unevenly consumed due to key distribution.

Which of the following should be implemented for the DynamoDB table?

- `Use partition keys with high-cardinality attributes, which have a large number of distinct values for each item.`
- Avoid using a primary key that combines both a partition key and a sort key.
- Use partition keys with low-cardinality attributes, which have a small number of distinct values for each item.
- Reduce the number of partition keys in the DynamoDB table.

Yes — **your thinking is correct**. 👍

The key concept in this question is **DynamoDB partition-key design**.

### Think of it like this

Suppose you have 1 million users.

#### Bad partition key — low cardinality

You choose:

`country`

Values might be:

```text
Pakistan
USA
UK
India
Canada
```

Only a few distinct values.

So a huge number of requests may go to the same partition:

```text
Pakistan → 🔥🔥🔥🔥🔥🔥🔥
USA      → 🔥🔥🔥🔥
UK       → 🔥🔥
```

This can create a **hot partition**.

---

#### Good partition key — high cardinality

Instead, choose:

`user_id`

Values:

```text
user001
user002
user003
...
user1000000
```

Millions of distinct values.

Requests are much more evenly distributed:

```text
Partition A → user001, user105, user900...
Partition B → user002, user333, user700...
Partition C → user003, user450, user801...
```

So DynamoDB can use its provisioned capacity more efficiently.

### Exam rule 🧠

> **DynamoDB performance problem + uneven workload / hot partitions → choose a high-cardinality partition key.**

**High cardinality = many unique values → better distribution.**

**Low cardinality = few unique values → risk of hot partitions.**

And yes, don't get distracted by the fact that the application is running on ECS. **ECS is basically irrelevant to this question.** The question is testing your **DynamoDB partition-key design** knowledge.
