

37. Question

Category: CSAA – Design Secure Architectures

An online medical system hosted in AWS stores sensitive Personally Identifiable Information (PII) of the users in an Amazon S3 bucket. Both the master keys and the unencrypted data should never be sent to AWS to comply with the strict compliance and regulatory requirements of the company.

Which S3 encryption technique should the Architect use?

- Use S3 server-side encryption with customer provided key.
- `Use S3 client-side encryption with a client-side master key.`
- Use S3 client-side encryption with an AWS KMS key.
- Use S3 server-side encryption with an AWS KMS key.

### Question 37 — Short revision version

**What is the question asking?**

The company says:

> **"Neither unencrypted data nor our master key should ever go to AWS."**

That's the big clue.

### Core concept

**Client-side encryption** = **encrypt the data BEFORE sending it to S3.**

```text
Your application
     ↓
Encrypt locally
     ↓
Encrypted data
     ↓
S3
```

So AWS/S3 never receives the plaintext data.

### Which client-side encryption?

There are two possibilities:

**1. Client-side master key** ✅

```text
Your key → stays with you
Your plaintext → stays with you
Encrypted data → S3
```

This exactly matches the requirement.

**2. AWS KMS key** ❌

You are still using an AWS KMS key, so the requirement of keeping the master key completely outside AWS isn't satisfied.

### 🧠 Exam shortcut

> **"Plaintext must NEVER go to AWS" → Client-side encryption**

Then:

> **"Master key must ALSO never go to AWS" → Client-side master key**

### Remember the difference

| Encryption                   | Where encryption happens? | Key                         |
| ---------------------------- | ------------------------- | --------------------------- |
| SSE-S3                       | S3                        | AWS                         |
| SSE-KMS                      | S3                        | KMS                         |
| SSE-C                        | S3                        | Customer provides key       |
| **Client-side + master key** | **Your application**      | **Your key stays with you** |

**Answer: Client-side encryption with a client-side master key.**


26-August-2026

Almost. **Client-side encryption is not the software itself.**

Think of it as a **process/library in your application** that performs the encryption.

```text
Your application
      ↓
Encryption software/library
      +
Your client-side master key
      ↓
Encrypted data
      ↓
S3
```

For the exam:

* **Client-side encryption** → encryption happens **before data reaches AWS**
* **Client-side master key** → the **secret key you control**
* **Encryption library/software** → actually performs the encryption
* **S3** → receives/stores the **encrypted data**

So yes, there is software/code involved that performs the encryption, but **the master key is not the software**. It's the secret key used by that software.
