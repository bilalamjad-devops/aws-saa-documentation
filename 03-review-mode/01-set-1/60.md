60. Question

Category: CSAA – Design Resilient Architectures

A suite of web applications is hosted in an Auto Scaling group of Amazon EC2 instances across three Availability Zones and is configured with default settings. There is an Application Load Balancer that forwards the request to the respective target group on the URL path. The scale-in policy has been triggered due to the low number of incoming traffic to the application.

Which EC2 instance will be the first one to be terminated by the Auto Scaling group?

- The EC2 instance which has been running for the longest time
- `The EC2 instance launched from the oldest launch template.`
- The EC2 instance which has the least number of user sessions
- The instance will be randomly selected by the Auto Scaling group

Yes — this question is teaching you **how an Auto Scaling Group decides which EC2 instance to kill during scale-in**.

The wording looks complicated, but the core idea is simple.

## 1. What is happening?

The ASG currently has several EC2 instances:

```text
            Auto Scaling Group
        ┌───────────────────────┐
        │                       │
        │ EC2   EC2   EC2   EC2 │
        │                       │
        └───────────────────────┘
                 ↓
          Traffic decreases
                 ↓
             Scale IN
                 ↓
          Remove 1 instance
```

The question asks:

> **Which instance does ASG choose to terminate?**

The answer is **not simply "the oldest EC2 instance."**

There is a specific decision process.

---

# 2. Default ASG termination policy

For the **default termination policy**, remember this sequence:

### Step 1 — Keep AZs balanced

Suppose:

```text
AZ-A → 3 instances
AZ-B → 2 instances
AZ-C → 2 instances
```

ASG will first look at **AZ-A**, because it has the most instances.

Why?

Because AWS wants your ASG to remain reasonably balanced across Availability Zones.

---

### Step 2 — Look at launch template age

Suppose AZ-A has:

```text
EC2-1 → Launch Template v1
EC2-2 → Launch Template v2
EC2-3 → Launch Template v2
```

ASG prefers the instance using the **oldest launch template**.

So:

```text
Launch Template v1  ← oldest
        ↓
Terminate this instance
```

That's why the answer is:

> **The EC2 instance launched from the oldest launch template.**

---

### Step 3 — If multiple instances use the oldest template

Suppose:

```text
EC2-1 → LT v1
EC2-2 → LT v1
EC2-3 → LT v2
```

Now ASG has two candidates.

It then looks at which instance is **closest to the next billing hour**.

The idea is basically:

> "Which instance should I terminate to avoid wasting the most recent partial hour of usage?"

---

### Step 4 — If still tied

If two instances are equally close to the next billing hour:

➡️ ASG chooses **randomly** between those candidates.

---

# 3. Very important distinction

This question gives you:

> **oldest launch template**

Not:

> **instance that has been running the longest**

These sound similar but are different.

Imagine:

```text
EC2-A
Launch Template v1
Started yesterday

EC2-B
Launch Template v1
Started today
```

Both use the same oldest launch template.

ASG doesn't simply say:

> "EC2-A has been running longer, so kill EC2-A."

It moves to the **next criterion**.

---

# 4. What about user sessions?

ASG doesn't normally say:

> "This EC2 has only 5 users, let's kill it."

So:

❌ Least user sessions → **not the default termination criterion**

This is particularly important because your ALB is routing requests based on the URL path. The ASG isn't looking at application-level session counts when deciding which instance to terminate.

---

# 5. Your exam shortcut

Memorize this:

| Priority | ASG asks                                                            |
| -------- | ------------------------------------------------------------------- |
| **1️⃣**  | Which AZ has the most instances?                                    |
| **2️⃣**  | Within that AZ, which instance uses the **oldest launch template**? |
| **3️⃣**  | If tied, which is **closest to next billing hour**?                 |
| **4️⃣**  | If still tied → **random**                                          |

### 🔥 One-line shortcut

> **Scale-in → Most crowded AZ → Oldest Launch Template → Closest to billing hour → Random**

And don't memorize **"oldest EC2 instance."**

Memorize:

> **Oldest Launch Template first.**
