46. Question

Category: CSAA – Design Secure Architectures

A Solutions Architect identified a series of DDoS attacks while monitoring the Amazon VPC, where applications are fronted by Elastic Load Balancing. The Architect needs to fortify the current cloud infrastructure to protect the data of the clients.

Which of the following is the most suitable solution to mitigate these kinds of attacks?

- `Use AWS Shield Advanced to detect and mitigate DDoS attacks.`
- Use both Security Groups and Network Access Control Lists to restrict VPC traffic to authorized sources only.
- Using the AWS Firewall Manager, set up a security layer that will prevent SYN floods, UDP reflection attacks, and other DDoS attacks.
- Set up a web application firewall using AWS WAF to filter, monitor, and block HTTP traffic.

Exactly. You're mostly right. Just one correction: **AWS WAF is not simply "for HTTPS."** Think **HTTP/HTTPS application-layer traffic**.

### 1. DDoS attack

**DDoS = Distributed Denial of Service**

Attacker sends a huge amount of traffic/requests to overwhelm your application.

```text
Many attackers
   ↓ ↓ ↓ ↓ ↓
Huge traffic
   ↓
Load Balancer / Application
   ↓
❌ Application becomes unavailable
```

For SAA:

> **DDoS protection → AWS Shield**

---

### 2. AWS Shield 🛡️

AWS service specifically designed for **DDoS protection**.

Think:

> **Shield = protects AWS resources from DDoS**

Two levels:

* **Shield Standard** → basic DDoS protection, automatically included
* **Shield Advanced** → stronger protection for sophisticated/large DDoS attacks + extra visibility and DDoS Response Team

**Question #46:**

> "DDoS attacks" + ELB

➡️ **Shield Advanced** ✅

---

### 3. Security Group

Think:

> **SG = firewall for an EC2 instance/ENI**

```text
Internet
   ↓
Security Group
   ↓
EC2
```

* Instance level
* **Stateful**
* Controls inbound/outbound traffic
* Example: allow SSH only from `1.2.3.4/32`

---

### 4. Network ACL

Think:

> **NACL = firewall for a subnet**

```text
Internet
   ↓
NACL
   ↓
Subnet
   ↓
EC2
```

* Subnet level
* **Stateless**
* Supports allow **and deny** rules
* Useful for controlling subnet traffic

---

### 5. AWS Firewall Manager

Your understanding is close:

> **Firewall Manager = centrally manages firewall/security policies across multiple AWS accounts/resources.**

For example, an organization has 50 AWS accounts.

Instead of configuring WAF policies individually:

```text
AWS Firewall Manager
        ↓
 ┌──────┼──────┐
Account A  B   C
   ↓      ↓   ↓
  WAF    WAF WAF
```

So:

**Firewall Manager ≠ the actual firewall.**

It **manages/centrally applies** security policies.

---

### 6. AWS WAF 🔥

This is where your understanding needs one small correction.

Don't think:

> ❌ WAF = HTTPS

Think:

> ✅ **WAF = HTTP/HTTPS application-layer protection**

It protects web applications against things like:

* SQL injection
* Cross-site scripting (XSS)
* Malicious HTTP requests
* IP-based rules
* Rate-based rules

Example:

```text
User
 ↓
HTTP/HTTPS request
 ↓
AWS WAF
 ↓
ALB
 ↓
Application
```

WAF asks:

> "Is this HTTP request malicious?"

---

# 🧠 Your SAA Security Cheat Sheet

| Service              | Think                                                  |
| -------------------- | ------------------------------------------------------ |
| **AWS Shield**       | 🛡️ DDoS protection                                    |
| **AWS WAF**          | 🌐 HTTP/HTTPS web request filtering                    |
| **Security Group**   | 🖥️ Instance-level, stateful firewall                  |
| **NACL**             | 📦 Subnet-level, stateless firewall                    |
| **Firewall Manager** | 🎛️ Centrally manage firewall policies across accounts |

### Most important distinction

**DDoS → Shield**

**SQL injection / XSS / malicious HTTP request → WAF**

**EC2 traffic → Security Group**

**Subnet traffic → NACL**

**Multiple AWS accounts → Firewall Manager**

And in real architectures, **Shield + WAF can work together** rather than being mutually exclusive.
