41. Question

Category: CSAA – Design High-Performing Architectures

A cryptocurrency trading platform is using an API built in AWS Lambda and API Gateway. Due to the recent news and rumors about the upcoming price surge of Bitcoin, Ethereum and other cryptocurrencies, it is expected that the trading platform would have a significant increase in site visitors and new users in the coming days ahead.

In this scenario, how can you protect the backend systems of the platform from traffic spikes?

- `Enable throttling limits and result caching in API Gateway.`
- Switch from using AWS Lambda and API Gateway to a more scalable and highly available architecture using EC2 instances, ELB, and Auto Scaling.
- Use CloudFront in front of the API Gateway to act as a cache.
- Move the Lambda function in a VPC.

Yes. This question is mainly testing **API Gateway throttling + caching**.

### What is the problem?

Traffic is suddenly going to increase:

```text
Normal:
100 requests/sec

News about Bitcoin:
10,000 requests/sec 😱
```

If every request reaches Lambda/backend, the backend can become overloaded.

### 1. API Gateway Throttling

**Throttling = control how many requests are allowed through.**

For example:

```text
API Gateway
Limit = 1,000 requests/sec

Requests 1–1,000   → ✅ allowed
Requests 1,001+    → ❌ throttled (HTTP 429)
```

So API Gateway acts like a **traffic gate**.

> **Throttling protects the backend from too many requests.**

---

### 2. API Gateway Caching

Suppose 10,000 users ask:

> "What is Bitcoin price?"

Without caching:

```text
10,000 requests
      ↓
API Gateway
      ↓
10,000 Lambda calls
      ↓
Backend/DB
```

With caching:

```text
10,000 requests
      ↓
API Gateway
      ↓
   Cache
   ↙  ↓  ↘
Most requests get cached result
      ↓
Only some requests → Lambda/backend
```

So:

> **Caching reduces requests reaching the backend.**

---

### Why both together?

They solve different problems:

| Feature        | Purpose                          |
| -------------- | -------------------------------- |
| **Throttling** | Limits excessive traffic         |
| **Caching**    | Avoids unnecessary backend calls |

Therefore:

**API Gateway + throttling + caching = protect backend during traffic spikes.** ✅

### Why not CloudFront?

CloudFront is mainly a **CDN/cache for content delivery**.

It can also be used with APIs, but this question specifically asks about **protecting the backend from traffic spikes**, and API Gateway already provides **throttling and API caching**.

### 🧠 Exam shortcut

Remember:

> **API Gateway throttling = "Don't let too many requests through."**

> **API Gateway caching = "Don't send the same request to backend repeatedly."**

And **HTTP 429 = Too Many Requests / throttled**.
