24. Question

Category: CSAA – Design High-Performing Architectures

A company has a web application that uses Internet Information Services (IIS) for Windows Server. A file share is used to store the application data on the network-attached storage of the company’s on-premises data center. To achieve a highly available system, the company plans to migrate the application and file share to AWS. The team considered using Logical Volume Management (LVM) stripe on Amazon EC2, but this approach would not provide a managed, highly available SMB file service.

Which of the following can be used to fulfill this requirement?

- `Migrate the existing file share configuration to Amazon FSx for Windows File Server.`
- Migrate the existing file share configuration to Amazon EBS.
- Migrate the existing file share configuration to AWS Storage Gateway.
- Migrate the existing file share configuration to Amazon EFS.


Yes — your understanding is **very close**. The key is to separate **compute**, **file storage**, and **hybrid connectivity**.

### First, understand the question in simple words

The company currently has:

**On-premises:**

```text
Windows Server (IIS)
       |
       | SMB
       ↓
On-premises NAS / File Share
       |
   application files
```

They want to migrate this environment to AWS and make it **highly available**.

The important word is **SMB**.

> **SMB = Server Message Block** — the file-sharing protocol commonly used by Windows.

So the question is essentially:

> "I have a Windows application that needs a shared Windows file system. What AWS managed service should replace my on-premises NAS?"

Answer:

**Amazon FSx for Windows File Server.**

---

## 1. What does FSx do?

Think of FSx as:

> **"AWS-managed file server."**

For this question:

```text
                    AWS
                     |
              ┌──────────────┐
              │ EC2 Windows  │
              │ IIS App      │
              └──────┬───────┘
                     │
                  SMB
                     │
                     ↓
          ┌─────────────────────┐
          │ FSx for Windows     │
          │ File Server         │
          │                     │
          │ Shared Files        │
          └─────────────────────┘
```

Your Windows EC2 instances can access the same shared files.

That's exactly what the question needs.

---

# 2. The 3 FSx types you should remember

You said you forgot these. Don't memorize all the details; remember the **workload**.

| Service                         | Think                              |
| ------------------------------- | ---------------------------------- |
| **FSx for Windows File Server** | 🪟 Windows + SMB                   |
| **FSx for Lustre**              | ⚡ HPC / high-performance computing |
| **FSx for NetApp ONTAP**        | 🏢 Enterprise / advanced storage   |
| **FSx for OpenZFS**             | 🐧 Linux / ZFS workloads           |

For SAA, your strongest association should be:

> **Windows + SMB → FSx for Windows**

And:

> **Linux shared file system → EFS**

---

# 3. Why NOT EFS?

You already know EFS, but here's the important distinction:

**EFS = Linux file system**

**FSx for Windows = Windows file system**

So if the question says:

> Windows Server + SMB

🚨 Think **FSx for Windows**.

If it says:

> Linux servers need shared file storage

Think:

**EFS**

---

# 4. Why NOT EBS?

This is another important distinction.

**EBS = block storage**

Usually:

```text
EC2
 │
 └── EBS
```

Think of EBS like a disk attached to an EC2 instance.

It isn't designed to be your managed shared SMB file server.

So:

> EC2 disk → EBS

but:

> Multiple Windows machines sharing files through SMB → FSx for Windows

---

# 5. What about Storage Gateway?

This is where your question is important.

You said:

> "storage gateway is used to transfer data or share data. data should be in both on-premises and AWS?"

**Sometimes, yes — that's the idea of Storage Gateway.**

Storage Gateway is mainly a **hybrid storage service**.

Think:

```text
ON-PREMISES                         AWS

Your Data Center
     │
     │
     │ Storage Gateway
     │
     └──────────────────────────────→ AWS Storage
```

It helps organizations connect their **on-premises environment with AWS storage**.

So if the question says:

> "We are keeping our existing on-premises environment and want to access AWS storage."

Think **Storage Gateway**.

But this question says the company wants to **migrate the application and file share to AWS**.

Therefore:

> Don't keep the file server/NAS dependency on-premises → use **FSx for Windows**.

---

# 6. Very important distinction for your SAA exam

Memorize this little map:

```text
                    STORAGE
                       │
        ┌──────────────┼──────────────┐
        │              │              │
      Block          File           Object
        │              │              │
       EBS        ┌────┴────┐         S3
                  │         │
                 EFS       FSx
                  │         │
               Linux     Windows
                         SMB
```

Then:

```text
EBS
↓
EC2 disk

EFS
↓
Shared Linux file system

FSx for Windows
↓
Shared Windows file system / SMB

S3
↓
Object storage
```

---

## And your earlier question about "both on-premises and AWS"

Exactly: **Storage Gateway is commonly used when you have a hybrid requirement.**

For example:

```text
On-premises application
        │
        ↓
Storage Gateway
        │
        ↓
       S3
```

You might keep your applications on-premises while using AWS storage.

Whereas this question is more like:

```text
OLD

On-premises Windows
       +
On-premises NAS
       ↓
    Migrate
       ↓
NEW

AWS EC2 Windows
       +
FSx for Windows
```

That's why **FSx for Windows File Server** is the correct answer.

> 💽 **EBS**.

Exactly. Think of it like this:

| EC2 workload                            | Storage choice                  | Main idea                      |
| --------------------------------------- | ------------------------------- | ------------------------------ |
| **Linux EC2 → one instance**            | **EBS**                         | Block storage attached to EC2  |
| **Windows EC2 → one instance**          | **EBS**                         | Windows EC2 can also use EBS   |
| **Linux EC2 → many EC2s share files**   | **EFS**                         | Shared Linux file system       |
| **Windows EC2 → many EC2s share files** | **FSx for Windows File Server** | Shared Windows/SMB file system |

### The important correction

It's **not**:

> Linux = EBS, Windows = FSx

Both Linux **and Windows EC2 can use EBS**.

The distinction is mainly **how you need to access the storage**:

**1. One EC2 needs its own disk → EBS**

```text
EC2 Linux
   |
  EBS
```

or

```text
EC2 Windows
   |
  EBS
```

**2. Multiple Linux machines need the same shared files → EFS**

```text
EC2 Linux ─┐
EC2 Linux ─┼── EFS
EC2 Linux ─┘
```

**3. Multiple Windows machines need the same shared files → FSx for Windows**

```text
EC2 Windows ─┐
EC2 Windows ─┼── FSx for Windows
EC2 Windows ─┘
```

The keyword to remember for **FSx for Windows** is **SMB**.

So for your SAA questions:

> **Windows + shared file system + SMB → FSx for Windows File Server**

> **Linux + shared file system → EFS**

> **EC2 + individual block disk → EBS**

And yes, your previous Question 24 was exactly testing this distinction.
