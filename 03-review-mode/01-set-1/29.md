29. Question

Category: CSAA – Design Resilient Architectures

An application consists of multiple Amazon EC2 instances in private subnets in different availability zones. The application uses a single NAT Gateway for downloading software patches from the Internet to the instances. There is a requirement to protect the application from a single point of failure when the NAT Gateway encounters a failure or if its availability zone goes down.

How should the Solutions Architect redesign the architecture to be more highly available and cost-effective?

- Create three NAT Gateways in each availability zone. Configure the route table in each private subnet to ensure that instances use the NAT Gateway in the same availability zone.
- `Create a NAT Gateway in each availability zone. Configure the route table in each private subnet to ensure that instances use the NAT Gateway in the same availability zone`
- Create a NAT Gateway in each availability zone. Configure the route table in each public subnet to ensure that instances use the NAT Gateway in the same availability zone.
- Create two NAT Gateways in each availability zone. Configure the route table in each public subnet to ensure that instances use the NAT Gateway in the same availability zone.

# Session 1–7 Summary

## 1. AD, AD Connector, IAM Roles

### Your mental model

Think:

**Company already has users/groups in Microsoft Active Directory → connect that AD to AWS → give those users AWS IAM Roles.**

* **AD (Active Directory)** = company’s system for managing employees, users, groups, passwords, etc.
* **AD Connector** = a bridge/gateway between AWS and the company's existing AD.
* **Simple AD** = AWS provides a small/basic directory itself; you don't use this when the company already has an existing corporate AD.
* **IAM Role** = permissions/access that a user can assume in AWS.

So:

```text
Corporate AD
   ↓
AD Connector
   ↓
IAM Roles
   ↓
AWS Console
```

**Exam clue:**
If the question says **"existing corporate/on-premises Active Directory"**, think **AD Connector**.

# 2. Auto Scaling + Fault Tolerance

This was an important concept.

Requirement:

> Need **at least 2 instances**, but must survive an **AZ failure** and still have 2 instances.

If you put:

```text
AZ-A → 1 EC2
AZ-B → 1 EC2
```

and AZ-A dies:

```text
AZ-A ❌
AZ-B → 1 EC2
```

You temporarily have only **1 instance**.

Therefore, to guarantee 2 instances even after losing one AZ:

```text
AZ-A → 2 EC2
AZ-B → 2 EC2
```

So:

**Minimum = 4**
**Maximum = 6**

Why maximum 6?

Because normal requirement is 2, but peak requirement is 6.

### Important exam thinking

Don't just ask:

> "How many instances do I normally need?"

Ask:

> **"How many must remain after failure?"**

If you need **2 after losing one AZ**, you need **4 initially** when using two AZs with 2 per AZ.

# 3. API Gateway Throttling

You correctly recognized that API Gateway is used as an entry point to backend services such as Lambda, DynamoDB, etc.

Think:

```text
Users
   ↓
API Gateway
   ↓
Lambda / EC2 / other backend
```

Now imagine:

```text
Normal:
1,000 requests/sec

Suddenly:
100,000 requests/sec
```

If everything goes through to your backend, your backend could get overwhelmed.

### Throttling = "Slow down / limit requests"

For example:

```text
API Gateway
Maximum = 1,000 requests/sec

Requests 1–1,000 → allowed
Requests above limit → throttled / 429
```

So the mental model is:

> **Throttling protects the backend from too much traffic.**

Don't confuse it with scaling.

**Scaling = handle more capacity.**
**Throttling = limit how much traffic is allowed through.**

# 4. Lambda Environment Variables + KMS

The question was essentially asking:

> "I have database passwords and API keys. How do I protect them from other developers who can see the Lambda configuration?"

Lambda **does encrypt environment variables at rest by default**.

But for stronger control, use:

```text
Lambda
   ↓
Customer-managed KMS key
```

The important distinction:

### AWS-managed/default key

AWS manages the key for you.

### Customer-managed KMS key

**You control the key.**

You can control:

* who can use it
* who can decrypt
* key policies
* rotation
* auditing
* disabling the key

So for the exam:

> **Sensitive Lambda environment variables + maximum control → customer-managed KMS key + encryption helpers**

Also remember:

**KMS = encryption/key management**

# 5. CloudWatch Agent

This one should be very easy now.

Default EC2 CloudWatch metrics include things such as:

* CPU
* Network
* Disk I/O

But by default, CloudWatch doesn't give you things like:

* RAM/memory utilization
* disk space utilization
* swap utilization

So:

```text
EC2
  ↓
CloudWatch Agent
  ↓
Custom metrics
  ↓
CloudWatch
```

### Exam clue

If you see:

> **Memory utilization of EC2**

Immediately think:

**CloudWatch Agent**

Not:

* SSM Inventory
* Inspector
* default CloudWatch metrics

# 6. Aurora Global Database

This question introduced an important distinction.

You already know:

```text
RDS
 ├── MySQL
 ├── PostgreSQL
 ├── Oracle
 ├── SQL Server
 └── etc.

Aurora
 ├── Aurora MySQL
 └── Aurora PostgreSQL
```

And:

```text
DynamoDB = NoSQL
```

Now add this concept:

### RDS Multi-AZ

Primarily gives **regional high availability**.

Example:

```text
Region
 ├── AZ-A → Primary
 └── AZ-B → Standby
```

This protects against an **AZ failure**.

---

### Aurora Global Database

Used when you need **cross-Region disaster recovery**.

Think:

```text
Region A
Aurora Primary
      ↓
   replication
      ↓
Region B
Aurora Secondary
```

This is designed for very low replication lag and rapid cross-Region recovery.

So the exam clue:

> **Relational database + multi-region + RPO around 1 second + RTO under 1 minute**

Think:

# Aurora Global Database

---

### DynamoDB Global Tables

You already know:

> DynamoDB = NoSQL

And:

> DynamoDB Global Tables = multi-Region DynamoDB

So don't confuse:

| Requirement                  | Think                      |
| ---------------------------- | -------------------------- |
| Relational + Multi-AZ        | RDS Multi-AZ / Aurora      |
| Relational + Cross-Region DR | **Aurora Global Database** |
| NoSQL + Multi-Region         | **DynamoDB Global Tables** |

# 7. VPC Endpoints

This is another important networking mental model.

Imagine:

```text
Private EC2
    |
    | ❌ Internet
    |
    ↓
S3 / DynamoDB
```

The company doesn't want traffic going through the public Internet.

Use:

```text
Private EC2
     ↓
VPC Endpoint
     ↓
S3 / DynamoDB
```

The traffic stays on the AWS network.

### Important distinction

For S3 and DynamoDB, think:

**VPC Endpoint**

You don't need:

* NAT Gateway
* Internet Gateway
* VPN
* Direct Connect

for this particular private access requirement.
