54. Question

Category: CSAA – Design High-Performing Architectures

An AI-powered Forex trading application consumes thousands of data sets to train its machine learning model. The application’s workload requires a high-performance, parallel hot storage to process the training datasets concurrently. It also needs cost-effective cold storage to archive those datasets that yield low profit.

Which of the following Amazon storage services should the developer use?

- `Use Amazon FSx For Lustre and Amazon S3 for hot and cold storage respectively.`
- Use Amazon Elastic File System and Amazon S3 for hot and cold storage respectively.
- Use Amazon FSx For Lustre and the Provisioned IOPS SSD (io1) volumes of Amazon EBS for hot and cold storage respectively.
- Use Amazon FSx For Windows File Server and Amazon S3 for hot and cold storage respectively.

Yes. This question is mainly testing **“which AWS storage is designed for high-performance parallel processing?”** The key clue is **machine learning training + thousands of datasets + parallel processing**.

### 1. What is the question really asking?

It gives you **two different storage requirements**:

1. **Hot storage** → data is actively being processed → needs **very high performance + parallel access**
2. **Cold storage** → old/low-value data → needs **cheap storage**, because it is rarely accessed

So think:

> **Hot + parallel + ML → FSx for Lustre**
> **Cold + cheap + archive → S3 Glacier / Glacier Deep Archive**

# 2. What is FSx for Lustre?

This is the **most important concept in this question**.

**Lustre = high-performance parallel file system.**

Imagine you have:

```text
10,000 ML training files
        ↓
     FSx Lustre
   ↙   ↓   ↓   ↘
Server Server Server Server
   ↓     ↓     ↓
process process process process
```

Instead of one storage system becoming a bottleneck, Lustre is designed to **distribute data across multiple storage servers**, allowing many clients to process data concurrently.

That's why AWS commonly associates **FSx for Lustre** with:

* Machine learning
* HPC (High Performance Computing)
* Big data processing
* High-throughput workloads
* Parallel processing

### Exam clue

If you see:

> **Machine learning + high performance + parallel processing**

🚨 Think:

**FSx for Lustre**

---

# 3. What is FSx for Windows File Server?

This is completely different.

Think:

> **Windows applications → FSx for Windows**

It provides a managed Windows file system and supports things such as:

* SMB
* Windows/NTFS
* Active Directory integration

So:

| Requirement                | Think                           |
| -------------------------- | ------------------------------- |
| ML/HPC/parallel processing | **FSx for Lustre**              |
| Windows file shares/SMB/AD | **FSx for Windows File Server** |

Don't choose Windows FSx just because the question says "file storage."

The **parallel processing** clue is what points you to Lustre.

---

# 4. What is EFS?

**Amazon EFS = Elastic File System.**

Think:

> "I need a shared file system that multiple EC2 instances can access."

For example:

```text
EC2-1 ──┐
EC2-2 ──┤
EC2-3 ──┼── EFS
EC2-4 ──┤
EC2-5 ──┘
```

EFS is excellent when multiple Linux workloads need shared files.

But don't automatically think:

> "Multiple EC2 instances = Lustre."

The question says **high-performance parallel processing for ML datasets**.

That's much more specifically **FSx for Lustre**.

---

# 5. What is EBS?

EBS is basically:

> **Block storage attached to EC2.**

Think of it like a virtual hard drive:

```text
EC2
 │
 └── EBS volume
       │
       └── application/data
```

EBS has different volume types.

For example:

* General Purpose SSD
* Provisioned IOPS SSD
* Throughput Optimized HDD
* Cold HDD

### Provisioned IOPS SSD

This is for **very demanding I/O workloads** where you need predictable/high IOPS.

So don't confuse:

**Provisioned IOPS ≠ cold storage**

In fact, Provisioned IOPS is generally associated with **high-performance workloads**, not cheap archival storage.

---

# 6. What is cold storage?

This is another major clue.

Imagine:

```text
HOT
Data accessed constantly
↓
Expensive storage
↓
High performance


COLD
Data rarely accessed
↓
Cheap storage
↓
Retrieval may take longer/cost more
```

For AWS, when you hear:

> **Archive / rarely accessed / long-term retention / cold data**

think:

**S3 Glacier**

and for very long-term, lowest-cost archival:

**S3 Glacier Deep Archive**

So this question's second requirement is:

> "Datasets that yield low profit" → probably don't need expensive high-performance storage.

Therefore:

**S3 + Glacier storage class**

---

# 7. Why S3?

S3 is **object storage**.

You can store huge amounts of files/objects without worrying about managing disks.

And S3 has multiple storage classes.

Conceptually:

```text
Frequently accessed
        ↓
S3 Standard

Less frequently accessed
        ↓
S3 Standard-IA

Archive
        ↓
S3 Glacier

Very long-term archive
        ↓
S3 Glacier Deep Archive
```

So when the question says:

> **cold storage / archive / rarely accessed**

S3 Glacier should immediately come to mind.

---

# 8. Now understand the correct answer

The question says:

> "high-performance, parallel hot storage"

That's:

**FSx for Lustre**

Then:

> "cost-effective cold storage"

That's:

**S3 Glacier**

Therefore:

**FSx for Lustre + S3**

The answer isn't really testing whether you memorize the entire explanation.

It's testing whether you recognize:

```text
ML + parallel + high performance
             ↓
       FSx for Lustre

Rarely accessed + cheap/archive
             ↓
       S3 Glacier
```

# 9. Your option confusion: FSx vs EFS vs EBS

Use this mental map:

| AWS service         | Think of it as                  | Exam clue                             |
| ------------------- | ------------------------------- | ------------------------------------- |
| **EBS**             | Hard drive for EC2              | One EC2/block storage/high IOPS       |
| **EFS**             | Shared elastic file system      | Multiple Linux EC2s need shared files |
| **FSx for Lustre**  | Super-fast parallel file system | **ML/HPC/parallel processing**        |
| **FSx for Windows** | Windows file server             | **SMB/Windows/AD**                    |
| **S3**              | Object storage                  | Files/objects, massive scalability    |
| **S3 Glacier**      | Cheap archive                   | **Cold/rarely accessed data**         |

### Very important distinction

Don't memorize:

> "FSx = fast."

Instead memorize:

> **Lustre = parallel high-performance processing.**

That's the exam clue.

---

## And one correction about the question

You noticed that option 3 says:

> FSx for Lustre for hot + EBS Provisioned IOPS for cold

That is obviously suspicious once you understand the services.

**Provisioned IOPS is designed for high-performance I/O, not cheap archival storage.**

So:

```text
FSx Lustre → HOT ✅
EBS io1 → COLD ❌

S3 Glacier → COLD ✅
```

### One-line revision note

> **FSx for Lustre = ML/HPC + parallel + high throughput. EFS = shared file system. EBS = EC2 block storage. S3 = object storage. Glacier = cold/archive storage.**

That is the core lesson from Q54.
