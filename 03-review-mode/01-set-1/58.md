58. Question

Category: CSAA – Design Resilient Architectures

A company has a hybrid cloud architecture that connects its on-premises data center and cloud infrastructure in AWS. It requires a durable storage backup for its corporate documents stored on-premises and a local cache that provides low-latency access to recently accessed data to reduce data egress charges. The documents must be stored on and retrieved from AWS via the Server Message Block (SMB) protocol. These files must be immediately accessible within minutes for six months and archived for another decade to meet data compliance.

Which of the following is the best and most cost-effective approach to implement in this scenario?

- `Launch a new file gateway that connects to your on-premises data center using AWS Storage Gateway. Upload the documents to the file gateway and set up a lifecycle policy to move the data into Glacier for data archival.`
- Launch a new tape gateway that connects to your on-premises data center using AWS Storage Gateway. Upload the documents to the tape gateway and set up a lifecycle policy to move the data into Glacier for archival.
- Use AWS DataSync to transfer all files from the on-premises network directly to an Amazon S3 bucket, and set up a lifecycle policy to move the data into Glacier for archival.
- Establish a Direct Connect connection to integrate your on-premises network to your VPC. Upload the documents on Amazon EBS Volumes and use a lifecycle policy to automatically move the EBS snapshots to an Amazon S3 bucket, and then later to Glacier for archival.

Exactly. **Question 58 is mainly testing whether you can recognize when to use AWS Storage Gateway vs DataSync vs Direct Connect.**

The biggest clue is:

> **On-premises files + SMB + local cache + AWS storage + archival**

That combination strongly points to **Storage Gateway → File Gateway**.

### 1. What is AWS Storage Gateway?

Think of it as a **bridge between your on-premises environment and AWS storage**.

```text
ON-PREMISES
Windows/File Server
      ↓
AWS Storage Gateway
      ↓
     S3
      ↓
Glacier / archival
```

The important part is that the Storage Gateway can maintain a **local cache**.

So frequently/recently accessed files can be served from the local environment instead of going across the network every time.

---

### 2. What is File Gateway?

This is the one Question 58 wants you to recognize.

**File Gateway = on-premises file access → S3**

It supports:

* **SMB** → Windows
* **NFS** → Linux/Unix
* S3 as the underlying AWS storage
* Local cache for recently accessed data
* S3 lifecycle policies for archival

So:

```text
Windows users
     ↓ SMB
File Gateway
     ↓
 Local cache
     ↓
     S3
     ↓ after 6 months/according to policy
 Glacier
```

That's almost exactly the question.

---

### 3. What is DataSync?

**AWS DataSync = move/copy data**

Think:

> **"I have a lot of data somewhere and I want to transfer it somewhere else."**

For example:

```text
On-premises
     ↓
  DataSync
     ↓
    S3
```

It is excellent for **data migration and transfers**.

But Question 58 requires:

> **local cache + low-latency access to recently accessed files**

DataSync doesn't provide that file-gateway caching experience.

So:

**DataSync → transfer data**

**File Gateway → access files + cache + store in S3**

---

### 4. What is Direct Connect?

**AWS Direct Connect = dedicated network connection between on-premises and AWS.**

Think:

```text
Your Data Center
       │
       │ dedicated network connection
       ↓
AWS
```

It is useful when you need **consistent/private connectivity and high bandwidth** between on-premises and AWS.

But Direct Connect itself does **not**:

* provide file storage
* provide local file caching
* automatically archive files to Glacier

So don't confuse:

**Direct Connect = network**

**Storage Gateway = storage bridge**

---

### 5. What about Tape Gateway?

Storage Gateway has different gateway types. For your SAA exam, remember:

| Gateway            | Think                                  |
| ------------------ | -------------------------------------- |
| **File Gateway**   | Files → S3, SMB/NFS, local cache       |
| **Tape Gateway**   | Virtual tapes → backup/archive         |
| **Volume Gateway** | Block storage → iSCSI/EBS-style backup |

Question says **SMB files + local cache** → **File Gateway**.

---

## The clues in Question 58

When you see:

> **On-premises**

→ Think **Storage Gateway / DataSync / Direct Connect**

Then:

> **SMB**

→ Think **File Gateway**

Then:

> **local cache / low latency recently accessed data**

→ **File Gateway**

Then:

> **store in AWS / durable backup**

→ **S3**

Then:

> **long-term archival**

→ **S3 Glacier / Glacier Deep Archive**

Therefore:

### ✅ Correct architecture

```text
On-premises
    │
    │ SMB
    ↓
File Gateway
    │
    ├── Local cache
    │      ↓
    │   Fast access
    │
    ↓
   S3
    │
    │ Lifecycle Policy
    ↓
Glacier
    │
    ↓
10-year archive
```

### 🔥 Exam memory

**Storage Gateway = "I want my on-premises environment to work with AWS storage."**

**File Gateway = "I want files, SMB/NFS, S3, and local cache."**

**DataSync = "I want to transfer/migrate lots of data."**

**Direct Connect = "I want a dedicated network connection to AWS."**

And one correction to keep in mind: **Storage Gateway is not itself a replacement for Direct Connect.** You can use them together when you need both the storage-gateway functionality and dedicated connectivity.
