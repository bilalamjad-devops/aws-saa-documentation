15. Question

Category: CSAA – Design Secure Architectures

A government entity is conducting a population and housing census in the city. Each household’s information uploaded to its online portal is stored in encrypted files in Amazon S3. The government assigned its Solutions Architect to set compliance policies that verify data containing personally identifiable information (PII) in a manner that meets its compliance standards. It should also be alerted if there are potential policy violations with the privacy of its S3 buckets, beyond the object listing that S3 Inventory provides.

Which of the following should the Architect implement to satisfy this requirement?

- `Set up and configure Amazon Macie to monitor their S3 data.`
- Set up and configure Amazon Kendra to monitor malicious activity on their S3 data
- Set up and configure Amazon Polly to scan for usage patterns on S3 data
- Set up and configure Amazon Fraud Detector to send out alert notifications whenever a security violation is detected on their S3 data.

Yes, this question introduces a **new AWS security service: Amazon Macie**. The question sounds complicated, but the requirement is actually very simple.

### First, understand the situation

The government is collecting census information:

```text
Household
   ↓
Online Portal
   ↓
S3
   ↓
Encrypted files containing personal information
```

Those files may contain **PII**.

**PII = Personally Identifiable Information** — information that can identify a person, such as:

* Name
* Address
* Phone number
* Email
* National ID number
* Passport number

The government wants AWS to:

1. **Find sensitive/PII information inside S3**
2. **Identify potential privacy/security problems with S3 buckets**
3. **Generate findings/alerts when problems are detected**

That's exactly what **Amazon Macie** is for.

---

## 🧠 Think of Macie as an S3 privacy/security scanner

Imagine you have this S3 bucket:

```text
S3 Bucket
│
├── family1.csv
│   ├── Name
│   ├── Address
│   └── National ID
│
├── family2.csv
│   ├── Name
│   ├── Address
│   └── Phone
│
└── family3.csv
```

You don't want someone manually opening millions of files to determine:

> "Does this contain sensitive information?"

Macie can help discover and classify sensitive data such as **PII**.

So remember:

> **Macie → Sensitive data / PII → S3**

---

### Macie has TWO important things for your exam

#### 1. Sensitive data findings

Macie discovers sensitive information inside S3 objects.

For example:

```text
S3 object
   ↓
Macie scans it
   ↓
"Found sensitive personal information"
```

#### 2. Policy findings

Macie can also identify potential **security/privacy problems with S3 buckets**.

For example, a bucket may have a configuration that creates a privacy/security concern.

So:

> **Macie = S3 + PII + privacy/security findings**

---

## Why not the other services?

You can eliminate them very quickly:

| Service        | Main purpose                         |
| -------------- | ------------------------------------ |
| **Macie**      | 🔐 S3 sensitive data / PII discovery |
| Kendra         | 🔎 Enterprise search                 |
| Polly          | 🗣️ Text → speech                    |
| Fraud Detector | 💳 Detect fraud                      |

So when you see:

> **S3 + PII + sensitive data + privacy/security findings**

your brain should immediately say:

### **Amazon Macie** ✅

---

### One important distinction

Don't confuse **Macie** with **S3 Inventory**.

**S3 Inventory** tells you things about your objects, such as:

> "What objects exist in my bucket?"

Macie goes further and asks:

> "What sensitive information is inside these objects, and are there potential S3 privacy/security issues?"

That's why the question specifically says:

> **"beyond the object listing that S3 Inventory provides."**

That's a big exam clue for **Macie**.
