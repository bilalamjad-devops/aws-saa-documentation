62. Question

Category: CSAA – Design Secure Architectures

A medical records company is planning to store sensitive clinical trial data in an Amazon S3 repository with the object-level versioning feature enabled. The Solutions Architect is tasked with ensuring that no object can be overwritten or deleted by any user for a period of one year only. To meet the strict compliance requirements, the root user of the company’s AWS account must also be restricted from making any changes to an object in the S3 bucket. Backup Vault Lock offers similar immutability, but the company requires object-level protection in S3.

Which of the following is the most secure way of storing the data in S3?

- Enable S3 Object Lock in compliance mode with a legal hold of one year.
- Enable S3 Object Lock in governance mode with a retention period of one year.
- Enable S3 Object Lock in governance mode with a legal hold of one year.
- `Enable S3 Object Lock in compliance mode with a retention period of one year.`

Yes. **Question 62 is mainly testing whether you understand S3 Object Lock + Governance vs Compliance + Retention Period vs Legal Hold.** Once you understand those four things, the answer becomes almost automatic.

## 1. What is the question actually saying?

Forget the medical company for a moment.

The requirement is:

> "Put objects in S3 and make sure **nobody can modify, overwrite, or delete them for exactly 1 year — even the AWS root user**."

So the question gives you four clues:

| Clue                                | What it points to    |
| ----------------------------------- | -------------------- |
| S3 objects                          | **S3 Object Lock**   |
| Cannot overwrite/delete             | **Object Lock**      |
| For **1 year**                      | **Retention period** |
| Even **root user** cannot change it | **Compliance mode**  |

Therefore:

**S3 Object Lock + Compliance mode + 1-year retention period** ✅

---

# 2. What is S3 Object Lock?

Think of it as:

> 🔒 **"Don't let anyone change this object."**

It uses the **WORM** model:

**Write Once, Read Many**

Example:

```text
medical-record.pdf
       ↓
   S3 Object Lock
       ↓
 🔒 Cannot delete
 🔒 Cannot overwrite
 🔒 Cannot modify
```

It's useful for things like:

* compliance
* regulatory records
* financial records
* medical records
* audit data
* backups that must remain immutable

---

# 3. Object Lock has TWO modes

This is the most important part.

```text
             S3 Object Lock
                   |
          ┌────────┴────────┐
          ↓                 ↓
     Governance          Compliance
```

## Governance Mode

Think:

> **"Locked for normal users, but an authorized person can override it."**

For example:

```text
User
 ↓
Try deleting object
 ↓
❌ Blocked
```

But a user with the appropriate special permission can bypass the governance retention.

So:

> **Governance = protection, but override is possible.**

---

## Compliance Mode

Think:

> **"ABSOLUTE LOCK."**

```text
User
 ↓
❌ Delete

Admin
 ↓
❌ Delete

Root user
 ↓
❌ Delete
```

Even the root user cannot shorten the retention period or delete/overwrite the protected object version during the retention period.

Therefore:

> **Compliance = nobody can override the lock during retention.**

And this is exactly what Question 62 asks for.

---

# 4. Governance vs Compliance — memorize this

|                               | Governance                                              | Compliance            |
| ----------------------------- | ------------------------------------------------------- | --------------------- |
| Protect object                | ✅                                                       | ✅                     |
| Prevent normal users deleting | ✅                                                       | ✅                     |
| Can authorized users bypass?  | ✅                                                       | ❌                     |
| Root user can override?       | Governance can be bypassed with appropriate permissions | ❌                     |
| Strongest protection          | ❌                                                       | **✅**                 |
| Exam keyword                  | Flexible/admin override                                 | **Strict compliance** |

### Shortcut:

> **Governance = "I can override it."**

> **Compliance = "Nobody can override it."**

---

# 5. Now the second concept: Retention Period

The question says:

> **for one year**

That means you need a **retention period**.

For example:

```text
Jan 1, 2026
    ↓
Object locked
    ↓
1 year
    ↓
Jan 1, 2027
    ↓
Retention expires
```

The retention period tells S3:

> "Keep this object version protected until this date."

So:

**1 year → Retention Period** ✅

---

# 6. What is a Legal Hold?

This is where the question tries to trick you.

A **legal hold** also prevents an object from being deleted or overwritten.

But:

> **Legal hold does NOT have an expiration date.**

Think:

```text
Legal Hold
     ↓
🔒 LOCK
     ↓
No automatic expiry
     ↓
Someone authorized must REMOVE the hold
```

For example, suppose a company is involved in a lawsuit.

They might say:

> "Do NOT delete these records until this legal case is finished."

They don't know whether the case will finish in:

* 3 months
* 1 year
* 5 years

So they use a **legal hold**.

---

# 7. Retention vs Legal Hold

This table is worth memorizing:

| Feature                | Retention Period                   | Legal Hold                      |
| ---------------------- | ---------------------------------- | ------------------------------- |
| Prevents deletion      | ✅                                  | ✅                               |
| Prevents overwrite     | ✅                                  | ✅                               |
| Has fixed duration?    | **✅**                              | **❌**                           |
| Example                | Protect for 1 year                 | Protect until legal case ends   |
| Automatically expires? | **Yes**                            | **No**                          |
| Can be removed?        | Can't shorten compliance retention | Authorized user can remove hold |

### Shortcut:

> **"For 1 year" → Retention Period**

> **"Until further notice / legal case ends" → Legal Hold**

---

# 8. Now solve all four options

### A. Compliance + legal hold of one year ❌

Compliance is good.

But:

> Legal hold doesn't have "one year."

So wrong.

---

### B. Governance + retention period of one year ❌

Retention period = correct.

But governance can potentially be bypassed by an authorized principal.

The question specifically says:

> **even root user must be restricted**

So you need **Compliance**.

---

### C. Governance + legal hold of one year ❌

Two problems:

* Governance isn't strong enough.
* Legal hold doesn't have a one-year duration.

---

### D. Compliance + retention period of one year ✅

Everything matches:

```text
S3
 ↓
Object Lock
 ↓
Compliance Mode
 ↓
Retention Period
 ↓
1 year
```

**Correct.**

---

# 9. One subtle thing: versioning

You noticed the question says:

> "object-level versioning feature enabled"

This is important because **S3 Object Lock works with object versions**.

Imagine:

```text
report.pdf
   |
   ├── Version 1 🔒
   ├── Version 2 🔒
   └── Version 3 🔒
```

Object Lock protects the specific **object version**.

So don't think of it simply as:

> "The filename is locked."

Think:

> **"The particular version of that object is protected."**
