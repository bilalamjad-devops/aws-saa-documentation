
42. Question

Category: CSAA – Design Resilient Architectures

An application that records weather data every minute is deployed in a fleet of Amazon EC2 Spot instances and uses a MySQL RDS database instance. Currently, there is only one Amazon RDS instance running in one Availability Zone. The database needs to be improved to ensure high availability by enabling synchronous data replication to another RDS instance.

Which of the following performs synchronous data replication in RDS?

- Amazon CloudFront running as a Multi-AZ deployment
- RDS Read Replica
- `RDS DB instance running as a Multi-AZ deployment`
- Amazon DynamoDB Read Replica

Exactly. Your understanding is almost there. For exam notes, keep it this simple:

### 1. RDS Multi-AZ = Standby

When you make an RDS DB **Multi-AZ**:

```text
Application
    ↓
Primary RDS
   AZ-1
    │
    │ synchronous replication
    ↓
Standby RDS
   AZ-2
```

Yes — **there is a standby**.

* Primary handles normal traffic.
* Standby is kept synchronized.
* Standby is **not normally used for read traffic**.
* If primary fails → AWS automatically promotes the standby.
* Main purpose = **High Availability / failover**.

🧠 **Multi-AZ = Standby + Synchronous + HA**

---

### 2. RDS Read Replica = Read copy

Read Replica is different:

```text
              asynchronous
Primary RDS ─────────────→ Read Replica
                              ↓
                         Read traffic
```

* Data is replicated **asynchronously**.
* Application can send **read queries** to the replica.
* Main purpose = **read scaling**.
* There can be a small replication lag.

🧠 **Read Replica = Read scaling + Asynchronous**

---

### 3. What about "DynamoDB Read Replica"?

There is **no DynamoDB Read Replica feature** like RDS.

DynamoDB uses different mechanisms.

For example, **DynamoDB Global Tables**:

```text
Region A DynamoDB
       ↕
   replication
       ↕
Region B DynamoDB
```

This is used when you need **multi-Region data replication** and applications in different Regions need local access.

So don't think:

> RDS Read Replica = DynamoDB Read Replica

They are different concepts.

---

### 4. And CloudFront?

CloudFront has **nothing to do with database replication**.

CloudFront:

```text
User → CloudFront Edge → Content
```

It's a **CDN/cache**, not a database.

And yes, **CloudFront doesn't have "Multi-AZ deployment"** like an RDS database does.

---

## ⭐ Your exam cheat sheet

| Service/feature            | What is it?           | Replication                 |
| -------------------------- | --------------------- | --------------------------- |
| **RDS Multi-AZ**           | Standby for HA        | **Synchronous**             |
| **RDS Read Replica**       | Copy for read scaling | **Asynchronous**            |
| **DynamoDB Global Tables** | Multi-Region DynamoDB | Replication between Regions |
| **CloudFront**             | CDN/cache             | Not database replication    |

### The easiest memory trick:

**Multi-AZ → "My primary dies, standby takes over."**

**Read Replica → "My reads are too heavy, send them to the copy."**

That's the distinction you should recognize immediately in SAA questions.
