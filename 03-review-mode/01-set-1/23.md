23. Question

Category: CSAA – Design Secure Architectures

A company uses an Application Load Balancer (ALB) for its public-facing multi-tier web applications. The security team has recently reported that there has been a surge of SQL injection attacks lately, which causes critical data discrepancy issues. The same issue is also encountered by its other web applications in other AWS accounts that are behind an ALB. An immediate solution is required to prevent the remote injection of unauthorized SQL queries and protect their applications hosted across multiple accounts.

As a Solutions Architect, what solution would you recommend?

- `Use AWS WAF and set up a managed rule to block request patterns associated with the exploitation of SQL databases, like SQL injection attacks. Associate it with the Application Load Balancer. Integrate AWS WAF with AWS Firewall Manager to reuse the rules across all the AWS accounts.`
- Use AWS Network Firewall to filter web vulnerabilities and brute force attacks using stateful rule groups across all Application Load Balancers on all AWS accounts. Refactor the web application to be less susceptible to SQL injection attacks based on the security assessment.
- Use Amazon GuardDuty and set up a managed rule to block request patterns associated with the exploitation of SQL databases, like SQL injection attacks. Associate it with the Application Load Balancer and utilize the AWS Security Hub service to reuse the managed rules across all the AWS accounts
- Use Amazon Macie to scan for vulnerabilities and unintended network exposure. Refactor the web application to be less susceptible to SQL injection attacks based on the security assessment. Utilize the AWS Audit Manager to reuse the security assessment across all AWS accounts.


Yes — your understanding of the **main problem is correct**. The important thing is to identify **what layer the attack is happening at**.

### 1. First understand the attack

Imagine:

```text
User
  ↓
Internet
  ↓
ALB
  ↓
Web Application
  ↓
SQL Database
```

A malicious user sends something like:

```text
' OR 1=1 --
```

or another SQL-injection payload as part of an HTTP request.

The application may accidentally pass that input to the SQL database as a query.

So the problem is:

> **Malicious HTTP request → SQL injection → application/database**

We need something that can inspect **HTTP requests** and block suspicious SQL-injection patterns **before they reach the application**.

That's exactly where **AWS WAF** fits.

---

## 2. AWS WAF — remember this

Think:

> **WAF = Web Application Firewall = HTTP/HTTPS protection**

It can inspect requests such as:

```text
GET /login?username=...
POST /search
POST /api/users
```

and block things like:

* SQL injection
* Cross-site scripting (XSS)
* malicious IP addresses
* suspicious request patterns
* excessive requests/rate abuse

And WAF can directly protect:

```text
CloudFront
    ↓
   WAF

ALB
    ↓
   WAF

API Gateway
    ↓
   WAF
```

For this question, the key phrase is:

> **SQL injection attacks**

So immediately think:

**AWS WAF → SQL injection managed rule**

---

## 3. What is AWSManagedRulesSQLiRuleSet?

AWS provides managed rules so you don't have to write all the SQL-injection detection logic yourself.

For example:

```text
Internet
   ↓
 AWS WAF
   ↓
SQLi Rule
   ↓
   ALB
   ↓
Application
   ↓
Database
```

If WAF detects a request matching SQL-injection patterns:

```text
❌ BLOCK
```

The request doesn't continue to the application.

That's why **WAF is the correct service**.

---

# 4. Now let's clean up the other services in your mind

You already know some of these, but let's create a very simple mental map.

### AWS WAF

**Question to ask:**

> "Is someone sending a malicious web/HTTP request?"

Think:

**WAF**

```text
HTTP/HTTPS
   ↓
 WAF
   ↓
 ALB / CloudFront / API Gateway
```

Examples:

* SQL injection
* XSS
* malicious web requests
* rate limiting

---

### AWS Network Firewall

This is a **network-level firewall for VPC traffic**.

Think:

> **Network Firewall = protect network traffic inside/through VPC**

For example:

```text
Internet
   ↓
VPC
   ↓
Network Firewall
   ↓
Private resources
```

It can inspect/filter network traffic using firewall rules.

Don't confuse:

```text
WAF              → Web/application requests
Network Firewall → Network traffic
```

For a question specifically saying **SQL injection against an ALB**, WAF is the stronger clue.

---

### Amazon GuardDuty

Think:

> **GuardDuty = threat detection**

It analyzes AWS activity and signals to identify suspicious or malicious behavior.

For example:

```text
Someone compromises an EC2 instance
        ↓
 suspicious activity
        ↓
    GuardDuty
        ↓
   finding/alert
```

GuardDuty is primarily **detecting threats**, not acting as the HTTP firewall that blocks SQL injection requests.

So:

**GuardDuty = "Something suspicious is happening."**

**WAF = "Block this malicious web request."**

---

### Amazon Macie

Your memory is correct.

Think:

> **Macie = sensitive data discovery/security in S3**

Especially:

```text
S3
 ↓
Macie
 ↓
PII / sensitive data
```

For example, Macie can help discover:

* names
* addresses
* credit-card-related data
* other sensitive/PII data

So:

**Macie → S3 + sensitive data**

Not SQL injection.

---

### AWS Firewall Manager

This one is important for **this question**.

Suppose your company has:

```text
Account A
   ALB
   WAF

Account B
   ALB
   WAF

Account C
   ALB
   WAF
```

Management says:

> "I want the same security rules across all our AWS accounts."

That's where **AWS Firewall Manager** becomes useful.

Think:

> **Firewall Manager = centrally manage security rules across multiple AWS accounts**

So the question gives you two clues:

### Clue 1

> SQL injection

→ **AWS WAF**

### Clue 2

> Other applications in other AWS accounts

→ **AWS Firewall Manager**

Therefore:

```text
                 AWS Firewall Manager
                         │
              centrally manages
                         ↓
       ┌─────────────────────────┐
       │                         │
     Account A                Account B
       │                         │
      WAF                       WAF
       │                         │
      ALB                       ALB
       │                         │
      App                       App
```

That's why the answer combines:

**AWS WAF + AWS Firewall Manager**

---

# 5. Your mental map should now be

| Service                  | Think                                           |
| ------------------------ | ----------------------------------------------- |
| **AWS WAF**              | Web/HTTP attacks                                |
| **AWS Network Firewall** | Network/VPC traffic                             |
| **GuardDuty**            | Threat detection                                |
| **Macie**                | Sensitive data/PII in S3                        |
| **Firewall Manager**     | Centrally manage security rules across accounts |
| **Security Hub**         | Central view of security findings               |
| **Inspector**            | Vulnerability scanning                          |
| **CloudTrail**           | API/activity logging                            |

A very useful distinction:

> **WAF blocks malicious web requests.**
> **GuardDuty detects suspicious activity.**
> **Macie discovers sensitive data.**
> **Network Firewall protects network traffic.**
> **Firewall Manager centrally manages security policies across accounts.**

---

## 6. And one important correction to your wording

You said:

> "someone has injected data in SQL server"

Almost think of it as:

**Someone is attempting SQL injection through the web application.**

The attack path is:

```text
Attacker
   │
   │ malicious HTTP request
   ↓
AWS WAF
   │
   │ ❌ SQL injection detected
   │
   X BLOCK
   │
   ↓
ALB
   ↓
Application
   ↓
SQL Database
```

The big idea is **stop the malicious request before it reaches the application/database**.

### Exam shortcut 🧠

When you see:

**SQL injection + ALB/CloudFront/API Gateway**

→ **WAF**

When you additionally see:

**multiple AWS accounts**

→ **Firewall Manager**

So for Q23:

> **WAF + SQLi managed rule + Firewall Manager across accounts = correct.**
