43. Question

Category: CSAA – Design Secure Architectures

A pharmaceutical company has resources hosted on both its on-premises network and in the AWS cloud. The company requires all Software Architects to access resources in both environments using on-premises credentials, which are stored in Active Directory, rather than through an Amazon Cognito identity pool.

In this scenario, which of the following can be used to fulfill this requirement?

- Set up SAML 2.0-Based Federation by using a Web Identity Federation.
- `Set up SAML 2.0-Based Federation by using a Microsoft Active Directory Federation Service.`
- Use IAM users
- Use Amazon VPC

Yes — this question becomes easy once you separate **authentication methods**. Don't memorize the long explanation. Think about **where the user's identity comes from**.

## 1. Amazon Cognito Identity Pool

**What is it?**

Cognito Identity Pool gives users **temporary AWS credentials** so they can access AWS resources.

Think:

```text
User
 ↓
Cognito
 ↓
Temporary AWS credentials
 ↓
S3 / DynamoDB / other AWS services
```

It is commonly used for **applications with end users**, such as:

> Mobile app user wants to upload a photo directly to S3.

Cognito can work with identities from different providers.

**Memory:**

> **Cognito Identity Pool = give application users temporary AWS access.**

---

## 2. Microsoft Active Directory Federation Services (AD FS)

AD FS is a Microsoft service that can act as an **Identity Provider (IdP)**.

Suppose your company already has:

```text
Company Active Directory
        ↓
      AD FS
        ↓
       AWS
```

Employees use their **existing corporate username/password** rather than creating separate IAM users.

For example:

> Bilal logs into company AD → AD FS authenticates Bilal → AWS trusts AD FS → Bilal gets temporary AWS access.

---

## 3. SAML Federation

This is the **communication/standard** used between the identity provider and AWS.

SAML = **Security Assertion Markup Language**

Think:

```text
Active Directory / AD FS
          ↓
      SAML assertion
          ↓
         AWS
          ↓
 Temporary AWS role/credentials
```

So:

**AD FS = identity provider**

**SAML = protocol/standard used for federation**

This is why the question says:

> **SAML 2.0-Based Federation using Microsoft AD FS**

That's the combination.

---

## 4. Web Identity Federation

This is different.

It is mainly about users authenticating through **external web identity providers**, historically things like:

```text
Google
Facebook
Login with Amazon
       ↓
Web Identity Federation
       ↓
AWS temporary credentials
```

So don't confuse it with your company's Active Directory.

---

# ⭐ The easiest comparison

| Concept                     | Think                                       |
| --------------------------- | ------------------------------------------- |
| **Cognito Identity Pool**   | App users → temporary AWS credentials       |
| **AD FS**                   | Company's Microsoft identity system         |
| **SAML Federation**         | Protocol connecting corporate IdP → AWS     |
| **Web Identity Federation** | External web/social identity provider → AWS |
| **IAM User**                | AWS-created individual user                 |

### 🧠 Exam shortcut

If question says:

> **"Employees use existing on-premises Active Directory credentials to access AWS"**

Immediately think:

**AD FS + SAML federation** ✅

If it says:

> **"Mobile/web application users need temporary AWS credentials"**

Think:

**Cognito Identity Pool** ✅

If it says:

> **"Users authenticate using Google/Facebook/etc."**

Think:

**Web Identity Federation** ✅

The key distinction is **corporate employees vs application users vs external identity providers**.
