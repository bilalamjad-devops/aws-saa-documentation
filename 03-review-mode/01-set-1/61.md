61. Question

Category: CSAA – Design Cost-Optimized Architectures

A financial services company plans to migrate its trading application from on-premises Microsoft Windows Server to Amazon Web Services (AWS).

The solution must ensure high availability across multiple Availability Zones and offer low-latency access to block storage.

Which of the following solutions will fulfill these requirements?

- Configure the trading application on Amazon EC2 Windows instances across two Availability Zones. Use Amazon Simple Storage Service (Amazon S3) for storage and configure cross-region replication to sync data between S3 buckets in each Availability Zone.
- Deploy the trading application on Amazon EC2 Windows Server instances across two Availability Zones. Use Amazon Elastic File System (Amazon EFS) to provide shared storage between the instances. Configure Amazon EFS with cross-region replication to sync data across Availability Zones.
- Deploy the trading application on Amazon EC2 Windows Server instances across two Availability Zones. Use Amazon FSx for Windows File Server for shared storage.
- `Configure the trading application on Amazon EC2 Windows Server instances across two Availability Zones. Use Amazon FSx for NetApp ONTAP to create a Multi-AZ file system and access the data via iSCSI protocol.`

Exactly — **FSx is confusing because AWS has several different FSx products**, and each is designed for a different workload.

Let's first decode **what Question 61 is actually asking**, then build the FSx map you can use in the exam.

## 1. What is the question really asking?

There are **3 important clues**:

> **Microsoft Windows Server**

> **High availability across multiple Availability Zones**

> **Low-latency access to block storage**

So translate it into:

```text
I have:
Windows application
       +
Need HA across AZs
       +
Need BLOCK storage
       +
Need very low latency
```

The key clue is **BLOCK STORAGE**.

That eliminates S3, EFS, and FSx for Windows File Server.

The answer is:

**FSx for NetApp ONTAP + iSCSI + Multi-AZ**

---

# 2. First understand the 3 types of storage

This is extremely important for SAA.

### Object storage

Think:

> "I have files/photos/videos/documents."

```text
S3
 ↓
objects
 ↓
photos
videos
documents
backups
```

S3 = **object storage**

---

### File storage

Think:

> "Multiple servers need to access the same shared folder."

```text
       Shared File System
       /      |       \
    EC2-1   EC2-2    EC2-3
```

Examples:

* EFS
* FSx for Windows File Server
* FSx for Lustre
* FSx for OpenZFS
* FSx for NetApp ONTAP

---

### Block storage

Think:

> "I want a disk/volume attached to a server."

```text
EC2
 |
 |---- Block Volume
 |
Disk
```

Example:

* EBS
* **FSx for NetApp ONTAP via iSCSI**

This distinction is the key to Question 61.

---

# 3. Now let's understand FSx

**Amazon FSx** is basically AWS's family of **managed file systems**.

But there are different FSx products because different applications need different file-system technologies.

Think:

```text
                    Amazon FSx
                       |
       ┌───────────────┼─────────────────┐
       ↓               ↓                 ↓
 Windows File      Lustre            NetApp ONTAP
 Server
       |
       |
     SMB
```

And there is also:

```text
FSx for OpenZFS
```

So don't memorize "FSx = one thing."

Memorize:

> **FSx is a family. The name after FSx tells you the use case.**

---

# 4. FSx for Windows File Server

This one is easy.

### Think:

> **Windows → SMB → shared files → Active Directory**

Example:

```text
Windows EC2 ──┐
Windows EC2 ──┼──> FSx for Windows File Server
Windows EC2 ──┘
```

It provides:

* Windows-compatible file storage
* SMB protocol
* Active Directory integration
* shared file storage
* Windows workloads

Excellent for things like:

> Windows file shares, Microsoft applications, SharePoint-style workloads.

### Exam clue:

If you see:

**Windows + SMB + Active Directory + shared files**

→ **FSx for Windows File Server**

---

# 5. EFS

You already have the basic idea.

### EFS = Elastic File System

Think:

> **Linux + shared file system**

```text
Linux EC2 ──┐
Linux EC2 ──┼──> EFS
Linux EC2 ──┘
```

EFS uses **NFS**.

So:

| Requirement  | Think |
| ------------ | ----- |
| Linux        | EFS   |
| Shared files | EFS   |
| NFS          | EFS   |
| Windows/SMB  | ❌ EFS |

That's why EFS is wrong in Question 61.

---

# 6. FSx for Lustre

This one is VERY important for your SAA exam.

Think:

> **Lustre = extremely high-performance parallel file system**

Especially:

* Machine learning
* HPC
* big data
* scientific computing
* high-performance workloads

For example:

```text
        Training Dataset
              ↓
       FSx for Lustre
      ↙      ↓       ↘
   EC2-1   EC2-2    EC2-3
      ↘      ↓       ↙
       Parallel access
```

Many compute instances can process data concurrently.

### Exam clue:

If you see:

**Machine Learning + HPC + parallel processing + very high performance**

→ **FSx for Lustre**

You saw this in Question 54.

---

# 7. FSx for OpenZFS

Think:

> **Linux/Unix + high-performance file system + OpenZFS**

It is useful when applications need features/performance associated with the OpenZFS file system.

For SAA, don't overcomplicate it.

Remember:

> **OpenZFS → OpenZFS workloads**

It's generally not the first answer when the question screams Windows + SMB/AD or ML + parallel processing.

---

# 8. FSx for NetApp ONTAP ⭐

This is the one Question 61 is testing.

FSx for NetApp ONTAP is more flexible.

It supports multiple protocols, including:

**NFS**

**SMB**

**iSCSI**

That last one is the important clue.

### iSCSI

iSCSI provides **block storage over a network**.

Think:

```text
Windows EC2
     |
     | iSCSI
     ↓
FSx for NetApp ONTAP
     |
     ↓
Block storage
```

Therefore:

> **Windows + block storage + iSCSI → FSx for NetApp ONTAP**

And the question specifically says **Multi-AZ**.

FSx for NetApp ONTAP supports **Multi-AZ file systems**, giving high availability across AZs.

Therefore:

```text
        AZ-A                    AZ-B
          |                       |
       EC2 Windows            EC2 Windows
          \                       /
           \                     /
            FSx for NetApp ONTAP
                  |
                iSCSI
                  |
            Block storage
```

That's why the answer wins.

---

# 9. Why FSx for Windows is NOT the answer?

This is the trap.

You see:

> Windows Server

and your brain says:

> FSx for Windows File Server!

But then you must continue reading.

The question says:

> **low-latency access to block storage**

FSx for Windows File Server provides **file storage**, primarily through SMB.

The requirement is **block storage**.

So:

```text
Windows + shared FILES
        ↓
FSx for Windows File Server
```

but:

```text
Windows + BLOCK storage + iSCSI
        ↓
FSx for NetApp ONTAP
```

That's the distinction.

---

# 10. Why S3 is wrong?

S3 is:

> **Object storage**

Not block storage.

```text
S3
 ↓
Object
 ↓
photo.jpg
document.pdf
video.mp4
```

The question needs:

> low-latency block storage

So S3 ❌.

---

# 11. Why EFS is wrong?

EFS is:

> **File storage for Linux workloads using NFS**

The question says:

> Windows

and:

> block storage

So EFS ❌ for **both reasons**.

---

### 🔥 The shortcuts

| If question says...              | Think...         |
| -------------------------------- | ---------------- |

| **Windows + SMB + AD**           | FSx Windows      |

---

## 13. One important correction to keep in your notes

Don't memorize:

> "EFS is for Linux and FSx is for Windows."

That's **too simplistic and can hurt you in the exam.**

Instead memorize:

> **EFS = NFS/shared file storage, primarily Linux workloads.**

> **FSx for Windows = SMB/Windows/AD.**

> **FSx for Lustre = high-performance parallel workloads.**

> **FSx for NetApp ONTAP = flexible enterprise storage, including iSCSI block access.**

That's a much safer SAA mental model.

The question is essentially saying:

> **"I have a Windows application, I need HA across AZs, and I specifically need very low-latency BLOCK storage. Which AWS managed storage can give me that?"**

Answer:

**FSx for NetApp ONTAP + iSCSI + Multi-AZ.**

And the biggest exam clue is:

> **BLOCK + iSCSI → NetApp ONTAP.**
