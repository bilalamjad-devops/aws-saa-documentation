1. Question

Category: CSAA – Design Resilient Architectures

A telecommunications company is planning to grant AWS Console access to its developers. Company policy requires the use of identity federation and role-based access control. Currently, the roles are already assigned via groups in the corporate Active Directory.

In this scenario, what combination of the following services can provide developers access to the AWS console? (Select TWO.)

- `AWS Directory Service AD Connector`
- `IAM Roles`
- AWS Directory Service Simple AD
- AWS Lambda
- IAM Groups

Yes — and this is actually a **very useful mistake** because the question is testing a distinction that is easy to mix up.

### What the question is really saying

The company already has:

* **Corporate Active Directory**
* Developers are already organized into **AD groups**
* They want **AWS Console access**
* They require **identity federation**
* They require **role-based access control**

So the architecture is:

**Corporate AD → AD Connector → IAM Roles → AWS Console**

### Why your answer was probably wrong

The trap is **IAM Groups vs IAM Roles**.

You may have thought:

> "Users are already in groups, so AWS IAM Groups should be used."

But there are **two completely different types of groups**:

| Service                 | What it manages                  |
| ----------------------- | -------------------------------- |
| **Corporate AD Groups** | Your company's users/groups      |
| **IAM Groups**          | IAM users inside AWS             |
| **IAM Roles**           | Temporary AWS permissions/access |

The question specifically says the developers' roles are **already assigned via groups in corporate AD**.

Therefore, we don't need to recreate those users as IAM Users or put them into IAM Groups.

Instead:

**AD Group → IAM Role**

For example:

```text
Corporate AD

Developers
├── Alice
├── Bob
└── Charlie

        ↓

AD Connector

        ↓

IAM Role
"DeveloperRole"

        ↓

AWS Console
```

The AD group members can assume the appropriate IAM role.

## The important distinction: AD Connector vs Simple AD

This is another common exam trap.

### AD Connector

Think:

> **"I already have Microsoft AD somewhere else; connect AWS to it."**

```text
Existing On-Prem AD
        ↓
   AD Connector
        ↓
       AWS
```

That's exactly this question.

### Simple AD

Think:

> **"I don't have an existing Microsoft AD; give me a simple directory in AWS."**

So **Simple AD is not the best answer** when the question explicitly says:

> "Currently, the roles are already assigned via groups in the corporate Active Directory."

---

# The SAA exam rule to remember

When you see:

### **Existing corporate/on-premises Active Directory**

→ **AD Connector**

### **Need AWS permissions for federated users**

→ **IAM Roles**

### **Need IAM users grouped together**

→ **IAM Groups**

### **Need a new/simple directory in AWS**

→ **Simple AD**

---

# Why this doesn't mean you're weak

You actually understood part of the question. The mistake is probably that you focused on:

> **"roles are already assigned via groups"**

and thought:

> "Groups → IAM Groups."

But the exam wants you to recognize that **corporate AD groups are not IAM Groups**.

That's exactly the kind of distinction SAA questions are designed to test.

### Your mental model should be:

**Federation question?**

First ask:

> **Where are my users?**

If they're already in **corporate AD**:

**AD Connector + IAM Roles**

If they're AWS IAM users:

**IAM Users + IAM Groups/Roles**

---

And one more important point: **don't memorize "AD Connector = IAM Roles" as an isolated pair.** Understand the flow:

> **Existing AD → connect it to AWS → federated users assume IAM Roles → access AWS Console**

That will help you solve variations of this question rather than just recognizing the answer.

Absolutely. Let's make these **very simple**, because these three are easy to confuse in SAA questions.

## 1. What is AD?

**AD = Active Directory**

Think of AD as your **company's employee directory + login system**.

For example, your company has:

```text
Company Active Directory

Employees
├── Ali
├── Ahmed
├── Bilal
└── Sara

Groups
├── Developers
├── Finance
└── HR
```

AD stores:

* Who are the employees?
* What username/password do they have?
* Which group do they belong to?
* What access should they get?

For example:

> Bilal belongs to the **Developers** group.

So AD is basically:

> **"The company's system for managing users, groups, and identities."**

Usually, when an exam says **corporate AD** or **on-premises Microsoft Active Directory**, imagine the company's existing employee login system.

---

# 2. What is AD Connector?

Now imagine your company already has AD **inside its own data center**.

You don't want to create another copy of all your employees inside AWS.

You want AWS to say:

> "Whenever someone tries to log in, I'll ask the company's existing AD."

That's what **AD Connector** does.

Think of it as a **bridge/connector between AWS and your existing AD**.

```text
Company
On-Premises
     
┌───────────────┐
│ Active        │
│ Directory     │
└───────┬───────┘
        │
        │ AD Connector
        ▼
┌───────────────┐
│     AWS       │
└───────────────┘
```

### Easy sentence:

> **AD Connector = Connect AWS to my existing AD.**

It doesn't replace your AD.

It doesn't become your new employee database.

It basically **lets AWS use your existing AD**.

---

# 3. What is Simple AD?

This one is different.

Suppose you **don't already have Microsoft AD**.

You say:

> "I need a small/basic directory in AWS."

AWS can provide **Simple AD**.

Think:

> **Simple AD = AWS gives me a basic directory.**

```text
AWS
│
└── Simple AD
     ├── Ali
     ├── Ahmed
     └── Bilal
```

You aren't connecting to an existing corporate AD.

You're creating a **new directory in AWS**.

---

# The easiest way to remember all three

| Term             | Think                                   |
| ---------------- | --------------------------------------- |
| **AD**           | Company's user/identity database        |
| **AD Connector** | Bridge to an **existing** AD            |
| **Simple AD**    | **New basic** directory provided in AWS |

### One-line memory trick:

> **Already have AD? → AD Connector**
> **Need a basic new directory? → Simple AD**

## Now connect this to Question 1

The question said:

> "roles are already assigned via groups in the **corporate Active Directory**."

That immediately tells you:

**Existing AD → AD Connector**

Then:

**AD users/groups → IAM Roles → AWS Console**

So the answer was:

**AD Connector + IAM Roles**

---

### One last important distinction

Don't confuse:

**AD Groups**

with

**IAM Groups**

They are different:

```text
Corporate AD
   │
   └── Developers group
          │
          ↓
     IAM Role
          │
          ↓
      AWS Console
```

Whereas:

```text
AWS IAM
   │
   └── IAM Group
         ├── IAM User 1
         ├── IAM User 2
         └── IAM User 3
```

For **federated corporate users**, think **IAM Roles**, not IAM Groups.

This distinction is worth remembering for the SAA exam.
