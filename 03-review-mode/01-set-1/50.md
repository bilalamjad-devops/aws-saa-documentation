50. Question

Category: CSAA – Design Secure Architectures

A newly hired Solutions Architect is assigned to manage a set of CloudFormation templates that are used in the company’s cloud architecture in AWS. The Architect accessed the templates and tried to analyze the configured IAM policy for an S3 bucket.

```json
{ 
 "Version": "2012-10-17", 
 "Statement": [ 
  { 
   "Effect": "Allow", 
   "Action": [ 
    "s3:Get*", 
    "s3:List*" 
  ], 
  "Resource": "*" 
 }, 
 { 
   "Effect": "Allow", 
   "Action": "s3:PutObject", 
   "Resource": "arn:aws:s3:::boracay/*" 
  } 
 ] 
}
```

What does the above IAM policy allow? (Select THREE.)


- `An IAM user with this IAM policy is allowed to write objects into the boracay S3 bucket.`
- `An IAM user with this IAM policy is allowed to read objects from all S3 buckets owned by the account.`
- An IAM user with this IAM policy is allowed to change access rights for the boracay S3 bucket.
- `An IAM user with this IAM policy is allowed to read objects from the boracay S3 bucket.`
- An IAM user with this IAM policy is allowed to read objects in the boracay S3 bucket but not allowed to list the objects in the bucket.
- An IAM user with this IAM policy is allowed to read and delete objects from the boracay S3 bucket.

Yes — this question becomes easy if you read an IAM policy as:

> **Action = what can I do?**
> **Resource = where can I do it?**

### 1. `Action`

These are the important ones:

| Action            | Meaning                                 |
| ----------------- | --------------------------------------- |
| `s3:Get*`         | **Read/get** S3 data                    |
| `s3:List*`        | **List** buckets/objects                |
| `s3:PutObject`    | **Upload/write an object**              |
| `s3:DeleteObject` | Delete an object — **not present here** |

The `*` is a wildcard.

So:

`Get*` → GetObject, GetBucket..., etc.
`List*` → ListBucket, ListObjects..., etc.

---

### 2. `Resource`

First statement:

```json
"Resource": "*"
```

This means **all applicable S3 resources**.

So the first statement says roughly:

> "You can GET and LIST S3 resources."

Therefore, the user can **read/list S3 data broadly**, including the `boracay` bucket.

---

Second statement:

```json
"Action": "s3:PutObject",
"Resource": "arn:aws:s3:::boracay/*"
```

The important part is:

```text
boracay/*
```

It means:

> **Objects inside the `boracay` bucket**

Therefore:

> User can **upload/write objects into `boracay`**.

---

### Now read the whole policy

```text
Get*       → READ
List*      → LIST
PutObject  → WRITE/UPLOAD
```

and:

```text
Resource "*"          → broadly/all applicable S3 resources
Resource "boracay/*"  → objects inside boracay bucket
```

So the three correct answers are:

✅ **Read objects from S3 buckets**
✅ **Write objects into `boracay`**
✅ **Read objects from `boracay`**

And importantly:

❌ **Delete?** No `s3:DeleteObject`
❌ **Change permissions?** No `s3:PutBucketPolicy`, `s3:PutObjectAcl`, etc.

### 🧠 Exam shortcut

When you see an IAM question, immediately look for:

**1. Action → WHAT?**
**2. Resource → WHERE?**

For this question:

> `Get` = read
> `List` = see/list
> `Put` = upload/write
> `Delete` = delete

That's the main concept you need to remember.
