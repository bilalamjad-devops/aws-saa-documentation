52. Question

Category: CSAA – Design Secure Architectures

A company is in the process of migrating their applications to AWS. One of their systems requires a database that can scale globally and handle frequent schema changes. The application should not have any downtime or performance issues whenever there is a schema change in the database. It should also provide a low latency response to high-traffic queries.

Which is the most suitable database solution to use to achieve this requirement?

- Redshift
- An Amazon Aurora database with Read Replicas
- An Amazon RDS instance in Multi-AZ Deployments configuration
- `Amazon DynamoDB`

Yes. Let’s keep the **certification-prep style** from now on: **what is the question testing → identify the clue → choose the service → eliminate the others.** No huge explanation unless something is genuinely confusing.

## What is Question 52 teaching you?

The question is basically asking:

> **“I need a database that can handle very high traffic, scale globally, and allow the data structure/schema to change frequently without downtime. Which database should I choose?”**

The biggest clue is:

**“frequent schema changes” + “low latency” + “high traffic” + “global scale”**

👉 This points to **DynamoDB**.

### First, remember the 4 databases

| Service      | Think                                              |
| ------------ | -------------------------------------------------- |
| **RDS**      | Traditional relational database                    |
| **Aurora**   | AWS's high-performance relational database         |
| **DynamoDB** | NoSQL, massive scale, flexible schema, low latency |
| **Redshift** | Data warehouse / analytics                         |

So your mental shortcut should be:

> **RDS / Aurora → relational**
> **DynamoDB → NoSQL**
> **Redshift → warehouse/analytics**

---

## Why DynamoDB here?

The important clue is:

### “Frequent schema changes”

Imagine a relational table:

```text
Users

ID | Name | Email | Age
```

Now you want to add:

```text
Address
Phone
SocialMedia
```

In a traditional relational database, you generally need to modify the table structure/schema.

DynamoDB is much more flexible.

One item could look like:

```text
ID: 101
Name: Bilal
Email: x@example.com
Age: 25
```

Another item can have additional attributes:

```text
ID: 102
Name: Ali
Email: y@example.com
Address: Islamabad
Phone: 12345
```

That's the **schema flexibility** the question is pointing toward.

# RDS vs Aurora vs DynamoDB

This is probably the most important part for your exam.

### RDS

AWS manages the database infrastructure, but you're using a traditional relational engine.

```text
RDS
 ↓
MySQL
PostgreSQL
Oracle
SQL Server
```

Think:

> **Managed relational database**

---

### Aurora

Aurora is also **relational**.

Think:

> **AWS's high-performance relational database**

It is compatible with:

* MySQL
* PostgreSQL

Aurora can have replicas, Multi-AZ architecture, etc.

---

### DynamoDB

Completely different category:

> **NoSQL database**

Think:

```text
Huge traffic
+ very low latency
+ flexible schema
+ massive scalability
        ↓
    DynamoDB
```

---

### Redshift

Different again:

> **Data warehouse**

Think:

```text
Application data
       ↓
   Redshift
       ↓
Analytics / BI / reporting
```

---

## Exam shortcut 🧠

When you see:

**“frequent schema changes”**

When you see:

**“complex relationships / SQL / transactions”**

**“data warehouse / OLAP / analytics”**

→ **Redshift**

When you see:

**“massive scale + millisecond/low-latency + NoSQL”**

→ **DynamoDB**

### For Question 52:

**Frequent schema changes** → NoSQL
