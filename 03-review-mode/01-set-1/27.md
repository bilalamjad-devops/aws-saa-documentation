27. Question

Category: CSAA – Design High-Performing Architectures

A company is using Amazon S3 to store frequently accessed data. When an object is created or deleted, the S3 bucket will send an event notification to the Amazon SQS queue. A solutions architect needs to create a solution that will notify the development and operations team about the created or deleted objects.

Which of the following would satisfy this requirement?

- Create a new Amazon SNS FIFO topic for the other team. Grant S3 permission to send the notification to the second SNS topic.
- Set up an Amazon SNS topic and configure two SQS queues to poll the SNS topic. Grant S3 permission to send notifications to SNS and update the bucket to use the new SNS topic.
- `Create an Amazon SNS topic and configure two SQS queues to subscribe to the topic. Grant S3 permission to send notifications to SNS and update the bucket to use the new SNS topic.`
- Set up another SQS queue for the other team. Grant S3 permission to send a notification to the second SQS queue.

Yes — **your thinking is correct**. 👍

The key idea in this question is:

> **S3 event notification → one destination → SNS → multiple subscribers**

### Think of it like this

You have an S3 bucket:

```text
S3 Bucket
   │
   │ Object created/deleted
   ▼
  SNS Topic
   │
   ├──► SQS Queue 1 → Development team
   │
   └──► SQS Queue 2 → Operations team
```

S3 can send its event notification to a destination such as:

* **SNS**
* **SQS**
* **Lambda**

But when you need **multiple independent consumers**, SNS is the useful middle layer.

### Why SNS?

SNS provides **fan-out**.

One message comes into SNS:

```text
                 ┌──► SQS 1
S3 ──► SNS ──────┼──► SQS 2
                 └──► Lambda
```

Every subscriber can receive the same notification.

### One important correction

Don't memorize it as:

> "S3 can only send to exactly one destination."

For the **exam concept**, think:

> **When you need multiple destinations/consumers for the same S3 event, use SNS as the fan-out layer.**

And remember:

**SNS = push**
**SQS = queue that consumers poll**

So the wrong answer saying:

> "SQS queues poll SNS"

is wrong because **you don't poll SNS**. The queues **subscribe to SNS**, and SNS pushes the messages into the queues.

### Easy exam pattern

If you see:

**S3 event → one consumer**

Think:

```text
S3 → SQS
```

or

```text
S3 → Lambda
```

If you see:

**S3 event → multiple consumers/teams**

Think:

```text
S3 → SNS → SQS/SQS/Lambda
```

That's the important concept from Question 27.
