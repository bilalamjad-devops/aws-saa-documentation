38. Question

Category: CSAA – Design Secure Architectures

A payment processing company plans to migrate its on-premises application to an Amazon EC2 instance. An IPv6 CIDR block is attached to the company’s Amazon VPC. Strict security policy mandates that the production VPC must only allow outbound communication over IPv6 between the instance and the internet but should prevent the internet from initiating an inbound IPv6 connection. The new architecture should also allow traffic flow inspection and traffic filtering.


What should a solutions architect do to meet these requirements?

- Launch the EC2 instance to a private subnet and attach a NAT Gateway to the VPC to allow outbound IPv6 communication to the internet. Use AWS Firewall Manager to set up the required rules for traffic inspection and traffic filtering.
- Launch the EC2 instance to a private subnet and attach AWS PrivateLink interface endpoint to the VPC to control outbound IPv6 communication to the internet. Use Amazon GuardDuty to set up the required rules for traffic inspection and traffic filtering.
- Launch the EC2 instance to a public subnet and attach an Internet Gateway to the VPC to allow outbound IPv6 communication to the internet. Use Traffic Mirroring to set up the required rules for traffic inspection and traffic filtering.
- `Launch the EC2 instance to a private subnet and attach an Egress-Only Internet Gateway to the VPC to allow outbound IPv6 communication to the internet. Use AWS Network Firewall to set up the required rules for traffic inspection and traffic filtering.`

Yes — **your understanding is correct**. For the exam, keep it this simple:

### The core idea

**IPv4 → NAT Gateway**
**IPv6 → Egress-Only Internet Gateway**

Why?

* **NAT Gateway** = lets private IPv4 instances go **out** to the internet, while blocking unsolicited inbound connections.
* **Egress-Only Internet Gateway** = does the same concept for **IPv6**.

So remember:

```text
IPv4 private EC2
      ↓
 NAT Gateway
      ↓
  Internet
```

```text
IPv6 EC2
      ↓
Egress-Only IGW
      ↓
  Internet
```

### Then why Network Firewall?

This question has **two separate requirements**:

1. **Allow outbound IPv6 but block inbound IPv6** → **Egress-Only IGW**
2. **Inspect and filter traffic** → **AWS Network Firewall**

Think of Network Firewall as an actual **security checkpoint** for network traffic.

It can:

* inspect traffic
* allow/block traffic according to rules
* detect/block certain network threats
* perform stateful traffic filtering
* provide intrusion prevention capabilities

So:

```text
EC2
 │
 │ IPv6 outbound
 ↓
Network Firewall
 │
 ↓
Egress-Only IGW
 │
 ↓
Internet
```

### Don't confuse these 4 services

| Service                  | Simple meaning                                                               |
| ------------------------ | ---------------------------------------------------------------------------- |
| **NAT Gateway**          | IPv4 private → Internet                                                      |
| **Egress-Only IGW**      | IPv6 outbound → Internet, blocks inbound initiation                          |
| **AWS Network Firewall** | Inspect + filter network traffic                                             |
| **Firewall Manager**     | Centrally manage/apply firewall rules across multiple AWS accounts/resources |

And:

**GuardDuty ≠ firewall.**
GuardDuty mainly **detects threats/suspicious activity**. It doesn't sit in the traffic path and filter traffic like Network Firewall.

**Traffic Mirroring ≠ firewall.**
It **copies traffic** so another security/monitoring appliance can inspect it. It doesn't itself block traffic.

### Exam shortcut 🧠

If you see:

> **IPv6 + outbound only**

→ **Egress-Only Internet Gateway**

If you see:

> **traffic inspection + traffic filtering**

→ **AWS Network Firewall**

If you see:

> **centralized firewall management across accounts**

→ **AWS Firewall Manager**

That's really all you need to retain for this question.
