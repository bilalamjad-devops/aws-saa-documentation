63. Question

Category: CSAA – Design Secure Architectures

A tech company that you are working for has undertaken a Total Cost Of Ownership (TCO) analysis evaluating the use of Amazon S3 versus acquiring more storage hardware. The result was that all 1200 employees would be granted access to use Amazon S3 for the storage of their personal documents.

Which of the following will you need to consider so you can set up a solution that incorporates a single sign-on feature from your corporate AD or LDAP directory and also restricts access for each individual user to a designated user folder in an S3 bucket? (Select TWO.)

- `Set up a Federation proxy or an Identity provider, and use AWS Security Token Service to generate temporary tokens.`
- Use 3rd party Single Sign-On solutions such as Atlassian Crowd, OKTA, OneLogin and many others.
- `Configure an IAM role and an IAM Policy to access the bucket.`
- Map each individual user to a designated user folder in S3 using Amazon WorkDocs to access their personal documents.
- Set up a matching IAM user for each of the 1200 users in your corporate directory that needs access to a folder in the S3 bucket.

Yes — you already understand most of the pieces. The **main thing Question 63 is testing is:**

> **"1200 employees already exist in corporate AD/LDAP. How can they use S3 with SSO without creating 1200 IAM users, while restricting each employee to their own folder?"**

The answer is basically **Federation + STS + IAM Role/Policy**.

---

# 1. First understand the problem

Imagine the company has:

```text
Corporate network

AD / LDAP
   |
   ├── Bilal
   ├── Ali
   ├── Ahmed
   ├── Sara
   └── ...1200 employees
```

The company wants these employees to access:

```text
S3 Bucket
   |
   ├── /Bilal/
   ├── /Ali/
   ├── /Ahmed/
   ├── /Sara/
   └── ...
```

And they want:

### Requirement 1 — SSO

Employees should use their **existing corporate username/password**.

They shouldn't have:

```text
Corporate password
+
AWS IAM password
```

They want:

```text
Corporate AD login
       ↓
      AWS
       ↓
      S3
```

That's **federated access / SSO**.

---

### Requirement 2 — Don't create 1,200 IAM users

They don't want:

```text
IAM Users

Bilal
Ali
Ahmed
Sara
...
1200 users
```

Instead, existing corporate identities should be used.

---

### Requirement 3 — Each employee gets their own S3 folder

For example:

```text
S3 Bucket
│
├── Bilal/
│    ├── CV.pdf
│    └── photo.jpg
│
├── Ali/
│    ├── document.pdf
│    └── resume.pdf
│
└── Ahmed/
     └── report.pdf
```

Bilal should **not** be able to access:

```text
Ali/
Ahmed/
```

---

# 2. What is AD?

**AD = Active Directory.**

Microsoft's directory service commonly used by organizations to manage:

* users
* passwords
* computers
* groups
* permissions

Example:

```text
Company AD

Users:
Bilal
Ali
Ahmed
Sara

Groups:
Developers
Finance
HR
Architects
```

So when Question 63 says:

> "corporate AD"

think:

> **The company's existing user database.**

---

# 3. What is LDAP?

**LDAP = Lightweight Directory Access Protocol.**

It's a protocol used to communicate with directory services.

Very simplified:

```text
Application
     |
    LDAP
     ↓
Directory
     |
Users / Groups / Credentials
```

AD can support LDAP.

So for the exam, you can roughly think:

> **AD = directory system**

> **LDAP = protocol used to communicate with directory services**

Don't confuse LDAP with S3 or IAM. They solve completely different problems.

---

# 4. What is Federation?

This is the BIG concept.

Normally, without federation:

```text
Employee
   ↓
AWS IAM User
   ↓
AWS
```

You would have to create AWS identities.

But with federation:

```text
Employee
   ↓
Corporate AD
   ↓
Federation
   ↓
AWS
```

AWS trusts the company's identity system.

So the employee can use their **existing corporate identity**.

### Simple definition:

> **Federation = allowing users from an external identity system to access AWS without creating separate IAM users for them.**

---

# 5. What is a Federation Proxy / Identity Provider?

This part can sound complicated.

Think of an **Identity Provider (IdP)** as:

> **The system that says "Yes, I know this person and they are authenticated."**

For example:

```text
Employee
   ↓
Corporate AD
   ↓
Identity Provider
   ↓
AWS
```

The IdP handles authentication.

Examples include:

* AD FS
* Okta
* other SAML-compatible identity providers

In Question 63, the company already has corporate AD/LDAP.

So we can connect that identity system to AWS using federation.

---

# 6. Where does SAML come in?

You saw SAML in Question 43.

**SAML = Security Assertion Markup Language.**

You don't need to get lost in the name.

Think:

> **SAML is a standard used to exchange authentication information between the corporate identity provider and AWS.**

For example:

```text
Employee
   ↓
Corporate AD
   ↓
AD FS / IdP
   ↓
SAML assertion
   ↓
AWS
```

AWS can then trust that authentication.

---

# 7. Now AWS STS enters the picture ⭐

You are correct:

> **STS gives temporary credentials.**

More specifically:

**AWS Security Token Service (STS)** issues **temporary AWS credentials**.

Think:

```text
Employee authenticates
        ↓
Federation
        ↓
STS
        ↓
Temporary AWS credentials
        ↓
S3
```

Instead of giving Bilal permanent AWS access keys, STS gives temporary credentials.

For example, conceptually:

```text
Temporary credentials
    ↓
Valid for limited time
    ↓
Access S3
    ↓
Expire
```

This is much better for federated users than creating permanent IAM users.

---

# 8. What is the IAM Role doing?

This is another important piece.

The **IAM Role** defines:

> "What is this person allowed to do?"

For example:

```text
IAM Role
   ↓
Allow S3 access
   ↓
Bucket: company-documents
```

Then an IAM policy can restrict the user to their own folder.

For example, conceptually:

```text
Bilal
   ↓
IAM Role
   ↓
Policy
   ↓
S3/company-documents/Bilal/*
```

While Ali gets:

```text
Ali
   ↓
IAM Role
   ↓
Policy
   ↓
S3/company-documents/Ali/*
```

So the role/policy handles **authorization**.

---

# 9. Authentication vs Authorization

This is VERY important for your SAA exam.

### Authentication

> **Who are you?**

Example:

```text
AD:
"Yes, this is Bilal."
```

### Authorization

> **What are you allowed to do?**

Example:

```text
IAM Policy:
"Bilal can access only:

company-documents/Bilal/*
"
```

So:

| Concept        | Question                    |
| -------------- | --------------------------- |
| Authentication | **Who are you?**            |
| Authorization  | **What can you access/do?** |

AD/IdP helps with authentication.

IAM roles/policies help determine AWS authorization.

---

# 10. What does "3rd party SSO" mean?

Examples in the question:

* Okta
* OneLogin
* Atlassian Crowd

These are identity/SSO products.

They can be used to provide SSO.

For example:

```text
Employee
   ↓
Okta
   ↓
AWS
   ↓
S3
```

But **this particular question doesn't require them**.

Why?

Because AWS's federation capabilities can already solve the requirement.

So don't think:

> "SSO = must use Okta."

No.

SSO is the **concept**.

Okta is **one possible product** that can implement it.

---

# 11. Why not create 1,200 IAM users?

This is an important exam clue.

Question says:

> **1200 employees**

and they already have corporate identities.

If you create:

```text
IAM User 1
IAM User 2
IAM User 3
...
IAM User 1200
```

you've created unnecessary administrative overhead.

Instead:

```text
Corporate AD
     ↓
Federation
     ↓
STS temporary credentials
     ↓
IAM Role
     ↓
S3
```

Much better.

---

# 12. What is the question's complete architecture?

Now put everything together:

```text
                 COMPANY
                    │
                    ↓
              Corporate AD
                    │
                    ↓
            Identity Provider
             / Federation
                    │
                 SAML
                    │
                    ↓
                  AWS
                    │
                    ↓
                   STS
                    │
          Temporary credentials
                    │
                    ↓
                IAM Role
                    │
                    ↓
               IAM Policy
                    │
                    ↓
                 Amazon S3
                    │
          ┌─────────┼─────────┐
          ↓         ↓         ↓
       Bilal/     Ali/      Ahmed/
```

The policy can make sure each person accesses only their designated prefix/folder.

---

# 13. Now look at the answers

### ✅ Answer 1

> Set up a Federation proxy or Identity Provider + AWS STS temporary tokens.

Correct.

Why?

Because this gives you:

**Corporate identity → federation → temporary AWS credentials**

---

### ✅ Answer 2

> Configure an IAM role and IAM policy.

Correct.

Why?

Because you need to determine:

> **What S3 resources is each user allowed to access?**

---

### ❌ 3rd-party SSO

Possible in the real world, but **not necessary** for this question.

---

### ❌ WorkDocs

Unrelated to the federation requirement.

---

### ❌ 1,200 IAM users

Exactly what the architecture is trying to avoid.

If you see:

**"Existing corporate AD + SSO + AWS access"**

→ **Federation / SAML**

If you see:

**"temporary credentials for federated users"**

→ **STS**

**"what can the user access?"**

→ **IAM Role + IAM Policy**

**"1200 employees already exist in corporate directory; don't create IAM users"**
