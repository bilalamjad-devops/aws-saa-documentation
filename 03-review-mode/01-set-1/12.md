Category: CSAA – Design Secure Architectures

A government agency plans to store confidential tax documents on AWS. Due to the sensitive information in the files, the Solutions Architect must restrict the data access requests made to the storage solution to a specific Amazon VPC only. The solution should also prevent the files from being deleted or overwritten to meet the regulatory requirement of having a write-once-read-many (WORM) storage model.

Which combination of the following options should the Architect implement? (Select TWO.)


- Store the tax documents in the Amazon S3 Glacier Instant Retrieval storage class. Use the PutBucketPolicy API to apply a bucket policy that restricts access requests to a specific VPC.
- `Configure an Amazon S3 Access Point for the S3 bucket to restrict data access to a particular VPC only.`
- Enable Object Lock but disable Object Versioning on the new Amazon S3 bucket to comply with the write-once-read-many (WORM) storage model requirement.
- Set up a new Amazon S3 bucket to store the tax documents and integrate it with AWS Network Firewall. Configure the Network Firewall to only accept data access requests from a specific VPC.
- `Create a new Amazon S3 bucket with the S3 Object Lock feature enabled. Store the documents in the bucket and set the Legal Hold option for object retention.`

Absolutely. Think of **S3 Access Point** as a **special doorway into an S3 bucket**.

Normally, you access an S3 bucket directly:

```text
Application → S3 Bucket
```

With Access Points:

```text
Application → S3 Access Point → S3 Bucket
```

The important part is that **each doorway can have its own permissions and network restrictions**.

### Simple example

Imagine a company has one bucket:

```text
company-data
├── finance/
├── HR/
├── marketing/
└── analytics/
```

Different teams need different access.

You could create:

```text
Finance Access Point
        ↓
   S3 Bucket
        ↓
    finance/

HR Access Point
        ↓
   S3 Bucket
        ↓
      HR/

Analytics Access Point
        ↓
   S3 Bucket
        ↓
   analytics/
```

Each Access Point can have its own **access policy**.

### Why did AWS create Access Points?

Imagine a huge company with **hundreds of applications and teams** accessing the same S3 bucket.

Instead of making one giant complicated bucket policy:

> "Allow this application, deny that application, allow this VPC, deny that account..."

You can create separate access points:

```text
Application A → Access Point A → Bucket
Application B → Access Point B → Bucket
Application C → Access Point C → Bucket
```

Each doorway has its own rules.

---

## The important SAA exam point

An S3 Access Point can have a **VPC restriction**.

For example:

```text
VPC A
  │
  ↓
S3 Access Point
  │
  ↓
S3 Bucket
```

You can configure the Access Point to accept requests **only from VPC A**.

So if the question says:

> "Allow access to S3 only from a specific VPC"

your brain should immediately think:

**S3 Access Point** ✅

---

### Don't confuse these three

This is especially important for your SAA:

| Requirement                                        | Think               |
| -------------------------------------------------- | ------------------- |
| Private connection from VPC to S3                  | **S3 VPC Endpoint** |
| Control access through a specific S3 doorway / VPC | **S3 Access Point** |
| Prevent deletion/overwrite                         | **S3 Object Lock**  |

For example:

**Private EC2 → S3**

```text
EC2 in VPC
    ↓
S3 VPC Endpoint
    ↓
S3
```

**Restrict S3 access to a particular VPC using an access point**

```text
VPC
 ↓
S3 Access Point
 ↓
S3 Bucket
```

Both can involve a VPC, but they're solving **different problems**.

That's a very useful distinction for the exam.

Yes — **that is one common use case**, but there's one important correction:

**Access Points are not the folders themselves.** They are separate **access endpoints/doorways** to the same S3 bucket, and each Access Point can restrict which objects/prefixes a team can access.

For example:

```text
S3 Bucket: company-data
│
├── finance/
├── HR/
├── marketing/
└── analytics/
```

You could have:

```text
Finance Team
     ↓
Finance Access Point
     ↓
company-data/finance/*


HR Team
     ↓
HR Access Point
     ↓
company-data/HR/*


Marketing Team
     ↓
Marketing Access Point
     ↓
company-data/marketing/*
```

So the **bucket is still one bucket**, while the Access Points provide different controlled ways to access it.

### But remember for SAA

Don't think:

> "Access Point = folder"

Think:

> **Access Point = controlled doorway to an S3 bucket.**

The doorway can have its own **permissions and network restrictions**.

For example, an Access Point can say:

> "Only requests coming from VPC-A can use this doorway."

That's exactly why it was the correct answer in your Question 12.

And if the question instead says:

> "EC2 in a private subnet needs to privately access S3 without Internet/NAT"

think **S3 VPC Endpoint**, not Access Point.

### Requirement 2: "Nobody can delete or overwrite the documents"

This is the **WORM** requirement.

WORM means:

> **Write Once, Read Many**

In simple words:

```text
Write document
      ↓
    LOCK 🔒
      ↓
Read ✅
Read ✅
Read ✅

Delete ❌
Overwrite ❌
```

For this, think:

> **S3 Object Lock**

So:

> **WORM / prevent deletion or overwrite → S3 Object Lock**

---

# Put the two together

```text
                 Specific VPC
                     │
                     ↓
             S3 Access Point
                     │
                     ↓
                S3 Bucket
                     │
              🔒 Object Lock
                     │
                     ↓
              Tax Documents
```

Therefore:

**1. S3 Access Point** → controls **WHERE requests can come from**

**2. S3 Object Lock** → controls **whether objects can be modified/deleted**

## One important thing: Legal Hold

The answer specifically says:

> "set the Legal Hold option"

Think of Legal Hold as:

> **"Don't delete this object until I explicitly remove the hold."**

It's useful for regulatory/legal situations where you don't necessarily know the exact retention period.

There are two important Object Lock concepts you'll see:

### Retention period

Example:

> "This document cannot be deleted/overwritten for 7 years."

```text
2026 ─────────────────── 2033
       🔒 LOCKED
```

### Legal Hold

Example:

> "Keep this document locked until the legal/regulatory case is finished."

```text
Legal Hold ON
     ↓
Delete ❌
Overwrite ❌
     ↓
Legal Hold OFF
     ↓
Normal rules apply
```

---

### And remember Object Lock + Versioning

For the exam:

> **S3 Object Lock requires S3 Versioning.**

So don't choose an answer saying:

> Object Lock + disable Versioning ❌

The mental shortcut I want you to build is:

| Requirement                             | AWS service/feature       |
| --------------------------------------- | ------------------------- |
| Access S3 only from a specific VPC      | **S3 Access Point**       |
| WORM                                    | **S3 Object Lock**        |
| Prevent deletion/overwrite for a period | **Object Lock retention** |
| Don't delete until explicitly released  | **Legal Hold**            |
| Object Lock requirement                 | **Versioning enabled**    |

So yes, your interpretation is correct:

> **"The documents are confidential, so access must be restricted to the VPC; and because they're regulatory documents, they must not be overwritten or deleted."**

That's exactly what the question is asking.
