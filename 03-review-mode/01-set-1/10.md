10. Question

Category: CSAA – Design Resilient Architectures

A logistics company plans to automate its order management application. The company wants to use SFTP file transfer for uploading business-critical documents. Since the files are confidential, encryption at rest is required, and high availability must be ensured. Additionally, each file must be automatically deleted one month after creation.

Which of the following options should be implemented to meet the company’s requirements with the least operational overhead?

- Create an Amazon S3 bucket with encryption enabled. Configure AWS Transfer for SFTP to securely upload files to the S3 bucket. Configure the retention policy on the SFTP server to delete files after a month.
- Create an Amazon Elastic File System (Amazon EFS) and enable encryption. Configure AWS Transfer for SFTP to securely upload files to the EFS file system. Apply an EFS lifecycle policy to delete files after 30 days.
- Provision an Amazon EC2 instance and install the SFTP service. Mount an encrypted Amazon EFS file system on the EC2 instance to store the uploaded files. Add a cron job to delete the files older than a month.
- `Create an Amazon S3 bucket with encryption enabled. Launch an AWS Transfer for SFTP endpoint to securely upload files to the S3 bucket. Configure an S3 lifecycle rule to delete files after a month.`


Yes — **your understanding is basically correct**, but there is one important extra requirement: **the company specifically wants clients to upload files using SFTP**.

Let's break it down.

## 1. What does SFTP mean?

**SFTP = SSH File Transfer Protocol.**

It's a secure way for a user/application to transfer files.

Think of someone at the company having:

```text
invoice.pdf
contract.pdf
customer-data.csv
```

They want to upload these files to AWS using an SFTP client.

Instead of:

```text
User → S3 directly
```

they want:

```text
User
  ↓ SFTP
AWS Transfer Family
  ↓
S3
```

AWS Transfer Family provides the **SFTP endpoint**. You don't have to build and maintain your own SFTP server.

---

# 2. What are the requirements?

The question gives you **four requirements**:

### Requirement 1 — SFTP

> "use SFTP file transfer"

Therefore:

**AWS Transfer Family**

---

### Requirement 2 — Store files

Where should the files go?

**S3**

```text
AWS Transfer Family
        ↓
       S3
```

---

### Requirement 3 — Encryption at rest

The files are confidential.

So enable **S3 encryption**.

Conceptually:

```text
S3
 └── Encryption at rest
```

The files are encrypted while stored in S3.

---

### Requirement 4 — Delete after one month

This is where **S3 Lifecycle Rules** come in.

```text
File uploaded
     ↓
30 days
     ↓
S3 Lifecycle
     ↓
Delete object
```

You don't need a cron job.

You don't need Lambda.

You don't need an EC2 server.

---

# Therefore the architecture is:

```text
                SFTP Client
                     │
                     │ SFTP
                     ↓
          AWS Transfer Family
                     │
                     ↓
              Amazon S3 Bucket
               🔐 Encryption
                     │
                     │
             S3 Lifecycle Rule
                     │
                  30 days
                     ↓
                  DELETE
```

That's why the correct answer is:

> **S3 + encryption + AWS Transfer for SFTP + S3 Lifecycle rule**

---

## The important distinction

You said:

> "the company wants the data should be encrypted what are are in s3, and we should enable lifecycle to delete data after 30 days"

**Correct.** 👍

But don't forget:

> **They also explicitly require SFTP.**

So whenever you see:

**"We need SFTP to upload files to AWS"**

your brain should immediately say:

> **AWS Transfer Family**

And when you see:

**"Automatically delete S3 objects after X days"**

think:

> **S3 Lifecycle expiration rule**

---

## Why not EFS?

This is a common exam trap.

EFS lifecycle means:

```text
Standard → Infrequent Access
```

It does **NOT** mean:

```text
30 days → DELETE
```

S3 Lifecycle can actually **expire/delete objects**.

So:

**S3 Lifecycle = transition OR expiration**

**EFS Lifecycle = storage-class tiering, not deletion**

---

## Why not EC2 + SFTP?

You *could* build:

```text
EC2
 └── SFTP server
       ↓
      EFS
```

and then run:

```text
cron → delete files older than 30 days
```

But now **you manage the server**.

AWS Transfer Family removes that operational burden.

### SAA exam pattern

When the question says:

> **SFTP + S3 + least operational overhead**

think:

**AWS Transfer Family → S3**

Then add whatever S3 feature the question asks for:

> **Encryption → S3 encryption**

> **Delete after 30 days → S3 Lifecycle**

That pattern is worth remembering.
