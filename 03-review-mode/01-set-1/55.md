55. Question

Category: CSAA – Design Resilient Architectures

A company plans to migrate its on-premises workload to AWS. The current architecture is composed of a Microsoft SharePoint server that uses a Windows shared file storage. The Solutions Architect needs to use a cloud storage solution that is highly available and can be integrated with Active Directory for access control and authentication, and must be accessible from on-premises via a direct connection.

Which of the following options can satisfy the given requirement?

- Create a Network File System (NFS) file share using AWS Storage Gateway.
- `Provision an Amazon FSx for Windows File Server file system and join it to an AWS Active Directory domain.`
- Create a file system using Amazon EFS and join it to an Active Directory domain.
- Launch an Amazon EC2 Windows Server to mount a new Amazon S3 bucket as a file volume.

Yes. This question is mainly testing whether you can recognize **Windows file storage + Active Directory + on-premises connectivity**.

### 1. What is the question asking?

The company currently has:

**SharePoint → Windows Server → Windows shared file storage**

They want to move the file storage to AWS, but they still need:

1. **Highly available storage**
2. **Windows-compatible file sharing**
3. **Active Directory authentication/access control**
4. **Access from on-premises through a Direct Connect/private connection**

So your brain should immediately think:

> **Windows + shared files + AD → FSx for Windows File Server**

That is the key clue.

# 3. NFS vs SMB — VERY important

This is one of those SAA concepts you should memorize.

### NFS

**NFS = Network File System**

Mostly associated with:

> **Linux/Unix**

Example:

```text
Linux EC2
    ↓
   NFS
    ↓
Shared files
```

### SMB

**SMB = Server Message Block**

Mostly associated with:

> **Windows**

Example:

```text
Windows Server
      ↓
     SMB
      ↓
Shared files
```

So:

| Protocol | Think   |
| -------- | ------- |
| **NFS**  | Linux   |
| **SMB**  | Windows |

When you see:

> Windows + shared file system

your first thought should be:

> **SMB**

# 4. What is Amazon FSx for Windows File Server?

This is the AWS service specifically designed for this type of requirement.

Think:

> **FSx for Windows = managed Windows file server in AWS**

It supports:

* Windows
* SMB
* Active Directory
* Windows permissions
* shared file storage
* concurrent access
* high availability

So:

```text
Windows users
      ↓
 Active Directory
      ↓
FSx for Windows File Server
      ↓
    SMB
      ↓
   Files
```

This is why the answer is:

> **Provision Amazon FSx for Windows File Server and join it to Active Directory.**

# 5. Why does Active Directory matter?

Imagine your company has:

```text
AD users:

Ali
Bilal
Ahmed
Sara
```

You can have permissions such as:

```text
Finance folder
   ↓
Finance AD Group → Read/Write

HR folder
   ↓
HR AD Group → Read/Write
```

So users don't need completely separate AWS identities just to access files.

Their existing corporate identity can control access.

That's why the question specifically mentions:

> **Active Directory for access control and authentication**

That's another huge clue for **FSx for Windows**.

# 6. What about AWS Storage Gateway?

This is where the question tries to confuse you.

AWS Storage Gateway can provide file storage interfaces and can connect on-premises environments with AWS storage.

For example:

```text
On-premises
     ↓
Storage Gateway
     ↓
     AWS
```

It can provide **NFS** and **SMB** file shares depending on the gateway configuration.

So Storage Gateway isn't inherently "wrong" for every Windows scenario.

But in **this particular question**, the expected solution is the managed Windows file system with AD integration:

> **FSx for Windows File Server**

The answer explanation you pasted is also emphasizing that **NFS is primarily associated with Linux**, whereas the requirement is specifically a Windows shared file environment.

---

# 7. Why EFS is wrong?

Amazon EFS is essentially:

> **managed shared file storage for Linux workloads**

Think:

```text
Linux EC2
   ↓
  NFS
   ↓
  EFS
```

It is not the natural choice for:

```text
Windows + SMB + Active Directory
```

So remember:

**EFS → Linux/NFS**

**FSx Windows → Windows/SMB/AD**

---

# 8. Why S3 is wrong?

S3 is:

> **Object storage**

Not a traditional Windows shared file system.

Think:

```text
S3
 ↓
Objects
 ↓
Photos / videos / backups / documents
```

Whereas:

```text
FSx Windows
 ↓
Files + folders
 ↓
Windows permissions + SMB
```

The question wants a **file system**, not object storage.

---

# 9. And what does "accessible from on-premises via a direct connection" mean?

This means the company wants something like:

```text
                    AWS
                     |
              FSx for Windows
                     |
                 VPC Network
                     |
              Direct Connect
                     |
             On-premises network
                     |
             Windows/SharePoint
```

AWS Direct Connect provides a dedicated network connection between the company's on-premises environment and AWS.

So don't confuse:

**Direct Connect = connectivity**

with:

**FSx = storage**

They solve different problems.
