18. Question

Category: CSAA – Design High-Performing Architectures

A healthcare organization wants to build a system that can predict drug prescription abuse. The organization will gather real-time data from multiple sources, which include Personally Identifiable Information (PII). It’s crucial that this sensitive information is anonymized prior to landing in a NoSQL database for further processing.

Which solution would meet the requirements?

- `Ingest real-time data using Amazon Kinesis Data Stream. Use an AWS Lambda function to anonymize the PII, then store it in Amazon DynamoDB.`
- Create a data lake in Amazon S3 and use it as the primary storage for patient health data. Use an S3 trigger to run an AWS Lambda function that performs anonymization. Send the anonymized data to Amazon DynamoDB.
- Stream the data in an Amazon DynamoDB table. Enable DynamoDB Streams, and configure an AWS Lambda function with AmazonDynamoDBFullAccess permissions to perform anonymization on newly written items.
- Deploy an Amazon Data Firehose stream to capture and transform the streaming data. Deliver the anonymized data to Amazon Redshift for analysis.

Yes — **your understanding of the question is correct.** The key phrase is:

> **PII must be anonymized BEFORE it lands in the NoSQL database.**

Let's build this into your mental model.

## 1. What is the question actually saying?

The healthcare organization receives real-time data from many sources.

For example, raw data might look like:

```text
Patient: Bilal
CNIC: 12345-678
Drug: Oxycodone
Prescription: 10 tablets
```

They **do NOT want this personal information stored in DynamoDB**.

They want:

```text
Raw data
   ↓
Remove/anonymize PII
   ↓
Safe data
   ↓
DynamoDB
```

For example:

```text
Patient: USER_8271
Drug: Oxycodone
Prescription: 10 tablets
```

So the architecture is:

```text
Multiple data sources
        ↓
Kinesis Data Streams
        ↓
AWS Lambda
(anonymize PII)
        ↓
Amazon DynamoDB
(NoSQL)
```

That's why **Answer 1 is correct**.

---

# 2. What is Kinesis Data Streams?

Your statement:

> "Kinesis is used for data processing."

Close, but let's make it more precise.

**Kinesis Data Streams is primarily for collecting/ingesting real-time streaming data.**

Think:

```text
Many sources
    ↓
    ↓
    ↓
Kinesis Data Streams
    ↓
Lambda / applications
    ↓
Processing
```

Examples of streaming data:

* website clicks
* application logs
* IoT sensor data
* financial transactions
* healthcare events
* real-time activity

So don't think:

> Kinesis = database

Instead:

> **Kinesis Data Streams = pipeline/channel carrying real-time data.**

---

# 3. Very important: Kinesis Stream ≠ DynamoDB Stream

You noticed something very important:

> "two terms are same name: DynamoDB Stream and Kinesis Stream."

They sound similar, but **they are different things**.

### Kinesis Data Stream

You use it to **ingest your own streaming data**.

```text
Source
  ↓
Kinesis Data Stream
  ↓
Lambda
  ↓
DynamoDB
```

### DynamoDB Stream

It automatically records **changes that already happened inside DynamoDB**.

```text
Application
    ↓
DynamoDB
    ↓
DynamoDB Stream
    ↓
Lambda
```

For example:

```text
DynamoDB:

User 101
Drug = A
   ↓
User 101
Drug = B
```

DynamoDB Stream can capture:

> "This item changed from A → B."

---

# 4. This is exactly why Answer 3 is wrong

Answer 3 says:

```text
DynamoDB
   ↓
DynamoDB Stream
   ↓
Lambda
   ↓
Anonymize
```

Problem?

The PII has **already entered DynamoDB**.

For a moment, DynamoDB contains:

```text
Patient: Bilal
CNIC: 12345
Drug: ...
```

Only afterward does Lambda anonymize it.

But the requirement says:

> **Anonymize BEFORE landing in the NoSQL database.**

Therefore:

```text
❌ Wrong

DynamoDB
   ↓
DynamoDB Stream
   ↓
Lambda
   ↓
Anonymize
```

versus:

```text
✅ Correct

Kinesis Data Stream
   ↓
Lambda
   ↓
Anonymize
   ↓
DynamoDB
```

---

# 5. Why not S3?

Answer 2 does:

```text
Raw PII
   ↓
S3
   ↓
Lambda
   ↓
Anonymize
   ↓
DynamoDB
```

Again, problem:

**Raw PII has already been stored in S3.**

The requirement says it must be anonymized **before landing in storage**.

So this violates the requirement.

---

# 6. Why not Firehose → Redshift?

Answer 4:

```text
Streaming data
      ↓
Kinesis Data Firehose
      ↓
Redshift
```

There are actually two problems.

The biggest one for the exam:

**Redshift is a data warehouse, not a NoSQL database.**

The question specifically wants:

> **NoSQL database**

And you already know:

**DynamoDB = NoSQL.**

So:

```text
DynamoDB ✅
Redshift  ❌
```

---

# 7. One more important distinction for your SAA knowledge

You should now have this mental map:

### Kinesis Data Streams

**"I have real-time data coming IN."**

```text
Sources
   ↓
Kinesis Data Streams
```

### DynamoDB Streams

**"Something changed INSIDE my DynamoDB."**

```text
DynamoDB
   ↓
DynamoDB Streams
```

### S3 Event

**"A file was uploaded/changed in S3."**

```text
S3
 ↓
EventBridge / Lambda
```

### EventBridge

**"Something happened; trigger another service."**

```text
Event
 ↓
EventBridge
 ↓
Target
```
