34. Question

Category: CSAA – Design High-Performing Architectures

A car dealership website hosted in Amazon EC2 stores car listings in an Amazon Aurora database managed by Amazon RDS. Once a vehicle has been sold, its data must be removed from the current listings and forwarded to a distributed processing system.

Which of the following options can satisfy the given requirement?

- Create an RDS event subscription and send the notifications to Amazon SQS. Configure the SQS queues to fan out the event notifications to multiple Amazon SNS topics. Process the data using AWS Lambda functions.
- `Use an Aurora MySQL native function to invoke an AWS Lambda function whenever a vehicle listing is deleted. Configure the Lambda function to send the data to an Amazon SQS queue for the distributed processing system to consume.`
- Create an RDS event subscription and send the notifications to AWS Lambda. Configure the Lambda function to fanout the event notifications to multiple Amazon SQS queues to update the target groups.
- Create an RDS event subscription and send the notifications to Amazon SNS. Configure the SNS topic to fan out the event notifications to multiple Amazon SQS queues. Process the data using AWS Lambda functions.

Yes — this question is testing a **new concept for you: database changes vs RDS events**. Once you separate those two, the question becomes straightforward.

## 1. First understand what the company wants

The database contains:

```text
Aurora
│
├── Car A → available
├── Car B → available
└── Car C → SOLD ❌
```

When Car C is sold, the application does something like:

```text
DELETE car C FROM Aurora
```

But the company also wants the **deleted car's information** to be sent somewhere for further processing.

So the requirement is:

```text id="x4f3u1"
Car sold
   ↓
Delete car from Aurora
   ↓
Capture that deleted data
   ↓
Send to distributed processing system
   ↓
SQS
```

The question is essentially asking:

> **How can we detect a DELETE operation inside Aurora and send information about it to another system?**

---

# 2. The important concept: RDS Events ≠ Database Changes

This is the main thing you need to learn.

### RDS Event Subscription

RDS events are about **the database infrastructure/service itself**.

For example:

```text
RDS
 ↓
Database instance stopped
Database instance started
Backup completed
Failover occurred
Maintenance started
```

These are **RDS events**.

They are NOT:

```text
INSERT car
UPDATE car
DELETE car
```

So an RDS event subscription doesn't tell you:

> "Car #123 was deleted from the database."

That's why all the RDS Event Subscription answers are wrong.

---

# 3. What does the correct answer use?

The correct answer says:

> **Use an Aurora MySQL native function to invoke Lambda whenever a vehicle listing is deleted.**

This is a special Aurora MySQL capability.

Conceptually:

```text id="6w8j8k"
Aurora MySQL
     │
     │ DELETE car
     ↓
Aurora native Lambda function
     ↓
AWS Lambda
     ↓
Amazon SQS
     ↓
Distributed processing
```

So when your application executes:

```sql
DELETE FROM cars
WHERE car_id = 123;
```

Aurora can invoke Lambda.

Lambda then sends the relevant information to SQS.

---

# 4. Why SQS?

Because the question says:

> **distributed processing system**

SQS is very useful when you want different workers to process messages asynchronously.

For example:

```text id="j3n5p2"
                ┌── Worker 1
                │
Aurora → Lambda → SQS ── Worker 2
                │
                └── Worker 3
```

Maybe one worker:

* archives the sold vehicle
* another updates analytics
* another sends a notification
* another updates another system

The workers don't need to process the event immediately.

---

# 5. Why not SNS?

You might be thinking:

> "But SNS can distribute messages!"

Correct. **SNS is for pub/sub fanout.**

But the question doesn't say:

> "Notify multiple subscribers."

It says:

> **send the deleted vehicle data to a distributed processing system.**

SQS is appropriate as a queue for workers to consume and process the data.

---

# 6. The most important distinction for your notes

Add this:

### RDS Events

Monitor **RDS infrastructure/service events**:

```text
Instance failure
Failover
Backup
Maintenance
Configuration changes
```

They **do NOT detect SQL data changes** such as:

```text
INSERT
UPDATE
DELETE
```

### Aurora MySQL → Lambda

Aurora MySQL can use native Lambda integration to react to database operations.

```text
Database change
      ↓
Aurora MySQL
      ↓
Lambda
      ↓
SQS
```

---

## 🧠 Exam shortcut

If the question says:

> **"RDS instance failed / backup completed / failover / maintenance"**

Think:

**RDS Event Subscription → SNS/SQS/Lambda**

But if it says:

> **"A row was INSERTED / UPDATED / DELETED"**

Think:

**Database-level change detection**, not RDS Event Subscription.

For **this specific question**:

> Car sold → row deleted → capture the deletion → send data to processing system

Therefore:

**Aurora MySQL native Lambda function → Lambda → SQS** ✅

This is a useful new concept to add to your SAA knowledge because you've already learned **S3 events, DynamoDB Streams, SNS/SQS**, and now you're seeing how **database changes** can trigger processing.
