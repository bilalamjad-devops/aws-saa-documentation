57. Question

Category: CSAA – Design Secure Architectures

A financial application consists of an Auto Scaling group of Amazon EC2 instances, an Application Load Balancer, and a MySQL RDS instance set up in a Multi-AZ Deployment configuration. To protect customers’ confidential data, it must be ensured that the Amazon RDS database is only accessible using an authentication token specific to the profile credentials of EC2 instances.

Which of the following actions should be taken to meet this requirement?

- Use a combination of IAM and STS to enforce restricted access to your RDS instance using a temporary authentication token.
- Configure SSL in your application to encrypt the database connection to RDS.
- Create an IAM Role and assign it to your EC2 instances which will grant exclusive access to your RDS instance.
- Enable the IAM DB Authentication.

Yes. **Question 57 is basically asking:**

> "How can I make my EC2 application connect to MySQL RDS **without storing a normal database password**, and instead use a temporary authentication token tied to the EC2's IAM role?"

The answer is **IAM DB Authentication**.

### 1. What is the question trying to teach?

Normally, your application connects like:

```text
EC2
 ↓
username: admin
password: MyPassword123
 ↓
RDS MySQL
```

The problem is that the application has to somehow store/manage that database password.

With **IAM DB Authentication**:

```text
EC2
 ↓
IAM Role
 ↓
temporary authentication token
 ↓
RDS MySQL
```

The token is generated using AWS credentials and is valid for **15 minutes**.

So the important clue is:

> **"authentication token specific to the profile credentials of EC2 instances"**

→ **IAM DB Authentication**

---

## 2. What is STS?

**STS = AWS Security Token Service.**

Its main job is to provide **temporary AWS credentials**.

For example:

```text
IAM Role
   ↓
STS
   ↓
Temporary AWS credentials
   ↓
Access AWS resources
```

Instead of giving an application permanent credentials like:

```text
Access Key
Secret Access Key
```

you can use temporary credentials.

They look conceptually like:

```text
Access Key ID
Secret Access Key
Session Token
Expiration time
```

The credentials expire automatically.

### Simple way to remember STS

**STS = temporary AWS credentials**

---

## 3. But don't confuse STS with the RDS authentication token

This is important for the exam.

There are two related ideas:

### STS

Provides **temporary AWS credentials**.

```text
STS
→ temporary AWS credentials
```

### IAM DB Authentication

Uses IAM credentials to generate a **temporary database authentication token** for RDS.

```text
EC2 IAM Role
      ↓
IAM authentication
      ↓
RDS authentication token
      ↓
MySQL RDS
```

The RDS authentication token lasts **15 minutes**.

So if the question specifically says:

> **RDS + authentication token + EC2 IAM role/profile**

think:

# IAM DB Authentication

---

## 4. What does the EC2 IAM Role do?

Suppose you have:

```text
EC2
  |
  | IAM Role
  ↓
Permissions
  |
  ↓
RDS IAM authentication
```

The EC2 doesn't need to have a database password stored in the application.

The application can use the EC2's IAM role credentials to obtain the RDS authentication token.

That's why the question specifically says:

> **"profile credentials of EC2 instances"**

That's a strong clue toward **IAM DB Authentication**.

---

## 5. What about SSL?

SSL/TLS answers a different question.

### SSL/TLS:

> "How do I encrypt the connection?"

```text
EC2 ===== encrypted connection ===== RDS
```

### IAM DB Authentication:

> "How does the application prove it is allowed to connect to RDS without a normal DB password?"

```text
EC2 → IAM → temporary token → RDS
```

IAM DB Authentication also requires/uses encrypted connections, but **SSL by itself doesn't provide the IAM authentication-token requirement**.

---

## 6. Your SAA memory table

| Service/concept           | Think                                   |
| ------------------------- | --------------------------------------- |
| **IAM Role**              | Give AWS permissions to EC2             |
| **STS**                   | Temporary AWS credentials               |
| **IAM DB Authentication** | Temporary authentication token for RDS  |
| **SSL/TLS**               | Encrypt data in transit                 |
| **Secrets Manager**       | Store/rotate database passwords/secrets |
| **RDS Multi-AZ**          | High availability                       |
| **RDS Read Replica**      | Read scaling                            |

### One-line memory trick

**STS → temporary AWS credentials**

**IAM DB Authentication → temporary RDS login token**

**SSL → encrypted connection**

**Secrets Manager → store database credentials**

So for Question 57:

> **"RDS + EC2 + IAM/profile credentials + authentication token"**

🔥 **IAM DB Authentication**.
