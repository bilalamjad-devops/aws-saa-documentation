53. Question

Category: CSAA – Design Resilient Architectures

An online cryptocurrency exchange platform is hosted in AWS, utilizing an Amazon ECS Cluster and Amazon RDS in a Multi-AZ Deployments configuration. The application heavily uses the RDS instance to process complex read and write database operations. To maintain reliability, availability, and performance, it is necessary to closely monitor how the different processes or threads on a DB instance use the CPU, including the percentage of CPU bandwidth and total memory consumed by each process.

Which of the following is the most suitable solution to monitor the database properly?

- Use Amazon CloudWatch to monitor the CPU Utilization of your database.
- Create a script that collects and publishes custom metrics to Amazon CloudWatch, which tracks the real-time CPU Utilization of the RDS instance, and then set up a custom CloudWatch dashboard to view the metrics.

- Check the CPU% and MEM% metrics which are readily available in the RDS console that shows the percentage of the CPU bandwidth and total memory consumed by each database process of your RDS instance.
- `Enable Enhanced Monitoring in RDS.`

Exactly. For this question, **don't memorize the long explanation**. The question is testing one distinction:

> **CloudWatch = normal RDS metrics**
> **RDS Enhanced Monitoring = detailed OS/process-level metrics**

### What is the question asking?

It says:

> “I want to know how **different processes/threads inside the RDS database instance** are using CPU and memory.”

The key words are **“each process or thread”**, **CPU bandwidth**, and **memory consumed**.

That means normal CloudWatch isn't detailed enough.

✅ **Answer: RDS Enhanced Monitoring**

---

### 1. CloudWatch — what is it?

**CloudWatch = AWS monitoring service.**

For RDS, it can give you things like:

* CPUUtilization
* FreeStorageSpace
* FreeableMemory
* DatabaseConnections
* Read/Write IOPS

Think:

> **“How is my AWS resource performing?”**

But it doesn't normally show:

> “Process A is using 20% CPU, Process B is using 15% memory...”

---

### 2. CloudWatch Agent — why install it on EC2?

Your understanding is correct.

For **EC2**, you can install the **CloudWatch Agent** when you need additional OS-level information such as:

* Memory/RAM
* Disk usage
* Processes
* Swap
* etc.

Why?

Because EC2 is **your server**. You have access to the OS, so you can install an agent.

Think:

**EC2 → I control the OS → I can install CloudWatch Agent.**

---

### 3. What about RDS?

With RDS, AWS manages the underlying server.

You **don't SSH into the underlying RDS server and install your own agent**.

So AWS provides:

### **RDS Enhanced Monitoring**

It gives you much more detailed information about the **underlying OS** and resource usage.

Think:

**RDS → AWS controls the OS → AWS provides Enhanced Monitoring for deeper visibility.**

---

### Very important exam distinction

| Requirement                     | Think of                |
| ------------------------------- | ----------------------- |
| Normal AWS metrics              | **CloudWatch**          |
| EC2 memory/disk/process metrics | **CloudWatch Agent**    |
| RDS detailed OS/process metrics | **Enhanced Monitoring** |

### Easy memory trick

> **CloudWatch = “How is RDS doing?”**
> **Enhanced Monitoring = “What is happening inside RDS?”**

So when you see:

**“individual processes/threads + CPU + memory inside RDS”**

🚨 **Immediately think: Enhanced Monitoring.**

And yes, your understanding of the previous EC2 concept is right: **CloudWatch Agent is commonly used when you need OS-level metrics such as RAM and disk that standard CloudWatch doesn't provide for EC2.**
