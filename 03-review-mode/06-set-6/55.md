55. Question

Category: CSAA – Design Resilient Architectures

A tech company is running two production web servers hosted on Reserved EC2 instances with EBS-backed root volumes. These instances have a consistent CPU load of 90%. Traffic is being distributed to these instances by an Elastic Load Balancer. In addition, they also have Multi-AZ RDS MySQL databases for their production, test, and development environments.

What recommendation would you make to reduce cost in this AWS environment without affecting availability and performance of mission-critical systems? Choose the best answer.

- Consider using On-demand instances instead of Reserved EC2 instances
- Consider removing the Elastic Load Balancer
- `Consider not using a Multi-AZ RDS deployment for the development and test database`
- Consider using Spot instances instead of reserved EC2 instances

Is question ka correct answer **Consider not using a Multi-AZ RDS deployment for the development and test database** hai.

---

### Scenario Breakdown & Key Requirements

1. **Production EC2 Instances:** 2 Reserved EC2 instances hain jin par consistently 90% CPU load rehta hai (steady-state production workload).
2. **Production DBs:** Multi-AZ RDS MySQL databases production, test, aur dev environments ke liye chal rahe hain.
3. **Goal:** Production/mission-critical systems ki **availability aur performance ko affect kiye bina cost reduce** karni hai.

---

### Correct Option Explanation

#### ✅ **Disable Multi-AZ for Non-Production (Dev/Test) RDS Databases**

* **Multi-AZ Purpose:** Multi-AZ RDS deployments synchronous replication aur automatic failover provide karti hain high availability ke liye, lekin yeh **Single-AZ deployment ke muqabla mein double cost (2x)** karti hain.
* **Dev/Test Needs:** Development aur Testing environments mission-critical nahi hote. Un par Multi-AZ failover ki zaroorat nahi hoti.
* Dev/Test databases ko **Single-AZ** par shift karne se **cost 50% tak kam** ho jaye gi jabke production availability par koi farq nahi parega.

---

### Incorrect Options Breakdown (Elimination)

* ❌ **Option 1 (Use On-Demand instead of Reserved Instances):** Reserved Instances (RIs) steady-state 90% CPU load wale workloads ke liye On-Demand ke muqabla mein up to 72% saste hote hain. On-Demand par shift hone se cost ziada ho jaye gi.
* ❌ **Option 2 (Remove Elastic Load Balancer):** Load Balancer remove karne se high availability aur traffic distribution kharab ho jaye gi, jo production system ko affect kare gi.
* ❌ **Option 4 (Use Spot instances instead of Reserved EC2):** Production web servers par 90% consistent load rehta hai. Spot instances kisi bhi waqt 2-minute notice par terminate ho sakte hain, jis se mission-critical production website down ho jaye gi.

---

### SAA-C03 RDS & EC2 Cost Optimization Cheat Sheet 💡

> * **Non-Production Environments (Dev/Test):** Use **Single-AZ RDS** & **Scheduled EC2 Instances** (Stop after working hours).
> * **Production Steady-State Workloads (24/7):** Use **Reserved Instances (RIs) / Savings Plans**.
> * **Production Mission-Critical DBs:** Use **Multi-AZ RDS** for High Availability & Automatic Failover.
> * **Fault-Tolerant / Stateless / Batch Processing:** Use **Spot Instances**.
