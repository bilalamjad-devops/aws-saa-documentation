23. Question

Category: CSAA – Design High-Performing Architectures

A manufacturing company launched a new type of IoT sensor that collects large streams of data records. A Solutions Architect needs to design a solution that can ingest and analyze the data in real time with millisecond response times.

Which of the following is the best option that should be implemented in this scenario?

- Ingest the data by directly writing to Amazon DynamoDB using Provisioned Capacity mode with 1,000 Read Capacity Units (RCU) and 1,000 Write Capacity Units (WCU).
- Ingest the data using Amazon Kinesis Data Streams and create an AWS Lambda function to store the data in Amazon Redshift.
- Ingest the data using Amazon Simple Queue Service and create an AWS Lambda function to store the data in Amazon Redshift.
- `Ingest the data using Amazon Kinesis Data Streams and create an AWS Lambda function to store the data in Amazon DynamoDB.`


Is question ka correct answer **Ingest the data using Amazon Kinesis Data Streams and create an AWS Lambda function to store the data in Amazon DynamoDB.** hai.

---

### Scenario Breakdown & Key Requirements

1. **IoT Data Streams:** Large streams of data records (IoT sensors se continuous data aa raha hai).
2. **Real-time Ingestion:** Real-time stream processing ki zaroorat hai.
3. **Millisecond Response Times:** Data ko store aur query karne mein **millisecond response time** chahiye.

---

### Correct Option Explanation

#### ✅ **Kinesis Data Streams + Lambda + DynamoDB**

* **Amazon Kinesis Data Streams:** Real-time IoT data streams ko smoothly ingest aur buffer karne ke liye sab se suitable service hai.
* **AWS Lambda:** Kinesis se aane wale data batch ko process/transform karke aage bhejta hai.
* **Amazon DynamoDB:** NoSQL database hai jo **single-digit millisecond latency** (sub-millisecond with DAX) provide karta hai. High-throughput IoT write workloads ke liye yeh best fit hai.

---

### Incorrect Options Breakdown (Elimination)

* ❌ **Direct write to DynamoDB with Provisioned 1000 WCU/RCU:** IoT sensors se aane wali sudden spikes (throttling) ko directly DynamoDB handle nahi kar sakti agar WCU limit exceed ho jaye. Beech mein Kinesis jaisa buffer/stream ingester zaroori hai.
* ❌ **Kinesis + Lambda + Amazon Redshift:** Amazon Redshift ek Data Warehouse hai jo OLAP (complex analytical batch queries) ke liye hota hai. Redshift **seconds se minutes** leta hai, yeh **millisecond response time** ke liye design nahi kiya gaya.
* ❌ **SQS + Lambda + Amazon Redshift:** SQS ki jagah Kinesis streaming data ke liye better hai, aur Redshift millisecond response times offer nahi karta.

---

### SAA-C03 Real-Time Architecture Rule 💡

> * **Streaming Ingestion:** Kinesis Data Streams
> * **Processing:** AWS Lambda
> * **Millisecond Storage:** Amazon DynamoDB (NoSQL)
> * **Analytics Storage (Seconds/Minutes):** Amazon Redshift (OLAP)
