37. Question

Category: CSAA – Design Secure Architectures

An online stock trading system is hosted in AWS and uses an AWS Auto Scaling group of Amazon EC2 instances, an Amazon Relational Database Service (Amazon RDS) database, and an Amazon ElastiCache for Redis. To improve the data security of the in-memory data store, it is required for users to enter a password before being granted permission to execute Redis commands.

Which of the following should be done to meet the above requirement?


- Create a new Redis replication group and set the AtRestEncryptionEnabled parameter to true.
- Create a new Redis replication group and enable AWS KMS managed keys (CSE-KMS) to secure the in-memory data store.
- `Authenticate the users using Redis AUTH by creating a new Redis Cluster with both the --transit-encryption-enabled and --auth-token parameters enabled.`
- Enable the in-transit encryption for Redis replication groups.

Is question ka correct answer **Authenticate the users using Redis AUTH by creating a new Redis Cluster with both the --transit-encryption-enabled and --auth-token parameters enabled.** hai.

---

### Scenario Breakdown & Key Requirements

1. **In-Memory Data Store:** Application **Amazon ElastiCache for Redis** use kar rahi hai.
2. **Security Requirement:** Users ko Redis commands execute karne se pehle **password enter karna zaroori (Authentication required)** hai taake in-memory data secure ho sake.

---

### Correct Option Explanation

#### ✅ **Redis AUTH + Transit Encryption (--auth-token & --transit-encryption-enabled)**

* **Redis AUTH:** Amazon ElastiCache for Redis mein password-based authentication feature ko **Redis AUTH** kehte hain. Is ke zariye commands execute karne se pehle authentication token (password) require hota hai.
* **Transit Encryption Prerequisite:** ElastiCache Redis mein Redis AUTH (password protection) tabhi enable ho sakta hai jab **In-Transit Encryption (TLS/SSL)** bhi enabled ho (`--transit-encryption-enabled`).
* Is liye password set karne ke liye `--auth-token` (password string) aur `--transit-encryption-enabled` dono flags ko new cluster create karte waqt enable karna hota hai.

---

### Incorrect Options Breakdown (Elimination)

* ❌ **Option 1 & 2 (AtRestEncryption / KMS):** At-rest encryption disk par save data ko encrypt karti hai, yeh user/command-level **password authentication** provide nahi karti.
* ❌ **Option 4 (In-transit encryption alone):** In-transit encryption client aur server ke beech network data ko TLS se encrypt karti hai, lekin bina `--auth-token` (Redis AUTH) ke yeh users se password nahi maangti.

---

### SAA-C03 ElastiCache Redis Security Cheat Sheet 💡

> * **Password Authentication (Redis AUTH):** Requires **In-Transit Encryption** + `--auth-token`.
> * **Role-Based Access Control (RBAC):** Users and user groups can be created using Redis 6.x+.
> * **Data Protection at Rest:** Enabled via **KMS Customer Managed / AWS Managed Keys**.
