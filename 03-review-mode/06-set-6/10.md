10. Question

Category: CSAA – Design High-Performing Architectures

A commercial bank has designed its next-generation online banking platform to use a distributed system architecture. The Solutions Architect was tasked to ensure that the architecture is highly scalable, cost-effective, and leverages Amazon EC2 for compute resources.

Which of the following will provide the most suitable solution for this scenario?

- Launch multiple EC2 instances and use Elastic Load Balancing to distribute traffic across the instances, which will host application services, while Amazon SNS will act as a highly-scalable buffer for messages as they travel between distributed applications.
- `Launch an Auto-Scaling group of EC2 instances to host your application services and an Amazon SQS queue. Include an Auto Scaling trigger to watch the SQS queue size which will either scale in or scale out the number of EC2 instances based on the queue.`
- Launch multiple On-Demand EC2 instances to host your application services and an Amazon SQS queue which will act as a highly-scalable buffer that stores messages as they travel between distributed applications.
- Launch multiple EC2 instances behind an Application Load Balancer to host your application services, and an AWS Step Functions workflow which will act as a highly scalable buffer that stores messages as they travel between distributed applications.

Is question ka correct answer **Launch an Auto-Scaling group of EC2 instances to host your application services and an Amazon SQS queue. Include an Auto Scaling trigger to watch the SQS queue size which will either scale in or scale out the number of EC2 instances based on the queue.** hai.

---

### Key Scenario Breakdown

* **Architecture:** Distributed system architecture (microservices / decoupled components).
* **Key Requirements:**
1. **Highly Scalable & Cost-Effective:** Load ke mutabiq resources automatic scale hon taake extra cost na aaye.
2. **Leverages Amazon EC2:** Compute processing ke liye EC2 instances.
3. **Decoupling / Buffering:** Distributed components ke darmiyan messages handle karna.



---

### Correct Option Explanation

#### ✅ **EC2 Auto Scaling Group + SQS Queue (Backlog-per-instance Metric)**

* **SQS (Simple Queue Service):** Distributed systems ko decouple karne aur traffic spikes ko absorb karne ke liye ideal **buffer** ka kaam karti hai.
* **Auto Scaling based on Queue Size:** Jab messages SQS queue mein jama honay lagtay hain (backlog barhta hai), toh Auto Scaling Group automatically mazeed EC2 instances **Scale Out** kar deta hai taake processing fast ho jaye. Jab queue khaali hoti hai, toh extra instances **Scale In** (terminate) ho jatay hain taake cost bache.
* Yeh design **highly scalable, fault-tolerant aur cost-effective** hota hai.

---

### Incorrect Options Breakdown (Elimination)

* ❌ **SNS as a buffer:** **Amazon SNS buffer nahi hai**. SNS ek pub/sub notification service hai jo messages store nahi karti (pass-through / fan-out karti hai). Buffering ke liye SQS zaroori hai.
* ❌ **Fixed On-Demand EC2 instances + SQS:** Fixed instances hone ki wajah se automatic scaling nahi hogi, jis se cost-effectiveness aur dynamic elasticity nahi milti.
* ❌ **AWS Step Functions as a message buffer:** Step Functions application workflows aur state machines ko orchestrate/coordinate karti hai, yeh traditional high-throughput message storage buffer nahi hai.

---

### SAA-C03 Exam Rule

> **Decoupling & Dynamic Scaling Rule:**
> * Distributed systems ko decouple karne aur spikes ke waqt messages hold karne ke liye **Amazon SQS** use hota hai.
> * Worker EC2 instances ko scale karne ke liye **SQS Queue Size (ApproximateNumberOfMessagesVisible)** ko Target Tracking / Step Scaling policy ke sath use kiya jata hai.
