4. Question

Category: CSAA – Design Secure Architectures

A company has an application architecture that stores both the access key ID and the secret access key in a plain text file on a custom Amazon Machine Image (AMI). The EC2 instances, which are created by using this AMI, are using the stored access keys to connect to a DynamoDB table.

What should the Solutions Architect do to make the current architecture more secure?

- Do nothing. The architecture is already secure because the access keys are already in the Amazon Machine Image.
- Put the access keys in an Amazon S3 bucket instead.
- Put the access keys in Amazon Glacier instead.
- `Remove the stored access keys in the AMI. Create a new IAM role with permissions to access the DynamoDB table and assign it to the EC2 instances.`

Is question ka correct answer **Remove the stored access keys in the AMI. Create a new IAM role with permissions to access the DynamoDB table and assign it to the EC2 instances.** hai.

---

### Key Scenario Breakdown

* **Current Problem:** Access Key ID aur Secret Access Key plain text file mein AMI ke andar saved hain.
* **Security Risk:** Plain text keys leak ho sakti hain aur inko rotate karna boht mushkil hota hai.
* **Goal:** EC2 instances ko DynamoDB table ke sath connect karne ka sab se secure tareeqa follow karna.

---

### Correct Option Explanation

#### ✅ **IAM Role for Amazon EC2**

* AWS Best Practices ke mutabiq, EC2 instances ko kisi bhi AWS service (jaise DynamoDB) se communicate karne ke liye **Hardcoded Access Keys** use nahi karni chahiyen.
* Best practice yeh hai ke AMI se keys delete ki jayen aur ek **IAM Role** banaya jaye jismein DynamoDB ki required permissions hoon, aur yeh Role EC2 instances ko assign (**EC2 Instance Profile**) kiya jaye.
* **Benefit:** AWS background mein temporary, automatically-rotated credentials handle karta hai, jisse leakage ka khatra 0% ho jata hai.

---

### Incorrect Options Breakdown (Elimination)

* ❌ **Do nothing:** AMI mein hardcoded credentials rakhna boht bara security risk hai.
* ❌ **Put access keys in Amazon S3 bucket:** S3 mein text file rakhne se bhi access keys hardcoded hi rehti hain aur security flaw solve nahi hota.
* ❌ **Put access keys in Amazon Glacier:** Glacier cold archival storage ke liye hota hai, runtime access keys access karne ke liye nahi.

---

### Exam Rule for SAA-C03

> **Security Rule:**
> Jab bhi EC2 instance ko kisi doosri AWS service (S3, DynamoDB, SQS) ke sath communicate karna ho, **HAMESHA IAM Roles (Instance Profiles)** choose karein. Access keys ko kabhi bhi EC2 ya AMI mein hardcode na karein.
