24. Question

Category: CSAA – Design Resilient Architectures

A company has a VPC for its Human Resource department and another VPC located in different AWS regions for its Finance department. The Solutions Architect must redesign the architecture to allow the finance department to access all resources that are in the human resource department, and vice versa. An Intrusion Prevention System (IPS) must also be integrated for active traffic flow inspection and to block any vulnerability exploits.

Which network architecture design in AWS should the Solutions Architect set up to satisfy the above requirement?

- Establish a secure connection between the two VPCs using a NAT Gateway. Manage user sessions via the AWS Systems Manager Session Manager service.
- Create a Direct Connect Gateway and add VPC attachments to connect all departments. Configure AWS Security Hub to secure the application traffic travelling between the VPCs.
- `Launch an AWS Transit Gateway and add VPC attachments to connect all departments. Set up AWS Network Firewall to secure the application traffic travelling between the VPCs.`
- Create a Traffic Policy in Amazon Route 53 to connect the two VPCs. Configure the Route 53 Resolver DNS Firewall to do active traffic flow inspection and block any vulnerability exploits.

Is question ka correct answer **Launch an AWS Transit Gateway and add VPC attachments to connect all departments. Set up AWS Network Firewall to secure the application traffic travelling between the VPCs.** hai.

---

### Scenario Breakdown & Key Requirements

1. **Multi-Region & Multi-VPC Interconnection:** HR department ka VPC aur Finance department ka VPC alag-alag AWS regions mein hain. Dono ko aapas mein full connectivity chahiye.
2. **Active Traffic Inspection & Exploit Blocking:** Aisa Intrusion Prevention System (IPS) chahiye jo traffic flow ko active inspect kare aur **vulnerability exploits ko block** kar sake (Layer 3-7 deep packet inspection).

---

### Correct Option Explanation

#### ✅ **AWS Transit Gateway + AWS Network Firewall**

* **AWS Transit Gateway (TGW):** Transit Gateway ek central regional router ki tarah kaam karta hai. Peering routing ko simplify karta hai aur cross-region VPC attachments ko easily connect kar leta hai.
* **AWS Network Firewall (IPS):** AWS Network Firewall mein **Suricata-compatible Intrusion Prevention System (IPS)** built-in hota hai. Yeh VPC-to-VPC traffic ki deep packet inspection karta hai, malicious traffic detect karta hai aur vulnerability exploits ko real-time block karta hai.

---

### Incorrect Options Breakdown (Elimination)

* ❌ **NAT Gateway + SSM Session Manager:** NAT Gateway sirf private subnet ke instances ko outbound internet access deta hai, VPC-to-VPC routing nahi karta. Session Manager admin shell access ke liye hai, IPS ke liye nahi.
* ❌ **Direct Connect Gateway + Security Hub:** AWS Direct Connect Gateway on-premises data center ko AWS VPCs se connect karne ke liye hota hai (VPC-to-VPC routing ke liye nahi). Security Hub compliance findings aur alert aggregation karta hai, active network-level traffic block nahi karta.
* ❌ **Route 53 Traffic Policy + Resolver DNS Firewall:** DNS Firewall sirf **DNS domain queries (domain filtering)** ko filter/block karta hai. Yeh actual application network traffic ka **deep packet inspection (IPS)** nahi kar sakta.

---

### SAA-C03 Networking & Security Rule 💡

> **Multi-VPC Security & Routing Rule:**
> * Centralized Multi-VPC / Multi-Region Connectivity $\rightarrow$ **AWS Transit Gateway**
> * Statefull/Stateless Active Traffic Flow Inspection & IPS Protection $\rightarrow$ **AWS Network Firewall**
>

Boht hi acha aur important question hai! Aap ne bilkul sahi socha ke do VPCs ko aapas mein connect karne ke liye **VPC Peering** bhi use ho sakta hai.

Lekin is question mein **VPC Peering wale option ke reject hone aur Transit Gateway select hone ki do bari wajoohat** hain:

---

### 1. Options Mein VPC Peering Diya Hi Nahi Gaya! 😅

Pehli simple waja yeh hai ke question ke diaye gaye chaar options mein **VPC Peering ka koi option majood hi nahi tha**.

Chaar options yeh thay:

1. NAT Gateway + SSM Session Manager ❌
2. Direct Connect Gateway + Security Hub ❌
3. **AWS Transit Gateway + AWS Network Firewall** ✅
4. Route 53 Traffic Policy + DNS Firewall ❌

---

### 2. Transit Gateway Architectural Advantage (Deep Technical Reason)

Agar option mein **VPC Peering + Network Firewall** hota bhi, tab bhi **Transit Gateway** architecture-wise behtar choice hoti, kyunke:

* **Centralized Traffic Inspection (Inspection VPC Pattern):** Jab aap ko do ya do se zyaada VPCs ke beech aane jane wale traffic par **Intrusion Prevention System (IPS / Network Firewall)** lagana hota hai, toh Transit Gateway ke zariye traffic ko ek **Centralized Inspection VPC** se guzaarna boht aasan aur scalable hota hai.
* **VPC Peering Limitations:** VPC Peering mein transitive routing allow nahi hoti (yani VPC A $\rightarrow$ VPC B $\rightarrow$ VPC C traffic nahi ja sakta). transit gateway bina complex routing meshing ke centralized firewall inspection allow karta hai.

---

### Summary Rule 💡

> **AWS SAA-C03 Architectural Concept:**
> * Direct 2-3 VPCs connection bina central firewall ke $\rightarrow$ **VPC Peering**
> * Centralized security/inspection (Network Firewall / IPS) ya boht saare VPCs ko aapas mein jodna $\rightarrow$ **AWS Transit Gateway**
