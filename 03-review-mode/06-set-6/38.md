38. Question

Category: CSAA – Design High-Performing Architectures

A Solutions Architect is implementing a new High-Performance Computing (HPC) system in AWS that involves orchestrating several Amazon Elastic Container Service (Amazon ECS) tasks with an Amazon EC2 launch type that is part of an ECS cluster. The ECS cluster is configured with an ECS Capacity Provider to dynamically manage and scale the EC2 instances based on ECS task demand, ensuring sufficient compute resources are always available for high-throughput workloads.

Users around the globe will frequently access the system, and it is expected that hundreds of ECS tasks will run most of the time. These tasks require high-frequency read and write operations to a shared storage system. The output data of each ECS task is around 10 MB, and although obsolete data is eventually archived and deleted, the total storage size will not exceed 10 TB.

Which of the following is the MOST suitable solution that the Architect should recommend?


- `Launch an Amazon Elastic File System (Amazon EFS) with Provisioned Throughput mode and set the performance mode to Max I/O. Configure the EFS file system as the container mount point in the ECS task definition of the ECS cluster.`
- Launch an Amazon Elastic File System (Amazon EFS) file system with Bursting Throughput mode and set the performance mode to General Purpose. Configure the EFS file system as the container mount point in the ECS task definition of the ECS cluster.
- Launch an Amazon DynamoDB table with DynamoDB Accelerator (DAX) and DynamoDB Streams enabled. Configure the table to be accessible by all ECS cluster instances. Set the DynamoDB table as the container mount point in the ECS task definition of the ECS cluster.
- Set up an SMB file share by creating an Amazon FSx for Windows File Server. Set the file share as the container mount point in the ECS task definition of the ECS cluster.

Is question ka correct answer **Launch an Amazon Elastic File System (Amazon EFS) with Provisioned Throughput mode and set the performance mode to Max I/O. Configure the EFS file system as the container mount point in the ECS task definition of the ECS cluster.** hai.

---

### Scenario Breakdown & Key Requirements

1. **Workload Type:** High-Performance Computing (HPC) system jo Amazon ECS (EC2 launch type) tasks par chal raha hai.
2. **Access Requirement:** Hundreds of ECS tasks ko **shared storage system** par high-frequency concurrent read/write operations karne hain.
3. **Data Volume & Throughput:** Har task ka output 10 MB hai, total storage up to 10 TB hai, aur high network/storage throughput required hai.

---

### Correct Option Explanation

#### ✅ **Amazon EFS (Provisioned Throughput + Max I/O Performance Mode)**

* **Shared Storage for Linux Containers:** Amazon EFS ek POSIX-compliant, fully managed NFS file system hai jo hundreds of Linux ECS tasks/containers ke zariye simultanously mount aur share kiya ja sakta hai.
* **Max I/O Performance Mode:** EFS Max I/O mode High-Performance Computing (HPC) aur massive parallel workloads ke liye design kiya gaya hai jahan hundreds of tasks ek sath heavy read/write I/O operations karte hain.
* **Provisioned Throughput Mode:** Standard Bursting mode storage capacity ke hisab se throughput deta hai (choti/medium storage size par low throughput milta hai). **Provisioned Throughput** select karne se aap storage size se alag high throughput baseline lock kar sakte hain jo HPC applications ke liye zaroori hota hai.

---

### Incorrect Options Breakdown (Elimination)

* ❌ **Option 2 (Bursting Throughput + General Purpose):** General Purpose mode aur Bursting throughput High-Performance Computing ke heavy concurrent IOPS aur high-frequency parallel write demands ko sustain nahi kar saken ge (latency bottlenecks aayenge).
* ❌ **Option 3 (DynamoDB + DAX):** DynamoDB ek NoSQL key-value database hai. Isay container mount point ke taur par filesystem ki tarah bind/mount nahi kiya ja sakta.
* ❌ **Option 4 (FSx for Windows File Server):** SMB/Windows file share heterogenous Linux-based ECS tasks ke HPC storage ke liye recommended nahi hota (EFS is Linux native NFS).

---

### SAA-C03 EFS Performance Modes Cheat Sheet 💡

> * **General Purpose Mode:** Default mode for web servers, CMS, and general dev environments (low latency per I/O).
> * **Max I/O Mode:** High-Performance Computing (HPC), Big Data, and massive parallel container workloads (higher I/O throughput across hundreds of clients).
> * **Provisioned Throughput:** When application needs high throughput regardless of storage volume size.
