35. Question

Category: CSAA – Design Cost-Optimized Architectures

A company has multiple AWS sandbox accounts that are used by its development team. All developers must be given access to the contents of one of the main account’s S3 buckets. For security purposes, any personally identifiable information (PII) or financial data uploaded in the bucket must be continuously monitored and removed.

How can this be done at the lowest possible cost and with the least amount of configuration effort?

- `Create an S3 bucket policy that grants access from the sandbox accounts. Use Amazon Macie to discover personally identifiable information (PII) or financial data.`
- Configure cross-account replication on the S3 bucket. Integrate AWS Audit Manager with the S3 bucket to discover any personally identifiable information (PII) or financial data.
- Generate a pre-signed URL for the objects on the S3 bucket. Use the Amazon S3 Storage Lens to discover personally identifiable information (PII) or financial data.
- Add S3 read permission to the IAM policy of each IAM user from the sandbox accounts. Use Amazon Detective to discover personally identifiable information (PII) or financial data.

Is question ka correct answer **Create an S3 bucket policy that grants access from the sandbox accounts. Use Amazon Macie to discover personally identifiable information (PII) or financial data.** hai.

---

### Scenario Breakdown & Key Requirements

1. **Cross-Account S3 Access:** Sandbox accounts ke developers ko main account ki S3 bucket ke contents ka access chahiye.
2. **PII & Financial Data Monitoring:** Bucket mein uploaded kisi bhi **Personally Identifiable Information (PII)** ya financial data ko continuously scan/discover karna hai aur highlight/remove karna hai.
3. **Lowest Cost & Least Effort:** Sab se sasta aur kam mehnat (lowest operational overhead) wala solution chahiye.

---

### Correct Option Explanation

#### ✅ **Bucket Policy + Amazon Macie**

* **Amazon Macie:** AWS ki fully-managed data security aur data privacy service hai jo Machine Learning (ML) aur pattern matching use karke S3 buckets mein sensitive data jaise **PII** (names, addresses, SSNs) aur financial data (credit card numbers) ko automatically discover aur classify karti hai.
* **S3 Bucket Policy:** Cross-account access allow karne ke liye source S3 bucket par ek simple **Bucket Policy** attach karna sab se least effort aur direct tareeqa hai (bina cross-account replication ya pre-signed URLs ke complex setups ke).

---

### Incorrect Options Breakdown (Elimination)

* ❌ **Option 2 (Cross-Account Replication + AWS Audit Manager):** S3 bucket ko replicate karna storage cost barha dega. AWS Audit Manager compliance framework management ke liye hai, S3 objects ke andar PII scan karne ke liye nahi.
* ❌ **Option 3 (Pre-signed URL + S3 Storage Lens):** S3 Storage Lens storage analytics aur usage metrics (bytes, object counts) deta hai, S3 files ke andar PII scan nahi karta.
* ❌ **Option 4 (IAM Policy per User + Amazon Detective):** Har sandbox account ke har IAM user ki policy ko manually update karna high operational effort hai. Amazon Detective security investigations ke liye VPC flow logs, CloudTrail, aur GuardDuty data analyze karta hai, S3 objects ke andar sensitive PII data scan nahi karta.

---

### SAA-C03 AWS Security Services Cheat Sheet 💡

> * **PII / Sensitive Data in S3 Discovery:** $\rightarrow$ **Amazon Macie**
> * **Security Log Analysis & Root Cause Investigation:** $\rightarrow$ **Amazon Detective**
> * **Compliance Assessment & Audits:** $\rightarrow$ **AWS Audit Manager**
> * **Threat Detection (Malware, Anomalies):** $\rightarrow$ **Amazon GuardDuty**
