11. Question

Category: CSAA – Design High-Performing Architectures

A multinational company has been building its new data analytics platform with high-performance computing workloads (HPC) which requires a scalable, POSIX-compliant storage service. The data need to be stored redundantly across multiple AZs and allows concurrent connections from thousands of EC2 instances hosted on multiple Availability Zones.

Which of the following AWS storage service is the most suitable one to use in this scenario?

- Amazon ElastiCache
- `Amazon Elastic File System`
- Amazon EBS Volumes
- Amazon S3

Is question ka correct answer **Amazon Elastic File System (Amazon EFS)** hai.

---

### Scenario Breakdown & Key Requirements

1. **HPC Workloads:** High-Performance Computing data analytics platform.
2. **POSIX-Compliant:** Shared file system permissions aur standard Linux file system semantics zaroori hain.
3. **Multi-AZ Redundancy:** Data pehle se multiple Availability Zones mein redundantly store hona chahiye.
4. **Concurrent Connections:** Thousand(s) of EC2 instances across multiple AZs ek sath (concurrently) is storage ko mount aur read/write kar sakain.

---

### Correct Option Explanation

#### ✅ **Amazon Elastic File System (Amazon EFS)**

* **Shared Network File System (NFS):** EFS fully managed NFS file system hai jo Linux instances ke liye **POSIX-compliant** hai.
* **Multi-AZ Access:** EFS data ko multiple AZs mein automatically replicate karta hai aur thousands of EC2 instances multiple AZs se isay **concurrently mount** kar sakte hain.
* **Elastic & Scalable:** Storage automatically grow aur shrink hoti hai jaise files add ya remove hotay hain.

---

### Incorrect Options Breakdown (Elimination)

* ❌ **Amazon EBS Volumes:** EBS Volume ek **Block Storage** hai. High-performance Multi-Attach sirf specific io1/io2 volumes par aur limited instances ke liye single AZ mein hota hai. Yeh POSIX shared network file system scale cross-AZ nahi deta.
* ❌ **Amazon S3:** S3 **Object Storage** hai, POSIX-compliant file system nahi (S3 mein standard Linux file operations jaise `append` ya `byte-level locks` kaam nahi karte).
* ❌ **Amazon ElastiCache:** Yeh **In-memory Caching** service (Redis/Memcached) hai, POSIX file storage nahi.

---

### SAA-C03 Exam Rule

> **Storage Selection Guide:**
> * **POSIX + Multi-AZ + Thousands of EC2 Concurrent Mounts (Linux):** $\rightarrow$ **Amazon EFS**
> * **POSIX + High Throughput / Lustre (HPC Heavy):** $\rightarrow$ **AWS FSx for Lustre**
> * **Block Storage (Single Instance / Low Latency):** $\rightarrow$ **Amazon EBS**
> * **Object Storage (Web/Media/Static Assets):** $\rightarrow$ **Amazon S3**
