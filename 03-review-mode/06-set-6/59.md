59. Question

Category: CSAA – Design Resilient Architectures

A cryptocurrency company wants to go global with its international money transfer app. Your project is to make sure that the database of the app is highly available in multiple regions.

What are the benefits of adding Multi-AZ deployments in Amazon RDS? (Select TWO.)

- Significantly increases the database performance.
- `Provides enhanced database durability in the event of a DB instance component failure or an Availability Zone outage.`
- Provides SQL optimization.
- Creates a primary DB Instance and synchronously replicates the data to a standby instance in a different Availability Zone (AZ) in a different region.
- `Increased database availability in the case of system upgrades like OS patching or DB Instance scaling.`


Is question ke correct **TWO** options hain:

* **Provides enhanced database durability in the event of a DB instance component failure or an Availability Zone outage.**
* **Increased database availability in the case of system upgrades like OS patching or DB Instance scaling.**

---

### Scenario Breakdown & Key Requirements

1. **Requirement:** Amazon RDS mein **Multi-AZ deployments** ke core benefits identify karne hain jo system resiliency aur uptime ko increase karte hain.

---

### Correct Options Explanation

#### ✅ **1. Enhanced Durability during Failures & AZ Outages**

* Multi-AZ deployment doosre Availability Zone (AZ) mein ek **standby replica** maintain karti hai.
* Agar primary database instance ka koi hardware fail ho jaye ya poora AZ down ho jaye, toh RDS automatically **failover** kar ke standby instance ko primary bana deta hai. Is se data durability aur availability maintain rehti hai.

#### ✅ **2. High Availability during OS Patching & Instance Scaling**

* Maintenance tasks (jaise OS patching, DB engine upgrades, ya instance class scaling) ke waqt pehle standby instance update hota hai, us ke baad failover hota hai aur phir purana primary update hota hai.
* Is process se maintenance downtime minute-level tak minimize ho jata hai aur high availability bani rehti hai.

---

### Incorrect Options Breakdown (Elimination)

* ❌ **Significantly increases database performance:** Multi-AZ high availability/failover ke liye hota hai, performance/read scale-out ke liye nahi. Performance/Read throughput barhane ke liye **Read Replicas** use hotay hain (in fact, synchronous replication ki waja se write latency thodi barh sakti hai).
* ❌ **Provides SQL optimization:** SQL queries ko optimize karna RDS service ka kaam nahi hota.
* ❌ **Replicates to a standby instance in a DIFFERENT REGION:** Multi-AZ deployment **SAME Region ke different Availability Zones (AZs)** mein hoti hai. Different region mein data replicate karne ke liye **Cross-Region Read Replicas** ya Aurora Global Database use hota hai.

---

### SAA-C03 RDS Multi-AZ vs Read Replicas Cheat Sheet 💡

> * **RDS Multi-AZ:**
> * **Purpose:** High Availability (HA) & Disaster Recovery (DR).
> * **Replication:** Synchronous.
> * **Scope:** Same Region (across different AZs).
> * **Primary Use:** Automatic Failover, OS Patching without downtime.
> 
> 
> * **RDS Read Replicas:**
> * **Purpose:** Scalability & Read Performance.
> * **Replication:** Asynchronous.
> * **Scope:** Same Region OR Cross-Region.
> * **Primary Use:** Offloading read traffic from primary DB.
