19. Question

Category: CSAA – Design Resilient Architectures

A disaster recovery team is planning to back up on-premises records to a local file server share through SMB protocol. To meet the company’s business continuity plan, the team must ensure that a copy of data from 48 hours ago is available for immediate access. Accessing older records with delay is tolerable.

Which should the DR team implement to meet the objective with the LEAST amount of configuration effort?

- Create an SMB file share in Amazon FSx for Windows File Server that has enough storage to store all backups. Access the file share from on-premises.
- Mount an Amazon EFS file system on the on-premises client and copy all backups to an NFS share.
- Create an AWS Backup plan to copy data backups to a local SMB share every 48 hours.
- `Use an AWS Storage File gateway with enough storage to keep data from the last 48 hours. Send the backups to an SMB share mounted as a local disk.`


Is question ka correct answer **Use an AWS Storage File gateway with enough storage to keep data from the last 48 hours. Send the backups to an SMB share mounted as a local disk.** hai.

---

### Scenario Breakdown & Key Requirements

1. **Protocol & On-Premises Integration:** Local file server se backup **SMB protocol** ke zariye bhejna hai.
2. **Immediate Access (Low Latency):** Pichle 48 hours ka data immediately local network par available rehna chahiye.
3. **Older Data:** Purana data AWS cloud mein store ho sakta hai jahan se delay se access karna acceptable hai.
4. **LEAST Effort:** Configuration effort sab se kam honi chahiye (existing local backup systems me zyada changes na karne padain).

---

### Correct Option Explanation

#### ✅ **AWS Storage File Gateway (Amazon S3 File Gateway)**

* **Local Caching + Cloud Storage:** File Gateway on-premises server par as a Virtual Machine (VM) deploy hoti hai aur **SMB share** provide karti hai.
* **Low-Latency Local Access:** Is ki local cache disk ko 48 hours ke data ke barabar configure kiya ja sakta hai, jis se pichle 48 hours ka data local speed par immediately milega.
* **Automatic Cloud Backup:** Data background mein automatically Amazon S3 bucket mein sync ho jata hai, jahan purana data safely store rehta hai.
* **Least Effort:** Existing on-premises backup software local SMB share ko target karta rahega bina kisi major reconfiguration ke.

---

### Incorrect Options Breakdown (Elimination)

* ❌ **Amazon FSx for Windows File Server directly from On-Premises:** Direct cloud FSx SMB share use karne se har backup direct internet/VPN ke zariye cloud par jayega, jis se local 48-hour immediate low-latency access nahi milti aur latency problems aate hain.
* ❌ **Amazon EFS over NFS:** Question mein explicitly **SMB protocol** ki requirement thi. EFS NFS protocol use karta hai, SMB nahi. Iske ilawa EFS ko on-premises mount karne ke liye Direct Connect / VPN zaroori hota hai.
* ❌ **AWS Backup plan to copy backups to a local SMB share:** AWS Backup cloud-based backup service hai, yeh cloud se data ko local SMB share par 48 hours baad copy karne ka automated local agent-less solution nahi deti.

---

### SAA-C03 AWS Storage Gateway Cheat Sheet 💡

> * **Amazon S3 File Gateway:** On-premises applications ke liye **NFS / SMB** file shares provide karta hai jo background mein S3 objects ban jate hain (local cache supported).
> * **Volume Gateway:** On-premises servers ko **iSCSI block storage** volumes deta hai (Stored Volumes / Cached Volumes).
> * **Tape Gateway:** On-premises physical tape backup infrastructure ko **virtual tape library (VTL)** se replace karta hai.
