54. Question

Category: CSAA – Design Secure Architectures

A company deployed a web application to an EC2 instance that adds a variety of photo effects to a picture uploaded by the users. The application will put the generated photos to an S3 bucket by sending PUT requests to the S3 API.

What is the best option for this scenario considering that you need to have API credentials to be able to send a request to the S3 API?

- Encrypt the API credentials and store in any directory of the EC2 instance.
- `Create a role in IAM. Afterwards, assign this role to a new EC2 instance.`
- Store the API credentials in the root web application directory of the EC2 instance.
- Store your API credentials in Amazon S3 Glacier.


Is question ka correct answer **Create a role in IAM. Afterwards, assign this role to a new EC2 instance.** (IAM Role to EC2) hai.

---

### Scenario Breakdown & Key Requirements

1. **Application Action:** EC2 instance par chalne wali web app user ki uploaded photos par effects apply karke unhe Amazon S3 bucket mein `PUT` API request ke zariye upload karti hai.
2. **Security Requirement:** S3 API ko access karne ke liye AWS API credentials (Access Key ID & Secret Access Key) chahiye hotay hain.
3. **Core Question:** Best security practice kya hai jisse bina hardcode kiye EC2 ko credentials mil jayein?

---

### Correct Option Explanation

#### ✅ **IAM Role for EC2 Instance**

* **No Hardcoded Credentials:** AWS ki **#1 Security Best Practice** yeh hai ke kabhi bhi API keys ko code, EC2 storage, ya config files mein store na kiya jaye.
* **Temporary Security Credentials:** Jab aap ek **IAM Role** banate hain (jis mein S3 write permissions hon) aur usay **EC2 instance profile** ke zariye EC2 par attach karte hain, toh EC2 Instance Metadata Service (IMDS) automatically temporary, rotating credentials application ko provide kar deti hai.
* Is se security vulnerabilities khatam ho jati hain aur keys rotate karne ka koi manual overhead nahi hota.

---

### Incorrect Options Breakdown (Elimination)

* ❌ **Option 1 (Encrypt and store credentials on EC2):** Credentials ko EC2 par local directory mein rakhna (chahe encrypted hi kyun na ho) secure practice nahi hai.
* ❌ **Option 3 (Store credentials in web application directory):** Web root directory mein Access Keys rakhna nihayat khatarnak hai, kyunke hacker web app breach karke in keys ko steal kar sakta hai.
* ❌ **Option 4 (Store credentials in Amazon S3 Glacier):** Glacier long-term archival storage hai, wahan credentials store karne ka API authentication flow se koi talaluq nahi hai.

---

### SAA-C03 Security & IAM Best Practices Cheat Sheet 💡

> * **EC2 to AWS Services (S3, DynamoDB, etc.):** Always use **IAM Roles** (Instance Profiles). Never hardcode API Keys.
> * **Cross-Account Access:** Use **IAM Roles** with `AssumeRole`.
> * **Lambda to AWS Services:** Use **Lambda Execution Role**.
