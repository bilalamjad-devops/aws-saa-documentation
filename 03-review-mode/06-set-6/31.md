31. Question

Category: CSAA – Design Resilient Architectures

An application is using an AWS Lambda function to process complex financial data that runs for 15 minutes on average. The Lambda function has been configured with the maximum memory allocation to handle the computational demands of the financial data processing. Most invocations were successfully processed. However, a few terminated invocations were noticed throughout the day, which caused a data discrepancy in the application.

Which of the following is the most likely cause of this issue?

- The Lambda function contains a recursive code and has been running for over 15 minutes.
- The failed Lambda Invocations contain a ServiceException error which means that the Lambda service encountered an internal error.
- The concurrent execution limit has been reached.
- `The failed Lambda functions have been running for over 15 minutes and reached the maximum execution time.`

Is question ka correct answer **The failed Lambda functions have been running for over 15 minutes and reached the maximum execution time.** hai.

---

### Scenario Breakdown & Key Requirements

1. **Lambda Execution Duration:** Financial data processing average par **15 minutes** leti hai.
2. **Lambda Max Memory:** Lambda ko maximum memory allocate ki gayi hai taake computation handle ho sakay.
3. **Intermittent Failures:** Aksar invocations successfully complete hoti hain, lekin din mein **kuch invocations unexpectedly terminate/fail** ho rahi hain jis se data discrepancy aa rahi hai.

---

### Correct Option Explanation

#### ✅ **Reached Maximum Execution Time (15 Minutes Timeout)**

* **AWS Lambda Hard Limit:** AWS Lambda ka maximum execution timeout limit **15 minutes (900 seconds)** hota hai.
* Average processing time 15 minutes hai, iska matlab hai ke jab data thora ziada complex ya heavy hota hai, toh execution time **15 minutes se cross (exceed)** kar jata hai.
* Jaise hi execution 15 minutes touch karti hai, AWS Lambda function ko **forcibly terminate (kill)** kar deta hai, jis se data processing adhuri reh jati hai aur application mein data discrepancy aati hai.

---

### Incorrect Options Breakdown (Elimination)

* ❌ **ServiceException (Internal Error):** ServiceException AWS service ki taraf se temporary internal error hota hai. Yeh average 15-minute processing trend aur timeout limitation se directly relate nahi karta.
* ❌ **Concurrent Execution Limit Reached:** Agar concurrency limit hit hoti, toh request **Throttled (429 Too Many Requests)** hoti aur execution start hi na hoti. Question mein keh rahe hain ke function start hua lekin terminate ho gaya.
* ❌ **Recursive Code:** Recursive code loop mein phans kar run ho sakta hai, lekin yahan main waja execution duration ka 15-minute hard limit exceed hona hai.

---

### SAA-C03 AWS Lambda Execution Rule 💡

> **AWS Lambda Timeout Rule:**
> * Maximum Timeout Limit = **15 Minutes**.
> * Agar task 15 minutes se zyaada ka ho $\rightarrow$ Use **AWS Step Functions**, **AWS Fargate (ECS)**, ya **AWS Batch**.
