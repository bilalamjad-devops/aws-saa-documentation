13. Question

Category: CSAA – Design High-Performing Architectures

A Solutions Architect needs to set up the required compute resources for the application which have workloads that require high, sequential read and write access to very large data sets on local storage.

Which of the following instance type is the most suitable one to use in this scenario?

- Memory Optimized Instances
- `Storage Optimized Instances`
- Compute Optimized Instances
- General Purpose Instances



Aap ki baat boht sahi jagah se uthi hai — question ki pehli line mein likha hai: *"set up the required **compute resources**..."*

Lekin AWS ki terminologies mein **"compute resources"** ek general (aam) word hai jo kisi bhi **EC2 Instance / Server** ke liye istemal hota hai.

### Summary Rule

> **"Compute Resources"** = EC2 Instance (General Term)
> **"High Sequential Read/Write on Local Storage"** = Storage Optimized (Specific Requirement)

Isliye yahan answer **Storage Optimized Instances** hi hoga!

### Scenario Breakdown & Key Requirements

1. **High, Sequential Read/Write Access:** Disk par zyaada speed se data read/write karne ki requirement.
2. **Very Large Data Sets on Local Storage:** Boht bade data sets jo local instance store disks par rapidly process hotay hon.

---

### Correct Option Explanation

#### ✅ **Storage Optimized Instances (e.g., I3, I3en, Im4gn, Is4gen, D2, D3)**

* **Design Purpose:** Yeh instance families un workloads ke liye specially design ki gayi hain jinhe **local storage par high sequential read/write capabilities** aur massive IOPS (Input/Output Operations Per Second) zaroori hotay hain.
* **Use Cases:** Large parallel data processing platforms, NoSQL databases (Cassandra, MongoDB), relational databases, transactional databases, aur data warehousing applications.

---

### Incorrect Options Breakdown (Elimination)

* ❌ **Memory Optimized Instances (e.g., R5, X1):** In-memory databases (Redis, Memcached) ya fast RAM-processing workloads ke liye hotay hain, local disk read/write throughput ke liye nahi.
* ❌ **Compute Optimized Instances (e.g., C5, C6g):** High CPU-bound workloads (web servers, batch processing, video encoding) ke liye hotay hain.
* ❌ **General Purpose Instances (e.g., M5, T3):** Balanced compute, memory, aur networking ke liye hotay hain (baseline applications).

---

### SAA-C03 EC2 Instance Types Quick Cheat Sheet

> * **Storage Optimized (I, D series):** High sequential/random IOPS & local storage access (Big Data, NoSQL).
> * **Memory Optimized (R, X, High Memory):** High RAM requirements (In-Memory Caches, SAP HANA).
> * **Compute Optimized (C series):** High CPU / Processing power (Batch jobs, HPC).
> * **General Purpose (M, T series):** Balanced workloads (Standard Web Servers).
