36. Question

Category: CSAA – Design Resilient Architectures

A startup is building IoT devices and monitoring applications. They are using IoT sensors to monitor the traffic in real-time by using an Amazon Kinesis Stream that is configured with default settings. It then sends the data to an Amazon S3 bucket every 3 days. When you checked the data in S3 on the 3rd day, only the data for the last day is present and no data is present from 2 days ago.

Which of the following is the MOST likely cause of this issue?

- `By default, data records in Kinesis are only accessible for 24 hours from the time they are added to a stream.`
- Someone has manually deleted the record in Amazon S3.
- Amazon S3 bucket has encountered a data loss.
- The access of the Kinesis stream to the S3 bucket is insufficient.


Is question ka correct answer **By default, data records in Kinesis are only accessible for 24 hours from the time they are added to a stream.** hai.

---

### Scenario Breakdown & Key Requirements

1. **Amazon Kinesis Data Streams:** Real-time traffic monitoring ke liye default settings ke sath Kinesis Data Stream use ho raha hai.
2. **Batch Processing Schedule:** Data har **3 days** baad S3 bucket mein bheja ja raha hai.
3. **Data Loss Problem:** Jab 3rd day par S3 mein data check kiya gaya, toh sirf pichle 1 din (last 24 hours) ka data mojood tha, jabke shuru ke 2 dino ka data missing tha.

---

### Correct Option Explanation

#### ✅ **Kinesis Data Retention Period Limit**

* **Default Retention Period:** Amazon Kinesis Data Streams ka default data retention period **24 hours (1 day)** hota hai.
* Agar aap data ko 24 hours ke andar process karke S3 par dump nahi karenge, toh 24 ghante purana data stream se **automatically expire/delete** ho jata hai.
* Isi liye jab 3rd day par batch run hua, toh Kinesis mein sirf aakhri 24 hours ka data hi bacha hua tha jo S3 mein chala gaya.

---

### Incorrect Options Breakdown (Elimination)

* ❌ **Someone manually deleted data in S3:** S3 mein data kabhi aaya hi nahi tha kyunke Kinesis ne stream level par hi 24 hours baad drop kar diya tha.
* ❌ **S3 encountered data loss:** S3 High Availability aur 99.999999999% (11 9s) durability offer karta hai, wahan automated data loss hona lagbhag na-mumkin hai.
* ❌ **Access/Permissions insufficient:** Agar permissions ki problem hoti toh 3rd day ka data bhi S3 mein copy na ho pata (poora process error de deta).

---

### SAA-C03 Kinesis Retention Rule 💡

> **Amazon Kinesis Data Streams Retention:**
> * **Default:** 24 Hours.
> * **Maximum Configurable:** Up to 365 Days (1 Year) for an additional fee.
> * *Fix for this scenario:* Stream Retention period ko 3 days (72 hours) ya is se ziada par extend karna padega.
