26. Question

Category: CSAA – Design High-Performing Architectures

A Solutions Architect created a new Standard-class Amazon S3 bucket to store financial reports that are not frequently accessed but should immediately be available when an auditor requests the reports. To save costs, the Architect changed the storage class of the S3 bucket from Standard to Infrequent Access storage class.

In S3 Standard – Infrequent Access storage class, which of the following statements are true? (Select TWO.)

- It automatically moves data to the most cost-effective access tier without any operational overhead.
- Ideal to use for data archiving.
- `It is designed for data that requires rapid access when needed.`
- It provides high latency and low throughput performance.
- `It is designed for data that is accessed less frequently.`

Yes — this question is testing whether you understand **S3 storage classes**, especially **S3 Standard-IA**.

The easiest way to understand it is to ignore the complicated wording and ask two questions:

> **How often is the data accessed?**
> **How quickly do I need it when I access it?**

---

# 1. What is S3 Standard-IA?

**IA = Infrequent Access**

It means:

> "I don't access this data often, BUT when I need it, I want it immediately."

For example:

```text
Financial reports
      ↓
Not accessed every day
      ↓
Auditor requests report
      ↓
Need it quickly
      ↓
S3 Standard-IA ✅
```

That's exactly what the question describes.

---

# 2. Why use Standard-IA instead of Standard?

Suppose you have:

**S3 Standard**

```text
Storage cost: higher
Retrieval: fast
Access: frequent
```

And:

**S3 Standard-IA**

```text
Storage cost: lower
Retrieval: fast
Access: infrequent
```

So Standard-IA is basically:

> **"I want cheaper storage because I rarely access the data, but I don't want slow retrieval when I do need it."**

There is a **retrieval fee** with Standard-IA, so it is intended for data you don't retrieve frequently.

---

# 3. Now let's understand the correct answers

### ✅ "It is designed for data that requires rapid access when needed."

Correct.

You might have:

```text
January report
February report
March report
April report
...
```

You don't normally access them.

But an auditor suddenly says:

> "Give me the March 2025 report."

You want it quickly.

That's Standard-IA.

---

### ✅ "It is designed for data that is accessed less frequently."

Correct.

That's literally what **IA = Infrequent Access** means.

So remember:

> **Standard-IA = Infrequent access + Rapid retrieval**

These are the two correct answers.

---

# 4. Why is "high latency and low throughput" wrong?

This is testing an important characteristic.

Standard-IA still provides:

**Low latency + high throughput**

It is NOT:

```text
Cheap storage
      +
Slow retrieval ❌
```

Instead:

```text
Cheaper storage
      +
Fast access ✅
```

So:

> **Standard-IA = low latency + high throughput**

---

# 5. Why isn't "Ideal for data archiving" the answer?

This is where AWS storage classes can become confusing.

"Archiving" makes you think:

> Glacier!

And generally, yes, **S3 Glacier storage classes** are designed for archive/long-term storage use cases.

Think:

```text
Need data frequently
        ↓
S3 Standard


Need data rarely but immediately
        ↓
S3 Standard-IA


Access pattern unpredictable
        ↓
S3 Intelligent-Tiering


Long-term archive
        ↓
S3 Glacier classes
```

Don't memorize "Glacier = slow" too simplistically, though. Glacier has multiple classes with different retrieval characteristics.

For the SAA exam, the key association is:

> **Archive / long-term backup → Glacier**

---

# 6. What about Intelligent-Tiering?

This answer:

> "Automatically moves data to the most cost-effective access tier without operational overhead"

is describing:

### **S3 Intelligent-Tiering**

The difference is:

### Standard-IA

**You decide** to put the object into IA.

```text
You
 ↓
Standard-IA
 ↓
Rare access
```

### Intelligent-Tiering

S3 **automatically monitors access patterns** and moves objects between access tiers.

```text
Object
  ↓
Intelligent-Tiering
  ↓
S3 monitors access
  ↓
Automatically moves between tiers
```

So:

> **Automatic movement based on changing access patterns → Intelligent-Tiering**

---

# 7. One important correction to your mental model

The question says:

> "changed the storage class of the S3 bucket from Standard to Infrequent Access"

Technically, **S3 storage class is associated with objects, not the bucket itself**.

A single bucket can contain:

```text
Bucket
│
├── report1.pdf → Standard
├── report2.pdf → Standard-IA
├── report3.pdf → Glacier
└── report4.pdf → Intelligent-Tiering
```

That's an important SAA concept.

---

# 🧠 Memorize this

| Storage class                     | Think                                              |
| --------------------------------- | -------------------------------------------------- |
| **S3 Standard**                   | Frequently accessed                                |
| **S3 Standard-IA**                | Rarely accessed + need fast retrieval              |
| **S3 Intelligent-Tiering**        | Access pattern changes/unknown + automatic tiering |
| **S3 Glacier Instant Retrieval**  | Archive + milliseconds retrieval                   |
| **S3 Glacier Flexible Retrieval** | Archive + retrieval in minutes/hours               |
| **S3 Glacier Deep Archive**       | Very long-term archive + lowest storage cost       |

### Question 26 in one sentence:

> **"I rarely access these financial reports, but when an auditor asks for one, I need it quickly."**

Therefore:

**S3 Standard-IA = ✅**

And the two answers are:

1. ✅ **Designed for data that requires rapid access when needed**
2. ✅ **Designed for data that is accessed less frequently**
