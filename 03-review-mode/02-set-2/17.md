17. Question

Category: CSAA – Design Resilient Architectures

A Solutions Architect of a multinational gaming company develops video games for PS4, Xbox One, and Nintendo Switch consoles, plus a number of mobile games for Android and iOS. Due to the wide range of their products and services, the architect proposed that they use API Gateway.

What are the key features of API Gateway that the architect can tell to the client? (Select TWO.)

- `Enables you to build RESTful APIs and WebSocket APIs that are optimized for serverless workloads.`
- Provides you with static anycast IP addresses that serve as a fixed entry point to your applications hosted in one or more AWS Regions.
- `You pay only for the API calls you receive and the amount of data transferred out.`
- It automatically provides a query language for your APIs similar to GraphQL.
- Enables you to run applications requiring high levels of inter-node communications at scale on AWS through its custom-built operating system (OS) bypass hardware interface.

Yes. Q17 looks complicated, but the **actual question is simple**: it is testing what **Amazon API Gateway does** and distinguishing it from **Global Accelerator, GraphQL, and EFA**.

## 1. What is the question saying?

The gaming company has lots of applications:

```text
PS4
Xbox
Nintendo Switch
Android
iOS
```

These applications may need to communicate with backend services.

For example:

```text
Mobile Game
     ↓
GET /player/score
     ↓
API Gateway
     ↓
Lambda / EC2 / other backend
     ↓
Database
```

The architect says:

> "Let's use API Gateway."

The question asks:

> **What are TWO important features of API Gateway?**

---

# 2. What is an API?

Very simply:

> **API = a way for one application to communicate with another application/service.**

Imagine your mobile game wants the player's score.

```text
Game
  ↓
"Give me player 123's score"
  ↓
API
  ↓
Backend
  ↓
Database
```

The API is the doorway through which the application communicates with the backend.

---

# 3. What is API Gateway?

Think of API Gateway as the **front door for your APIs**.

```text
             Clients
       /       |       \
    PS4      Android    iOS
       \       |       /
             ↓
       API Gateway
             ↓
      ┌──────┼──────┐
      ↓      ↓      ↓
   Lambda   EC2   Other AWS
```

API Gateway can handle things like:

* accepting API requests
* authentication/authorization
* throttling
* monitoring
* API versioning
* routing requests to backend services

---

# 4. Option 1 — REST APIs and WebSocket APIs ✅

> **Enables you to build RESTful APIs and WebSocket APIs...**

Correct.

API Gateway supports different API types.

### REST API

Client asks:

```text
GET /players/123
```

Backend returns:

```text
{
  "name": "Bilal",
  "score": 500
}
```

### WebSocket API

Useful when you need **ongoing two-way communication**.

For example, multiplayer gaming:

```text
Player A ←→ Server ←→ Player B
```

The connection stays open and data can move in both directions.

So:

**API Gateway → REST + WebSocket ✅**

---

# 5. Option 2 — Pay only for API calls + data transferred ✅

Also correct.

API Gateway doesn't require you to run an EC2 server just to receive API requests.

You pay based on usage, including API calls and data transfer out.

So:

> **No need to maintain API servers yourself.**

That's another important API Gateway feature.

---

# 6. Option 3 — Static Anycast IP ❌

This is the tricky one.

The option says:

> "Provides static anycast IP addresses..."

That should immediately make you think:

### **AWS Global Accelerator**

Not API Gateway.

Remember our previous question:

```text
Global Accelerator
        ↓
Static Anycast IP
        ↓
AWS application
```

So:

**Static Anycast IP → Global Accelerator**

**API Gateway → APIs**

---

# 7. What is Anycast IP?

Don't worry too much about the technical details for SAA.

Just remember:

> **Global Accelerator gives you static IP addresses that act as a fixed entry point to applications.**

For example:

```text
Users
  ↓
Static IP
  ↓
Global Accelerator
  ↓
Best AWS Region
  ↓
Application
```

So when you see:

**"static IP addresses" + "fixed entry point" + "multiple AWS Regions"**

👉 **Global Accelerator**

---

# 8. Option 4 — GraphQL ❌

The question says:

> "Automatically provides a query language similar to GraphQL."

No.

**GraphQL is a separate API technology/query language.**

API Gateway doesn't automatically turn your API into GraphQL.

For the exam:

> **GraphQL ≠ API Gateway feature**

Don't spend too much time here.

---

# 9. Option 5 — Elastic Fabric Adapter ❌

This one sounds scary 😄.

The option says:

> "high levels of inter-node communication"

and

> "OS bypass hardware interface"

That's talking about:

### **Elastic Fabric Adapter (EFA)**

EFA is specialized networking for applications that need **very high-performance communication between EC2 instances**.

Think:

```text
EC2 ←→ EC2 ←→ EC2
       ↑
      EFA
```

Used for workloads such as:

* HPC
* machine learning
* tightly coupled applications

So:

**High-performance inter-node communication → EFA**

Not API Gateway.

---

### Q17 answer:

✅ **API Gateway supports RESTful + WebSocket APIs**

✅ **Pay based on API calls/data transferred**

---

### One very useful mental model

Don't think:

> "API Gateway = server."

Think:

> **API Gateway = front door for APIs.**

For example:

```text
        Android Game
             ↓
        API Gateway
             ↓
          Lambda
             ↓
        DynamoDB
```

The game doesn't need to directly know how Lambda/DynamoDB works. **API Gateway provides the controlled API entry point.**

That is the main concept this question wants you to learn.
