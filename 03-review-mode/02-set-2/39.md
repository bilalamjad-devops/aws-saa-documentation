
39. Question

Category: CSAA – Design Secure Architectures

An application is hosted in AWS Fargate and uses RDS database in Multi-AZ Deployments configuration with several Read Replicas. A Solutions Architect was instructed to ensure that all of their database credentials, API keys, and other secrets are encrypted and rotated on a regular basis to improve data security. The application should also use the latest version of the encrypted credentials when connecting to the RDS database.

Which of the following is the MOST appropriate solution to secure the credentials?

- `Use AWS Secrets Manager to store and encrypt the database credentials, API keys, and other secrets. Enable automatic rotation for all of the credentials.`
- Store the database credentials, API keys, and other secrets in AWS KMS.
- Store the database credentials, API keys, and other secrets to AWS ACM.

- Store the database credentials, API keys, and other secrets to Systems Manager Parameter Store each with a SecureString data type. The credentials are automatically rotated by default.

## 1. Core AWS Rules (Secrets Manager vs Parameter Store)

AWS SAA-C03 exam mein credentials / secrets store karne ke do main options aate hain: **AWS Secrets Manager** aur **AWS Systems Manager Parameter Store**. In dono mein farq samajhna sab se zaroori hai:

| Feature | AWS Secrets Manager | SSM Parameter Store (`SecureString`) |
| --- | --- | --- |
| **Primary Focus** | Confidential secrets (DB passwords, API keys) | Configuration parameters, DB strings, AMI IDs |
| **Automatic Rotation** | **Built-in Automatic Rotation** (uses AWS Lambda under the hood) | **NO built-in automatic rotation** (requires manual custom Lambda setup) |
| **RDS Integration** | Native seamless integration with RDS | Basic storage |
| **Cost** | Paid per secret per month | Free (Standard tier) / Low cost (Advanced tier) |

---

## 2. Scenario Breakdown

* **Requirements:**
1. Database credentials, API keys, aur doosre secrets ko **encrypt** aur **store** karna.
2. Credentials ko **regular basis par rotate** karna (automatic rotation).
3. Application Fargate/RDS latest rotated credentials retrieve kar sake.



---

## 3. Correct Option Explanation

#### ✅ **Use AWS Secrets Manager to store and encrypt the database credentials, API keys, and other secrets. Enable automatic rotation for all of the credentials.**

* **Why it works:**
1. **Secrets Manager** specifically RDS passwords aur API keys ko encrypt karke store karta hai.
2. Is mein **out-of-the-box native automatic rotation** ka feature hota hai jo exact specified schedule par passwords change kar deta hai.
3. Fargate application SDK/API call ke zariye Secrets Manager se dynamic, latest secrets pull kar sakti hai.



---

## 4. Incorrect Options Breakdown

| Incorrect Option | Why It Is Wrong (Exam Elimination Technique) |
| --- | --- |
| **Store... in Systems Manager Parameter Store... credentials are automatically rotated by default** | **Factually False.** SSM Parameter Store secrets ko **automatically rotate NAHI karta** by default. Rotation ke liye manual Lambda writing ki zaroorat hoti hai. |
| **Store... in AWS KMS** | **KMS is for KMS Keys, not text credentials.** KMS sirf encryption keys manage/generate karta hai. Yeh actual passwords store karne ka database ya vault nahi hai. |
| **Store... in AWS ACM** | **ACM is for SSL/TLS Certificates.** ACM (AWS Certificate Manager) website ke SSL certificates manage karta hai, database credentials store nahi karta. |

---

## 5. Exam Decision Matrix (Cheat Sheet)

* **Keywords: "Rotate credentials automatically", "RDS DB Passwords Rotation", "Manage API Keys":** $\rightarrow$ **AWS Secrets Manager**
* **Keywords: "Store config settings", "License keys", "Free/Cheap Parameter Storage", "No native auto-rotation needed":** $\rightarrow$ **SSM Parameter Store**
* **Keywords: "Encrypt data at rest", "Manage KMS Master Keys":** $\rightarrow$ **AWS KMS**
* **Keywords: "HTTPS / SSL / TLS Certificates":** $\rightarrow$ **AWS ACM**

# 🎯 1. What is the question really asking?

Forget the Fargate/RDS Multi-AZ/Read Replica details for a moment.

The actual requirements are:

1. Store **database passwords**
2. Store **API keys**
3. Encrypt them
4. **Rotate them automatically**
5. Application should get the **latest credential** after rotation

So the question is asking:

> **Which AWS service is specifically designed to store and manage secrets with automatic rotation?**

Answer:

### ✅ AWS Secrets Manager

---

# 🧠 2. What exactly is a "secret"?

A secret is sensitive information that you don't want sitting in your application code.

For example:

```text
DB_USERNAME = admin
DB_PASSWORD = MySuperSecretPassword
API_KEY     = abc123xyz
```

Bad architecture:

```text
Fargate Application
      ↓
Password hardcoded in code ❌
      ↓
RDS
```

Someone who gets access to your code might see the password.

Better:

```text
Fargate
   ↓
Secrets Manager
   ↓
"Give me database password"
   ↓
Latest password
   ↓
RDS
```

---

# 🔄 3. Why does rotation matter?

Suppose today your database password is:

```text
Password = ABC123
```

After some time, you want to change it:

```text
Password = XYZ789
```

The problem with hardcoding is:

```text
Application
   ↓
ABC123
```

You change the database password:

```text
RDS
 ↓
XYZ789
```

But your application is still using:

```text
ABC123 ❌
```

Application breaks.

Secrets Manager helps manage this process.

```text
              Secrets Manager
                    │
                    │ automatically rotate
                    ↓
             New credential
                    │
          ┌─────────┴─────────┐
          ↓                   ↓
       Secrets              Database
       Manager                RDS
          │                   │
          └──── application ──┘
```

Your application retrieves the current secret rather than having a permanent password embedded in the code.

---

# 🔐 4. Where does KMS fit?

This is where your understanding needs one small correction.

You said:

> "secret manager has key-rotation feature"

Be careful here.

### Secrets Manager stores and manages the **secret**.

### KMS manages the **encryption keys** used to encrypt data.

Think:

```text
Secrets Manager
       │
       │ "I need to encrypt this secret"
       ↓
      KMS
       │
       ↓
Encryption key
```

So:

```text
        Secrets Manager
       ┌───────────────┐
       │ DB password   │
       │ API key       │
       │ Other secret  │
       └───────┬───────┘
               │ encrypted using
               ↓
              KMS
```

KMS itself is **not your password vault**.

That's why:

> ❌ "Store credentials in KMS"

is wrong.

---

# 🔄 5. What does "rotation" actually mean?

This is different from **KMS key rotation**.

There are two different things:

### Secrets Manager rotation

```text
Old DB password
      ↓
Secrets Manager rotation
      ↓
New DB password
```

This is about changing the **secret/credential**.

### KMS key rotation

```text
Encryption Key
      ↓
KMS key rotation
      ↓
New cryptographic key material
```

This is about the **encryption key**.

🔥 Don't mix these two.

# 🆚 6. Secrets Manager vs KMS vs ACM vs Parameter Store

This table is extremely useful for SAA.

| Service             | Main purpose              | Store secrets? |              Automatic secret rotation? |
| ------------------- | ------------------------- | -------------: | --------------------------------------: |
| **Secrets Manager** | **Store/manage secrets**  |              ✅ |                                       ✅ |
| **KMS**             | Encryption key management |              ❌ | KMS rotates keys, not your DB passwords |
| **ACM**             | SSL/TLS certificates      |              ❌ |                  Certificate management |
| **Parameter Store** | Configuration parameters  | ✅ SecureString |          ❌ Not automatically by default |

# 🔍 7. Option-by-option

### A. Secrets Manager + automatic rotation ✅

Exactly what the question asks.

```text
DB credentials
API keys
Other secrets
       ↓
Secrets Manager
       ↓
Encryption + rotation
```

✅ **Correct**

---

### B. KMS ❌

KMS is for **encryption key management**.

Think:

> "I need to encrypt something."

→ KMS

Not:

> "I need somewhere to manage my database password."

→ Secrets Manager

❌ Wrong.

---

### C. ACM ❌

ACM = **AWS Certificate Manager**.

Think:

```text
HTTPS
 ↓
SSL/TLS certificate
 ↓
ACM
```

Example:

```text
https://example.com
        ↓
TLS certificate
        ↓
ACM
```

It isn't your general-purpose secret/password store.

❌ Wrong.

---

### D. Parameter Store SecureString ❌

This is the **tricky option**.

Parameter Store absolutely **can store encrypted sensitive values**:

```text
Parameter Store
      ↓
SecureString
      ↓
Encrypted parameter
```

So don't learn:

> "Parameter Store cannot store secrets."

That's false.

It **can**.

The problem is the question specifically requires:

> **automatic rotation**

Parameter Store doesn't automatically rotate your database credentials by default.

Therefore, given these choices:

**Secrets Manager is the better answer.**
