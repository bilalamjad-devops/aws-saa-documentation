36. Question

Category: CSAA – Design Resilient Architectures

A company is running a custom application in an Auto Scaling group of Amazon EC2 instances. Several instances are failing due to insufficient swap space. The Solutions Architect has been instructed to troubleshoot the issue and effectively monitor the available swap space of each EC2 instance.

Which of the following options fulfills this requirement?

- Create a new trail in AWS CloudTrail and configure Amazon CloudWatch Logs to monitor your trail logs.

- `Install the CloudWatch agent on each instance and monitor the SwapUtilization metric.`

- Create a CloudWatch dashboard and monitor the SwapUsed metric.

- Enable detailed monitoring on each instance and monitor the SwapUtilization metric.

Yes 😄 **this one is much easier**. The key is just understanding **default EC2 metrics vs. CloudWatch Agent metrics**.

# 🎯 What is the question really asking?

The problem says:

> EC2 instances are running out of **swap space**, and we need to **monitor swap utilization**.

So the important words are:

**EC2 → Swap → SwapUtilization**

Now ask:

> Does EC2/CloudWatch provide this metric automatically?

**No.**

Therefore, we need the **CloudWatch Agent**.

---

# 🧠 1. What is swap space?

Very simply, swap is disk space that the operating system can use when it needs more memory.

Think:

```text
EC2
┌─────────────────┐
│ RAM             │ ← fast
│ 4 GB            │
└────────┬────────┘
         │ RAM getting full
         ↓
┌─────────────────┐
│ Swap            │ ← disk space
│ 2 GB            │
└─────────────────┘
```

If the instance doesn't have enough RAM, the OS can use swap space.

The question says:

> Several instances are failing due to insufficient swap space.

So the architect wants to **monitor how much swap is being used**.

---

# 🧠 2. The important AWS distinction

CloudWatch already provides some **default EC2 metrics**.

For example:

| EC2 metric                 | Available by default?                                 |
| -------------------------- | ----------------------------------------------------- |
| CPUUtilization             | ✅                                                     |
| NetworkIn                  | ✅                                                     |
| NetworkOut                 | ✅                                                     |
| Disk-related basic metrics | Some are available depending on what you're measuring |
| SwapUtilization            | ❌                                                     |
| MemoryUtilization          | ❌                                                     |

Why?

Because AWS doesn't automatically know everything happening **inside the operating system**.

For example:

```text
AWS knows:

EC2
 ├── CPU
 ├── Network
 └── basic instance-level metrics
```

But:

```text
Inside the OS:

RAM usage
Swap usage
Processes
Disk filesystem usage
etc.
```

For these detailed OS-level metrics, you generally install:

**CloudWatch Agent**

---

# 🧠 3. What does CloudWatch Agent do?

You install the agent **inside the EC2 instance**:

```text
EC2
┌────────────────────────┐
│ Operating System       │
│                        │
│ CloudWatch Agent       │
│       ↓                │
│ Collects:              │
│ • Memory               │
│ • Swap                 │
│ • Disk                │
│ • Processes            │
│ • Logs                 │
└───────────┬────────────┘
            ↓
       CloudWatch
```

Now CloudWatch can receive metrics such as:

```text
SwapUtilization
MemoryUtilization
DiskSpaceUtilization
```

and you can create alarms/dashboards based on them.

---

# 🔍 4. Let's eliminate the options

### A. CloudTrail + CloudWatch Logs ❌

CloudTrail answers:

> **"Who did what in my AWS account?"**

For example:

```text
Someone
   ↓
Called TerminateInstances
   ↓
CloudTrail records it
```

CloudTrail is about **AWS API activity**.

It doesn't monitor operating-system swap usage.

❌ Wrong.

---

### B. CloudWatch Agent + SwapUtilization ✅

This is exactly what we need:

```text
EC2
 ↓
CloudWatch Agent
 ↓
SwapUtilization
 ↓
CloudWatch
```

✅ **Correct.**

---

### C. CloudWatch Dashboard + SwapUsed ❌

A dashboard is just a **place to visualize metrics**.

Think:

```text
Metric → Dashboard
```

A dashboard doesn't magically create a metric.

If `SwapUsed` isn't being collected first, putting a dashboard in front of it doesn't help.

You need:

```text
CloudWatch Agent
      ↓
collect swap data
      ↓
CloudWatch metric
      ↓
Dashboard
```

❌ Wrong.

---

### D. Detailed Monitoring + SwapUtilization ❌

This one is a classic exam trap.

**Detailed Monitoring** gives you EC2 metrics at a higher frequency.

It does **not** suddenly give you operating-system metrics like swap usage.

Think:

```text
Basic monitoring
     ↓
EC2 default metrics

Detailed monitoring
     ↓
EC2 default metrics more frequently

CloudWatch Agent
     ↓
OS-level/custom metrics
```

So enabling detailed monitoring doesn't solve this problem.

❌ Wrong.

---

# 📊 Final summary

| Tool/Feature            | Purpose                           |       SwapUtilization? |
| ----------------------- | --------------------------------- | ---------------------: |
| **CloudWatch Agent**    | Collect OS-level/custom metrics   |              ✅ **Yes** |
| CloudWatch Dashboard    | Visualize collected metrics       | ❌ Doesn't collect them |
| EC2 Detailed Monitoring | More frequent default EC2 metrics |                      ❌ |
| CloudTrail              | AWS API activity/auditing         |                      ❌ |

---

# 🔥 SAA shortcuts

Memorize these:

**EC2 CPU → CloudWatch default metric**

**EC2 memory → CloudWatch Agent**

**EC2 swap → CloudWatch Agent**

**EC2 filesystem/disk-space details → CloudWatch Agent**

**AWS API activity → CloudTrail**

**Visualize metrics → CloudWatch Dashboard**

### The big shortcut:

> **If the question asks about something happening INSIDE the EC2 operating system, think CloudWatch Agent.**

So yes — **Q36 is basically a recognition question.** Once you know that `SwapUtilization` is an OS-level metric, the answer becomes immediate.
