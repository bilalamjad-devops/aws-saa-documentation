18. Question

Category: CSAA – Design Secure Architectures

A company wants to streamline the process of creating multiple AWS accounts within an AWS Organization. Each organization unit (OU) must be able to launch new accounts with preapproved configurations from the security team which will standardize the baselines and network configurations for all accounts in the organization.

Which solution entails the least amount of effort to implement?

- Centralized the creation of AWS accounts using AWS Systems Manager OpsCenter. Enforce policies and detect violations to all AWS accounts using AWS Security Hub.
- `Set up an AWS Control Tower Landing Zone. Enable pre-packaged guardrails to enforce policies or detect violations.`
- Configure AWS Resource Access Manager (AWS RAM) to launch new AWS accounts as well as standardize the baselines and network configurations for each organization unit
- Set up an AWS Config aggregator on the root account of the organization to enable multi-account, multi-region data aggregation. Deploy conformance packs to standardize the baselines and network configurations for all accounts.

Absolutely. Q18 is mainly testing **AWS Organizations + Control Tower + Guardrails**. Don't let the long wording scare you.

## 1. What is the company trying to do?

Imagine a company has **50 AWS accounts**:

```text
AWS Organization
│
├── Production OU
│   ├── Account 1
│   ├── Account 2
│   └── Account 3
│
├── Development OU
│   ├── Account 4
│   └── Account 5
│
└── Security OU
    └── Security Account
```

The security team says:

> "Whenever a new AWS account is created, I want it to automatically come with our approved security/network configuration."

For example:

```text
New AWS Account
      ↓
Automatically get:
✓ approved baseline
✓ security settings
✓ networking setup
✓ governance rules
✓ policies
```

And the question asks:

> **Which AWS service does this with the least effort?**

Answer:

### ✅ AWS Control Tower

---

# 2. What is AWS Control Tower?

Think of Control Tower as:

> **"Set up and govern my whole multi-account AWS environment for me."**

It is especially useful when an organization has **many AWS accounts**.

It can help with:

* creating/provisioning accounts
* standardized account setup
* organizational structure
* baseline configurations
* governance
* security controls
* compliance

So this question should trigger:

> **Many AWS accounts + standardized setup + governance + least effort = Control Tower**

---

# 3. What is a Landing Zone?

This term appears frequently in SAA questions.

A **Landing Zone** is basically your organization's **properly structured AWS multi-account environment**.

Think:

```text
                 Control Tower
                      ↓
                Landing Zone
                      ↓
        ┌─────────────┼─────────────┐
        ↓             ↓             ↓
   Security OU     Dev OU       Production OU
        ↓             ↓             ↓
      Accounts      Accounts      Accounts
```

Control Tower helps you create and manage this environment.

---

# 4. What are Guardrails?

This is another important exam word.

A **guardrail = governance rule/control**.

Imagine the security team says:

> "Nobody is allowed to disable CloudTrail."

That's a governance rule.

Or:

> "This type of resource cannot be created."

That's another governance rule.

Control Tower provides pre-packaged **guardrails/controls** to help enforce or detect these requirements.

Very simple:

> **Control Tower = manages the environment**
>
> **Guardrails = rules that keep the environment compliant**

---

# 5. "Enforce" vs "Detect"

This is useful for the exam.

### Prevent / Enforce

```text
User tries to do something forbidden
             ↓
          BLOCKED ❌
```

### Detect

```text
User does something that violates policy
             ↓
       AWS detects it ⚠️
```

Control Tower can use different AWS building blocks underneath, such as:

* AWS Organizations SCPs
* AWS Config
* CloudFormation

You don't need to memorize every internal implementation for this question.

---

# 6. Why AWS RAM is wrong ❌

**AWS Resource Access Manager (RAM)** has a completely different job.

RAM means:

> **Share AWS resources with other AWS accounts.**

For example:

```text
Account A
   │
   │ shares resource
   ↓
Account B
```

You might use RAM to share things like:

* VPC subnets
* Transit Gateway
* certain other supported resources

But RAM does **NOT**:

```text
Create AWS accounts ❌
Create account baselines ❌
Govern your organization ❌
```

Therefore:

**RAM = resource sharing**

not account provisioning.

---

# 7. Why AWS Config Aggregator is wrong ❌

AWS Config is mainly about:

> **recording and evaluating resource configurations/compliance.**

For example:

```text
EC2 Security Group
       ↓
AWS Config
       ↓
"Does this comply with our rule?"
```

A **Config aggregator** lets you centrally view configuration/compliance data from multiple accounts and Regions.

But it doesn't primarily create new AWS accounts.

So:

> **Config = configuration/compliance visibility**

not:

> **"Create a new account with everything already configured."**

---

# 8. What is a Conformance Pack?

You may see this in future questions.

A conformance pack is basically a **collection of AWS Config rules/remediation actions** packaged together.

Think:

```text
Conformance Pack
│
├── Rule 1
├── Rule 2
├── Rule 3
└── Rule 4
```

Useful for standardizing compliance rules.

But again:

**Config can check/enforce configuration compliance; it isn't the account-provisioning solution here.**

---

# 9. Why Systems Manager OpsCenter is wrong ❌

AWS Systems Manager is a huge collection of management tools.

**OpsCenter** specifically helps operations teams manage operational issues/work items called **OpsItems**.

Think:

```text
Something goes wrong
       ↓
OpsCenter
       ↓
Investigate / resolve
```

It isn't designed to:

> automatically create standardized AWS accounts.

So don't choose it.

---

# 🧠 The 4 services you should separate in your head

| Service                       | Simple meaning                                   |
| ----------------------------- | ------------------------------------------------ |
| **Control Tower**             | 🏢 Set up + govern multi-account AWS environment |
| **AWS RAM**                   | 🤝 Share resources between accounts              |
| **AWS Config**                | 🔍 Check resource configuration/compliance       |
| **Systems Manager OpsCenter** | 🛠️ Manage operational issues                    |

And:

> **Guardrails = governance controls/rules**
