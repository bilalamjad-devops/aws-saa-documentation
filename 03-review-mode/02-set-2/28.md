28. Question

Category: CSAA – Design Secure Architectures

A solutions architect is designing a three-tier website that will be hosted on an Amazon EC2 Auto Scaling group fronted by an Internet-facing Application Load Balancer (ALB). The website will persist data to an Amazon Aurora Serverless DB cluster, which will also be used for generating monthly reports.

The company requires a network topology that follows a layered approach to reduce the impact of misconfigured security groups or network access lists. Web filtering must also be enabled to automatically stop traffic to known malicious URLs and to immediately drop requests coming from blacklisted fully qualified domain names (FQDNs).

Which network topology provides the minimum resources needed for the website to work?

- Set up an Application Load Balancer and a NAT Gateway deployed in public subnets. Launch the Auto Scaling Group of EC2 instances and Aurora Serverless DB cluster in private subnets. Directly integrate the AWS Network Firewall with the Application Load Balancer to automatically stop traffic to known malicious URLs and drop requests coming from blacklisted FQDNs.
- Set up an Application Load Balancer in front of an Auto Scaling group of EC2 instances with an Aurora Serverless DB cluster to persist data. Launch a NAT Gateway in a public subnet to restrict external services from initiating a connection to the EC2 instances and immediately drop requests from unauthorized FQDNs. Deploy all other resources in private subnets.
- `Set up an Application Load Balancer deployed in a public subnet, then host the Auto Scaling Group of EC2 instances and the Aurora Serverless DB cluster in private subnets. Launch an AWS Network Firewall with the appropriate firewall policy to automatically stop traffic to known malicious URLs and drop requests coming from blacklisted FQDNs. Reroute your Amazon VPC network traffic through the firewall endpoints.`
- Set up an Auto Scaling group of EC2 instances behind an Application Load Balancer with an Aurora Serverless DB cluster to store application data. Deploy all resources in a public subnet. Configure host-based routing to the Application Load Balancer to stop traffic to known malicious URLs and drop requests from blacklisted FQDNs.

Exactly 👍 You got the **most important architecture concept** from that question.

For a typical **3-tier application on AWS**, remember:

```text
                 Internet
                    │
                    ▼
          ┌─────────────────┐
          │ Public Subnet   │
          │      ALB        │
          └────────┬────────┘
                   │
                   ▼
          ┌─────────────────┐
          │ Private Subnet  │
          │   EC2 ASG       │
          └────────┬────────┘
                   │
                   ▼
          ┌─────────────────┐
          │ Private Subnet  │
          │ Aurora / DB     │
          └─────────────────┘
```

### The simple rule

**ALB → Public subnet**
Because it needs to receive traffic from the Internet.

**EC2 ASG → Private subnet**
Users shouldn't directly access your EC2 instances. Traffic should come through the ALB.

**Database → Private subnet**
The database should never be directly exposed to the Internet.

So your takeaway is **100% correct**:

> **Public ALB → Private EC2 → Private DB**

And this is a very common **3-tier architecture pattern** you'll see repeatedly in SAA questions.

The question added another layer — **AWS Network Firewall** — but don't let that distract you from the core architecture you learned. That's an additional security requirement on top of the basic 3-tier design.


Absolutely. This question is mainly teaching you **how to build a secure 3-tier VPC using layers**, and it introduces an important new service: **AWS Network Firewall**.

Don't worry about all the wording. Let's reduce it to the actual problem.

---

# 1. What architecture are they asking for?

They have a 3-tier application:

```text
Internet
   ↓
Web tier
   ↓
Application tier
   ↓
Database tier
```

In AWS, that becomes roughly:

```text
Internet
   ↓
ALB
   ↓
EC2 Auto Scaling Group
   ↓
Aurora Serverless
```

The question wants this architecture to be **secure and layered**.

---

# 2. What does "layered approach" mean?

This is the biggest concept in the question.

Instead of putting everything in one public subnet:

```text
❌ BAD

Internet
   ↓
ALB
EC2
Aurora
```

you separate the components.

```text
Internet
    ↓
PUBLIC SUBNET
    ↓
ALB
    ↓
PRIVATE SUBNET
    ↓
EC2
    ↓
PRIVATE SUBNET
    ↓
Aurora
```

Why?

Because if you accidentally make one security control too permissive, there is another layer protecting your resources.

This is called:

> **Defense in depth**

Think of a castle:

```text
Outer wall
   ↓
Inner wall
   ↓
Building
   ↓
Vault
```

If someone gets through one layer, they still have more barriers to cross.

---

# 3. Why is ALB public?

The application needs to receive requests from users on the Internet.

So:

```text
Internet
   ↓
Internet-facing ALB
```

The ALB belongs in **public subnets**.

The EC2 instances don't need to be directly accessible from the Internet.

So:

```text
Internet
   ↓
ALB ✅ public
   ↓
EC2 ❌ private
```

The ALB sends requests to the EC2 instances.

---

# 4. Why is EC2 private?

You don't want users on the Internet directly accessing your EC2 instances.

Instead:

```text
Internet
    ↓
ALB
    ↓
EC2
```

Security groups can then say:

> EC2 accepts traffic only from the ALB.

That's much safer than:

```text
Internet
    ↓
EC2
```

---

# 5. Why is Aurora private?

Your database definitely shouldn't be publicly accessible.

So:

```text
ALB → EC2 → Aurora
              ↑
          PRIVATE
```

Aurora sits in private subnets.

Users shouldn't be able to directly connect to the database.

---

# 6. Now the new concept: AWS Network Firewall

This is probably the part that is making the question confusing.

**AWS Network Firewall** is a managed firewall for your VPC.

It can inspect network traffic and apply rules.

In this question, they specifically want:

> Block traffic to known malicious domains/URLs and blacklisted FQDNs.

### FQDN

**FQDN = Fully Qualified Domain Name**

For example:

```text
www.example.com
api.badwebsite.com
malicious-site.example
```

It's basically the complete domain name.

Network Firewall can have rules such as:

```text
Allow:
*.trusted.com

Deny:
*.malicious.com
```

So:

```text
EC2
 ↓
Network Firewall
 ↓
Internet
```

If EC2 tries to communicate with a blacklisted domain:

```text
EC2
 ↓
Network Firewall
 ↓
❌ BLOCK
```

---

# 7. Important: Network Firewall ≠ WAF

This question is also testing the difference.

### AWS WAF

Usually protects **web applications**.

For example:

```text
Internet
   ↓
WAF
   ↓
ALB
```

It can block things such as:

* SQL injection
* XSS
* malicious HTTP requests
* IP addresses
* HTTP headers
* URLs/path patterns

### AWS Network Firewall

Works at the **VPC/network level** and can inspect network traffic and use domain-based rules.

Think:

```text
WAF
↓
Protect my web application


Network Firewall
↓
Protect/filter network traffic in my VPC
```

---

# 8. Why option 1 is wrong

It says:

> ALB + NAT Gateway in public subnet + EC2/Aurora private + directly integrate Network Firewall with ALB.

There are two problems.

### Problem 1: Network Firewall doesn't directly integrate with ALB

You can't simply do:

```text
ALB
 ↓
Network Firewall
```

as an ALB integration.

That's more like what you can do with **AWS WAF**.

### Problem 2: NAT Gateway isn't required just to make the architecture work

NAT Gateway is used when private resources need to **initiate outbound Internet connections**.

For example:

```text
Private EC2
    ↓
NAT Gateway
    ↓
Internet
```

The Internet cannot initiate a connection back through the NAT Gateway to your private EC2.

But the question's core requirement is the **layered topology + Network Firewall**, not "give private EC2 Internet access."

---

# 9. Why option 2 is wrong

It says NAT Gateway will:

> immediately drop requests from unauthorized FQDNs.

No.

NAT Gateway's job is basically:

> "Allow private resources to initiate outbound Internet connections."

It isn't a domain filtering firewall.

So:

```text
NAT Gateway
❌ Not a malicious-domain filtering service
```

Network Firewall is the appropriate service for the stated filtering requirement.

---

# 10. Why option 4 is wrong

It puts everything in public subnets:

```text
Internet
   ↓
ALB
   ↓
EC2
   ↓
Aurora
```

Technically, you might make it work.

But security-wise, it's a bad design.

The question explicitly says:

> **layered approach**

Therefore:

```text
ALB      → Public
EC2      → Private
Aurora   → Private
```

is much better.

---

# 11. The correct architecture

The answer is essentially:

```text
                    INTERNET
                        │
                        ▼
                ┌───────────────┐
                │      ALB      │
                │ Public Subnet │
                └───────┬───────┘
                        │
                        ▼
                ┌───────────────┐
                │      EC2      │
                │ Private Subnet│
                │      ASG      │
                └───────┬───────┘
                        │
                        ▼
                ┌───────────────┐
                │    Aurora     │
                │ Private Subnet│
                └───────────────┘


          Network Firewall
                 ↓
       inspect/filter VPC traffic
                 ↓
        malicious domains/FQDNs
                 ↓
               BLOCK
```

The exact Network Firewall routing topology can be more involved than this simplified picture—the important exam point is that **VPC traffic must be routed through the firewall endpoints**.

---

# 12. One thing I want you to remember for SAA

You now have several different security services that can sound similar.

### Security Group

Controls traffic to/from:

```text
EC2
ALB
RDS
etc.
```

Think:

> **Instance/resource-level virtual firewall**

---

### NACL

Controls traffic at:

> **Subnet level**

And it's **stateless**.

---

### AWS WAF

Think:

> **HTTP/HTTPS web application protection**

Usually:

```text
Internet
 ↓
WAF
 ↓
ALB
```

---

### AWS Network Firewall

Think:

> **VPC network traffic filtering + stateful inspection + domain/FQDN rules**

---

### NAT Gateway

Think:

> **Private subnet → Internet outbound access**

Not a security firewall.

---

# 🧠 The exam shortcut

When you see:

> **3-tier architecture + layered security**

Think:

```text
ALB       → PUBLIC
EC2       → PRIVATE
Database  → PRIVATE
```

When you see:

> **Block malicious domains/FQDNs at the VPC/network level**

Think:

> **AWS Network Firewall**

When you see:

> **Protect an ALB/web application from malicious HTTP requests**

Think:

> **AWS WAF**

When you see:

> **Private EC2 needs outbound Internet**

Think:

> **NAT Gateway**

And Question 28 combines **all of these concepts**, but the correct answer is fundamentally:

**Public ALB → Private EC2 → Private Aurora + Network Firewall controlling/routing VPC traffic.**
