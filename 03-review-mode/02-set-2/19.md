19. Question

Category: CSAA – Design Cost-Optimized Architectures

A company has a requirement to move an 80 TB data warehouse to the cloud. It would take 2 months to transfer the data based on the current bandwidth allocation.

Which option is the most cost-effective for quick data upload to AWS?

- AWS Direct Connect
- `AWS Data Transfer Terminal`
- AWS Storage Gateway Volume Gateway
- AWS DataSync

Yes. Q19 is very similar to Q10, so this is a good one to lock the **data-transfer decision pattern** into your memory.

## 1. What is the question saying?

Company has:

> **80 TB of data**

They want to move it from their own data center/on-premises to AWS.

Their Internet/network is slow enough that:

> **80 TB → would take 2 months**

They ask:

> **What's the fastest and most cost-effective way?**

The key problem is **bandwidth**.

So instead of sending 80 TB through their Internet connection:

```text
On-premises
   ↓
Internet
   ↓
AWS
```

they can physically take their storage device to an **AWS Data Transfer Terminal** and upload the data using the terminal's high-bandwidth AWS connectivity.

```text
Your storage device
       ↓
AWS Data Transfer Terminal
       ↓
AWS
```

### ✅ Answer: AWS Data Transfer Terminal

---

# 2. AWS Data Transfer Terminal

Think of it as:

> **"I have a huge amount of data. My network is too slow. I'll physically bring my storage device to an AWS facility and transfer it there."**

For example:

```text
Your company
   │
   │ 80 TB
   ↓
SSD / storage device
   │
   │ physically transport
   ↓
AWS Data Transfer Terminal
   │
   │ high-speed connection
   ↓
AWS
```

This avoids your slow Internet connection.

### Exam clue 🚨

If you see:

> **Huge amount of data + current bandwidth is too slow + one-time migration**

Think:

### 👉 Data Transfer Terminal

---

# 3. AWS Direct Connect ❌

Direct Connect gives you a **dedicated network connection between your on-premises environment and AWS**.

Think:

```text
Company Data Center
       │
       │ Dedicated connection
       ↓
AWS Direct Connect
       │
       ↓
AWS
```

It's excellent when you need **ongoing connectivity**.

For example:

> "Our company constantly needs private, predictable connectivity between our data center and AWS."

Then:

### ✅ Direct Connect

But this question says:

> "I need to move 80 TB quickly."

And the existing transfer takes **2 months**.

Setting up Direct Connect for a one-time migration isn't the most cost-effective solution.

### Remember:

**Direct Connect = ongoing dedicated connection**

**Data Transfer Terminal = large physical one-time transfer**

---

# 4. AWS DataSync ❌

DataSync is designed to **move/synchronize data between storage systems**.

For example:

```text
On-premises NAS
      ↓
   DataSync
      ↓
     S3
```

It's very useful for:

* ongoing transfers
* migrations
* synchronization
* moving files between on-premises storage and AWS

But there is one problem here:

### Your network is the bottleneck.

If:

```text
80 TB
 ↓
network
 ↓
2 months
```

DataSync doesn't magically remove that network limitation.

So:

**DataSync = network-based transfer**

while:

**Data Transfer Terminal = physically bring storage + high-speed AWS connection**

---

# 5. Storage Gateway Volume Gateway ❌

This one is different.

Storage Gateway lets your **on-premises applications use cloud-backed storage**.

Volume Gateway presents storage volumes to your on-premises applications, typically through iSCSI.

Think:

```text
On-premises application
       ↓
Volume Gateway
       ↓
AWS storage
```

It's designed for **hybrid cloud storage**.

It's not primarily:

> "I have 80 TB sitting on disks and want to quickly migrate it to AWS."

So don't choose it here.

---

# 🧠 Compare the four

| Service                            | Simple meaning                              | Q19? |
| ---------------------------------- | ------------------------------------------- | ---- |
| **Data Transfer Terminal**         | Physically bring storage → transfer to AWS  | ✅    |
| **Direct Connect**                 | Dedicated ongoing network connection        | ❌    |
| **DataSync**                       | Network-based data synchronization/transfer | ❌    |
| **Storage Gateway Volume Gateway** | Hybrid cloud storage for on-prem apps       | ❌    |

---

## ⭐ Very important exam pattern

Remember these three:

### 🚚 Huge one-time data migration + network too slow

**→ Data Transfer Terminal**

### 🔌 Need dedicated ongoing connection between on-premises and AWS

**→ Direct Connect**

### 🔄 Need recurring/scheduled synchronization between storage

**→ DataSync**

That's enough for Q19. Don't over-study the details—the **scenario clues** are what you need to recognize quickly in the exam.
