38. Question

Category: CSAA – Design Secure Architectures

A Solutions Architect is building a cloud infrastructure where Amazon EC2 instances require access to various AWS services, such as Amazon S3 and Amazon Redshift. The Architect will also need to provide access to system administrators so that the system administrators can deploy and test changes.

Which configuration should be used to ensure that access to the resources is secured and not compromised? (Select TWO.)

- Store the AWS Access Keys in the EC2 instance.
- Assign an IAM user for each EC2 Instance.
- `Enable Multi-Factor Authentication.`
- `Assign an IAM role to the EC2 instance.`
- Store the AWS Access Keys in ACM.

Yes, this one is also quite straightforward once you identify **who needs access** and **what they need access to**.

There are actually **two different access problems** in the question:

```text
EC2 applications  → AWS services
Admins             → AWS resources
```

And AWS uses different mechanisms for these.

---

# 🎯 1. What is the question really asking?

The question says:

### EC2 needs to access:

```text
EC2 → S3
EC2 → Redshift
```

And:

### System administrators need to:

```text
Admin → AWS → deploy/test changes
```

So we need secure authentication/authorization for both.

The two answers are:

✅ **IAM Role for EC2**

✅ **MFA for administrators**

---

# 🧠 2. Why IAM Role for EC2?

Suppose your EC2 application needs to upload something to S3.

A beginner might think:

```text
EC2
 ↓
AWS Access Key
 ↓
S3
```

So you might put:

```text
AWS_ACCESS_KEY_ID=xxxxx
AWS_SECRET_ACCESS_KEY=xxxxx
```

inside the EC2 instance.

### 🚨 That's a bad idea.

If someone compromises the EC2 instance, they might steal those credentials.

Instead:

```text
              IAM Role
                 ↓
EC2 ─────────────→ S3
                 ↓
             Redshift
```

You attach an **IAM role to the EC2 instance**.

AWS then provides the application running on that EC2 instance with **temporary credentials**.

The application doesn't need you to manually store permanent access keys.

---

# 🧠 Think of IAM Role as a temporary badge

Imagine an employee needs access to a building.

Bad approach:

```text
Give employee a permanent master key 🔑
```

Better:

```text
Give employee a temporary access badge 🎫
```

IAM Role is basically that **temporary permission mechanism**.

For example:

```text
EC2 IAM Role
   │
   ├── s3:GetObject
   ├── s3:PutObject
   └── redshift:GetClusterCredentials
```

The EC2 application gets only the permissions it needs.

---

# 🧠 3. What about administrators?

The administrators are **humans**.

They need to log in and make changes.

So we want stronger authentication:

```text
Admin
  ↓
Username + Password
  +
MFA code
  ↓
AWS
```

That's why:

### ✅ Enable MFA

MFA gives us an additional authentication factor.

Without MFA:

```text
Password stolen
     ↓
Attacker may log in
```

With MFA:

```text
Password stolen
     ↓
Attacker still needs MFA
     ↓
Much harder to compromise account
```

---

# 🔍 4. Let's eliminate the other options

### A. Store AWS Access Keys in EC2 ❌

Don't do this.

```text
EC2
 ↓
Hard-coded access keys
```

Permanent credentials can potentially be exposed.

Use:

```text
EC2
 ↓
IAM Role
 ↓
Temporary credentials
```

---

### B. Assign IAM user for each EC2 instance ❌

IAM **users are primarily identities for people**, while IAM **roles are intended for workloads/services**.

You don't want:

```text
EC2 #1 → IAM User #1
EC2 #2 → IAM User #2
EC2 #3 → IAM User #3
```

Instead:

```text
EC2 #1 → IAM Role
EC2 #2 → IAM Role
EC2 #3 → IAM Role
```

Much easier to manage.

---

### C. Enable MFA ✅

For the **system administrators/human users**.

```text
Admin
 ↓
Password
 +
MFA
 ↓
AWS
```

Correct.

---

### D. Assign IAM Role to EC2 ✅

For the **application running on EC2**.

```text
EC2
 ↓
IAM Role
 ↓
S3 / Redshift
```

Correct.

---

### E. Store AWS Access Keys in ACM ❌

This one is testing whether you know what **ACM** is.

**ACM = AWS Certificate Manager.**

It's for:

```text
SSL/TLS certificates
```

For example:

```text
HTTPS
 ↓
Certificate
 ↓
ACM
```

It is **not a credential-storage service for AWS access keys**.

---

# 📊 Final summary

| Requirement                      | Correct solution | Why                                 |
| -------------------------------- | ---------------- | ----------------------------------- |
| EC2 needs S3/Redshift access     | **IAM Role**     | Temporary credentials + permissions |
| Administrators need secure login | **MFA**          | Additional authentication factor    |
| Store access keys on EC2         | ❌                | Credentials can be compromised      |
| IAM user for every EC2           | ❌                | Roles are designed for workloads    |
| Store access keys in ACM         | ❌                | ACM manages SSL/TLS certificates    |

---

# 🔥 SAA shortcut

This is one of the **most important IAM patterns**:

> **AWS service/workload needs access → IAM Role**

```text
EC2 → IAM Role
Lambda → IAM Role
ECS → IAM Role
```

And:

> **Human needs stronger login security → MFA**

```text
Administrator → MFA
IAM User → MFA
Root User → MFA
```

So for this question, just split it into:

**EC2 = Role** 🎫
**Human admin = MFA** 🔐

That's why the two correct answers are **IAM Role + MFA**.
