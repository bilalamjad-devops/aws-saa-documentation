42. Question

Category: CSAA – Design Resilient Architectures

A company has a top priority requirement to monitor certain database metrics and send email notifications to the Operations team if any issues occur.

Which combination of AWS services can accomplish this requirement? (Select TWO.)

- Amazon EC2 Instance with a running Berkeley Internet Name Domain (BIND) Server.
- `Amazon CloudWatch`
- `Amazon Simple Notification Service (SNS)`
- Amazon Simple Queue Service (SQS)
- Amazon Simple Email Service

Exactly. **Q42 is very easy once you recognize the pattern.** 👍

The entire question can be reduced to:

```text
Database
   ↓
MONITOR
   ↓
CloudWatch
   ↓
ALERT / NOTIFY
   ↓
SNS
   ↓
📧 Operations Team
```

### 🎯 The two jobs

| Requirement              | AWS service    |
| ------------------------ | -------------- |
| Monitor database metrics | **CloudWatch** |
| Send notification/email  | **SNS**        |

So:

### ✅ CloudWatch + SNS

---

### 🧠 Why CloudWatch?

CloudWatch is your **AWS monitoring service**.

It collects things like:

* CPU utilization
* Database connections
* Storage
* Network
* latency
* application metrics
* logs

For example:

```text
RDS CPU > 80%
       ↓
CloudWatch Alarm
       ↓
"Problem detected!"
```

---

### 🔔 Why SNS?

SNS is your **notification/messaging service**.

```text
CloudWatch Alarm
       ↓
SNS Topic
       ↓
Email
       ↓
Operations Team
```

So the mental model is:

> **CloudWatch detects → SNS tells people.**

---

# 🔥 Very important SAA pattern

You'll see this pattern **again and again**:

```text
AWS Resource
     ↓
CloudWatch
     ↓
CloudWatch Alarm
     ↓
SNS
     ↓
Email / SMS / other subscribers
```

For example:

**EC2 CPU too high**

```text
EC2 → CloudWatch → Alarm → SNS → Email
```

**RDS storage getting low**

```text
RDS → CloudWatch → Alarm → SNS → Email
```

**Lambda errors**

```text
Lambda → CloudWatch → Alarm → SNS → Email
```

---

## 🆚 Don't confuse SNS, SQS, SES

This is worth remembering:

| Service        | Mental model                        |
| -------------- | ----------------------------------- |
| **CloudWatch** | 👀 Monitor                          |
| **SNS**        | 📢 Notify / broadcast               |
| **SQS**        | 📥 Queue / waiting line             |
| **SES**        | 📧 Send application/business emails |

### Easy distinction:

> **CloudWatch = "Something happened."**

> **SNS = "Tell everyone who needs to know."**

> **SQS = "Put this job in a queue for someone to process."**

> **SES = "I need to send emails from my application."**

So your summary is **perfect**:

### **Monitoring → CloudWatch**

### **Notification → SNS** ✅
