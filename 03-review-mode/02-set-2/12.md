12. Question

Category: CSAA – Design Secure Architectures

A media company has two VPCs: VPC-1 and VPC-2 with peering connection between each other. VPC-1 only contains private subnets while VPC-2 only contains public subnets. The company uses a single AWS Direct Connect connection and a virtual interface to connect their on-premises network with VPC-1.

Which of the following options increase the fault tolerance of the connection to VPC-1? (Select TWO.)

- `Establish a hardware VPN over the Internet between VPC-1 and the on-premises network.`
- Establish a new AWS Direct Connect connection and private virtual interface in the same region as VPC-2.
- `Establish another AWS Direct Connect connection and private virtual interface in the same AWS region as VPC-1.`
- Use the AWS VPN CloudHub to create a new AWS Direct Connect connection and private virtual interface in the same region as VPC-2.
- Establish a hardware VPN over the Internet between VPC-2 and the on-premises network.

Bilal, this question is mainly testing **network redundancy / fault tolerance** and one important rule: **VPC Peering does NOT provide transitive routing.**

### 1. What is the current setup?

Think of it like this:

```text
On-Premises
     |
     | Direct Connect
     |
   VPC-1  <------ VPC Peering ------>  VPC-2
(private)                           (public)
```

Currently, there is **only ONE Direct Connect connection** between on-premises and VPC-1.

### 2. What's the problem?

If that **one Direct Connect connection fails**, your on-premises network loses connectivity to VPC-1.

So AWS asks:

> "What can you add so that if the primary connection fails, there is another path?"

That's what **fault tolerance** means here.

---

## Answer 1: Add another Direct Connect

You can create:

```text
                 Direct Connect #1
On-Premises ------------------------> VPC-1
     |
     |
     +---------- Direct Connect #2 -> VPC-1
```

Now if DX #1 fails:

```text
DX #1 ❌

On-Premises --------DX #2--------> VPC-1
```

So:

**Another Direct Connect + private VIF in the same region as VPC-1 = ✅**

---

## Answer 2: Add a VPN

You can also create a backup VPN:

```text
                   Direct Connect
                 /
On-Premises ----
                 \
                   VPN over Internet
```

Normally traffic can use Direct Connect.

If DX fails, VPN can provide another path.

So:

**Hardware VPN between on-premises and VPC-1 = ✅**

---

# But why can't we use VPC-2?

This is the tricky part.

You might think:

```text
On-Premises
     |
    VPN
     |
   VPC-2
     |
 VPC Peering
     |
   VPC-1
```

But AWS says **NO**.

Why?

Because **VPC Peering does not support transitive routing.**

In simple words:

> **VPC Peering connects A ↔ B, but B cannot act as a router to C.**

For example:

```text
On-Premises <--VPN--> VPC-2 <--Peering--> VPC-1
```

You cannot use VPC-2 as a middleman to reach VPC-1.

### Very important exam shortcut

**VPC Peering = direct connection only, NOT a transit router.**

---

# One more thing: Direct Connect vs VPN

Think of them like this:

| Service              | Simple meaning                                               |
| -------------------- | ------------------------------------------------------------ |
| **Direct Connect**   | Dedicated private network connection from on-premises to AWS |
| **Site-to-Site VPN** | Encrypted connection over the public Internet                |
| **VPC Peering**      | Direct private connection between two VPCs                   |
| **VPN CloudHub**     | Connect multiple remote networks/VPN sites through a hub     |
| **Private VIF**      | Direct Connect interface used to access resources in a VPC   |

So for this question:

| Option                       | Correct? | Why                                                        |
| ---------------------------- | -------- | ---------------------------------------------------------- |
| VPN: On-premises → VPC-1     | ✅        | Backup path                                                |
| New DX: On-premises → VPC-1  | ✅        | Second independent connection                              |
| DX: On-premises → VPC-2      | ❌        | Doesn't solve connectivity to VPC-1                        |
| VPN: On-premises → VPC-2     | ❌        | Can't use VPC peering transitively                         |
| VPN CloudHub involving VPC-2 | ❌        | Doesn't overcome the peering/transitive-routing limitation |

### 🧠 Shortcut

| If you see...                          | Think...                            |
| -------------------------------------- | ----------------------------------- |
| **Fault tolerance for Direct Connect** | Add another **DX** or **VPN**       |
| **VPC A → VPC B → VPC C**              | ❌ VPC Peering is **not transitive** |
| **Need backup for DX**                 | **VPN over Internet**               |
| **Two VPCs need direct communication** | **VPC Peering**                     |
| **On-premises → AWS privately**        | **Direct Connect / VPN**            |

**The exam's core idea:**

> One DX connection = single point of failure. Add **another DX** or **VPN directly to VPC-1**.
