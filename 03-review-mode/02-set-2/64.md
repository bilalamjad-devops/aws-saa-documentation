64. Question

Category: CSAA – Design Resilient Architectures

A start-up company has an EC2 instance that is hosting a web application. The volume of users is expected to grow in the coming months and hence, you need to add more elasticity and scalability in your AWS architecture to cope with the demand.

Which of the following options can satisfy the above requirement for the given scenario? (Select TWO.)

- `Set up two EC2 instances and use Route 53 to route traffic based on a Weighted Routing Policy.`
- Set up an AWS WAF behind your EC2 Instance.
- `Set up two EC2 instances and then put them behind an Elastic Load balancer (ELB).`
- Set up an S3 Cache in front of the EC2 instance.
- Set up two EC2 instances deployed using Launch Templates and integrated with AWS Glue.

### 🎯 What is being tested?

**EC2 application → add scalability + elasticity + handle growing traffic.**

### ✅ Correct answers — Select TWO

**1. Set up two EC2 instances and then put them behind an Elastic Load Balancer (ELB).**

**2. Set up two EC2 instances and use Route 53 to route traffic based on a Weighted Routing Policy.**

### 🔑 Key concept

**ELB + multiple EC2 instances**
→ Distributes incoming traffic across instances.
→ Provides **high availability and scalability**.

**Route 53 Weighted Routing**
→ Can distribute traffic across multiple EC2 instances/resources based on assigned weights.

### ❌ Why others are wrong

* **AWS WAF** ❌ → Security/firewall service, not scalability.
* **S3 Cache** ❌ → No such architecture/service; caching would typically involve **CloudFront**.
* **Launch Templates + AWS Glue** ❌ → Glue is an ETL/data integration service, unrelated to EC2 web-app scalability.

### 🔥 Exam shortcut

**Growing web traffic + multiple EC2 = ELB**

**Route 53 Weighted = distribute traffic by percentage/weight**

Also remember:

> **Scalability → add more EC2 instances**
> **Load balancing → ELB distributes traffic**
> **Elasticity → automatically add/remove capacity (usually ASG)**
