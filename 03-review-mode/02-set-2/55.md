55. Question

Category: CSAA – Design High-Performing Architectures

A company receives semi-structured and structured data from different sources, which are eventually stored in the Amazon S3 data lake that uses client-side encryption with a custom client-side root key (CSE-Custom). The Solutions Architect plans to use big data processing frameworks to analyze data and access it using various business intelligence tools and standard SQL queries.

Which of the following provides the MOST high-performing solution that fulfills this requirement?

<img width="701" height="251" alt="AWS-EMR-Redshift-Services (1)" src="https://github.com/user-attachments/assets/045c5f4f-b227-4400-800d-ee978ae9d315" />


- `Create an Amazon EMR cluster and store the processed data in Amazon Redshift.`
- Create an Amazon EC2 instance and store the processed data in Amazon EBS.
- Use Amazon Managed Service for Apache Flink Studio and store the processed data in Amazon DynamoDB.
- Use AWS Batch jobs to process the data and store the processed data in S3.

### 🎯 What is being tested?

**Big data processing + SQL/BI analytics.**

### ✅ Correct answer

**Amazon EMR → Amazon Redshift**

* **EMR** → runs big-data frameworks like **Hadoop/Spark** for processing and ETL.
* **Redshift** → data warehouse for **complex SQL queries + BI tools** over structured/semi-structured data.

### ❌ Quick elimination

* **EC2 + EBS** → manual management, poor scalability.
* **Flink + DynamoDB** → Flink is mainly for **streaming**; DynamoDB isn't the right SQL/BI analytics warehouse.
* **AWS Batch + S3** → good for batch compute, but doesn't provide the required high-performance SQL/BI analytics.

🔥 **Exam shortcut:**
**Big data frameworks → EMR**
**SQL + BI + data warehouse → Redshift**

So: **EMR processes → Redshift analyzes.**
