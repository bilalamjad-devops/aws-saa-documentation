31. Question

Category: CSAA – Design Secure Architectures

An organization stores and manages financial records of various companies in its on-premises data center, which is almost out of space. The management decided to move all of its existing records to a cloud storage service. All future financial records will also be stored in the cloud. For additional security, all records must be prevented from being deleted or overwritten. Once migrated, the records will be accessed less than once a month but must be available immediately if audited, requiring the use of S3 Standard-Infrequent Access.

Which of the following should be done to meet the above requirement?

- Use AWS Storage Gateway to establish hybrid cloud storage. Store all of your data in Amazon EBS and enable object lock.
- Use multi-Region replication to transfer the on‑premises records into Amazon S3 and enable Object Lock.
- `Use AWS DataSync to move the data. Store all of your data in Amazon S3 and enable object lock.`
- Use AWS DataSync to move the data. Store all of your data in Amazon EFS and enable object lock.

Exactly 👍 This one is also **easy once you identify the 3 requirements**. The question is mainly testing whether you can match the right AWS service to each requirement.

## 1. What is the question asking?

There are **three separate requirements**:

### Requirement 1 — Move existing on-premises data to AWS

They already have financial records in their own data center:

```text
On-premises data center
        │
        │ migrate
        ▼
       AWS
```

For moving a large existing dataset from on-premises → AWS:

👉 **AWS DataSync**

---

### Requirement 2 — Where should the records be stored?

They specifically require:

> S3 Standard-Infrequent Access

So obviously:

👉 **Amazon S3**

And because the records are accessed less than once a month but must be available immediately:

```text
S3 Standard-IA
      ↓
Infrequent access
      +
Immediate retrieval
```

Remember the S3 storage-class pattern:

| Requirement                                 | Think                  |
| ------------------------------------------- | ---------------------- |
| Frequently accessed                         | S3 Standard            |
| Infrequently accessed + immediate access    | **S3 Standard-IA**     |
| Automatically optimize between access tiers | S3 Intelligent-Tiering |
| Long-term archive                           | Glacier classes        |

---

### Requirement 3 — Nobody can delete or overwrite records

This is the biggest security keyword:

> **prevented from being deleted or overwritten**

👉 **S3 Object Lock**

Think of it like putting a legal record into a **tamper-proof box**:

```text
Financial Record
      │
      ▼
   S3 Bucket
      │
      ▼
  Object Lock 🔒
      │
      ├── Cannot delete
      └── Cannot overwrite
```

This is particularly relevant for financial/compliance records.

---

# Therefore:

```text
On-premises
    │
    │ AWS DataSync
    ▼
S3 Standard-IA
    │
    └── Object Lock 🔒
```

That's why **Option 3 is correct.**

---

# Now let's eliminate the options

### Option 1 ❌

> Storage Gateway → EBS → Object Lock

Multiple problems.

**EBS doesn't support S3 Object Lock.**

Object Lock is an **S3 feature**.

Also, Storage Gateway is more about maintaining a **hybrid storage environment**, where on-premises applications continue accessing AWS-backed storage.

This question is primarily asking:

> "Move my existing data to AWS and archive it there."

That's where **DataSync** fits better.

---

### Option 2 ❌

> Multi-Region replication → transfer on-premises records into S3

The problem is the **direction**.

S3 replication works like:

```text
S3 Bucket A
     │
     │ replication
     ▼
S3 Bucket B
```

It replicates **S3 objects to another S3 bucket**.

It doesn't mean:

```text
On-premises
     │
     ▼
S3
```

For on-premises → S3 migration:

👉 **DataSync**

---

### Option 3 ✅

> DataSync → S3 → Object Lock

Everything matches:

```text
Existing data
     │
     ▼
 AWS DataSync
     │
     ▼
 S3 Standard-IA
     │
     ▼
 Object Lock 🔒
```

**Correct.**

---

### Option 4 ❌

> DataSync → EFS → Object Lock

DataSync can indeed move data to EFS.

So the **DataSync part is fine**.

The problem is:

> **EFS does not have S3 Object Lock.**

Object Lock is an **S3 capability**.

Therefore:

**DataSync + EFS = ❌**

**DataSync + S3 = ✅**

---

# The important exam shortcut

This question is actually teaching you **four things at once**:

```text
ON-PREMISES → AWS
      ↓
  DataSync

OBJECT STORAGE
      ↓
     S3

Rarely accessed + immediate retrieval
      ↓
 S3 Standard-IA

Prevent deletion/overwrite
      ↓
 S3 Object Lock
```

### 🔥 Memorize this combination:

> **On-premises → S3 migration = DataSync**
> **Infrequent but immediate access = S3 Standard-IA**
> **Prevent deletion/overwrite = S3 Object Lock**

And you're right — **Q31 is mainly a keyword-matching question**. The only thing worth making sure you understand deeply is the difference between **DataSync vs Storage Gateway**, because AWS loves testing that distinction.
