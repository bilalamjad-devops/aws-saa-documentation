63. Question

Category: CSAA – Design Secure Architectures

For data privacy, a healthcare company has been asked to comply with the Health Insurance Portability and Accountability Act (HIPAA). The company stores all its backups on an Amazon S3 bucket. It is required that data stored on the S3 bucket must be encrypted.

What is the best option to do this? (Select TWO.)

- Enable Server-Side Encryption on an S3 bucket to make use of AES-128 encryption.
- Store the data on Amazon EBS volumes with encryption enabled instead of using S3.
- `Enable Server-Side Encryption on an S3 bucket to make use of AES-256 encryption.`
- Store the data in encrypted Amazon EBS snapshots.
- `Before sending the data to S3 over HTTPS, encrypt the data locally first using your own encryption keys.`

### 🎯 What is being tested?

**S3 encryption → which encryption methods satisfy data-at-rest encryption?**

### ✅ Correct answers — Select TWO

**1. Enable Server-Side Encryption on an S3 bucket to make use of AES-256 encryption.**

**2. Before sending the data to S3 over HTTPS, encrypt the data locally first using your own encryption keys.**

### 🔑 Key concepts

**S3 Server-Side Encryption (SSE)**
→ AWS encrypts the data **after it reaches S3**.
→ S3 uses **AES-256** encryption.

**Client-Side Encryption**
→ You encrypt the data **before uploading it to S3** using your own keys.
→ Then upload the already-encrypted data over HTTPS.

Both provide **encryption at rest**.

### ❌ Why others are wrong

* **AES-128** ❌ → S3 server-side encryption uses **AES-256**, not AES-128.
* **EBS volumes** ❌ → The company is storing backups in **S3**; moving them to EBS doesn't solve the requirement.
* **Encrypted EBS snapshots** ❌ → Same issue; they're EBS backups, not S3 backups.

### 🔥 Exam shortcut

**S3 encryption → remember AES-256**

**SSE:** AWS encrypts it
**Client-side:** *You* encrypt it before upload

> **HTTPS = encryption in transit**
> **SSE / client-side encryption = encryption at rest**
