
3. Question

Category: CSAA – Design Secure Architectures

A company is hosting its web application in an Auto Scaling group of Amazon EC2 instances behind an Application Load Balancer. Recently, the Solutions Architect identified a series of SQL injection attempts and cross-site scripting attacks to the application, which had adversely affected its production data.

Which of the following should the Architect implement to mitigate this kind of attack?

- Using AWS Firewall Manager, set up security rules that block SQL injection and cross-site scripting attacks. Associate the rules to the Application Load Balancer.
- Block all the IP addresses where the SQL injection and cross-site scripting attacks originated using the Network Access Control List.
- Using AWS X-Ray to detect and block SQL injection and cross‑site scripting attacks.
- `Set up security rules that block SQL injection and cross-site scripting attacks in AWS Web Application Firewall (AWS WAF). Associate the rules to the Application Load Balancer.`

Exactly. This question is reinforcing the **WAF pattern** you already learned in Question 56. The main thing to learn here is **which AWS security service works at which layer**.

## What is the question saying?

Your architecture is:

```text
Internet
   ↓
   ALB
   ↓
EC2 Auto Scaling Group
   ↓
Application
```

Attackers are sending things like:

```text
SQL Injection
XSS (Cross-Site Scripting)
```

These are **web/application-layer attacks**.

The question asks:

> "Which AWS service can inspect web requests and block these malicious requests before they reach my application?"

Answer:

**AWS WAF → attach to ALB.** ✅

Think:

```text
Attacker
   ↓
AWS WAF  ← "Is this malicious HTTP request?"
   ↓
  ALB
   ↓
  EC2
```

---

# 1. AWS WAF

**WAF = Web Application Firewall**

It understands **web/HTTP requests** and can filter them.

Examples:

* SQL injection
* XSS
* malicious HTTP requests
* unwanted IP addresses
* specific HTTP headers
* suspicious query strings
* rate limiting

So:

> **Web attack → WAF**

And WAF can protect:

* CloudFront
* ALB
* API Gateway
* AppSync

### Easy memory

**WAF = Web attacks**

---

# 2. AWS X-Ray

This one is completely different.

**X-Ray = application tracing/observability.**

Imagine your application has:

```text
User
 ↓
ALB
 ↓
EC2
 ↓
Service A
 ↓
Service B
 ↓
RDS
```

Something is slow.

You want to know:

> "Where is the request spending 5 seconds?"

X-Ray helps trace the request through the application.

For example:

```text
Request
  ↓
ALB       20 ms
  ↓
EC2       50 ms
  ↓
Service   100 ms
  ↓
RDS       4,000 ms  ← problem!
```

So:

> **X-Ray = trace/debug application requests**

It **doesn't block SQL injection or XSS**.

### Shortcut

**WAF → blocks web attacks**

**X-Ray → traces application requests**

---

# 3. AWS Firewall Manager

Your understanding is basically correct. 👍

Firewall Manager is primarily about **centrally managing security rules across multiple AWS accounts/resources**.

Imagine a company has:

```text
AWS Organization
│
├── Account A
├── Account B
├── Account C
└── Account D
```

They want the same WAF policy across all accounts.

Instead of manually configuring WAF everywhere:

```text
Account A → WAF
Account B → WAF
Account C → WAF
Account D → WAF
```

Firewall Manager helps centrally manage/enforce those security policies.

So remember:

> **Firewall Manager = central management of security policies across accounts/resources**

It doesn't replace WAF.

Think:

```text
Firewall Manager
       ↓
 manages/enforces
       ↓
      WAF
       ↓
      ALB
```

---

# 4. NACL

NACL = **Network Access Control List**

This works at the **subnet/network layer**.

For example:

```text
Internet
   ↓
NACL
   ↓
Subnet
   ↓
ALB
```

You can say:

> Allow traffic from `1.2.3.4`

or:

> Deny traffic from `5.6.7.8`

But NACL doesn't understand:

```text
SELECT * FROM users WHERE...
<script>...
```

It primarily deals with **network traffic based on things such as IP addresses and ports**, not the meaning of HTTP application requests.

Therefore:

**SQL injection → don't think NACL.**

---

# 🧠 The important comparison

| Service              | What does it do?                         | Think                              |
| -------------------- | ---------------------------------------- | ---------------------------------- |
| **AWS WAF**          | Inspects/filters web requests            | 🛡️ SQL injection, XSS             |
| **AWS X-Ray**        | Traces application requests              | 🔍 Find where app is slow          |
| **Firewall Manager** | Centrally manages security policies      | 🏢 Multiple AWS accounts           |
| **NACL**             | Controls network traffic at subnet level | 🌐 IP/port/network                 |
| **Security Group**   | Controls traffic to ENI/instance         | 🔐 Instance-level network firewall |

### 🔥 SAA shortcut

When you see:

**SQL injection / XSS / malicious HTTP request**

→ **WAF**

When you see:

**trace request / troubleshoot latency / distributed application**

→ **X-Ray**

When you see:

**centrally apply WAF/security policies across multiple AWS accounts**

→ **Firewall Manager**

When you see:

**allow/deny IP, subnet, port traffic**

→ **NACL / Security Group**

---

### One more important distinction

Don't think:

> "Firewall Manager blocks attacks."

Think:

> **WAF blocks web attacks. Firewall Manager manages/enforces WAF/security policies centrally.**

That's the distinction this question wants you to learn.
