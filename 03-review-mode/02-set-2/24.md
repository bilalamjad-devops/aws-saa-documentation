24. Question

Category: CSAA – Design Secure Architectures

A startup has multiple AWS accounts that are assigned to its development teams. Since the company is projected to grow rapidly, the management wants to consolidate all of its AWS accounts into a multi-account setup. To simplify the login process on the AWS accounts, the management wants to utilize its existing directory service for user authentication

Which combination of actions should a solutions architect recommend to meet these requirements? (Select TWO.)

- Create an identity pool on Amazon Cognito and configure it to use the company’s directory service. Configure AWS IAM Identity Center (AWS Single Sign-On) to accept Cognito authentication.
- Create Service Control Policies (SCP) in the organization to manage the child accounts. Configure AWS IAM Identity Center (AWS Single Sign-On) to use AWS Directory Service.
- `On the master account, use AWS Organizations to create a new organization with all features turned on. Invite the child accounts to this new organization.`
- On the master account, use AWS Organizations to create a new organization with all features turned on. Enable the organization’s external authentication and point it to use the company’s directory service.
- `Configure AWS IAM Identity Center (AWS Single Sign-On) for the organization and integrate it with the company’s directory service using the Active Directory Connector`

Absolutely. This question is basically testing **two separate things**:

1. **How do we combine/manage multiple AWS accounts?** → **AWS Organizations**
2. **How do users log in to all those AWS accounts using the company's existing directory?** → **IAM Identity Center + Active Directory Connector**

Let's break it down simply.

---

# 1. What is the question saying?

The company already has:

```text
AWS Account 1 → Development Team A
AWS Account 2 → Development Team B
AWS Account 3 → Development Team C
AWS Account 4 → Development Team D
```

They have many separate AWS accounts.

Management says:

> "We are growing. Let's manage all these AWS accounts together."

That's where **AWS Organizations** comes in.

So:

```text
             AWS Organization
                    |
       ┌────────────┼────────────┐
       ↓            ↓            ↓
   Account 1    Account 2    Account 3
```

AWS Organizations gives you **centralized management of multiple AWS accounts**.

---

# 2. Second requirement: simplify login

The company already has a **directory service**.

Think of a company directory as:

```text
Company Active Directory

Bilal
Ahmed
Ali
Sara
...
```

The company already has usernames/passwords there.

They don't want employees to create separate IAM users in every AWS account.

Without centralized login:

```text
Bilal
 ↓
AWS Account 1 → username/password
AWS Account 2 → username/password
AWS Account 3 → username/password
```

That's annoying.

Instead, they want:

```text
             Company Directory
             (Active Directory)
                     ↓
          IAM Identity Center
                     ↓
        ┌────────────┼────────────┐
        ↓            ↓            ↓
    Account 1    Account 2    Account 3
```

Bilal logs in once and gets access to the AWS accounts he's authorized to use.

That's **IAM Identity Center**.

---

# 3. What is IAM Identity Center?

Think:

> **IAM Identity Center = centralized login/access to multiple AWS accounts**

For example:

```text
Bilal logs into AWS Access Portal
             ↓
       IAM Identity Center
             ↓
       ┌─────┼─────┐
       ↓     ↓     ↓
      Dev   Test   Prod
```

The user can see the AWS accounts they have permission to access.

It is especially useful with **AWS Organizations**.

---

# 4. What is Active Directory Connector?

This part is confusing, but the idea is simple.

Suppose the company already has:

```text
Company Active Directory
        ↓
  bilal
  ahmed
  sara
```

AWS doesn't need you to create those users again.

**AWS Directory Service — AD Connector** can connect AWS IAM Identity Center to the company's existing Active Directory.

Conceptually:

```text
Company's existing AD
        ↓
   AD Connector
        ↓
IAM Identity Center
        ↓
 AWS Organizations
        ↓
AWS Account 1
AWS Account 2
AWS Account 3
```

So employees can use their **existing corporate credentials**.

---

# 5. Now let's understand the correct answers

### ✅ Option 1

> On the master account, use AWS Organizations to create a new organization with all features turned on. Invite the child accounts to this new organization.

Correct.

Why?

Because the company wants to consolidate multiple AWS accounts.

**AWS Organizations = account management.**

```text
Organization
   ├── Account A
   ├── Account B
   ├── Account C
   └── Account D
```

---

### ✅ Option 2

> Configure AWS IAM Identity Center for the organization and integrate it with the company's directory service using the Active Directory Connector.

Correct.

Why?

Because the company wants to use its **existing directory for authentication**.

```text
Existing Company AD
        ↓
   AD Connector
        ↓
IAM Identity Center
        ↓
AWS Accounts
```

So the two answers together solve both requirements:

| Requirement                   | AWS service             |
| ----------------------------- | ----------------------- |
| Manage multiple AWS accounts  | **AWS Organizations**   |
| Centralized login             | **IAM Identity Center** |
| Use existing Active Directory | **AD Connector**        |

---

# 6. Why is Cognito wrong?

The option says:

> Create an identity pool on Amazon Cognito...

Remember the distinction we discussed earlier.

**Amazon Cognito is primarily for users logging into your applications.**

For example:

```text
Your Website
     ↓
  Cognito
     ↓
User logs in
```

Example:

```text
myshoppingapp.com

Login with:
- Google
- Facebook
- username/password
```

Cognito is about **application users**.

IAM Identity Center is about **people accessing AWS accounts/applications**.

### Easy distinction

```text
Cognito
   ↓
"My customers need to log into my application."

IAM Identity Center
   ↓
"My employees need to log into AWS accounts."
```

---

# 7. Why is SCP wrong?

Option:

> Create Service Control Policies (SCP) ... Configure IAM Identity Center...

SCP is not a login mechanism.

Think:

**SCP = guardrail/restriction**

For example:

> "Nobody in these accounts is allowed to use certain AWS services."

```text
AWS Organization
       ↓
      SCP
       ↓
Restrict what accounts can do
```

It doesn't authenticate Bilal.

So:

```text
Authentication
     ↓
Who are you?
     ↓
IAM Identity Center / directory
```

Whereas:

```text
SCP
 ↓
What are you allowed to do at the organization level?
```

---

# 8. Why is "external authentication in Organizations" wrong?

The option says:

> Enable the organization's external authentication and point it to the company's directory.

No.

**AWS Organizations doesn't provide this login mechanism.**

Organizations manages accounts.

IAM Identity Center handles centralized AWS access/login and can integrate with your directory.

So don't mix these two.

---

# 9. The big picture you should remember

This is probably the most important thing for your SAA exam:

```text
                    AWS ORGANIZATIONS
                           |
              ┌────────────┼────────────┐
              ↓            ↓            ↓
          AWS Account   AWS Account   AWS Account
              1             2            3
              ↑             ↑            ↑
              └─────────────┼────────────┘
                            |
                  IAM Identity Center
                            ↑
                            |
                      AD Connector
                            ↑
                            |
                Company's Active Directory
```

### Memorize these four:

**AWS Organizations**
→ Manage **multiple AWS accounts**

**IAM Identity Center**
→ Centralized **AWS account login/access**

**AD Connector**
→ Connect AWS to existing **Microsoft Active Directory**

**Cognito**
→ User authentication for **your applications/web/mobile apps**

---

## One-line exam trick 🧠

When you see:

> **"Multiple AWS accounts + existing corporate directory + centralized login"**

Think:

**AWS Organizations + IAM Identity Center + Active Directory Connector**

And when you see:

> **"Users need to log into our web/mobile application"**

Think:

**Amazon Cognito**.
