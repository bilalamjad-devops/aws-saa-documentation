1. Question

Category: CSAA – Design High-Performing Architectures

A company is running a multi-tier web application farm in a virtual private cloud (VPC) that is not connected to their corporate network. They are connecting to the VPC over the Internet to manage the fleet of Amazon EC2 instances running in both the public and private subnets. The Solutions Architect has added a bastion host with Microsoft Remote Desktop Protocol (RDP) access to the application instance security groups, but the company wants to further limit administrative access to all of the instances in the VPC.

Which of the following bastion host deployment options will meet this requirement?

- `Deploy a Windows Bastion host with an Elastic IP address in the public subnet and allow RDP access to bastion only from the corporate IP addresses.`
- Deploy a Windows Bastion host on the corporate network that has RDP access to all EC2 instances in the VPC.
- Deploy a Windows Bastion host with an Elastic IP address in the private subnet, and restrict RDP access to the bastion from only the corporate public IP addresses.
- Deploy a Windows Bastion host with an Elastic IP address in the public subnet and allow SSH access to the bastion from anywhere.

Absolutely. This question is teaching you a **very common AWS networking/security pattern: Bastion Host (Jump Server).**

### What is the question saying?

Imagine your VPC has:

```text
Internet
   |
   | RDP
   ↓
[Bastion Host]
   |
   | RDP
   ↓
[Private EC2 instances]
```

You have EC2 instances in **public and private subnets**, and administrators need to manage them.

The company says:

> "I don't want administrators connecting directly to every EC2 instance. I want ONE controlled entry point."

That ONE entry point is the **Bastion Host**.

### Why public subnet?

The administrators are coming from outside AWS over the Internet.

Therefore:

**Bastion → Public subnet → Elastic/Public IP**

A public subnet has a route to the Internet Gateway, allowing administrators to reach the bastion.

The private EC2 instances don't need public IPs.

### Why allow RDP only from corporate IP?

Because this is the security improvement the question is asking for.

Bad:

```text
Internet → Bastion
          Anyone can try RDP ❌
```

Better:

```text
Corporate IP
     |
     | RDP : 3389
     ↓
Bastion
     |
     | RDP
     ↓
Private EC2
```

So the bastion's Security Group should essentially say:

> Allow TCP 3389 **only from the company's public IP addresses**.

### Why not private subnet?

Because the administrator is connecting **from the Internet**.

A private-subnet bastion doesn't have direct Internet reachability.

So remember:

**Internet → Bastion = Public subnet**

**Bastion → Private EC2 = Private subnet**

### Why RDP instead of SSH?

The question specifically says **Windows Bastion**.

Windows administration → **RDP**

Linux administration → **SSH**

So:

| Situation   | Protocol |
| ----------- | -------- |
| Windows EC2 | RDP      |
| Linux EC2   | SSH      |

### 🔑 Shortcut

| Clue in question                       | Think                               |
| -------------------------------------- | ----------------------------------- |
| Need controlled admin entry point      | **Bastion Host**                    |
| Administrators coming through Internet | Bastion in **Public Subnet**        |
| Bastion needs Internet reachability    | **Public/Elastic IP**               |
| Windows                                | **RDP (3389)**                      |
| Linux                                  | **SSH (22)**                        |
| Restrict administrators                | Allow only **corporate public IPs** |
| EC2 behind bastion                     | Usually **Private Subnet**          |

**One-line exam memory:**

> **Bastion = public subnet + public/Elastic IP + SSH/RDP restricted to trusted IPs → then access private instances.**

This is exactly the kind of pattern worth memorizing for your SAA exam.

Yes — **your understanding of the access-control idea is correct**, with one small correction.

### What is a corporate IP address?

It means the **public IP address from which the company's network appears on the Internet**.

For example:

```text
Company office network
        |
        | Public Internet
        |
   Public IP: 203.0.113.10
        |
        ↓
      AWS VPC
```

The company may have a **static public IP address** assigned by its ISP. It does **not have to be an AWS Elastic IP**.

So don't memorize:

> Corporate IP = Elastic IP ❌

Instead:

> **Corporate IP = trusted public IP address of the company's network.** ✅

---

### And yes, your second understanding is exactly right

The Bastion Security Group can say:

```text
Source IP              Action
──────────────────────────────
203.0.113.10           ✅ Allow RDP
198.51.100.20          ❌ Reject
45.x.x.x               ❌ Reject
Any other IP           ❌ Reject
```

So:

```text
Corporate network
203.0.113.10
      |
      | RDP 3389
      ↓
[Bastion Host]
      |
      ↓
Private EC2
```

But:

```text
Random Internet user
198.51.100.20
      |
      | RDP 3389
      ↓
[Bastion]
      X
    DENIED
```

### 🔥 The important exam idea

The question isn't really testing **Elastic IP**.

It's testing:

> **"How do I make the Bastion Host accessible only to trusted administrators?"**

Answer:

**Restrict the Bastion Security Group's RDP inbound rule to the company's trusted public IP/CIDR range.**

And because it's Windows:

**RDP = TCP 3389.**

So your mental shortcut can be:

> **Corporate IP = trusted source → allow; everyone else → deny.**
