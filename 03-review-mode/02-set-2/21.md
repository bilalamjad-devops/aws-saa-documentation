21. Question

Category: CSAA – Design Secure Architectures

A multinational company currently operates multiple AWS accounts to support its operations across various branches and business units. The company needs a more efficient and secure approach in managing its vast AWS infrastructure to avoid costly operational overhead.

To address this, they plan to transition to a consolidated, multi-account architecture while integrating a centralized corporate directory service for authentication purposes.

Which combination of options can be used to meet the above requirements? (Select TWO.)

- `Integrate AWS IAM Identity Center with the corporate directory service for centralized authentication. Configure a service control policy (SCP) to manage the AWS accounts.`
- Utilize AWS CloudTrail to enable centralized logging and monitoring across all AWS accounts.
- Establish an identity pool through Amazon Cognito and adjust the AWS IAM Identity Center settings to allow Amazon Cognito authentication.
- Set up a new entity in AWS Organizations and configure its authentication system to utilize AWS Directory Service directly.
- `Implement AWS Organizations to create a multi-account architecture that provides a consolidated view and centralized management of AWS accounts.`

Yes. Your understanding of **IAM, Cognito, and CloudTrail** is already mostly correct. This question is mainly teaching you the difference between **AWS Organizations, IAM Identity Center, SCP, and corporate directory**.

# 21. First: What is the question saying?

The company has many AWS accounts:

```text
Company
│
├── AWS Account 1 → Pakistan
├── AWS Account 2 → UAE
├── AWS Account 3 → UK
├── AWS Account 4 → Development
└── AWS Account 5 → Production
```

They have two problems:

### Problem 1 — Too many AWS accounts

They want:

> "Give me one centralized place to manage all these AWS accounts."

👉 **AWS Organizations**

### Problem 2 — Employees have corporate accounts

They already have a corporate directory, for example:

```text
Company Active Directory
        ↓
Employees
        ↓
Bilal
Ahmed
Ali
...
```

They want employees to use their **corporate identity** to access AWS.

👉 **IAM Identity Center**

So the two big answers are:

**AWS Organizations + IAM Identity Center** ✅

---

# 1. What is AWS Organizations?

Think:

> 🏢 **AWS Organizations = Manager of multiple AWS accounts**

Instead of managing 20 AWS accounts separately:

```text
Account 1
Account 2
Account 3
Account 4
...
```

Organizations gives you a centralized structure:

```text
                 AWS Organization
                       │
              Management Account
                       │
          ┌────────────┼────────────┐
          ↓            ↓            ↓
        OU-1          OU-2         OU-3
       Security       Dev          Prod
          │            │            │
       Accounts      Accounts     Accounts
```

It helps with things like:

* centralized account management
* consolidated billing
* Organizational Units (OUs)
* Service Control Policies (SCPs)

---

# 2. What is an OU?

You will see **OU** a LOT in SAA questions.

OU = **Organizational Unit**

Simply:

> A folder/group for AWS accounts.

For example:

```text
AWS Organization
│
├── Security OU
│     ├── Security Account
│     └── Logging Account
│
├── Development OU
│     ├── Dev Account 1
│     └── Dev Account 2
│
└── Production OU
      ├── Prod Account 1
      └── Prod Account 2
```

---

# 3. What is an SCP?

SCP = **Service Control Policy**

This is extremely important.

Think:

> 🛑 **SCP = organization-level guardrail**

For example, your company says:

> "Nobody in any AWS account is allowed to use certain services."

You can use an SCP.

```text
AWS Organization
       │
       ↓
      SCP
       │
       ↓
"Don't allow this service"
       │
 ┌─────┼─────┐
 ↓     ↓     ↓
Dev   Test   Prod
```

### VERY IMPORTANT

An SCP **doesn't give permission**.

It sets the **maximum permissions/guardrails** an account can have.

For exam purposes:

> **IAM policy = what a user/role CAN do**

> **SCP = what an account/OU is ALLOWED to do at maximum**

---

# 4. What is IAM Identity Center?

This is the part you asked about.

You know IAM:

> IAM manages identities and permissions **inside AWS**.

IAM Identity Center is more about:

> **Centralized workforce access to multiple AWS accounts and applications.**

Imagine your company has:

```text
Corporate Directory
       │
       ↓
 IAM Identity Center
       │
 ┌─────┼─────┐
 ↓     ↓     ↓
Dev   Test   Prod
AWS   AWS    AWS
```

Employee logs in using their corporate identity.

Then they can be assigned access to:

* Development account
* Production account
* Security account
* etc.

### Simple memory:

> **IAM → manage access to AWS resources**

> **IAM Identity Center → centralized employee access across AWS accounts**

---

# 5. What is an IAM Identity Provider?

This terminology can be confusing.

An **Identity Provider (IdP)** is basically:

> A system that knows who the user is and authenticates them.

For example, your company might have:

```text
Microsoft Entra ID
Microsoft Active Directory
Okta
Google Workspace
```

These can act as an organization's identity source.

Instead of creating:

```text
AWS username
AWS password
```

for every employee, AWS can trust the company's identity system.

Conceptually:

```text
Employee
   ↓
Corporate login
   ↓
Identity Provider
   ↓
IAM Identity Center
   ↓
AWS Account
```

So when you hear:

**Identity Provider / IdP**

think:

> **"The system that verifies who I am."**

---

# 6. What is AWS Directory Service?

This is different from IAM Identity Center.

**AWS Directory Service** helps you run/use directory services such as **Microsoft Active Directory** with AWS workloads.

Think:

```text
Company
   ↓
Active Directory
   ↓
Users / Groups / Computers
```

AWS Directory Service allows AWS applications/resources to work with directory services.

### Don't confuse:

**Directory Service ≠ IAM**

Directory Service is about **directory infrastructure/Active Directory**.

IAM Identity Center is about **centralized workforce access to AWS accounts/apps**.

---

# 7. What is Cognito?

Your understanding is correct.

Think:

> 👤 **Cognito = login system for your applications**

For example, you build:

```text
My Website
     ↓
"Login"
     ↓
Amazon Cognito
     ↓
User authenticated
```

Cognito is commonly used for **application users**, such as:

* customers
* website users
* mobile-app users
* external users

Example:

```text
Netflix-like application
        ↓
Cognito
        ↓
Customer login
```

Whereas IAM Identity Center is generally about:

```text
Company employee
       ↓
IAM Identity Center
       ↓
AWS accounts
```

### Exam shortcut

> **Cognito → customers/application users**

> **IAM Identity Center → employees/workforce/AWS accounts**

---

# 8. What is CloudTrail?

Yes — you already understand this correctly.

**CloudTrail = audit/API activity history**

For example:

```text
Bilal
   ↓
Deleted S3 bucket
   ↓
CloudTrail records the API event
```

You can investigate:

> Who did it?
> What API call happened?
> When did it happen?
> Which resource was affected?

So:

> **CloudTrail = "Who did what in AWS?"**

But CloudTrail does **not** create your multi-account architecture.

That's why it isn't the answer.

---

# 9. Now let's understand each option

### ✅ Option 1

> Integrate IAM Identity Center with corporate directory + configure SCP.

Correct.

Why?

**IAM Identity Center** → centralized employee authentication/access.

**SCP** → organization-level restrictions/guardrails.

---

### ❌ Option 2

> Use CloudTrail for centralized logging.

CloudTrail is useful, but it doesn't solve the main requirement.

The question wants:

> centralized multi-account architecture + corporate authentication.

CloudTrail only answers:

> "What API activity happened?"

So ❌.

---

### ❌ Option 3

> Cognito + IAM Identity Center

Cognito is primarily for application/customer identities.

The question is about **corporate employees/workforce access to AWS accounts**.

So IAM Identity Center is the appropriate service, not Cognito.

❌

---

### ❌ Option 4

> AWS Organizations + AWS Directory Service directly for authentication

AWS Organizations is correct for the **multi-account architecture**, but Directory Service isn't the mechanism the question is looking for to provide centralized AWS-account workforce access.

You use:

**Corporate directory → IAM Identity Center → AWS accounts**

So ❌.

---

### ✅ Option 5

> AWS Organizations for multi-account architecture.

Exactly.

AWS Organizations gives:

```text
One Organization
     ↓
Multiple AWS accounts
     ↓
Centralized management
     ↓
OUs + SCPs + consolidated billing
```

✅

Keep this in your notes:

| Service                 | Think                                             |
| ----------------------- | ------------------------------------------------- |
| **IAM**                 | AWS permissions                                   |
| **IAM Identity Center** | Employees → multiple AWS accounts                 |
| **AWS Organizations**   | Manage multiple AWS accounts                      |
| **SCP**                 | Organization-level permission guardrail           |
| **Cognito**             | Application/customer login                        |
| **Directory Service**   | Active Directory/directory services               |
| **CloudTrail**          | Who did what/API activity                         |
| **Control Tower**       | Automated multi-account landing zone + governance |

And there's a very useful relationship:

```text
             AWS Organization
                    │
          ┌─────────┴─────────┐
          ↓                   ↓
   IAM Identity Center       SCP
          │                   │
          ↓                   ↓
  Employee access       Organization guardrails
          │
          ↓
    AWS Accounts
```

### One-line memory:

> **Organizations manages the accounts. Identity Center manages workforce access. SCP restricts what accounts can do. CloudTrail records what happened. Cognito handles application users.**

If you remember those **five sentences**, this entire question becomes much easier.
