53. Question

Category: CSAA – Design High-Performing Architectures

A company has an on-premises MySQL database that needs to be replicated in Amazon S3 as CSV files. The database will eventually be launched on an Amazon Aurora Serverless cluster and accessed through an Amazon RDS Proxy endpoint to allow the web applications to pool and share database connections. Once data has been fully copied, the ongoing changes to the on-premises database should be continually streamed into the S3 bucket. The company wants a solution that can be implemented with little management overhead yet still highly secure.

Which ingestion pattern should a solutions architect take?

- Use AWS Schema Conversion Tool (AWS SCT) to convert MySQL data to CSV files. Set up the AWS Transform MGN to capture ongoing changes from the on-premises MySQL database and send them to S3.
- `Create a full load and change data capture (CDC) replication task using AWS Database Migration Service (AWS DMS). Add a new Certificate Authority (CA) certificate and create a DMS endpoint with SSL.`
- Set up a full load replication task using AWS Database Migration Service (AWS DMS). Launch a DMS endpoint with SSL using the AWS Network Firewall service.
- Use AWS DataSync to migrate data to S3 and AWS Data Transfer Terminal for ongoing changes. Create your own custom AWS KMS envelope encryption key for the associated DataSync job.

## 1. What Is Being Tested Here? (Core Exam Concepts)

Is single question mein AWS 3 main concepts test kar raha hai:

1. **Initial Load vs Ongoing Changes:**
* Pehle poora database ek baar copy karna (**Full Load**).
* Phir database mein hone wali roz marrah ki updates/deletes/inserts ko live stream karna (**Change Data Capture / CDC**).


2. **Database to S3 Replication Tool:**
* On-premises relational database (MySQL) se live changes read karke S3 mein `.csv` ya `.parquet` format mein dump karne ke liye konsi specific service use hoti hai $\rightarrow$ **AWS DMS (Database Migration Service)**.


3. **In-Transit Security:**
* On-premises se AWS tak database traffic ko **SSL / TLS encryption** ke zariye secure kaise kiya jata hai $\rightarrow$ **DMS Endpoint with CA Certificate**.



---

## 2. Core AWS Technical Rules

* **AWS DMS Capabilities:** DMS na sirf one-time migration karta hai, balke source database ke transaction logs read karke **CDC (Change Data Capture)** ke zariye S3 bucket mein `.csv` files continue stream karta rehta hai.
* **AWS DataSync vs AWS DMS:**
* **AWS DataSync:** File systems (NFS, SMB, S3, EFS) ke beech files transfer karne ke liye hai. Yeh database replication/CDC nahi karta.


* **AWS Application Migration Service (MGN) / SCT:**
* **SCT (Schema Conversion Tool):** Engine conversion ke liye hota hai (e.g., Oracle to PostgreSQL schema conversion).
* **MGN (Application Migration Service):** Entire OS/Server block-level migration ke liye hota hai, DB-to-S3 CSV streaming ke liye nahi.



---

## 3. Correct Option Explanation

#### ✅ **Create a full load and change data capture (CDC) replication task using AWS Database Migration Service (AWS DMS). Add a new Certificate Authority (CA) certificate and create a DMS endpoint with SSL.**

* **Why it works:**
1. **Full Load + CDC:** Initial data copy ke sath-sath live updates (CDC) ko continuously S3 tak stream karega.
2. **Native S3 Target Support:** DMS source DB records ko S3 mein by default `.csv` format mein likhta hai.
3. **SSL/CA Certificate:** Endpoint level par CA certificate add karne se transfer encrypted aur secure ho jata hai bina kisi extra service ki zaroorat ke.



---

## 4. Incorrect Options Elimination Strategy

| Option | Why It Fails the Exam Requirement |
| --- | --- |
| **Full load... using AWS Network Firewall** | 1. Sirf Full Load chunne se ongoing changes (CDC) miss ho jayenge.<br>

<br>2. AWS Network Firewall SSL endpoints manage nahi karta; SSL certificates seedha DMS console par upload hote hain. |
| **Use AWS DataSync... AWS Data Transfer Terminal** | DataSync files/storage copy ke liye hai, database engine replication ke liye nahi. "AWS Data Transfer Terminal" naam ki koi streaming service nahi hoti. |
| **Use AWS SCT... AWS Transform MGN** | SCT schema Assessment/Conversion tool hai. MGN server rehosting ke liye hai. Yeh dono DB-to-S3 CSV CDC streaming supported nahi karte. |

---

## 5. Decision Matrix (Cheat Sheet)

* **Relational DB $\rightarrow$ Live continuous streaming to S3/Database (CDC):** $\rightarrow$ **AWS DMS (Full Load + CDC)**
* **File Server / NAS $\rightarrow$ S3 / EFS File Migration:** $\rightarrow$ **AWS DataSync**
* **Convert heterogeneous DB schemas (e.g., Oracle $\rightarrow$ Aurora PostgreSQL):** $\rightarrow$ **AWS SCT**
* **Rehost (Lift & Shift) entire virtual/physical servers to EC2:** $\rightarrow$ **AWS MGN**

## 🎯 What is being tested?

**On-prem MySQL → S3 CSV + continuous changes (CDC) + secure connection.**

### ✅ Correct

**AWS DMS with Full Load + CDC + SSL**

```text
On-prem MySQL
      ↓
    DMS
  Full Load + CDC
      ↓
   S3 (.csv)
```

* **Full Load** → copies existing data.
* **CDC** → continuously copies new changes.
* **SSL** → encrypts the connection.

### ❌ Other options

* **SCT + MGN** → ❌ SCT is for schema conversion; MGN is for server migration, not DB CDC.
* **DMS Full Load only + Network Firewall** → ❌ No CDC; Network Firewall doesn't create DMS SSL endpoints.
* **DataSync + Transfer Terminal** → ❌ Designed for file transfer/physical bulk transfer, not database CDC.

### 🔥 Shortcut

> **Database → S3 + initial migration + ongoing changes → AWS DMS Full Load + CDC**

> **Secure DMS connection → SSL/CA certificate**
