16. Question

Category: CSAA – Design Cost-Optimized Architectures

A digital media company shares static content to its premium users around the world and also to their partners who syndicate their media files. The company is looking for ways to reduce its server costs and securely deliver their data to their customers globally with low latency.

Which combination of services should be used to provide the MOST suitable and cost-effective architecture? (Select TWO.)

- `Amazon S3`
- AWS Global Accelerator
- AWS Lambda
- AWS Fargate
- `Amazon CloudFront`

<img width="555" height="324" alt="4-v-2 (1)" src="https://github.com/user-attachments/assets/e069d652-cb28-4442-bf2d-e2471f663a6b" />


Yes — Q16 is mainly teaching you **S3 + CloudFront for global static content**. This is a very common SAA pattern.

## 1. What is the question saying?

The company has **static media files** — for example:

```text
images
videos
PDFs
audio
CSS
JavaScript
```

They need:

* 🌍 customers around the world
* ⚡ low latency
* 💰 reduce server costs
* 🔒 secure delivery

So instead of keeping files on EC2 servers, use:

```text
             🌍 Users
                ↓
        Amazon CloudFront
          (CDN / cache)
                ↓
            Amazon S3
        (original files)
```

✅ **Answer: S3 + CloudFront**

---

# 2. What is S3 doing?

S3 is the **storage**.

You put your media files into S3:

```text
S3 Bucket
│
├── video1.mp4
├── video2.mp4
├── image1.jpg
└── music.mp3
```

S3 is:

* highly durable
* scalable
* relatively cheap
* designed for object storage

So think:

> **S3 = where my files live.**

---

# 3. What is CloudFront doing?

CloudFront is a **CDN — Content Delivery Network**.

Imagine your S3 bucket is in one AWS Region.

A customer in Pakistan requests:

```text
video.mp4
```

Instead of making that customer repeatedly travel all the way to the S3 origin, CloudFront can cache the file at an edge location closer to the customer.

```text
                 S3
              Origin
                 ↑
                 │
        CloudFront CDN
       /       |       \
      ↓        ↓        ↓
 Pakistan   Europe    USA
   Edge      Edge     Edge
```

If the file is already cached at the nearby edge:

```text
User → CloudFront Edge → cached video
```

Much faster.

---

# 4. Why does this reduce server costs?

Imagine you use EC2:

```text
Users
  ↓
EC2
  ↓
Static files
```

Your EC2 servers have to handle lots of requests for those files.

Instead:

```text
Users
  ↓
CloudFront
  ↓
S3
```

CloudFront handles delivery and caching.

So you don't need a fleet of EC2 servers just to serve static content.

### Remember:

> **S3 stores the content. CloudFront delivers the content globally.**

---

# 5. What is AWS Global Accelerator?

This is where the question tries to confuse you.

Both CloudFront and Global Accelerator use the AWS global network, but they solve different problems.

### CloudFront

Primarily:

> **CDN / caching / content delivery**

Great for:

```text
images
videos
CSS
JS
static files
web content
```

### Global Accelerator

Primarily:

> **Accelerate network traffic to applications**

For example:

```text
User
 ↓
Global Accelerator
 ↓
ALB / EC2 / application
```

It's useful for things like:

* TCP/UDP applications
* gaming
* IoT
* VoIP
* applications needing static IPs
* fast regional failover

So for **static media files**, think:

**CloudFront ✅**

not Global Accelerator.

---

# 6. What about Lambda?

Lambda = **run code**.

```text
Request
   ↓
Lambda
   ↓
execute code
```

It isn't your storage service and isn't a CDN.

So:

**Lambda ❌**

---

# 7. What about Fargate?

Fargate = **run containers without managing servers**.

```text
Container
   ↓
Fargate
```

Again, it isn't designed to be your static-file storage/CDN.

**Fargate ❌**

---

# 🧠 The important SAA pattern

Whenever you see:

> **Static content + global users + low latency + cost optimization**

Your brain should immediately say:

### **S3 + CloudFront**

```text
          GLOBAL USERS
          ↓    ↓    ↓
       CloudFront
      CDN / Caching
           ↓
          S3
    Durable Storage
```

### And remember this distinction:

| Service                | Think                                     |
| ---------------------- | ----------------------------------------- |
| **S3**                 | 📦 Store objects/files                    |
| **CloudFront**         | 🌍 Deliver/cache content globally         |
| **Global Accelerator** | 🚀 Accelerate application network traffic |
| **Lambda**             | ⚙️ Run code                               |
| **Fargate**            | 🐳 Run containers                         |

So **Q16's entire lesson is basically:**

> **Don't use compute servers to serve static content globally. Put the static content in S3 and put CloudFront in front of it.**
