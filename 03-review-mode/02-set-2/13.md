
13. Question

Category: CSAA – Design Secure Architectures

An organization needs to control access to several Amazon S3 buckets. The organization plans to use a gateway endpoint to allow access to trusted buckets. The organization shall not use overly broad policies like AmazonS3FullAccess.

Which of the following could help achieve this requirement?

- Generate an endpoint policy for trusted VPCs.
- Generate a bucket policy for trusted VPCs.
- Generate a bucket policy for trusted S3 buckets.
- `Generate an endpoint policy for trusted S3 buckets.`

<img width="2930" height="1344" alt="s3-gateway-endpoint-policy-sample" src="https://github.com/user-attachments/assets/069c16af-455c-4e5d-8e5c-4cbf217f4632" />

Yes. This question is testing **VPC Gateway Endpoint + Endpoint Policy + S3 Bucket Policy**. Let's make it very simple.

### 1. First, what is a Gateway Endpoint?

Suppose you have:

**EC2 in private subnet → S3**

Normally, a private EC2 needs something like NAT/Internet connectivity to reach S3.

With an **S3 Gateway Endpoint**:

```text
Private EC2
    |
    | VPC route
    ↓
S3 Gateway Endpoint
    |
    ↓
Amazon S3
```

So your private EC2 can access S3 **without going through the Internet Gateway or NAT Gateway**.

---

### 2. What is the question asking?

The company has **several S3 buckets**.

They want:

> "Our EC2 instances can access only the S3 buckets that we trust."

For example:

```text
Trusted:
my-company-data
my-company-backups
my-company-logs

NOT trusted:
random-bucket-1
random-bucket-2
```

They also don't want to give something overly broad like:

```text
AmazonS3FullAccess
```

So they want to **restrict which S3 buckets can be accessed through the endpoint**.

That's where the **Endpoint Policy** comes in.

---

### 3. Endpoint Policy = "Which S3 resources can this endpoint access?"

Think of it like a gatekeeper:

```text
EC2
 ↓
S3 Gateway Endpoint
 ↓
Endpoint Policy
 ↓
 ├── ✅ company-data
 ├── ✅ company-backups
 └── ❌ other-bucket
```

You can create **one endpoint policy** that says:

> Allow access only to these trusted S3 buckets.

Therefore:

✅ **Generate an endpoint policy for trusted S3 buckets.**

That's the answer.

---

### 4. Endpoint Policy vs Bucket Policy

This is the important exam distinction.

**Endpoint policy:**

> "From this VPC endpoint, which S3 resources are allowed?"

**Bucket policy:**

> "Who is allowed to access this particular bucket?"

Think:

```text
             S3 Gateway Endpoint
                    |
             Endpoint Policy
             "Which buckets?"
                    |
          ┌─────────┴─────────┐
          ↓                   ↓
     Bucket A              Bucket B
          |                   |
     Bucket Policy       Bucket Policy
     "Who can access?"   "Who can access?"
```

Both policies can participate in controlling access.

But the question specifically wants an efficient way to control **several trusted S3 buckets**.

Instead of creating/modifying a policy on every bucket:

```text
Bucket A → policy
Bucket B → policy
Bucket C → policy
Bucket D → policy
...
```

you can use **one endpoint policy** at the Gateway Endpoint.

---

### 5. Why "trusted VPCs" is wrong

Look carefully at the wording:

> trusted **S3 buckets**

The requirement isn't:

> "Which VPCs can access?"

It's:

> "Which S3 buckets can be accessed?"

Therefore:

❌ Endpoint policy for trusted VPCs

❌ Bucket policy for trusted VPCs

The answer needs to control the **S3 resources**.

---

### One exam memory trick 🧠

Remember:

**Endpoint Policy → controls what can be accessed THROUGH the endpoint.**

**Bucket Policy → controls access TO a particular bucket.**

And:

> **Gateway Endpoint = private access to S3/DynamoDB from a VPC.**

So for this question:

**Private EC2 → S3 Gateway Endpoint → Endpoint Policy → only trusted S3 buckets.**
