62. Question

Category: CSAA – Design Secure Architectures

A company has several web applications with users all around the world. Each application is hosted in an Auto Scaling group of EC2 instances in multiple AZs behind an Application Load Balancer (ALB). All applications have their own fully qualified domain name. For added security, the applications must use a publicly trusted SSL certificate.

Which solution will meet this requirement with the LEAST operational overhead?

- Use OpenSSL to generate a self-signed certificate. Import the SSL/TLS certificate to the AWS Certificate Manager (ACM) and associate it with the HTTPS listener of the ALBs
- Launch a self-hosted certificate authority (CA) using the Let’s Encrypt tool in an Amazon EC2 instance. Utilize the built-in ISRG Root X1 trusted root CA certificate. Generate a new SSL/TLS certificate using the certbot CLI utility. Associate the new certificate on the HTTPS listener of the ALBs.
- Issue an SSL/TLS certificate using the AWS Certificate Manager Private Certificate Authority. Associate the new certificate on the HTTPS listener of the ALBs.
- `Use the AWS Certificate Manager (ACM) to generate a public SSL/TLS certificate. Associate the new SSL/TLS certificate on the HTTPS listener of the ALBs.`

Is question mein **Publicly Trusted SSL/TLS Certificates**, **AWS Certificate Manager (ACM)**, aur **Least Operational Overhead** ka concept test ho raha hai.

Aayein requirements aur options ko step-by-step analyze karte hain:

---

### 1. Requirement Breakdown

1. **Architecture:** Web apps worldwide users ke liye ALBs aur Auto Scaling EC2 instances par hosted hain with unique domain names.
2. **Security Standard:** Publicly trusted SSL/TLS certificates require hain.
3. **Constraint:** **LEAST operational overhead** (kam se kam manual work, automatic renewal, minimum maintenance) hona chahiye.

---

### 2. Technical Evaluation

```
[ Domain Names ] ──► [ AWS Certificate Manager (ACM) ] ──► [ Public SSL/TLS Cert ]
                                                                   │
                                                           (Automatic Renewal)
                                                                   │
                                                                   ▼
                                                         [ HTTPS Listener on ALB ]

```

1. **AWS Certificate Manager (ACM) Public Certificates:**
* ACM directly **free, publicly trusted SSL/TLS certificates** issue karta hai.
* ACM ke public certificates automatically AWS ALB, CloudFront, aur API Gateway ke sath integrate ho jaate hain.
* **Zero Operational Overhead:** ACM ACM-issued public certificates ko **automatically renew** kar deta hai expire hone se pehle (bina kisi manual work ya certbot scripts ke).


2. **Public vs Private CA:**
* **Private CA** internal corporate networks / VPNs ke liye hota hai aur public browser extensions usko trust nahi karte jab tak client devices par root cert push na kiya jaye.


3. **Self-Signed / Self-Hosted Certs (OpenSSL / Certbot):**
* Self-signed certs public browsers warning (`Not Secure`) dete hain.
* Self-hosted Let's Encrypt / Certbot instances manage karna server maintenance, cron jobs, aur manual script handling ka operational overhead barha deta hai.



---

### 3. Correct Option Explanation

#### ✅ **Use the AWS Certificate Manager (ACM) to generate a public SSL/TLS certificate. Associate the new SSL/TLS certificate on the HTTPS listener of the ALBs.**

* **Why it works:** ACM automatically public certificates issue karta hai jo worldwide browsers dwara trusted hote hain. Unko ALBs par bind karna effortless hai aur rotation automatically managed hoti hai (least operational overhead).

---

### 4. Incorrect Options Breakdown (Elimination Strategy)

| Option | Why It Fails |
| --- | --- |
| **OpenSSL self-signed certificate...** | Self-signed certificates public users/browsers ke liye trusted nahi hote (SSL warnings aate hain). |
| **Self-hosted Let's Encrypt / certbot...** | EC2 instance par certbot script run karna aur renew manage karna high operational overhead create karta hai. |
| **ACM Private Certificate Authority...** | ACM Private CA internal resources ke liye hota hai aur is ke liye private trust store setup required hota hai; plus public users ke liye default trusted nahi hota. |

---

### 5. Cheat Sheet for ACM Certificates (SAA-C03)

* **Public Web Applications + Zero Overhead:** $\rightarrow$ **ACM Public Certificate** (Free + Auto-Renewal).
* **Internal Microservices / VPN Access:** $\rightarrow$ **ACM Private CA**.
* **Imported Third-Party Certs in ACM:** $\rightarrow$ **No Auto-Renewal** (Manual re-import required before expiry).
