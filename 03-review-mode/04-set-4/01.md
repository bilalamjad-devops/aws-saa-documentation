1. Question

Category: CSAA – Design High-Performing Architectures

A company hosts all its applications on its data center on the US East Coast. Most of the workloads are legacy applications that are hosted on individual virtual machines running in Linux and Windows operating systems. The company plans to migrate all of its VM workloads to the AWS cloud. To minimize changes in the applications during the migration process, it has been decided that the company will use a “lift-and-shift” strategy. The company also wants to minimize downtime during the migration process.

Which of the following options should the Solutions Architect implement for this scenario?

- `Install the AWS Replication Agent on each of the on-premises VMs to continuously replicate the servers to AWS. Use AWS Migration Service (AWS MGN) to launch test instances and perform cutover once testing is completed.`
- Utilize AWS DataSync to migrate the application workloads to AWS. Deploy the AWS DataSync VM on the on-premises data center. Once replication is completed, launch Amazon EC2 instances based on the created AMIs.
- Export the on-premises VMs and upload the images to an Amazon S3 bucket. Use VM Import/Export service to import the images and launch them as Amazon EC2 instances.
- Use the AWS Application Discovery Service for lift-and-shift migrations. Deploy the AWS Application Discovery Agent to the on-premises data center to start the replication process. After the replication task is completed, launch Amazon EC2 instances based on the created AMIs.

Is question mein **AWS Migration Services (Lift-and-Shift Strategy & Minimal Downtime)** ka core concept test ho raha hai.

Aayein requirements aur options ko Roman Urdu mein simple steps mein analyze karte hain:

---

## 1. Requirement Breakdown

1. **Strategy:** "Lift-and-shift" (Rehosting) strategy apply karni hai taake legacy applications/VMs mein koi modification na karni paray.
2. **Key Constraint:** Migration ke dauran **minimal downtime** (kam se kam downtime) hona chahiye.
3. **Core Task:** On-premises VMs (Linux aur Windows) ko continuously replicate karke EC2 par cutover karne ka sab se suitable tool kaun sa hai.

---

## 2. Technical Evaluation of Migration Tools

1. **AWS Application Migration Service (AWS MGN):**
* Yeh AWS ki **primary recommended service** hai rehosting / lift-and-shift migrations ke liye.
* Yeh source servers par **AWS Application Migration Agent (Replication Agent)** install karti hai jo block-level replication (continuous data replication) shuru kar deta hai.
* Is continuous replication ki waja se final cutover ke waqt downtime nazdeeq-tareen zero (minimal) hota hai.



---

## 3. Correct Option Explanation

#### ✅ **Install the AWS Replication Agent on each of the on-premises VMs to continuously replicate the servers to AWS. Use AWS Migration Service (AWS MGN) to launch test instances and perform cutover once testing is completed.**

* **Why it works:** AWS MGN continuous block-level replication provide karta hai, jo testing ke baad fast cutover enable karta hai, jisse downtime minimized rehta hai.

---

## 4. Incorrect Options Breakdown (Elimination Strategy)

| Option | Why It Fails the Exam Requirement |
| --- | --- |
| **Utilize AWS DataSync...** | AWS DataSync **file/object storage data migrate** karne ke liye hota hai (EFS, S3, SMB/NFS), virtual machine server migration/replication ke liye nahi. |
| **Export VMs and upload to S3... VM Import/Export...** | Yeh manual aur offline import method hai. Is se continuous replication nahi hoti aur **downtime bohot zayada** hota hai. |
| **Use AWS Application Discovery Service... start replication...** | Application Discovery Service sirf servers aur dependencies ko **discover/inventory perform** karne ke liye hoti hai; yeh server replication ya migration nahi karti. |

---

## 5. Exam Decision Matrix (AWS Migration Services Cheat Sheet)

* **Primary Lift-and-Shift / Rehost Server Migration Tool:** $\rightarrow$ **AWS Application Migration Service (AWS MGN)**
* **Database Schema & Data Migration:** $\rightarrow$ **AWS Database Migration Service (AWS DMS)**
* **On-Prem Server Discovery & Inventory Mapping:** $\rightarrow$ **AWS Application Discovery Service**
* **Large-scale File/Data Storage Transfers:** $\rightarrow$ **AWS DataSync**

18-September-2026

### 🎯 What is being tested?

**Lift-and-shift migration + minimum downtime.**

### ✅ Correct answer

**Install the AWS Replication Agent on each on-premises VM → use AWS Application Migration Service (AWS MGN) → test instances → cutover.**

### 🔑 Key concept

**AWS MGN** continuously **replicates on-premises servers to AWS**.

Flow:

**On-prem VM → Replication Agent → Continuous replication → AWS EC2 test → Cutover**

This gives:

* Minimal application changes ✅
* Continuous replication ✅
* Very low downtime during final cutover ✅
* Supports Linux and Windows servers ✅

### ❌ Others

* **DataSync** → mainly file/data transfer, not whole VM migration.
* **VM Import/Export** → works, but requires image export/upload and more downtime/manual work.
* **Application Discovery Service** → **discovers and assesses** workloads; it does not perform the actual server replication/migration.

### 🔥 Exam shortcut

**On-prem VM → AWS + lift-and-shift + minimal downtime → AWS MGN.**
