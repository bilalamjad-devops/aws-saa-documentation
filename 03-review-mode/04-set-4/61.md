61. Question

Category: CSAA – Design Resilient Architectures

A financial firm is designing an application architecture for its online trading platform that must have high availability and fault tolerance. Their Solutions Architect configured the application to use an Amazon S3 bucket located in the us-east-1 region to store large amounts of intraday financial data. The stored financial data in the bucket must not be affected even if there is an outage in one of the Availability Zones or if there’s a regional service failure.

What should the Architect do to avoid any costly service disruptions and ensure data durability?

- Copy the S3 bucket to an EBS-backed EC2 instance.
- `Enable Cross-Region Replication.`
- Create a Lifecycle Policy to regularly backup the S3 bucket to Amazon Glacier.
- Create a new S3 bucket in another region and configure Cross-Account Access to the bucket located in us-east-1.


Is question mein **Amazon S3 High Availability**, **Regional Outage Protection**, aur **Cross-Region Replication (CRR)** ka concept test ho raha hai.

Aayein requirements aur options ko step-by-step analyze karte hain:

---

### 1. Requirement Breakdown

1. **Current Setup:** Online trading platform jiska data `us-east-1` region ke ek Amazon S3 bucket mein stored hai.
2. **Availability Standard:** System ko **Availability Zone (AZ) failure** aur **Regional Service Outage** dono se protect hona chahiye.
3. **Core Goal:** Agar poora ek AWS Region (`us-east-1`) bhi outage ka shikar ho jaye, toh financial data affect na ho aur **Data Durability & High Availability** maintain rahe.

---

### 2. Technical Evaluation

```
[ S3 Bucket (Primary Region: us-east-1) ]
                  │
                  │ (Asynchronous Cross-Region Replication)
                  ▼
[ S3 Bucket (Secondary Region: e.g., us-west-2) ]

```

1. **Standard S3 Built-in Protection (Single Region):**
* Default S3 Standard storage class data ko automatically akele region ke andar kam se kam **3 different Availability Zones (AZs)** par replicate karti hai. Is wajah se 1 AZ failure se S3 data safe rehta hai.


2. **Protecting Against Regional Outage:**
* Jab pure **Region** (jaise `us-east-1`) mein disaster ya service outage aa jaye, toh single-region data accessible nahi rehta.
* Region-level failure se bachne ke liye data ko doosre geographical AWS region (e.g., `us-west-2`) mein copy/replicate karna zaroori hai.


3. **Cross-Region Replication (CRR):**
* **Amazon S3 CRR** ek automatic, asynchronous feature hai jo primary bucket mein aane wale har object ko doosre target region ke S3 bucket mein automatically copy/sync kar deta hai.



---

### 3. Correct Option Explanation

#### ✅ **Enable Cross-Region Replication.**

* **Why it works:** CRR enable karne se objects automatic doosre AWS region ke target bucket mein replicate ho jaate hain. Agar primary region offline bhi ho jaye, toh secondary region se data 100% durable aur available rehta hai.

---

### 4. Incorrect Options Breakdown (Elimination Strategy)

| Option | Why It Fails |
| --- | --- |
| **Copy S3 bucket to EBS-backed EC2...** | EBS volumes Single-AZ scope hote hain. EC2 par manually copy karna complex operational overhead hai aur multi-region redundancy provide nahi karta. |
| **Lifecycle Policy to Amazon Glacier...** | Lifecycle policies same region ke andar storage class change karti hain. Agar same region down ho jaye, toh Glacier data bhi accessible nahi rahega. |
| **Cross-Account Access...** | Cross-Account access doosre AWS account ko access permissions deta hai, yeh multi-region data replication/backup feature nahi hai. |

---

### 5. Cheat Sheet for S3 Replication & Redundancy (SAA-C03)

* **Single-Region Protection (Multi-AZ):** Standard S3 default behavior (3+ AZs in 1 Region).
* **Multi-Region Disaster Recovery / Regional Failure Protection:** $\rightarrow$ **S3 Cross-Region Replication (CRR)**.
* **Prerequisites for S3 Replication (CRR/SRR):** **S3 Versioning MUST be enabled** on both source and destination buckets.
