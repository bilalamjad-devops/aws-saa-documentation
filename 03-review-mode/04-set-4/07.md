7. Question

Category: CSAA – Design High-Performing Architectures

A company plans to migrate a NoSQL database to an EC2 instance. The database is configured to replicate the data automatically to keep multiple copies of data for redundancy. The Solutions Architect needs to launch an instance that has a high IOPS and sequential read/write access.

Which of the following options fulfills the requirement if I/O throughput is the highest priority?

- Use Compute optimized instance with instance store volume.
- Use Memory optimized instances with EBS volume.
- Use General purpose instances with EBS volume.
- `Use Storage optimized instances with instance store volume.`

Bilkul sahi pakda aap ne! Conceptual framing bilkul wahi hai, bas ek choti si technical correction:

Scenario mein **MySQL** (Relational Database) ki bajaye **NoSQL Database** (jaise MongoDB, Cassandra, ya Couchbase) ka zikr hai.

Relational Databases (jaise MySQL, PostgreSQL) ke liye **AWS RDS** standard best choice hota hai. Lekin jab company **NoSQL Database** ko custom EC2 par chalana chahti hai aur application layer par data replication khud handle karti hai, tab sawal yeh hota hai ke konsa EC2 type select kiya jaye:

---

### EC2 Selection Logic

1. **Storage-Optimized EC2 (`I3` / `I4i` Series):** Specialized hardware jo heavy database operations, millions of IOPS, aur fast read/write ke liye design kiya gaya hai.
2. **Instance Store Volumes (Local NVMe SSDs):** Direct physical motherboard par lagi hui SSDs jo EBS network drives se kahin zayada fast I/O throughput aur zero network latency deti hain.

Kyun ke application data replication khud handle karti hai, is liye local drives ka temporary hona problem nahi banta — aur speed sab se highest mil jati hai!

18-September-2026


### 🎯 What is being tested?

**EC2 instance type + storage performance.**

### ✅ Correct answer

**Use Storage Optimized instances with Instance Store volume.**

### 🔑 Key concept

**Storage Optimized (I family)** → designed for:

* Very high **IOPS**
* High disk throughput
* Sequential/random read/write
* Databases and I/O-intensive workloads

**Instance Store** → physically attached to the host → very high performance.

The database already **replicates data**, so losing instance-store data isn't as concerning because replicas provide redundancy.

### ❌ Others

* **Compute optimized** → CPU-intensive workloads.
* **Memory optimized** → memory-intensive workloads.
* **General purpose + EBS** → balanced, but not highest I/O throughput.

### 🔥 Exam shortcut

**Highest IOPS / disk throughput → Storage Optimized + Instance Store.**
