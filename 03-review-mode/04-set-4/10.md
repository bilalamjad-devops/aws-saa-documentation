10. Question

Category: CSAA – Design High-Performing Architectures

A popular augmented reality (AR) mobile game is heavily using a RESTful API which is hosted in AWS. The API uses Amazon API Gateway and a DynamoDB table with a preconfigured read and write capacity. Based on your systems monitoring, the DynamoDB table begins to throttle requests during high peak loads which causes the slow performance of the game.

Which of the following can you do to improve the performance of your app?

- Integrate an Application Load Balancer with your DynamoDB table.
- Create an SQS queue in front of the DynamoDB table.
- `Use DynamoDB Auto Scaling`
- Add the DynamoDB table to an Auto Scaling Group.

Is question mein **Amazon DynamoDB Throttling** aur **Capacity Management (DynamoDB Auto Scaling)** ka core concept test ho raha hai.

Aayein scenario ko Roman Urdu mein simple steps mein analyze karte hain:

---

### 1. Requirement Breakdown

1. **Problem:** Peak loads ke waqt DynamoDB table **requests throttle (`ProvisionedThroughputExceededException`)** kar raha hai. Is se application/game ki performance slow ho rahi hai.
2. **Current Setup:** DynamoDB table mein **preconfigured (fixed) read/write capacity** set hai.
3. **Goal:** Database capacity ko demand ke hisaab se dynamically scale karna taake performance improve ho aur throttling khatam ho.

---

### 2. Technical Evaluation

1. **DynamoDB Auto Scaling:**
* DynamoDB ki built-in Auto Scaling feature target utilization percentage (e.g., 70% read/write utilization) ke mutabiq **Read Capacity Units (RCUs)** aur **Write Capacity Units (WCUs)** ko automatically adjust / increase kar deti hai.
* Jab traffic surge / peak load aata hai, toh capacity auto-scale ho kar requests throttling ko prevent karti hai.



---

### 3. Correct Option Explanation

#### ✅ **Use DynamoDB Auto Scaling**

* **Why it works:** Dedicated DynamoDB Auto Scaling feature provisioned read/write capacity ko traffic variation ke mutabiq dynamically increase karke throttling resolution provide karti hai.

---

### 4. Incorrect Options Breakdown (Elimination Strategy)

| Option | Why It Fails the Exam Requirement |
| --- | --- |
| **Integrate an ALB with DynamoDB table...** | Application Load Balancer (ALB) EC2, IP addresses, ya Lambda target groups ke aage lagta hai; ALB direct DynamoDB ke aage attach nahi hota. |
| **Create an SQS queue in front of DynamoDB...** | SQS write operations ko buffer/queue kar sakta hai, lekin yeh direct RESTful API read/write performance increase nahi karega aur synchronous game responses ko support nahi karega. |
| **Add DynamoDB table to an Auto Scaling Group...** | EC2 Auto Scaling Groups (ASG) EC2 instances ko scale karne ke liye hote hain, DynamoDB tables ko ASG mein add nahi kiya ja sakta. |

---

### 5. Exam Decision Matrix (DynamoDB Capacity Management Cheat Sheet)

* **Handling Traffic Spikes with Provisioned Mode:** $\rightarrow$ **DynamoDB Auto Scaling**
* **Unpredictable / Short Spikes Workloads (Zero Capacity Planning):** $\rightarrow$ **DynamoDB On-Demand Mode**
* **Ultra-Low Latency In-Memory Caching for Reads:** $\rightarrow$ **DynamoDB Accelerator (DAX)**
