50. Question

Category: CSAA – Design Secure Architectures

A company is using the AWS Directory Service to integrate its on-premises Microsoft Active Directory (AD) domain with its Amazon EC2 instances via an AD connector. The IAM identities, which are members of an AD group, have the following identity‑based policy attached to allow Directory Service access:

 ```saa
{ 
   "Version":"2012-10-17", 
   "Statement":[ 
      {
         "Sid":"DirectoryTutorialsDojo1234", 
         "Effect":"Allow", 
         "Action":[
            "ds:*"
         ], 
         "Resource":"arn:aws:ds:us-east-1:987654321012:directory/d-1234567890"
      }, 
    {
}
```


Which of the following BEST describes what the above resource policy does?


- Allows all Directory Service (ds) calls as long as the resource contains the directory name of: DirectoryTutorialsDojo1234
- `Allows all Directory Service (ds) calls as long as the resource contains the directory ID: d-1234567890`
- Allows all Directory Service (ds) calls as long as the resource contains the directory ID: DirectoryTutorialsDojo1234
- Allows all Directory Service (ds) calls as long as the resource contains the directory ID: 987654321012

Is question mein **IAM Policy Syntax Analysis**, **Resource ARNs**, aur **AWS Directory Service (`ds:*`) Actions** ka policy evaluation concept test ho raha hai.

Aayein policy JSON ko break down karke analyze karte hain:

---

### 1. IAM Policy JSON Breakdown

```json
{ 
   "Version":"2012-10-17", 
   "Statement":[ 
      {
         "Sid":"DirectoryTutorialsDojo1234", 
         "Effect":"Allow", 
         "Action":[
            "ds:*"
         ], 
         "Resource":"arn:aws:ds:us-east-1:987654321012:directory/d-1234567890"
      }
   ]
}

```

* **`Sid` (Statement ID):** `"DirectoryTutorialsDojo1234"` — Yeh sirf ek user-defined descriptive label/identifier hai statement ko identify karne ke liye. Yeh permission evaluation mein koi role play nahi karta.
* **`Effect`:** `"Allow"` — Mentioned actions ko permission allow karta hai.
* **`Action`:** `["ds:*"]` — All Directory Service (`ds`) API calls / permissions allow karta hai.
* **`Resource`:** `"arn:aws:ds:us-east-1:987654321012:directory/d-1234567890"` — Specifiically target karta hai us Directory resource ko jiska **Directory ID** **`d-1234567890`** hai (AWS Account ID: `987654321012` ke andar in `us-east-1`).

---

### 2. Correct Option Explanation

#### ✅ **Allows all Directory Service (ds) calls as long as the resource contains the directory ID: d-1234567890**

* **Why it works:** Policy ka `Action` field sabhi `ds:*` calls allow karta hai, lekin strict constraint `Resource` field se aati hai jo exact Directory ID **`d-1234567890`** tak scope ko restrict karti hai.

---

### 3. Incorrect Options Breakdown (Elimination Strategy)

| Option | Why It Fails |
| --- | --- |
| **...directory name of: DirectoryTutorialsDojo1234** | `DirectoryTutorialsDojo1234` directory name nahi balkay Statement ID (`Sid`) hai. |
| **...directory ID: DirectoryTutorialsDojo1234** | Statement ID ko Directory ID samajhna syntax confusion ki wajah se hai. Directory ID syntax `d-XXXXXXXXXX` hota hai. |
| **...directory ID: 987654321012** | `987654321012` AWS Account ID hai, Directory ID nahi. |

---

### 4. Cheat Sheet for IAM Policy Structure (SAA-C03)

```
arn:aws:service:region:account-id:resource-type/resource-id
 └─┬─┘ └─┬─┘   └─┬─┘    └────┬───┘  └──────┬────┘ └─────┬──────┘
  aws   ds   us-east-1  987654321012   directory  d-1234567890

```

* **`Sid`:** Optional statement label (does not grant permissions).
* **`Action`:** Defines WHAT API operations are permitted (`ds:*`).
* **`Resource`:** Defines WHICH specific resource ID receives the permission (`d-1234567890`).
