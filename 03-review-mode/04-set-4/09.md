9. Question

Category: CSAA – Design High-Performing Architectures

A company has a team of developers that provisions its own resources on the AWS cloud. The developers use IAM user access keys to automate resource provisioning and application testing processes in AWS. To ensure proper security compliance, the security team wants to automate the process of deactivating and deleting any IAM user access key that is over 90 days old.

Which solution will meet these requirements with the LEAST operational effort?

- `Use the AWS Config managed rule to check if the IAM user access keys are not rotated within 90 days. Create an Amazon EventBridge rule for the non-compliant keys, and define a target to invoke a custom AWS Lambda function to deactivate and delete the keys.`
- Create an Amazon EventBridge rule to filter IAM user access keys older than 90 days. Schedule an AWS Batch job that runs every 24 hours to delete all the specified access keys.
- Create an Amazon EventBridge rule to filter IAM user access keys older than 90 days. Define a target to invoke an AWS Lambda function to deactivate and delete the old access keys.
- Create a custom AWS Config rule to check the max-age of IAM access keys. Use Amazon EventBridge Scheduler to invoke an AWS Batch job every 24 hours to delete all non-compliant access keys.

Is question mein **AWS Compliance Monitoring (AWS Config)**, **Event-Driven Automation (EventBridge)**, aur **Remediation (AWS Lambda)** ka integration test ho raha hai.

Aayein requirements ko Roman Urdu mein simple steps mein analyze karte hain:

---

## 1. Requirement Breakdown

1. **Goal:** IAM user access keys ko monitor karna aur jo keys **90 days se ziada purani** hon, unhe automatically **deactivate aur delete** karna.
2. **Key Constraint:** Solution **LEAST operational effort** wala hona chahiye (AWS Managed Rules ko preference milay gi custom code/rules ke muqable mein).

---

## 2. Technical Evaluation

```
[ IAM Access Key (>90 days old) ]
               │
               ▼
   [ AWS Config Managed Rule ] ──► Detects Non-Compliant Key
               │
               ▼
  [ Amazon EventBridge Rule ] ──► Triggers Event
               │
               ▼
    [ AWS Lambda Function ]   ──► Deactivates & Deletes Key

```

1. **AWS Config Managed Rule (`iam-user-access-key-old-check`):**
* AWS Config ke paas tayyar (built-in) managed rule hota hai jo yeh check karta hai ke access keys 90 days ke andar rotate hui hain ya nahi.
* Built-in managed rule use karne se custom compliance logic likhne ka operational effort bach jata hai.


2. **EventBridge + Lambda Automation:**
* Jab AWS Config kisi key ko **Non-Compliant** mark karta hai, toh EventBridge rule trigger hota hai.
* EventBridge target ke taur par **AWS Lambda** function ko call karta hai jo AWS SDK ke zariye key ko deactivate aur delete kar deta hai.



---

## 3. Correct Option Explanation

#### ✅ **Use the AWS Config managed rule to check if the IAM user access keys are not rotated within 90 days. Create an Amazon EventBridge rule for the non-compliant keys, and define a target to invoke a custom AWS Lambda function to deactivate and delete the keys.**

* **Why it works:** AWS Config Managed Rule Compliance evaluation handle kar leta hai (least operational effort), jabke EventBridge aur Lambda event-driven remediation achieve karte hain.

---

## 4. Incorrect Options Breakdown (Elimination Strategy)

| Option | Why It Fails the Exam Requirement |
| --- | --- |
| **EventBridge rule to filter keys older than 90 days... AWS Batch...** | EventBridge khud IAM access key age inspect/filter nahi kar sakta; event-filtering ke liye AWS Config ki zarurat hoti hai. AWS Batch yahan overhead hai. |
| **EventBridge rule to filter keys... Lambda...** | EventBridge direct IAM key age evaluate nahi karta — is ke liye state/compliance evaluation engine (AWS Config) chahiye. |
| **Custom AWS Config rule... AWS Batch...** | Custom rule likhna aur AWS Batch manage karna unnecessary operational effort create karta hai jab built-in managed rule aur serverless Lambda mojood hain. |

---

## 5. Exam Decision Matrix (IAM & Security Automation Cheat Sheet)

* **Detect Non-Compliant / Old IAM Keys (Managed):** $\rightarrow$ **AWS Config Managed Rule**
* **Event-Driven Security Remediation Trigger:** $\rightarrow$ **Amazon EventBridge**
* **Serverless Remediation Action Executer:** $\rightarrow$ **AWS Lambda**

18-September-2026

### 🎯 What is being tested?

**Automatically detect and remove old IAM access keys with minimum operational effort.**

### ✅ Correct answer

**Use AWS Config managed rule → EventBridge → Lambda to deactivate and delete keys.**

### 🔑 Key concept

**AWS Config** already has a managed rule for checking whether IAM access keys are rotated within a specified number of days.

Flow:

**AWS Config → detects non-compliant key → EventBridge → Lambda → deactivate/delete key**

Why this is best:

* Managed Config rule → no custom detection logic.
* Lambda → simple serverless remediation.
* No servers/Batch jobs to manage.

### ❌ Others

* **EventBridge directly filtering keys by age** → EventBridge isn't designed to inspect IAM key age this way.
* **AWS Batch** → unnecessary operational overhead.
* **Custom Config rule** → more work when a managed rule exists.

### 🔥 Exam shortcut

**Compliance check + existing AWS managed rule → AWS Config managed rule → EventBridge → Lambda remediation.**
