3. Question

Category: CSAA – Design Secure Architectures

A Solutions Architect is working for a large global media company with multiple office locations all around the world. The Architect is instructed to build a system to distribute training videos to all employees.

Using Amazon CloudFront, what method would be used to serve content that is stored in Amazon S3 but not publicly accessible from S3 directly?

- Create an S3 bucket policy that lists the CloudFront distribution ID as the principal and the target bucket as the Amazon Resource Name (ARN).
- Create a web ACL in AWS WAF to block any public S3 access and attach it to the CloudFront distribution.
- `Create an Origin Access Control (OAC) for CloudFront and grant access to the objects in your S3 bucket to that OAC.`
- Create an Identity and Access Management (IAM) user for CloudFront and grant access to the objects in your S3 bucket to that IAM user.

Is question mein **CloudFront aur Amazon S3 ke darmayan Private Content Distribution** aur **Direct S3 Access Block** karne ka exact mechanism test ho raha hai.

Aayein requirements ko Roman Urdu mein simple steps mein analyze karte hain:

---

## 1. Requirement Breakdown

1. **Goal:** Global employees ko S3 bucket se training videos distribute karna using **Amazon CloudFront**.
2. **Security Constraint:** S3 bucket public nahi honi chahiye (Direct S3 URL se access allow na ho).
3. **Core Question:** CloudFront ko private S3 bucket se files parhne ki permission dene ke liye kaun sa **AWS Security Mechanism** use hoga?

---

## 2. Technical Evaluation

```
[ Employees / Users ] ──► [ Amazon CloudFront Distribution ] ──► (OAC Authentication) ──► [ Private S3 Bucket ]
                                    │
                                    └── Direct Access Blocked for Public (403 Forbidden)

```

1. **Origin Access Control (OAC):**
* CloudFront distribution mein **OAC (Origin Access Control)** create kiya jata hai.
* S3 Bucket Policy update ki jati hai jahan **OAC ko Read Access (`s3:GetObject`)** grant ki jati hai.
* Direct S3 internet access completely block rehta hai; content sirf CloudFront ke zariye hi route aur serve hota hai.



---

## 3. Correct Option Explanation

#### ✅ **Create an Origin Access Control (OAC) for CloudFront and grant access to the objects in your S3 bucket to that OAC.**

* **Why it works:** OAC AWS ka current best practice standard hai jo CloudFront ko private S3 bucket contents fetch karne ki permission deta hai jabki direct public S3 URLs ko completely block rakhta hai.

---

## 4. Incorrect Options Breakdown (Elimination Strategy)

| Option | Why It Fails the Exam Requirement |
| --- | --- |
| **S3 bucket policy with CloudFront distribution ID as principal...** | CloudFront Distribution ID direct AWS IAM Principal nahi hota. OAC Service Principal (`cloudfront.amazonaws.com`) along with `AWS:SourceArn` condition use hoti hai. |
| **Create a web ACL in AWS WAF to block public S3 access...** | AWS WAF CloudFront distribution par incoming HTTP/S requests filter karta hai. Yeh S3 bucket ki direct public access ko restrict ya control nahi kar sakta. |
| **Create an IAM user for CloudFront...** | CloudFront distribution ke liye IAM Users create nahi hote. Modern setup mein OAC (aur legacy setup mein OAI - Origin Access Identity) use hota hai. |

---

## 5. Exam Decision Matrix (S3 Origin Protection Cheat Sheet)

* **Secure S3 Bucket behind CloudFront (Modern Method):** $\rightarrow$ **Origin Access Control (OAC)**
* **Secure S3 Bucket behind CloudFront (Legacy Method):** $\rightarrow$ **Origin Access Identity (OAI)** *(Deprecated / Not recommended for new setups)*
* **Restrict Access to Specific Files via CloudFront:** $\rightarrow$ **CloudFront Signed URLs / Cookies**

### 🎯 What is being tested?

**CloudFront accessing a private S3 bucket.**

### ✅ Correct answer

**Create an Origin Access Control (OAC) for CloudFront and grant access to the objects in your S3 bucket to that OAC.**

### 🔑 Key concept

**OAC = CloudFront's secure identity for accessing private S3.**

Flow:

**Employee → CloudFront → OAC → Private S3**

* S3 remains **private** 🔒
* CloudFront is authorized to retrieve objects.
* Users don't need direct S3 access.

### 🔥 Exam shortcut

**Private S3 + CloudFront → OAC**

> Older questions may mention **OAI (Origin Access Identity)**, but **OAC is the current recommended mechanism**.
