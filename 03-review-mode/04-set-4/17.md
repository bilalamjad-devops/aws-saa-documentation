17. Question


Category: CSAA – Design Resilient Architectures

A company has a web application hosted in an On-Demand EC2 instance. You are creating a shell script that needs the instance’s public and private IP addresses.

What is the best way to get the instance’s associated IP addresses which your shell script can use?

- By using a CloudWatch metric.
- By using IAM.
- By using a Curl or Get Command to get the latest user data information from http://169.254.169.254/latest/user-data/
- `By using a Curl or Get Command to get the latest metadata information from http://169.254.169.254/latest/meta-data/`

<img width="583" height="384" alt="AWS-EC2-Metadata" src="https://github.com/user-attachments/assets/525ae313-1d44-4893-81ed-b0f03c5644e7" />

Is question mein **EC2 Instance Metadata Service (IMDS)** ka core concept test ho raha hai.

Aayein requirements ko Roman Urdu mein simple steps mein analyze karte hain:

---

### 1. Requirement Breakdown

1. **Task:** Shell script ke andar se EC2 instance ki **Public IP** aur **Private IP** address fetch karni hain.
2. **Constraint:** Best, automated, aur reliable tarika kya hai jo EC2 instance apne andar se hi chalay?

---

### 2. Technical Evaluation

```
[ EC2 Instance / Shell Script ] ──► HTTP GET http://169.254.169.254/latest/meta-data/ ──► IP Addresses, Instance ID, MAC, etc.

```

1. **Instance Metadata (`[http://169.254.169.254/latest/meta-data/](http://169.254.169.254/latest/meta-data/)`):**
* Instance Metadata running EC2 instance ke baare mein runtime info provide karta hai (e.g., Public IP, Private IP, Instance ID, Security Groups, IAM Role credentials).
* Script ke andar `curl [http://169.254.169.254/latest/meta-data/public-ipv4](http://169.254.169.254/latest/meta-data/public-ipv4)` ya `local-ipv4` chala kar directly IP fetch ki jati hai.


2. **User Data (`[http://169.254.169.254/latest/user-data/](http://169.254.169.254/latest/user-data/)`):**
* User Data mein woh bootstrap scripts / launch commands hoti hain jo instance launch hote waqt run hoti hain. Is mein IP address dynamic metadata ki tarah query nahi hota.



---

### 3. Correct Option Explanation

#### ✅ **By using a Curl or Get Command to get the latest metadata information from `[http://169.254.169.254/latest/meta-data/](http://169.254.169.254/latest/meta-data/)**`

* **Why it works:** Link `169.254.169.254` (link-local IP) instance metadata endpoint hai jo shell scripts ko running EC2 instance ki network settings (Public & Private IPs) fetch karne ki ijazat deta hai.

---

### 4. Incorrect Options Breakdown (Elimination Strategy)

| Option | Why It Fails the Exam Requirement |
| --- | --- |
| **By using a CloudWatch metric...** | CloudWatch CPU, RAM, Disk I/O, aur network traffic performance metrics monitor karta hai; individual EC2 instance ki IP addresses query karne ke liye use nahi hota. |
| **By using IAM...** | IAM authentication aur authorization (roles, permissions) handle karta hai; instances ki IP metadata store ya return nahi karta. |
| **By using user-data endpoint...** | `user-data` endpoint launch time initialization scripts store karta hai, dynamic networking info (meta-data) nahi. |

---

### 5. Exam Decision Matrix (IMDS Cheat Sheet)

* **Instance Properties (IPs, MAC, Instance ID, IAM Credentials):** $\rightarrow$ **`[http://169.254.169.254/latest/meta-data/](http://169.254.169.254/latest/meta-data/)`**
* **Launch / Bootstrap Scripts Provided at Launch:** $\rightarrow$ **`[http://169.254.169.254/latest/user-data/](http://169.254.169.254/latest/user-data/)`**
* **IMDS Security Enhancement against SSRF Attacks:** $\rightarrow$ **IMDSv2 (Uses Session Tokens via PUT headers)**
