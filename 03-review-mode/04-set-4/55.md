55. Question

Category: CSAA – Design Resilient Architectures

A company has a web application hosted in AWS cloud where the application logs are sent to Amazon CloudWatch. Lately, the web application has been encountering some errors which can be resolved simply by restarting the instance.

What will you do to automatically restart the EC2 instances whenever the same application error occurs?

- First, look at the existing Flow logs for keywords related to the application error to create a custom metric. Then, create a CloudWatch alarm for that custom metric which invokes an action to restart the EC2 instance.
- First, look at the existing Flow logs for keywords related to the application error to create a custom metric. Then, create a CloudWatch alarm for that custom metric which calls a Lambda function that invokes an action to restart the EC2 instance.
- First, look at the existing CloudWatch logs for keywords related to the application error to create a custom metric. Then, create an alarm in Amazon SNS for that custom metric which invokes an action to restart the EC2 instance.
- `First, look at the existing CloudWatch logs for keywords related to the application error to create a custom metric. Then, create a CloudWatch alarm for that custom metric which invokes an action to restart the EC2 instance.`

Is question mein **CloudWatch Metric Filters**, **CloudWatch Alarms**, aur **EC2 Auto-Recovery/EC2 Actions** ka concept test ho raha hai.

Aayein requirements aur options ko step-by-Step analyze karte hain:

---

### 1. Requirement Breakdown

1. **Log Location:** Application logs pehle se **Amazon CloudWatch Logs** mein sent ho rahe hain.
2. **Issue:** Log mein ek particular error keyword aata hai jisko resolve karne ke liye EC2 instance ko **restart/reboot** karna padta hai.
3. **Goal:** Error keyword aane par EC2 instance ko **automatically restart** karne ka system banana hai.

---

### 2. Technical Evaluation

```
[ Application Logs ] ──► [ CloudWatch Logs ] ──(Metric Filter: "Error Keyword")──► [ Custom Metric ]
                                                                                         │
                                                                                 (Threshold Exceeded)
                                                                                         ▼
                                                                               [ CloudWatch Alarm ]
                                                                                         │
                                                                             (Built-in EC2 Action)
                                                                                         ▼
                                                                              [ Restart EC2 Instance ]

```

1. **CloudWatch Logs vs. VPC Flow Logs:**
* Application errors (jaise `HTTP 500`, `DatabaseConnectionError`, etc.) **CloudWatch Logs** mein hote hain.
* **VPC Flow Logs** sirf network IP traffic (Source IP, Destination IP, Ports, ACCEPT/REJECT) capture karte hain, is mein application-level logs nahi hote.


2. **Metric Filter Creation:**
* CloudWatch Logs mein moojood log stream par ek **Metric Filter** lagaya jata hai joSpecific error keywords ko scan karke ek **Custom Metric** (e.g., `ErrorCount`) banata hai.


3. **CloudWatch Alarm & EC2 Actions:**
* Custom Metric par ek **CloudWatch Alarm** create hota hai.
* CloudWatch Alarms ke paas **built-in EC2 Actions** hote hain (jaise *Reboot*, *Stop*, *Terminate*, ya *Recover* an instance). Is ke liye alag se Lambda function ya SNS alarm ki zaroorat nahi parti.



---

### 3. Correct Option Explanation

#### ✅ **First, look at the existing CloudWatch logs for keywords related to the application error to create a custom metric. Then, create a CloudWatch alarm for that custom metric which invokes an action to restart the EC2 instance.**

* **Why it works:** CloudWatch logs se custom metric banta hai, aur CloudWatch Alarm ka direct built-in **EC2 Reboot/Restart Action** use karke instance auto-restart ho jata hai with minimal complexity.

---

### 4. Incorrect Options Breakdown (Elimination Strategy)

| Option | Why It Fails |
| --- | --- |
| **Flow logs for keywords...** | Flow logs network packet details capture karte hain, application logs/errors nahi. |
| **Flow logs + Lambda function...** | Flow logs application error read nahi kar sakte. Lambda add karna unnecessary overhead hai kyun ke CloudWatch Alarms mein EC2 restart action pehle se built-in hota hai. |
| **Alarm in Amazon SNS...** | Amazon SNS messaging service hai, Alarms **CloudWatch** mein bante hain (SNS sirf notification bhejne ke liye use hota hai). |

---

### 5. Cheat Sheet for CloudWatch Log Automation (SAA-C03)

* **Extract specific keywords from CloudWatch Logs:** $\rightarrow$ **CloudWatch Metric Filter**
* **Direct EC2 Reboot / Stop / Recover on Alarm:** $\rightarrow$ **CloudWatch Alarm Built-in EC2 Action**
* **Inspect Network IP Packets:** $\rightarrow$ **VPC Flow Logs**
