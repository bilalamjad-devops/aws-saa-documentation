54. Question

Category: CSAA – Design Secure Architectures

A multinational bank is storing its confidential files in an S3 bucket. The security team recently performed an audit, and the report shows that multiple files have been uploaded without 256-bit Advanced Encryption Standard (AES) server-side encryption. For added protection, the encryption key must be automatically rotated every year. The solutions architect must ensure that there would be no other unencrypted files uploaded in the S3 bucket in the future.

Which of the following will meet these requirements with the LEAST operational overhead?


- `Create an S3 bucket policy that denies permissions to upload an object unless the request includes the s3:x-amz-server-side-encryption": "AES256" header. Enable server-side encryption with Amazon S3-managed encryption keys (SSE-S3) and rely on the built-in key rotation feature of the SSE-S3 encryption keys.`
- Create a Service Control Policy (SCP) for the S3 bucket that rejects any object uploads unless the request includes the s3:x-amz-server-side-encryption": "AES256" header. Enable server-side encryption with Amazon S3-managed encryption keys (SSE-S3) and modify the built-in key rotation feature of the SSE-S3 encryption keys to rotate the key yearly.
- Create a new customer-managed key from the AWS Key Management Service (AWS KMS). Configure the default encryption behavior of the bucket to use the customer-managed key. Manually rotate the KMS key and every year.
- Create an S3 bucket policy for the S3 bucket that rejects any object uploads unless the request includes the s3:x-amz-server-side-encryption":"aws:kms" header. Enable the S3 Object Lock in compliance mode for all objects to automatically rotate the built-in AES256 customer-managed key of the bucket.

Is question mein **Amazon S3 Bucket Encryption Rules**, **SSE-S3 Key Rotation**, aur **Least Operational Overhead** ka security concept test ho raha hai.

Aayein requirements aur options ko step-by-step analyze karte hain:

---

### 1. Requirement Breakdown

1. **Security Audit Issue:** Pehle uploaded kuch files bina encryption ke hain. Aage se koi bhi **unencrypted file S3 bucket mein upload na ho sake**.
2. **Encryption Standard:** 256-bit Advanced Encryption Standard (AES-256) server-side encryption use honi chahiye.
3. **Key Rotation:** Encryption key ko **har saal (yearly) automatically rotate** hona chahiye.
4. **Constraint:** **LEAST operational overhead** (kam se kam manual kaam) ke sath yeh setup karna hai.

---

### 2. Technical Evaluation

1. **SSE-S3 Encryption Standard & Key Rotation:**
* **SSE-S3 (Server-Side Encryption with S3-Managed Keys)** AES-256 algorithm use karta hai (`"AES256"`).
* SSE-S3 mein keys ki rotation AWS background mein **automatically yearly basis par handle karta hai** (aap ko koi manual script ya KMS settings chalane ki zaroorat nahi hoti).


2. **Preventing Unencrypted Uploads via Bucket Policy:**
* An S3 Bucket Policy with an explicit `Deny` condition targeting uploads (`s3:PutObject`) that lack the header `"s3:x-amz-server-side-encryption": "AES256"` ensures that any request to upload an unencrypted file is rejected.



---

### 3. Correct Option Explanation

#### ✅ **Create an S3 bucket policy that denies permissions to upload an object unless the request includes the s3:x-amz-server-side-encryption": "AES256" header. Enable server-side encryption with Amazon S3-managed encryption keys (SSE-S3) and rely on the built-in key rotation feature of the SSE-S3 encryption keys.**

* **Why it works:** S3 Bucket Policy missing encryption headers ko reject karti hai, SSE-S3 default 256-bit AES encryption enforce karta hai, aur built-in automatic rotation zero operational effort requirement ko satisfy karti hai.

---

### 4. Incorrect Options Breakdown (Elimination Strategy)

| Option | Why It Fails |
| --- | --- |
| **Service Control Policy (SCP)...** | SCPs AWS Organizations level par AWS accounts par control lagate hain, individual S3 buckets par directly S3 headers filter ke sath attach nahi hote. Plus, SSE-S3 key rotation settings user modify nahi kar sakta. |
| **Customer-managed KMS key + Manual rotation...** | Requirement **automatic rotation** ki thi. Manual rotation operational overhead ko barha deti hai. |
| **S3 Object Lock compliance mode...** | S3 Object Lock Write-Once-Read-Many (WORM) compliance (file deletion prevent karne) ke liye hota hai; yeh encryption keys rotate karne ke liye design nahi hua. |

---

### 5. Cheat Sheet for S3 Encryption Enforcement (SAA-C03)

* **Enforce SSE-S3 via Bucket Policy:** $\rightarrow$ Condition check for `"s3:x-amz-server-side-encryption": "AES256"`
* **Built-in Automatic Key Rotation (Zero Overhead):** $\rightarrow$ **SSE-S3**
* **Manual / Managed Rotation Control with KMS:** $\rightarrow$ **AWS KMS Customer Managed Keys (CMK)**
