20. Question

Category: CSAA – Design High-Performing Architectures

A company has hundreds of VPCs with multiple VPN connections to their data centers spanning 5 AWS Regions. As the number of its workloads grows, the company must be able to scale its networks across multiple accounts and VPCs to keep up. A Solutions Architect is tasked to interconnect all of the company’s on-premises networks, VPNs, and VPCs into a single gateway, which includes support for inter-region peering across multiple AWS regions.

Which of the following is the BEST solution that the architect should set up to support the required interconnectivity?

- Set up an AWS VPN CloudHub for inter-region VPC access and a Direct Connect gateway for the VPN connections to the on-premises data centers. Create a virtual private gateway in each VPC, then create a private virtual interface for each AWS Direct Connect connection to the Direct Connect gateway.
- Set up an AWS Direct Connect Gateway to achieve inter-region VPC access to all of the AWS resources and on-premises data centers. Set up a link aggregation group (LAG) to aggregate multiple connections at a single AWS Direct Connect endpoint in order to treat them as a single, managed connection. Launch a virtual private gateway in each VPC and then create a public virtual interface for each AWS Direct Connect connection to the Direct Connect Gateway.
- `Set up an AWS Transit Gateway in each region to interconnect all networks within it. Then, route traffic between the transit gateways through a peering connection.`
- Enable inter-region VPC peering that allows peering relationships to be established between multiple VPCs across different AWS regions. Set up a networking configuration that ensures that the traffic will always stay on the global AWS backbone and never traverse the public Internet.

Is question mein **Multi-Region, Multi-Account Network Interconnectivity** aur **AWS Transit Gateway (TGW)** ka central integration test ho raha hai.

Aayein requirements ko Roman Urdu mein simple steps mein analyze karte hain:

---

### 1. Requirement Breakdown

1. **Scale:** Hundreds of VPCs, multiple VPN connections, 5 AWS Regions, aur on-premises data centers.
2. **Goal:** On-prem networks, VPNs, aur VPCs ko aapas mein **single centralized gateway architecture** ke zariye interconnect karna.
3. **Core Requirement:** **Inter-region peering** support honi chahiye across multiple AWS regions.
4. **Constraint:** Complex full-mesh peering manage na karni pade; scalable aur easily managed solution chahiye.

---

### 2. Technical Evaluation

```
[ Region 1: TGW ] ◄── Inter-Region Peering ──► [ Region 2: TGW ]
      │                                             │
 ┌────┴────┐                                   ┌────┴────┐
[VPCs / VPN]                                  [VPCs / VPN]

```

1. **AWS Transit Gateway (TGW):**
* Transit Gateway ek **Regional Network Hub** (centralized router) ki tarah kaam karta hai jo VPCs, VPNs, aur Direct Connect ko aapas mein connect karta hai.
* Region-to-Region connectivity ke liye aap har Region mein ek Transit Gateway banate hain aur unke darmayan **Transit Gateway Inter-Region Peering** enable karte hain.


2. **Scalability:**
* Direct VPC Peering se 100s of VPCs ke liye mesh banani padti hai ($N \times (N-1)/2$), jab ke Transit Gateway **Hub-and-Spoke topology** de kar network architecture ko massively simplify karta hai.



---

### 3. Correct Option Explanation

#### ✅ **Set up an AWS Transit Gateway in each region to interconnect all networks within it. Then, route traffic between the transit gateways through a peering connection.**

* **Why it works:** Har region mein Transit Gateway hub-and-spoke model setup karta hai jo region ke saare VPCs aur VPNs ko connect karta hai, aur Transit Gateway Peering se 5 Regions aapas mein securely connect ho jate hain.

---

### 4. Incorrect Options Breakdown (Elimination Strategy)

| Option | Why It Fails the Exam Requirement |
| --- | --- |
| **AWS VPN CloudHub + Direct Connect Gateway...** | VPN CloudHub multiple remote sites ko connect karne ke liye hota hai; hundreds of VPCs ki inter-region mesh management ke liye scalable nahi hai. |
| **Link Aggregation Group (LAG) + Direct Connect...** | LAG Direct Connect links ki bandwidth/redundancy badhane ke liye hota hai, 100s of VPCs aur VPNs ki routing/interconnectivity manage nahi karta. |
| **Enable inter-region VPC peering...** | Direct VPC Peering transitive routing support nahi karta. Hundreds of VPCs ke liye hazaron peering connections banane padenge jo manage karna impossible ho jayega. |

---

### 5. Exam Decision Matrix (AWS Networking Hubs Cheat Sheet)

* **Hub-and-Spoke Network Routing (VPCs + VPNs + DX across accounts/regions):** $\rightarrow$ **AWS Transit Gateway (TGW)**
* **Connect On-Premises DX to Multi-Region VPCs:** $\rightarrow$ **Direct Connect Gateway**
* **Connect Multiple Remote Branch Sites via VPN:** $\rightarrow$ **AWS VPN CloudHub**

---
