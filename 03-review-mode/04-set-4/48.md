48. Question

Category: CSAA – Design Cost-Optimized Architectures

A company is looking to store its confidential financial files in AWS, which are accessed every week. The Architect was instructed to set up the storage system, which uses envelope encryption and automates key rotation. It should also provide an audit trail that shows who used the encryption key and by whom for security purposes.

Which combination of actions should the Architect implement to satisfy the requirement in the most cost-effective way? (Select TWO.)

- Configure Server-Side Encryption with Customer-Provided Keys (SSE-C).
- `Configure Server-Side Encryption with AWS KMS Keys (SSE-KMS).`
- Configure Server-Side Encryption with Amazon S3-Managed Keys (SSE-S3).
- `Use Amazon S3 to store the data.`
- Use Amazon S3 Glacier Deep Archive to store the data.

Is question mein **S3 Encryption Options**, **AWS Key Management Service (AWS KMS)**, **Envelope Encryption**, aur **S3 Storage Classes** ka cost-optimization strategy test ho raha hai.

Aayein requirements aur options ko Roman Urdu mein Step-by-Step analyze karte hain:

---

### 1. Requirement Breakdown

1. **Access Frequency:** Data ko **har hafte (weekly)** access kiya jata hai.
2. **Security & Encryption Requirements:**
* **Envelope Encryption** use honi chahiye.
* **Automated Key Rotation** hona chahiye.
* **Audit Trail** (pata chalna chahiye kisne key kab use ki) moojood ho for security compliance.


3. **Cost Optimization:** Sub se cost-effective combination select karna hai.

---

### 2. Technical Evaluation

```
[ Amazon S3 (Standard) ] ──► [ AWS KMS Key (SSE-KMS) ] ──► [ AWS CloudTrail Audit Logs ]
(Weekly Access Data)           (Envelope Encryption &       (Track who accessed keys)
                                Auto-Rotation)

```

1. **Storage Class Selection:**
* Data **har hafte (weekly)** access ho raha hai.
* **S3 Glacier Deep Archive** pehli baar data retrive karne par 12–48 hours lagata hai aur high retrieval fees charge karta hai. Deep Archive sirf long-term archival data (jo saal mein 1-2 baar access ho) ke liye hota hai. Is liye weekly data ke liye **Amazon S3** standard/frequent storage right choice hai.


2. **Encryption Mechanism Selection:**
* **SSE-KMS (Server-Side Encryption with AWS KMS Keys):**
* Envelope Encryption leverage karta hai (Data Key + Master Key).
* Automatic yearly key rotation support karta hai.
* **AWS CloudTrail** ke sath natively integrate hota hai, jo poori Audit Trail log karta hai ke kis user/service ne kis waqt key call ki.


* **SSE-S3:** Managed keys hotay hain, detailed individual KMS audit trails / custom key rotation policies support nahi karte.
* **SSE-C:** Client-side management ki waja se operational overhead high hota hai.



---

### 3. Correct Options Explanation

#### ✅ **Configure Server-Side Encryption with AWS KMS Keys (SSE-KMS)**

* **Why it works:** SSE-KMS envelope encryption, automated key rotation, aur AWS CloudTrail integration ke zariye exact audit trails provide karta hai.

#### ✅ **Use Amazon S3 to store the data**

* **Why it works:** Financial files har hafte access honi hain, is liye S3 (Standard) immediate access allow karta hai bina kisi heavy retrieval delays ya extra charges ke.

---

### 4. Incorrect Options Breakdown (Elimination Strategy)

| Option | Why It Fails |
| --- | --- |
| **Configure SSE-C...** | Customer-provided keys mein AWS audit trails aur automatic rotation natively handle nahi karta; operational complexity barh jati hai. |
| **Configure SSE-S3...** | SSE-S3 (S3-managed keys) mein CloudTrail par KMS-level audit logs aur custom key rotation tracking available nahi hoti. |
| **Use Amazon S3 Glacier Deep Archive...** | Deep Archive **weekly access** ke liye bilkul suit nahi karta. Iski retrieval timing (12-48 hours) aur weekly data retrieval costs high hoti hain. |

---

### 5. Cheat Sheet for S3 Encryption & Storage (SAA-C03)

* **Envelope Encryption + Audit Trail + Key Rotation:** $\rightarrow$ **SSE-KMS**
* **Free / Simple Server-Side Encryption (No Audit):** $\rightarrow$ **SSE-S3**
* **Weekly / Frequent Data Access:** $\rightarrow$ **S3 Standard / S3 Standard-IA**
* **Rare Access (Once/Twice a Year Archival):** $\rightarrow$ **S3 Glacier Deep Archive**
