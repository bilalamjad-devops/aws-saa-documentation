28. Question

Category: CSAA – Design Secure Architectures

A Solutions Architect is designing a monitoring application that generates audit logs of all operational activities of the company’s cloud infrastructure. The IT Security and Compliance team mandates that the application retain the logs for 5 years before the data can be deleted.

How can the Architect meet the above requirement?

- Store the audit logs in an Amazon S3 bucket and enable Multi-Factor Authentication Delete (MFA Delete) on the S3 bucket.
- `Store the audit logs in an Amazon S3 bucket with versioning and S3 Object Lock enabled in Compliance mode.`
- Store the audit logs in an Amazon EFS volume and use Network File System version 4 (NFSv4) file-locking mechanism.
- Store the audit logs in an Amazon EBS volume and then take EBS snapshots every month.

Is question mein **Data Retention, WORM (Write Once, Read Many) Compliance, aur S3 Object Lock** ka security architecture rule test ho raha hai.

### 1. Requirement Breakdown

1. **Goal:** Cloud infrastructure ke audit logs ko mandatory **5 years** tak preserve/retain karna hai.
2. **Constraint:** 5 saal se pehle koi bhi user (hata ke AWS root account user) in logs ko modify ya delete na kar sake.

---

### 2. Correct Option Explanation

#### ✅ **Store the audit logs in an Amazon S3 bucket with versioning and S3 Object Lock enabled in Compliance mode.**

* **Why it works:** **S3 Object Lock** (WORM model) compliance enforcement ke liye use hota hai. **Compliance mode** mein koi bhi user (including root account) retention period (5 years) khatam hone se pehle objects ko delete ya overwrite nahi kar sakta. Versioning is function ke liye mandatory prerequisite hai.

---

### 3. Incorrect Options Breakdown (Elimination Strategy)

| Option | Why It Fails the Exam Requirement |
| --- | --- |
| **Enable MFA Delete on S3...** | MFA Delete unauthorized users se protect karta hai, lekin 5 saal ki fixed retention compliance enforce nahi karta (MFA code hone par root user pehle hi delete kar sakta hai). |
| **Amazon EFS + NFSv4 file-locking...** | NFSv4 locks concurrent file access ke liye hote hain, long-term 5-year compliance retention ke liye nahi. |
| **Amazon EBS + Monthly Snapshots...** | Monthly snapshots 5 saal ke beech files ko overwrite/delete hone se nahi rokte. |

---

### 4. Exam Decision Matrix (S3 Compliance Cheat Sheet)

* **WORM Compliance (No one can delete for X years, even root):** $\rightarrow$ **S3 Object Lock in Compliance Mode**
* **Flexible WORM (Users restricted, but privileged users can alter/delete):** $\rightarrow$ **S3 Object Lock in Governance Mode**
* **Prevent Accidental Deletions via MFA:** $\rightarrow$ **S3 MFA Delete**
