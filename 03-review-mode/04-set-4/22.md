22. Question

Category: CSAA – Design Resilient Architectures

A company has a set of Linux servers running on multiple On-Demand Amazon EC2 instances powered by the EC2 Nitro System. The Audit team wants to collect and process the application log files generated from these servers for the report.

Which of the following is the most suitable solution to meet this requirement?

- Amazon S3 Glacier for storing the application log files and Spot EC2 Instances for processing them.
- Amazon S3 Glacier Deep Archive for storing the application log files and AWS ParallelCluster for processing the log files.
- `Amazon S3 for storing the application log files and Amazon Elastic MapReduce for processing the log files.`
- A single On-Demand EC2 instance for both storing and processing the log files

Is question mein **Log Collection, Centralized Storage, aur Scalable Processing** ka architecture design test ho raha hai.

Aayein requirements ko Roman Urdu mein analyze karte hain:

---

### 1. Requirement Breakdown

1. **Source:** Multiple Linux EC2 instances se application log files collect karni hain.
2. **Tasks:**
* Log files ko **store** karna.
* Reports generate karne ke liye log files ko **process** karna.


3. **Core Requirement:** Sub-systems scalable, reliable, aur audit logging workflows ke liye suitable honi chahiye.

---

### 2. Technical Evaluation

```
[ Multiple Linux EC2 Instances ] ──► [ Amazon S3 (Centralized Log Storage) ] ──► [ Amazon EMR (Log Processing Cluster) ]

```

1. **Storage (Amazon S3):**
* S3 log storage ke liye industry standard hai (durable, scalable, aur cheap).
* EMR Direct S3 se data read aur write kar sakta hai (S3 Select / EKS / Hadoop integration ke zariye).


2. **Processing (Amazon Elastic MapReduce - EMR):**
* Large-scale log processing, analytics, aur transformation ke liye **Amazon EMR (Spark/Hadoop)** sab se powerful managed tool hai.


3. **Glacier Limits:**
* Glacier / Glacier Deep Archive direct log processing ke liye ready-to-use nahi hain (pehlei data restore karna padta hai jo hours leta hai, is liye active batch processing fail ho jayegi).



---

### 3. Correct Option Explanation

#### ✅ **Amazon S3 for storing the application log files and Amazon Elastic MapReduce for processing the log files.**

* **Why it works:** Amazon S3 centralized, highly durable storage offer karta hai log storage ke liye, aur Amazon EMR distributed log analysis aur processing efficiently compute kar leta hai.

---

### 4. Incorrect Options Breakdown (Elimination Strategy)

| Option | Why It Fails the Exam Requirement |
| --- | --- |
| **S3 Glacier + Spot EC2 Instances...** | Glacier se data retrieve hone mein ghante lagte hain; direct logs process nahi ho sakte. |
| **Glacier Deep Archive + AWS ParallelCluster...** | Deep Archive retrieval time 12+ hours hai; AWS ParallelCluster HPC (High-Performance Computing) simulation workloads ke liye hota hai, standard log analytics ke liye nahi. |
| **Single On-Demand EC2 Instance...** | Single instance multiple servers ke heavy logs ko store aur process karne mein scale nahi kar payega (Single Point of Failure + Bottleneck). |

---

### 5. Exam Decision Matrix (Log Storage & Processing Cheat Sheet)

* **Big Data / Log Analytics at Scale (Hadoop/Spark):** $\rightarrow$ **Amazon EMR + Amazon S3**
* **Serverless SQL Querying on S3 Logs:** $\rightarrow$ **Amazon Athena + Amazon S3**
* **Real-time Log Ingestion & Streaming:** $\rightarrow$ **Amazon Kinesis Data Firehose + Amazon S3**
