22. Question

Category: CSAA – Design Secure Architectures

A well-known music streaming service is planning to broaden its platform globally. However, the company must ensure that listeners in certain countries cannot access specific music content until it is officially launched in their respective regions, in accordance with its music licensing agreements and restrictions.

To achieve this, the company will utilize Amazon CloudFront’s content delivery network and Origin Access Control (OAC) feature to prevent unauthorized users from accessing the content. Customized error messages must also be configured for users who are not authorized to access particular music tracks.

What solution would be able to fulfill these requirements?

- Configure CloudFront to return a custom error response to the viewer. Use both signed URLs and signed cookies for secure content access.
- Configure CloudFront to return a custom error response to the viewer. Implement a time-restricted IAM access policy for CloudFront distribution.
- Configure CloudFront to return a custom error response to the viewer. Set up a CloudFront Function URL to control access.
- `Configure CloudFront to return a custom error response to the viewer and apply geographic restrictions using an Allow list.`

### Question Ka Summary:

Music streaming service ko global expansion ke dauran **country-specific licensing restrictions** implement karni hain taake specific countries ke listeners ghair-mujaaz (unauthorized) access na kar sakein.

**Key Requirements:**

1. **Geographic Blocking/Allowing:** Certain countries mein content access allowed ho aur baaqi mein block.
2. **Custom Error Messages:** Unauthorized country users ke liye custom error response return hona chahiye.
3. **CloudFront Distribution:** AWS CloudFront use kiya ja raha hai.

---

### Options Ka Breakdown:

1. **Option 1 (Signed URLs and Signed Cookies):**
* **Galat:** Signed URLs / Signed Cookies specific individual users ko time-bound links ke zariye access dene ke liye hote hain (jaise paid subscriber download link). Country-based geographic restriction ke liye yeh main solution nahi hai.


2. **Option 2 (Time-restricted IAM access policy for CloudFront):**
* **Galat:** IAM policies AWS resources ki permissions manage karti hain, end-user listeners ki location-based web access controls handle nahi kartin.


3. **Option 3 (CloudFront Function URL to control access):**
* **Galat:** CloudFront Functions URL rewrites ya headers manipulation ke liye lightweight edge computing code hotay hain. Standard geographic country blocking ke liye built-in features majood hain, function writing redundant effort hai.


4. **Option 4 (Custom Error Response + Geographic Restrictions / Allow List):**
* **Sahi (Correct):**
* **Amazon CloudFront Geographic Restriction (Geo Restriction):** Yeh natively allow list ya deny list (country codes ke mutabiq) create karne ki saholat deta hai taake specific regions mein content restrict kiya ja sake.
* Jab koi restricted country se access karne ki koshish karta hai, toh CloudFront **403 Forbidden** status code deta hai. **Custom Error Pages / Responses** feature ke zariye aap is 403 error ko custom localized message page se replace kar sakte hain.





---

### Sahi Jawab:

**Option 4:** **Configure CloudFront to return a custom error response to the viewer and apply geographic restrictions using an Allow list.**

> **Exam Tip:**
> * **Country-level Access Control in CloudFront** = **CloudFront Geo Restriction (Allow List / Block List)**
> * **Custom User Error Messaging** = **CloudFront Custom Error Responses (HTTP 403 / 404 handling)**
