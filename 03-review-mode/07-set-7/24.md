24. Question

Category: CSAA – Design Secure Architectures

A company has moved its suite of internal tools to AWS. For audit compliance, several CloudTrail trails are made to record all API calls. Each log file is also protected with server-side encryption with AWS KMS keys (SSE-KMS). Despite this, the company wants to ensure it can identify whether a log file has been tampered with.

Which security measure should the solutions architect employ?

- `Enable the CloudTrail Log File Validation feature on all trails.`
- Use the CloudTrail Processing Library when doing audit compliance.
- Enable CloudTrail Insights events.
- Configure CloudWatch Logs to monitor all trails and use Amazon SNS to send notifications when a log file has been tampered with.

### Question Ka Summary:

Company ne apne CloudTrail log files ko SSE-KMS se encrypt kiya hua hai. Compliance audit ke liye unhe yeh verify karna hai ke **kya koi CloudTrail log file tampered (modify, delete, ya alter) hui hai ya nahi**.

Requirement: **Log file tampering (unauthorized modification) detect karne ke liye sab se suitable AWS security measure konsa hai?**

---

### Options Ka Breakdown:

1. **Option 1 (Enable CloudTrail Log File Validation feature):**
* **Sahi (Correct):**
* **CloudTrail Log File Validation** ek built-in feature hai jo cryptographically check karta hai ke CloudTrail log file deliver hone ke baad modify ya delete toh nahi hui.
* Yeh har deliver hone waali log file ke liye **SHA-256 cryptographic hash** aur **RSA digital signature** se digest files create karta hai. Is tarah aap CLI / API se verify kar sakte hain ke log file bilkul intact (tamper-free) hai.




2. **Option 2 (Use the CloudTrail Processing Library):**
* **Galat:** CloudTrail Processing Library Java-based library hai jo S3 se continuous CloudTrail events ko process karne ke liye use hoti hai (jaise event processing applications). Yeh built-in tamper detection verification mechanism nahi hai.


3. **Option 3 (Enable CloudTrail Insights events):**
* **Galat:** CloudTrail Insights unusual operational activity ya anomalous API call volumes (jaise sudden spike in API calls) ko identify karta hai. Yeh log files ki cryptographic integrity ya tampering check nahi karta.


4. **Option 4 (Configure CloudWatch Logs to monitor...):**
* **Galat:** CloudWatch Logs metrics aur alarms operational patterns monitor karte hain, lekin binary log files ki cryptographic hash validation ya file tampering verification perform nahi karte.



---

### Sahi Jawab:

**Option 1:** **Enable the CloudTrail Log File Validation feature on all trails.**

> **Exam Tip:**
> * **Verify CloudTrail Log Integrity / Tampering Detection** = **CloudTrail Log File Validation** (Uses SHA-256 hashes & RSA signatures).
> * **Detect Unusual API Call Spikes / Anomalies** = **CloudTrail Insights**.
