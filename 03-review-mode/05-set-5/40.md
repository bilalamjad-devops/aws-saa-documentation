40. Question

Category: CSAA – Design Resilient Architectures

An investment bank has a distributed batch processing application that is hosted in an AWS Auto Scaling group of Amazon EC2 Spot instances with an Amazon SQS queue. The SQS queue is currently configured to use short polling to retrieve messages, and the components are configured to use client-side buffering so that the calls made from the client will be buffered first and then sent as a batch request to SQS.

What is a period of time during which the SQS queue prevents other consuming components from receiving and processing a message?

- Processing Timeout
- Component Timeout
- `Visibility Timeout`
- Receiving Timeout

Is question ka correct answer **Visibility Timeout** hai.

Aayein Amazon SQS ke is crucial feature aur is ke workflow ko samajhte hain:

---

### Key Scenario Breakdown & Concept

* **Workload:** EC2 Spot instances par chalne wali batch processing application jo Amazon SQS queue se messages retrieve karti hai.
* **Core Question:** Woh konsa time period hota hai jisme SQS queue ek message ko baqi consumer components se chupa (prevent) deti hai taake usay ek hi worker process kare aur duplicate processing na ho?

---

### Correct Option Explanation

#### ✅ **Visibility Timeout**

* **How it Works:**
1. Jab koi consumer process SQS queue se message read karta hai (receive karta hai), SQS us message ko queue se **delete nahi karta** balkay background mein ek timer start kar deta hai—jise **Visibility Timeout** kehte hain.
2. Is Visibility Timeout ke dauran, woh particular message baqi sabhi consumers ke liye **invisible** (hidden) ho jata hai.
3. Agar worker/consumer us time ke andar message successfully process karke SQS se delete kar de, toh story khatam.
4. Agar worker crash ho jaye ya timeout khatam hone tak delete na kar sakay, toh SQS message ko dobara **visible** kar deta hai taake koi doosra worker usay pick karke process kar sake.


* **Default Value:** Amazon SQS ka default Visibility Timeout **30 seconds** hota hai (jise 0 seconds se 12 hours tak adjust kiya ja sakta hai).

---

### Incorrect Options Breakdown (Elimination)

* ❌ **Processing Timeout:** Aisi koi formal SQS metric/setting nahi hoti.
* ❌ **Component Timeout:** Yeh ek generic term hai, SQS ka feature nahi.
* ❌ **Receiving Timeout:** SQS mein *Receive Message Wait Time* hota hai jo **Long Polling** ke liye use hota hai (message chupanay ke liye nahi).

---

### SAA-C03 SQS Cheat Sheet

> * **Prevent Duplicate Processing / Message Invisibility Period:** **Visibility Timeout**
> * **Reduce Cost & Empty Responses (Wait for messages):** **Long Polling** (Wait time up to 20 seconds)
> * **Handle Poison Pill / Unprocessable Messages:** **Dead Letter Queue (DLQ)** with `maxReceiveCount`
