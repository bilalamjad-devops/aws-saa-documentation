31. Question

Category: CSAA – Design Secure Architectures

An On-Demand EC2 instance is launched into a VPC subnet with the Network ACL configured to allow all inbound traffic and deny all outbound traffic. The instance’s security group has an inbound rule to allow SSH from any IP address and does not have any outbound rules.

In this scenario, what are the changes needed to allow SSH connection to the instance?

- Both the outbound security group and outbound network ACL need to be modified to allow outbound traffic.
- `The network ACL needs to be modified to allow outbound traffic.`
- The outbound security group needs to be modified to allow outbound traffic.
- No action needed. It can already be accessed from any IP address using SSH.

Is question ka correct answer **The network ACL needs to be modified to allow outbound traffic.** hai.

Aayein **Security Group vs Network ACL (NACL)** ke core difference se isko step-by-step samajhte hain:

---

### Key Scenario Breakdown

* **Security Group (Stateful):**
* Inbound rule: Allowed SSH (Port 22) from any IP.
* Outbound rule: No rules defined.


* **Network ACL (Stateless):**
* Inbound rule: Allowed ALL traffic.
* Outbound rule: **DENIED ALL traffic**.



---

### Core Concept: Stateful vs Stateless

1. **Security Groups Stateful hain:**
* Jab aap Security Group mein Inbound SSH request allow karte hain, toh Security Group automatically **Outbound response (return traffic) ko allow kar deta hai**, chahe outbound rules mein kuch bhi likha ho ya khali ho. Is liye Security Group ka Outbound rule change karne ki bilkul zaroorat nahi hai.


2. **Network ACLs Stateless hain:**
* NACL ko Inbound aur Outbound traffic ka alag alag tracker rakhna padta hai.
* Agarchay NACL ne Inbound request allow kar di, lekin jab EC2 instance response wapas bhejne ki koshish karega, toh **NACL Outbound Deny Rule** us return traffic ko block kar dega.
* Is waja se SSH connection establish nahi ho payega jab tak NACL ka outbound rule modify na kiya jaye.



---

### Option Analysis

* ❌ **Both SG and NACL need modification:** Security Group stateful hota hai, is liye us par outbound rule ki zaroorat nahi hai.
* ✅ **The network ACL needs to be modified to allow outbound traffic:** Yeh bilkul correct hai, kyunke NACL stateless hai aur iska outbound deny response traffic ko rok raha hai.
* ❌ **The outbound security group needs to be modified:** Security Group ki statefulness response traffic ko auto-allow kar deti hai.
* ❌ **No action needed:** Connection fail ho jaye ga kyunke NACL outbound response ko drop kar dega.

---

### SAA-C03 Exam Rule

> **Stateful (Security Group):** Allowed inbound traffic automatically gets allowed outbound response.
> **Stateless (NACL):** Allowed inbound traffic MUST explicitly be allowed in outbound rules as well (including ephemeral ports for response).
