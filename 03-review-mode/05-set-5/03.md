3. Question

Category: CSAA – Design Cost-Optimized Architectures

A wellness company is currently working on a wearable device that monitors key health metrics such as heart rate, sleep, and steps per day. The device is designed to send data to an Amazon S3 bucket for storage and analysis. On a daily basis, the device produces 1 MB of data. In order to quickly process and summarize this data, the company requires 512 MB of memory and must complete the task within a maximum of 10 seconds.

Which solution can fulfill these requirements in the MOST cost-effective manner?

- Store the data in Amazon Redshift and process it with AWS Lambda.
- Use Amazon Data Firehose to send the data from the device to Amazon S3. Process the data on an EC2 instance with at least 512 MB of memory.
- `Use AWS Lambda with a Python library for processing.`
- Create an AWS Glue PySpark job to process the data.

Is question mein **Serverless Event-Driven Processing**, **Small/Short Workloads**, aur **Cost Optimization** ka concept test ho raha hai.

Aayein requirements aur options ko step-by-step analyze karte hain:

---

### 1. Requirement Breakdown

1. **Input Data Size:** Har device daily sirf **1 MB data** S3 bucket mein bhejta hai (bohot chhota dataset).
2. **Compute Requirements:** Processing ke liye sirf **512 MB Memory** aur maximum **10 seconds execution time** chahiye.
3. **Goal:** Is short, low-memory, aur low-duration task ko sab se **MOST cost-effective** tarike se process karna.

---

### 2. Technical Evaluation

```
[ S3 Bucket (1 MB File) ] ──► [ S3 Event Notification / Trigger ] ──► [ AWS Lambda (512 MB RAM, ~10s execution) ]
                                                                                │
                                                                                ▼
                                                                     (Process & Summarize Data)

```

1. **AWS Lambda for Small & Short Tasks:**
* AWS Lambda microservices aur small data files (1 MB) ko short duration (10 seconds) ke liye process karne ke liye sab se cheap aur efficient solution hai.
* Lambda ka pricing Model: Pay only for execution duration (milliseconds) aur allocated RAM (512 MB). 1 MB file ko 10s mein process karne ka cost fraction of a cent hota hai.


2. **AWS Glue / Amazon Redshift / EC2 Overkill:**
* **AWS Glue (PySpark):** Heavy ETL pipelines (Gigabytes/Terabytes) ke liye hota hai. Glue jobs ka minimum billing 1-minute DPUs par hota hai, jo 1 MB file ke liye bohot expensive padega.
* **Amazon Redshift:** Data Warehousing solution hai. 1 MB daily file ke liye Redshift cluster chalana extreme money wastage hai.
* **EC2 Instance:** Continuous provisioning costs mangta hai (24/7 idle time cost), jabki task sirf 10 seconds ka hai.



---

### 3. Correct Option Explanation

#### ✅ **Use AWS Lambda with a Python library for processing.**

* **Why it works:** AWS Lambda automatically scale hota hai, exact allocated memory (512 MB) aur execution duration (10 seconds) ke hisab se billing karta hai. Small daily payloads (1 MB) ke liye yeh absolute most cost-effective architecture hai.

---

### 4. Incorrect Options Breakdown (Elimination Strategy)

| Option | Why It Fails |
| --- | --- |
| **AWS Glue PySpark job...** | Glue high-throughput, large-scale ETL (data lake) processes ke liye hota hai; 1 MB file par run karna extremely expensive padega. |
| **Amazon Redshift + AWS Lambda...** | Redshift petabyte-scale data warehouse hai. Small daily file summarization ke liye unnecessary complex aur costly hai. |
| **Amazon Data Firehose + EC2...** | EC2 instance ko continuous run karna (idle time ka pay karna) serverless Lambda ke muqable bohot costly hota hai. |

---

### 5. Cheat Sheet for Compute Selection (SAA-C03)

* **Small File (< Few MBs) + Short Duration (< 15 mins) + Event-Driven:** $\rightarrow$ **AWS Lambda** (Most Cost-Effective).
* **Large Dataset (GBs/TBs) + Distributed ETL / Spark:** $\rightarrow$ **AWS Glue** or **Amazon EMR**.
* **Continuous / Long-Running Workloads (> 15 mins execution):** $\rightarrow$ **Amazon EC2** or **AWS Fargate / ECS**.
