4. Question

Category: CSAA – Design Cost-Optimized Architectures

A company has 10 TB of infrequently accessed financial data files that would need to be stored in AWS. These data would be accessed infrequently during specific weeks when they are retrieved for auditing purposes. The retrieval time is not strict as long as it does not exceed 24 hours.

Which of the following would be a secure, durable, and cost-effective solution for this scenario?

- Upload the data to S3 then use a lifecycle policy to transfer data to S3 One Zone-IA.
- `Upload the data to S3 and set a lifecycle policy to transition data to Glacier after 0 days.`
- Upload the data to S3 then use a lifecycle policy to transfer data to S3-IA.
- Upload the data to Amazon FSx for Windows File Server using the Server Message Block (SMB) protocol.

Aayein is question ko ek simple real-life example se samajhte hain:

---

### Real-Life Analogy (Office Files & Store Room)

Sochein aap ke paas **10 TB (bohot bada dher)** puraane **Audit / Tax Records** hain:

1. Aap ko yeh files daily nahi chahiye (mahino mein kabhi ek baar audit ke liye chahiye hote hain).
2. Jab auditor aaye, toh usko files milne mein agar **3 se 12 ghante (under 24 hours)** ka time bhi lag jaye, toh koi masla nahi hai.

Aap ke paas office mein 3 jagah hain yeh files rakhne ki:

* **Office Ke Desk Par (S3 Standard / S3-IA):**
Files minutes mein mil jati hain, lekin jagah ka kiraya (Storage Cost) **bohot mahanga** hai.
* **Kareeb Ki Shop Mein (S3 One Zone-IA):**
Kiraya thoda kam hai, lekin agar us shop ko aag lag jaye (1 AZ down ho jaye), toh saara audit data khatam ho sakta hai.
* **Base Camp / Lock-up Store Room (S3 Glacier):**
Kiraya **nahone ke barabar (sab se sasta)** hai. Jab bhi file chahiye ho, aap request bhejte hain aur 3-12 ghante ke andar store room wala banda file nikaal kar de deta hai.

---

### S3 Storage Classes Ka Mukabla

| Storage Class | Kiraya (Cost) | Availability / Durability | Retrieval Time (File Milne Ka Waqt) |
| --- | --- | --- | --- |
| **S3 Standard** | High | 3+ AZs (High) | Instantly (Milliseconds) |
| **S3 Standard-IA** | Medium | 3+ AZs (High) | Instantly (Milliseconds) |
| **S3 One Zone-IA** | Lower | **1 AZ Only** (Riskier) | Instantly (Milliseconds) |
| **S3 Glacier** | **Lowest (Boht Sasta)** | 3+ AZs (High) | **3 to 12 Hours** (Under 24 hours) |

---

### Question Ka Direct Answer

Question ne 3 baatein maangi thi:

1. Data **infrequently access** hota hai (audit ke liye).
2. File milne mein **24 ghante tak ka waqt** chalega.
3. Sab se **sasta (cost-effective)** tareeka chahiye.

Is liye sab se behtareen tareeka yeh hai ke data S3 mein upload karein aur **Lifecycle Policy** laga kar pehle hi din (**Day 0**) us data ko **S3 Glacier** mein bhej dein taake storage cost bilkul kam ho jaye.
