21. Question

Category: CSAA – Design Secure Architectures

A company is using AWS IAM to manage access to AWS services. The Solutions Architect of the company created the following IAM policy for AWS Lambda:


```saa
{
"Version": "2012-10-17",
"Statement": [
{
"Effect": "Allow",
"Action": [
"lambda:CreateFunction",
"lambda:DeleteFunction"
],
"Resource": "*"
},
{
"Effect": "Deny",
"Action": [
"lambda:CreateFunction",
"lambda:DeleteFunction",
"lambda:InvokeFunction",
"lambda:TagResource"
],
"Resource": "*",
"Condition": {
"IpAddress": {
"aws:SourceIp": "187.5.104.11/32"
}
}
}
]
}
```


Which of the following options is allowed by this policy?

- Delete an AWS Lambda function from any network address.
- Create an AWS Lambda function using the 187.5.104.11/32 address.
- Delete an AWS Lambda function using the 187.5.104.11/32 address.
- `Create an AWS Lambda function using the 100.220.0.11/32 address.`

Is question mein **IAM Policy Evaluation Logic** (Deny vs Allow rules) test ho raha hai.

Aayein policy ko step-by-step analyze karte hain:

---

### 1. IAM Policy Breakdown

Policy mein do statements hain:

1. **Statement 1 (Allow):**
* **Actions Allowed:** `lambda:CreateFunction`, `lambda:DeleteFunction`
* **Condition:** Har IP address se allow karta hai.


2. **Statement 2 (Deny with Condition):**
* **Actions Denied:** `CreateFunction`, `DeleteFunction`, `InvokeFunction`, `TagResource`
* **Condition:** Agar request ka source IP **`187.5.104.11/32`** hoga, toh yeh actions **DENY** (block) ho jayenge.



---

### 2. IAM Evaluation Rule (The Golden Rule)

> **Explicit Deny Always Overrides Allow!**
> Agar ek policy mein kisi action ko `Allow` kiya gaya ho aur doosri jagah us par `Deny` ki condition lagayi jaye, toh **Deny hamesha jeet ta hai**.

```
Request Source IP = 187.5.104.11  ──► Matches Deny Condition ──► ❌ DENIED (Blocked)
Request Source IP = Any other IP  ──► Skips Deny Condition  ──► ✅ ALLOWED (by Statement 1)

```

---

### 3. Options Evaluation

* ❌ **Delete Lambda from any network address:** Galat hai, kyun ke IP `187.5.104.11` se delete nahi ho sakta.
* ❌ **Create Lambda using 187.5.104.11/32:** Galat hai, kyun ke `187.5.104.11` explicit DENY statement mein blocked hai.
* ❌ **Delete Lambda using 187.5.104.11/32:** Galat hai, again explicit DENY match ho raha hai.
* ✅ **Create an AWS Lambda function using the 100.220.0.11/32 address:** **Correct!** Kyun ke IP `100.220.0.11` Deny list (`187.5.104.11`) mein nahi hai, is liye Statement 1 isay **Allow** kar dega.

---

### Correct Option Explanation

#### ✅ **Create an AWS Lambda function using the 100.220.0.11/32 address.**

* **Why it works:** Source IP `100.220.0.11` Deny condition se match nahi hota, is liye Allow statement successfully implement hota hai.
