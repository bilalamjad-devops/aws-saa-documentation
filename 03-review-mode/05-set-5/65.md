65. Question

Category: CSAA – Design High-Performing Architectures

An application is hosted in an Auto Scaling group of EC2 instances. To improve the monitoring process, you have to configure the current capacity to increase or decrease based on a set of scaling adjustments. This should be done by specifying the scaling metrics and threshold values for the CloudWatch alarms that trigger the scaling process.

Which of the following is the most suitable type of scaling policy that you should use?

- Target tracking scaling
- `Step scaling`
- Simple scaling
- Scheduled Scaling

Is question ka correct answer **Step scaling** hai.

Aap ne Target Tracking socha tha, par Tension na lein! Yeh concept boht aasan hai. Aayein pehle farq samajhte hain taake exam mein dobara galti na ho.

---

### Step Scaling Kyun Sahi Hai? (Question Key Terms)

Question ke keywords ko ghor se dekhein:

> **"...increase or decrease based on a set of scaling adjustments."**
> **"...specifying scaling metrics and threshold values for CloudWatch alarms..."**

Jab bhi question mein **multiple thresholds** (alag alag limits) ya **set of adjustments (steps)** ki baat ho, toh wahan **Step Scaling** lagti hai.

#### Step Scaling Ka Simple Example:

Maan lein aap CPU Utilization par scaling kar rahe hain:

* **Step 1:** Agar CPU 50% se 70% ho $\rightarrow$ Add 1 EC2 instance.
* **Step 2:** Agar CPU 70% se 90% ho $\rightarrow$ Add 2 EC2 instances.
* **Step 3:** Agar CPU 90% se upar chala jaye $\rightarrow$ Add 4 EC2 instances.

Aap ne dekha? Yahan **scaling adjustment CPU ke level/threshold ke hisab se "steps" mein badal rahi hai**.

---

### Sabhi Scaling Policies Ka Simple Breakdown

Auto Scaling ki **4 main policies** hoti hain:

| Policy Type | Simple Meaning | Exam Keywords |
| --- | --- | --- |
| **1. Target Tracking Scaling** | Aap ek target value set karte hain (e.g., "CPU ko HAMESHA 50% rakho"). AWS khud hi instances add/remove karta rehta hai. | *"Maintain a specific target metric"*, *"Like a thermostat"*, *"Keep CPU at 50%"* |
| **2. Step Scaling** *(Correct Answer)* | Alag alag limits (thresholds) par alag alag steps ke mutabiq scale karna. | *"Set of scaling adjustments"*, *"Based on step ranges"*, *"Multiple thresholds"* |
| **3. Simple Scaling** | Ek hi CloudWatch Alarm par ek fixed action (e.g., CPU > 70% hua toh 1 instance barha do). Old/legacy policy. | *"Single CloudWatch alarm threshold"*, *"Wait for cooldown period"* |
| **4. Scheduled Scaling** | Time/Date ke mutabiq scale karna (e.g., Har Monday Subah 9 baje 10 instances kar do). | *"Predictable traffic patterns"*, *"Specific time/date"*, *"Office hours"* |

---

### Exam Rule for SAA-C03

> * **Target Tracking:** Jab single target fix rakhna ho (e.g., average CPU 50%).
> * **Step Scaling:** Jab response traffic ke intensity/size par depend kare (steps based on threshold ranges).
