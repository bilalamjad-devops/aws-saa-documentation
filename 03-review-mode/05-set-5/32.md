32. Question

Category: CSAA – Design Secure Architectures

A company has an On-Demand EC2 instance with an attached EBS volume. There is a scheduled job that creates a snapshot of this EBS volume every midnight at 12 AM when the instance is not used. One night, there has been a production incident where you need to perform a change on both the instance and on the EBS volume at the same time when the snapshot is currently taking place.

Which of the following scenario is true when it comes to the usage of an EBS volume while the snapshot is in progress?

- The EBS volume can be used in read-only mode while the snapshot is in progress.
- The EBS volume cannot be detached or attached to an EC2 instance until the snapshot completes
- The EBS volume cannot be used until the snapshot completes.
- `The EBS volume can be used while the snapshot is in progress.`

Is question ka correct answer **The EBS volume can be used while the snapshot is in progress.** hai.

Aayein EBS Snapshots ki working mechanics ko detail se samajhte hain:

---

### Key Scenario Breakdown

* **Situation:** Central midnight snapshot job chal raha hai aur snapshot creation background mein process ho rahi hai.
* **Incident:** Same time par aap ko EC2 instance aur us par attached EBS volume par system changes (read/write operations) karne ki zaroorat pad gayi hai.
* **Core Question:** Kya snapshot progressing status mein hotay hue EBS volume normal usage (read/write) ke liye available hota hai?

---

### Correct Option Explanation

#### ✅ **The EBS volume can be used while the snapshot is in progress.**

* **Why it works:**
1. **Point-in-Time Pointing:** Jab aap EBS snapshot initiate karte hain, AWS instant ek **Point-in-Time** image freeze kar leta hai.
2. **Asynchronous Background Copy:** Snapshots asynchronous hotay hain. AWS background mein data ko Amazon S3 mein copy karta rehta hai.
3. **No I/O Block:** Snapshot background mein chalne ke dauran aap ka EBS volume fully operational rehta hai—aap read aur write dono performance lagatar kar sakte hain bina kisi downtime ya read-only restriction ke. Any new writes after the snapshot start time will simply not be included in that snapshot.



---

### Incorrect Options Breakdown (Elimination)

* ❌ **Read-only mode:** Volume read-only nahi hota, aap regular **Write** operations bhi perform kar sakte hain.
* ❌ **Cannot be detached or attached:** Snapshot background mein create hotay hue bhi aap volume ko detach ya attach kar sakte hain (agarchay best practice yeh hai ke data consistency ke liye active writes state ko handle kar liya jaye).
* ❌ **Cannot be used until snapshot completes:** EBS snapshots non-blocking hotay hain, volume par ongoing applications stop nahi hotin.

---

### SAA-C03 Exam Rule

> **EBS Snapshot Availability:** EBS Snapshots **point-in-time** aur **asynchronous** hotay hain. Snapshot chalte hue volume par **Read aur Write Operations** normal speed se jari rehte hain bina kisi interruption ke.
