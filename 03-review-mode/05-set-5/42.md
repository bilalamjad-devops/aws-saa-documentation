42. Question

Category: CSAA – Design Resilient Architectures

A company plans to deploy a Docker-based batch application in AWS. The application will be used to process both mission-critical data and non-essential batch jobs.

Which of the following is the most cost-effective option to use in implementing this architecture?

- `Use Amazon ECS as the container management service, then set up a combination of Reserved and Spot Amazon EC2 Instances for processing mission-critical and non-essential batch jobs, respectively.`
- Use Amazon ECS as the container management service, then set up Spot Amazon EC2 Instances for processing both mission-critical and non-essential batch jobs.
- Use Amazon ECS as the container management service, then set up Reserved Amazon EC2 Instances for processing both mission-critical and non-essential batch jobs.
- Use Amazon ECS as the container management service, then set up On-Demand Amazon EC2 Instances for processing both mission-critical and non-essential batch jobs.

Is question ka correct answer **Use Amazon ECS as the container management service, then set up a combination of Reserved and Spot Amazon EC2 Instances for processing mission-critical and non-essential batch jobs, respectively.** hai.

Aayein point-to-point concept aur elimination ko samajhte hain:

---

### Key Scenario Breakdown

* **Workload Type:** Docker-based containerized batch application running on Amazon ECS.
* **Two Job Categories:**
1. **Mission-Critical Jobs:** Inko uninterrupted, guaranteed capacity chahiye taake job beech mein fail ya terminate na ho.
2. **Non-Essential Batch Jobs:** In mein delay ya interruption tolerate ho sakti hai, is liye maximum cost savings target karni hai.


* **Goal:** Sub se **cost-effective** compute strategy choose karna jo dono business requirements ko satisfy kare.

---

### Correct Option Explanation

#### ✅ **Reserved Instances (Mission-Critical) + Spot Instances (Non-Essential)**

* **Why it works:**
1. **For Mission-Critical Data:** **Reserved Instances (RIs)** 1 ya 3 saal ke commitment par upto 72% discount dete hain aur continuous, non-interruptible compute capacity guarantee karte hain. Mission-critical workloads ke liye Spot use karna risky hota hai kyunke Spot instances 2-minute warning ke sath terminate ho sakte hain.
2. **For Non-Essential Jobs:** **Spot Instances** up to 90% discount par milte hain On-Demand pricing ke muqable mein. Non-essential ya fault-tolerant batch jobs ke liye Spot instances perfect fit hain.
3. **Cost-Effectiveness:** Dono job types ko alag compute pricing models se match karke optimum cost savings achieve hoti hai bina mission-critical reliability compromise kiye.



---

### Incorrect Options Breakdown (Elimination)

* ❌ **Spot Instances for BOTH:** Mission-critical jobs ke liye Spot instance run karna dangerous hai kyunke agar AWS ko capacity wapas chahiye hui toh EC2 terminate ho jayega aur critical job fail ho sakti hai.
* ❌ **Reserved Instances for BOTH:** Non-essential jobs ke liye Reserved Instances use karne se unn jobs par unnecessary fixed long-term commitment cost lag jayegi jo Spot se ziada mehngi padegi.
* ❌ **On-Demand Instances for BOTH:** On-Demand full retail price par charge hota hai, jo sub se kam cost-effective option hai.

---

### Exam Rule for SAA-C03

> **Workload Pricing Matching Strategy:**
> * **Predictable / Continuous / Mission-Critical:** **Reserved Instances (RIs)** ya **Savings Plans**
> * **Fault-Tolerant / Interrupted-Safe / Batch / Non-Essential:** **Spot Instances**
> * **Short-term / Unpredictable / Testing:** **On-Demand Instances**
