38. Question

Category: CSAA – Design High-Performing Architectures

A company deployed a web application that stores static assets in an Amazon Simple Storage Service (S3) bucket. The Solutions Architect expects the S3 bucket to immediately receive over 2000 PUT requests and 3500 GET requests per second at peak hour.

What should the Solutions Architect do to ensure optimal performance?

- Add a random prefix to the key names.
- `Do nothing. Amazon S3 will automatically manage performance at this scale.`
- Use Byte-Range Fetches to retrieve multiple ranges of an object data per GET request.
- Use a predictable naming scheme in the key names such as sequential numbers or date time sequences.

Yeh bilkul valid point hai! AWS ke exam questions mein bohot dafa **"Distractor" (confusing/confusing elements)** jaan boojh kar daale jaate hain taake candidate ki in-depth knowledge test ki ja sake.

Aayein is question ke piche ka **AWS Exam Mindset** samajhte hain:

---

### Question Complicated Kyun Banaya Gaya?

1. **Specific Numbers Ka Jaal (2,000 PUTs & 3,500 GETs):**
* Question mein 2000 aur 3500 ke exact numbers diye gaye hain.
* Agar aap ko S3 ki exact limit (**3,500 PUTs** aur **5,500 GETs**) yaad nahi hogi, toh aap ghabra kar koi na koi manual optimization option (jaise *Random Prefix*) select kar lenge.


2. **Old Best Practice vs New S3 Architecture:**
* **Purana Time (Pre-2018):** Pehle AWS S3 mein jab high traffic aata tha, toh AWS mashwara deta tha ke S3 files ke naam ke aage **Random Hash/Prefix** lagayein (e.g., `s3://mybucket/a8f9-image.jpg`) taake load distribute ho.
* **Aaj Ka S3 (Post-2018):** AWS ne S3 ka architecture update kar diya. Ab S3 khud background mein load balance kar leta hai jab tak traffic 3,500 PUTs / 5,500 GETs per second se kam ho.


3. **Distractor Options:**
* AWS ne "Random Prefix" wali option jaan boojh kar di taake dekha ja sake ke candidate ko **purani outdated practice** yaad hai ya **modern S3 performance capability** pata hai.



---

### Simple Bottom Line

* **S3 Limit Per Prefix:**
* **PUTs:** 3,500 per second tak AWS S3 tension free handle karta hai.
* **GETs:** 5,500 per second tak AWS S3 tension free handle karta hai.


* **Question Traffic:**
* 2,000 PUTs (3,500 se kam hai ✅)
* 3,500 GETs (5,500 se kam hai ✅)



Kyunke traffic S3 ki default limits ke andar hai, is liye humein **kuch bhi karne ki zaroorat nahi ("Do nothing")**.
