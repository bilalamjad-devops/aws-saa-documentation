1. Question
A company has an enterprise web application hosted on Amazon ECS Docker containers that use an Amazon FSx for Lustre filesystem for its high-performance computing workloads. The application uses AWS X-Ray to trace requests across its containerized services. A warm standby environment is running in another AWS Region for disaster recovery.

A solutions architect was assigned to design a system that will automatically route the live traffic to the disaster recovery (DR) environment only in the event that the primary application stack experiences an outage.

What should the Architect do to satisfy this requirement?


Set up a failover routing policy configuration in Amazon Route 53 by adding a health check on the primary service endpoint. Configure Route 53 to direct the DNS queries to the secondary record when the primary resource is unhealthy. Configure the network access control list and the route table to allow Route 53 to send requests to the endpoints specified in the health checks. Enable the Evaluate Target Health option by setting it to Yes.

Set up a Weighted routing policy configuration in Amazon Route 53 by adding health checks on both the primary stack and the DR environment. Configure the network access control list and the route table to allow Route 53 to send requests to the endpoints specified in the health checks. Enable the Evaluate Target Health option by setting it to Yes.

Set up an ​Amazon EventBridge rule to monitor the primary Amazon Route 53 DNS endpoint and create a custom AWS Lambda function. Execute the ChangeResourceRecordSets API call using the function to initiate the failover to the secondary DNS record.

Set up an Amazon CloudWatch Alarm to monitor the primary Amazon Route 53 DNS endpoint and create a custom AWS Lambda function. Execute the ChangeResourceRecordSets API call using the function to initiate the failover to the secondary DNS record.
