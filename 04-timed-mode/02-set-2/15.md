15. Question

A company has two On-Demand EC2 instances inside the Virtual Private Cloud in the same Availability Zone but are deployed to different subnets. One EC2 instance is running a database and the other EC2 instance a web application that connects with the database. You need to ensure that these two instances can communicate with each other for the system to work properly.

What are the things you have to check so that these EC2 instances can communicate inside the VPC? (Select TWO.)

- `Check if all security groups are set to allow the application host to communicate to the database on the right port and protocol.`
- Check if both instances are the same instance class.
- Check if the default route is set to a NAT instance or Internet Gateway (IGW) for them to communicate.
- Ensure that the EC2 instances are in the same Placement Group.
- `Check the Network ACL if it allows communication between the two subnets.`

**Bilkul 100% theek kaha aap ne! 🎯** Aap ne bilkul core point pakad liya hai.

Security Groups aur NACLs dono ka kaam traffic ko allow ya block karna (security guard ki tarah) hai, lekin inka farq sirf **level** aur **nature** ka hai:

---

### 1. Security Groups (SG) - **Instance Level Guard** 🛡️

* **Kahan hota hai:** Yeh seedha EC2 Instance ke gird deewar ki tarah hota hai.
* **Kaam:** Agar koi request instance tak aa gayi, toh SG check karta hai ke kya yeh port (jaise MySQL ke liye 3306) allowed hai ya nahi.
* **Khasiyat:** Yeh **Stateful** hota hai. Matlab agar aap ne request bhejne ki permission de di, toh wapsi ka rasta (response) automatic khul jata hai, wapsi ke liye alag se rule likhne ki zaroorat nahi parti.

### 2. Network ACLs (NACL) - **Subnet Level Guard** 🚪

* **Kahan hota hai:** Yeh poore Subnet ke darwaze par pehra deta hai (yani subnet ke andar jitne bhi instances honge, sab par NACL ka rule pehle lagega).
* **Kaam:** Yeh dekhta hai ke is subnet ke andar ya bahar traffic aane dena hai ya nahi.
* **Khasiyat:** Yeh **Stateless** hota hai. Matlab agar aap ko traffic aane ki permission deni hai, toh **Inbound** rule bhi likhna parega, aur wapsi (response) ke liye **Outbound** rule bhi alag se likhna parega!

---

### Summary Table ⚡

| Feature | Security Group (SG) | Network ACL (NACL) |
| --- | --- | --- |
| **Level** | **Instance Level** (EC2 par lagta hai) | **Subnet Level** (Subnet ke darwaze par lagta hai) |
| **Stateful / Stateless** | **Stateful** (Automatic response allowed) | **Stateless** (Inbound aur Outbound dono rules khud likhne parte hain) |
| **Rule Type** | Sirf **Allow** rules hote hain (Deny rule nahi hota) | **Allow** aur **Deny** dono rules hote hain |

Isliye jab bhi ek subnet se doosre subnet mein instances ko baat karni ho, humein **Security Group** aur **NACL** dono check karne parte hain taake raste mein koi guard traffic na rok le!
