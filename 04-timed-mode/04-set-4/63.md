63. Question

A company launched a global news website that is deployed to AWS and is using MySQL RDS. The website has millions of viewers from all over the world, which means that the website has a read-heavy database workload. All database transactions must be ACID compliant to ensure data integrity.

In this scenario, which of the following is the best option to use to increase the read-throughput on the MySQL database?

- Enable Amazon RDS Standby Replicas
- Enable Multi-AZ deployments
- Use SQS to queue up the requests
- `Enable Amazon RDS Read Replicas`

### Sawal Kya Keh Raha Hai? ❓

* **Scenario:** Ek global news website hai jo **MySQL RDS** database use kar rahi hai. Website par dunya bhar se millions of viewers hain, jis ki wajah se database par **read-heavy workload** hai (yani log articles read kar rahe hain, writes kam aur reads bohot zyada hain). Data ki integrity ke liye **ACID compliance** lazmi hai.
* **Requirement:** MySQL database par **read-throughput (read capacity aur speed) ko barhane** ke liye sab se behtareen tareeqa konsa hai?

---

### Correct Answer Kya Keh Raha Hai? 💡

* **Enable Amazon RDS Read Replicas**

---

### Asan Alfaz Mein Wazahat (Explanation) 🔍

* **Amazon RDS Read Replicas:** Jab aap ki application mein read operations (data parhna) bohot zyada hon, toh primary database par load barh jata hai. Iska hal yeh hota hai ke aap **Read Replicas** enable kar dete hain. Primary database write (insert/update) handle karta hai, jabke read traffic multiple read replicas par distribute ho jata hai, jis se read-throughput zabardast tarike se barh jati hai.
* **Multi-AZ ya Standby Replicas kyun nahi?** Multi-AZ deployment sirf **High Availability (HA)** aur disaster recovery ke liye hota hai (agar main database kharab ho jaye toh standby active ho jata hai). Multi-AZ ka standby replica read traffic handle karne ke liye use nahi hota, is liye woh read-throughput nahi barha sakta.
