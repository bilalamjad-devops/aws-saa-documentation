52. Question

A company has a team of developers that provisions its own resources on the AWS cloud. The developers use IAM user access keys to automate resource provisioning and application testing processes in AWS. To ensure proper security compliance, the security team wants to automate the process of deactivating and deleting any IAM user access key that is over 90 days old.

Which solution will meet these requirements with the LEAST operational effort?

- Create an Amazon EventBridge rule to filter IAM user access keys older than 90 days. Schedule an AWS Batch job that runs every 24 hours to delete all the specified access keys.
- Create a custom AWS Config rule to check the max-age of IAM access keys. Use Amazon EventBridge Scheduler to invoke an AWS Batch job every 24 hours to delete all non-compliant access keys.
- `Use the AWS Config managed rule to check if the IAM user access keys are not rotated within 90 days. Create an Amazon EventBridge rule for the non-compliant keys, and define a target to invoke a custom AWS Lambda function to deactivate and delete the keys.`
- Create an Amazon EventBridge rule to filter IAM user access keys older than 90 days. Define a target to invoke an AWS Lambda function to deactivate and delete the old access keys.

### Sawal Kya Keh Raha Hai? ❓

* **Scenario:** Company chahti hai ke jo IAM user access keys **90 din se zyada purani** ho chuki hain, unhein automatically deactivate aur delete kar diya jaye.
* **Requirement:** Yeh automation implement karne ke liye **sab se kam operational effort (mehnat)** wala tareeqa konsa hoga?

---

### Correct Answer Kya Keh Raha Hai? 💡

* **Use the AWS Config managed rule to check if the IAM user access keys are not rotated within 90 days. Create an Amazon EventBridge rule for the non-compliant keys, and define a target to invoke a custom AWS Lambda function to deactivate and delete the keys.**

---

### Wajah aur Key Concepts 🔍

* **AWS Config Managed Rule (Least Operational Effort):** AWS ke paas pehle se built-in (managed) rules hote hain (jaise `access-keys-rotated`) jo khud track karte hain ke konsi key 90 din se purani ho chuki hai. Agar aap custom rule banane baithoge ya khud se filtering karoge, toh zyada mehnat (operational effort) lagegi. AWS Config ka built-in rule use karne se effort sab se kam ho jati hai.
* **EventBridge + Lambda Automation:**
1. Jab AWS Config ko pata chalta hai ke koi key 90 din se purani hai (non-compliant), toh **Amazon EventBridge** foran us state change ko detect kar leta hai.
2. EventBridge us event ko aik chote se **AWS Lambda function** ko bhejta hai, jo code ke zariye us purani access key ko deactivate aur delete kar deta hai.


* **Ghalat Options kyun hain?**
* EventBridge akela khud se access keys ki age calculate nahi kar sakta jab tak AWS Config jaisi tracking service ka sahara na ho.
* AWS Batch heavy batch-processing jobs ke liye hota hai, jabke security compliance events ke liye EventBridge aur Lambda ka serverless combination sab se behtareen aur asan hota hai.
