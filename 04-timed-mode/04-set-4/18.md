18. Question

A financial services organization is developing a cloud-native application on AWS to process and analyze customer transaction data. The application utilizes Amazon Aurora for the database, Amazon EFS for file storage, and Amazon EventBridge to trigger AWS Step Functions for workflow orchestration. The operations team also uses AWS Systems Manager OpsCenter to centrally track and investigate operational issues.

The organization requires centralized authentication and access management for its data science, engineering, and compliance teams. These teams need secure access to Aurora and Amazon while maintaining strict data privacy standards. The solution must adhere to the principle of least privilege and minimize administrative overhead.

Which approach best satisfies these requirements?

- `Enable the AWS IAM Identity Center with an Identity Center directory and create permission sets for granular access for Aurora and EFS. Assign teams to groups linked to specific permission sets based on their roles.`
- Set up AWS Control Tower to manage multi-account access. Use Service Control Policies (SCPs) to restrict access to Aurora and EFS at the organizational level. Create IAM roles in each account with specific permissions.
- Create separate AWS accounts for each team using AWS Organizations. Set up cross-account IAM roles with least privilege and assign specific Aurora and EFS permissions based on team roles.
- Use Amazon Cognito User Pools for authentication and use Cognito Identity Pools to provide temporary AWS credentials. Create fine-grained IAM roles for Aurora and EFS access in each team.

### Question Kya Keh Raha Hai? ❓

* **Scenario:** Ek financial organization AWS par cloud-native application bana rahi hai jisme Aurora, EFS, Step Functions, aur Systems Manager use ho rahe hain.
* **Requirement:** Alag-alag teams (data science, engineering, compliance) ke liye **centralized authentication aur access management** chahiye, taake woh secure tareeqey se Aurora aur EFS ko access kar sakein. Solution mein **principle of least privilege** follow hona chahiye aur **administrative overhead (mehnat/complexity) kam se kam** honi chahiye.

---

### Correct Answer Kya Keh Raha Hai? 💡

* **Enable the AWS IAM Identity Center with an Identity Center directory and create permission sets for granular access for Aurora and EFS. Assign teams to groups linked to specific permission sets based on their roles.**
* **Wajah (Reason):** **AWS IAM Identity Center** (jise pehle AWS SSO kehte thay) centralized user authentication aur multi-account access management ke liye standard aur best service hai. Isme hum **permission sets** aur user groups ke zariye asani se least privilege access de sakte hain bina har account mein alag-alag IAM roles banaye, jisse administrative overhead bohat kam ho jata hai. *(Note: Service Control Policies (SCPs) guardrails ke liye hoti hain, user/team authentication ya granular permissions ke liye nahi).*
