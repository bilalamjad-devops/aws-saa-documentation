59. Question

A company has a set of Linux servers running on multiple On-Demand Amazon EC2 instances powered by the EC2 Nitro System. The Audit team wants to collect and process the application log files generated from these servers for the report.

Which of the following is the most suitable solution to meet this requirement?

- `Amazon S3 for storing the application log files and Amazon Elastic MapReduce for processing the log files.`
- Amazon S3 Glacier for storing the application log files and Spot EC2 Instances for processing them.
- A single On-Demand EC2 instance for both storing and processing the log files
- Amazon S3 Glacier Deep Archive for storing the application log files and AWS ParallelCluster for processing the log files.

### Sawal Kya Keh Raha Hai? ❓

* **Scenario:** Company ke paas multiple On-Demand EC2 instances par Linux servers chal rahe hain.
* **Requirement:** Audit team chahti hai ke in servers se jo **application log files** generate ho rahi hain, unhein collect kiya jaye aur phir reports ke liye **process** kiya jaye.

---

### Correct Answer Kya Keh Raha Hai? 💡

* **Amazon S3 for storing the application log files and Amazon Elastic MapReduce for processing the log files.**

---

### Asan Alfaz Mein Wazahat (Explanation) 🔍

Is sawal ko hal karne ke liye do cheezein dekhni hain:

1. **Storage ke liye Amazon S3:**
* Log files ko safely, securely aur scale-able tarike se store karne ke liye **Amazon S3** sab se behtareen aur standard object storage hai.


2. **Processing ke liye Amazon EMR (Elastic MapReduce):**
* Jab bohot saare servers ke logs ikhtatta ho jayein aur unhein analyze ya process karna ho (Big Data processing), toh uske liye **Amazon EMR** use hota hai jo heavy log data ko fast aur efficiently process kar sakta hai.



---

### Baqi Options Ghalat Kyun Hain? ❌

* **S3 Glacier / Glacier Deep Archive:** Yeh long-term archival (bohot lambay arsay tak data safe rakhne) ke liye hote hain jahan data foran access nahi hota. Jab logs ko process karke report banani ho, toh Glacier suitable nahi hai.
* **Single On-Demand EC2 instance:** Jab multiple servers hain aur logs ka data bohot zyada hai, toh ek akela (single) EC2 instance load handle nahi kar payega aur bottleneck ban jayega.
