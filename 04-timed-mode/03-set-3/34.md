34. Question


A company needs to use Amazon Aurora as the Amazon RDS database engine for its web application. The Solutions Architect has been instructed to implement a 90-day RDS backup retention policy.

Which of the following options can satisfy the given requirement?

- Configure an automated backup and set the backup retention period to 90 days.
- Create a daily scheduled event using Amazon EventBridge and AWS Lambda to directly download the RDS automated snapshot to an Amazon S3 bucket. Archive snapshots older than 90 days to Glacier.
- `Create an AWS Backup plan to take daily snapshots with a retention period of 90 days.`
- Configure RDS to export the automated snapshot automatically to Amazon S3 and create a lifecycle policy to delete the object after 90 days.

### Keywords Scan 🔍

1. **"implement a 90-day RDS backup retention policy"**
* **Trigger:** AWS RDS automated backups ki native limit **35 days** hoti hai. 35 days se zyada retention period (maslan 90 days) ke liye centrally managed **AWS Backup** service use hoti hai.



---

### Correct Answer

**Create an AWS Backup plan to take daily snapshots with a retention period of 90 days.**

---

---

### Question Aur Answer Ka Breakdown 💡

#### Question Kya Keh Raha Hai? ❓

* Application ke **Amazon Aurora RDS** database ke liye **90 days (3 mahine)** ki backup retention policy set karni hai.
* Solutions Architect ko aisi option choose karni hai jo is 90-day retention constraint ko officially support karti ho.

#### Answer Kya Keh Raha Hai? 💡

* **AWS Native RDS Automated Backups Limit:** Amazon RDS / Aurora ke built-in automated backups ka **maximum retention period 35 days** hota hai. Aap built-in RDS console se 35 days se zyada set nahi kar sakte.
* **AWS Backup Service:** Agar aap ko 35 days se ziada (jaise **90 days**, 1 year, ya 7 years) tak backups maintain karne hon, toh AWS ka standard best-practice tool **AWS Backup** hai. Isme aap ek custom Backup Plan banate hain jo daily snapshots leta hai aur retention period ko exact **90 days** par manage karta hai.

---

### Baki Options Ghalt Kyun Hain? ❌

* **Set backup retention period to 90 days:** **False.** RDS automated backup console 35 days se zyada ki values reject kar deta hai.
* **EventBridge + Lambda directly download RDS automated snapshot:** **False.** RDS automated snapshots ko direct download nahi kiya ja sakta, aur yeh approach highly over-engineered aur invalid hai.
* **Export automated snapshot automatically to S3 with lifecycle policy:** Snapshot S3 export analytical/long-term raw data extraction ke liye best hai, lekin yeh automated native database recovery points maintain karne ke liye **AWS Backup** ka substitute nahi hai.

---

### RDS Retention Limits Cheat Sheet ⚡

| Backup Mechanism | Max Retention Limit | Best Use Case |
| --- | --- | --- |
| **RDS Native Automated Backup** | **35 Days** | Short-term point-in-time recovery (PITR) |
| **AWS Backup Service** | **Unlimited** (Customable 90 days, 1 year, etc.) | Long-term compliance & centralized enterprise backups |
| **Manual DB Snapshots** | **Indefinite** (Until manually deleted) | Pre-deployment or explicit point-in-time state locks |
