9. Question


An online registration system hosted in an Amazon EKS cluster stores data to a db.t4g.medium Amazon Aurora DB cluster. The database performs well during regular hours but is unable to handle the traffic surge that occurs during flash sales. A solutions architect must move the database to Aurora Serverless while minimizing downtime and the impact on the operation of the application.

Which change should be taken to meet the objective?

- Add an Aurora Replica to the cluster and set its instance class to Serverless. Failover to the read replica and promote it to primary.
- Change the Aurora Instance class to Serverless
- Take a snapshot of the DB cluster. Use the snapshot to create a new Aurora DB cluster.
- `Use AWS Database Migration Service (AWS DMS) to migrate to a new Aurora Serverless database.`

Koi baat nahi! Aayein isay bilkul aasan alfaz aur real-life misaal se samajhte hain ke question kya puch raha hai aur answer mein DMS kyun use ho raha hai. 💡

---

### 1. Question Kya Keh Raha Hai? (Problem Statement) ❓

* **Aap ka System:** Aap ki website **Amazon EKS** (Kubernetes) par chal rahi hai aur data save karne ke liye ek standard database (**Aurora Provisioned DB - `db.t4g.medium**`) use kar rahi hai.
* **Masla (Problem):** Jab achanak flash sale aati hai aur boht saare log website par aa jate hain, toh yeh standard database **traffic ka load nahi utha pata** aur slow ho jata hai ya crash ho jata hai.
* **Goal:** Aap ko apne database ko **Aurora Serverless** par shift karna hai (taake traffic barhne par database khud ba khud expand ho jaye), lekin yeh sab karte waqt **downtime (website band hone ka waqt) kam se kam** honi chahiye.

---

### 2. Answer Kya Keh Raha Hai? (Solution: AWS DMS) 💡

> **Use AWS Database Migration Service (AWS DMS) to migrate to a new Aurora Serverless database.**

Iska matlab yeh hai ke aap ek naya **Aurora Serverless** database side by side khada karte hain, aur **AWS DMS** ka tool use karte hain jo:

1. Purane database ka saara data copy kar ke naye Serverless database mein dal deta hai (**Full Load**).
2. Saath hi sath live chalte hue transactions ko bhi real-time mein purane DB se naye Serverless DB par bhejta rehta hai (**Change Data Capture / CDC**).
3. Jab sara data sync ho jata hai, aap apni application (EKS) ka rasta purane DB se hata kar naye Serverless DB par laga dete hain. Is se website band kiye baghair database upgrade ho jata hai!

---

### Real-Life Analogy 🛒🏦

Socho aap ka ek chota **Bank Counter (Provisioned DB)** hai jahan achanak eid ki shopping par boht lambi line lag jaye aur counter slow ho jaye.

* Aap decide karte hain ke hum ek naya **Auto-Expanding Digital Counter (Aurora Serverless)** banayenge.
* **AWS DMS** ek aisi team hai jo chupke se purane counter ka sara record naye digital counter par copy kar leti hai aur live chalne wale naye customers ko bhi sath sath update karti rehti hai.
* Jaise hi sara record sync ho jata hai, aap purana counter band kar dete hain aur sare log naye fast counter par shift ho jate hain—aur kisi ko pata bhi nahi chalta ke transition ho gayi!
