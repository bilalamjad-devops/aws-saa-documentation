32. Question


A firm has a containerized application that runs on a self-managed Kubernetes cluster. The cluster writes data in an on-premises MongoDB database. A solutions architect is requested to move the service to AWS in order to minimize operational overhead. The firm prohibits any changes to the code.

Which action meets these objectives?

- Migrate the cluster to an Amazon Elastic Kubernetes Service (EKS) cluster using Amazon EKS Anywhere and the database to an Amazon DynamoDB table.
- Migrate the cluster to an Amazon Elastic Container Service (ECS) cluster with the images stored in the Amazon Elastic Container Registry (Amazon ECR). Move the database to an Amazon Neptune database
- Migrate the cluster to an Amazon Elastic Container Service (ECS) cluster using Amazon ECS Anywhere and the database to an Amazon Aurora Serverless database.
- `Migrate the cluster to an Amazon Elastic Kubernetes Service (EKS) cluster and the database to an Amazon DocumentDB (with MongoDB compatibility) database.`


### Keywords Scan 🔍

1. **"self-managed Kubernetes cluster $\rightarrow$ move to AWS... minimize operational overhead"**
* **Trigger:** Managed Kubernetes in AWS $\rightarrow$ **Amazon EKS**.


2. **"on-premises MongoDB database"**
* **Trigger:** Fully managed MongoDB-compatible database in AWS $\rightarrow$ **Amazon DocumentDB** (with MongoDB compatibility).


3. **"prohibits any changes to the code"**
* **Trigger:** Code level changes allow nahi hain, isliye exact Kubernetes primitives (EKS) aur exact MongoDB drivers/API (DocumentDB) required hain.



---

### Correct Answer

**Migrate the cluster to an Amazon Elastic Kubernetes Service (EKS) cluster and the database to an Amazon DocumentDB (with MongoDB compatibility) database.**

---

### Question Aur Answer Ka Breakdown 💡

#### Question Kya Keh Raha Hai? ❓

* Ek company ka containerized app apne local **Kubernetes cluster** par chal raha hai aur database ke liye **MongoDB** use kar raha hai.
* Company isay AWS par shift karna chahti hai taake **management/operational overhead kam se kam ho**.
* **Strict Requirement:** **Code mein bilkul koi tabdeeli (change) nahi karni!**

#### Answer Kya Keh Raha Hai? 💡

* **Kubernetes $\rightarrow$ Amazon EKS:** Code aur YAML manifests change kiye bina Kubernetes workload direct AWS EKS par shift ho jata hai.
* **MongoDB $\rightarrow$ Amazon DocumentDB:** DocumentDB natively **MongoDB compatibility** provide karta hai. Iska matlab app ka code, drivers, aur queries bina badle DocumentDB ke sath perfectly kaam karenge!

---

### Baki Options Ghalt Kyun Hain? ❌

* **EKS Anywhere / DynamoDB:** **DynamoDB** ka API structure MongoDB se bilkul alag hai; is se application code badalna parhega (jo prohibited hai).
* **ECS + Neptune:** **ECS** par jaane ke liye deployment configs badalni hongi, aur **Neptune** ek Graph Database hai (MongoDB document database hai), isliye code change karna parhega.
* **ECS Anywhere + Aurora Serverless:** **Aurora** relational/SQL DB hai, jabke MongoDB NoSQL/Document DB hai. SQL queries ke liye app code rewrite karna parhega.

---

### EKS Anywhere Kya Hota Hai? (Amazon EKS Anywhere) 🌐

Aap ne puchha ke **EKS Anywhere** kya hai:

* **Concept:** EKS Anywhere AWS ka ek software tool hai jisse aap **EKS ko apne On-Premises (apne local data center) hardware par run kar sakte hain**.
* **Kyun Reject Hua?** Question mein explicitly likha hai ke app ko **AWS cloud par move karna hai**, local data center mein EKS Anywhere chala kar apne servers manage nahi karne.
