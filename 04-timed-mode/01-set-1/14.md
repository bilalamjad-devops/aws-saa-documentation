14. Question

An application consists of multiple Amazon EC2 instances in private subnets in different availability zones. The application uses a single NAT Gateway for downloading software patches from the Internet to the instances. There is a requirement to protect the application from a single point of failure when the NAT Gateway encounters a failure or if its availability zone goes down.

How should the Solutions Architect redesign the architecture to be more highly available and cost-effective?

- Create three NAT Gateways in each availability zone. Configure the route table in each private subnet to ensure that instances use the NAT Gateway in the same availability zone.
- Create a NAT Gateway in each availability zone. Configure the route table in each public subnet to ensure that instances use the NAT Gateway in the same availability zone.
- `Create a NAT Gateway in each availability zone. Configure the route table in each private subnet to ensure that instances use the NAT Gateway in the same availability zone`
- Create two NAT Gateways in each availability zone. Configure the route table in each public subnet to ensure that instances use the NAT Gateway in the same availability zone.

### Keywords Scan 🔍

1. **"single NAT Gateway ... protect from single point of failure if AZ goes down"**
* **Trigger:** Single NAT Gateway across multiple Availability Zones ek **Single Point of Failure (SPOF)** hota hai. High Availability (HA) ke liye har AZ mein ek dedicated NAT Gateway deploy karna hota hai.


2. **"cost-effective"**
* **Trigger:** Har AZ mein sirf **1 NAT Gateway** kaafi hota hai (multiple NAT Gateways per AZ unnecessary bill barhate hain).


3. **"Configure route table in each private subnet"**
* **Trigger:** Outbound internet traffic private subnets se originate hota hai, is liye route update **private subnet ki route table** mein hoga (na ke public subnet ki).



---

### Correct Answer

**Create a NAT Gateway in each availability zone. Configure the route table in each private subnet to ensure that instances use the NAT Gateway in the same availability zone**

---

### Roman Urdu Explanation 💡

* **Problem:** Jab ek hi NAT Gateway saare AZs ke private subnets serve kar raha hota hai, toh agar woh specific AZ down ho jaye, toh poore system ka internet access khatam ho jata hai.
* **Solution:** Har AZ ke public subnet mein **1 NAT Gateway** banayein. Phir har AZ ke **private subnet ki route table** mein `0.0.0.0/0` ko usi AZ ke local NAT Gateway par point karein. Is se continuous uptime bhi milta hai aur cross-AZ data transfer charges bhi bachte hain.

---

### Elimination Rules ❌

* **Three / Two NAT Gateways in *each* AZ:** Har AZ mein ek se zyada NAT Gateways lagana wasteful hai aur cost barha deta hai.
* **Configure route table in *public* subnet:** Traffic Private Subnet se outbound nikalta hai, is liye routes Private Subnet ki Route Table mein update hote hain.
