62. Question

A Docker application, which is running on an Amazon ECS cluster behind a load balancer, is heavily using Amazon DynamoDB. The application requires improved database performance by distributing the workload evenly and utilizing the provisioned throughput efficiently. Currently, the table’s write capacity units (WCU) are unevenly consumed due to key distribution.

Which of the following should be implemented for the DynamoDB table?

- `Use partition keys with high-cardinality attributes, which have a large number of distinct values for each item.`
- Avoid using a primary key that combines both a partition key and a sort key.
- Reduce the number of partition keys in the DynamoDB table.
- Use partition keys with low-cardinality attributes, which have a small number of distinct values for each item.

### Keywords Scan 🔍

1. **"write capacity units (WCU) are unevenly consumed due to key distribution"**
* **Trigger:** Hot Partition Issue (Jab saari write requests ek hi partition par gir rahi hon kyun ke partition key repetitive ya common values wali hai).


2. **"improved database performance by distributing workload evenly"**
* **Trigger:** **High-Cardinality Partition Keys** (Partition key aisi chunna jiski unique values boht zyada hon, taaki write requests saare partitions par barabar distribute/spread hon).



---

### Correct Answer

**Use partition keys with high-cardinality attributes, which have a large number of distinct values for each item.**

---

### Roman Urdu Explanation 💡

* **DynamoDB Partition Key Cardinality:**
* DynamoDB partitions ke andar data store karta hai.
* **High Cardinality** ka matlab hota hai aisi field jiski boht si **distinct/unique values** hon (jaise `User_ID`, `Order_ID`, ya `UUID`). Is se DynamoDB har item ko alag alag physical partitions par balance karke store karta hai (Uniform Distribution).
* **Low Cardinality** (jaise `Gender`, `Status: Active/Inactive`, ya `Country`) ki waja se **"Hot Partition"** problem ban jati hai, jahan ek hi partition par boht ziada traffic chala jata hai aur WCU throttle hona shuru ho jate hain.



---

### Elimination Rules ❌

* **Avoid using primary key with partition key and sort key:** Composite primary keys (Partition Key + Sort Key) performance kharab nahi karti balki data organizing aur fine-grained queries ke liye best practice hain.
* **Reduce the number of partition keys:** Partition keys reduce/kam karne se hot partition ka risk ulta barh jata hai kyun ke traffic mazeed kam keys par concentrate ho jaye ga.
* **Use partition keys with low-cardinality attributes:** Low cardinality (small number of distinct values) exact opposite hai—yeh hot partitions create karti hai aur performance ko severely degrade karti hai.
