15. Question

There was an incident in a production environment where user data stored in an Amazon S3 bucket was accidentally deleted by a Junior DevOps Engineer. The issue was escalated to management, and after a few days, an instruction was given to improve the security and protection of AWS resources.

What combination of the following options will protect the S3 objects in the bucket from both accidental deletion and overwriting? (Select TWO.)

- Enable S3 Intelligent-Tiering
- `Enable Multi-Factor Authentication Delete`
- Provide access to S3 data strictly through pre-signed URL only
- `Enable Versioning`
- Disallow S3 Delete using an IAM bucket policy

### Keywords Scan 🔍

1. **"protect ... S3 objects ... from overwriting"**
* **Trigger:** **Enable Versioning** (Versioning objects ke purane state ko preserve karta hai jab bhi koi file overwrite hoti hai ya delete request aati hai).


2. **"protect ... from accidental deletion"**
* **Trigger:** **Enable Multi-Factor Authentication (MFA) Delete** (MFA Delete require karta hai ke kisi object version ko permanently delete karne ya bucket ki versioning state badalne ke liye extra authentication code dia jaye).



---

### Correct Answers (Select TWO)

* **Enable Versioning**
* **Enable Multi-Factor Authentication Delete**

---

### Roman Urdu Explanation 💡

* **Versioning:** Jab Versioning enabled hoti hai aur koi junior engineer file delete karta hai, toh S3 file ko sach mein erase nahi karta balki ek **Delete Marker** laga deta hai. Aap purana version easily restore kar sakte hain. Overwrite hone par bhi pichla version mehfooz rehta hai.
* **MFA Delete:** Permanent deletion se bachne ke liye MFA Delete zaroori hai. Versioning ke hote hue bhi agar koi permanent deletion (DELETE ObjectVersion) karne ki koshish karega, toh S3 us se **hardware/virtual MFA token** se Code maange ga.

---

### Elimination Rules ❌

* **Enable S3 Intelligent-Tiering:** Yeh storage class access pattern ke hisab se cost optimize karti hai, deletion/overwriting se protect nahi karti.
* **Pre-signed URLs:** Yeh temporary access (upload/download) ke liye hote hain, lifecycle security ya deletion protection ke liye nahi.
* **Disallow S3 Delete using an IAM bucket policy:** Direct IAM policy se delete block karna standard object-level version protection nahi deta, aur yeh legitimate administrative cleanup workflows ko Tod deta hai bina versioning history maintain kiye.
