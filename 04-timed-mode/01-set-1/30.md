30. Question

A software development company is using serverless computing with AWS Lambda to build and run applications without having to set up or manage servers. The company has a Lambda function that connects to a MongoDB Atlas, which is a popular Database as a Service (DBaaS) platform, and also uses a third-party API to fetch certain data for its application. One of the developers was instructed to create the environment variables for the MongoDB database hostname, username, and password, as well as the API credentials that will be used by the Lambda function for DEV, SIT, UAT, and PROD environments.

Considering that the Lambda function is storing sensitive database and API credentials, how can this information be secured to prevent other developers on the team, or anyone, from seeing these credentials in plain text? Select the best option that provides maximum security.

- Enable SSL encryption that leverages on AWS CloudHSM to store and encrypt the sensitive information.
- Create a new AWS KMS key and use it to enable encryption helpers that leverage on AWS Key Management Service to store and encrypt the sensitive information.
- Lambda does not provide encryption for the environment variables. Deploy your code to an Amazon EC2 instance instead.
- There is no need to do anything because, by default, Lambda already encrypts the environment variables using the AWS Key Management Service.








Simple aur fast words mein samjho:

### Default behavior (Aam Tareeqa):

Lambda environment variables ko pehle se hi background mein encrypt karta hai, **LEKIN** jab koi developer AWS Console par ja kar Lambda function khole na, toh usko username/password **safal aur clear text** mein nazar aa jata hai.

### Masla (Problem):

Sawal ki requirement hai ke team ke **kisi bhi banday ko password plain text (khulla) nazar na aaye**.

### Hal (Solution):

Aap custom **KMS Key** bana kar **Encryption Helpers** (console par ek checkbox/tool) enable kar dete ho. Is se password console par bhi **cipher/secret code** ban jata hai aur chhup jata hai. Code chaltay waqt Lambda khud KMS se use decrypt kar leta hai.

---

### Quick Cheat Sheet 💡

* **Default Lambda Encryption:** Background mein safe hai, par **Console par text nazar aata hai**.
* **KMS Encryption Helpers:** **Console par bhi text chhup jata hai** (Maximum Security).


### Keywords Scan 🔍

1. **"storing sensitive database and API credentials ... environment variables"**
* **Trigger:** Lambda environment variables mein DB/API passwords store ho rahe hain.


2. **"prevent other developers ... from seeing these credentials in plain text ... maximum security"**
* **Trigger:** **AWS KMS Encryption Helpers** (Console par custom Customer Managed Key se Client-Side Encryption karna taaki plain-text value IAM console view par bhi mask ho jaye).



---

### Correct Answer

**Create a new AWS KMS key and use it to enable encryption helpers that leverage on AWS Key Management Service to store and encrypt the sensitive information.**

---

### Roman Urdu Explanation 💡

* **Default vs Helper Encryption:** Default par Lambda environment variables AWS KMS key se **Encryption at Rest** hotay hain, lekin console par developers ko values **plain text** dikhti hain.
* **Encryption Helpers:** Jab aap custom KMS Customer Managed Key (CMK) bana kar **Encryption Helpers** enable kartay hain, toh variables console par mask/encrypt rehtay hain. Code runtime par AWS SDK ke zariye KMS API call karke decrypt karta hai. Isse plain-text visibility fully block ho jati hai.

---

### Elimination Rules ❌

* **AWS CloudHSM:** Single Lambda environment variable ke liye over-engineered aur bohot expensive (~$1.50/hr) solution hai.
* **Deploy to Amazon EC2:** Lambda serverless execution abandon karke EC2 par jana unnecessary architecture modification hai.
* **By default KMS encryption is enough:** Default encryption sirf transit/rest par secure karti hai, Console UI par plain text view protect nahi karti (requirement fail ho jayegi).
