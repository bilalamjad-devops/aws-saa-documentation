18. Question

An online medical system hosted in AWS stores sensitive Personally Identifiable Information (PII) of the users in an Amazon S3 bucket. Both the master keys and the unencrypted data should never be sent to AWS to comply with the strict compliance and regulatory requirements of the company.

Which S3 encryption technique should the Architect use?

- Use S3 client-side encryption with an AWS KMS key.
- `Use S3 client-side encryption with a client-side master key.`
- Use S3 server-side encryption with an AWS KMS key.
- Use S3 server-side encryption with customer provided key.

### Keywords Scan 🔍

1. **"Both the master keys and the unencrypted data should never be sent to AWS"**
* **Trigger:** Master keys aur unencrypted data AWS ke paas jana hi nahi chahiye. Yeh strict constraint **Server-side encryption** (jahan AWS data decrypt/encrypt karta hai) aur **AWS KMS** (jahan keys AWS mein hoti hain) dono ko reject kar deta hai.


2. **"S3 encryption technique"**
* **Trigger:** Encryption hamesha client-side (AWS ke bahar, aapke apne environment mein) honi chahiye, jahan master key local client application ke paas rehti hai.



---

### Correct Answer

**Use S3 client-side encryption with a client-side master key.**

---

### Roman Urdu Explanation 💡

* **Client-Side Encryption with Client-Side Master Key:** Data S3 ko bhejney se **pehle** aapke apne local server/application par encrypt hota hai. Key bhi aapke apne paas hoti hai. S3 ke paas sirf pehle se encrypted data pohenchta hai. Is se na toh unencrypted data AWS ke paas jata hai aur na hi master key.
* **KMS / Server-Side (SSE):** SSE-S3, SSE-KMS, ya SSE-C mein data S3 buckets tak unencrypted jata hai aur S3 server par ja kar encrypt hota hai, jo is compliance rule ko break kar deta hai.

---

### Elimination Rules ❌

* **Client-side with AWS KMS key:** Keys AWS KMS ke paas jati/rehti hain, jo requirement ke khilaf hai.
* **Server-side with AWS KMS key (SSE-KMS):** Unencrypted data AWS par jata hai aur AWS KMS keys manage karta hai.
* **Server-side with customer provided key (SSE-C):** Data encrypt karne ke liye unencrypted data aur encryption key dono AWS S3 ko bhejne parte hain.
