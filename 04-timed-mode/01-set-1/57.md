57. Question

A company is using Amazon S3 to store frequently accessed data. When an object is created or deleted, the S3 bucket will send an event notification to the Amazon SQS queue. A solutions architect needs to create a solution that will notify the development and operations team about the created or deleted objects.

Which of the following would satisfy this requirement?

- Create an Amazon SNS topic and configure two SQS queues to subscribe to the topic. Grant S3 permission to send notifications to SNS and update the bucket to use the new SNS topic.
- Set up another SQS queue for the other team. Grant S3 permission to send a notification to the second SQS queue.
- Create a new Amazon SNS FIFO topic for the other team. Grant S3 permission to send the notification to the second SNS topic.
- Set up an Amazon SNS topic and configure two SQS queues to poll the SNS topic. Grant S3 permission to send notifications to SNS and update the bucket to use the new SNS topic.

### Keywords Scan 🔍

1. **"S3 bucket event notification ... notify multiple teams (Dev & Ops)"**
* **Trigger:** **Fan-out pattern** (Ek event notification ko multiple queues / endpoints par publish karna).


2. **"notify dev and ops team about created or deleted objects"**
* **Trigger:** **Amazon SNS Topic + Multiple SQS Queues Subscription** (S3 event notification SNS topic par bhejta hai, aur dono teams ki individual SQS queues us SNS topic ko subscribe karti hain).



---

### Correct Answer

**Create an Amazon SNS topic and configure two SQS queues to subscribe to the topic. Grant S3 permission to send notifications to SNS and update the bucket to use the new SNS topic.**

---

### Roman Urdu Explanation 💡

* **Fan-out Architectural Pattern (SNS to SQS):**
* S3 Bucket Events directly multiple SQS queues par same event send karne mein limitations rakhti hain (overlapping event rules nahi ban sakte).
* Iska standard solution **SNS Fan-out Pattern** hai:
1. S3 bucket event trigger hone par notification ek **Amazon SNS Topic** par bhejta hai.
2. Dev team ki SQS Queue aur Ops team ki SQS Queue, dono is **SNS Topic ke subscribers** bante hain.
3. SNS automatically event ko copy karke dono SQS queues mein simultaneously deliver kar deta hai (Fan-out).





```
[ Amazon S3 Event ] ──> [ Amazon SNS Topic ] ┬──> [ SQS Queue (Dev Team) ]
                                             └──> [ SQS Queue (Ops Team) ]

```

---

### Elimination Rules ❌

* **Set up another SQS queue directly:** S3 bucket policies/configurations mein overlapping prefixes/events ke liye multiple direct SQS queues attach karna error deta hai (Unsupported Notification Destination / Overlapping Configuration).
* **SNS FIFO topic for the other team:** S3 event notifications standard SNS topics use karte hain, aur FIFO mandatory nahi hai jab tak exact strict ordering requirement na ho.
* **SQS queues to poll the SNS topic:** SQS queues SNS topic ko **poll** nahi karti, balki SQS queues SNS topic ki **subscriber** hoti hain (SNS queue mein messages **push** karta hai).
