46. Question

A cryptocurrency trading platform is using an API built in AWS Lambda and API Gateway. Due to the recent news and rumors about the upcoming price surge of Bitcoin, Ethereum and other cryptocurrencies, it is expected that the trading platform would have a significant increase in site visitors and new users in the coming days ahead.

In this scenario, how can you protect the backend systems of the platform from traffic spikes?

- Use CloudFront in front of the API Gateway to act as a cache.
- Move the Lambda function in a VPC.
- `Enable throttling limits and result caching in API Gateway.`
- Switch from using AWS Lambda and API Gateway to a more scalable and highly available architecture using EC2 instances, ELB, and Auto Scaling.

### Keywords Scan 🔍

1. **"cryptocurrency trading platform ... API built in AWS Lambda and API Gateway"**
* **Trigger:** Serverless API backend.


2. **"protect the backend systems ... from traffic spikes"**
* **Trigger:** **Throttling limits** (API request rate limit set karke backend database/downstream systems ko overwhelm hone se bachana) and **API Gateway Result Caching** (repeated requests ko cache se serve karke backend load reduce karna).



---

### Correct Answer

**Enable throttling limits and result caching in API Gateway.**

---

### Roman Urdu Explanation 💡

* **Throttling Limits (Rate Limiting):**
* API Gateway par **Throttling** (Requests Per Second - RPS) set karke aap token bucket algorithm ke through backend resources (Lambda, Databases) ko crash ya overload hone se rokte hain. Jab rate limit exceed hoti hai, API Gateway `429 Too Many Requests` status code return karta hai.


* **API Gateway Stage Caching:**
* Repeated endpoint queries ko cache mein store kar leta hai. Jab visitors ki quantity achanak barhti hai, toh requests Lambda function tak jane ke bajaye API Gateway cache se hi reply ho jati hain, jis se cost bachti hai aur backend protect rehta hai.



---

### Elimination Rules ❌

* **Use CloudFront in front of API Gateway to act as a cache:** API Gateway ka apna built-in caching engine aur native throttling hota hai. Purely backend protection aur rate limiting ke liye API Gateway settings sab se direct aur standard hain.
* **Move the Lambda function in a VPC:** Lambda ko VPC mein daalne se latency aur network interfaces (ENIs) ki allocation barhti hai, traffic spikes se backend protect nahi hota.
* **Switch to EC2, ELB, and Auto Scaling:** Lambda aur API Gateway by default multi-AZ scalable hain. Inhe EC2 architecture se replace karna operational complexity, overhead aur cost barhayega.
