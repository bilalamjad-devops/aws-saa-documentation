59. Question

A startup is using Amazon RDS to store data from a web application. Most of the time, the application has low user activity but it receives bursts of traffic within seconds whenever there is a new product announcement. The Solutions Architect needs to create a solution that will allow users around the globe to access the data using an API.

What should the Solutions Architect do meet the above requirement?

- Create an API using Amazon API Gateway and use Amazon Elastic Beanstalk with Auto Scaling to handle the bursts of traffic in seconds.
- Create an API using Amazon API Gateway and use an Auto Scaling group of Amazon EC2 instances to handle the bursts of traffic in seconds.
- `Create an API using Amazon API Gateway and use AWS Lambda to handle the bursts of traffic in seconds.`
- Create an API using Amazon API Gateway and use the Amazon ECS cluster with Service Auto Scaling to handle the bursts of traffic in seconds.

### Keywords Scan 🔍

1. **"low user activity ... receives bursts of traffic WITHIN SECONDS"**
* **Trigger:** **AWS Lambda** (Serverless execution jo sub-second scaling handle karta hai. EC2 ya ECS scaling policies ko spin-up hone mein 1-3 minutes lagte hain, jabke Lambda sub-second scale karta hai).


2. **"access the data using an API ... users around the globe"**
* **Trigger:** **Amazon API Gateway + AWS Lambda** (Serverless REST/HTTP API architecture).



---

### Correct Answer

**Create an API using Amazon API Gateway and use AWS Lambda to handle the bursts of traffic in seconds.**

---

### Roman Urdu Explanation 💡

* **AWS Lambda (Sub-second Scaling):**
* Lambdas **serverless** hain. Normal waqt mein jab traffic zero ya low hota hai, aapko kuch pay nahi karna padta ($0$ idle cost).
* Jab sudden product announcement par **seconds mein traffic burst** aata hai, toh Lambda milliseconds ke andar thousands of concurrent executions tak scale kar jata hai.


* **EC2 / ECS / Beanstalk Auto Scaling (Delayed Scaling):**
* EC2 instances ya ECS tasks ko metric breach hone par launch hone aur initialization scripts run karne mein **1 se 3 minute** lag jate hain, jo "bursts within seconds" requirement ko fail kar deta hai.



---

### Elimination Rules ❌

* **Elastic Beanstalk / Auto Scaling EC2:** EC2 instances launch hone aur load balancer mein healthy hone mein kam se kam 1-2 minutes lagte hain. Sudden 2-second spikes ke waqt users ko timeouts aur 5xx errors milenge.
* **Amazon ECS with Service Auto Scaling:** Container tasks ki provisioning time bhi EC2/Fargate scaling limits ki waja se seconds ke burst load ke liye Lambda jitni fast nahi hoti.
