61. Question

An online cryptocurrency exchange platform is hosted in AWS, utilizing an Amazon ECS Cluster and Amazon RDS in a Multi-AZ Deployments configuration. The application heavily uses the RDS instance to process complex read and write database operations. To maintain reliability, availability, and performance, it is necessary to closely monitor how the different processes or threads on a DB instance use the CPU, including the percentage of CPU bandwidth and total memory consumed by each process.

Which of the following is the most suitable solution to monitor the database properly?

- `Enable Enhanced Monitoring in RDS.`
- Create a script that collects and publishes custom metrics to Amazon CloudWatch, which tracks the real-time CPU Utilization of the RDS instance, and then set up a custom CloudWatch dashboard to view the metrics.
- Check the CPU% and MEM% metrics which are readily available in the RDS console that shows the percentage of the CPU bandwidth and total memory consumed by each database process of your RDS instance.
- Use Amazon CloudWatch to monitor the CPU Utilization of your database.

### Keywords Scan 🔍

1. **"monitor how different processes or threads on a DB instance use the CPU"**
* **Trigger:** **RDS Enhanced Monitoring** (OS-level metrics jaise individual process/thread CPU, memory, aur OS process list monitor karne ke liye).


2. **"percentage of CPU bandwidth and total memory consumed by EACH process"**
* **Trigger:** Standard CloudWatch sirf Hypervisor level par overall DB instance CPU Utilization $0-100\%$ dikhata hai, jabke **Enhanced Monitoring** OS level par har single process/thread ka breakout dikhati hai.



---

### Correct Answer

**Enable Enhanced Monitoring in RDS.**

---

### Roman Urdu Explanation 💡

* **RDS Enhanced Monitoring vs. Standard CloudWatch:**
* **Standard CloudWatch Metrics:** Hypervisor layer se metrics collect karta hai. Yeh aapko overall instance ki health batata hai (e.g., total `CPUUtilization` is 80%), lekin yeh **nahi** bata sakta ke kaunsa specific database process ya thread CPU/Memory consume kar raha hai.
* **Enhanced Monitoring:** RDS DB Instance ke andar **OS Agent** ke zariye run hota hai. Yeh exact OS-level metrics collect karta hai, jismein real-time process list hoti hai ($CPU\%$, $MEM\%$, process ID, thread details) taaki aap dekh sakein ke kaunsi database query ya process system ko choke kar rahi hai.



---

### Elimination Rules ❌

* **Custom script to CloudWatch:** Unnecessary operational overhead. RDS mein Enhanced Monitoring built-in feature hai jo direct OS-level metrics metrics collector ke sath aata hai.
* **Readily available in RDS console:** Standard RDS console metrics mein individual process-level OS metrics default bina Enhanced Monitoring enable kiye nahi dikhte.
* **Use Amazon CloudWatch to monitor CPU Utilization:** Standard CloudWatch metrics sirf hypervisor-level overall CPU average dikhate hain, individual database processes/threads ki granular distribution nahi dikhate.
