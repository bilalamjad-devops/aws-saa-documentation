56. Question

A company is using a combination of Amazon API Gateway and AWS Lambda for the web services of an online web portal that is accessed by hundreds of thousands of clients each day. The company will be announcing a new revolutionary product, and it is expected that the web portal will receive a massive number of visitors from all around the globe.

How can the back-end systems and applications, beyond the subnet-level filtering of network ACLs, be protected from traffic spikes?

- Manually upgrade the Amazon EC2 instances being used by API Gateway
- `Use throttling limits in API Gateway`
- API Gateway will automatically scale and handle massive traffic spikes so you do not have to do anything.
- Configure API Gateway for Multi-AZ deployment and provision a read replica


### Keywords Scan 🔍

1. **"Amazon API Gateway and AWS Lambda ... massive number of visitors / traffic spikes"**
* **Trigger:** Backend resources (Lambda concurrent executions, downstream databases/APIs) ko crash hone se bachana.


2. **"protected from traffic spikes"**
* **Trigger:** **Throttling limits in API Gateway** (Requests Per Second - RPS aur Burst limits set karke excess traffic ko reject/throttle karna).



---

### Correct Answer

**Use throttling limits in API Gateway**

---

### Roman Urdu Explanation 💡

* **API Gateway Throttling:**
* By default, API Gateway standard steady-state rate limit aur burst limit follow karta hai (Token Bucket Algorithm par).
* Jab global traffic spike aati hai, toh agar aap throttling limits configure kar dete hain, toh API Gateway backend (Lambda/DBs) par load jane ke bajaye extra client requests ko drop kar ke `429 Too Many Requests` status code return karta hai. Is se aapka entire backend system crash hone se bach jata hai.



---

### Elimination Rules ❌

* **Manually upgrade Amazon EC2 instances being used by API Gateway:** API Gateway ek fully managed serverless service hai, isme user ko EC2 instances upgrade karne ki koi access ya zaroorat nahi hoti.
* **API Gateway will automatically scale ... do not have to do anything:** Halanke API Gateway auto-scale karta hai, lekin agar aap throttling limits set nahi karenge toh sudden spike aapke backend Lambda functions ki concurrency limits exhaust kar sakti hai aur downstream database/APIs crash ho jayenge.
* **Multi-AZ deployment and provision a read replica:** Yeh DB-level settings hain. API Gateway by default multi-AZ managed service hai, isme read replicas ka concept nahi hota.
