2. Question

A company has a highly available architecture consisting of an Elastic Load Balancer and multiple Amazon EC2 instances configured with Auto Scaling across three Availability Zones. The company needs to monitor EC2 instances based on a specific metric that is not readily available in Amazon CloudWatch.

Which of the following is a custom metric in CloudWatch that requires manual setup?


- CPU Utilization of an EC2 instance
- Network packets out of an EC2 instance
- `Memory Utilization of an EC2 instance`
- Disk Read activity of an EC2 instance

Aaiye is question ke **Keywords Scan** karke core concept pakadte hain:

---

### Step 1: Keywords Scan 🔍

1. **Core Problem:** `"monitor EC2 instances based on a specific metric that is not readily available in Amazon CloudWatch"`
* **Trigger:** AWS Hypervisor inherently OS ke andar ki state nahi dekh sakta, isliye woh metric default CloudWatch mein nahi milta.


2. **Requirement:** `"custom metric in CloudWatch that requires manual setup"`
* **Trigger:** OS-level metrics (jaise RAM/Memory usage aur Disk Space utilization) ke liye **CloudWatch Agent** install karke **custom metric** ke taur par bhejnah padta hai.



---

### Step 2: Correct Answer

**Memory Utilization of an EC2 instance**

---

### Step 3: Fast Elimination Rules ❌

* **CPU Utilization:** Hypervisor-level metric hai (Default CloudWatch).
* **Network packets out:** Hypervisor-level metric hai (Default CloudWatch).
* **Disk Read activity:** Hardware IOPS level metric hai (Default CloudWatch).

> **AWS Exam Rule:** Hypervisor host ke bahar se **CPU, Network, aur Disk I/O** ko monitor kar sakta hai, lekin OS ke andar ki **Memory (RAM) aur Disk Space Used/Free** ko dekhne ke liye hamesha **CloudWatch Agent (Custom Metric)** ki zaroorat hoti hai.
