41. Question

A company has a hybrid cloud architecture that connects its on-premises data center and cloud infrastructure in AWS. It requires a durable storage backup for its corporate documents stored on-premises and a local cache that provides low-latency access to recently accessed data to reduce data egress charges. The documents must be stored on and retrieved from AWS via the Server Message Block (SMB) protocol. These files must be immediately accessible within minutes for six months and archived for another decade to meet data compliance.

Which of the following is the best and most cost-effective approach to implement in this scenario?

- `Launch a new file gateway that connects to your on-premises data center using AWS Storage Gateway. Upload the documents to the file gateway and set up a lifecycle policy to move the data into Glacier for data archival.`
- Launch a new tape gateway that connects to your on-premises data center using AWS Storage Gateway. Upload the documents to the tape gateway and set up a lifecycle policy to move the data into Glacier for archival.
- Use AWS DataSync to transfer all files from the on-premises network directly to an Amazon S3 bucket, and set up a lifecycle policy to move the data into Glacier for archival.
- Establish a Direct Connect connection to integrate your on-premises network to your VPC. Upload the documents on Amazon EBS Volumes and use a lifecycle policy to automatically move the EBS snapshots to an Amazon S3 bucket, and then later to Glacier for archival.

### Keywords Scan 🔍

1. **"hybrid cloud ... local cache ... low-latency access ... SMB protocol"**
* **Trigger:** **AWS Storage Gateway - Amazon S3 File Gateway** (SMB/NFS support ke sath local caching aur S3 integration deta hai).


2. **"immediately accessible ... for six months and archived for another decade"**
* **Trigger:** **Amazon S3 + S3 Lifecycle Policy** (S3 Standard se S3 Glacier Flexible/Deep Archive mein long-term archival transition).



---

### Correct Answer

**Launch a new file gateway that connects to your on-premises data center using AWS Storage Gateway. Upload the documents to the file gateway and set up a lifecycle policy to move the data into Glacier for data archival.**

---

### Roman Urdu Explanation 💡

* **S3 File Gateway (SMB + Caching):**
* S3 File Gateway aap ke on-premises data center mein ek local virtual machine (VM) ki tarah deploy hota hai.
* Yeh **SMB/NFS file share** expose karta hai aur frequent files ko local disk par cache kar leta hai taaki low-latency access mile aur bandwidth / egress cost bache.
* Internal background mein yeh files ko direct Amazon S3 bucket mein synchronous sync/store kar deta hai.


* **S3 Lifecycle Policy (6 Months + 10 Years Archival):**
* Bucket par Lifecycle rule set hota hai: files 6 months tak active storage (S3 Standard/Standard-IA) mein rehti hain, aur us ke baad 10 saal tak cost-effective compliance ke liye **S3 Glacier / Glacier Deep Archive** mein shift ho jati hain.



---

### Elimination Rules ❌

* **Tape Gateway:** Virtual Tape Library (VTL) / iSCSI-based backup tape software ke liye hota hai, direct SMB network file shares ke liye nahi.
* **AWS DataSync:** Bulk one-time ya scheduled data transfer service hai; on-premises applications ko active local SMB cache or low-latency local storage file share provide nahi karti.
* **Direct Connect + EBS Snapshots to Glacier:** EBS volumes EC2 instances se attach hote hain, direct on-premises SMB file shares ya lifecycle transition through S3 Glacier directly offer nahi karte.
