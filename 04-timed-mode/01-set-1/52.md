52. Question

A company has recently migrated its microservices-based application to Amazon Elastic Kubernetes Service (Amazon EKS). As part of the migration, the company must ensure that all sensitive configuration data and credentials, such as database passwords and API keys, are stored securely and encrypted within the Amazon EKS cluster’s etcd key-value store.

What is the most suitable solution to meet the company’s requirements?

- Use AWS Secrets Manager with a new AWS KMS key to securely manage and store sensitive data within the EKS cluster's etcd key-value store.
- Use Amazon EKS default options and the Amazon Elastic Block Store (Amazon EBS) Container Storage Interface (CSI) driver as an add-on to securely store sensitive data within the Amazon EKS cluster.
- `Enable secret encryption with a new AWS KMS key on an existing Amazon EKS cluster to encrypt sensitive data stored in the EKS cluster's etcd key-value store.`
- Enable default Amazon EBS volume encryption for the account with a new AWS KMS key to ensure encryption of sensitive data within the Amazon EKS cluster.

### Keywords Scan 🔍

1. **"Amazon EKS ... stored securely and encrypted within the etcd key-value store"**
* **Trigger:** **EKS Envelope Encryption for Secrets / KMS Key integration** (EKS cluster control plane ke etcd database mein Kubernetes Secrets ko encrypt karna).


2. **"sensitive configuration data and credentials ... in existing/new Amazon EKS cluster"**
* **Trigger:** **Enable secret encryption in EKS with an AWS KMS Customer Managed Key (CMK)**.



---

### Correct Answer

**Enable secret encryption with a new AWS KMS key on an existing Amazon EKS cluster to encrypt sensitive data stored in the EKS cluster's etcd key-value store.**

---

### Roman Urdu Explanation 💡

* **EKS KMS Envelope Encryption for Kubernetes Secrets:**
* Amazon EKS control plane apna sara state aur Kubernetes Secrets `etcd` key-value database mein store karta hai.
* By default, etcd mein secrets base64-encoded hote hain (jo ke plain text ki tarah hai). Isko at-rest cryptographically encrypt karne ke liye EKS native **KMS Secret Encryption** feature offer karta hai.
* Jab aap ek naye AWS KMS Customer Master Key (CMK) ke sath Secret Encryption enable karte hain, toh EKS `etcd` mein write hone waale har Kubernetes Secret ko Envelope Encryption se encrypt kar deta hai.



---

### Elimination Rules ❌

* **Use AWS Secrets Manager with KMS key:** AWS Secrets Manager S3/EKS se alag ek standalone external secret storage service hai. Yeh direct EKS ke internal `etcd` key-value store ko encrypt nahi karti.
* **EBS CSI driver as an add-on:** EBS CSI driver persistent storage volumes ko Pods ke sath attach karne ke liye use hota hai, EKS control plane ke `etcd` store ke liye nahi.
* **Enable default Amazon EBS volume encryption:** EBS volume encryption worker node disks ko encrypt karti hai, EKS managed control plane ke internal `etcd` database ko nahi.
