64. Question

A company hosted a web application in an Auto Scaling group of EC2 instances. The IT manager is concerned about the over-provisioning of the resources that can cause higher operating costs. A Solutions Architect has been instructed to create a cost-effective solution without affecting the performance of the application.

Which dynamic scaling policy should be used to satisfy this requirement?

- `Use target tracking scaling.`
- Use scheduled scaling.
- Use simple scaling.
- Use suspend and resume scaling.

### Keywords Scan 🔍

1. **"over-provisioning ... higher operating costs ... dynamic scaling policy"**
* **Trigger:** **Target Tracking Scaling Policy** (Yeh automatic thermostat ki tarah kaam karta hai, exact target metric level maintain karta hai taaki resource over-provision na hon).


2. **"cost-effective solution without affecting performance"**
* **Trigger:** Target Tracking Auto Scaling (Resource load ke hisab se scale-out aur scale-in automatically handle karta hai).



---

### Correct Answer

**Use target tracking scaling.**

---

### Roman Urdu Explanation 💡

* **Target Tracking Scaling Policy:**
* Target tracking scaling policy bilkul ghar ke **AC ke thermostat** ki tarah hoti hai. Aap ek metric ki target value set kar dete hain (e.g., *Average CPU Utilization = 50%*).
* Auto Scaling continuous load monitor karta hai:
* Jab load barhta hai, toh target 50% maintain karne ke liye instances **add (scale-out)** kar deta hai.
* Jab load kam hota hai, toh over-provisioning aur extra cost se bachne ke liye khudi instances **remove (scale-in)** kar deta hai.


* AWS recommended best practice hai dynamic workload scaling ke liye kyun ke isme manual CloudWatch alarms configure karne ki zaroorat nahi hoti.



---

### Elimination Rules ❌

* **Scheduled scaling:** Scheduled scaling specific time/calendar events ke liye hoti hai (e.g., har Monday subah 9 baje scale karo). Variable/unpredictable dynamic traffic ke over-provisioning ko yeh prevent nahi kar sakti.
* **Simple scaling:** Simple scaling purana method hai jo single CloudWatch alarm par step-by-step scale karta hai. Yeh target tracking jitna smooth nahi hota aur scale-in throttling handling mein cost inefficiencies paida kar sakta hai.
* **Suspend and resume scaling:** Yeh Auto Scaling processes ko temporary pause/stop karne ke liye use hota hai (testing ya maintenance ke waqt), yeh koi active dynamic scaling policy nahi hai.
