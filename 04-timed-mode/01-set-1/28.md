28. Question

A tech company that you are working for has undertaken a Total Cost Of Ownership (TCO) analysis evaluating the use of Amazon S3 versus acquiring more storage hardware. The result was that all 1200 employees would be granted access to use Amazon S3 for the storage of their personal documents.

Which of the following will you need to consider so you can set up a solution that incorporates a single sign-on feature from your corporate AD or LDAP directory and also restricts access for each individual user to a designated user folder in an S3 bucket? (Select TWO.)

- `Set up a Federation proxy or an Identity provider, and use AWS Security Token Service to generate temporary tokens.`
- Set up a matching IAM user for each of the 1200 users in your corporate directory that needs access to a folder in the S3 bucket.
- `Configure an IAM role and an IAM Policy to access the bucket.`
- Map each individual user to a designated user folder in S3 using Amazon WorkDocs to access their personal documents.
- Use 3rd party Single Sign-On solutions such as Atlassian Crowd, OKTA, OneLogin and many others.

### Keywords Scan 🔍

1. **"single sign-on feature from corporate AD or LDAP ... 1200 employees"**
* **Trigger:** **Federation Proxy / Identity Provider (IdP)** ke zariye **AWS Security Token Service (STS)** se temporary credentials generate karna (1200 IAM users nahi banaye jaate).


2. **"restricts access for each individual user to a designated user folder in an S3 bucket"**
* **Trigger:** **IAM Role + Policy** (jisme `s3:prefix` / `${aws:username}` policy variables hotay hain jo user ko sirf unke apne private folder tak restricted rakhte hain).



---

### Correct Answers (Select TWO)

* **Set up a Federation proxy or an Identity provider, and use AWS Security Token Service to generate temporary tokens.**
* **Configure an IAM role and an IAM Policy to access the bucket.**

---

### Roman Urdu Explanation 💡

* **STS + Identity Federation:** Corporate AD/LDAP users ko AWS login dene ke liye STS se temporary security tokens liye jaate hain, taaki IAM mein 1200 alag accounts na banane padain.
* **IAM Role & Dynamic Policy:** Single IAM Role ke sath dynamic policy (jaise `arn:aws:s3:::mybucket/${aws:username}/*`) attach ki jaati hai, jisse har user automated tarike se sirf apne hi specific S3 folder ko access kar pata hai.

---

### Elimination Rules ❌

* **Set up a matching IAM user for 1200 users:** Operational overhead bohot high hoga aur corporate Active Directory federation design principle ke khilaf hai.
* **Amazon WorkDocs:** Document collaboration tool hai, raw Amazon S3 bucket direct folder-level permissions manage karne ka architectural solution nahi.
* **3rd party SSO options (Atlassian, OKTA, etc.):** AWS native federation capability (STS/IAM Roles) mojood hai, overall AWS-centric architecture mein baseline answer 3rd-party vendor locking nahi hota.
