14. Question

A healthcare company manages patient data using a distributed system. The organization utilizes a microservice-based serverless application to handle various aspects of patient care. Data has to be retrieved and written from multiple Amazon DynamoDB tables.

The primary goal is to enable efficient retrieval and writing of data without impacting the baseline performance of the application as well as ensuring seamless access to patient information for healthcare professionals.

Which of the following is the MOST operationally efficient solution?

- `Utilize AWS AppSync pipeline resolvers`
- Use CloudFront functions
- Launched AWS Lambda functions with an edge-optimized Amazon API Gateway
- Set up DynamoDB connector for Amazon Athena Federated Query


### Sawal Kya Keh Raha Hai? ❓

* **Scenario:** Ek healthcare company ek distributed, microservice-based serverless application chala rahi hai jisme patient data ko handle karne ke liye multiple **Amazon DynamoDB tables** se data read aur write karna parta hai.
* **Requirement:** Ek aisi **operationally efficient** solution chahiye jo multiple tables se efficiently data retrieve aur write kar sake bina application ki baseline performance ko mutasir kiye, aur healthcare professionals ko seamless access de sake.

---

### Correct Answer Kya Keh Raha Hai? 💡

* **Utilize AWS AppSync pipeline resolvers**

---

### Asan Alfaz Mein Wazahat (Explanation) 🔍

* **AWS AppSync Pipeline Resolvers:** Jab aap ko ek hi GraphQL API request ke zariye multiple data sources ya multiple DynamoDB tables se data fetch ya write karna ho, toh **AppSync Pipeline Resolvers** sab se behtareen aur operationally efficient tareeqa hain.
* Pipeline resolvers aap ko alag-alag functions (steps) execute karne ki ijazat dete hain—misal ke tor par, pehle table se patient profile nikalna aur doosre table se medical records fetch karna—yeh sab ek hi organized pipeline mein baghair kisi zyadah custom code ya Lambda orchestration ke ho jata hai. Is se operational overhead bohot kam ho jata hai.

---

### Baqi Options Ghalat Kyun Hain? ❌

* **Lambda functions with an API Gateway:** Isme aap ko multiple tables ke liye khud custom orchestration code likhna parega, jo operational overhead barha deta hai.
* **Amazon Athena Federated Query:** Athena **analytics aur reporting** ke liye hota hai, na ke real-time operational microservice application ke low-latency reads/writes ke liye.
* **CloudFront Functions:** CloudFront functions sirf lightweight HTTP header manipulation ya URL redirects ke liye edge par chalte hain; inka database ya data retrieval se koi taluq nahi hai.

### AWS AppSync Kya Hai? 🚀

**AWS AppSync** ek fully managed **GraphQL service** hai jo aap ki applications (jaise mobile apps, web apps, ya microservices) ko data sources (jaise DynamoDB, Lambda, ya SQL databases) ke sath asani se connect karti hai.

Asan alfaz mein, agar aap ko apni application ke liye ek aisi API chahiye jo bohot fast ho, real-time data sync kare, aur multiple jagahon se data ek hi request mein utha kar la sake, toh **AppSync** use hota hai.

---

### AppSync Ki Main Features 💡

1. **GraphQL API Power:**
* Traditional REST APIs mein agar aap ko alag-alag data chahiye ho toh multiple endpoints call karne parte hain. GraphQL mein client sirf wahi data mangwata hai jo use chahiye, ek hi request mein.


2. **Multiple Data Sources Connectivity:**
* AppSync seedha **Amazon DynamoDB, Aurora, OpenSearch, ya AWS Lambda** ke sath connect ho sakta hai bina kisi complex backend server ke.


3. **Pipeline Resolvers (Jo pichle sawal mein use hue):**
* Agar aap ko ek hi request ke andar multiple steps chalane hon—jaise pehle DynamoDB table A se data nikalna, phir table B mein write karna—toh AppSync ke pipeline resolvers yeh sara kaam baghair kisi extra code ke asani se kar dete hain.


4. **Real-time & Offline Support:**
* Yeh WebSockets use karta hai jis se real-time updates (jaise chat apps ya live tracking) milti hain, aur client offline hone par bhi data store karke baad mein sync kar sakta hai.
