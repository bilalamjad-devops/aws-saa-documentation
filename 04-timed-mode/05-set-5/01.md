1. Question

A company has several microservices that send messages to an Amazon SQS queue and a backend application that poll the queue to process the messages. The company also has a Service Level Agreement (SLA) which defines the acceptable amount of time that can elapse from the point when the messages are received until a response is sent. The backend operations are I/O-intensive as the number of messages is constantly growing, causing the company to miss its SLA. The Solutions Architect must implement a new architecture that improves the application’s processing time and load management.

Which of the following is the MOST effective solution that can satisfy the given requirement?

- Create an AMI of the backend application's EC2 instance and launch it to a cluster placement group.
- Create an AMI of the backend application’s EC2 instance. Use the image to set up an Auto Scaling group and configure a target tracking scaling policy based on the CPUUtilization metric with a target value of 80%.
- `Create an AMI of the backend application’s EC2 instance. Use the image to set up an Auto Scaling group and configure a target tracking scaling policy based on the ApproximateAgeOfOldestMessage metric.`
- Create an AMI of the backend application's EC2 instance and replace it with a larger instance size.


### 1. Sawal Kya Keh Raha Hai? ❓

* **Scenario:** Company ki microservices ek **Amazon SQS queue** mein messages bhejti hain, aur ek backend application us queue ko poll karke messages process karti hai.
* **Masla:** Backend operations **I/O-intensive** hain (yani CPU busy nahi hota lekin messages queue mein jama ho rahe hain), jis ki wajah se company apna **SLA (Service Level Agreement)** miss kar rahi hai (messages time par process nahi ho pa rahe).
* **Requirement:** Application ki processing speed aur load management ko improve karne ke liye sab se behtareen tareeqa konsa hai?

---

### 2. Correct Answer Kya Keh Raha Hai? 💡

* **Create an AMI of the backend application’s EC2 instance. Use the image to set up an Auto Scaling group and configure a target tracking scaling policy based on the `ApproximateAgeOfOldestMessage` metric.**
* **Wazahat:** Kyunke workload I/O-intensive hai, isliye CPU usage low rehti hai (is liye CPU-based scaling kaam nahi karegi). SQS queue ke liye sab se best metric **`ApproximateAgeOfOldestMessage`** hai, jo yeh dekhta hai ke queue mein sab se purana message kitni der se para hai. Jaise hi message purana hone lage, ASG automatically naye servers (instances) launch kar deta hai taake backlog khatam ho jaye.

---

### 3. What is SLA? (Service Level Agreement) 📋

* **SLA** ka matlab **Service Level Agreement** hota hai.
* Yeh ek formal agreement ya commitment hoti hai (company aur customer ya internal teams ke darmiyan) ke kisi bhi service ko kis standard ya waqt ke andar perform kiya jayega.
* **Misal ke tor par:** Is sawal mein SLA ka matlab yeh tha ke message milne ke baad aik fix time limit (jaise kuch seconds ya milliseconds) ke andar response bhejna lazmi hai. Agar us waqt ke andar response na jaye, toh SLA breach (miss) ho jata hai.
