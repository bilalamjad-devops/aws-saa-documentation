3. Question

In a startup company you are working for, you are asked to design a web application that requires a NoSQL database that has no limit on the storage size for a given table. The startup is still new in the market and it has very limited human resources who can take care of the database infrastructure.

Which is the most suitable service that you can implement that provides a fully managed, scalable and highly available NoSQL service?

- Amazon Neptune
- SimpleDB
- `DynamoDB`
- Amazon Aurora

### Sawal Kya Keh Raha Hai? ❓

* **Scenario:** Aap ek startup ke liye web application design kar rahe hain jise ek **NoSQL database** ki zaroorat hai.
* **Requirements & Constraints:**
1. Table ke storage size par **koi limit na ho** (unlimited storage scaling).
2. Startup naya hai aur unke paas database management ke liye **bohot kam human resources** (maintenance team/staff) hain.
3. Solution **fully managed, scalable, aur highly available** NoSQL database hona chahiye.



---

### Correct Answer Kya Keh Raha Hai? 💡

* **DynamoDB**

---

### Asan Alfaz Mein Wazahat (Explanation) 🔍

* **Amazon DynamoDB:** Yeh AWS ki fully managed **NoSQL database** service hai.
* **No Storage Limit:** DynamoDB tables automatically scale hoti hain aur in par storage size ki **koi limit nahi hoti**.
* **Zero Operational Overhead (Fully Managed):** Isme aap ko koi hardware provisioning, setup, configuration, replication, ya patching karne ki zaroorat nahi hoti. Is liye choti teams ya startups ke liye yeh perfect hai.
* **High Availability & Speed:** Built-in multi-AZ replication aur single-digit millisecond latency milti hai.



---

### Baqi Options Ghalat Kyun Hain? ❌

* **Amazon Aurora:** Yeh **Relational (SQL)** database hai, NoSQL nahi.
* **Amazon Neptune:** Yeh **Graph database** service hai, general-purpose NoSQL key-value/document store nahi.
* **SimpleDB:** Yeh AWS ki bohot purani aur legacy service hai jisme strict limits (jaise 10 GB per domain) hoti hain, is liye yeh scale nahi kar sakti.
