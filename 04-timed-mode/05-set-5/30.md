30. Question

A healthcare company stores sensitive patient health records in their on-premises storage systems. These records must be kept indefinitely and protected from any type of modifications once they are stored. Compliance regulations mandate that the records must have granular access control and each data access must be audited at all levels. Currently, there are millions of obsolete records that are not accessed by their web application, and their on-premises storage is quickly running out of space. The Solutions Architect must design a solution to immediately move existing records to AWS and support the ever-growing number of new health records.

Which of the following is the most suitable solution that the Solutions Architect should implement to meet the above requirements?

- `Set up AWS DataSync to move the existing health records from the on-premises network to the AWS Cloud. Launch a new Amazon S3 bucket to store existing and new records. Enable AWS CloudTrail with Data Events and Amazon S3 Object Lock in the bucket.`
- Set up AWS Storage Gateway to move the existing health records from the on-premises network to the AWS Cloud. Launch a new Amazon S3 bucket to store existing and new records. Enable AWS CloudTrail with Management Events and Amazon S3 Object Lock in the bucket.
- Set up AWS DataSync to move the existing health records from the on-premises network to the AWS Cloud. Launch a new Amazon S3 bucket to store existing and new records. Enable AWS CloudTrail with Management Events and Amazon S3 Object Lock in the bucket.
- Set up AWS Storage Gateway to move the existing health records from the on-premises network to the AWS Cloud. Launch an Amazon EBS-backed EC2 instance to store both the existing and new records. Enable Amazon S3 server access logging and S3 Object Lock in the bucket.

### 1. Sawal Kya Keh Raha Hai? ❓

* **Scenario:** Ek healthcare company ke paas on-premises storage systems par sensitive patient health records hain. On-prem storage ki jagah khatam ho rahi hai aur millions of *obsolete (purane) records* hain jo web application use nahi karti.
* **Requirements:**
1. In existing records ko **foran AWS par move karna hai** (migration).
2. Records ko indefinitely rakhna hai aur unhein modify hone se bachana hai (**WORM compliance / Object Lock**).
3. Granular access control hona chahiye aur **har data access ki auditing** honi chahiye (at all levels).



---

### 2. Correct Answer Kya Keh Raha Hai? 💡

* **Set up AWS DataSync to move the existing health records from the on-premises network to the AWS Cloud. Launch a new Amazon S3 bucket to store existing and new records. Enable AWS CloudTrail with Data Events and Amazon S3 Object Lock in the bucket.**

---

### Asan Alfaz Mein Wazahat (Explanation) 🔍

* **AWS DataSync:** Kyunke on-premises storage khatam ho rahi thi aur millions of obsolete records ko *foran* AWS par shift karna tha, iske liye **AWS DataSync** sab se fast aur secure online data transfer/migration service hai. (Storage Gateway tab use hota hai jab data on-prem rakhte hue hybrid access chahiye ho, lekin yahan data ko poori tarah move karna tha).
* **Amazon S3 Object Lock:** Iska maqsad records ko **Write Once, Read Many (WORM)** protection dena hai taake koi bhi unhein delete ya modify na kar sakay.
* **CloudTrail Data Events:** Sawal mein pucha gaya hai ke **"each data access must be audited at all levels"**. CloudTrail ke andar **Management Events** sirf bucket creation ya settings change (control plane) ko track karte hain, jabki individual objects par hone wali data access (jaise `GetObject` ya `PutObject`) ko track karne ke liye **Data Events** enable karne parte hain.

---

### Baqi Options Ghalat Kyun Hain? ❌

* Jo options **AWS Storage Gateway** use karti hain, woh isliye ghalat hain kyunki gateway hybrid access ke liye hota hai jab aap ko data on-prem rakna ho, jabke yahan data ko completely migrate karke space khali karni thi.
* Jo options **CloudTrail with Management Events** kehti hain, woh ghalat hain kyunki object-level data access ko audit karne ke liye Management events nahi balkay **Data Events** zaroori hote hain.
