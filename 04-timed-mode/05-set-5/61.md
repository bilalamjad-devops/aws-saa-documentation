61. Question

A company is using AWS IAM to manage access to AWS services. The Solutions Architect of the company created the following IAM policy for AWS Lambda:

```saa
{
"Version": "2012-10-17",
"Statement": [
{
"Effect": "Allow",
"Action": [
"lambda:CreateFunction",
"lambda:DeleteFunction"
],
"Resource": "*"
},
{
"Effect": "Deny",
"Action": [
"lambda:CreateFunction",
"lambda:DeleteFunction",
"lambda:InvokeFunction",
"lambda:TagResource"
],
"Resource": "*",
"Condition": {
"IpAddress": {
"aws:SourceIp": "187.5.104.11/32"
}
}
}
]
}
```


Which of the following options is allowed by this policy?


- `Create an AWS Lambda function using the 100.220.0.11/32 address.`
- Delete an AWS Lambda function using the 187.5.104.11/32 address.
- Create an AWS Lambda function using the 187.5.104.11/32 address.
- Delete an AWS Lambda function from any network address.

Koi baat nahi, isay bilkul aasan aur saday alfaz mein samajhte hain! 💡

IAM policy mein asal mein **do rules** chal rahe hain:

1. **Allow Rule (Ijazat):** Policy kehta hai ke koi bhi user Lambda function bana ya mita sakta hai.
2. **Deny Rule (Sakht Mana):** Policy kehta hai ke agar IP address **`187.5.104.11`** hua, toh **kisi bhi halat mein ijazat nahi milegi** (AWS mein "Deny" ka matlab pakka "No" hota hai, yeh Allow ko bhi override kar deta hai).

### Sahi Jawab Kyun Theek Hai? ✅

* Jiss option mein IP address **`100.220.0.11`** use ho raha hai, woh **`187.5.104.11` nahi hai**.
* Is ka matlab yeh hua ke us par **Deny rule apply nahi hota**. Aur jab Deny rule nahi laga, toh pehla **Allow rule** chal gaya, aur function successfully create ho gaya!
