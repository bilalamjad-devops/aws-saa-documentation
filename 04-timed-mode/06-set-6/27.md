27. Question

A disaster recovery team is planning to back up on-premises records to a local file server share through SMB protocol. To meet the company’s business continuity plan, the team must ensure that a copy of data from 48 hours ago is available for immediate access. Accessing older records with delay is tolerable.

Which should the DR team implement to meet the objective with the LEAST amount of configuration effort?

- `Use an AWS Storage File gateway with enough storage to keep data from the last 48 hours. Send the backups to an SMB share mounted as a local disk.`
- Create an AWS Backup plan to copy data backups to a local SMB share every 48 hours.
- Create an SMB file share in Amazon FSx for Windows File Server that has enough storage to store all backups. Access the file share from on-premises.
- Mount an Amazon EFS file system on the on-premises client and copy all backups to an NFS share.


### 1. Sawal Kya Keh Raha Hai? (Question Breakdown) ❓

* **Scenario:** On-premises local file server par SMB protocol ke zariye disaster recovery backups lene hain.
* **Requirements:**
1. **Data Availability:** Pura 48 ghante (2 days) purana data **immediate access** ke liye available hona chahiye.
2. **Older Records:** 48 hours se zyada purane data ko access karne mein halka-fulka delay (lag) chalta hai.
3. **Protocol:** Local file server SMB protocol ke zariye connect hona chahiye.
4. **Least Effort:** Solution implement karne mein minimum configuration lagni chahiye.



---

### 2. Sahi Jawab Kya Keh Raha Hai? (Correct Answer) 💡

* **Option:** *Use an AWS Storage File gateway with enough storage to keep data from the last 48 hours. Send the backups to an SMB share mounted as a local disk.*
* **Wazahat:**
* **AWS Storage Gateway (File Gateway / S3 File Gateway)** on-premises environment mein local caching (cache disk) provide karti hai.
* Agar hum local cache storage 48 hours ke data jitni allocate kar dein, toh pichle 48 ghante ka data **local cache mein immediate low-latency access** ke saath maujood rahega.
* 48 hours se purana data automatically AWS S3 cloud storage mein asynchronous sync ho jata hai, jahan se usay zarurat parne par download kiya ja sakta hai (jis mein thora delay tolerable hai).

### 3. Keyword Scanning Cheat Sheet 🔑

| Question Keyword / Phrase | Direct Exam Mapping | Logic / Wajah |
| --- | --- | --- |
| **"On-premises" + "SMB protocol" + "Immediate access for last X hours"** | **AWS Storage File Gateway (with local cache)** | Storage Gateway local cache storage use karti hai jisse recent data locally immediate milta hai aur older data S3 mein sync rehta hai. |
| **"Amazon FSx for Windows File Server" (Trap Option)** | **Direct Cloud Share** | Direct FSx over VPN/DirectConnect use karne se local 48-hour immediate caching ka benefit nahi milta aur network latency aati hai. |
| **"Amazon EFS" (Trap Option)** | **NFS protocol, not SMB** | EFS Linux/NFS based hai, SMB support nahi karta on-premises Windows shares ke liye. |
