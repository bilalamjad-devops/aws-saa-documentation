30. Question

A game development company operates several virtual reality (VR) and augmented reality (AR) games that use various RESTful web APIs hosted in its on-premises data center, which currently sits behind a content delivery network (CDN) for faster global delivery. Due to the unprecedented growth of the company, the management decided to migrate its system to AWS Cloud to scale out its resources as well as to minimize costs.

Which of the following is the most cost-effective and scalable solution to meet the above requirement?

- `Use AWS Lambda and Amazon API Gateway.`
- Host the APIs in a static Amazon S3 web hosting bucket behind a Amazon CloudFront web distribution.
- Set up a micro-service architecture with Amazon ECS, Amazon ECR, and AWS Fargate.
- Use a Spot Fleet of Amazon EC2 instances, each with an Elastic Fabric Adapter (EFA) for more consistent latency and higher network throughput. Set up an Application Load Balancer to distribute traffic to the instances.

### 1. Sawal Kya Keh Raha Hai? (Question Breakdown) ❓

* **Scenario:** Ek game development company ke paas VR aur AR games ke liye **RESTful web APIs** hain jo abhi on-premises data center mein chal rahi hain aur global delivery ke liye CDN ke peechay hain. Company abhi **AWS Cloud par migrate** karna chahti hai taake resources easily scale ho sakein aur **cost minimum** rahe.
* **Requirements:**
1. **RESTful web APIs** ko host karna hai.
2. **Most cost-effective** aur **scalable** solution hona chahiye.
3. Unprecedented growth ko handle karne ke liye serverless ya auto-scaling architecture best ho.



---

### 2. Sahi Jawab Kya Keh Raha Hai? (Correct Answer) 💡

* **Option:** *Use AWS Lambda and Amazon API Gateway.*
* **Wazahat:**
* **AWS Lambda + API Gateway** serverless architecture banata hai. Iska sab se bara faida yeh hai ke **"Pay-as-you-go"** model par kaam karta hai—agar koi request nahi aa rahi, toh koi paisa nahi dena parega (minimal cost).
* Serverless hone ki wajah se yeh automatically scale ho jata hai (chahe hazaron users achanak aa jayein), aur koi underlying EC2 server manage karne ki zaroorat nahi parti (lowest operational overhead & management cost).



*Kyunki baqi options ghalat ya mehngay hain:*

* *ECS/ECR/Fargate:* Microservices ke liye achha hai lekin containers 24/7 chalte hain ya Fargate tasks maintain karne parte hain, jo lambda ki tarah pure pay-per-request / scale-to-zero nahi hote.
* *EC2 Spot Fleet + EFA:* EFA (Elastic Fabric Adapter) High Performance Computing (HPC) ya machine learning/MPI workloads ke liye hota hai, standard REST APIs ke liye nahi.
