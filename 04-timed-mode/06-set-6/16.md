16. Question

A Solutions Architect is working for a weather station in Asia with a weather monitoring system that needs to be migrated to AWS. Since the monitoring system requires a low network latency and high network throughput, the Architect decided to launch the EC2 instances to a new cluster placement group. The system was working fine for a couple of weeks, however, when they try to add new instances to the placement group that already has running EC2 instances, they receive an ‘insufficient capacity error’.

How will the Architect fix this issue?

- Submit a capacity increase request to AWS as you are initially limited to only 12 instances per Placement Group.
- Verify all running instances are of the same size and type and then try the launch again.
- Create another Placement Group and launch the new instances in the new group.
- `Stop and restart the instances in the Placement Group and then try the launch again.`

Aap ka guess **100% sahi** hai! Simple words mein **Cluster Placement Group = Ek single physical rack (ya closely connected racks)** jahan aap ke EC2 instances aik doosre ke bilkul aamne-saamne rakhe hote hain.

---

### Key Technical Concepts 💡

1. **Physical Layout:**
* AWS ke data center ke andar EC2 instances physical hardware racks par hote hain. Cluster placement group ka matlab hai ke AWS aap ke sary instances ko **ek hi Availability Zone (AZ) ke andar ek hi physical rack/cluster** par pack kar deta hai.


2. **Fayda (Why use it?):**
* **Lowest Latency & Highest Speed:** Kyunke instances physical hardware ke level par ek doosre ke bohat qareeb hote hain, unke beech network speed 10 Gbps se 100 Gbps+ tak milti hai aur network delay (latency) na hone ke barabar hota hai.
* **Use Case:** High-Performance Computing (HPC), Big Data analytics, aur weather modeling.


3. **Khas Limitation (The Catch):**
* **Single Hardware Dependency:** Agar us specific physical rack mein jagah khatam ho jaye, toh naye instances add karte waqt **"Insufficient capacity error"** aata hai.
* Isko fix karne ke liye hum poore group ke instances ko **Stop aur Restart** karte hain taake AWS poore group ko utha kar kisi bare physical rack par move kar de.



---

### Placement Groups Quick Comparison 📊

| Type | Key Purpose | Physical Layout |
| --- | --- | --- |
| **Cluster** | High Throughput / Low Latency | Single rack in **1 AZ** |
| **Spread** | High Availability / Isolation | Each instance on a **different rack** |
| **Partition** | Scale-out Workloads (Hadoop/Kafka) | Divided into partitions across racks |

### 1. Stop aur Restart karne se asal mein kya hota hai? 🔄

Jab aap instances ko **Stop** karte hain, toh AWS unhein us purane physical hardware rack se **release (free)** kar deta hai jahan woh pehle se locked thay.

Jab aap unhein dubara **Start** karte hain (sath hi naye instances ko bhi launch karte hain), toh AWS background mein ek **naya aur bara physical rack** talash karta hai jahan aap ke *purane aur naye saare instances* aik sath fit aa sakein. Is tarah naye instances ke liye jagah ban jati hai aur error khatam ho jata hai.

---

### 2. Option mein "Cluster" kyon nahi likha? 📝

Aap ki observation bilkul theek hai!
Sawal ke shuru mein hi **"cluster placement group"** bata diya jata hai. Is liye options mein baar baar "cluster" repeat karne ki bajaye sirf *"in the Placement Group"* likh diya jata hai.

Lekin aap ko yeh yaad rakhna hai ke yeh specific rule (**Stop and Restart karne wala fix**) sirf aur sirf **Cluster Placement Group** ke liye hi hota hai, kyunki wahi par saare instances ek hi physical rack par pack hote hain aur jagah khatam hone ka issue aata hai.
