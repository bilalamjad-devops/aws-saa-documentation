29. Question

An application is loading hundreds of JSON documents into an Amazon S3 bucket every hour which is registered in AWS Lake Formation as a data catalog. The Data Analytics team uses Amazon Athena to run analyses on these data, but due to the volume, most queries take a long time to complete.

What change should be made to improve the query performance while ensuring data security?


- Compress the data into GZIP format before storing it in the S3 bucket. Apply an IAM policy with aws:SourceArn and aws:SourceAccount global condition context keys in Lake Formation that prevents cross-service confused deputy problems and other security issues.
- `Transform the JSON data into Apache Parquet format. Ensure that the user has an lakeformation:GetDataAccess IAM permission for underlying data access control.`
- Convert the JSON documents into CSV format. Provide fine-grained named resource access control to specific databases or tables in AWS Lake Formation.
- Apply minification on the data and implement the Lake Formation tag-based access control (LF-TBAC) authorization strategy to ensure security.

### 1. Sawal Kya Keh Raha Hai? (Question Breakdown) ❓

* **Scenario:** Ek application har ghante saikron JSON documents Amazon S3 bucket mein dal rahi hai, jo AWS Lake Formation data catalog ke sath registered hain. Data Analytics team **Amazon Athena** use kar ke in par queries chalati hai, lekin data ka volume itna zyada hai ke **queries chalne mein bohot waqt (slow performance)** le rahi hain.
* **Requirements:**
1. **Query Performance improve** karni hai (Athena par queries fast honi chahiye).
2. **Data Security** bhi maintain karni hai (Lake Formation ke zariye proper access control).



---

### 2. Sahi Jawab Kya Keh Raha Hai? (Correct Answer) 💡

* **Option:** *Transform the JSON data into Apache Parquet format. Ensure that the user has an lakeformation:GetDataAccess IAM permission for underlying data access control.*
* **Wazahat:**
* **JSON vs. Apache Parquet:** JSON ek row-based format hai, is liye jab Athena query chalata hai toh usay poora file scan karna parta hai jo slow hota hai. Is ke bar-aks **Apache Parquet** ek columnar storage format hai jo analytics ke liye optimized hota hai. Parquet mein sirf wohi columns scan hote hain jo query mein maange jayein, jis se speed kai guna barh jati hai aur cost bhi kam hoti hai.
* **Lake Formation Security:** AWS Lake Formation ke through Athena queries chalane ke liye user ke paas `lakeformation:GetDataAccess` permission honi lazmi hai taake secure tareeqay se underlying data access kiya ja sake.



*Kyunki baqi options ghalat hain:*

* *GZIP / CSV:* GZIP compression help karti hai lekin JSON ko columnar format (Parquet/ORC) mein convert karna Athena ke liye sab se behtareen solution hai. CSV bhi row-based hai aur JSON jaisi hi limitations rakhti hai.
