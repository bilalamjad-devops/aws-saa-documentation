3. Question

A software development company has hundreds of Amazon EC2 instances with multiple Application Load Balancers (ALBs) across multiple AWS Regions. The public applications hosted in their EC2 instances are accessed on their on-premises network. The company needs to reduce the number of IP addresses that it needs to regularly whitelist on the corporate firewall device.

Which of the following approach can be used to fulfill this requirement?

- Launch a Network Load Balancer with an associated Elastic IP address. Set the ALBs in multiple Regions as targets.
- Use AWS Global Accelerator and create multiple endpoints for all the available AWS Regions. Associate all the private IP addresses of the EC2 instances to the corresponding endpoints.
- `Use AWS Global Accelerator and create an endpoint group for each AWS Region. Associate the Application Load Balancer from each region to the corresponding endpoint group.`
- Create a new Lambda function that tracks the changes in the IP addresses of all ALBs across multiple AWS Regions. Schedule the function to run and update the corporate firewall every hour using Amazon CloudWatch Events.

### Sawal Kya Keh Raha Hai? ❓

* **Scenario:** Ek company ke paas bohot saari EC2 instances aur multiple ALBs (Application Load Balancers) hain jo **multiple AWS regions** mein phailay hue hain. On-premises network ke employees in applications ko access karte hain.
* **Requirement:** Corporate firewall par bar bar change hone wale aur bohot saare IP addresses ko **whitelist karna mushkil ho raha hai**, is liye aik aisa solution chahiye jo in IP addresses ki tadad ko kam (reduce) kar ke fix/static kar de.

---

### Correct Answer Kya Keh Raha Hai? 💡

* **Use AWS Global Accelerator and create an endpoint group for each AWS Region. Associate the Application Load Balancer from each region to the corresponding endpoint group.**

---

### Asan Alfaz Mein Wazahat (Explanation) 🔍

* **AWS Global Accelerator:**
* Jab aap multiple regions mein applications chalate hain, toh har region ke ALBs ke apne public IPs hote hain jo badaltay rehte hain ya bohot saare hote hain.
* **AWS Global Accelerator** aap ko **do static Anycast IP addresses** deta hai.
* Aap in static IPs ko corporate firewall par sirf ek baar whitelist kar dete hain. Jab koi traffic aati hai, Global Accelerator usay AWS ke apne private, fast global network ke zariye sahi region aur ALB tak safely pohchwa deta hai. Is se firewall par bar bar IPs change karne ya bohot saare IPs whitelist karne ki zaroorat nahi rehti!



---

### Baqi Options Ghalat Kyun Hain? ❌

* **Lambda script / CloudWatch Events:** Har ghante script chala kar firewall update karna aik manual, complex, aur error-prone tareeqa hai jabke AWS ki bani-banai native service (**Global Accelerator**) mojood hai.
* **NLB with Elastic IP targeting multiple regions:** Ek single Network Load Balancer (NLB) cross-region ALBs ko asani se direct target nahi kar sakta, aur yeh Global Accelerator jitna effective multi-region routing solution nahi hai.
