62. Question

A global medical research company has a molecular imaging system that provides each client with frequently updated images of what is happening inside the human body at the molecular and cellular levels. The system is hosted in AWS and the images are hosted in an S3 bucket behind a CloudFront web distribution. When a fresh batch of images is uploaded to S3, it is required to keep the previous ones in order to prevent them from being overwritten.

Which of the following is the most suitable solution to solve this issue?

- `Use versioned objects`
- Add Cache-Control no-cache, no-store, or private directives in the S3 bucket
- Add a separate cache behavior path for the content and configure a custom object caching with a Minimum TTL of 0
- Invalidate the files in your CloudFront web distribution

### 1. Sawal Kya Keh Raha Hai? (Question Breakdown) ❓

* **Scenario:** Ek medical research company ke paas molecular imaging system hai jo Amazon S3 bucket mein images host karta hai aur front-end par Amazon CloudFront Web Distribution lagi hui hai.
* **Problem / Requirement:** Jab bhi naya image batch upload ho, purani images ko overwrite hone se bachana hai aur unka **previous history / state keep (preserve)** karni hai.
* **Goal:** Aisa tareeqa dhundna hai jo S3 bucket mein pehle se majood files ko overwriting se bachaye.

---

### 2. Sahi Jawab Kya Keh Raha Hai? (Correct Answer) 💡

* **Option:** *Use versioned objects*
* **Wazahat:**
* **S3 Versioning:** S3 bucket par Versioning enable karne se agar same name ki file dobara upload ki jaye, toh purani file delete ya overwrite nahi hoti. System automatically us file ka aik naya version (with a unique Version ID) create kar deta hai aur purane versions ko safe rakhta hai.
* Yeh exact requirement ko fulfill karta hai: *"keep the previous ones in order to prevent them from being overwritten."*



*Kyunki baqi options ghalat hain:*

* *Cache-Control directives / Custom TTL / Invalidate CloudFront files:* Yeh sab **CloudFront caching mechanisms** se taalluq rakhte hain (ke edge locations par files kitni der save rahengi ya update hongi). Unka S3 bucket ke andar actual files ko overwrite hone se rokne ya versions preserve karne se koi relation nahi hai.
