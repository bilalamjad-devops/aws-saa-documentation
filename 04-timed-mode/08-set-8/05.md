5. Question

A company manages an on-premises Server Message Block (SMB) file server, which is used to store large files. These files are typically accessed within the first 10 days after they are created. After this period, the files will no longer be accessed. However, the company requires that they remain accessible with a maximum retrieval time of 12 hours.

Which solution will meet these requirements?

- Set up an AWS DataSync task to transfer data that is older than 10 days from the SMB file server to AWS.
- Configure user access to Amazon S3. Create an S3 Lifecycle policy to transition the data to S3 Glacier Flexible Retrieval after 10 days.
- Set up an Amazon FSx File Gateway. Configure an Amazon S3 Lifecycle policy to transition the data to S3 Glacier Deep Archive after 10 days.
- `Set up an Amazon S3 File Gateway. Configure an S3 Lifecycle policy to transition the data to S3 Glacier Deep Archive after 10 days.`

Yeh raha aapka agla behtareen MCQ! Chaliye is question ko aasan lafzon mein samajhte hain ke yeh kya pooch raha hai aur iska sahi jawab kya hai.

---

### 🧠 Question kya keh raha hai? (Scenario Breakdown)

1. **On-Premises Setup:** Company ke paas ek on-premises **SMB file server** hai jo baray files store karne ke liye use hota hai.
2. **Access Pattern:** Files banne ke pehle **10 dino** tak frequent access hoti hain. Uske baad woh files mazeed access nahi hotiin.
3. **Requirement:** Files ko delete nahi karna, balkay woh accessible rehni chahiyein aur unki **maximum retrieval time (nikalne ki limit) 12 ghante (hours)** tak ho sakti hai.

---

### 🔍 Options ka Tajziya (Analysis):

* **SMB Protocol & AWS Integration:** Kyunki company on-premises **SMB file server** use kar rahi hai aur users local SMB shares ke adi hain, isliye AWS ke sath connect karne ke liye **Amazon S3 File Gateway** sab se behtareen choice hai jo SMB protocol ko support karta hai.
* **Storage Tier & Retrieval Time:**
* Aisi files jo 10 din baad access nahi hotin aur unke liye **12 hours** tak ka retrieval time acceptable ho, unke liye sab se sasti aur cost-effective storage class **Amazon S3 Glacier Deep Archive** hai. S3 Glacier Deep Archive ki standard retrieval time "within 12 hours" hoti hai, jo requirement ko perfectly match karti hai.


* **Options Comparison:**
* **Option 1 (DataSync):** Yeh sirf data transfer karta hai, automatic lifecycle ya SMB file share integration ke liye native file gateway approach nahi hai.
* **Option 2 (Direct S3 + Flexible Retrieval):** Users direct S3 access nahi kar rahe balkay on-premises SMB file server use kar rahe hain, aur Flexible Retrieval ka standard time 3-5 hours hota hai (jabke Deep Archive 12 hours ki requirement ke sath sab se zyada cost-effective hai).
* **Option 3 (FSx File Gateway):** "Amazon FSx File Gateway" is context mein theek nahi hai kyunki standard SMB file server backup/tiering ke liye S3 File Gateway use hota hai.
* **Option 4 (S3 File Gateway + Glacier Deep Archive):** Yeh on-premises SMB file server ko S3 se connect karta hai, aur S3 Lifecycle policy ke zariat 10 din baad data ko S3 Glacier Deep Archive mein move kar deta hai, jo 12 hours ke retrieval time aur cost optimization ki requirement ko poora karta hai.



---

### ✅ Correct Answer:

* **Set up an Amazon S3 File Gateway. Configure an S3 Lifecycle policy to transition the data to S3 Glacier Deep Archive after 10 days.**
