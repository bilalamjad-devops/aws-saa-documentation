24. Question

A consumer goods company runs its website, handling online orders from customers, and supporting microservices on an Amazon Elastic Kubernetes Service (Amazon EKS) cluster.

A solution is required to route requests to the hosted services based on URL paths.

Which option will meet this requirement with the LEAST amount of setup?

- Provision a Network Load Balancer (NLB) using the AWS Load Balancer Controller.
- `Provision an Application Load Balancer (ALB) using the AWS Load Balancer Controller.`
- Provision a NGINX Ingress controller.
- Use an AWS Lambda function to proxy requests to EKS.

### 🧠 Question Kya Keh Raha Hai? (Scenario Breakdown)

1. **Setup:** Company apni website aur microservices ko **Amazon EKS (Elastic Kubernetes Service)** cluster par run kar rahi hai.
2. **Core Requirement:** Incoming HTTP/HTTPS requests ko **URL paths** ke mutabiq alag-alag microservices par route karna hai (jaise `/cart` ek service par jaye aur `/checkout` doosri service par).
3. **Main Constraint:** **LEAST amount of setup** (kam se kam configuration aur management overhead).

---

### 🔍 Keyword Scanning (Sawal se Sahi Jawab Tak)

* **Keywords in Question:** `"route requests based on URL paths"`, `"Amazon EKS cluster"`, `"LEAST amount of setup"`.
* **Matching AWS Feature:**
* **Path-based routing on Layer 7:** 👉 **Application Load Balancer (ALB)**.
* **AWS Native Integration for Kubernetes:** 👉 **AWS Load Balancer Controller** automatically EKS Ingress resources ko AWS ALB ke sath map kar deta hai, jisse manual load balancer setup ki zaroorat nahi parti aur least setup requirement poori hoti hai.



---

### ❌ Baaqi Options Kyun Galat Hain?

* **Network Load Balancer (NLB):** NLB Layer 4 (TCP/UDP) par kaam karta hai. Yeh IP addresses aur ports par traffic route karta hai, **URL paths** (Layer 7 routing) ko directly inspect ya route nahi kar sakta. URL path routing ke liye NLB ke aage alag se proxy lagana parta hai jo setup ko lamba kar deta hai.
* **NGINX Ingress Controller:** NGINX Ingress ko EKS cluster ke andar deploy, configure, aur manually maintain karna parta hai, jo AWS native ALB ke muqabale mein zyada setup aur management overhead rakhta hai.
* **AWS Lambda to proxy requests:** Lambda function ko API Gateway ya Function URLs ke zariye EKS ke aage proxy banana custom code aur extra latency add karta hai, jo microservices architecture ke liye inefficient hai.

---

### ✅ Correct Answer:

* **Provision an Application Load Balancer (ALB) using the AWS Load Balancer Controller.**

---

**Summary:** The AWS Load Balancer Controller natively provisions and manages an Application Load Balancer (ALB) from EKS Ingress resources, delivering built-in Layer 7 path-based routing with minimal operational overhead.
