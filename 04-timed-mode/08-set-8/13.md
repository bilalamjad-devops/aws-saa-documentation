13. Question

A company operates a three-tier application with all its components hosted on AWS, except for the data layer. This data layer consists of a MySQL-compatible database located on-premises, connected to AWS through a Site-to-Site VPN. The database’s memory consumption ranges from 2 to 16 GiB.

On the other hand, the application experiences unpredictable traffic patterns, including spikes and periods of zero activity, which translates to irregular load on the database. The company wants to replace the on-premises database with a managed service that can automatically adapt to varying demands through serverless capacity scaling.

Which option will meet these requirements?

- `Configure an Amazon Aurora Serverless v2 database with a minimum capacity of 1 and a maximum of 8 Aurora capacity units (ACUs).`
- Set up an Amazon RDS for the MySQL database with 4 gigabytes of memory.
- Set up an Amazon Aurora database with a memory-optimized DB instance class type.
- Set up an Amazon DynamoDB table with auto-scaling enabled. Configure the table with a minimum of 2 and a maximum of 16 capacity units.

### 🧠 Question kya keh raha hai? (Scenario Breakdown)

1. **Current Setup:** Application 3-tier hai jismein application components AWS par hain, jabke **MySQL-compatible database on-premises** par hai jo Site-to-Site VPN se connected hai.
2. **Database Memory:** Database ki memory requirement **2 se 16 GiB** ke darmiyan vary karti hai.
3. **Traffic Pattern:** Load bohot unpredictable hai — kabhi spikes aate hain aur kabhi zero activity hoti hai (irregular load).
4. **Main Goal:** On-premises database ko ek **managed, serverless service** se replace karna hai jo unpredictable traffic ke mutabiq **automatically scale** ho sake.

---

### 🔍 Keyword Scanning (Sawal se Sahi Jawab Tak)

* **Keywords in Question:** `"MySQL-compatible"`, `"unpredictable traffic / irregular load"`, `"serverless capacity scaling"`, `"2 to 16 GiB memory"`.
* **Matching AWS Feature:**
* **MySQL-compatible + Serverless auto-scaling:** 👉 **Amazon Aurora Serverless v2**
* **Memory Calculation:** 1 ACU (Aurora Capacity Unit) ≈ 2 GiB memory.
* 1 ACU = 2 GiB (Minimum)
* 8 ACUs = 16 GiB (Maximum)
* Maximum 8 ACUs exact 16 GiB requirement ko poora karta hai.





---

### ❌ Baaqi Options Kyun Galat Hain?

* **RDS for MySQL (4 GiB):** Yeh Provisioned instance hai, serverless nahi. Fixed 4 GiB memory scaling ya unpredictable spikes ko handle nahi kar sake gi.
* **Aurora with Memory-Optimized Instance:** Yeh bhi Provisioned EC2-based instance class hai, serverless auto-scaling component nahi hai.
* **DynamoDB:** DynamoDB ek NoSQL database hai. Existing application SQL/MySQL-compatible database use karti hai, is liye schema rewrite ki zaroorat parti.

---

### ✅ Correct Answer:

* **Configure an Amazon Aurora Serverless v2 database with a minimum capacity of 1 and a maximum of 8 Aurora capacity units (ACUs).**

---

**Summary:** Aurora Serverless v2 automatically scales MySQL-compatible relational workloads in fractions of an ACU (1 ACU = 2 GiB RAM) to handle unpredictable spikes and zero-activity periods seamlessly.
