21. Question

An organization operates a high-traffic static website hosted on Amazon S3, which is distributed via Amazon CloudFront. The current CloudFront distribution has a default Time-to-Live (TTL) of 10 seconds, leading to no caching. The company aims to implement caching to enhance website performance while ensuring that outdated content is not served for more than a few minutes post-deployment.

Which caching strategies should a solutions architect apply to achieve these objectives?

- Set up Amazon S3 lifecycle policies to automatically delete objects older than 7 days, ensuring that CloudFront edge caches are regularly purged of stale content.
- `Set the CloudFront default TTL to 4 minutes and implement a Cache-Control private directive on objects stored within Amazon S3.`
- Deploy an AWS Lambda@Edge function to insert an Expires header into HTTP responses. Set this function to trigger on viewer response.
- Apply a default TTL of 4 minutes on the S3 bucket.

Koi baat nahi! Is question ko simple steps mein samajhte hain:

---

### 1. Problem Kya Thi?

* Main issue yeh tha ke website ka content cache nahi ho raha tha (TTL sirf 10 seconds tha), jis se site slow chal rahi thi.
* Company chahti thi ke caching **start** ho taake site fast ho, lekin purana content max **kuch minutes** (3-5 minutes) se zyada screen par na nazar aaye.

---

### 2. AWS Caching Ka Simple Asool:

* **TTL (Time-To-Live)** humesha **CloudFront** par set hota hai, S3 bucket par nahi.
* Agar aap CloudFront ka **Default TTL = 4 minutes** set karte hain:
1. Content Edge Locations par 4 minutes ke liye store (cache) ho jayega.
2. 4 minutes ke baad CloudFront automatically S3 se naya content mangwaye ga. Is se purana content 4 minutes se zyada nahi dikhega.



---

### 3. Baaqi Options Kyun Wrong Hain?

* **S3 Par TTL Lagana:** S3 bucket ke paas TTL set karne ki koi option nahi hoti (TTL CloudFront ka feature hai).
* **S3 Lifecycle Policy:** Yeh 7 din baad S3 se file delete karta hai, CloudFront ki cache ko update nahi karta.

---

### 💡 Short Rule of Thumb:

> CloudFront caching controls (TTL) hamesha **CloudFront Distribution** ki settings par lagaye jaate hain, S3 bucket par nahi.

21. Question

A company operates a data lake on Amazon S3, integrating data in Apache Parquet format from various sources. To enhance the data for analysis, the company employs multiple transformation steps. These include filtering anomalies, standardizing date and time formats, and generating analytical aggregates. The transformed data is stored in S3 buckets for access by data analysts.

The company seeks a pre-built, non-coding solution for these data transformations. This solution must include data lineage and profiling features. Additionally, the data transformation steps must be transparent and shareable across the entire organization.

What is the most suitable AWS solution to fulfill these specific needs?

- Leverage AWS Glue Studio's visual interface for data transformation. Use Amazon Redshift ML to generate predictive aggregates from the transformed data. Distribute the transformation process across the organization by utilizing Glue jobs.
- Utilize AWS Glue DataBrew for the data transformation tasks. Make the transformation steps available to employees through the use of DataBrew recipes.
- Set up Amazon EMR to manage data transformation. Document and share the transformation steps with employees through EMR Studio notebooks.
- Query data using Amazon Athena to execute the data transformation using SQL queries. Facilitate the sharing of these Athena SQL queries among employees.

Koi baat nahi! Is question ko bilkul aasan misal se samajhte hain:

---

### 1. Problem Kya Thi?

* Company ke paas data tha aur unhein us data ko clean aur transform karna tha (jaise filtering, date format theek karna).
* **Lekin 2 bari shartein thin:**
1. **Non-coding solution:** Koyi code ya programming nahi likhni parni chahiye (jaise normal log Excel ya visual software use karte hain).
2. **Recipes/Sharing:** Jo steps ek baar data saaf karne ke liye banayein, unhein save karke doosre logo ke sath share kiya ja sake taake unhein dobara mehnat na karni pare.



---

### 2. AWS Glue DataBrew Kyun Sahi Hai?

* **Glue DataBrew** ek visual, click-and-point tool hai jismein bina coding ke data clean kiya jata hai.
* Isme **"DataRecipes"** ka feature hota hai. Iska matlab hai ke jo steps aapne data ko theek karne ke liye kiye, woh ek recipe ki tarah save ho jate hain aur aap apni puri company mein share kar sakte hain.

---

### 3. Baaqi Options Kyun Galat Hain?

* **EMR aur Athena:** In dono ke liye SQL queries ya Python/Spark ka **code likhna parta hai**, jabke sawal mein saaf mana kiya gaya tha ke code nahi chahiye (non-coding).
