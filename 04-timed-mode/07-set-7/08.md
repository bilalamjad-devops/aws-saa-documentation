8. Question

A company is preparing a solution that the sales team can use for generating weekly revenue reports. The team must be able to run analysis on sales records stored in Amazon S3 and visualize the results of queries.

How can the solutions architect meet the requirement in the most cost-effective way possible?

- Send the records to an Amazon Kinesis Data stream. Run queries using Kinesis Data Analytics. Use Amazon QuickSight for visualization.
- Use AWS Glue crawler to build tables in AWS Glue Data Catalog. Run queries using Amazon Athena. Use Amazon QuickSight for visualization.
- Load the records into an Amazon OpenSearch (Amazon ElasticSearch) cluster. Run queries in Amazon OpenSearch and visualize the results using Kibana.
- Load the records into an Amazon Redshift cluster. Run queries in Amazon Redshift and send the results in Amazon S3. Use Amazon QuickSight for visualization.

### 1. Sawal Ki Asal Kahani (The Problem) 🛑

* **Scenario:** Sales team ko **weekly revenue reports** banani hain.
* **Data Location:** Sales records pehle se **Amazon S3** mein pare hain.
* **Requirements:**
1. S3 data par queries run karke analysis karna hai.
2. Results ko visualize (charts/dashboards ki shakal mein) karna hai.
3. Sab se **cost-effective (sasta)** tareeqa hona chahiye.



---

### 2. Sahi Jawab Ka Breakdown (The Solution) 💡

Sahi option yeh hai:

> **Use AWS Glue crawler to build tables in AWS Glue Data Catalog. Run queries using Amazon Athena. Use Amazon QuickSight for visualization.**

**Yeh kyun sab se sasta aur behtareen hai?**

1. **AWS Glue Crawler:** Yeh S3 bucket ko scan karta hai aur khud-ba-khud schema (tables) bana kar **Glue Data Catalog** mein save kar deta hai — yani koi server manually configure nahi karna parta.
2. **Amazon Athena (Serverless SQL Query):** Athena ek **serverless** query engine hai. Iska matlab hai ke aap ko 24/7 servers chala kar paise zaya nahi karne parte. Aap sirf tab pay karte hain jab aap query run karte hain aur jitna data scan hota hai (pay-per-query model). Weekly reports ke liye yeh ideal aur sab se sasta tareeqa hai!
3. **Amazon QuickSight:** Yeh AWS ki managed Business Intelligence (BI) / visualization service hai jo data ko graphs aur dashboards ki shakal mein dikhati hai.

---

### 3. Baqi Options Kyun Ghalat Hain? ❌

* **Option 1 (Kinesis Streams + Kinesis Data Analytics):**
* *Ghalat kyun?* Kinesis real-time streaming data ke liye hota hai (jaise live sensors ya clickstreams). Weekly reports ke liye streaming setup rakhna mehnga aur fazool hai.


* **Option 3 (Amazon OpenSearch + Kibana):**
* *Ghalat kyun?* OpenSearch search logs aur text search ke liye best hai, aur isme clusters ko 24/7 chalana parta hai jo ke cost-effective nahi hai.


* **Option 4 (Amazon Redshift):**
* *Ghalat kyun?* Redshift aik data warehouse hai jiske liye dedicated clusters run karne parte hain (24/7 costs). Jab data pehle se S3 mein pada ho aur sirf weekly reports chahiye hon, toh Redshift khariadna ya cluster chalana over-engineering aur mehangi choice hai. Jabke Athena serverless hai aur koi cluster maintain nahi karna parta.

### 1. AWS Glue Crawler & Glue Data Catalog Kya Hai? 📂

Imagine karein ke aap ke paas Amazon S3 mein hazaron CSV files pari hain jin mein sales ka data hai.

* Computer ko raw S3 files dekh kar yeh samajh nahi aati ke konsa column "Name" ka hai aur konsa "Price" ka hai. Use pehle se ek **Table** ki shakal (Schema) chahiye hoti hai jismein rows aur columns define hon.

Yahan aata hai **AWS Glue Crawler**:

1. **Glue Crawler (The Smart Clerk):** Yeh ek automated worker hai jo aap ke S3 bucket ke andar jata hai, files ko khol kar parhta hai, aur khud-ba-khud pata laga leta hai ke columns ke naam kya hain aur data kis type ka hai (jaise text, number, date).
2. **Glue Data Catalog (The Filing Cabinet):** Jab Crawler saari information nikal leta hai, toh woh use ek organized **Data Catalog (Database/Tables)** mein save kar deta hai.

**Faida:** Ab Amazon Athena ya koi bhi query tool direct S3 ki raw files par nahi balkay is Glue Data Catalog ki table par SQL query chala sakta hai — bilkul waise jaise aap kisi SQL database ko query karte hain!

---

### 2. Amazon QuickSight vs. OpenSearch Dashboards (Kibana) 📊

Yeh dono data ko visualize (charts aur graphs ki shakal mein) karne ke tools hain, lekin inka istemal bilkul mukhtalif jagahon par hota hai:

| Feature | Amazon QuickSight | OpenSearch Dashboards (Kibana) |
| --- | --- | --- |
| **Main Purpose** | **Business Intelligence (BI) & Reports** (Jaise sales charts, revenue graphs, executive dashboards). | **Log Analysis & Real-time Monitoring** (Jaise server logs, error tracking, security alerts). |
| **Kiske sath chalta hai?** | Yeh **Amazon Athena**, RDS, aur Redshift ke sath deeply integrated hota hai. | Yeh sirf **Amazon OpenSearch (Elasticsearch)** ke sath chalta hai. |
| **Pricing Model** | Serverless, **Pay-per-session** (jab user dekhta hai tab paise lagte hain). | Dedicated cluster chalana parta hai (24/7 hourly charges). |

**Is sawal mein QuickSight kyun sahi tha?**
Kyunki sales team ko weekly revenue reports aur business analytics chahiye thin jo S3/Athena par bani tables se aani thin, na ke servers ke logs ya search data!
