33. Question

A DevOps Engineer is asked to deploy a web application on Amazon EC2 instances. The instances are defined in a target group and are able to scale horizontally based on the configuration of an Auto Scaling group.

The domain should be available publicly via the internet and is to be configured with session affinity (sticky sessions) to improve the user session management of the application. The application should be secured with an AWS WAF for additional protection against web attacks.

Which among the choices below should be set up to satisfy this requirement? (Select TWO.)

- `Set up an internet-facing Application Load Balancer (ALB). Configure the listener over HTTP and HTTPS to forward traffic to the application target group.`
- Launch a Gateway Load Balancer. Configure the IP listener routing to forward traffic to the application target group.
- `Create a Web ACL in AWS WAF configured with the public domain.`
- Provision a Network Load Balancer (NLB) with a public subnet. Configure the TCP listener to forward traffic to the application target group.
- Deploy an AWS Network Firewall to a public subnet of a VPC.


Aaiye is sawal ko apne crisp, fast-track aur keyword-focused breakdown ke sath samajhte hain! 🚀

---

### 🎯 1. Sawal Kya Keh Raha Hai? (Question Breakdown)

Ek web application Amazon EC2 instances (Auto Scaling Group + Target Group) par deploy karni hai.

* **Requirements:**
1. Web application publicly Internet par accessible ho.
2. **Session affinity (sticky sessions)** support ho user session management ke liye.
3. Web application attacks se bachne ke liye **AWS WAF** ki protection implement ho.


* **Goal:** In requirements ko satisfy karne ke liye kaun se **2 components** choose karne hain (**Select TWO**).

---

### ✅ 2. Sahi Jawab Kya Keh Raha Hai? (Correct Answers)

> 1. **Set up an internet-facing Application Load Balancer (ALB). Configure the listener over HTTP and HTTPS to forward traffic to the application target group.**
> 2. **Create a Web ACL in AWS WAF configured with the public domain.** *(Note: WAF Web ACL is associated with the ALB).*
> 
> 

#### **Deep-Dive Explanation:**

1. **Application Load Balancer (ALB):** ALB Layer 7 (HTTP/HTTPS) load balancer hai jo natively **sticky sessions (session affinity)** support karta hai. Internet-facing ALB web traffic ko receive karke target group ko forward karega.
2. **AWS WAF Association:** AWS WAF directly **ALB** ke sath integrate hota hai (via Web ACL association) taake Layer 7 attacks (jaise SQLi, XSS) ko block kiya ja sake.

---

### ❌ 3. Baqi Options Kyun Ghalat Hain?

* **Provision a Network Load Balancer (NLB):**
* *Ghalat kyun?* NLB Layer 4 (TCP/UDP) load balancer hai. Yeh HTTP-level cookie-based sticky sessions support nahi karta aur is ke sath **AWS WAF directly integrate nahi ho sakta**.


* **Launch a Gateway Load Balancer:**
* *Ghalat kyun?* GWLB 3rd-party virtual network appliances (jaise Palo Alto firewalls) ke routing ke liye hota hai, standard web app sticky session load balancing ke liye nahi.


* **Deploy an AWS Network Firewall to a public subnet:**
* *Ghalat kyun?* Network Firewall VPC-level L3-L7 traffic inspect karta hai, lekin yeh Web Application Layer (WAF) rule protection aur ALB sticky sessions ka alternate nahi hai.
