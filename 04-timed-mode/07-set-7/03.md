3. Question

A solutions architect is formulating a strategy for a startup that needs to transfer 50 TB of on-premises data to Amazon S3. The startup has a slow network transfer speed between its data center and AWS which causes a bottleneck for data migration.

Which of the following should the solutions architect implement?

- Integrate AWS Storage Gateway File Gateway with the on-premises data center.
- Enable Amazon S3 Transfer Acceleration on the target S3 bucket.
- Deploy an AWS Migration Hub Discovery agent in the on-premises data center.
- `Request an Import Job to Amazon S3 using a Snowball device in the AWS Snowball Console.`

### 1. Sawal Kya Keh Raha Hai? (Question Breakdown) ❓

* **Scenario:** Aik startup ke paas **50 TB** on-premises data hai jise Amazon S3 par transfer karna hai.
* **Problem / Bottleneck:** Data center aur AWS ke darmiyan **network transfer speed bohot slow** hai (slow internet connection).
* **Goal:** Aisa tareeqa dhundna hai jo slow internet ki rukawat ko bypass kar ke 50 TB data efficiently AWS tak pohancha sake.

---

### 2. Sahi Jawab Kya Keh Raha Hai? (Correct Answer) 💡

* **Option:** *Request an Import Job to Amazon S3 using a Snowball device in the AWS Snowball Console.*
* **Wazahat:**
* **AWS Snowball (Snow Family):** Jab data ka volume bara ho (aam taur par **10 TB se upar**) aur internet ki bandwidth itni kam ho ke data upload karne mein weeks ya months lag jayein, toh AWS aap ke ghar/office ek physical secure hardware device (**Snowball Edge**) bhejta hai.
* Aap local server se data us device par copy karte hain aur AWS ko wapas courier kar dete hain. AWS us data ko direct aapke S3 bucket mein load kar deta hai. Yeh slow network ka sab se behtareen physical solution hai.



*Kyunki baqi options ghalat hain:*

* *S3 Transfer Acceleration:* Yeh CloudFront edge locations aur optimized routing use karta hai, lekin agar on-premises internet connection hi bohot slow hai (e.g., weak DSL/broadband), toh Transfer Acceleration bhi us slow speed ka jadu se mukammal ilaaj nahi kar sakta.
* *Storage Gateway File Gateway:* Yeh on-premises systems ko S3 se mount karne ke liye hybrid backup/storage ke taur par use hota hai, bulk initial data migration (50 TB over slow network) ke liye physical Snowball device prefer hota hai.
* *Migration Hub Discovery Agent:* Yeh servers ki inventory aur dependencies discovery ke liye hota hai, data migration ke liye nahi.
