22. Question

A company is revamping its existing stateless inventory management system. The application is deployed across 7 EC2 instances in multiple Availability Zones behind an Application Load Balancer (ALB). The application is designed to handle varying traffic patterns. Still, engineers have observed that traffic is consistently routed to a single EC2 instance, resulting in performance bottlenecks and higher latency for some requests.

What is the most effective solution to resolve the underlying load balancing issue?

- Utilize a Gateway Load Balancer (GWLB) instead of an ALB.
- Turn off sticky sessions on the Application Load Balancer (ALB).
- Terminate the favored EC2 instance and redeploy the remaining 6 EC2 instances evenly across all Availability Zones in the region.
- Modify the interval for health checks in the ALB's target group settings.

Yes — this question tests a fundamental setting in Application Load Balancers that controls how client requests are distributed among backend instances.

---

### 🎯 1. Sawal Kya Keh Raha Hai? (What is the Question Saying?)

Ek company ki **stateless application** hai jo 7 EC2 instances par multiple Availability Zones (AZs) mein **Application Load Balancer (ALB)** ke peeche chal rahi hai.

* **Masla (Problem):** ALB saari traffic ko saree instances par baantne ke bajaye **sirf ek hi EC2 instance par baar baar bhej raha hai** (consistently routing to a single instance). Is se wo ek instance overloaded ho gaya hai aur latency barh gayi hai.
* **Goal:** Load balancing ka yeh issue hal karna hai taake traffic tamam EC2 instances par barabar distribute ho.

---

### ✅ 2. Sahi Jawab Kya Keh Raha Hai? (What is the Correct Answer Saying?)

> **Turn off sticky sessions on the Application Load Balancer (ALB).**

#### Breakdown:

* **Sticky Sessions (Target Group Attribute):** Jab ALB par Sticky Sessions (Session Affinity) ON hota hai, toh ALB ek cookie ke zariye client ko pehchanta hai aur **ek hi user ki saari requests ko hamesha us ek hi EC2 instance par bhejta hai**.
* **Stateless Application:** Kyunki application pehle se **stateless** hai (yaani session data instance par save nahi hota), isliye Sticky Sessions ki koi zaroorat nahi hai.
* **Solution:** Sticky sessions ko **OFF / Turn off** karne se ALB har nayi request ko Round Robin algorithm ke zariye tamam 7 EC2 instances par barabar (evenly) distribute kar dega.

---

### ❌ 3. Baqi Options Kyun Ghalat Hain?

* **Utilize a Gateway Load Balancer (GWLB) instead of an ALB:**
* *Ghalat kyun?* GWLB (Gateway Load Balancer) third-party virtual appliances (firewalls, deep packet inspection) ke liye use hota hai, web application traffic balancing ke liye nahi.


* **Terminate the favored EC2 instance and redeploy...:**
* *Ghalat kyun?* Agar aap ek instance terminate karenge toh ALB baki bache instances mein se kisi ek ko dobara "sticky" bana kar saari traffic us par bhejna shuru kar dega. Main root cause (Sticky Sessions) hal nahi hoga.


* **Modify the interval for health checks...:**
* *Ghalat kyun?* Health check timing badalne se unhealthy instances detect hote hain, is se traffic unevenly route hone ka sticky session problem solve nahi hota.
