9. Question

A Solutions Architect is developing a three-tier cryptocurrency web application for a FinTech startup. The Architect has been instructed to restrict access to the database tier to only accept traffic from the application-tier and deny traffic from other sources. The application-tier is composed of application servers hosted in an Auto Scaling group of EC2 instances.

 Which of the following options is the MOST suitable solution to implement in this scenario?

- Set up the Network ACL of the database subnet to allow inbound database traffic from the subnet of the application-tier.
- Set up the security group of the database tier to allow database traffic from the security group of the application servers.
- Set up the security group of the database tier to allow database traffic from a specified list of application server IP addresses.
- Set up the Network ACL of the database subnet to deny all inbound non-database traffic from the subnet of the application-tier.

### 1. Sawal Ki Asal Kahani (The Problem) 🛑

* **Scenario:** Aik three-tier web application hai (Frontend ➔ Application Tier ➔ Database Tier).
* **Requirement:** Database tier ko sirf **application-tier** se traffic aane ki ijazat deni hai, aur baqi sab sources se block karna hai.
* **Twist:** Application-tier **Auto Scaling Group (ASG)** mein hai, iska matlab hai ke servers zaroorat ke mutabiq automatic banate aur khatam hote rehte hain, isliye unke **IP addresses fix nahi hain (dynamic hain)**.

---

### 2. Sahi Jawab Ka Breakdown (The Solution) 💡

Sahi option yeh hai:

> **Set up the security group of the database tier to allow database traffic from the security group of the application servers.**

**Yeh kyun sab se behtareen hai?**

1. **Security Groups (SGs) are Stateful:** SGs instance-level par firewall ka kaam karte hain.
2. **Referencing another Security Group:** Kyunki application-tier Auto Scaling Group mein hai aur instances ke IP addresses badalte rehte hain, aap IPs hardcode nahi kar sakte. AWS mein aap **Database ke Security Group mein yeh rule laga sakte hain ke "App-tier ke Security Group se aane wali traffic ko allow karo"**. Is se chahe 2 instances hon ya 20, jab bhi naya instance ASG mein launch hoga, use automatic database access mil jayega kyunki woh us Security Group ka hissa hai!

---

### 3. Baqi Options Kyun Ghalat Hain? ❌

* **Option 3 (Specify a list of application server IP addresses):**
* *Ghalat kyun?* Kyunki application servers Auto Scaling Group mein hain, unke IPs dynamic hain (barhte/kam hote rehte hain). Aap har daika naye IP addresses manual update nahi kar sakte.


* **Options 1 & 4 (Network ACLs):**
* *Ghalat kyun?* Network ACLs (NACLs) **subnet level** par kaam karti hain aur **stateless** hoti hain. Tier-to-tier granular security aur dynamic scaling ke liye Security Groups (jo instance-level par dusre SG ko reference kar sakte hain) standard aur best practice hain.
