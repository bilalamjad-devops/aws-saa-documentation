7. Question

A manufacturing company is building an IoT-based system to detect faults in its production process in real-time. The system will feed sensor data to an Amazon API Gateway REST API, where the data will be analyzed for any anomalies or faults.

The result of the data processing will then determine the necessary remedial action to be taken. It’s critical that the data is processed in the sequence in which it was sent.

Which of the following is the most operationally efficient solution?

- Implement an API Gateway authorizer to ensure that the data stream is processed in real-time and in order of arrival.
- Utilize an API Gateway integration to send incoming data to an Amazon Kinesis Data Stream. Attach an AWS Lambda function to the Kinesis stream to process the data.
- Store incoming data in a standard Amazon SQS queue and configure an AWS Lambda function to process the data as it arrives in the queue.
- Store incoming data in Amazon S3 and trigger an AWS Lambda function to process the data via S3 Event Notification

Aaiye, is sawal ko bhi pehle wale ki tarah bilkul simple aur real-world scenario mein tor kar samajhte hain!

---

### 1. Sawal Ki Asal Kahani (The Problem) 🛑

* **Scenario:** Ek factory mein IoT sensors lage hain jo production machine ka data real-time mein **Amazon API Gateway** par bhejte hain.
* **Problem / Main Requirement:** Data ko analyze karke faults dhoondne hain, lekin sab se zaroori shart yeh hai ke **data bilkul usi TARTEEB (Sequence / Order of arrival) mein process hona chahiye jis tarteeb mein sensors ne bheja hai**.
*(Masla: Agar Event A pehle aaya aur Event B baad mein, toh system pehle A ko hi read kare, B ko nahi).*
* **Goal:** Sub se zyada **Operationally Efficient (Managed & Automated)** solution chunna hai.

---

### 2. Sahi Jawab Ka Breakdown (The Solution) 💡

Sahi option yeh hai:

> **Utilize an API Gateway integration to send incoming data to an Amazon Kinesis Data Stream. Attach an AWS Lambda function to the Kinesis stream to process the data.**

**Yeh kyun sahi hai?**

1. **Real-time & Strict Ordering:** **Amazon Kinesis Data Streams** khas tor par real-time streaming data (jaise IoT sensor feeds) ke liye bana hai. Kinesis Data Streams har shard ke andar data ke **sequence (order)** ko guarantee karta hai.
2. **Seamless Integration:** API Gateway bina kisi extra code ke seedha Kinesis Data Stream ke sath integrated ho sakta hai (API Gateway Native AWS Integration).
3. **AWS Lambda:** Lambda function Kinesis stream se records ek fixed sequence (order) mein read karta hai aur realtime anomaly detection kar leta hai.

---

### 3. Baqi Options Kyun Ghalat Hain? ❌

* **Option 1 (API Gateway Authorizer):**
* *Ghalat kyun?* Authorizer ka kaam sirf yeh check karna hota hai ke request bhejne wala authenticated user/device hai ya nahi (Security/Access Control). Yeh data ki ordering ya processing nahi kar sakta.


* **Option 3 (Standard Amazon SQS Queue):**
* *Ghalat kyun?* **Standard SQS Queue** mein data ki **strict sequence/order ki guarantee NAHI hoti**. SQS Standard best-effort ordering karta hai aur messages out-of-order process ho sakte hain. (Agar SQS FIFO queue hota toh ordering milti, lekin standard queue mein nahi).


* **Option 4 (Amazon S3 + Event Notification):**
* *Ghalat kyun?* S3 ek object storage hai, real-time streaming buffer nahi. S3 mein files save karke event trigger karwane se real-time low-latency processing nahi milti aur na hi strict sequence manage hota hai.
