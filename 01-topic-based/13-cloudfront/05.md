5. Question

Category: CSAA – Design Cost-Optimized Architectures

A digital media company shares static content to its premium users around the world and also to their partners who syndicate their media files. The company is looking for ways to reduce its server costs and securely deliver their data to their customers globally with low latency.

Which combination of services should be used to provide the MOST suitable and cost-effective architecture? (Select TWO.)

- `Amazon S3`
- AWS Global Accelerator
- `Amazon CloudFront`
- AWS Fargate
- AWS Lambda

# Step 1: Simplify the Question

The company has:

* Premium users around the world 🌍
* Static content

  * Images
  * Videos
  * Files
* Wants:

  * Lower cost
  * Secure delivery
  * Low latency

The question is asking:

> **Which AWS services are best for storing and delivering static files globally?**

---

# Step 2: Highlight the Keywords

### "Static content"

Think:

* Images
* CSS
* JavaScript
* Videos
* PDFs

Immediately think:

> **Amazon S3**

because S3 is AWS's storage service.

---

### "Users around the world"

Think:

How do we deliver files globally?

Immediately think:

> **CloudFront**

CloudFront caches files in edge locations close to users.

---

### "Low latency"

Again:

CloudFront.

---

### "Reduce server costs"

Notice something important.

It never says:

* run applications
* process requests
* containers

It only says:

> Share static files.

Static files don't need EC2.

They don't need containers.

Just store them in S3.

---

# Final Architecture

```text
Users Worldwide
        │
        ▼
  CloudFront CDN
        │
        ▼
     Amazon S3
```

This is one of the most common AWS architectures.

---

# Option 1 — Amazon S3 ✅

Perfect.

S3 stores:

* images
* videos
* documents
* static website files

Very cheap.

Highly durable.

---

# Option 2 — CloudFront ✅

CloudFront:

* caches content
* delivers from nearest Edge Location
* reduces latency
* reduces S3 requests
* integrates with AWS Shield
* can use Signed URLs/Cookies

Exactly matches the scenario.

---

# Option 3 — Global Accelerator ❌

This is the exam trap.

Many students confuse CloudFront and Global Accelerator.

CloudFront works like this:

```text
User
   │
Nearest Edge Location
   │
Cache
   │
S3
```

Global Accelerator works differently:

```text
User
   │
AWS Global Network
   │
ALB / NLB / EC2
```

Notice:

Global Accelerator **does not cache files**.

Also:

It **does not directly work with S3** as an origin.

It's mainly for:

* TCP
* UDP
* Gaming
* VoIP
* Static IP
* Fast failover

Not static websites.

---

# Option 4 — Fargate ❌

Fargate runs containers.

Question says:

Static files.

No need for containers.

Too expensive.

---

# Option 5 — Lambda ❌

Lambda executes code.

It doesn't store images.

It isn't a CDN.

---

# Easy Comparison

| Service                | Purpose                                       |
| ---------------------- | --------------------------------------------- |
| **S3**                 | Store files                                   |
| **CloudFront**         | Deliver files globally                        |
| **Global Accelerator** | Accelerate TCP/UDP apps, static IPs, failover |
| **Lambda**             | Run code                                      |
| **Fargate**            | Run containers                                |

---

# CloudFront vs Global Accelerator (Very Important for the Exam)

| CloudFront                       | Global Accelerator                                             |
| -------------------------------- | -------------------------------------------------------------- |
| CDN                              | Network accelerator                                            |
| Caches content                   | Does not cache                                                 |
| Best for images, videos, CSS, JS | Best for applications                                          |
| Works with S3                    | Doesn't use S3 directly as an origin                           |
| HTTP/HTTPS                       | TCP & UDP (also supports HTTP applications needing static IPs) |
| Reduces latency by caching       | Reduces latency by routing traffic over AWS global network     |
| Static website                   | Gaming, APIs, VoIP, multi-region apps                          |

# Final Memory Trick

Think of it like a restaurant:

```text
Kitchen (S3)
      │
      ▼
Local Branches (CloudFront Edge Locations)
      │
      ▼
Customers
```

The kitchen (S3) stores the food (files), and the local branches (CloudFront edge locations) keep popular items close to customers for fast delivery.

In contrast:

```text
Traffic Police (Global Accelerator)
```

Global Accelerator doesn't store or cache anything—it simply directs network traffic along the fastest AWS path to your application. That's why for **static content**, the correct pair is:

* ✅ **Amazon S3** (storage)
* ✅ **Amazon CloudFront** (global content delivery)
