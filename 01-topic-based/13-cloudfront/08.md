8. Question

Category: CSAA – Design Cost-Optimized Architectures

A solutions architect is instructed to host a website that consists of HTML, CSS, and some Javascript files. The web pages will display several high-resolution images. The website should have optimal loading times and be able to respond to high request rates.

Which of the following architectures can provide the most cost-effective and fastest loading experience?

- Launch an Auto Scaling Group using an AMI that has a pre-configured Apache web server, then configure the scaling policy accordingly. Store the images in an Elastic Block Store. Then, point your instance’s endpoint to AWS Global Accelerator.
- Upload the HTML, CSS, Javascript, and the images in a single bucket. Then enable website hosting. Create a CloudFront distribution and point the domain on the S3 website endpoint.
- Host the website in an AWS Elastic Beanstalk environment. Upload the images in an S3 bucket. Use CloudFront as a CDN to deliver the images closer to your end-users.
- Host the website using an Nginx server in an EC2 instance. Upload the images in an S3 bucket. Use CloudFront as a CDN to deliver the images closer to end-users.

# Step 3: What is Static Website?

A static website simply sends files.

```
Browser
     |
GET index.html
     |
S3 returns index.html
```

No server processing.

No EC2.

No Lambda.

No RDS.

Just files.

---

# Step 4: Where should static files live?

AWS created S3 Website Hosting exactly for this.

```
S3 Bucket

index.html
style.css
app.js
logo.png
photo1.jpg
photo2.jpg
```

S3 automatically serves them.

No server.

No maintenance.

Almost zero cost.

---

# Step 5: But users are worldwide

Suppose:

Users

Pakistan

USA

Germany

Australia

Japan

If every user downloads directly from S3 (say, in us-east-1):

```
Pakistan
      \
USA ----> S3 us-east-1
      /
Japan
```

Far users experience more latency.

---

# Step 6: CloudFront solves this

Instead:

```
        S3
         ^
         |
CloudFront Edge Locations
 /    |     |      \
PK   UK    USA    Japan
```

The first request goes to S3.

Then CloudFront caches it.

Next users receive it from the nearest edge location.

Much faster.

---

This is AWS's recommended architecture for static websites.

# Step 10: Why not Global Accelerator?

Many students confuse these.

CloudFront and Global Accelerator are different.

## CloudFront

Optimized for:

* HTML
* CSS
* JS
* Images
* Videos
* APIs

Uses **HTTP/HTTPS**.

Caches content.

---

## Global Accelerator

Optimized for:

* TCP
* UDP

Examples:

* Gaming
* VoIP
* Financial apps
* Static IP requirement
* Regional failover

It does **not cache** content.

So for a website, CloudFront is the right service.

# CloudFront Decision Table (Very Important)

| Scenario                              | AWS Service                         |
| ------------------------------------- | ----------------------------------- |
| Static website                        | S3 Website Hosting                  |
| Faster global delivery                | CloudFront                          |
| Private S3 access                     | Origin Access Control (OAC)         |
| One private file                      | Signed URL                          |
| Multiple private files                | Signed Cookies                      |
| DDoS protection                       | AWS WAF + CloudFront (+ AWS Shield) |
| Cache objects                         | CloudFront                          |
| Dynamic database caching              | ElastiCache                         |
| Non-HTTP apps (gaming, VoIP, TCP/UDP) | Global Accelerator                  |

---

This question is one of the highest-frequency patterns in the SAA exam. If you see **"static website + cheapest + fastest + global users"**, the answer is almost always:

**Amazon S3 (Website Hosting) + Amazon CloudFront.**
