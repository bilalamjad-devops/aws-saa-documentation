6. Question

Category: CSAA – Design High-Performing Architectures

A company has a global news website hosted in a fleet of EC2 Instances. Lately, the load on the website has increased which resulted in slower response time for the site visitors. This issue impacts the revenue of the company as some readers tend to leave the site if it does not load after 10 seconds. The goal is to address the issue in a cost-effective manner.”

Which of the below services in AWS can be used to solve this problem? (Select TWO.)

- Use Amazon CloudFront with website as the custom origin.
- For better read throughput, use AWS Storage Gateway to distribute the content across multiple regions.
- Deploy the website to all regions in different VPCs for faster processing.
- Use Amazon RDS Multi-AZ deployments for database read scalability.
- Use Amazon ElastiCache for the website's in-memory data store or cache.

This is a classic **CloudFront + ElastiCache** question. The exam wants you to identify **where the bottleneck is**.

---

# Step 1: Simplify the Question

The company has:

* 🌍 Global news website
* Hosted on EC2
* Website is becoming slow
* Visitors leave if it takes more than 10 seconds
* Wants a **cost-effective** solution

The question is asking:

> **How can we make the website faster without deploying servers everywhere?**

---

# Step 2: Find the Keywords

### Keyword 1

> **Global website**

Immediately think:

> ✅ CloudFront

because users are worldwide.

---

### Keyword 2

> **News website**

What is a news website?

Mostly:

* Reading articles
* Reading images
* Reading CSS
* Reading JavaScript

Very few writes.

This means:

> **Read-heavy workload**

---

### Keyword 3

> **Slower response time**

Why?

Every request is probably reaching:

```text
User
   │
Internet
   │
EC2
```

Every visitor hits EC2.

That becomes expensive.

---

# Correct Architecture

```text
Users
   │
   ▼
CloudFront
   │
   ├──── Cached images
   ├──── Cached CSS
   ├──── Cached JS
   └──── Cached articles
          │
          ▼
      EC2 Website
          │
          ▼
    ElastiCache (Redis/Memcached)
          │
          ▼
      Database
```

CloudFront reduces traffic to EC2, while ElastiCache reduces repeated database queries.

---

# Option 1 — CloudFront ✅

Question says:

> Global users

CloudFront caches content at Edge Locations.

Instead of:

```text
Pakistan
      │
USA EC2
```

It becomes:

```text
Pakistan
      │
Pakistan/Nearest Edge Location
```

Much faster.

---

# Option 2 — Storage Gateway ❌

Storage Gateway is for:

* On-premises storage
* Hybrid storage
* Backup

It has nothing to do with speeding up websites.

---

# Option 3 — Deploy website to every Region ❌

Technically possible.

But the question says:

> **Cost-effective**

Deploying EC2 instances worldwide is expensive and operationally complex.

CloudFront already solves global content delivery much more efficiently.

---

# Option 4 — RDS Multi-AZ ❌

This is a very common exam trap.

Students think:

Database is slow →

Use Multi-AZ.

Wrong.

Multi-AZ provides:

* High Availability
* Disaster Recovery
* Automatic Failover

It **does not increase read performance**.

If the question asked about scaling database reads, think about **Read Replicas**, not Multi-AZ.

---

# Option 5 — ElastiCache ✅

Suppose your homepage shows:

* Top 10 articles
* Latest news
* Trending topics

Without cache:

```text
User 1
      │
Database

User 2
      │
Database

User 3
      │
Database

User 10000
      │
Database
```

The database is repeatedly answering the same query.

With ElastiCache:

```text
User
   │
ElastiCache
   │
Database (only if cache miss)
```

The first request fetches from the database and stores the result in cache. Subsequent users get the cached data, making responses much faster and reducing database load.

---

# Why Both Together?

Think of it this way:

CloudFront caches content **near users**.

ElastiCache caches data **near your application**.

```text
User
   │
CloudFront
   │
EC2
   │
ElastiCache
   │
Database
```

CloudFront reduces requests reaching EC2.

ElastiCache reduces requests reaching the database.

Together they significantly improve performance.

---

# Easy Comparison

| Service             | Speeds up                          |
| ------------------- | ---------------------------------- |
| **CloudFront**      | Users → Website                    |
| **ElastiCache**     | Application → Database             |
| **Storage Gateway** | Hybrid storage                     |
| **RDS Multi-AZ**    | High availability, not performance |
| **Read Replica**    | Database read scaling              |

# Final Memory Trick

Think of a library:

* **CloudFront** = Many small local libraries around the world that keep copies of popular books close to readers.
* **ElastiCache** = The librarian keeps the most requested books on the front desk instead of going to the storage room every time.
* **RDS Multi-AZ** = A backup library that opens only if the main library fails.
* **Read Replica** = An extra reading room where people can read the same books simultaneously.

### ✅ Correct Answers

* **Amazon CloudFront** — speeds up delivery for global users by caching content at edge locations.
* **Amazon ElastiCache** — speeds up application performance by caching frequently accessed data in memory.
