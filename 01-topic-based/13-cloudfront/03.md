3. Question

Category: CSAA – Design Secure Architectures

A company has clients all across the globe that access product files stored in several Amazon S3 buckets, which are behind each of the respective Amazon CloudFront web distributions. The company currently wants to deliver content to a specific client, ensuring that only that client can access the data. At present, all clients can access the S3 buckets directly using an S3 URL or through the CloudFront distribution. The Solutions Architect must serve the private content via CloudFront only, to secure the distribution of files.

Which combination of actions should the Architect implement to meet the above requirements? (Select TWO.)

- Enable the Origin Shield feature of the CloudFront distribution to protect the files from unauthorized access.
- Create a custom CloudFront function to check and ensure that only their clients can access the files.
- `Require the users to access the private content by using special CloudFront signed URLs or signed cookies.`
- `Restrict access to files in the origin by creating an origin access control (OAC) and giving it permission to read the files in the bucket.`
- Generate an S3 presigned URL to ensure that only the client can access the files. Remove permission to use S3 URLs to read the files for anyone else.

# Step 1: Simplify the Question

The question is saying:

> "We have files stored in S3."

```
Users
   │
   ▼
CloudFront
   │
   ▼
S3 Bucket
```

Currently users can access files in **two ways**:

```
1. Through CloudFront ✅

2. Directly using the S3 URL ❌
```

Example:

```
https://mybucket.s3.amazonaws.com/image.jpg
```

The company **does NOT want this anymore.**

They want:

```
Users
   │
   ▼
CloudFront ONLY
   │
   ▼
S3
```

And they also want:

> Only authorized clients should be able to access the files.

So there are actually **two requirements**.

---

## Requirement 1

**Don't allow direct S3 access.**

Users should never reach S3 directly.

Only CloudFront should.

---

## Requirement 2

Even through CloudFront,

only authorized users should access the files.

---

# Step 2: Which AWS services solve each requirement?

## Requirement 1

Stop users from accessing S3 directly.

AWS solution:

✅ Origin Access Control (OAC)

Think:

```
S3 Bucket

↓

Who can read me?

Only CloudFront
```

Without OAC

```
Internet
    │
    ▼
S3

Everyone can access
```

With OAC

```
Internet
     X

CloudFront
     │
     ▼
S3
```

CloudFront becomes the **only door** to S3.

---

## Requirement 2

Only certain customers can use CloudFront.

AWS solution:

Signed URL

or

Signed Cookies

Exactly what we learned in the previous question.

---

# Therefore answer is

✅ OAC

AND

✅ Signed URL / Signed Cookies

---

# Think of a Shopping Mall

Imagine S3 is a warehouse.

```
Warehouse (S3)
```

CloudFront is the front reception.

```
Customer

↓

Reception (CloudFront)

↓

Warehouse
```

Without OAC

A customer can ignore reception.

```
Customer

↓

Warehouse
```

Not secure.

OAC locks the warehouse.

Only reception has the key.

---

Now suppose only VIP customers should enter.

Reception checks

```
Signed URL

or

Signed Cookie
```

If valid

```
Open door
```

Otherwise

```
Access Denied
```

# Why S3 Presigned URL is wrong?

Many students confuse these.

Suppose S3 Presigned URL:

```
https://bucket.s3.amazonaws.com/photo.jpg?token=abc
```

Notice something?

The URL still goes to

```
S3
```

NOT

```
CloudFront
```

The requirement says

> Serve private content **via CloudFront only**

That immediately eliminates S3 Presigned URLs.

---

# Why CloudFront Function is wrong?

CloudFront Functions are for lightweight logic like:

* redirect URLs
* add headers
* rewrite paths
* modify requests

They are **not** the AWS feature for private content access.

AWS already provides:

* Signed URLs
* Signed Cookies

Use the built-in feature.

---

# Why Origin Shield is wrong?

Origin Shield is about:

* reducing requests to S3
* caching
* performance
* lower origin load

It is **NOT** an access control feature.

---

# Exam Trick

Whenever you see:

> Users should NOT access S3 directly

Immediately think:

✅ **Origin Access Control (OAC)**

---

Whenever you see:

> Only authenticated users should access CloudFront

Think:

✅ **Signed URL**

or

✅ **Signed Cookies**

---

# Final Architecture

```
                 User
                  │
                  │ Signed URL/Cookie
                  ▼
            CloudFront
                  │
             (OAC)
                  │
                  ▼
              S3 Bucket
```

* **Signed URL/Cookies** → Decide **who** can access the content.
* **Origin Access Control (OAC)** → Ensures **how** the content is accessed (only through CloudFront, never directly from S3).

---

## 🎯 CloudFront Decision Table

| Requirement                                                  | AWS Service                     |
| ------------------------------------------------------------ | ------------------------------- |
| Deliver content globally                                     | CloudFront                      |
| Prevent direct S3 access                                     | **Origin Access Control (OAC)** |
| One private file                                             | Signed URL                      |
| Many private files                                           | Signed Cookies                  |
| Improve cache/origin performance                             | Origin Shield                   |
| Temporary direct access to an S3 object (without CloudFront) | S3 Presigned URL                |
