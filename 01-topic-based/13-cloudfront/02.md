2. Question

Category: CSAA – Design Secure Architectures

A company has a web application that uses Amazon CloudFront to distribute its images, videos, and other static content stored in its Amazon S3 bucket to users around the world. The company has recently introduced a new member-only access feature for some of its high-quality media files. There is a requirement to provide access to multiple private media files only to paying subscribers without having to change the current URLs.

Which of the following is the most suitable solution to implement to satisfy this requirement?

- Create a Signed URL with a custom policy which only allows the members to see the private files.
- Configure your CloudFront distribution to use Field-Level Encryption to protect your private data and only allow access to members.

- `Use Signed Cookies to control who can access the private files in your CloudFront distribution by modifying your application to determine whether a user should have access to your content. For members, send the required Set-Cookie headers to the viewer which will unlock the content only to them.`
- Configure your CloudFront distribution to use Match Viewer as its Origin Protocol Policy which will automatically match the user request. This will allow access to the private content if the request is a paying member and deny it if it is not a member.

Excellent. This is one of the highest-yield CloudFront questions in SAA. There are only **two concepts** you need to master.

---

# CloudFront Private Content

Suppose you have a website:

```
Netflix.com
```

Some videos are free.

Some videos are only for Premium users.

How do you stop everyone from accessing Premium videos?

CloudFront provides **2 methods**.

---

# Method 1 — Signed URL

Think:

> "One file"

Example:

```
download.pdf
```

or

```
movie.mp4
```

You generate a unique URL:

```
https://cdn.example.com/movie.mp4?signature=abc123
```

Only that URL works.

After expiry:

```
Access Denied
```

Perfect for

* download one file
* invoice
* report
* software installer

---

## Example

User buys

```
terraform-course.zip
```

Generate

```
Signed URL
```

Valid for 24 hours.

After 24 hours

No access.

---

# Method 2 — Signed Cookies

Think:

> "Many files"

Instead of signing every URL...

CloudFront checks browser cookies.

Example

User logs in.

Application returns

```
Set-Cookie
```

Browser stores it.

Now user can access

```
image1.jpg

video1.ts

video2.ts

video3.ts

manifest.m3u8

pdf1.pdf

ebook.pdf
```

No URL changes.

CloudFront simply checks

```
Cookie valid?

YES → Allow

NO → Deny
```

---

# Why Signed Cookies here?

Question says

> multiple private media files

and

> don't change existing URLs

Exactly what Signed Cookies solve.

Imagine Netflix.

Thousands of video chunks.

Changing every URL is impossible.

Just login once.

Browser gets cookie.

Everything works.

---

# Why not Signed URL?

Because

Signed URL

↓

```
file1
```

Need URL 1

```
file2
```

Need URL 2

```
file3
```

Need URL 3

```
file4
```

Need URL 4

Very inefficient.

---

# Easy Exam Rule

### One file

✅ Signed URL

---

### Many files

✅ Signed Cookies

---

### Existing URLs must remain unchanged

✅ Signed Cookies

---

### Client doesn't support cookies

✅ Signed URL

---

# Why others are wrong

### Field-Level Encryption ❌

People confuse this often.

Field-Level Encryption

≠ Access control

It protects **sensitive fields submitted by users**.

Example

```
Credit Card

SSN

Passport Number
```

during upload to your application.

It has nothing to do with downloading private files.

---

### Match Viewer ❌

This only decides

CloudFront ↔ Origin communication

```
Viewer uses HTTPS

↓

CloudFront also uses HTTPS
```

or

```
Viewer uses HTTP

↓

CloudFront uses HTTP
```

It is **not authentication**.

---

# CloudFront Private Content Cheat Sheet

| Requirement                                 | Use                                                              |
| ------------------------------------------- | ---------------------------------------------------------------- |
| Single file                                 | ✅ Signed URL                                                     |
| Multiple files                              | ✅ Signed Cookies                                                 |
| Keep existing URLs                          | ✅ Signed Cookies                                                 |
| Downloads without cookies                   | ✅ Signed URL                                                     |
| Protect form fields (credit card, SSN)      | ✅ Field-Level Encryption                                         |
| HTTP vs HTTPS between CloudFront and origin | ✅ Origin Protocol Policy (Match Viewer / HTTP Only / HTTPS Only) |

---

## 🎯 CloudFront Exam Memory

* **CloudFront + S3** → Global content delivery (CDN)
* **Private content (one file)** → **Signed URL**
* **Private content (many files / no URL changes)** → **Signed Cookies**
* **Protect sensitive form fields** → **Field-Level Encryption**
* **DDoS protection** → **AWS WAF + Rate-based rules** (often with CloudFront, plus AWS Shield)
* **Origin = ALB** → Dynamic web applications
* **Origin = S3** → Static websites, images, CSS, JavaScript

These are the CloudFront concepts that appear most frequently on the SAA exam. Once you're comfortable with these patterns, you'll recognize the correct answer almost immediately.
