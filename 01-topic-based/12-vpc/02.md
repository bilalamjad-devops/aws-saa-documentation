2. Question

Category: CSAA – Design Secure Architectures

An insurance company utilizes SAP HANA for its day-to-day ERP operations. Since it can’t migrate this database due to customer preferences, it needs to integrate it with the current AWS workload in the VPC, in which it is required to establish a site-to-site VPN connection.

What needs to be configured outside of the VPC for an AWS Virtual Private Network connection to succeed?

- A dedicated NAT instance in a public subnet
- An EIP to the Virtual Private Gateway
- `An Internet-routable IP address (static) of the customer gateway's external interface for the on-premises network`
- The main route table in your VPC to route traffic through a NAT instance


Bilal, this is **completely normal**. VPC is probably the hardest topic in the SAA exam because it introduces networking services that many people have never used in real life.

The mistake many courses make is they teach the services first. I prefer teaching the **problem first**, then the AWS service.

---

# Think like a company

Suppose your company has this:

```text
Office (Pakistan)

|
|  Employees
|  Database
|  SAP Server
|
```

Then you start using AWS.

```text
Office ---------------- AWS
```

Now ask:

> "How can these two places communicate?"

AWS has **three major answers**.

---

# 1. VPC Peering (AWS ↔ AWS)

Imagine your company has **two AWS networks**.

```text
VPC A        VPC B
```

You want EC2 in A to talk to EC2 in B.

AWS solution:

```text
VPC A <-------> VPC B

      VPC Peering
```

Notice:

Both are inside AWS.

No office involved.

### Think

> AWS network ↔ AWS network

= **VPC Peering**

---

# 2. Site-to-Site VPN (Office ↔ AWS)

Now your office still has servers.

```text
Office

SAP Server
Database
```

You also have AWS.

```text
Office ---------------- AWS VPC
```

You want them connected securely over the Internet.

AWS solution:

```text
Office ==== Encrypted VPN ==== AWS
```

This is called

**Site-to-Site VPN**

Think:

> Office ↔ AWS

---

# 3. Direct Connect (Office ↔ AWS)

Now suppose you're a bank.

You don't trust the public Internet.

Instead, AWS installs a **private fiber cable**.

```text
Office ================= AWS

Private cable
```

This is

**Direct Connect**

Very fast.

Very expensive.

---

# Now let's understand the gateways

People get scared by these names.

Don't memorize them.

Think of them as **doors**.

---

## Your Office

Every office has a router.

```text
Office

Router
```

AWS calls this

**Customer Gateway**

Because

You are the customer.

```text
Office

Router

↓

Customer Gateway
```

Same thing.

---

## AWS Side

AWS also needs a router.

```text
AWS VPC

Router
```

AWS calls it

**Virtual Private Gateway**

```text
AWS Router

↓

Virtual Private Gateway
```

Again,

it's basically AWS's router.

---

# So the VPN becomes

```text
Office Router

(Customer Gateway)

       ||

Encrypted Tunnel

       ||

AWS Router

(Virtual Private Gateway)
```

That's all.

No magic.

Just two routers talking securely.

---

# Why does AWS ask for a Static Public IP?

Imagine someone wants to call you.

They need your phone number.

AWS also needs to know

> Which office should I connect to?

Your office router has

```text
203.0.113.25
```

AWS stores that.

Now AWS knows where your office is.

---

# Easy Story

Imagine AWS is your friend.

Your friend asks:

> "Where is your office?"

You reply:

```text
203.0.113.25
```

AWS says

"Great, I'll connect there."

That's why the Customer Gateway needs a **public static IP**.

| ------------------------------------- | ---------------- |

| Office ↔ AWS                          | Site-to-Site VPN |
| Office ↔ AWS (private dedicated line) | Direct Connect   |

## My suggestion

Don't rush into solving more VPC questions yet. Spend **20–30 minutes** understanding this basic architecture. Once you clearly understand **VPC Peering, Site-to-Site VPN, Customer Gateway, Virtual Private Gateway, Internet Gateway, and NAT Gateway**, you'll find that nearly all VPC exam questions are just different combinations of these building blocks rather than completely new topics.

This question looks difficult because of the VPN terminology, but it's actually testing **one concept only**:

> **What exists on the customer's (on-premises) side?**

---

# Step 1: Understand the architecture

The company has:

* AWS VPC
* On-premises data center (SAP HANA)

They want a VPN.

Diagram:

```text
On-Premises                     AWS

+-------------+            +-------------+
| SAP HANA    |            |     VPC     |
|             |            |             |
| Customer    |============| Virtual     |
| Gateway     |   VPN      | Private     |
|             |            | Gateway     |
+-------------+            +-------------+
```

Notice there are **2 gateways**.

---

# AWS Side

AWS provides:

✅ **Virtual Private Gateway (VGW)**

Attached to your VPC.

---

# Customer Side

Your company provides:

✅ **Customer Gateway (CGW)**

This is your firewall/router.

Examples:

* Cisco router
* Fortinet firewall
* Palo Alto firewall

---

# The important requirement

AWS must know

> **Where is your company?**

How?

By using your router's **public static IP address**.

Example:

```text
Office Router

203.0.113.25
```

AWS connects to that IP.

---

# Therefore

AWS asks:

> What's your Customer Gateway IP?

You answer:

```text
203.0.113.25
```

VPN tunnel is created.

---

# Correct Answer

✅ **An Internet-routable IP address (static) of the customer gateway's external interface.**

Translation:

Your on-premises router/firewall must have a **public static IP**.

---

# Why not the others?

## ❌ NAT Instance

NAT Gateway/Instance is for:

```text
Private EC2
     │
     ▼
Internet
```

It has **nothing to do with VPNs**.

---

## ❌ Elastic IP on Virtual Private Gateway

AWS does **not** ask you to attach an Elastic IP to a VGW.

AWS manages the VPN endpoints.

---

## ❌ Route traffic through NAT Instance

Again,

NAT ≠ VPN

Different services.

---

# Easy Memory Trick

Think of a phone call.

AWS wants to call your office.

What does AWS need?

Your office phone number.

```text
AWS

calls

203.0.113.25
```

That "phone number" is your **Customer Gateway public static IP**.

Without it,

AWS doesn't know where to connect.

# Components of Site-to-Site VPN

```text
On-Premises                    AWS

Customer Gateway  =====VPN=====  Virtual Private Gateway
        │                              │
 Public Static IP                 Attached to VPC
```

Remember:

* **Customer Gateway (CGW)** = Your router/firewall (on-premises)
* **Virtual Private Gateway (VGW)** = AWS gateway attached to the VPC

---

# Exam Memory Rules

| Keyword                    | Answer                                           |
| -------------------------- | ------------------------------------------------ |
| Connect VPC to on-premises | Site-to-Site VPN                                 |
| AWS side                   | Virtual Private Gateway (VGW)                    |
| On-premises side           | Customer Gateway (CGW)                           |
| Customer Gateway needs     | **Public static IP address**                     |
| NAT                        | Internet access for private subnets, **not** VPN |

---

## One-Line Memory Rule

> **For an AWS Site-to-Site VPN, AWS uses a Virtual Private Gateway on the AWS side and a Customer Gateway with a public static IP on the on-premises side.**
