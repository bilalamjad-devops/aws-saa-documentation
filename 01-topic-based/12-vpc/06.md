6. Question

Category: CSAA – Design Secure Architectures

A company hosted a web application on a Linux Amazon EC2 instance in the public subnet that uses a non-default network ACL. The instance uses a default security group and has an attached Elastic IP address. The network ACL is configured to block all inbound and outbound traffic. The Solutions Architect must allow incoming traffic on port 443 to access the application from any source.

Which combination of steps will accomplish this requirement? (Select TWO.)


- In the Security Group, create a new rule to allow TCP connection on port 443 to destination 0.0.0.0/0

- In the Network ACL, update the rule to allow outbound TCP connection on port 32768 - 65535 to destination 0.0.0.0/0

- `In the Network ACL, update the rule to allow inbound TCP connection on port 443 from source 0.0.0.0/0 and outbound TCP connection on port 32768 - 65535 to destination 0.0.0.0/0`
- `In the Security Group, add a new rule to allow TCP connection on port 443 from source 0.0.0.0/0`
- In the Network ACL, update the rule to allow both inbound and outbound TCP connection on port 443 from source 0.0.0.0/0 and to destination 0.0.0.0/0


That's completely normal. In fact, **most people who build small AWS projects rarely touch Network ACLs**.

Here's what you'll find in the real world:

* **Security Groups (SG):** Used every day. Every EC2, ALB, RDS, Lambda (in a VPC), and EKS cluster uses them.
* **Network ACLs (NACLs):** Much less common. Many AWS environments leave the **default NACL** in place and never modify it.

The **SAA exam**, however, loves NACL questions because they test whether you understand AWS networking.

## Think of a company building

Imagine this building.

```text
Street

↓

Main Gate

↓

Office Door

↓

Employee
```

The **Main Gate** is the **Network ACL**.

The **Office Door** is the **Security Group**.

To reach the employee:

* The main gate must allow you.
* The office door must also allow you.

If either says "No," you can't enter.

---

## The only difference you need to know

### Security Group (Door)

The guard remembers you.

You enter.

When leaving, he says:

> "I remember you came in. Go ahead."

No extra check.

This is called **stateful**.

---

### Network ACL (Main Gate)

The guard has no memory.

When you enter:

> "Show your ID."

When you leave:

> "Show your ID again."

This is called **stateless**.

So you need **both inbound and outbound rules**.

| Feature        | Security Group | Network ACL                |
| -------------- | -------------- | -------------------------- |
| Attached to    | EC2/ENI        | Subnet                     |
| Stateful?      | ✅ Yes          | ❌ No                       |
| Allow rules    | ✅ Yes          | ✅ Yes                      |
| Deny rules     | ❌ No           | ✅ Yes                      |
| Return traffic | Automatic      | Must be allowed explicitly |

This table alone answers a lot of SAA questions.

## What you actually need for SAA

Don't study every NACL feature.

Just remember these four facts:

1. **Security Group = Stateful**
2. **Network ACL = Stateless**
3. **NACL works at the subnet level**
4. **NACL supports both Allow and Deny rules**

That's enough for most exam questions.

# Step 1: Draw the architecture

```text
Internet
    │
    ▼
Network ACL
    │
    ▼
Security Group
    │
    ▼
EC2 (HTTPS Web Server)
```

The traffic must pass through **both**:

* Network ACL
* Security Group

If either blocks it, the connection fails.

---

# Step 2: Read the important sentence

The question says:

> **The Network ACL blocks ALL inbound and outbound traffic.**

That is the biggest clue.

It means:

```text
Inbound = DENY ❌

Outbound = DENY ❌
```

Nothing passes.

---

# Step 3: Security Group

The EC2 uses the **default Security Group**.

Default SG:

```text
Outbound:
Allow ALL
```

So we only need to add:

```text
Inbound

HTTPS (443)

Source:
0.0.0.0/0
```

That's answer #1.

---

# Step 4: Why isn't that enough?

Because the Network ACL still says

```text
Inbound = DENY

Outbound = DENY
```

Remember:

Traffic reaches the NACL **before** the Security Group.

---

# Step 5: The tricky part (Ephemeral Ports)

Suppose your laptop connects.

```text
Laptop

Port 55000
      │
      ▼
EC2

Port 443
```

Notice:

The client (your laptop) chooses a **random port**.

Example:

```text
55000
```

That is called an **ephemeral port**.

---

The request looks like

```text
Laptop

55000
      │
      ▼
443

EC2
```

Now EC2 sends the response.

```text
EC2

443
      │
      ▼
55000

Laptop
```

The response goes **back to the client's random port**.

That is why the Network ACL must allow:

```text
Outbound

32768-65535
```

Otherwise the response gets blocked.

---

# Why only outbound ephemeral ports?

Because EC2 is acting as the **server**.

Clients connect **to 443**.

Responses go back to the client's random port.

Therefore

Inbound

```text
443
```

Outbound

```text
32768-65535
```

---

# Why not outbound 443?

Many students choose this.

Think about the return traffic.

The return packet isn't going to

```text
Laptop:443
```

It goes to

```text
Laptop:55000
```

So opening outbound 443 does nothing.

---

# Security Group vs Network ACL

This question exists mainly to test this table.

| Security Group                       | Network ACL                               |
| ------------------------------------ | ----------------------------------------- |
| Stateful                             | Stateless                                 |
| Return traffic automatically allowed | Return traffic must be explicitly allowed |
| Usually configure inbound only       | Often configure both inbound and outbound |

---

# Why SG only needs inbound?

Security Groups are **stateful**.

You allow

```text
Inbound

443
```

AWS automatically allows

```text
Outbound response
```

No extra rule required.

---

# Why NACL needs both?

Network ACLs are **stateless**.

AWS forgets every packet.

So you must allow

Inbound

```text
443
```

AND

Outbound

```text
32768-65535
```

# Easy Memory Trick

**Security Group = Smart Security Guard**

He remembers who entered.

So when someone leaves,

he lets them out automatically.

---

**Network ACL = Gate with No Memory**

Every person entering or leaving is checked separately.

So you need two rules:

* Allow entry (443)
* Allow exit (ephemeral ports)

---

# ⭐ Cheat Sheet for the Exam

| Service | Security Group | Network ACL                      |
| ------- | -------------- | -------------------------------- |
| HTTP    | Inbound 80     | Inbound 80 + Outbound Ephemeral  |
| HTTPS   | Inbound 443    | Inbound 443 + Outbound Ephemeral |
| SSH     | Inbound 22     | Inbound 22 + Outbound Ephemeral  |

If you remember just one sentence for the exam, make it this:

> **Security Groups are stateful (return traffic is automatic). Network ACLs are stateless (you must explicitly allow both directions, including ephemeral ports for responses).**
