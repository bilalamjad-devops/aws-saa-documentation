This is actually one of the **easiest Security Group questions**. The screenshots make it look difficult, but the examiner is testing just one idea.

---

# Step 1: Read the clues

The question says:

> ✅ You can SSH into the EC2 instance.

But

> ❌ You cannot open the website in Chrome.

---

# Step 2: What does SSH tell us?

SSH uses:

```text
Port 22
```

If SSH works:

* EC2 is running ✅
* Route Table is correct ✅
* Internet Gateway is working ✅
* Public IP exists ✅

So networking is **already working**.

---

# Step 3: What does Chrome use?

A web browser uses:

```text
HTTP = Port 80

or

HTTPS = Port 443
```

If HTTP isn't allowed,

the browser cannot reach the web server.

---

# Imagine the Security Group

Suppose it looks like:

```text
Inbound Rules

SSH (22)    ✔

HTTP (80)   ❌ Missing
```

Then

```text
Laptop

↓

SSH

↓

EC2

Works
```

But

```text
Laptop

↓

HTTP

↓

Blocked by Security Group
```

---

# The fix

Simply add

```text
Inbound Rule

HTTP

Port 80

Source:
0.0.0.0/0
```

Now

```text
Chrome

↓

HTTP

↓

EC2

↓

Apache/Nginx

Website opens
```

---

# Why not modify the Route Table?

The question tricks students into changing networking.

But remember:

> **SSH already works.**

If the Route Table were wrong,

SSH would also fail.

So don't touch it.

---

# Why not remove SSH?

Removing SSH only makes things worse.

It doesn't help the website.

---

# Exam Shortcut

Whenever you see:

```text
SSH works

Website doesn't
```

Think:

> **Security Group is missing HTTP (80) or HTTPS (443).**

---

# Real-life analogy

Your house has two doors.

Door 1

```text
SSH
```

Door 2

```text
HTTP
```

The SSH door is unlocked.

The HTTP door is locked.

The solution isn't to build a new road (Route Table).

It's simply to unlock the second door.

---

# Exam Cheat Sheet

| Situation                  | Answer                                                    |
| -------------------------- | --------------------------------------------------------- |
| SSH works, Website doesn't | Add HTTP (80) inbound rule                                |
| Website uses HTTPS         | Add HTTPS (443) inbound rule                              |
| Nothing works              | Check Route Table, Internet Gateway, NACL, Security Group |
| SSH doesn't work           | Check port 22 rule                                        |

---

## ⭐ Golden Rule for the SAA exam

Always use the **working connection** as a clue.

* **SSH works** → Routing, Internet Gateway, and public connectivity are already fine.
* **Ping works but HTTP doesn't** → Check Security Group or the web server.
* **Nothing works** → Start investigating networking (Route Tables, IGW, NACLs, Security Groups).

In this question, because SSH already succeeds, the only missing piece is the **HTTP inbound rule (port 80)** in the Security Group.
