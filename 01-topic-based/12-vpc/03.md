3. Question

Category: CSAA – Design Resilient Architectures

A company has multiple VPCs with IPv6 enabled for its suite of web applications. The Solutions Architect attempted to deploy a new Amazon EC2 instance but encountered an error indicating that there were no available IP addresses on the subnet. The VPC has a combination of IPv4 and IPv6 CIDR blocks, but the IPv4 CIDR blocks are nearing exhaustion. The architect needs a solution that will resolve this issue while allowing future scalability.

How should the Solutions Architect resolve this problem?

- Set up a new IPv4 subnet with a larger CIDR range. Associate the new subnet with the VPC and then launch the instance.
- `Set up a new IPv6-only subnet with a large CIDR range. Associate the new subnet with the VPC then launch the instance.`
- Disable the IPv4 support in the VPC and use the available IPv6 addresses.
- Ensure that the VPC has IPv6 CIDRs only. Remove any IPv4 CIDRs associated with the VPC.

This is actually a **new-type question** that is more difficult than the usual SAA questions. Don't worry if it feels confusing.

The examiner is testing only **one idea**:

> **IPv4 addresses are running out. What should you do?**

---

# Step 1: Understand the problem

The company has a VPC.

```text
VPC
│
├── Subnet A
├── Subnet B
├── Subnet C
```

Each subnet has IP addresses.

Example:

```
10.0.1.0/24
```

A `/24` subnet has **256 IP addresses** (AWS reserves a few, so you get fewer usable ones).

Now imagine almost all IPs are already assigned.

```
10.0.1.5   → EC2
10.0.1.6   → EC2
10.0.1.7   → EC2
...
10.0.1.250 → EC2

No IPs left
```

Now you launch another EC2.

AWS says:

❌ **No available IP addresses.**

---

# Step 2: The important sentence

The question says:

> **The VPC already has IPv6 enabled.**

This is the clue.

AWS is telling you:

> "Why are you trying to use more IPv4? You already have IPv6."

---

# Step 3: Why not create another IPv4 subnet?

This looks tempting.

```
Old subnet

10.0.1.0/24
```

Create

```
10.0.2.0/24
```

Works?

Yes.

Best solution?

No.

Why?

Because IPv4 is limited.

Eventually

```
10.0.3.0
10.0.4.0
10.0.5.0
```

will also run out.

The question says:

> **future scalability**

IPv4 is **not** the long-term answer.

---

# Step 4: Why IPv6?

IPv6 has an enormous address space.

Think of it like this:

IPv4

```
Small parking lot
```

IPv6

```
Huge city full of parking lots
```

You'll never realistically run out.

---

# Correct Solution

Create a new subnet that only uses IPv6.

```
VPC

├── IPv4 subnet
├── IPv4 subnet
├── IPv6-only subnet   ← New
```

Launch the EC2 there.

Done.

---

# Why not disable IPv4?

AWS VPC is built around IPv4.

You **cannot** disable IPv4.

Think of IPv4 as the foundation.

IPv6 is an additional capability.

---

# Why not remove IPv4?

Same reason.

AWS does not let you have an IPv6-only VPC.

A VPC always has IPv4.

You **can** have:

```
VPC

IPv4

+

IPv6
```

You **cannot** have:

```
VPC

IPv6 only
```

---

# Memory Trick

Think of roads.

Old city:

```
IPv4

Small roads

Traffic jams
```

New city:

```
IPv6

Massive highways

No traffic
```

AWS says:

> Build new houses on the new highway.

Don't keep squeezing them into the old roads.

---

# Exam Cheat Sheet

| Situation                       | Answer                |
| ------------------------------- | --------------------- |
| IPv4 addresses exhausted        | Use IPv6 if available |
| VPC supports both IPv4 and IPv6 | Called **Dual Stack** |
| Can a VPC be IPv6 only?         | ❌ No                  |
| Can a subnet be IPv6 only?      | ✅ Yes                 |
| Future scalability              | IPv6                  |

---

## One thing for the exam

You do **not** need to memorize IPv6 addresses like:

```
2001:db8:85a3:0000:0000:8a2e:0370:7334
```

The SAA exam almost never asks you to work with IPv6 address formats. It only expects you to know **when to choose IPv6**.

## Easy Rule to Remember

* **VPC** → must have **IPv4** (it can also have IPv6).
* **Subnet** → can be **IPv4**, **dual-stack**, or **IPv6-only**.
* If the question says **"IPv4 is exhausted"** and **"future scalability"**, the expected answer is almost always **create an IPv6-only subnet**.
