7. Question

Category: CSAA – Design Secure Architectures

A media company has two VPCs: VPC-1 and VPC-2 with peering connection between each other. VPC-1 only contains private subnets while VPC-2 only contains public subnets. The company uses a single AWS Direct Connect connection and a virtual interface to connect their on-premises network with VPC-1.

Which of the following options increase the fault tolerance of the connection to VPC-1? (Select TWO.)

- `Establish a hardware VPN over the Internet between VPC-1 and the on-premises network.`
- Establish a hardware VPN over the Internet between VPC-2 and the on-premises network.
- `Establish another AWS Direct Connect connection and private virtual interface in the same AWS region as VPC-1.`
- Establish a new AWS Direct Connect connection and private virtual interface in the same region as VPC-2.
- Use the AWS VPN CloudHub to create a new AWS Direct Connect connection and private virtual interface in the same region as VPC-2.

This is one of the **hardest VPC questions** in SAA because it combines **VPC Peering + Direct Connect + Site-to-Site VPN + Edge-to-Edge Routing**.

Don't worry if it feels difficult. Let's simplify it.

---

# Step 1: Draw the architecture

```text
               On-Premises
                     │
              Direct Connect
                     │
                 VPC-1
             (Private Subnets)
                     │
            VPC Peering
                     │
                 VPC-2
             (Public Subnets)
```

Notice:

* On-premises is connected **only** to **VPC-1**.
* VPC-2 is connected to VPC-1 only through **VPC Peering**.

---

# Step 2: What does the company want?

The question asks:

> **Increase fault tolerance of the connection to VPC-1.**

This means:

> "If Direct Connect fails, how can we still reach VPC-1?"

---

# Answer 1

✅ **Create another Direct Connect to VPC-1**

```text
          On-Prem
          /     \
      DX1       DX2
        \       /
         VPC-1
```

If one Direct Connect fails,

the second one continues working.

Easy.

---

# Answer 2

✅ **Create a Site-to-Site VPN to VPC-1**

```text
          On-Prem
             │
      Direct Connect
             │
          VPC-1

             ▲
             │
      Site-to-Site VPN
```

If Direct Connect dies,

traffic automatically uses VPN.

AWS even recommends this as a backup architecture.

---

# Why NOT connect to VPC-2?

Many students think:

> "VPC-2 is peered with VPC-1, so I'll connect there."

This is where AWS says:

> **No.**

---

## The Golden Rule

### ❌ VPC Peering is NOT transitive.

Think of it like this.

```
A ---- B ---- C
```

A can talk to B.

B can talk to C.

Can A talk to C?

**NO.**

AWS blocks it.

---

In this question:

```
On-Prem
    │
    ▼
 VPC-1
    │
    ▼
 VPC-2
```

If Direct Connect is attached to VPC-2,

traffic cannot travel

```
On-Prem

↓

VPC-2

↓

VPC-1
```

because that is **edge-to-edge routing**, which VPC Peering does **not** support.

---

# AWS calls this...

**Edge-to-Edge Routing**

This is an exam favorite.

VPC Peering **cannot** forward:

* Internet Gateway traffic
* NAT Gateway traffic
* VPN traffic
* Direct Connect traffic
* Gateway Endpoint traffic

If you see:

> "Can I use VPC-A's Internet Gateway from VPC-B?"

Answer:

❌ No

---

# Real Example

Suppose:

```
VPC-A

↓

Internet Gateway
```

VPC-B is peered.

Can EC2 inside VPC-B access the Internet using VPC-A's Internet Gateway?

❌ No.

Exactly the same rule.

---

# Same for Direct Connect

```
On-Prem

↓

Direct Connect

↓

VPC-1

↓

Peering

↓

VPC-2
```

Can VPC-2 use that Direct Connect?

❌ No.

---

# Same for VPN

```
On-Prem

↓

VPN

↓

VPC-1

↓

Peering

↓

VPC-2
```

Can VPC-2 use that VPN?

❌ No.

---

# Memory Trick

Whenever you see:

```
VPC Peering
```

Immediately think:

> **No Transitive Routing**

or

> **No Edge-to-Edge Routing**

Those two phrases answer many SAA networking questions.

---

# Exam Shortcut

If the question says:

> Increase fault tolerance for **VPC-1**

then the backup must connect **directly to VPC-1**, not to a peered VPC.

So the correct answers are:

✅ Hardware VPN → **VPC-1**

✅ Another Direct Connect → **VPC-1**

---

## Cheat Sheet

| Connection                         | Can VPC Peering Forward It? |
| ---------------------------------- | --------------------------- |
| Internet Gateway                   | ❌ No                        |
| NAT Gateway                        | ❌ No                        |
| Site-to-Site VPN                   | ❌ No                        |
| Direct Connect                     | ❌ No                        |
| Gateway VPC Endpoint (S3/DynamoDB) | ❌ No                        |

---

### One sentence to remember for the exam

> **VPC Peering is one-to-one only. It is not transitive and does not support edge-to-edge routing. If a backup connection is needed, connect it directly to the target VPC, not through another peered VPC.**
