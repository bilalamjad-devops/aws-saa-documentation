
1. Question

Category: CSAA – Design Resilient Architectures

A large insurance company has an AWS account that contains three VPCs (DEV, UAT and PROD) in the same region. UAT is peered to both PROD and DEV using a VPC peering connection. All VPCs have non-overlapping CIDR blocks. The company wants to push minor code releases from Dev to Prod to speed up time to market.

Which of the following options helps the company accomplish this?

- Create a new entry to PROD in the DEV route table using the VPC peering connection as the target.
- Change the DEV and PROD VPCs to have overlapping CIDR blocks to be able to connect them.
- `Create a new VPC peering connection between PROD and DEV with the appropriate routes.`
- Do nothing. Since these two VPCs are already connected via UAT, they already have a connection to each other.

Excellent! This is one of the **most frequently tested VPC concepts** in the SAA exam.

The entire question is testing **one rule only**:

> **VPC Peering is NOT transitive.**

If you remember this one sentence, you'll solve many questions.

---

# Step 1: Draw the architecture

Current setup:

```text
        DEV
         |
    Peering
         |
        UAT
         |
    Peering
         |
       PROD
```

Notice:

* DEV ↔ UAT ✅
* UAT ↔ PROD ✅
* DEV ↔ PROD ❌

---

# What does the company want?

They want

```text
DEV  --------->  PROD
```

to send code directly.

---

# Most students think

> DEV is connected to UAT.

> UAT is connected to PROD.

So DEV should reach PROD.

Sounds logical.

But AWS says...

❌ **No.**

---

# Why?

Because **VPC Peering is NOT transitive.**

Think of it like friendship.

```
You ↔ Ahmed

Ahmed ↔ Ali
```

Does that automatically make you connected to Ali?

❌ No.

You need your own connection.

Same in AWS.

---

# AWS Rule

VPC Peering only works between the **two VPCs that are directly peered.**

```
DEV ←→ UAT
```

Only these two communicate.

```
UAT ←→ PROD
```

Only these two communicate.

Traffic cannot pass through UAT.

---

# Correct Solution

Create another peering connection.

```text
        DEV
       /   \
      /     \
   Peer     Peer
    /         \
  UAT ------- PROD
```

Now

DEV ↔ PROD

works directly.

---

# Correct Answer

✅ **Create a new VPC peering connection between PROD and DEV with the appropriate routes.**

---

# Why not Option 1?

> Create a route from DEV to PROD.

Students often choose this.

But ask yourself:

**Route through what?**

There is **no peering connection** between DEV and PROD.

A route cannot magically create connectivity.

Think of roads.

```
City A

City B
```

If there is no bridge,

painting a new road on the map won't help.

You must build the bridge first.

The bridge = **VPC Peering**

The road = **Route Table**

Bridge first.

Then route.

---

# Why not Option 2?

It says:

> Make overlapping CIDRs.

Example

```
DEV

10.0.0.0/16

PROD

10.0.0.0/16
```

AWS does **not** allow peering when CIDRs overlap.

Correct design:

```
DEV

10.0.0.0/16

PROD

10.1.0.0/16
```

Different CIDRs.

---

# Why not Option 4?

This is the biggest trap.

```
DEV

↓

UAT

↓

PROD
```

Looks connected.

But AWS blocks this.

This is called

> **Transitive Routing**

AWS does **not** allow transitive VPC peering.

---

# Exam Memory Trick

Imagine three houses.

```
House A ---- House B ---- House C
```

You can visit B.

B can visit C.

Can you walk through B's house to reach C?

AWS says

❌ No.

You must build another road.

```
A ---------------- C
```

---

# Rules to Memorize

### Rule 1

✅ VPC Peering is **one-to-one**.

---

### Rule 2

❌ No transitive routing.

```
A ↔ B

B ↔ C

A ↔ C

NOT allowed
```

---

### Rule 3

❌ Overlapping CIDRs are not allowed.

```
10.0.0.0/16

10.0.0.0/16
```

Cannot peer.

---

### Rule 4

Routes alone cannot create connectivity.

Need:

1. Peering connection
2. Route tables

Both.

---

# Exam Cheat Sheet

| Scenario                            | Answer                            |
| ----------------------------------- | --------------------------------- |
| Two VPCs need private communication | VPC Peering                       |
| Three VPCs connected in a chain     | ❌ No transitive routing           |
| Need DEV ↔ PROD communication       | Create another peering connection |
| Overlapping CIDRs                   | ❌ Cannot peer                     |
| Added route but no peering          | ❌ Won't work                      |
| Peering created but no routes       | ❌ Won't work                      |

---

## One-Line Memory Rule

> **VPC Peering is direct only. It is not transitive, and both VPCs must have non-overlapping CIDR blocks and appropriate route table entries.**

This single concept appears very frequently in the SAA exam, sometimes with DEV/UAT/PROD, sometimes with multiple AWS accounts, but the underlying rule is always the same.
