2. Question

Category: CSAA – Design High-Performing Architectures

A software company has resources hosted in AWS and on-premises servers. You have been requested to create a decoupled architecture for applications which make use of both resources.

Which of the following options are valid? (Select TWO.)

- Use VPC peering to connect both on-premises servers and EC2 instances for your decoupled application
- Use RDS to utilize both on-premises servers and EC2 instances for your decoupled application
- `Use SQS to utilize both on-premises servers and EC2 instances for your decoupled application`
- Use DynamoDB to utilize both on-premises servers and EC2 instances for your decoupled application
- `Use SWF to utilize both on-premises servers and EC2 instances for your decoupled application`


Good! This question is actually testing **one keyword only**:

> **Decoupled architecture**

Once you know what "decouple" means, this question becomes very easy.

---

# Step 1: What is decoupling?

Suppose you have two applications.

Without SQS:

```text
App A ─────────► App B
```

If App B crashes...

```text
App A ─────X──► App B
```

App A also gets affected.

They are **tightly coupled**.

---

Now add SQS.

```text
App A
   │
   ▼
 SQS Queue
   │
   ▼
 App B
```

Now if App B crashes...

```text
App A
   │
   ▼
 SQS Queue (stores messages)
```

Messages wait safely.

When App B comes back, it continues processing.

That is **decoupling**.

---

# Step 2: Read the question

> Resources hosted in AWS and on-premises servers.

Notice this.

```text
On-Premises

↓

AWS
```

They want both systems to communicate.

Not directly.

Through a service.

That service should **decouple** them.

---

# Option A

> Use VPC Peering

❌ Wrong

Why?

Because VPC Peering only connects

```text
AWS VPC
      ↔
AWS VPC
```

It **cannot connect**

```text
On-Premises ↔ AWS
```

For on-premises you use:

* VPN
* Direct Connect

Not VPC Peering.

---

# Option B

> Use RDS

RDS is simply

```text
Database
```

It stores data.

It is **not** a message queue.

❌ Wrong.

---

# Option C

> Use SQS

YES ✅

Remember:

```text
Application

↓

SQS

↓

Application
```

Works perfectly.

Even if one application is on-premises.

Even if another is in AWS.

---

# Option D

> Use DynamoDB

Again

Database.

Not for decoupling.

❌ Wrong.

---

# Option E

> Use SWF

Also Correct.

---

# What is SWF?

SWF stands for

**Simple Workflow Service**

Think of it as a manager.

Imagine making a pizza.

```text
Step 1

↓

Step 2

↓

Step 3

↓

Done
```

SWF manages the workflow.

Example:

```text
Receive Order

↓

Validate Payment

↓

Prepare Pizza

↓

Deliver Pizza
```

SWF coordinates all these steps.

It can coordinate work between:

* EC2
* On-premises servers
* Applications
* Humans

So it is also a **decoupling service**.

---

# SQS vs SWF

This is enough for the exam.

| SQS                    | SWF                  |
| ---------------------- | -------------------- |
| Message Queue          | Workflow Service     |
| Stores messages        | Coordinates tasks    |
| Decouples applications | Decouples workflows  |
| Very common            | Rarely used nowadays |

---

# Why not databases?

People often think:

> "Applications share the same database, so they are decoupled."

No.

Database ≠ Queue.

For example:

```text
App A

↓

Database

↓

App B
```

App B still depends on reading the database correctly.

There is no message buffering.

No retries.

No asynchronous processing.

Databases store data.

Queues store work.

---

# Exam Shortcut 🚀

Whenever you see:

* Decouple applications
* Buffer requests
* Asynchronous communication
* Queue messages

👉 Think **SQS**.

If you see:

* Coordinate multiple tasks
* Workflow
* Human approval
* Step-by-step execution

👉 Think **SWF** (or, in modern AWS architectures, often Step Functions).

---

## One thing to remember for the SAA exam

Although **SWF** is technically a correct answer and still appears in some older practice questions, **AWS Step Functions** is the newer and more commonly used workflow orchestration service in modern architectures.

So remember:

* **SQS** → Queue messages between applications.
* **SWF / Step Functions** → Coordinate a sequence of tasks or a workflow.

For this question, the correct answers are:

✅ **Use SQS to utilize both on-premises servers and EC2 instances for your decoupled application.**

✅ **Use SWF to utilize both on-premises servers and EC2 instances for your decoupled application.**
