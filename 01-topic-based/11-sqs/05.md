5. Question

Category: CSAA – Design High-Performing Architectures

A company launched a website that accepts high-quality photos and turns the photos into a downloadable video montage. The website offers both a free and a premium account, with the premium account guaranteeing faster processing. All requests by both free and premium members go through a single Amazon SQS queue and are then processed by a group of Amazon EC2 instances that generate the videos. The company needs to ensure that premium users, who paid for the service, have higher priority than free members.

How should the company re-design its architecture to address this requirement?

- Use Amazon Kinesis to process the photos and generate the video montage in real-time.
- Use Amazon S3 to store and process the photos and then generate the video montage afterward.
- Create an SQS queue for free members and another one for premium members. Configure your EC2 instances to consume messages from the premium queue first and if it is empty, poll from the free members' SQS queue.
- For the requests made by premium members, set a higher priority in the SQS queue so it will be processed first compared to the requests made by free members.

Excellent. You're understanding SQS very well. This is actually one of the **most common AWS exam traps**.

---

# Step 1: What is the problem?

The company has:

```
Users
   │
   ▼
SQS Queue
   │
   ▼
EC2 Workers
```

Both **Free** and **Premium** users put requests into the **same queue**.

Example:

```
Queue

Free
Free
Premium
Free
Premium
```

SQS processes messages in arrival order (Standard Queue has best effort ordering, FIFO preserves order, but **neither supports priorities**).

So Premium users may wait behind Free users.

❌ Bad.

---

# Step 2: What does the company want?

They want:

> Premium users should always be processed first.

---

# Step 3: Student's first thought

Many students think:

> "Let's assign High Priority."

But...

### ❌ SQS has NO priority feature.

There is no such thing as:

```
Priority = High
Priority = Low
```

SQS simply doesn't support it.

This is a very famous exam trick.

---

# Step 4: AWS solution

Instead of one queue:

```
Queue
```

Create

```
Premium Queue

Free Queue
```

Now architecture becomes:

```
Premium Users
      │
      ▼
 Premium Queue
      │
      ▼
     EC2

Free Users
      │
      ▼
 Free Queue
      │
      ▼
     EC2
```

---

# Step 5: Even better

The worker checks Premium queue first.

```
while(true)

Check Premium Queue

↓

If message exists

Process it

↓

Otherwise

Check Free Queue
```

Example:

Premium Queue

```
Order 10
Order 11
```

Free Queue

```
Order 1
Order 2
Order 3
Order 4
```

Worker does:

```
Premium 10

Premium 11

Free 1

Free 2

Free 3
```

Premium customers always get faster service.

---

# Step 6: Why not one queue?

Because SQS cannot do:

```
Premium (Priority 10)

Free (Priority 1)
```

There is **no priority field**.

AWS says:

> Need priority?
>
> 👉 Use multiple queues.

---

# Why other options are wrong?

### ❌ Kinesis

Kinesis is for:

* Live streaming
* IoT
* Video streams
* Clickstreams

Not for prioritizing jobs.

---

### ❌ S3

S3 stores files.

It doesn't process jobs.

---

### ❌ Set higher priority in SQS

Sounds perfect.

But SQS simply **doesn't support message priority**.

This is the biggest exam trap.

---

# Exam keywords

If you see:

> Premium users

> VIP customers

> Paid customers

> Gold members

> Higher priority

Think immediately:

```
Multiple SQS Queues
```

NOT

```
One Queue + Priority
```

# SQS Cheat Sheet (so far)

| Requirement           | AWS Solution            |
| --------------------- | ----------------------- |
| Decouple applications | SQS                     |
| Notify many systems   | SNS → SQS Fanout        |
| Reduce empty polling  | Long Polling            |
| Worker crashes        | Visibility Timeout      |
| Failed messages       | Dead Letter Queue (DLQ) |
| Premium users first   | Multiple SQS queues     |
| Message priority      | ❌ Not supported in SQS  |
| Retry later           | Visibility Timeout      |
| Multiple consumers    | SNS + SQS               |

---

* ✅ Long Polling

* ✅ Message Filtering
* ✅ Visibility Timeout
* ✅ Multiple Queues for Priority

The remaining SQS questions are usually variations of these same concepts, so once these are solid, you'll recognize the patterns quickly.
