
3. Question

Category: CSAA – Design High-Performing Architectures

An insurance company plans to implement a message filtering feature in its web application. To implement this solution, it needs to create separate Amazon SQS queues for each type of quote request. The entire message processing should not exceed 24 hours.

As the Solutions Architect for the company, which of the following solutions should be implemented to meet the above requirement?

- `Create one Amazon SNS topic and configure the SQS queues to subscribe to the SNS topic. Set the filter policies in the SNS subscriptions to publish the message to the designated SQS queue based on its quote request type.`
- Create a data stream in Amazon Kinesis Data Streams. Use the Kinesis Client Library to deliver all the records to the designated SQS queues based on the quote request type.
- Create one Amazon SNS topic and configure the SQS queues to subscribe to the SNS topic. Publish the same messages to all SQS queues. Filter the messages in each queue based on the quote request type.
- Create multiple Amazon SNS topics and configure the SQS queues to subscribe to the SNS topics. Publish the message to the designated SQS queue based on the quote request type.


Excellent. This question is actually teaching **SNS Message Filtering**, not SQS. Once you understand one picture, you'll never forget it.

---

# Step 1: What is happening?

Insurance company receives different quote requests.

Example:

```
Home Insurance
Car Insurance
Health Insurance
Travel Insurance
```

Different teams process different requests.

```
Home Team
Car Team
Health Team
Travel Team
```

They don't want every team to receive every request.

---

# Bad Solution

One SNS Topic

```
          SNS
      /   |   |   \
 Home  Car Health Travel Queue
```

If someone publishes

```
Car Quote
```

Every queue receives it.

```
Home Queue     ❌
Car Queue      ✅
Health Queue   ❌
Travel Queue   ❌
```

Then every worker has to check

```
Is this my message?

No

Delete
```

Waste of time.

Waste of processing.

---

# Better Solution (Answer)

SNS supports **Filter Policies**.

```
               SNS
                 |
      -------------------------
      |      |       |       |
 HomeQ CarQ HealthQ TravelQ
```

Each subscription has a filter.

Example

Home Queue

```
QuoteType = Home
```

Car Queue

```
QuoteType = Car
```

Health Queue

```
QuoteType = Health
```

Travel Queue

```
QuoteType = Travel
```

Now publisher sends

```
QuoteType = Car
```

SNS checks filters.

Only

```
Car Queue
```

gets the message.

Everything else gets nothing.

Much faster.

---

# Real Example

Publisher sends

```json
{
   "QuoteType":"Car",
   "Customer":"Ali"
}
```

SNS checks

```
Home Queue
Looking for Home
No
```

```
Car Queue
Looking for Car
Yes
```

Message delivered.

```
Health Queue
No
```

```
Travel Queue
No
```

Done.

# Why not Multiple SNS Topics?

Option says

```
Home Topic
Car Topic
Health Topic
Travel Topic
```

Could this work?

Yes.

But AWS asks for the **best** solution.

Creating many topics means

* more management
* more publishers
* more configuration

Instead

```
One Topic

+
Filter Policy
```

Much simpler.

AWS likes managed and simple solutions.

---

# Why not Kinesis?

Kinesis is for

```
Streaming data
```

Examples

* Sensor data
* IoT
* Clickstream
* Logs
* Video analytics

Not for routing messages to different queues.

When you see

> Same message goes to multiple applications

Think

> SNS

---

When you see

> Different applications need different messages

Think

> SNS + Filter Policy

---

When you see

> Queue messages for processing

Think

> SQS

---

When you see

> One publisher → many consumers

Think

```
SNS
```

---

When you see

> One publisher → many SQS queues

Think

```
SNS
      ↓
   SQS Queue A

```

---

When you see

Think

```
SNS Filter Policy
```

# ⭐ Tiny Cheat Sheet

| Requirement                               | Service           |
| ----------------------------------------- | ----------------- |
| Store messages                            | SQS               |
| Notify many subscribers                   | SNS               |
| One message → many queues                 | SNS + SQS         |
| Send only specific messages to each queue | SNS Filter Policy |
| Queue processes messages later            | SQS               |
| Pub/Sub pattern                           | SNS               |

## Exam Trick 🚨

If the question contains words like:

* **multiple SQS queues**
* **different teams**
* **different message types**
* **route messages**
* **filter messages**
* **fan-out**

Immediately think:

> **SNS Topic → SQS Queues → Filter Policy**

This is one of the most common SNS/SQS patterns tested in the SAA exam.
