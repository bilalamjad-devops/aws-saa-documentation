8. Question

Category: CSAA – Design High-Performing Architectures

The start-up company that you are working for has a batch job application that is currently hosted on an EC2 instance. It is set to process messages from a queue created in SQS with default settings. You configured the application to process the messages once a week. After 2 weeks, you noticed that not all messages are being processed by the application.

What is the root cause of this issue?

- The batch job application is configured to long polling.
- `Amazon SQS has automatically deleted the messages that have been in a queue for more than the maximum message retention period.`
- Missing permissions in SQS.
- The SQS queue is set to short-polling.

Excellent. This is the **last major SQS concept** for the SAA exam: **Message Retention Period**.

---

# Step 1: What happened?

The application processes messages:

> **Once every week**

But after 2 weeks:

> Some messages are missing.

---

# Step 2: Most students think

Maybe:

* Visibility Timeout ❌
* Long Polling ❌
* Short Polling ❌

None of these delete messages.

---

# Step 3: The real issue

SQS has something called **Message Retention Period**.

It means:

> **How long SQS keeps an unprocessed message in the queue.**

---

Nobody processes it.

## Day 5

By default, SQS says:

> "This message has been waiting too long."

It deletes it automatically.

```
❌ Deleted
```

---

# Default retention

By default:

```
4 days
```

Maximum:

```
14 days
```

---

# Now apply it to the question

Application runs

```
Every 7 days
```

But SQS keeps messages only

```
4 days
```

Timeline:

```text
Day 1

Message arrives

↓

Day 5

Deleted automatically

↓

Day 7

Application starts

↓

Nothing to process
```

That is exactly why messages disappeared.

---

# Correct Answer

✅ **Amazon SQS has automatically deleted the messages that have been in a queue for more than the maximum message retention period.**

---

# Why the others are wrong

### ❌ Long Polling

Long Polling only waits longer for messages.

It never deletes messages.

---

### ❌ Short Polling

Short Polling checks the queue immediately.

It also never deletes messages.

---

### ❌ Missing permissions

If permissions were missing,

the application wouldn't work consistently.

The question specifically says:

> Some messages are missing after weeks.

That points to retention.

---

# Easy Memory Trick

Imagine SQS is a lost-and-found box.

It keeps lost items for **4 days**.

```text
Item arrives

↓

Stored

↓

4 days pass

↓

Thrown away
```

If you come back after 7 days...

Nothing is there anymore.

# SQS Cheat Sheet (Complete)

| Concept                 | Purpose                              | Default                             |
| ----------------------- | ------------------------------------ | ----------------------------------- |
| Long Polling            | Reduce empty responses and cost      | `ReceiveMessageWaitTimeSeconds > 0` |
| Short Polling           | Immediate polling                    | `ReceiveMessageWaitTimeSeconds = 0` |
| Visibility Timeout      | Hide message while processing        | **30 seconds**                      |
| Message Retention       | Keep unprocessed messages            | **4 days** (max **14 days**)        |
| DeleteMessage           | Permanently remove processed message | Called by consumer                  |
| Dead Letter Queue (DLQ) | Store repeatedly failed messages     | Configurable                        |
| Standard Queue          | High throughput, possible duplicates | Default                             |
| FIFO Queue              | Ordered processing, no duplicates    | Special queue type                  |

---

## 📌 SAA Exam Memory Rules

When you see:

* **"Reduce empty responses"** → ✅ Long Polling
* **"Another worker should not process the same message"** → ✅ Visibility Timeout
* **"Worker crashed"** → ✅ Message becomes visible again after Visibility Timeout
* **"Messages disappear after several days"** → ✅ Message Retention Period
* **"Failed many times"** → ✅ Dead Letter Queue (DLQ)
* **"Premium users first"** → ✅ Multiple SQS queues
* **"One message to many consumers"** → ✅ SNS + SQS Fanout
