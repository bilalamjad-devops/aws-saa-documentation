16. Question
Category: CSAA – Design Secure Architectures
An application is hosted in an Auto Scaling group of EC2 instances and a Microsoft SQL Server on Amazon RDS. There is a requirement that all in-flight data between your web servers and RDS should be secured.

Which of the following options is the MOST suitable solution that you should implement? (Select TWO.)


- `Force all connections to your DB instance to use SSL by setting the rds.force_ssl parameter to true. Once done, reboot your DB instance.`
- `Download the Amazon RDS Root CA certificate. Import the certificate to your servers and configure your application to use SSL to encrypt the connection to RDS.`
- Enable the IAM DB authentication in RDS using the AWS Management Console.
- Specify the TDE option in an RDS option group that is associated with that DB instance to enable transparent data encryption (TDE).
- Configure the security groups of your EC2 instances and RDS to only allow traffic to and from port 443.

Exactly — this question is testing one very important distinction:

> **"How do I encrypt data while it is traveling from EC2 → RDS?"**

Not data sitting on the database.

## 1. What is the scenario saying?

You have:

```text
Users
  ↓
ALB
  ↓
EC2 Auto Scaling Group
  ↓
Microsoft SQL Server on RDS
```

The requirement says:

> **All in-flight data between EC2 and RDS must be secured.**

"In-flight" means data **moving across the network**:

```text
EC2 ───────────────► RDS
       🔒 encrypted
```

So we need **SSL/TLS encryption** between the application and SQL Server.

---

# 2. Correct answer #1 — Force SSL

### ✅ `rds.force_ssl = true`

This tells RDS:

> "Do not accept unencrypted connections. Every connection must use SSL."

Conceptually:

```text
EC2
 │
 │  SSL/TLS 🔒
 │
 ▼
RDS SQL Server
```

The important exam detail:

```text
rds.force_ssl = true
```

is a **static parameter**.

Therefore:

```text
Change parameter
      ↓
Reboot RDS
      ↓
Setting takes effect
```

### Exam memory:

**Force every connection to be encrypted → `rds.force_ssl = true`**

---

# 3. Correct answer #2 — RDS Root CA certificate

The second answer is about making the **client/application** trust the RDS server's certificate.

Think of HTTPS.

When your browser connects to:

```text
https://example.com
```

the browser verifies the server's certificate.

Similarly:

```text
EC2 application
      ↓
RDS SQL Server
```

The application needs to establish a trusted SSL/TLS connection with RDS.

So you:

1. Download the Amazon RDS Root CA certificate.
2. Install/import it on the EC2 servers.
3. Configure your application/database client to use SSL.

Then:

```text
EC2 Application
      │
      │ SSL/TLS 🔒
      │ + certificate verification
      ▼
RDS SQL Server
```

---

# 4. Why not port 443?

This is a **very important trap**.

The option says:

> Configure security groups to only allow traffic on port 443.

You might think:

> "HTTPS = 443 = encrypted."

But that's not how this works.

**Security Group controls network access. It does NOT encrypt the traffic.**

For example:

```text
Security Group
      ↓
Allow TCP 1433
      ↓
EC2 ─────────► RDS
       ❌ could still be unencrypted
```

Port 443 doesn't magically encrypt arbitrary database traffic.

You need **SSL/TLS at the database connection level**.

---

# 5. Why not TDE?

This is another common exam distinction.

**TDE = Transparent Data Encryption**

It protects **data at rest**.

Think:

```text
RDS storage
┌─────────────────────┐
│ 🔒 Database files   │
│ 🔒 Data on disk     │
└─────────────────────┘
```

But the question asks about:

> **data in transit**

That's:

```text
EC2 ─────────────► RDS
       🔒
```

So:

| Requirement          | Technology           |
| -------------------- | -------------------- |
| Data **at rest**     | TDE / encryption     |
| Data **in transit**  | SSL/TLS              |
| Force SQL Server SSL | `rds.force_ssl=true` |

---

# 6. Why not IAM DB Authentication?

IAM DB authentication isn't the solution here.

IAM authentication answers:

> **"Who is allowed to log into the database?"**

SSL answers:

> **"How do we encrypt the connection?"**

Different problems.

And for this particular question, the provided explanation also points out that IAM DB authentication isn't supported for RDS SQL Server.

---

# 🧠 The big exam pattern

Whenever you see:

> **"secure/encrypt data between EC2 and RDS"**

think:

### 🔒 SSL/TLS

Then look for:

**Option A:** Force SSL → `rds.force_ssl = true`
**Option B:** Configure client/application to use SSL + RDS CA certificate

That's why the two correct answers are:

✅ **Force all RDS connections to use SSL with `rds.force_ssl=true`**

✅ **Install the RDS Root CA certificate and configure the application to use SSL**

---

### One-line memory trick

> **At rest = encrypt the storage. In transit = SSL/TLS. Authentication = IAM/password. Security Group = controls traffic, doesn't encrypt it.**
