27. Question

Category: CSAA – Design Secure Architectures

A local bank has an in-house application that handles sensitive financial data in a private subnet. After the data is processed by the EC2 worker instances, they will be delivered to S3 for ingestion by other services.

How should you design this solution so that the data does not pass through the public Internet?

- `Configure a VPC Endpoint along with a corresponding route entry that directs the data to S3.`
- Configure a Transit gateway along with a corresponding route entry that directs the data to S3.
- Provision a NAT gateway in the private subnet with a corresponding route entry that directs the data to S3.
- Create an Internet gateway in the public subnet with a corresponding route entry that directs the data to S3.

Yes bro. This is a **VPC Endpoint** question, and the main thing they're testing is:

> **How can a private-subnet EC2 instance access S3 without using the public Internet?**

## What is the scenario?

The architecture is:

```text
Private Subnet
     │
     ├── EC2 Worker
     │
     │ processes sensitive data
     ↓
   Amazon S3
```

The requirement is:

> **EC2 → S3, but traffic must NOT go through the public Internet.**

### ✅ Answer

**Configure a VPC Endpoint for S3 and the appropriate route entry.**

---

# Why VPC Endpoint?

A VPC Endpoint provides a **private path** between your VPC and supported AWS services.

Instead of:

```text
EC2
 ↓
NAT Gateway
 ↓
Internet
 ↓
S3
```

you can have:

```text
EC2
 ↓
VPC Endpoint
 ↓
AWS private network
 ↓
S3
```

The traffic stays within the **AWS network** rather than traversing the public Internet.

---

# ⭐ Important: S3 has a Gateway Endpoint

For S3, the classic exam answer is:

> **S3 Gateway VPC Endpoint**

There are two major endpoint types you should remember:

### Gateway Endpoint

Used for:

* **Amazon S3**
* **Amazon DynamoDB**

Example:

```text id="f8fj6r"
Private EC2
     ↓
Route Table
     ↓
S3 Gateway Endpoint
     ↓
S3
```

There is **no NAT Gateway required**.

And importantly:

> **Gateway endpoints have no additional charge.**

That's why they're often the preferred/cost-effective answer for S3.

---

### Interface Endpoint

Uses:

> **AWS PrivateLink**

and creates an ENI with a private IP inside your subnet.

Used for many AWS services.

Conceptually:

```text id="jkj9yr"
EC2
 ↓
Private IP
 ↓
Interface Endpoint
 ↓
AWS Service
```

For **S3**, when the question specifically asks for the **most cost-effective/private connectivity**, you'll very often see:

> **Gateway Endpoint**

---

# Why not NAT Gateway?

This is a very important distinction.

A NAT Gateway gives:

```text id="7a6lvp"
Private EC2
     ↓
NAT Gateway
     ↓
Internet
```

Its purpose is essentially:

> **Private resources → Internet**

So if the question says:

> "Private EC2 needs to download updates from the Internet"

Think:

**NAT Gateway.**

But this question says:

> "Private EC2 needs to access S3 without going through the public Internet."

Think:

**S3 Gateway Endpoint.**

---

# Why not Internet Gateway?

Internet Gateway is for Internet connectivity.

You don't want:

```text id="5u9vpp"
Private EC2
    ↓
Internet Gateway
    ↓
Public Internet
    ↓
S3
```

The requirement explicitly says:

> **Don't use public Internet.**

So IGW is wrong.

---

# Why not Transit Gateway?

Transit Gateway is mainly for connecting networks:

```text id="9qz7v1"
VPC A ──┐
        │
VPC B ──┼── Transit Gateway
        │
VPC C ──┘
        │
On-premises
```

It's a **network-to-network connectivity hub**.

It isn't the normal solution for:

> Private VPC → S3.

---

# 🧠 Memorize this for SAA

When you see:

### Private EC2 → S3 without Internet

Immediately think:

> **S3 Gateway VPC Endpoint**

### Private EC2 → Internet

Think:

> **NAT Gateway**

### Public EC2 → Internet

Think:

> **Internet Gateway**

### VPC → VPC / on-premises networks

Think:

> **Transit Gateway** (depending on architecture)

---

### One small correction to the explanation you pasted

The statement:

> "traffic coming from your VPC to your S3 bucket is traversing the public Internet by default"

is a bit oversimplified. For SAA purposes, the important architectural distinction is that **a VPC endpoint provides private connectivity to S3 without requiring an Internet Gateway/NAT path**. That's the concept the question is testing.

So the exam mental model should be:

**S3 + private access + no Internet → Gateway VPC Endpoint.**
