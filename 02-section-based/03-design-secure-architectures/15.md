15. Question

Category: CSAA – Design Secure Architectures

An organization needs to control access to several Amazon S3 buckets. The organization plans to use a gateway endpoint to allow access to trusted buckets. The organization shall not use overly broad policies like AmazonS3FullAccess.

Which of the following could help achieve this requirement?

- Generate a bucket policy for trusted VPCs.
- `Generate an endpoint policy for trusted VPCs.`
- Generate a bucket policy for trusted S3 buckets.
- `Generate an endpoint policy for trusted S3 buckets.`

Yes bro. This one is testing **VPC Gateway Endpoint + Endpoint Policy**, especially how to restrict which S3 buckets can be accessed.

## 1. What is the question asking?

Imagine your architecture:

```text
EC2 in Private Subnet
        │
        ▼
S3 Gateway VPC Endpoint
        │
        ├── Bucket A ✅
        ├── Bucket B ✅
        └── Bucket C ❌
```

The company says:

> "Our EC2 instances should access S3 through a Gateway Endpoint, but they should ONLY be able to access certain trusted S3 buckets."

And they don't want something broad like:

```text
AmazonS3FullAccess
```

So the question is:

> **Where should we put the restriction so the endpoint only allows access to specific S3 buckets?**

Answer:

### ✅ Endpoint Policy for trusted S3 buckets

---

# 2. What is a Gateway Endpoint?

Normally, an EC2 instance in a private subnet might need:

```text
EC2
 ↓
NAT Gateway
 ↓
Internet
 ↓
S3
```

But for S3, AWS provides a better option:

```text
EC2
 ↓
Gateway Endpoint
 ↓
S3
```

No NAT Gateway or Internet Gateway is required for this path.

And the Gateway Endpoint can have a policy controlling which S3 resources can be accessed.

---

# 3. The important distinction

This is the part you should remember for the exam.

### Endpoint Policy

Controls:

> **What can be accessed through this VPC endpoint?**

For example:

```text
Gateway Endpoint
       │
       ├── company-data-bucket ✅
       ├── backup-bucket ✅
       └── random-public-bucket ❌
```

So you can say:

> Through this endpoint, only these S3 buckets are allowed.

---

### Bucket Policy

Controls:

> **Who/what is allowed to access this particular S3 bucket?**

For example:

```text
company-data-bucket
       │
       ├── VPC Endpoint A ✅
       ├── VPC Endpoint B ❌
       └── Internet ❌
```

So bucket policy is attached to the **bucket**.

Endpoint policy is attached to the **VPC endpoint**.

---

# 4. Why is Endpoint Policy the best answer?

Suppose you have 20 trusted S3 buckets.

With bucket policies, you potentially have to configure:

```text
Bucket 1 → policy
Bucket 2 → policy
Bucket 3 → policy
...
Bucket 20 → policy
```

That's annoying to manage.

Instead:

```text
             Gateway Endpoint
                    │
             Endpoint Policy
                    │
       ┌────────────┼────────────┐
       ▼            ▼            ▼
   Bucket A      Bucket B      Bucket C
      ✅            ✅            ❌
```

One endpoint policy can define which S3 resources are allowed through that endpoint.

That's why the exam wants:

### ✅ Generate an endpoint policy for trusted S3 buckets.

---

# 5. Why "trusted VPCs" is wrong?

Look carefully at the wording:

> **trusted buckets**

The requirement isn't:

> "Which VPCs can access S3?"

It's:

> **"Which S3 buckets can be accessed?"**

Therefore:

```text
❌ trusted VPCs
✅ trusted S3 buckets
```

---

# 6. Why isn't bucket policy the best answer?

This is a little tricky.

The question says:

> Which of the following **could help** achieve this requirement?

Technically, a **bucket policy can also restrict access**.

So:

### Bucket policy → possible ✅

But:

### Endpoint policy → better/preferred ✅

Because the organization wants to control access to **several S3 buckets** through the gateway endpoint.

The exam explanation itself says the bucket-policy approach would require managing policies on each bucket, whereas one endpoint policy can whitelist the trusted buckets.

---

# 🧠 Exam memory trick

Whenever you see:

> **Gateway Endpoint + restrict which S3 buckets can be accessed**

Think:

### **Endpoint Policy**

And remember the difference:

| Policy               | Main question                                                |
| -------------------- | ------------------------------------------------------------ |
| **Endpoint Policy**  | "What AWS resources can I access **through this endpoint**?" |
| **S3 Bucket Policy** | "Who/what can access **this bucket**?"                       |
| **IAM Policy**       | "What can **this IAM identity** do?"                         |

So for Q15:

**Requirement:** EC2 → S3 through Gateway Endpoint → only trusted buckets

**Answer:** ✅ **Endpoint Policy for trusted S3 buckets**.
