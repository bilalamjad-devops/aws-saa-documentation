4. Question

Category: CSAA – Design Secure Architectures

A top IT Consultancy has a VPC with two On-Demand EC2 instances with Elastic IP addresses. You were notified that the EC2 instances are currently under SSH brute force attacks over the Internet. The IT Security team has identified the IP addresses where these attacks originated. You have to immediately implement a temporary fix to stop these attacks while the team is setting up AWS WAF, GuardDuty, and AWS Shield Advanced to permanently fix the security vulnerability.

Which of the following provides the quickest way to stop the attacks to the instances?

- Place the EC2 instances into private subnets
- `Block the IP addresses in the Network Access Control List`
- Remove the Internet Gateway from the VPC
- Assign a static Anycast IP address to each EC2 instance

Yes — this question is mainly testing **Network ACL vs Security Group**, plus the word **“immediately.”**

### What is happening?

You have:

```text
Internet
   ↓
🚨 Attacker IPs
   ↓
Internet Gateway
   ↓
VPC
   ↓
NACL
   ↓
EC2 instances
```

Security team already knows the **attacker IP addresses**.

The requirement is:

> **Stop those specific IPs immediately.**

So the fastest solution is:

✅ **Block the IP addresses in the Network ACL.**

---

### Why NACL?

A **Network ACL** works at the **subnet level** and supports both:

* `ALLOW`
* `DENY`

For example:

```text
Inbound NACL

Rule 100
Source: 203.0.113.50/32
Protocol: TCP
Port: 22
Action: DENY
```

That immediately blocks SSH traffic from that IP to instances in that subnet.

Notice:

**`/32` = exactly one IP address.**

---

## Why not Security Group?

This is an important distinction.

Security Groups are:

> **Allow-only**

They don't have explicit **DENY** rules.

So if you specifically know:

> "Block these attacker IPs"

a NACL is very convenient because you can explicitly say:

```text
DENY 203.0.113.50/32
```

---

## NACL vs Security Group — remember this

|                        | Security Group        | Network ACL            |
| ---------------------- | --------------------- | ---------------------- |
| Level                  | EC2/ENI               | Subnet                 |
| Stateful?              | ✅ Yes                 | ❌ No                   |
| Allow rules            | ✅                     | ✅                      |
| Deny rules             | ❌                     | ✅                      |
| Rule evaluation        | All applicable rules  | Lowest number first    |
| Good for               | Instance-level access | Subnet-level filtering |
| Can block specific IP? | Not with DENY         | ✅                      |

### The big exam memory

> **SG = Allow**
>
> **NACL = Allow + Deny**

---

### Why the other answers fail

**Private subnet** ❌
Would remove public Internet access, but moving an existing EC2 instance isn't the quickest temporary block—and you could also lose your own access.

**Remove Internet Gateway** ❌
Blocks Internet connectivity for everyone, including legitimate users/administrators. Too destructive.

**Static Anycast IP** ❌
That's associated with **AWS Global Accelerator**, which is for improving availability/performance and traffic routing—not blocking attackers.

---

### 🧠 SAA shortcut

When the question says:

> **"We know the attacker's IP addresses and need to block them immediately."**

Think:

**NACL → DENY the IP → `/32`**

And one more important concept:

> **NACL is stateless**, so if you allow something inbound, the return traffic must separately be allowed outbound.
