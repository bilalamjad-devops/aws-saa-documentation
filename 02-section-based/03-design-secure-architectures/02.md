2. Question

Category: CSAA – Design Secure Architectures

A startup launched a new FTP server using an On-Demand EC2 instance in a newly created VPC with default settings. The server should not be accessible publicly but only through the IP address 175.45.116.100 and nowhere else.

Which of the following is the most suitable way to implement this requirement?



- `Create a new inbound rule in the security group of the EC2 instance with the following details:`

`Protocol: TCP`

`Port Range: 20 – 21`

`Source: 175.45.116.100/32`


- Create a new Network ACL inbound rule in the subnet of the EC2 instance with the following details:


Protocol: TCP

Port Range: 20 – 21

Source: 175.45.116.100/0

Allow/Deny: ALLOW


- Create a new inbound rule in the security group of the EC2 instance with the following details:

Protocol: UDP

Port Range: 20 – 21

Source: 175.45.116.100/32


- Create a new Network ACL inbound rule in the subnet of the EC2 instance with the following details:

Protocol: UDP

Port Range: 20 – 21

Source: 175.45.116.100/0

Allow/Deny: ALLOW


Yes bro. This question is mainly testing **Security Group vs NACL + CIDR `/32` vs `/0` + TCP vs UDP**.

### First understand the requirement

> FTP server should be accessible **only from `175.45.116.100`**.

Think:

```text
Internet
   |
   | FTP (TCP 20/21)
   |
175.45.116.100
   |
   v
[ Security Group ]
   |
   v
[ EC2 FTP Server ]
```

We need to allow **exactly ONE IP address**.

### 1. Why `/32`?

`175.45.116.100/32` means:

> **Only this one IP address**

Examples:

| CIDR                | Meaning                         |
| ------------------- | ------------------------------- |
| `175.45.116.100/32` | Exactly one IP                  |
| `175.45.116.0/24`   | 256 IP addresses                |
| `0.0.0.0/0`         | Everyone / entire IPv4 Internet |

So:

```text
175.45.116.100/32
```

✅ Correct.

But:

```text
175.45.116.100/0
```

❌ Essentially means **all IPv4 addresses**, not just that IP.

---

### 2. FTP uses TCP, not UDP

FTP traditionally uses:

* **TCP 21** → control connection
* **TCP 20** → data connection in active mode

So:

```text
TCP 20-21
```

✅

Not:

```text
UDP 20-21
```

❌

---

### 3. Why Security Group?

The question gives us an **EC2 instance** and asks to restrict access to it.

A Security Group is normally the first choice:

```text
Security Group

Inbound:
Protocol: TCP
Port: 20-21
Source: 175.45.116.100/32
```

This means:

> "Only this specific IP can initiate FTP connections to this EC2 instance."

And because the VPC's **default NACL already allows traffic**, we don't need to modify the NACL for this question.

---

## 🧠 The exam shortcut

When you see:

> **"Allow access from only this specific IP"**

Think:

**Security Group + `/32`**

When you see:

> **"FTP"**

Think:

**TCP**

Therefore:

**TCP + 20/21 + `175.45.116.100/32` + Security Group**

That's the answer.

### One important distinction

Don't think:

> "NACL is security, therefore NACL must be used."

Both **Security Groups and NACLs** can filter traffic, but they behave differently:

| Security Group                           | NACL                         |
| ---------------------------------------- | ---------------------------- |
| Attached to ENI/EC2                      | Attached to subnet           |
| **Stateful**                             | **Stateless**                |
| Allow rules only                         | Allow + Deny                 |
| Usually first choice for instance access | Subnet-level traffic control |

For SAA questions, if the requirement is simply **"allow this EC2 instance to receive traffic from this specific IP"**, Security Group is usually the clean answer.

And one correction to the TutorialsDojo explanation: saying `175.45.116.100/0` is an "invalid" CIDR is misleading. `/0` is a **valid CIDR**, but it represents the entire IPv4 address space (`0.0.0.0/0`), so it doesn't meet the "only this IP" requirement.

**Memory trick:**

> 🔐 **One IP = /32**

> 🌍 **Everyone = /0**

> 📡 **FTP = TCP**

> 🛡️ **EC2 access control = Security Group**
