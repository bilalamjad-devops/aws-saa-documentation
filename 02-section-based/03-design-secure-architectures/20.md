20. Question

Category: CSAA – Design Secure Architectures

A pharmaceutical company has resources hosted on both its on-premises network and in the AWS cloud. The company requires all Software Architects to access resources in both environments using on-premises credentials, which are stored in Active Directory, rather than through an Amazon Cognito identity pool.

In this scenario, which of the following can be used to fulfill this requirement?

- Use Amazon VPC
- Set up SAML 2.0-Based Federation by using a Web Identity Federation.
- `Set up SAML 2.0-Based Federation by using a Microsoft Active Directory Federation Service.`
- Use IAM users

Absolutely bro. **Q20 is basically an authentication/federation question.** The key is to recognize what the company already has and what it wants to avoid.

### What is the question asking?

The company has:

* **On-premises resources**
* **AWS resources**
* Employee credentials already stored in **Microsoft Active Directory (AD)**
* Employees need to access **both on-premises and AWS**
* They **do not want separate IAM users**
* They **do not want Amazon Cognito**

So the requirement is:

> **“Can employees use their existing corporate AD username/password to access AWS?”**

Yes → **SAML 2.0 Federation using Microsoft AD FS.**

### Think of it like this

Without federation:

```text
Employee
   ↓
IAM username/password
   ↓
AWS
```

You would have to create/manage AWS IAM users.

With federation:

```text
Employee
   ↓
Corporate Active Directory
   ↓
AD FS
   ↓
SAML 2.0
   ↓
AWS IAM Role
   ↓
AWS Resources
```

The employee uses their **existing company credentials**.

### What is AD FS?

**AD FS = Active Directory Federation Services.**

It acts as the bridge between your company's **Active Directory** and AWS.

For example:

```text
Bilal
  ↓
username: bilal
password: company-password
  ↓
Active Directory
  ↓
AD FS verifies identity
  ↓
SAML assertion
  ↓
AWS trusts AD FS
  ↓
AWS gives Bilal an IAM Role
```

Notice something important:

**You don't create an IAM user for Bilal.**

AWS gives him temporary permissions through an **IAM role**.

---

## Why SAML 2.0?

SAML is commonly used for **Single Sign-On (SSO)** between an organization's identity provider and a service provider.

Here:

* **AD FS = Identity Provider (IdP)**
* **AWS = Service Provider**
* **SAML 2.0 = communication/federation mechanism**

So remember:

> **Corporate AD → AD FS → SAML → AWS**

---

## Why the other answers are wrong?

### ❌ Amazon VPC

VPC is about **networking**.

```text
VPC → subnets, route tables, security groups, etc.
```

It has nothing to do with authenticating employees.

---

### ❌ Web Identity Federation

This is associated with external identity providers such as:

* Google
* Facebook
* Login with Amazon

Think:

> **Web Identity = external/social identity providers**

Not your company's internal Active Directory.

---

### ❌ IAM Users

IAM users would mean creating separate AWS credentials for employees.

But the requirement specifically says:

> **Use the existing on-premises Active Directory credentials.**

So IAM users are not the desired solution.

---

# 🧠 Exam shortcut

Whenever you see:

> **On-premises Active Directory + AWS + existing corporate credentials + SSO**

Think:

### **SAML 2.0 + AD FS**

And if you see:

> **Google / Facebook / Amazon login**

Think:

### **Web Identity Federation**

Don't confuse these:

| Requirement                         | Think                       |
| ----------------------------------- | --------------------------- |

### 1. What is an IdP?

**IdP = Identity Provider.**

An Identity Provider is a system that **authenticates the user** — basically:

> “Yes, I know this user, and they successfully logged in.”

Examples:

* **Microsoft AD FS** → can authenticate users against an organization's Active Directory.
* **Keycloak** → can act as an IdP and authenticate users using its own users or connect to LDAP/Active Directory.
* **Google** → can act as an external IdP.
* **Okta** → IdP.
* **Microsoft Entra ID** → IdP.

Think:

```text
User
  ↓
IdP
  ↓
"Yes, this user is Bilal"
  ↓
Application / AWS
```

---

### 2. AD FS specifically

**AD FS (Active Directory Federation Services)** is commonly used by organizations that already have **Microsoft Active Directory on-premises**.

For example:

```text
Company employees
       ↓
   AD credentials
       ↓
    AD FS
       ↓
   SAML 2.0
       ↓
      AWS
```

So employees don't need separate IAM users.

They use their **existing company username/password**.

This is exactly what your Question 20 was testing.

---

### 3. What about Keycloak?

Yes — **Keycloak can also act as an IdP**.

For example:

```text
Employee
   ↓
Keycloak
   ↓
SAML / OIDC
   ↓
AWS / Application
```

Keycloak can also integrate with an existing Active Directory/LDAP.

So you could have:

```text
Active Directory
       ↓
   Keycloak
       ↓
    SAML/OIDC
       ↓
      AWS
```

The important point is:

> **AD FS and Keycloak are examples of Identity Providers.**

---

## 4. What is Web Identity Federation?

This is where your second idea is correct.

Web Identity Federation is typically:

> **“Let users authenticate using an external identity provider such as Google, Facebook, or Amazon.”**

For example, imagine you build a mobile application.

Instead of creating an account/password system yourself:

```text
Your App
   ↓
"Sign in with Google"
   ↓
Google authenticates user
   ↓
Your App receives identity information
```

AWS can use services such as **Amazon Cognito** to work with these external identities.

Conceptually:

```text
User
 ↓
Google / Facebook / Apple
 ↓
Cognito
 ↓
Temporary AWS credentials
 ↓
AWS resources
```

## 5. Very important distinction for your SAA exam

Remember this table:

| Situation                                                     | Think of                              |
| ------------------------------------------------------------- | ------------------------------------- |
| Company's existing **Active Directory**                       | **AD FS / SAML federation**           |
| Company wants employees to use existing corporate credentials | **SAML federation**                   |
| Keycloak/Okta/Entra ID as corporate IdP                       | **Federation**                        |
| User clicks **Sign in with Google**                           | **Web identity federation / Cognito** |
| User clicks **Login with Facebook**                           | **Web identity federation / Cognito** |
| Create AWS-specific username/password                         | **IAM users**                         |
| Network connectivity between on-prem and AWS                  | **VPN / Direct Connect**, not IdP     |

Think:

**AD → AD FS → SAML → AWS**

> **“Users authenticate using Google/Facebook/Amazon.”**

Think:

**External IdP → Cognito → AWS**

### And one correction to keep your mental model clean

**Google/GitHub login and AD FS are both identity federation scenarios**, but they are not necessarily the exact same AWS feature/flow.

For SAA questions, the strongest pattern is:

**Corporate identity → SAML federation**

**Consumer/social identity → Cognito + external IdP**

And **Keycloak** can fit into the first category when an organization uses it as its corporate identity provider.
