24. Question

Category: CSAA – Design Secure Architectures

A Solutions Architect created a brand new IAM User with a default setting using AWS CLI. This is intended to be used to send API requests to Amazon S3, DynamoDB, Lambda, and other AWS resources of the company’s cloud infrastructure.

Which of the following must be done to allow the user to make API calls to the AWS resources?

- Assign an IAM Policy to the user to allow it to send API calls.
- `Create a set of Access Keys for the user and attach the necessary permissions.`
- Enable Multi-Factor Authentication for the user.
- Do nothing as the IAM User is already capable of sending API calls to your AWS resources.

Yes bro — this one is testing **IAM User credentials vs permissions**. There are actually **two separate things** you need to keep apart.

## What is the question asking?

A brand-new IAM user was created using the **AWS CLI**.

The company wants this user to make **programmatic API calls**, such as:

```text
IAM User
   ↓
AWS CLI / SDK
   ↓
S3
DynamoDB
Lambda
etc.
```

The question asks:

> **What must you give this IAM user so it can actually make those API calls?**

### ✅ Correct answer: Create Access Keys

An IAM user needs **programmatic credentials**:

```text
Access Key ID
+
Secret Access Key
```

These are used by:

* AWS CLI
* AWS SDK
* AWS API calls

For example:

```text
AWS CLI
   ↓
Access Key ID + Secret Access Key
   ↓
AWS
```

---

# But here's the important part

Having **Access Keys does NOT automatically mean the user has permission**.

You need to distinguish:

### 🔑 Authentication

> **Who are you?**

Access keys answer this.

### 🛂 Authorization

> **What are you allowed to do?**

IAM policies answer this.

So conceptually:

```text
              IAM User
                 |
        ┌────────┴────────┐
        ↓                 ↓
  Access Keys        IAM Policies
        ↓                 ↓
 "Who are you?"     "What can you do?"
```

For example:

```text
Access Key
     ↓
"I am user Bilal"
     ↓
IAM Policy
     ↓
"Bilal can read S3"
```

---

## Why isn't "Assign an IAM Policy" the answer?

This is the tricky part of the question.

Suppose you create:

```text
IAM User: bilal
```

and attach:

```text
AmazonS3ReadOnlyAccess
```

Now AWS knows:

> Bilal **is allowed** to read S3.

But how is Bilal going to authenticate programmatically?

He still needs credentials.

Therefore:

**Policy = permission**

**Access Key = programmatic credential**

---

## What happens with a brand-new IAM user?

When created through CLI/API, the user starts with essentially:

```text
IAM User
 ├── Console password ❌
 ├── Access keys ❌
 └── Permissions ❌
```

You need to provide the appropriate credentials and permissions.

For this question, the key requirement is:

> **Create Access Keys.**

---

## What about MFA?

MFA is an **additional authentication factor**.

It does NOT replace the access key.

Think:

```text
Access Key
    +
MFA
```

MFA strengthens authentication, but it doesn't magically create programmatic credentials.

---

# 🧠 One very important SAA distinction

You'll see these three concepts repeatedly:

| Thing                                 | Purpose                          |
| ------------------------------------- | -------------------------------- |
| **Access Key ID + Secret Access Key** | Programmatic authentication      |
| **IAM Policy**                        | Permissions/authorization        |
| **MFA**                               | Additional authentication factor |

### Example

Suppose you want an application to read S3:

```text
IAM User
   │
   ├── Access Keys 🔑
   │       ↓
   │   Authenticate
   │
   └── IAM Policy 🛂
           ↓
      Allow s3:GetObject
```

That's the mental model I want you to remember.

### ⚠️ And one modern AWS best-practice point

For **applications running on AWS resources like EC2**, don't normally create IAM user access keys and put them on the instance.

Instead:

> **EC2 → IAM Role → temporary credentials**

That's exactly what your **Question 22** was testing.

So:

**Human/programmatic IAM user → Access Keys (if needed)**

**EC2 application → IAM Role**

This distinction is very important for the SAA exam.
