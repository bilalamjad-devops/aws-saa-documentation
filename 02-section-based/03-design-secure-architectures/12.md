12. Question

Category: CSAA – Design Secure Architectures

A Solutions Architect is hosting a website in an Amazon S3 bucket named tutorialsdojo. The users load the website using the following URL: http://tutorialsdojo.s3-website-us-east-1.amazonaws.com. A new requirement has been introduced to add JavaScript on the webpages to make authenticated HTTP GET requests against the same bucket using the S3 API endpoint (tutorialsdojo.s3.amazonaws.com). However, upon testing, the web browser blocks JavaScript from allowing those requests.

Which of the following options is the MOST suitable solution to implement for this scenario?

- `Enable Cross-origin resource sharing (CORS) configuration in the bucket.`
- Enable cross-account access.
- Enable Cross-Zone Load Balancing.
- Enable Cross-Region Replication (CRR).

Yes bro. This one is actually **very easy once you understand what the browser is complaining about**. The question is testing **CORS**.

# 12. What is the question asking?

You have an S3 static website:

```text
Browser
   │
   │ loads website
   ▼
S3 Website Endpoint
tutorialsdojo.s3-website-us-east-1.amazonaws.com
```

Now JavaScript running on that website wants to make an API request to:

```text
tutorialsdojo.s3.amazonaws.com
```

Notice something important:

### These are different origins/domains

```text
Website:
tutorialsdojo.s3-website-us-east-1.amazonaws.com

API:
tutorialsdojo.s3.amazonaws.com
```

The browser says:

> "Wait! JavaScript from one origin is trying to access resources from another origin. I'm going to block this unless the destination explicitly allows it."

That's where **CORS** comes in.

---

# What is CORS?

**CORS = Cross-Origin Resource Sharing**

It basically tells the browser:

> "It's okay. I allow JavaScript from this particular website to access my resources."

So you configure CORS on the **S3 bucket**.

Conceptually:

```text
Website Origin
    │
    │ JavaScript GET
    ▼
S3 API Endpoint
    │
    │ CORS says:
    │ "I allow this origin"
    ▼
    ✅ Request allowed
```

Without CORS:

```text
JavaScript
    │
    ▼
Different origin
    │
    ▼
Browser
    │
    └── ❌ Blocked by same-origin policy
```

With CORS:

```text
JavaScript
    │
    ▼
Different origin
    │
    ▼
S3 CORS configuration
    │
    └── ✅ Allowed
```

---

# Why does this happen?

Browsers have a security mechanism called the **same-origin policy**.

It prevents a malicious website from freely making requests to other websites on your behalf.

For example, imagine you're logged into your bank.

Then you visit:

```text
evil-site.com
```

Without browser security restrictions, JavaScript on `evil-site.com` could potentially try to make requests to:

```text
yourbank.com
```

That's dangerous.

So browsers say:

> "Cross-origin requests aren't automatically allowed."

CORS provides a controlled mechanism for allowing legitimate cross-origin requests.

---

# In THIS question

The origins are:

### Origin 1

```text
http://tutorialsdojo.s3-website-us-east-1.amazonaws.com
```

### Origin 2

```text
https://tutorialsdojo.s3.amazonaws.com
```

JavaScript loaded from Origin 1 wants to access Origin 2.

Therefore:

> **Configure CORS on the S3 bucket.** ✅

---

# Don't confuse CORS with these

The exam gives you several "cross" terms to confuse you.

### 1. Cross-origin ❗ → CORS

If the question says:

> Browser blocks JavaScript from accessing another domain/origin

Think:

**CORS** ✅

---

### 2. Cross-account

This is about:

```text
AWS Account A
       │
       ▼
AWS Account B
```

Example:

Your AWS account needs to access another company's S3 bucket.

That's an IAM/resource-policy problem.

Not this question.

---

### 3. Cross-Zone Load Balancing

This belongs to:

```text
Load Balancer
     │
 ┌───┴────┐
AZ-1     AZ-2
```

It helps distribute load across Availability Zones.

Nothing to do with browser JavaScript.

---

### 4. Cross-Region Replication

This means:

```text
S3 Bucket
us-east-1
    │
    │ replication
    ▼
S3 Bucket
eu-west-1
```

Used for things like:

* Disaster recovery
* Compliance
* Geographic redundancy
* Data replication

Again, nothing to do with browser cross-origin requests.

---

# 🧠 SAA exam shortcut

Whenever you see:

> **Browser + JavaScript + different domain/origin + request blocked**

Immediately think:

# **CORS** ✅

For example:

```text
JavaScript
   ↓
Different domain
   ↓
Browser blocks request
   ↓
CORS
```

### Remember this distinction:

| Problem                       | Think                         |
| ----------------------------- | ----------------------------- |
| JavaScript → different origin | **CORS**                      |
| AWS Account A → AWS Account B | **Cross-account/IAM**         |
| Traffic across AZs            | **Cross-Zone Load Balancing** |
| S3 → S3 in another Region     | **Cross-Region Replication**  |

**One-line memory:**

> **CORS is for the browser allowing JavaScript to talk to a different origin.**
