5. Question

Category: CSAA – Design Secure Architectures

A company has a regional API Gateway in the us-east-2 region that serves as a proxy to a backend service. Clients connect to the service using the invoke URL of the API stage. To improve usability, the company wants to associate a custom domain name (api.tutorialsdojo.com) with the API. Moreover, the domain name must support HTTPS to ensure secure connections. The company has an existing hosted zone for its domain on Amazon Route 53.

Which of the following would be the next step to achieve the company’s objective?

- Request a public certificate in the us-east-1 region for api.tutorialsdojo.com using AWS Certificate Manager (ACM). Create a regional API Gateway domain name and associate it with api.tutorialsdojo.com and the ACM certificate. In Route 53, create an alias record for api.tutorialsdojo.com that points to the API Gateway domain name.
- Import an existing public certificate for api.tutorialsdojo.com into AWS Certificate Manager (ACM) in the us-east-2. In Route 53, create a CNAME record for api.tutorialsdojo.com that points to the invoke URL of the API Gateway stage.
- Use the AWS Certificate Manager Private Certificate Authority (ACM PCA) to generate a private certificate for api.tutorialsdojo.com. Override the invoke URL using stage variables.
- `Request a public certificate in the us-east-2 region for api.tutorialsdojo.com using AWS Certificate Manager (ACM). Create a regional API Gateway domain name and associate it with api.tutorialsdojo.com and the ACM certificate. In Route 53, create an alias record for api.tutorialsdojo.com that points to the API Gateway domain name.`

Yes bro. This question looks complicated, but it is really testing **3 things together: API Gateway custom domain + ACM certificate + Route 53**.

## 1. What is the question actually asking?

Currently users access the API like:

```text
https://abc123.execute-api.us-east-2.amazonaws.com/prod
```

That's the normal **API Gateway invoke URL**.

The company doesn't like this ugly URL. They want users to access:

```text
https://api.tutorialsdojo.com
```

And they specifically want **HTTPS**.

So the problem is:

> "How do I replace the API Gateway invoke URL with my own domain name and secure it with HTTPS?"

---

# 2. The three AWS services involved

Think of it like this:

```text
                 User
                  |
                  | https://api.tutorialsdojo.com
                  ↓
            Route 53
          "Where should
           this domain go?"
                  |
                  ↓
        API Gateway Custom
          Domain Name
                  |
                  ↓
          API Gateway API
                  |
                  ↓
           Backend service
```

And **ACM** provides the HTTPS certificate:

```text
ACM
 |
 | SSL/TLS certificate
 ↓
API Gateway Custom Domain
```

So:

* **Route 53** → DNS/name resolution
* **API Gateway** → API
* **ACM** → HTTPS certificate

---

# 3. The most important clue: `us-east-2`

The question says:

> regional API Gateway in **us-east-2**

This is the key.

For a **Regional API Gateway**, the ACM certificate must be in the **same region**.

Therefore:

```text
API Gateway
us-east-2
     ↓
ACM certificate
us-east-2
```

✅ Same region.

That's why the correct answer is:

> Request a public certificate in **us-east-2**, create a Regional API Gateway custom domain, associate the certificate, and create a Route 53 alias.

---

# 4. Why do we need ACM?

When someone visits:

```text
https://api.tutorialsdojo.com
```

the browser needs to verify:

> "Is this website really `api.tutorialsdojo.com`?"

The SSL/TLS certificate proves that.

ACM = **AWS Certificate Manager**

You request:

```text
Certificate:
api.tutorialsdojo.com
```

Then API Gateway uses that certificate for HTTPS.

Think:

> **ACM = certificate shop/manager**

---

# 5. Why Route 53?

Route 53 is basically saying:

> "When somebody asks for `api.tutorialsdojo.com`, where should I send them?"

So you create:

```text
api.tutorialsdojo.com
        ↓
API Gateway custom domain
```

Usually this is done using an **Alias record** for API Gateway.

---

# 6. What is API Gateway Custom Domain?

Without custom domain:

```text
abc123.execute-api.us-east-2.amazonaws.com
```

With custom domain:

```text
api.tutorialsdojo.com
```

API Gateway has a feature called:

**Custom Domain Names**

You configure:

```text
Custom domain:
api.tutorialsdojo.com

Certificate:
ACM certificate

API:
Your regional API
```

Then Route 53 connects your friendly domain to that API Gateway custom domain.

---

Memorize this flow:

# 8. Why the other options are wrong

### ❌ Option: ACM certificate in `us-east-1`

This is the classic trap.

You might remember:

> "CloudFront certificates must be in us-east-1."

That's true.

But **this is NOT CloudFront**.

It's a **Regional API Gateway** in `us-east-2`.

Therefore:

```text
Regional API Gateway → certificate same region
CloudFront → certificate us-east-1
```

This distinction is extremely important for SAA.

---

### ❌ Private Certificate

The API is publicly accessed by clients.

So you need a:

**Public ACM certificate**

Not an ACM Private CA certificate.

---

### ❌ CNAME directly to API Gateway invoke URL

You don't simply take:

```text
api.tutorialsdojo.com
```

and CNAME it directly to the normal invoke URL.

You first configure:

**API Gateway → Custom Domain Name**

Then Route 53 points your domain to that custom domain.

---

# 🧠 SAA exam memory trick

When you see:

> **API Gateway + custom domain + HTTPS**

Think:

```text
ACM
 +
API Gateway Custom Domain
 +
Route 53
```

Then look for whether the API is **Regional** or **Edge-optimized**.

### Regional API

```text
API Gateway: us-east-2
ACM:         us-east-2
```

### CloudFront / Edge-optimized

```text
ACM certificate → us-east-1
```

The **us-east-1 certificate rule is a huge exam trap**.

---

## One-line summary

The question is simply asking:

> **"I have an API Gateway API, but instead of users seeing the ugly AWS invoke URL, how do I let them use `https://api.tutorialsdojo.com` securely?"**

Answer:

**ACM public certificate + API Gateway Custom Domain + Route 53 Alias**, with the certificate in **the same region as the Regional API Gateway**.
