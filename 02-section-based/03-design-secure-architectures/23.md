23. Question

Category: CSAA – Design Secure Architectures

For data privacy, a healthcare company has been asked to comply with the Health Insurance Portability and Accountability Act (HIPAA). The company stores all its backups on an Amazon S3 bucket. It is required that data stored on the S3 bucket must be encrypted.

What is the best option to do this? (Select TWO.)

- `Enable Server-Side Encryption on an S3 bucket to make use of AES-256 encryption.`
- Store the data in encrypted Amazon EBS snapshots.
- `Before sending the data to S3 over HTTPS, encrypt the data locally first using your own encryption keys.`
- Enable Server-Side Encryption on an S3 bucket to make use of AES-128 encryption.
- Store the data on Amazon EBS volumes with encryption enabled instead of using S3.

Yes bro. This question is testing **two different layers of encryption**: **client-side encryption** and **S3 server-side encryption**.

## What is the question asking?

The company stores backups in:

```text
Healthcare company
       ↓
     Amazon S3
       ↓
   Backup data
```

Because of HIPAA/data privacy requirements, the data **must be encrypted**.

The question asks:

> **Which TWO methods can ensure the S3 data is encrypted?**

The answers are:

✅ **1. S3 Server-Side Encryption using AES-256 (SSE-S3)**
✅ **2. Encrypt the data yourself before sending it to S3 (client-side encryption)**

---

# 1. Server-Side Encryption — SSE-S3

This is the simple one.

You send your data to S3:

```text
Your application
      |
      | upload
      ↓
     S3
      |
      ↓
S3 encrypts the object
      |
      ↓
🔐 Encrypted at rest
```

With **SSE-S3**, Amazon S3 manages the encryption keys for you.

The exam describes this as:

> **AES-256**

So:

**SSE-S3 → S3 manages keys → AES-256**

---

# 2. Client-Side Encryption

Here, **you encrypt the data before S3 receives it**.

```text
Your application
      |
      | encrypt locally
      ↓
🔐 Encrypted data
      |
      | HTTPS
      ↓
     S3
```

S3 receives data that is **already encrypted**.

For example:

```text
Original:
patient-record.csv

Your application
       ↓
Encrypt
       ↓
8f73a9...encrypted-data...
       ↓
S3
```

This gives you more control because **you manage the encryption process/keys**.

So the exam's second correct answer is:

> **Before sending the data to S3 over HTTPS, encrypt the data locally first using your own encryption keys.**

---

# 🔥 Very important: Encryption at rest vs in transit

This question can be confusing because it mentions **HTTPS**.

Don't think:

> HTTPS = S3 encryption at rest

They are different things.

### HTTPS

Protects data **while travelling**:

```text
Application
    🔐 HTTPS
       ↓
      S3
```

That's **encryption in transit**.

### SSE-S3

Protects data **while stored**:

```text
S3
 ↓
🔐 Encrypted object
 ↓
Disk/storage
```

That's **encryption at rest**.

### Client-side encryption

You encrypt **before transmission**:

```text
Application
 ↓
🔐 Encrypt
 ↓
🔐 HTTPS
 ↓
S3
```

So you're getting protection both during transmission and while the encrypted object is stored.

---

# What about AES-128?

❌ Wrong.

For this question's context:

> **SSE-S3 → AES-256**

Don't choose AES-128.

---

# What about EBS?

❌ Wrong.

The requirement specifically says:

> **Data is stored in an S3 bucket.**

So moving the data to EBS doesn't answer the question.

Think:

| Storage | Encryption     |
| ------- | -------------- |
| S3      | S3 encryption  |
| EBS     | EBS encryption |
| RDS     | RDS encryption |
| EFS     | EFS encryption |

Don't let an answer distract you by saying **"encrypted"**. The question asks about **the actual storage being used**.

---

# 🧠 SAA exam shortcut

When you see:

### "Encrypt S3 data at rest"

Think:

**SSE-S3 / SSE-KMS / SSE-C**

### "Encrypt before uploading to S3"

Think:

**Client-side encryption**

### "Protect data while travelling to S3"

Think:

**HTTPS/TLS**

So for this question:

> **S3 + encryption → SSE-S3 (AES-256)**
> **Encrypt before upload → client-side encryption**

Those are your two answers.
