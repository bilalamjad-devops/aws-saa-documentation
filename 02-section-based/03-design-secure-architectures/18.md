18. Question

Category: CSAA – Design Secure Architectures

An organization stores and manages financial records of various companies in its on-premises data center, which is almost out of space. The management decided to move all of its existing records to a cloud storage service. All future financial records will also be stored in the cloud. For additional security, all records must be prevented from being deleted or overwritten. Once migrated, the records will be accessed less than once a month but must be available immediately if audited, requiring the use of S3 Standard-Infrequent Access.

Which of the following should be done to meet the above requirement?

- Use multi-Region replication to transfer the on‑premises records into Amazon S3 and enable Object Lock.
- `Use AWS DataSync to move the data. Store all of your data in Amazon S3 and enable object lock.`
- Use AWS DataSync to move the data. Store all of your data in Amazon EFS and enable object lock.
- Use AWS Storage Gateway to establish hybrid cloud storage. Store all of your data in Amazon EBS and enable object lock.

Yes bro. This question is testing **three separate concepts together**:

1. **How to migrate on-premises data to AWS**
2. **Where to store financial records**
3. **How to prevent those records from being deleted/overwritten**

Let's break it down.

---

# 1. What is the scenario saying?

The company currently has:

```text
On-Premises Data Center
        │
        │ Financial records
        ▼
   Almost full
```

They want to move the existing records to AWS.

And:

> Future records should also be stored in AWS.

Then there is a **very important security requirement**:

> Records must not be deleted or overwritten.

And another storage requirement:

> Records are accessed less than once a month, but when needed, they must be available immediately.

That points toward **S3 Standard-IA**.

So we're looking for:

```text
On-Premises
     │
     │ migrate
     ▼
AWS DataSync
     │
     ▼
Amazon S3
     │
     ├── S3 Standard-IA
     │
     └── S3 Object Lock
```

### ✅ Correct answer

**AWS DataSync → Amazon S3 → Object Lock**

---

# 2. Why AWS DataSync?

The first question you should ask is:

> "How do I move a large amount of existing data from on-premises into AWS?"

AWS gives us **DataSync** for this.

Think:

### DataSync = Data migration/transfer

```text
On-premises
     │
     │ DataSync
     ▼
S3 / EFS / FSx
```

It is designed for moving large amounts of data between on-premises storage and AWS storage services.

So:

> **Existing on-premises financial records → DataSync**

---

# 3. Why S3?

Now ask:

> "Where should I store these financial records?"

S3 is appropriate because the records are essentially objects/files and need durable storage.

And the question specifically tells you:

> accessed less than once a month but must be immediately available.

That's the clue for:

### S3 Standard-IA

**IA = Infrequent Access**

Use it when:

* Data isn't accessed frequently
* But when you need it, you want immediate access

For example:

```text
Financial records
     │
     ├── Accessed rarely
     │
     └── Must be immediately available
                ↓
          S3 Standard-IA
```

Don't confuse it with Glacier storage classes here because the question explicitly says **S3 Standard-IA**.

---

# 4. Why Object Lock?

This is probably the most important security concept in this question.

The requirement says:

> **"all records must be prevented from being deleted or overwritten."**

That's basically screaming:

# 🔒 S3 Object Lock

Object Lock provides **WORM** protection.

### WORM = Write Once, Read Many

Meaning:

```text
Write record
     ↓
LOCK
     ↓
Can't delete
Can't overwrite
     ↓
Can still read
```

This is commonly useful for things like:

* Financial records
* Compliance records
* Audit data
* Regulatory records

So when you see:

> **"cannot be deleted or overwritten"**

Think:

### 🧠 S3 Object Lock

---

# 5. Why not EFS?

Option:

> DataSync → EFS + Object Lock

❌ Wrong.

Because **S3 Object Lock is an S3 feature**.

EFS doesn't have S3 Object Lock.

So:

```text
S3 → Object Lock ✅
EFS → Object Lock ❌
```

---

# 6. Why not EBS?

Option:

> Storage Gateway → EBS + Object Lock

❌ Wrong.

Again:

**EBS does not support S3 Object Lock.**

And EBS is **block storage**, not the right service for this object-based archival/record-storage requirement.

---

# 7. Why not Multi-Region Replication?

This option sounds attractive:

> "Use multi-Region replication to transfer on-premises records into S3."

But here's the trick.

**S3 Cross-Region Replication does NOT migrate data from your on-premises server into S3.**

It replicates:

```text
S3 Bucket A
     │
     │ Cross-Region Replication
     ▼
S3 Bucket B
```

It requires the data to already be in S3.

For:

```text
On-premises → S3
```

use:

### DataSync

---

# 8. DataSync vs Storage Gateway

This is another useful SAA distinction.

### AWS DataSync

Think:

> **"I need to MOVE/MIGRATE data."**

```text
On-premises
     ↓
DataSync
     ↓
AWS storage
```

### AWS Storage Gateway

Think:

> **"I want my on-premises applications to KEEP USING cloud-backed storage."**

For example:

```text
On-premises application
       │
       ▼
Storage Gateway
       │
       ▼
AWS storage
```

So this question says the existing data center is **almost out of space** and they want to **move the existing records to the cloud**.

That's strongly pointing toward:

### DataSync

---

# 🧠 Exam shortcut for this question

Remember this chain:

**On-premises → migrate → DataSync**

**Rarely accessed + immediate retrieval → S3 Standard-IA**

**Cannot delete/overwrite → S3 Object Lock**

Therefore:

> **DataSync → S3 Standard-IA → Object Lock**

### One-line memory trick:

**"Move it with DataSync, store it in S3, lock it with Object Lock."**
