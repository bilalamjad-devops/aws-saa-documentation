8. Question

Category: CSAA – Design Secure Architectures

A company decided to change its third-party data analytics tool to a cheaper solution. They sent a full data export on a CSV file which contains all of their analytics information. You then save the CSV file to an S3 bucket for storage. Your manager asked you to do some validation on the provided data export.

In this scenario, what is the most cost-effective and easiest way to analyze export data using standard SQL?

- Use mysqldump client utility to load the CSV export file from S3 to a MySQL RDS instance. Run some SQL queries once the data has been loaded to complete your validation.
- Use a migration tool to load the CSV export file from S3 to a database that is designed for online analytic processing (OLAP) such as AWS RedShift. Run some queries once the data has been loaded to complete your validation.
- Create a migration tool to load the CSV export file from S3 to a DynamoDB instance. Once the data has been loaded, run queries using DynamoDB.
- `To be able to run SQL queries, use Amazon Athena to analyze the export data file in S3.`

Exactly. This question is testing a **very important SAA pattern: "Data is already in S3 + I just need SQL analysis" → Amazon Athena.**

## What is the question actually asking?

You have:

```text
Third-party analytics tool
        │
        │ CSV export
        ↓
     Amazon S3
        │
        │
        ↓
   "I need to validate
    this data using SQL"
```

The key question is:

> **Do I really need to load this CSV into a database?**

**No.**

Athena can query the data **directly where it already exists in S3**.

---

## 🟢 Amazon Athena

Think of Athena as:

> **"SQL directly on files in S3."**

For example, suppose your CSV contains:

```text
customer_id,product,amount,country
101,laptop,1200,Pakistan
102,phone,800,Sweden
103,laptop,1500,Japan
```

You can use Athena to run something like:

```sql
SELECT country, SUM(amount)
FROM sales
GROUP BY country;
```

Athena reads the CSV from S3 and returns the result.

### You don't need:

* EC2
* RDS
* Redshift cluster
* DynamoDB
* Database server
* Data migration

That's why it is **easy and cost-effective** for this scenario.

---

# 🧠 Remember this SAA pattern

### Data already in S3 + ad-hoc SQL

➡️ **Athena**

```text
S3
 │
 │ CSV / JSON / Parquet / ORC
 ↓
Athena
 │
 │ SQL
 ↓
Results
```

# Why the other answers are wrong

### ❌ RDS MySQL

You would have to:

```text
S3
 ↓
Load CSV
 ↓
RDS MySQL
 ↓
SQL
```

That's unnecessary infrastructure for simply validating a file.

---

### ❌ Redshift

Redshift is excellent for **data warehousing / large-scale analytics**, but you're being asked for a simple, cost-effective way to query an exported CSV.

You don't need to build a data warehouse just to inspect a file.

---

### ❌ DynamoDB

DynamoDB is a **NoSQL key-value/document database**.

It isn't the natural choice for:

> "I have a CSV in S3 and want to run standard SQL against it."

---

# ⭐ Athena vs Redshift — important for your exam

This distinction will come up a lot.

| Requirement                        | Service      |
| ---------------------------------- | ------------ |
| SQL directly on files in S3        | **Athena**   |
| Ad-hoc queries on S3 data          | **Athena**   |
| Serverless SQL queries             | **Athena**   |
| Data warehouse                     | **Redshift** |
| Large-scale analytical warehouse   | **Redshift** |
| Need to load/manage warehouse data | **Redshift** |
| No infrastructure to manage        | **Athena**   |

### Easy memory trick:

> **Athena = Ask S3 questions using SQL.**

> **Redshift = Build/use a data warehouse for analytics.**

And one more important point: **Athena doesn't store the CSV data itself.** Your data remains in S3; Athena is the query engine that reads it.
