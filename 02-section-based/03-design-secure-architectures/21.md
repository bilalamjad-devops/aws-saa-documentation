21. Question

Category: CSAA – Design Secure Architectures

A company has 3 DevOps engineers that are handling its software development and infrastructure management processes. One of the engineers accidentally deleted a file hosted in Amazon S3 which has caused disruption of service.

What can the DevOps engineers do to prevent this from happening again?

- Set up a signed URL for all users.
- Use S3 Infrequently Accessed storage to store the data.
- Create an IAM bucket policy that disables delete operation.
- `Enable S3 Versioning and Multi-Factor Authentication Delete on the bucket.`

Exactly. This question is testing **data protection against accidental deletion**, not access control.

### What is the question asking?

You have:

**DevOps engineers → S3 bucket → one engineer accidentally deletes a file → service breaks**

AWS wants you to make the bucket **recoverable if someone accidentally deletes something**.

The best answer is:

> ✅ **Enable S3 Versioning + MFA Delete**

### 1. S3 Versioning = "keep previous versions"

Imagine you upload:

```text
app.zip
Version 1
```

Then someone accidentally deletes `app.zip`.

With **Versioning enabled**, S3 doesn't simply lose the old version. It keeps the previous version and puts a delete marker on the object.

So you can recover it.

Think:

```text
Before:
app.zip → Version 1

Someone deletes app.zip

After:
app.zip → Delete Marker
       → Version 1 still exists ✅
```

So **Versioning protects against accidental deletion and overwriting.**

---

### 2. MFA Delete = "extra protection for permanent deletion"

Versioning alone isn't the strongest protection.

If someone tries to **permanently delete a specific object version**, MFA Delete can require an additional MFA authentication step.

Think:

```text
Normal deletion
      ↓
Delete marker
      ↓
Old version still recoverable

Permanent deletion of version
      ↓
🔐 MFA required
```

So MFA Delete makes destructive operations harder to perform accidentally.

---

### Why the other answers are wrong

| Option                             | Why wrong                                                       |
| ---------------------------------- | --------------------------------------------------------------- |
| Signed URL                         | Controls **access**, not accidental deletion                    |
| S3 Infrequent Access               | **Storage class**, has nothing to do with deletion protection   |
| IAM bucket policy disabling Delete | Could prevent legitimate deletion too; not a recovery mechanism |
| **Versioning + MFA Delete**        | ✅ Protects against accidental deletion                          |

### 🧠 Exam memory trick

Remember:

> **Accidental S3 deletion → Versioning**
> **Permanent deletion protection → MFA Delete**

And don't confuse this with **S3 Object Lock**:

* **Versioning** → recover old versions
* **MFA Delete** → extra authentication for permanently deleting versions
* **Object Lock** → prevent objects from being deleted/overwritten for a retention period

For SAA questions, when you see **"someone accidentally deleted/overwrote an S3 object"**, your first thought should be **S3 Versioning**.
