19. Question

Category: CSAA – Design Secure Architectures

A media company needs to configure an Amazon S3 bucket to serve static assets for the public-facing web application. Which methods ensure that all of the objects uploaded to the S3 bucket can be read publicly all over the Internet? (Select TWO.)

- Create an IAM role to set the objects inside the S3 bucket to public read.
- Configure the cross-origin resource sharing (CORS) of the S3 bucket to allow objects to be publicly accessible from all domains.
- `Grant public read access to the object when uploading it using the S3 Console.`
- `Configure the S3 bucket policy to set all objects to public read.`
- Do nothing. Amazon S3 objects are already public by default.

Exactly bro. This one is mainly testing **S3 public access vs CORS vs IAM**. Let's simplify it.

## What is the question asking?

The company has:

```text
S3 Bucket
   ↓
Static website files
   ↓
Anyone on the Internet should be able to READ them
```

The question asks:

> **Which TWO methods can make the objects publicly readable?**

So don't overthink it. We need something that actually grants **public read permission**.

---

## ✅ Answer 1: Public read when uploading the object

You can grant public read permission to an object during upload.

Conceptually:

```text
Upload object
     ↓
Grant public read
     ↓
Anyone on Internet
     ↓
Can GET/read object
```

So this option is correct:

> **Grant public read access to the object when uploading it using the S3 Console.**

### But remember

This is an **object-level** permission.

If you upload 1,000 files, you have to make sure the objects have the appropriate public-read permission.

---

# ✅ Answer 2: S3 Bucket Policy

This is generally the better approach for a public website.

You can create a bucket policy saying:

> Allow everyone (`Principal: "*"`) to perform `s3:GetObject` on objects in this bucket.

Conceptually:

```text
Bucket Policy
     ↓
Principal: *
Action: s3:GetObject
Resource: objects in bucket
     ↓
🌍 Public read
```

Therefore:

> **Configure the S3 bucket policy to set all objects to public read.**

is correct.

---

# ❌ Why CORS is NOT the answer

This is a very important distinction.

Many beginners think:

> CORS = make S3 public

❌ No.

### CORS answers a different question:

> **"Can a webpage from Domain A make browser requests to Domain B?"**

For example:

```text
website.com
     │
     │ JavaScript request
     ▼
S3 bucket
```

The browser may block that cross-origin request.

CORS tells the browser:

> "It's okay for this origin to access my resources."

So:

### CORS ≠ authentication/authorization

Think:

**CORS = browser permission**

**S3 policy = AWS access permission**

---

# ❌ Why IAM Role?

An IAM role doesn't automatically make S3 objects public.

For example:

```text
EC2
 ↓
IAM Role
 ↓
s3:GetObject
 ↓
EC2 can access S3
```

That's **private authenticated access**.

It doesn't mean:

```text
🌍 Everyone → S3
```

To make the objects public, you need an appropriate S3 resource policy/permissions.

---

# ❌ "Do nothing"

Definitely wrong.

S3 resources are **private by default**.

So:

```text
New S3 bucket
      ↓
Objects
      ↓
🔒 Private
```

You must explicitly grant access.

---

# 🧠 The key distinction for your exam

Memorize these three:

| Concept              | What does it do?                                    |
| -------------------- | --------------------------------------------------- |
| **S3 Bucket Policy** | Controls who can access S3 resources                |
| **IAM Policy/Role**  | Gives AWS identities permission to access resources |
| **CORS**             | Allows browser-based cross-origin requests          |

### The easiest memory trick:

> **CORS doesn't make something public. It makes cross-origin browser requests possible.**

And:

> **Bucket policy can actually grant public `s3:GetObject`.**

---

### One more important modern AWS note

For **real-world AWS configurations today**, S3 **Block Public Access** is enabled by default/recommended, so simply writing a public bucket policy may not work until the relevant public-access blocking settings are addressed. For the **exam question**, however, follow the stated scenario and the answer choices: **public-read upload + bucket policy**.
