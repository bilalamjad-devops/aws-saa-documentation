13. Question

Category: CSAA – Design Secure Architectures

An application is hosted on an EC2 instance with multiple EBS Volumes attached and uses Amazon Neptune as its database. To improve data security, you encrypted all of the EBS volumes attached to the instance to protect the confidential data stored in the volumes.

Which of the following statements are true about encrypted Amazon Elastic Block Store volumes? (Select TWO.)

- Snapshots are not automatically encrypted.
- Only the data in the volume is encrypted and not all the data moving between the volume and the instance.
- The volumes created from the encrypted snapshot are not encrypted.
- `All data moving between the volume and the instance are encrypted.`
- `Snapshots are automatically encrypted.`


Exactly — this question is testing **what encryption on EBS actually covers**.

## What is the question asking?

You have:

```text
EC2
 │
 ├── EBS Volume 1 🔒
 ├── EBS Volume 2 🔒
 └── EBS Volume 3 🔒
```

You encrypted the EBS volumes.

The question asks:

> **When an EBS volume is encrypted, what exactly gets encrypted?**

You need to select **TWO** correct statements.

### ✅ Correct answers

1. **All data moving between the volume and the instance are encrypted.**
2. **Snapshots are automatically encrypted.**

---

## 1. Data at rest is encrypted 🔒

An encrypted EBS volume protects the data stored inside it.

```text
EC2
 │
 ▼
┌─────────────────┐
│  EBS Volume     │
│                 │
│  Data 🔒        │
└─────────────────┘
```

This is called **encryption at rest**.

But AWS doesn't stop there.

---

## 2. Data moving between EC2 and EBS is also encrypted 🔒

This is the part that can easily be missed.

When the EC2 instance communicates with its attached encrypted EBS volume:

```text
EC2
 │
 │ 🔒 encrypted
 ▼
EBS Volume
```

The data moving between the instance and the EBS volume is encrypted.

Therefore:

> **"All data moving between the volume and the instance are encrypted."** ✅

---

## 3. What about snapshots?

This is another important exam point.

Suppose:

```text
Encrypted EBS Volume
        │
        ▼
   Snapshot 🔒
```

A snapshot created from an **encrypted EBS volume is automatically encrypted**.

So:

> **"Snapshots are automatically encrypted."** ✅

And if you create a new volume from that encrypted snapshot:

```text
Encrypted EBS
      │
      ▼
Encrypted Snapshot
      │
      ▼
New EBS Volume 🔒
```

The new volume is also encrypted.

---

# Let's eliminate the other answers

### ❌ "Snapshots are not automatically encrypted."

Wrong.

Encrypted EBS volume → snapshots created from it are **automatically encrypted**.

---

### ❌ "Only the data in the volume is encrypted and not all the data moving between the volume and the instance."

Wrong.

EBS encryption covers both:

* Data at rest
* Data moving between EC2 and EBS

---

### ❌ "The volumes created from the encrypted snapshot are not encrypted."

Wrong.

They **are encrypted**.

---

# 🧠 Memorize this for SAA

When you see:

> **Encrypted EBS volume**

Think of this chain:

```text
                 EBS Encryption
                      │
       ┌──────────────┼──────────────┐
       ▼              ▼              ▼
 Data at rest     EC2 ↔ EBS      Snapshots
    🔒               🔒              🔒
                                      │
                                      ▼
                              Volumes from
                              snapshot 🔒
```

### The key exam rule:

**Encrypted EBS → encrypted data + encrypted EC2/EBS traffic + encrypted snapshots + encrypted volumes created from snapshots.**

So for this question:

**✅ All data moving between the volume and the instance are encrypted.**
**✅ Snapshots are automatically encrypted.**

---

### One important distinction

Don't generalize this to **all EC2 network traffic**.

EBS encryption specifically protects the communication between:

```text
EC2 instance ↔ attached EBS volume
```

It does **not** mean that all network traffic coming from the EC2 instance is automatically encrypted.

For example:

```text
EC2 ──────── EBS       → EBS encryption
EC2 ──────── RDS       → separate consideration
EC2 ──────── Internet  → separate consideration
EC2 ──────── another EC2 → separate consideration
```

That's a useful distinction for SAA questions.
