11. Question
Category: CSAA – Design Secure Architectures
A solutions architect is writing an AWS Lambda function that will process encrypted documents from an Amazon FSx for NetApp ONTAP file system. The documents are protected by an AWS KMS customer key. After processing the documents, the Lambda function will store the results in an S3 bucket with an Amazon S3 Glacier Flexible Retrieval storage class. The solutions architect must ensure that the files can be decrypted by the Lambda function.

Which action accomplishes the requirement?


- Attach the kms:decrypt permission to the Lambda function’s resource policy. Add a statement to the AWS KMS key’s policy that grants the function’s execution role the kms:decrypt permission.
- Attach the kms:decrypt permission to the Lambda function’s resource policy. Add a statement to the AWS KMS key’s policy that grants the function’s resource policy ARN the kms:decrypt permission.
- Attach the kms:decrypt permission to the Lambda function’s execution role. Add a statement to the AWS KMS key’s policy that grants the function’s ARN the kms:decrypt permission.
- `Attach the kms:decrypt permission to the Lambda function’s execution role. Add a statement to the AWS KMS key’s policy that grants the function’s execution role the kms:decrypt permission.`

Absolutely bro. This one looks complicated because it throws **Lambda + FSx for ONTAP + KMS + S3 Glacier** at you, but the actual question is testing one simple AWS concept:

> **How does a Lambda function get permission to decrypt data using a KMS customer-managed key?**

---

# 1. What is the question actually saying?

Let's simplify the story.

You have:

```text
FSx for NetApp ONTAP
        │
        │ encrypted documents
        ▼
   AWS KMS key
        │
        │ Lambda needs to decrypt
        ▼
     Lambda
        │
        │ process document
        ▼
       S3
   Glacier Flexible Retrieval
```

The important part is:

> Lambda needs to **decrypt** the encrypted documents.

The question asks:

> **Where do we give Lambda permission to use `kms:Decrypt`?**

Answer:

### Two places:

1. **Lambda execution role** → give it `kms:Decrypt`
2. **KMS key policy** → allow that Lambda execution role to use `kms:Decrypt`

---

# 2. First understand Lambda Execution Role

Remember this concept:

A Lambda function needs to call AWS services.

For example:

```text
Lambda
  │
  ├──► S3
  ├──► DynamoDB
  ├──► KMS
  └──► CloudWatch
```

How does AWS know what Lambda is allowed to do?

Through its **execution role**.

For example:

```text
Lambda Execution Role
│
├── s3:GetObject
├── s3:PutObject
└── kms:Decrypt
```

So if Lambda needs to decrypt something:

> Give its **execution role** `kms:Decrypt`.

---

# 3. But why do we ALSO need the KMS key policy?

This is the part the question is really testing.

KMS is special.

A KMS key has a **key policy**.

Think of it as:

> **"Who is allowed to use this particular KMS key?"**

So you have:

```text
Lambda Execution Role
        │
        │ IAM policy
        │ kms:Decrypt
        ▼
      Lambda
        │
        │ request decrypt
        ▼
   KMS Customer Key
        │
        │ Key Policy
        │ allows Lambda execution role
        ▼
      Decrypt
```

Therefore, for this question, both sides matter.

### Lambda execution role:

```text
Action:
kms:Decrypt
```

### KMS key policy:

```text
Principal:
Lambda execution role ARN

Action:
kms:Decrypt
```

---

# 4. Very important: Execution Role vs Resource Policy

This is where the answer choices are trying to trick you.

There are two different things:

### Lambda execution role

Answers:

> **What can my Lambda function DO?**

For example:

```text
Lambda execution role
    ↓
kms:Decrypt
s3:GetObject
s3:PutObject
```

### Lambda resource policy

Answers:

> **Who can INVOKE my Lambda function?**

For example:

```text
Lambda resource policy
    ↓
Allow another AWS account
to invoke this Lambda
```

So:

**Lambda resource policy ≠ permissions Lambda uses to call KMS.**

For KMS access, think:

> **Execution Role**

---

# 5. Why isn't the Lambda function ARN used?

This is another exam trap.

The option says something like:

> Give `kms:Decrypt` to the Lambda function ARN.

❌ Not the right principal.

Lambda interacts with KMS using the **execution role**.

So:

```text
❌ Lambda Function ARN
```

versus

```text
✅ Lambda Execution Role ARN
```

Remember:

> **Lambda → AWS services = Execution Role**

---

# 6. Why is `kms:Decrypt` needed?

Because the document is encrypted.

Imagine:

```text
Encrypted document
      ↓
   KMS key
      ↓
kms:Decrypt
      ↓
Lambda can process it
```

If Lambda doesn't have permission:

```text
Lambda
   │
   │ "Please decrypt this"
   ▼
KMS
   │
   └── ❌ AccessDenied
```

So we need:

```text
kms:Decrypt
```

---

# 7. What about FSx for NetApp ONTAP?

Don't let this part confuse you.

The question mentions:

> FSx for NetApp ONTAP

because that's where the encrypted documents are stored.

FSx for NetApp ONTAP encrypts data at rest using KMS.

But your application doesn't manually decrypt the underlying FSx storage encryption.

AWS/FSx handles the storage encryption transparently.

The important exam requirement is:

> **Lambda needs access to the KMS customer key.**

---

# 8. What about S3 Glacier Flexible Retrieval?

Again, don't get distracted.

The question says Lambda processes the document and then stores the result in:

> S3 Glacier Flexible Retrieval

That is mainly telling you where the processed result goes.

It isn't the key concept being tested.

The actual test is:

```text
KMS customer-managed key
          +
Lambda
          +
kms:Decrypt
          +
Execution Role + Key Policy
```

---

# 9. Let's eliminate every option

### Option A

> `kms:Decrypt` on Lambda **resource policy** + KMS key policy allows execution role.

❌ Wrong.

Lambda resource policy controls **who can invoke Lambda**, not what Lambda can call.

---

### Option B

> `kms:Decrypt` on Lambda resource policy + KMS policy allows resource policy ARN.

❌ Wrong twice.

* Wrong Lambda policy type.
* Resource policy ARN isn't the correct identity here.

---

### Option C

> `kms:Decrypt` on Lambda execution role + KMS policy allows **Lambda function ARN**.

❌ Almost correct, but wrong principal.

Should be:

```text
Lambda execution role ARN
```

not:

```text
Lambda function ARN
```

---

### Option D ✅

> `kms:Decrypt` on Lambda execution role + KMS key policy allows Lambda execution role.

Exactly right.

---

# 🧠 Exam memory trick

When you see:

> **Lambda needs to access KMS**

immediately think:

```text
Lambda
  │
  ▼
Execution Role
  │
  │ kms:Decrypt
  ▼
KMS Key
  │
  ▼
Key Policy
  │
  │ allows Execution Role
  ▼
Access granted
```

### Memorize this:

> **Lambda's permissions → Execution Role**
> **KMS's permissions → Key Policy**

And one more:

> **Lambda Resource Policy = who can invoke Lambda**

---

## One important correction to keep in your notes

The Tutorials Dojo explanation is a little easy to misread because it says IAM policies alone don't necessarily grant access to a KMS key.

For exam purposes, the safest mental model is:

**KMS access requires authorization through the KMS key policy, and the Lambda execution role must have the IAM permission as appropriate.**

So when the answer explicitly asks for both, choose:

> ✅ **Execution role: `kms:Decrypt` + KMS key policy: allow that execution role `kms:Decrypt`.**

That's the pattern you should recognize in SAA questions.
