28. Question

Category: CSAA – Design Secure Architectures

A company is designing a customized text messaging service that targets its mobile app users. As part of its multi-engagement marketing campaign, a company needs to send a one-time confirmation message to all of its subscribers using Short Message Service (SMS). The solutions architect must design the system to allow a subscriber to reply to the SMS messages.

The customer responses must be kept for an entire year for analysis and targeted sale promotions. In addition, the SMS responses must also be collected, processed, and analyzed in near-real-time.

Which solution will meet these requirements with the LEAST operational overhead?

- Launch a new Amazon Simple Queue Service (Amazon SQS) queue to send out SMS messages. Use AWS Step Functions and AWS Lambda to collect, process, and analyze responses. Store the data to Amazon S3 Glacier Instant Retrieval.
- Create a new topic in Amazon Simple Notification Service (Amazon SNS) and an Amazon Kinesis data stream configured with all its default settings. Send SMS messages using Amazon SNS. Integrate the Kinesis data stream to the SNS topic for data collection, archiving, and analysis.
- `Create an Amazon Pinpoint journey for the multi-engagement SMS marketing campaign and an Amazon Kinesis Data Stream for analysis. Configure Amazon Pinpoint to send events to the Kinesis data stream for collection, processing, and analysis. Set the retention period of the Kinesis data stream to 365 days.`
- Set up an Amazon Connect contact flow to send the confirmation SMS messages to the mobile app users. Deploy an AWS Lambda function to process and analyze the responses. Store the data to Amazon S3 Glacier Flexible Retrieval

Yes bro. This question looks complicated because it combines **SMS marketing + replies + real-time processing + 1-year retention**. But once you separate the requirements, the answer becomes quite easy.

# What is the question asking?

A company wants to send **SMS messages to many mobile users**.

For example:

```text
Company
   │
   │ SMS
   ↓
100,000 subscribers
```

The SMS is something like:

> "Your confirmation code is 123456."

But there's an additional requirement:

> Users must be able to **reply** to the SMS.

For example:

```text
Company → "Reply YES to confirm your subscription"
                    ↓
                 User
                    ↓
               "YES"
                    ↓
                 Company
```

Now the company wants to do **two things with those replies**:

### 1. Keep them for 1 year

```text
User response
     ↓
Store
     ↓
365 days
```

Why? For future analysis and marketing.

### 2. Process them almost immediately

"Near-real-time" means:

> Don't wait hours or days. Process/analyze the responses shortly after they arrive.

So the requirements are:

| Requirement                | Meaning                      |
| -------------------------- | ---------------------------- |
| SMS campaign               | Send SMS to subscribers      |
| Two-way SMS                | Users can reply              |
| Near-real-time             | Process responses quickly    |
| 1-year retention           | Keep event data for 365 days |
| Least operational overhead | Prefer managed services      |

---

# ✅ Correct answer

> **Amazon Pinpoint + Amazon Kinesis Data Streams with 365-day retention**

The architecture is roughly:

```text
                  Amazon Pinpoint
                       │
                 SMS Campaign
                       │
                       ↓
                 Mobile Users
                       │
                    Replies
                       │
                       ↓
              Pinpoint Events
                       │
                       ↓
             Kinesis Data Stream
                  │          │
                  │          │
                  ↓          ↓
             Processing    Analysis
                       
             Retention = 365 days
```

---

# What is Amazon Pinpoint?

Think of **Amazon Pinpoint as a marketing/customer-engagement service**.

It is designed for things like:

* SMS campaigns
* Email campaigns
* Push notifications
* Customer engagement
* Campaign journeys
* Tracking customer interactions

So when the question says:

> **multi-engagement marketing campaign**

🚨 Think:

**Amazon Pinpoint**

---

# What is a Pinpoint Journey?

A **Journey** lets you design a customer-engagement workflow.

For example:

```text
Send SMS
   ↓
Did customer respond?
   ↓
 YES ─────────→ Send offer
   │
   NO
   ↓
Wait
   ↓
Send reminder
```

That's why Pinpoint is much more suitable than simply using SNS for a marketing campaign.

---

# What does Kinesis do here?

This is the second major clue.

The question says:

> responses must be collected, processed, and analyzed in **near-real-time**.

🚨 Think:

**Kinesis**

Kinesis is designed for **streaming data**.

So:

```text
Pinpoint events
      ↓
Kinesis Data Stream
      ↓
Real-time processing
      ↓
Analytics
```

---

# Why 365 days?

This is the other big clue.

Kinesis Data Streams has a configurable retention period.

The question explicitly says:

> Keep responses for an entire year.

Therefore:

```text
Kinesis retention
      ↓
365 days
```

This is important because the default retention period in the exam explanation is only **24 hours**.

So if you choose:

> Kinesis with default settings

❌ You don't satisfy the one-year requirement.

---

# Why SNS is wrong?

SNS can absolutely send SMS.

That's what makes this option tempting.

But the question isn't simply:

> "Send an SMS."

It's:

> **Run a multi-engagement SMS marketing campaign and collect/analyze the resulting events.**

SNS is primarily a **pub/sub messaging service**.

Pinpoint is specifically designed for:

> **customer engagement and marketing campaigns.**

So:

```text
Simple SMS notification
       ↓
SNS can work

Marketing campaign / customer journey
       ↓
Pinpoint
```

---

# Why SQS is wrong?

SQS is a **message queue**.

Think:

```text
Application
    ↓
   SQS
    ↓
Worker
```

It's excellent for decoupling applications and processing messages asynchronously.

But SQS itself isn't your SMS marketing campaign service.

So:

> SQS → SMS campaign

❌ Wrong tool.

---

# Why Amazon Connect is wrong?

Amazon Connect is primarily a **contact center** service.

Think:

```text
Customer
   ↓
Contact Center
   ↓
Amazon Connect
   ↓
Agents / IVR / communication
```

You *could* build communication around it, but it introduces unnecessary complexity for this requirement.

The question specifically says:

> **LEAST operational overhead**

So don't choose a much heavier solution when Pinpoint is designed for this use case.

---

# 🧠 The important exam pattern

This question is really testing whether you can map **requirements → AWS service**.

### Marketing SMS campaign

➡️ **Amazon Pinpoint**

### Customer engagement journey

➡️ **Amazon Pinpoint Journey**

### Near-real-time event streaming

➡️ **Kinesis Data Streams**

### Keep stream data for 1 year

➡️ **Kinesis retention = 365 days**

So:

> **Pinpoint + Kinesis Data Streams + 365-day retention**

---

## One thing to be careful about

The wording in this question is somewhat dated. **Amazon Pinpoint's product/service availability and capabilities have changed over time**, so for your SAA exam, follow the version of the AWS material your practice bank is based on. The conceptual pattern being tested here is still:

**customer engagement/campaign → Pinpoint; streaming event data → Kinesis; long retention → configure retention appropriately.**

### 🔥 SAA shortcut

When you see:

> **Marketing + SMS + customer engagement + journey**

Think **Pinpoint**.

When you see:

> **Real-time streaming data/events**

Think **Kinesis**.

When you see:

> **Queue / decouple applications**

Think **SQS**.

When you see:

> **Pub/sub notifications**

Think **SNS**.

When you see:

> **Contact center / call center**

Think **Amazon Connect**.
