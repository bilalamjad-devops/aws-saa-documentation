29. Question

Category: CSAA – Design Secure Architectures

A large financial firm needs to set up a Linux bastion host to allow access to the Amazon EC2 instances running in their VPC. For security purposes, only the clients connecting from the corporate external public IP address 175.45.116.100 should have SSH access to the host.

Which is the best option that can meet the customer’s requirement?

- Network ACL Inbound Rule: Protocol – TCP, Port Range-22, Source 175.45.116.100/0
- Security Group Inbound Rule: Protocol – UDP, Port Range – 22, Source 175.45.116.100/32
- `Security Group Inbound Rule: Protocol – TCP. Port Range – 22, Source 175.45.116.100/32`
- Network ACL Inbound Rule: Protocol – UDP, Port Range – 22, Source 175.45.116.100/32


Yes bro, this one is a **very straightforward Security Group + CIDR + SSH** question. Let's break it down.

# What is the question asking?

The company has a **Linux bastion host**.

A bastion host is basically a **jump server**:

```text
Corporate Network
175.45.116.100
        │
        │ SSH
        ↓
   Bastion Host
        │
        │ SSH
        ↓
   Private EC2s
```

Instead of allowing employees to SSH directly into all the private EC2 instances, they first connect to the bastion host.

The requirement is:

> **Only the company's public IP `175.45.116.100` can SSH into the bastion host.**

Nobody else on the Internet should be able to SSH to it.

---

# ✅ Correct answer

**Security Group Inbound Rule:**

```text
Protocol: TCP
Port: 22
Source: 175.45.116.100/32
```

This is exactly what we want.

---

# Why `/32`?

This is extremely important for SAA.

Remember:

```text
175.45.116.100/32
```

means:

> **Exactly ONE IPv4 address**

So:

```text
175.45.116.100/32
        ↓
Only this IP
```

Whereas:

```text
0.0.0.0/0
```

means:

> **Everyone / all IPv4 addresses**

So if you used:

```text
175.45.116.100/0
```

that doesn't mean "this IP."

The `/0` effectively represents the entire IPv4 address space.

### Memorize:

| CIDR         | Meaning                          |
| ------------ | -------------------------------- |
| `x.x.x.x/32` | **One specific IP**              |
| `x.x.x.x/24` | Network containing 256 addresses |
| `0.0.0.0/0`  | **All IPv4 addresses**           |

---

# Why TCP?

SSH uses:

> **TCP port 22**

So:

```text
SSH
 ↓
TCP
 ↓
22
```

Not UDP.

Therefore these are immediately wrong:

```text
UDP + 22 ❌
```

---

# Why Security Group instead of NACL?

This is another important exam pattern.

### Security Group

Works at the:

> **EC2 instance/resource level**

So if the requirement says:

> "Protect this EC2 instance"

Security Group is usually the natural answer.

```text
VPC
 │
 └── Subnet
      │
      ├── Bastion EC2
      │      ↑
      │      Security Group
      │
      └── Other EC2
```

### Network ACL

Works at:

> **Subnet level**

So:

```text
Subnet
   ↑
 NACL
```

It can affect **all resources in that subnet**.

For this question, we're specifically controlling access to the **bastion EC2**, so Security Group is the better choice.

---

# Let's eliminate every option

### Option 1

> NACL + TCP 22 + `175.45.116.100/0`

❌ Wrong.

Why?

`/0` = entire IPv4 range.

The requirement is **only one IP**.

---

### Option 2

> Security Group + UDP 22 + `/32`

❌ Wrong.

The IP restriction is correct, but:

**SSH = TCP, not UDP.**

---

### Option 3

> Security Group + TCP 22 + `/32`

✅ **Correct.**

Everything matches:

```text
Security Group
TCP
22
175.45.116.100/32
```

---

### Option 4

> NACL + UDP 22 + `/32`

❌ Wrong twice:

* UDP instead of TCP
* NACL instead of the more appropriate instance-level Security Group

---

# 🧠 The exam shortcut

When you see:

> **Linux + SSH**

Think:

**TCP 22**

When you see:

> **Only this one IP**

Think:

**`/32`**

When you see:

> **Protect a specific EC2 instance**

Think:

**Security Group**

When you see:

> **Protect an entire subnet**

Think:

**NACL**

Therefore:

> **Linux bastion + SSH + one corporate IP = Security Group + TCP 22 + corporate-IP/32.**

This is actually the same pattern you just saw in **Question 2**, so you're starting to see the repetition in SAA questions.
