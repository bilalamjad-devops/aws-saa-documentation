4. Question

Category: CSAA – Design Resilient Architectures

A Forex trading platform, which frequently processes and stores global financial data every minute, is hosted in an on-premises data center and uses an Oracle database. Due to a recent cooling problem in its data center, the company urgently needs to migrate its infrastructure to AWS to improve the performance of its applications. As the Solutions Architect, the responsibility is to ensure that the database is properly migrated and remains available in case of database server failure in the future, following AWS Prescriptive Guidance for database migration and high availability.

Which combination of actions would meet the requirement? (Select TWO.)

- Launch an Oracle database instance in Amazon RDS with Recovery Manager (RMAN) enabled.
- `Create an Oracle database in Amazon RDS with Multi-AZ deployments.`
- Migrate the Oracle database to a non-cluster Amazon Aurora with a single instance.
- `Migrate the Oracle database to AWS using the AWS Database Migration Service`
- Convert the database schema using the AWS Schema Conversion Tool.

This one is actually a **very useful SAA pattern** because it combines **database migration + database compatibility + high availability**.

Let's make it very simple.

---

# First: What is the question asking?

The company currently has:

```text
On-premises
     ↓
Oracle Database
     ↓
Forex trading platform
```

They want to move it to AWS.

There are **two requirements**:

### Requirement 1 — Move the existing Oracle database to AWS

They already use **Oracle**.

### Requirement 2 — Database must survive a server failure

If the primary database server crashes:

```text
Primary DB ❌
     ↓
Application should continue
     ↓
Standby DB ✅
```

So we need:

**Migration tool + High Availability**

---

# Step 1: How do we migrate the database?

The existing database is:

> **Oracle**

AWS provides **AWS Database Migration Service (DMS)** for migrating databases.

Think of DMS as:

> 🚚 **A truck that moves database data from one place to another.**

```text
On-Premises Oracle
       ↓
      DMS
       ↓
AWS Oracle RDS
```

DMS is especially useful when you want to migrate with minimal downtime.

### Therefore:

✅ **AWS Database Migration Service**

---

# Step 2: How do we make Oracle highly available?

The company says:

> "database remains available in case of database server failure"

We need **Multi-AZ**.

With RDS Multi-AZ:

```text
             RDS
              |
       ┌──────┴──────┐
       ↓             ↓
   Primary        Standby
    AZ-1            AZ-2
       │             │
       └── sync ─────┘
```

Data is synchronously replicated to the standby.

If the primary fails:

```text
Primary ❌
    ↓
Automatic failover
    ↓
Standby becomes primary ✅
```

And importantly, the application continues using the same database endpoint.

### Therefore:

✅ **Create an Oracle database in Amazon RDS with Multi-AZ deployments.**

---

# ✅ Correct TWO answers

### 1. **Create an Oracle database in Amazon RDS with Multi-AZ deployments.**

### 2. **Migrate the Oracle database to AWS using AWS Database Migration Service.**

---

# Now let's understand why the other answers are wrong

## ❌ Oracle + RMAN

The answer says:

> Launch an Oracle database instance in RDS with Recovery Manager (RMAN) enabled.

RMAN is an Oracle database backup/recovery technology.

But the important SAA fact here is:

> **Amazon RDS for Oracle doesn't support RMAN in the way described.**

So don't choose it.

---

# ❌ AWS Schema Conversion Tool

This is an important distinction.

**AWS SCT = Schema Conversion Tool**

Think:

> "I'm changing the type of database."

For example:

```text
Oracle
   ↓
PostgreSQL
```

The schemas may be different, so you need conversion.

But here:

```text
Oracle
   ↓
Oracle RDS
```

It's the **same database engine**.

That's called a:

### Homogeneous migration

So:

```text
Oracle → Oracle
       ↓
   No schema conversion
```

Whereas:

```text
Oracle → PostgreSQL
       ↓
Schema conversion may be needed
```

Therefore:

❌ SCT

---

# ❌ Aurora single instance

This is another important trap.

Aurora is a great database service, but the question isn't simply asking:

> "Which AWS database is good?"

It specifically needs:

> **Oracle**

Aurora is compatible with:

* MySQL
* PostgreSQL

It is **not an Oracle database engine**.

So you can't simply take:

```text
Oracle
  ↓
Aurora
```

and expect it to remain an Oracle database.

You would need a database-engine conversion/migration strategy.

And the answer specifically says **non-cluster Aurora with a single instance**, which also doesn't meet the high-availability requirement well.

So:

❌ Aurora single instance

---

# 🧠 The important SAA pattern

This question teaches you **three things**.

### 1. Same database engine?

Think:

**Homogeneous migration**

```text
Oracle → Oracle
MySQL → MySQL
PostgreSQL → PostgreSQL
```

DMS can help.

---

### 2. Different database engine?

Think:

**Heterogeneous migration**

```text
Oracle → PostgreSQL
SQL Server → PostgreSQL
Oracle → Aurora PostgreSQL
```

Now **AWS SCT** may be needed to convert the schema.

Usually:

```text
SCT → convert schema
DMS → migrate data
```

---

### 3. Need database failure protection?

Think:

**RDS Multi-AZ**

```text
Primary
   ↓ synchronous replication
Standby
```

Failure:

```text
Primary ❌
   ↓
Automatic failover
   ↓
Standby ✅
```

---

# 🎯 Exam shortcut

When you see:

> **Existing Oracle → AWS Oracle RDS**

Think:

### **DMS**

When you see:

> **Different database engines**

Think:

### **SCT + DMS**

When you see:

> **Database must remain available if the DB server/AZ fails**

Think:

### **Multi-AZ**

So this question becomes:

```text
Oracle → Oracle RDS
       ↓
      DMS

Need HA
       ↓
   Multi-AZ
```

### Final answer:

**✅ RDS for Oracle + Multi-AZ**

**✅ AWS DMS**

---

### One correction to keep in your notes

Be careful with explanations that say **DMS guarantees "zero data loss."** DMS is designed to support low-downtime migrations and ongoing replication, but the exact data-loss characteristics depend on the migration configuration and cutover process.

For the exam, the important association is:

> **DMS = database migration/replication**

and

> **Multi-AZ = high availability/failover**.
