
29. Question

Category: CSAA – Design Resilient Architectures

A multinational manufacturing company has multiple accounts in AWS to separate their various departments such as finance, human resources, engineering and many others. There is a requirement to ensure that certain access to services and actions are properly controlled to comply with the security policy of the company.

As the Solutions Architect, which is the most suitable way to set up the multi-account AWS environment of the company?

- `Use AWS Organizations and Service Control Policies to control services on each account.`
- Set up a common IAM policy that can be applied across all AWS accounts.
- Connect all departments by setting up a cross-account access to each of the AWS accounts of the company. Create and attach IAM policies to your resources based on their respective departments to control access.
- Provide access to externally authenticated users via Identity Federation. Set up an IAM role to specify permissions for users from each department whose identity is federated from your organization or a third-party identity provider.


## Question 29 — AWS Organizations + SCP

This question is testing **centralized control over multiple AWS accounts**.

Imagine the company has:

```text
AWS Organization
│
├── Finance Account
├── HR Account
├── Engineering Account
├── Marketing Account
└── Security Account
```

Management wants to say:

> "Across these accounts, certain AWS services/actions must not be allowed."

For example:

> "Nobody in any account is allowed to disable CloudTrail."

That's where **AWS Organizations + Service Control Policies (SCPs)** come in.

### ✅ Correct answer

> **Use AWS Organizations and Service Control Policies (SCPs) to control services on each account.**

---

## What does an SCP actually do?

Think of an SCP as a **maximum permission boundary for an AWS account**.

For example:

```text
SCP
│
└── Deny disabling CloudTrail
          ↓
     ┌────┴────┐
     ↓         ↓
 Finance      HR
 Account    Account
```

Even if someone has an IAM policy saying:

```text
Allow cloudtrail:StopLogging
```

an SCP can prevent that action.

### 🧠 Very important distinction

**IAM Policy** → controls **what a user/role can do**

**SCP** → controls **what an AWS account can allow**

An SCP **does not grant permissions**.

It establishes the **maximum permissions** available within the account.

---

## Why AWS Organizations?

Organizations lets you centrally manage many AWS accounts.

Instead of manually configuring:

```text
Finance → policies
HR → policies
Engineering → policies
...
```

you can organize accounts and apply policies centrally.

For example:

```text
AWS Organizations
       │
       ↓
   Production OU
       │
   ┌───┴────┐
   ↓        ↓
Account A  Account B
   │        │
   └── SCP ─┘
```

This reduces administrative overhead.

---

## Why the other answers are wrong

### ❌ Common IAM policy

You cannot simply create **one IAM policy in one account and apply it globally to all AWS accounts**.

Organizations + SCP is designed for this centralized multi-account governance.

---

### ❌ Cross-account IAM roles

Cross-account roles are useful when:

> Account A needs to access resources in Account B.

But this question isn't primarily about **cross-account resource access**.

It's about:

> **centrally controlling what services/actions accounts are allowed to use.**

That's an SCP job.

---

### ❌ Identity Federation

Identity Federation answers:

> **"How do users authenticate and get access?"**

For example, employees sign in using an external identity provider.

But the question is asking:

> **"How do we centrally control AWS services/actions across many accounts?"**

That's **Organizations + SCP**.

---

# 🧠 Memorize this SAA distinction

| Requirement                         | Think                                |
| ----------------------------------- | ------------------------------------ |
| Multiple AWS accounts               | **AWS Organizations**                |
| Centrally restrict services/actions | **SCP**                              |
| Control what a user/role can do     | **IAM Policy**                       |
| User authentication                 | **IAM Identity Center / Federation** |
| Account A accessing Account B       | **Cross-account IAM role**           |

### 🎯 Exam shortcut

If you see:

> **"Multiple AWS accounts + centrally control/restrict AWS services/actions"**

🚨 **AWS Organizations + SCP**

And remember:

> **SCP = Guardrail, NOT permission grant.**

That's the most important concept from this question.
