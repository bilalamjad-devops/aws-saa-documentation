A company plans to implement a network monitoring system in AWS. The Solutions Architect launched an EC2 instance to host the monitoring system and used CloudWatch to monitor, store, and access the log files of the instance.

Which of the following provides an automated way to send log data to CloudWatch Logs from the Amazon EC2 instance?

- CloudTrail Processing Library
- AWS Transfer for SFTP
- `CloudWatch Logs agent`
- CloudTrail with log file validation

This one is much easier if you remember **what kind of logs we're talking about**.

# Question in very simple words

You have:

```text
EC2 instance
    ↓
contains application/system log files
    ↓
Need to automatically send those logs
    ↓
CloudWatch Logs
```

The question asks:

> **What tool can automatically take log files from an EC2 instance and send them to CloudWatch Logs?**

---

# ✅ Correct answer: CloudWatch Logs agent

The **CloudWatch Logs agent** runs on the EC2 instance and watches specified log files.

For example, your EC2 has:

```text
/var/log/messages
/var/log/app.log
/var/log/nginx/access.log
```

The agent can monitor these files and send their contents to:

```text
Amazon CloudWatch Logs
```

So conceptually:

```text
        EC2
┌──────────────────┐
│ /var/log/app.log │
│ /var/log/system  │
└────────┬─────────┘
         │
         │ CloudWatch Logs agent
         ↓
┌──────────────────────┐
│ CloudWatch Logs      │
│                      │
│ Log Group            │
│   └── Log Streams    │
└──────────────────────┘
```

### 🧠 Remember:

> **EC2 log files → CloudWatch Logs = CloudWatch agent**

---

# ⚠️ Modern AWS terminology

For your **exam preparation**, you'll often see older material calling this the **CloudWatch Logs agent**.

In modern AWS environments, the **Amazon CloudWatch agent** is the more important/current agent to know. It can collect:

* Logs
* Metrics
* System-level information

So when you're doing real-world work, think:

> **CloudWatch Agent → EC2 logs/metrics → CloudWatch**

But if the exam question specifically gives:

> **CloudWatch Logs agent**

that's the expected answer.

---

# Why the other answers are wrong

### ❌ AWS Transfer for SFTP

This is for transferring files using **SFTP**.

Think:

```text
SFTP
 ↓
Transfer files
```

It isn't an EC2 log collection agent.

---

### ❌ CloudTrail with log file validation

**CloudTrail = AWS API activity**

For example:

```text
Who deleted an S3 bucket?
Who created an EC2 instance?
Who changed an IAM policy?
```

CloudTrail records API/activity events.

It is **not** the normal tool for collecting:

```text
/var/log/app.log
```

---

### ❌ CloudTrail Processing Library

This is related to **processing CloudTrail events/logs**.

Don't confuse:

```text
CloudTrail
    ↓
AWS API activity
```

with:

```text
CloudWatch Agent
    ↓
EC2 logs + metrics
```

---

# 🧠 Important distinction for SAA

You should now have this mental map:

| Service/tool         | Think about                           |
| -------------------- | ------------------------------------- |
| **CloudWatch**       | Monitoring AWS resources              |
| **CloudWatch Logs**  | Collect/search/store logs             |
| **CloudWatch Agent** | Send EC2 logs + metrics to CloudWatch |
| **CloudTrail**       | AWS API calls / account activity      |
| **AWS Config**       | Resource configuration/compliance     |
| **VPC Flow Logs**    | Network traffic metadata              |

This distinction is **very important for SAA questions**.

### Quick examples

**"Who deleted my S3 bucket?"**

→ **CloudTrail**

**"I want to collect `/var/log/nginx/error.log` from EC2."**

→ **CloudWatch Agent**

**"I want to monitor EC2 CPU utilization."**

→ **CloudWatch**

**"I want to investigate traffic entering/leaving an ENI."**

→ **VPC Flow Logs**
