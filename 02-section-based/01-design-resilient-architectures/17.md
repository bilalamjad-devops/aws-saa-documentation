17. Question

Category: CSAA – Design Resilient Architectures

An application is using an AWS Lambda function to process complex financial data that runs for 15 minutes on average. The Lambda function has been configured with the maximum memory allocation to handle the computational demands of the financial data processing. Most invocations were successfully processed. However, a few terminated invocations were noticed throughout the day, which caused a data discrepancy in the application.

Which of the following is the most likely cause of this issue?

- The Lambda function contains a recursive code and has been running for over 15 minutes.
- The concurrent execution limit has been reached.
- The failed Lambda Invocations contain a ServiceException error which means that the Lambda service encountered an internal error.
- `The failed Lambda functions have been running for over 15 minutes and reached the maximum execution time.`

### Question 17 — Easy explanation

This question is testing **one very important Lambda limit**.

The application processes complex financial data and the Lambda function takes **around 15 minutes**.

The key fact is:

> **AWS Lambda maximum execution time = 15 minutes (900 seconds).**

So imagine:

```text
Lambda starts
     │
     ├── 5 min ✅
     ├── 10 min ✅
     ├── 14 min ✅
     └── 15 min ⛔
              ↓
       Lambda terminates
```

If a particular invocation needs **more than 15 minutes**, Lambda automatically terminates it.

### ✅ Correct answer

**The failed Lambda functions have been running for over 15 minutes and reached the maximum execution time.**

### Why only a few failed?

This is an important clue.

Most financial-data jobs finish within the 15-minute limit:

```text
Invocation 1 → 8 min  → ✅
Invocation 2 → 11 min → ✅
Invocation 3 → 14 min → ✅
Invocation 4 → 16 min → ❌
Invocation 5 → 9 min  → ✅
```

The few unusually large/complex workloads exceed the maximum.

### Why not concurrency?

If Lambda reaches its concurrency limit, **new invocations are throttled**. They aren't normally terminated after running for a while.

Think:

> **Concurrency limit → throttling**

> **15-minute limit → execution terminated**

### Why not recursive code?

Recursive Lambda code can cause many invocations and potentially high costs, but the key issue in this question is the **15-minute execution limit**.

### 🧠 SAA memory rule

Remember:

**Lambda**

* Default timeout → **3 seconds**
* Maximum timeout → **15 minutes / 900 seconds**

So when you see:

> "Lambda runs for 15 minutes and some executions are terminated"

🚨 **Immediately think: Lambda maximum execution timeout.**

And if the workload genuinely needs to run **longer than 15 minutes**, Lambda is usually not the appropriate compute service; consider something like **ECS/Fargate, AWS Batch, or EC2**, depending on the workload.
