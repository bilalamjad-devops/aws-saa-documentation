20. Question

Category: CSAA – Design Resilient Architectures

An accounting application uses an Amazon RDS database configured with RDS Multi-AZ to improve availability. What would happen to RDS if the primary database instance fails?

- `The canonical name record (CNAME) is switched from the primary to standby instance.`
- The primary database instance will reboot.
- The IP address of the primary DB instance is switched to the standby DB instance.
- A new database instance is created in the standby Availability Zone.

## Question 20 — Easy explanation

This is testing **RDS Multi-AZ failover**.

The important thing is that **RDS Multi-AZ already has a standby instance** in another Availability Zone.

Think:

```text
AZ-1                         AZ-2
┌──────────────┐             ┌──────────────┐
│   PRIMARY    │ ──sync──→   │   STANDBY    │
│   RDS DB     │             │   RDS DB     │
└──────────────┘             └──────────────┘
       │
       │ failure ❌
       ↓
                         STANDBY promoted
                              ↓
                           PRIMARY
```

So AWS **doesn't create a new database** when the primary fails. The standby is already there.

### ✅ Correct answer

> **The canonical name record (CNAME) is switched from the primary to the standby instance.**

The application continues using the **same RDS endpoint**. AWS changes where that endpoint points.

This is an important exam concept:

> **RDS Multi-AZ failover = standby becomes primary + DNS/CNAME endpoint is redirected**

### Why not IP address?

❌ **"The IP address is switched"**

Think of the application as connecting to:

```text
mydatabase.xxxxx.rds.amazonaws.com
```

It doesn't need to know the individual DB instance's IP.

AWS changes the DNS/CNAME mapping behind that endpoint.

### Why not reboot?

❌ **"Primary reboots"**

The primary has failed. The whole point of Multi-AZ is to fail over to the already-running standby rather than waiting for the failed instance to recover.

### Why not create a new instance?

❌ **"A new DB instance is created"**

There is **already a standby**.

That's why Multi-AZ provides fast failover.

---

## 🧠 Memorize this

### RDS Multi-AZ

**Primary fails → Standby takes over → DNS/CNAME points to standby**

And one very important SAA distinction:

> **Multi-AZ = High Availability / Failover**

> **Read Replicas = Read scalability**

So:

**Need protection from DB failure?** → **Multi-AZ**

**Need more read capacity?** → **Read Replicas**

This distinction will appear repeatedly in SAA questions.
