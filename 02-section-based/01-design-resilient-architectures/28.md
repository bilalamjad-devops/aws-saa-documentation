28. Question

Category: CSAA – Design Resilient Architectures

A company has a set of Linux servers running on multiple On-Demand Amazon EC2 instances powered by the EC2 Nitro System. The Audit team wants to collect and process the application log files generated from these servers for the report.

Which of the following is the most suitable solution to meet this requirement?

- Amazon S3 Glacier for storing the application log files and Spot EC2 Instances for processing them.
- Amazon S3 Glacier Deep Archive for storing the application log files and AWS ParallelCluster for processing the log files.
- `Amazon S3 for storing the application log files and Amazon Elastic MapReduce for processing the log files.`
- A single On-Demand EC2 instance for both storing and processing the log files


### Question 28 — Simple explanation

The key is to recognize **two separate requirements**:

1. **Store lots of application logs** → Amazon **S3**
2. **Process/analyze lots of logs** → Amazon **EMR**

So the correct answer is:

> ✅ **Amazon S3 for storing the application log files and Amazon EMR for processing the log files.**

### Why S3 + EMR?

Think of it as:

**EC2 servers → logs → S3 → EMR → analysis/report**

* **S3** = durable, scalable object storage. Great for collecting large amounts of logs.
* **EMR** = managed Big Data processing platform. It can run frameworks such as **Spark/Hadoop** to process huge datasets stored in S3.

### Why not the others?

* ❌ **S3 Glacier + Spot EC2** → Glacier is primarily for **archiving**, not data that you need to process frequently.
* ❌ **S3 Glacier Deep Archive + ParallelCluster** → Deep Archive is for very long-term archival and has retrieval delays. ParallelCluster is mainly for **HPC**, not this Big Data processing use case.
* ❌ **Single EC2 for storage + processing** → EC2 isn't your scalable storage layer. Use **S3 for storage**.

### 🧠 Memorize this

For these SAA questions:

> **Large data/logs → S3**
> **Big Data processing → EMR**
> **Long-term archive → Glacier / Glacier Deep Archive**
> **HPC → ParallelCluster**

So when you see **"collect/store huge logs + process/analyze them"**, think:

**S3 + EMR**.
