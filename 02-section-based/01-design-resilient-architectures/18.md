18. Question

Category: CSAA – Design Secure Architectures

A financial services organization is developing a cloud-native application on AWS to process and analyze customer transaction data. The application utilizes Amazon Aurora for the database, Amazon EFS for file storage, and Amazon EventBridge to trigger AWS Step Functions for workflow orchestration.

The organization has implemented AWS IAM Identity Center for user authentication. The data science, engineering, and compliance teams require secure access to Amazon Aurora and Amazon EFS while maintaining strict data privacy standards. The solution must adhere to the principle of least privilege and minimize administrative overhead.

Which approach best satisfies these requirements?

- Create separate AWS accounts for each team using AWS Organizations. Set up cross-account IAM roles with least privilege and assign specific Aurora and EFS permissions based on team roles.
- Set up AWS Control Tower to manage multi-account access. Use Service Control Policies (SCPs) to restrict access to Aurora and EFS at the organizational level. Create IAM roles in each account with specific permissions.
- Use Amazon Cognito User Pools for authentication and use Cognito Identity Pools to provide temporary AWS credentials. Create fine-grained IAM roles for Aurora and EFS access in each team.
- `Enable the IAM Identity Center with an Identity Center directory and create permission sets for granular access for Amazon Aurora and Amazon EFS. Assign teams to groups linked to specific permission sets based on their roles.`

### Question 18 — Easy explanation

This question is mainly testing:

> **IAM Identity Center + Permission Sets + Groups = centralized, least-privilege access**

The company **already uses IAM Identity Center**, so the best solution is to use it rather than introduce another authentication system.

Imagine three teams:

```text
IAM Identity Center
        │
        ├── Data Science Group
        │       └── Permission Set → required Aurora/EFS access
        │
        ├── Engineering Group
        │       └── Permission Set → required Aurora/EFS access
        │
        └── Compliance Group
                └── Permission Set → required Aurora/EFS access
```

### ✅ Correct answer

**Enable IAM Identity Center and create permission sets for granular Aurora and EFS access. Assign teams to groups linked to the appropriate permission sets.**

This gives you:

* **Centralized access management**
* **Least privilege**
* **Role/team-based permissions**
* **Less administrative work**
* No need to create separate accounts just for each team

### 🧠 What is a Permission Set?

Think of a **permission set as a predefined access package**.

For example:

```text
Engineering Permission Set
        ↓
Aurora: required access
EFS: required access

Compliance Permission Set
        ↓
Aurora: read-only
EFS: read-only
```

Users get access based on the group they're placed in.

### Why not the others?

**❌ Separate AWS accounts for each team**

Possible, but unnecessary here. More accounts + cross-account roles = more administration.

**❌ Control Tower + SCPs**

Control Tower/SCPs are primarily for **organization-level governance and guardrails**. SCPs aren't designed to give individual users fine-grained resource permissions.

**❌ Cognito**

Cognito is mainly for **application users** (customers/users of your application). The organization already uses **IAM Identity Center for workforce access**, so introducing Cognito adds unnecessary complexity.

### 🧠 SAA exam shortcut

When you see:

> **Employees/teams + existing IAM Identity Center + centralized access + least privilege**

Think:

**IAM Identity Center → Groups → Permission Sets → AWS resources**

Also remember the distinction:

* **IAM Identity Center** → workforce/user access
* **Cognito** → application/customer user authentication
* **SCP** → organization/account guardrails
* **IAM policy/role** → permissions to AWS resources
