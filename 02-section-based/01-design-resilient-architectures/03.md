
3. Question

Category: CSAA – Design Resilient Architectures
A company has recently adopted a hybrid cloud architecture and is planning to migrate a database hosted on-premises to AWS. The database currently has over 50 TB of consumer data, handles highly transactional (Online Transaction Processing – OLTP) workloads, and is expected to grow. The Solutions Architect should ensure that the database is ACID-compliant and can handle complex application queries.

Which type of database service should the Architect use?

- Amazon DynamoDB
- Amazon Redshift
- Amazon RDS
- `Amazon Aurora`

This question is **very important for SAA** because it tests whether you can choose a database based on the **workload**, not just memorize what each service does.

There are really **4 clues** in the question.

---

# 1. First understand the requirement

The company has an on-premises database:

* **50+ TB of data**
* Data will **continue growing**
* **OLTP** workload
* **ACID-compliant**
* **Complex queries**
* Migrating to AWS

In simple words:

> They need a **large, relational, transactional database** that can handle complex SQL queries and keep growing.

So we're looking for a **relational database**, not NoSQL and not an analytics warehouse.

---

# 2. What does OLTP mean?

This is important.

**OLTP = Online Transaction Processing**

Think about applications such as:

```text
Banking
Food delivery
E-commerce
Airline booking
Payment systems
```

They constantly perform transactions:

```text
Customer places order
       ↓
INSERT order

Payment completed
       ↓
UPDATE payment

Stock reduced
       ↓
UPDATE inventory
```

These require reliable transactions.

That's where **ACID** becomes important.

---

# 3. What does ACID mean?

You don't need to memorize the detailed definitions yet. For the exam, remember:

> **ACID = reliable database transactions**

For example, imagine ordering food.

You don't want:

```text
Money deducted ✅
Order NOT created ❌
```

The database needs to make sure the transaction behaves correctly.

Relational databases such as **Aurora** and **RDS** are designed for these workloads.

---

# 4. Why is 50+ TB important?

This is the biggest clue separating **Aurora from RDS** in this question.

Both Aurora and RDS are relational.

Both can support:

* SQL
* ACID
* OLTP
* complex queries

So why Aurora?

Because the question specifically says:

> **50+ TB and expected to grow**

Aurora's storage layer automatically grows as the database needs more storage, and Aurora is designed for very large database workloads.

Think:

```text
Database
   ↓
50 TB
   ↓
60 TB
   ↓
70 TB
   ↓
...
```

Aurora's distributed storage architecture is designed to scale with the database.

### Therefore:

**Large + relational + OLTP + complex queries + growing → Aurora**

---

# Let's eliminate the options

## ❌ Amazon DynamoDB

DynamoDB is:

> **NoSQL / key-value / document database**

Think:

```text
DynamoDB
   ↓
NoSQL
   ↓
Massive scale
   ↓
Very fast key-based access
```

It isn't the natural choice when the requirement emphasizes:

* complex relational queries
* traditional SQL
* OLTP relational database

So:

**DynamoDB = NoSQL → ❌**

---

# ❌ Amazon Redshift

This is a classic SAA trap.

Redshift is primarily:

> **Data warehouse / OLAP**

Think:

```text
Millions of historical records
          ↓
      Redshift
          ↓
     Analytics
          ↓
"How much did we sell?"
"Which region performed best?"
```

That's **OLAP**.

The question says:

> **OLTP**

So:

```text
OLTP → Aurora/RDS
OLAP → Redshift
```

### Therefore:

**Redshift = Analytics/OLAP → ❌**

---

# ❌ Amazon RDS

This is the tricky option.

RDS **can absolutely** handle:

* relational databases
* SQL
* ACID
* OLTP
* complex queries

So don't memorize:

> "RDS can't do this."

That's wrong.

The question is really asking:

> **Which is better for this very large and growing database?**

Aurora is designed with a distributed storage architecture that automatically grows and provides high performance and resilience.

So in this specific scenario:

**RDS → possible, but Aurora is better → ❌**

---

# ✅ Amazon Aurora

Aurora gives you:

```text
Relational
    +
SQL
    +
ACID
    +
OLTP
    +
Complex queries
    +
Large-scale storage
    +
Automatic storage growth
```

Therefore:

### ✅ Amazon Aurora

---

# The SAA decision tree 🧠

When you see a database question, don't immediately think of service names.

Ask these questions:

### Step 1 — SQL or NoSQL?

```text
SQL / relational
       ↓
   RDS / Aurora
```

```text
NoSQL
       ↓
   DynamoDB
```

### Step 2 — OLTP or OLAP?

```text
OLTP
 ↓
Aurora / RDS
```

```text
OLAP / analytics
 ↓
Redshift
```

### Step 3 — Is the database extremely large and expected to grow?

If the question emphasizes **large-scale relational workload + growth**, Aurora becomes particularly attractive.

---

# ⭐ Exam memory table

| Requirement                                   | Think            |
| --------------------------------------------- | ---------------- |
| NoSQL                                         | **DynamoDB**     |
| SQL + traditional relational DB               | **RDS**          |
| SQL + high-performance scalable relational DB | **Aurora**       |
| Data warehouse / analytics / OLAP             | **Redshift**     |
| Transactions / OLTP                           | **Aurora / RDS** |
| Complex SQL queries                           | **Aurora / RDS** |
| Huge growing relational workload              | **Aurora**       |

### The key pattern for this question:

> **50+ TB + growing + OLTP + ACID + complex queries**

### → **Amazon Aurora** ✅
