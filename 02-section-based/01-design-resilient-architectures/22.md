22. Question

Category: CSAA – Design Resilient Architectures

A data analytics company, which uses machine learning to collect and analyze consumer data, is using Redshift cluster as their data warehouse. You are instructed to implement a disaster recovery plan for their systems to ensure business continuity even in the event of an AWS region outage.

Which of the following is the best approach to meet this requirement?

- `Enable Cross-Region Snapshots Copy in your Amazon Redshift Cluster.`
- Do nothing because Amazon Redshift is a highly available, fully-managed data warehouse which can withstand an outage of an entire AWS region.
- Create a scheduled job that will automatically take the snapshot of your Redshift Cluster and store it to an S3 bucket. Restore the snapshot in case of an AWS region outage.
- Use Automated snapshots of your Redshift Cluster.


## Question 22 — Redshift Disaster Recovery

This one is testing a very important concept:

> **What happens if an entire AWS Region goes down?**

The key word is **Region**.

### First, understand the problem

Your Redshift cluster is in:

```text
us-east-1
   ↓
Redshift
   ↓
Your data
```

If `us-east-1` has a major outage, your Redshift cluster **and its local snapshots** may not be available.

So you need a copy **outside that Region**.

---

## ✅ Correct answer

> **Enable Cross-Region Snapshot Copy in your Amazon Redshift cluster.**

Think:

```text
Region A                         Region B
─────────                        ─────────
Redshift                         Redshift
   │
   │ snapshots
   └──────────────────────────→  Snapshot
                                  │
                                  ↓
                              DR location
```

Redshift automatically copies new snapshots to the **destination Region**.

If Region A goes down:

```text
Region A ❌

      ↓

Region B
      ↓
Restore Redshift
      ↓
Business continues
```

That's disaster recovery.

---

## Why not normal Automated Snapshots?

This is the most important distinction.

### Automated snapshot

```text
Redshift
   ↓
Automated snapshot
   ↓
Same Region
```

If the **entire Region** fails, you potentially lose access to both the cluster and its snapshots.

So:

> **Automated snapshot ≠ Region-level disaster recovery**

### Cross-Region Snapshot Copy

```text
Region A
Redshift
   ↓
Snapshot
   ↓
Cross-Region copy
   ↓
Region B
```

Now you have protection against a **Regional outage**.

---

# Why not manually copy to S3?

You could create some custom automation:

```text
Redshift
 ↓
Snapshot
 ↓
S3
 ↓
Another Region
```

But the question asks for the **best approach**.

AWS already provides a native feature:

> **Cross-Region Snapshot Copy**

So don't build your own solution when AWS provides a managed feature that directly solves the requirement.

---

# 🧠 The SAA pattern to memorize

Whenever you see:

### "Protect against AZ failure"

Think:

> **Multi-AZ**

### "Protect against Region failure"

Think:

> **Cross-Region replication / backup**

For Redshift specifically:

> **Regional disaster recovery → Cross-Region Snapshot Copy**

---

### One more important distinction

Don't confuse these:

**Automated snapshots**

→ Regular backup/recovery

**Cross-Region Snapshot Copy**

→ Disaster recovery from **Regional failure**

So the question says:

> **"business continuity even in the event of an AWS region outage"**

🚨 Your brain should immediately say:

**Cross-Region Snapshot Copy → another Region → restore there.**
