24. Question

Category: CSAA – Design Resilient Architectures

A real-time data analytics application is using AWS Lambda to process data and store results in JSON format to an S3 bucket. To speed up the existing workflow, you have to use a service where you can run sophisticated Big Data analytics on your data without moving them into a separate analytics system.

Which of the following group of services can you use to meet this requirement?

- Amazon Glue, Amazon Redshift, Amazon S3
- Amazon X-Ray, Amazon Neptune, DynamoDB
- `Amazon Athena, Amazon Redshift Spectrum, AWS Glue`
- Amazon Neptune, DynamoDB DAX, Amazon Redshift Spectrum


## Question 24 — Big Data analytics directly on S3

This question is testing one key requirement:

> **"I have data in S3. I want to analyze it without moving it into another analytics system."**

Once you see that, the answer becomes much easier.

---

## First understand the architecture

Your Lambda is doing:

```text
Data
 ↓
AWS Lambda
 ↓
JSON files
 ↓
Amazon S3
```

Now the company wants to analyze those JSON files.

They **don't want to copy the data into another database/data warehouse first.**

So we need services that can work **with data sitting in S3**.

---

# ✅ Correct answer

> **Amazon Athena + Amazon Redshift Spectrum + AWS Glue**

Let's understand each one.

### 1. Amazon Athena → Query S3 directly

Athena is the easiest one to remember.

Think:

> **Athena = SQL directly on S3**

For example, your S3 contains:

```text
s3://my-bucket/data/
    customers.json
    transactions.json
    sales.json
```

You can use Athena:

```sql
SELECT *
FROM transactions
WHERE amount > 1000;
```

You don't need to move the data into a database first.

```text
S3
 │
 │ SQL
 ↓
Athena
 │
 ↓
Results
```

### 🧠 Memorize:

> **Athena = Serverless SQL on S3**

---

# 2. Redshift Spectrum → Redshift queries S3

Redshift is a data warehouse.

Normally:

```text
S3
 ↓
Load data
 ↓
Redshift
 ↓
Analytics
```

But **Redshift Spectrum** allows Redshift to query data that remains in S3.

```text
              ┌──────────────┐
              │   Redshift   │
              └──────┬───────┘
                     │
                Spectrum
                     │
                     ↓
              ┌──────────────┐
              │      S3      │
              └──────────────┘
```

So:

> **Redshift Spectrum = Redshift queries data directly in S3**

This is particularly useful when you already use Redshift but have large amounts of data stored in S3.

---

# 3. AWS Glue → Prepare/catalog the data

Glue is slightly different.

Glue isn't primarily your query engine.

Think:

> **Glue = Discover + catalog + ETL/transform data**

For example:

```text
S3
 ↓
Glue
 ↓
Discover / catalog / transform
 ↓
Athena / Redshift Spectrum
 ↓
Analytics
```

Glue can create a **Data Catalog** containing metadata about your S3 data.

For example:

```text
transactions.json

Columns:
customer_id
transaction_id
amount
date
```

Athena can then use that metadata to query the data.

---

# 🧠 The easiest way to memorize these three

Remember:

### **Athena = ASK**

You **ask questions** about S3 using SQL.

### **Glue = PREPARE**

You **prepare/catalog/transform** data.

### **Spectrum = REDSHIFT + S3**

Redshift can analyze data that remains in S3.

So:

```text
              S3
               │
       ┌───────┼────────┐
       ↓       ↓        ↓
    Athena   Glue   Spectrum
       │       │        │
     Query   Prepare  Redshift
```

---

# Why option 1 is wrong

> **Amazon Glue + Amazon Redshift + Amazon S3**

It looks tempting because all three are related to data analytics.

But there's a critical problem:

**Regular Redshift expects data to be loaded into Redshift for its normal analytics workload.**

The question specifically says:

> **without moving them into a separate analytics system**

That's why **Redshift Spectrum** is needed instead.

---

# Why the other options are obviously wrong

### ❌ X-Ray + Neptune + DynamoDB

These aren't the right tools for analytics on S3.

* **X-Ray** → application tracing
* **Neptune** → graph database
* **DynamoDB** → NoSQL database

---

### ❌ Neptune + DynamoDB DAX + Redshift Spectrum

Only Spectrum is relevant.

* Neptune → graph database
* DAX → DynamoDB caching
* Spectrum → S3 analytics

So the combination doesn't make sense.

---

# 🎯 SAA exam shortcut

When you see:

> **"Analyze/query data directly in S3 without loading it into a database"**

Think:

### **Athena** → SQL directly on S3

### **Redshift Spectrum** → Redshift queries S3

### **Glue** → catalog/ETL/prepare S3 data

And if the question says:

> **"serverless SQL queries on S3"**

🚨 **Athena**

If it says:

> **"Redshift needs to query data stored in S3"**

🚨 **Redshift Spectrum**

If it says:

> **"discover, catalog, transform, ETL"**

🚨 **AWS Glue**

That distinction is much more important than memorizing the explanation word-for-word.
