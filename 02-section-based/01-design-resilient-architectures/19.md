19. Question

Category: CSAA – Design Resilient Architectures


A company plans to deploy a Docker-based batch application in AWS. The application will be used to process both mission-critical data and non-essential batch jobs.

Which of the following is the most cost-effective option to use in implementing this architecture?

- Use Amazon ECS as the container management service, then set up Reserved Amazon EC2 Instances for processing both mission-critical and non-essential batch jobs.
- `Use Amazon ECS as the container management service, then set up a combination of Reserved and Spot Amazon EC2 Instances for processing mission-critical and non-essential batch jobs, respectively.`
- Use Amazon ECS as the container management service, then set up On-Demand Amazon EC2 Instances for processing both mission-critical and non-essential batch jobs.
- Use Amazon ECS as the container management service, then set up Spot Amazon EC2 Instances for processing both mission-critical and non-essential batch jobs.


Absolutely. **Question 19 is really testing EC2 purchasing options**, so let's understand those first. Once these are clear, this question becomes almost automatic.

## EC2 pricing / purchasing options

For SAA, focus on these four:

| Option                 | Simple meaning                                                      | Best for                             |
| ---------------------- | ------------------------------------------------------------------- | ------------------------------------ |
| **On-Demand**          | Pay normally, no commitment                                         | Unpredictable / short-term workloads |
| **Reserved Instances** | Commit to usage for 1 or 3 years → cheaper                          | Predictable, steady workloads        |
| **Spot Instances**     | Use spare AWS capacity at a huge discount, but AWS can interrupt it | Flexible, interruptible workloads    |
| **Savings Plans**      | Commit to $/hour usage for 1 or 3 years → discount                  | Predictable compute usage            |

### 1. On-Demand — "I need it, I'll pay normal price"

You launch an EC2 instance and pay the normal rate.

**No long-term commitment.**

Example:

```text
Need server today
     ↓
On-Demand
     ↓
Pay normal price
     ↓
Can stop/terminate when finished
```

Good when:

* workload is unpredictable
* you don't know how long you'll need it
* you don't want a commitment

**Memory:**

> **On-Demand = Flexibility**

---

### 2. Reserved Instances — "I know I'll need it"

You commit to a certain usage for a longer period, commonly **1 or 3 years**, in exchange for a discount.

Example:

Your company knows:

> "We will run these 10 EC2 instances continuously for the next 3 years."

Reserved Instances make sense.

```text
Predictable workload
       ↓
Long-term commitment
       ↓
Reserved Instance
       ↓
Lower cost
```

**Memory:**

> **Reserved = Predictable**

Important: A Reserved Instance isn't a physical server that AWS puts aside for you. It's primarily a **pricing commitment/discount** for matching EC2 usage.

---

### 3. Spot Instances — "Give me cheap spare capacity"

AWS has unused EC2 capacity. You can use it at a **very large discount**.

But there's a catch:

> AWS can interrupt your Spot Instance when it needs the capacity back.

Therefore:

```text
Non-critical / interruptible workload
              ↓
         Spot Instance
              ↓
          Very cheap 💰
```

Good examples:

* Batch processing
* Big data processing
* Image processing
* Scientific workloads
* CI jobs
* Fault-tolerant workloads

Bad example:

> "This server must NEVER be interrupted."

Don't use Spot alone for that.

**Memory:**

> **Spot = Cheap but interruptible**

---

### 4. Savings Plans — "I commit to spending"

Savings Plans are another way to get discounted compute pricing by committing to a certain amount of **compute spend per hour** for 1 or 3 years.

For SAA, remember:

> **Savings Plan = commitment + discount + more flexibility than traditional Reserved Instances**

You don't need to go very deep into them yet.

---

# Now Question 19 becomes easy

The application has **two types of workloads**:

### Mission-critical

Cannot tolerate interruption.

```text
Mission-critical
      ↓
Need reliable capacity
      ↓
Reserved
```

### Non-essential batch jobs

Can tolerate interruption.

```text
Non-essential batch
       ↓
Can tolerate interruption
       ↓
Spot
       ↓
Huge cost savings
```

Therefore:

> **ECS + Reserved EC2 for mission-critical workloads + Spot EC2 for non-essential workloads**

### ✅ Correct answer

**Use Amazon ECS with a combination of Reserved and Spot EC2 Instances for mission-critical and non-essential batch jobs, respectively.**

### The fastest exam decision rule

When you see:

**"Unpredictable"** → 🟢 **On-Demand**

**"Steady/predictable for 1–3 years"** → 🟢 **Reserved / Savings Plans**

**"Can be interrupted / non-critical / batch"** → 🟢 **Spot**

**"Mission-critical + non-essential workloads together"** → 🟢 **Mix them**

That's the important concept from Question 19.
