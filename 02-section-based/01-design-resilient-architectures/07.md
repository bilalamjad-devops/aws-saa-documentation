7. Question


Category: CSAA – Design Resilient Architectures

A tech company currently has an on-premises infrastructure. They are currently running low on storage and want to have the ability to extend their storage using the AWS cloud.

Which AWS service can help them achieve this requirement?

- Amazon EC2
- `AWS Storage Gateway`
- Amazon Elastic Block Storage
- Amazon SQS

This is a **very common hybrid-cloud question**. The important word is **on-premises**.

# Question in very simple words

The company already has its own data center:

```text
On-premises
┌─────────────────┐
│ Servers         │
│ Storage         │
└─────────────────┘
        │
        │ running out of storage
        ↓
     AWS Cloud
```

They want to **extend their existing on-premises storage into AWS**.

In other words:

> "We don't have enough storage in our data center. Can AWS provide additional storage that our on-premises environment can use?"

---

# ✅ Correct answer: AWS Storage Gateway

**AWS Storage Gateway** is specifically designed to connect:

```text
On-premises infrastructure
          ↕
   Storage Gateway
          ↕
      AWS Storage
```

It provides a bridge between your **on-premises environment** and AWS storage services.

So the key phrase is:

> **On-premises storage extension → Storage Gateway**

---

# 🧠 Think of Storage Gateway as a bridge

Imagine your company has:

```text
🏢 Company Data Center
        |
        | "We're running out of storage!"
        |
        ↓
┌──────────────────┐
│ Storage Gateway  │
└────────┬─────────┘
         |
         ↓
☁️ AWS Cloud Storage
```

The on-premises environment can interact with storage through the gateway while AWS provides scalable cloud storage behind it.

That's why AWS Storage Gateway is the natural answer.

---

# What is Storage Gateway actually for?

There are different gateway types, but for SAA you should understand the big picture:

### 1. File Gateway

Your applications can access files using standard file protocols such as **NFS/SMB**, while data is stored in Amazon S3.

Think:

```text
On-prem app
     ↓
File shares
     ↓
Storage Gateway
     ↓
S3
```

### 2. Volume Gateway

Provides **block storage volumes** to on-premises applications while using AWS storage in the backend.

Think:

```text
On-premises application
        ↓
Virtual disk
        ↓
Storage Gateway
        ↓
AWS
```

### 3. Tape Gateway

Used when organizations want to replace physical tape infrastructure with cloud-based virtual tapes.

Think:

```text
Traditional backup tapes
        ↓
Tape Gateway
        ↓
AWS
```

You don't need to memorize every implementation detail yet. For this question, remember the purpose.

---

# Why the other answers are wrong

### ❌ Amazon EC2

EC2 is **compute**.

Think:

> "I need a virtual server."

Not:

> "I need to extend my on-premises storage."

---

### ❌ Amazon EBS

EBS is **block storage for EC2**.

Think:

```text
EC2
 ↓
EBS
```

It's not primarily designed to extend an on-premises storage environment into AWS.

---

### ❌ Amazon SQS

SQS is a **message queue**.

Think:

```text
Application A
      ↓
     SQS
      ↓
Application B
```

It has nothing to do with extending storage capacity.

---

# 🎯 Exam shortcut

Whenever you see:

> **On-premises + extend storage + AWS**

Immediately think:

### ✅ AWS Storage Gateway

Don't confuse it with EBS or S3.

A useful mental map:

| Requirement                           | AWS service         |
| ------------------------------------- | ------------------- |
| Virtual server                        | **EC2**             |
| EC2 block storage                     | **EBS**             |
| Object storage                        | **S3**              |
| On-premises ↔ AWS storage integration | **Storage Gateway** |
| Message queue                         | **SQS**             |

### One-line memory trick

> **Storage Gateway = bridge between on-premises storage/users and AWS cloud storage.**
