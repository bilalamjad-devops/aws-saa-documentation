1. Question

Category: CSAA – Design Resilient Architectures

A financial analytics application that collects, processes, and analyzes stock data in real-time uses Amazon Kinesis Data Streams. The producers continually push data to Kinesis Data Streams while the consumers process the data in real time.

In Kinesis, where can the consumers store the results? (Select TWO.)

- AWS Glue
- Amazon EMR
- `Amazon S3`
- `Amazon Redshift`
- Amazon Athena

Notice that AWS is **not** asking where data comes from.

It is asking:

> **Where do consumers STORE the processed data?**

# 6. Analyze Every Option

---

## A) AWS Glue

❌ **Wrong**

### What is AWS Glue?

Glue is an **ETL service**.

ETL means:

* Extract
* Transform
* Load

It helps move and transform data between systems.

Example:

```
S3
 │
 ▼
Glue cleans data
 │
 ▼
Redshift
```

Glue prepares data.

It does **not** store data.

---

## B) Amazon EMR

❌ **Wrong**

### What is EMR?

EMR stands for:

**Elastic MapReduce**

It runs:

* Hadoop
* Spark
* Hive
* Presto

It is used for **big data processing**.

Example:

```
Huge Dataset
      │
      ▼
EMR Cluster
      │
      ▼
Processed Data
```

EMR is a compute service.

It is **not** where you permanently store results.

---

## C) Amazon S3

✅ **Correct**

### Why?

S3 is AWS Object Storage.

Consumers can process data and save files like:

* JSON
* CSV
* Images
* Logs
* Reports

Example:

```
Consumer
     │
     ▼
S3 Bucket

stock-report.csv
analysis.json
logs.txt
```

S3 is one of the most common destinations for Kinesis output.

---

## D) Amazon Redshift

✅ **Correct**

### What is Redshift?

Redshift is AWS's data warehouse.

Companies use it for analytics.

Example:

```
Consumer
      │
      ▼
Redshift

Millions of records

SQL Analytics
Dashboards
BI Reports
```

Perfect place to store processed stock data for reporting.

---

## E) Amazon Athena

❌ **Wrong**

Many students confuse Athena.

Athena is **not storage**.

Athena only runs SQL queries.

Example:

```
S3
 │
 ▼
Athena

SELECT *
FROM stocks;
```

Athena reads data from S3.

It doesn't save consumer output.

---

# 7. Why These Are the Best Answers

The requirement is:

> **Store processed results**

S3 stores objects.

Redshift stores structured analytical data.

Exactly what consumers need after processing.

# 8. Real-World Example

Imagine you're building a stock analytics platform.

Every second:

```

MSFT 430.11

AMZN 198.32
```

These prices enter Kinesis.

A consumer calculates:

* Average price
* Highest price
* Lowest price

Now where should these calculations go?

### Option 1

Save reports to S3.

```

```

### Option 2

Store everything in Redshift.

Then analysts run SQL:

```sql

FROM stock_prices;
```

Perfect use case.

# 9. Interview Tip

**Interviewer:**

"Why would you store Kinesis consumer output in Redshift instead of Athena?"

Good answer:

> "Redshift is the storage layer (data warehouse). Athena is only a query engine that queries data already stored in S3. Athena does not store processed data."

Absolutely. Let's forget the exam wording for a moment. **The confusing part is Kinesis itself and what "consumer stores the results" means.**

## First, understand the story

Imagine a stock application receiving prices continuously:

```text
Stock Market
     ↓
  Producer
     ↓
Kinesis Data Streams
     ↓
  Consumer
     ↓
Where do we SAVE the processed data?
```

### What is Kinesis?

Think of **Kinesis Data Streams as a pipe/conveyor belt for continuously arriving data**.

For example:

```text
10:01 → AAPL $200
10:02 → AAPL $201
10:03 → AAPL $199
10:04 → AAPL $202
```

The producers continuously put this data into Kinesis.

Kinesis's job is basically:

> **"Hold/stream this continuously arriving data so consumers can read it."**

Kinesis itself is **not the final database where your application necessarily stores its processed results.**

---

# Now what is a consumer?

A **consumer** reads data from Kinesis.

For example:

```text
Producer
   ↓
Kinesis
   ↓
Consumer
```

The consumer might be an application running on EC2.

It reads:

```text
AAPL $200
AAPL $201
AAPL $199
```

Then it might calculate:

```text
Average = $200
Highest = $201
Lowest  = $199
```

Now the question asks:

> **Where can the consumer STORE those results?**

This is the key.

---

# Option 1: Amazon S3 ✅

S3 is **storage**.

So the consumer can do:

```text
Kinesis
   ↓
Consumer
   ↓
S3
```

For example, the consumer could save:

```text
stock-results/
    daily-report.csv
    processed-data.json
```

Therefore:

**S3 = YES ✅**

---

# Option 2: Amazon Redshift ✅

Redshift is a **data warehouse**.

It is also a place where you store data, particularly data you want to analyze using SQL.

So:

```text
Kinesis
   ↓
Consumer
   ↓
Redshift
```

For example:

```text
Stock prices
     ↓
Redshift
     ↓
SQL queries
     ↓
Reports / Analytics
```

Therefore:

**Redshift = YES ✅**

---

# Now let's understand why the others are wrong

This is where the question becomes easy.

## AWS Glue ❌

Glue is mainly:

> **ETL / data preparation**

Think:

```text
Data
 ↓
Glue
 ↓
Clean / Transform
 ↓
Storage
```

Glue helps **prepare data**.

It isn't the storage destination we're looking for.

---

## Amazon EMR ❌

EMR is mainly:

> **Big-data processing**

Think:

```text
Huge dataset
     ↓
    EMR
     ↓
Processing
```

EMR can process data, including data coming from Kinesis, but **EMR itself isn't the answer when AWS asks for a storage destination.**

---

## Amazon Athena ❌

This one is VERY important.

Athena is:

> **A query service**

Imagine you already have data in S3:

```text
S3
 │
 │ data
 ↓
Athena
 │
 │ SQL query
 ↓
Results
```

Athena lets you ask:

```sql
SELECT *
FROM stock_data;
```

Athena **reads/query data**. It isn't the storage system.

So:

**Athena = Query ❌**
