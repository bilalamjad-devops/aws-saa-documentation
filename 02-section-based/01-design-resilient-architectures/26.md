26. Question

Category: CSAA – Design Resilient Architectures

A Solutions Architect for a global news company is configuring a fleet of EC2 instances in a subnet that currently is in a VPC with an Internet gateway attached. All of these EC2 instances can be accessed from the Internet. The architect launches another subnet and deploys an EC2 instance in it, however, the architect is not able to access the EC2 instance from the Internet.

What could be the possible reasons for this issue? (Select TWO.)

- The Amazon EC2 instance is not a member of the same Auto Scaling group.
- The Amazon EC2 instance does not have an attached Elastic Fabric Adapter (EFA).
- `The route table is not configured properly to send traffic from the EC2 instance to the Internet through the Internet gateway.`
- `The Amazon EC2 instance does not have a public IP address associated with it.`
- The route table is not configured properly to send traffic from the EC2 instance to the Internet through the customer gateway (CGW).


Yes — this is a **very important EC2/VPC question**, and the easiest way to remember it is to think about the **path to the Internet**.

### Correct answers: TWO

1. **EC2 does not have a public IP address**
2. **Route table does not have a route to the Internet Gateway (IGW)**

### Think of it as 2 doors 🚪

For an EC2 instance to be directly reachable from the Internet, you generally need:

**Internet → IGW → Route Table → EC2**

And the EC2 needs a **public IPv4 address/EIP**.

So check:

| Requirement                 | Why?                                          |
| --------------------------- | --------------------------------------------- |
| **Public IP / EIP**         | Gives the instance a public Internet address  |
| **Route `0.0.0.0/0 → IGW`** | Provides the path between subnet and Internet |

If either is missing → **Internet access won't work.**

### Why the other options are wrong

* **Same Auto Scaling Group?** ❌
  ASG has nothing to do with whether an EC2 can reach the Internet.

* **EFA?** ❌
  EFA is for **HPC / high-performance networking**, not normal Internet connectivity.

* **Customer Gateway (CGW)?** ❌
  CGW is associated with **VPN connectivity to on-premises**, not normal public Internet access.

### 🧠 Memorize this

> **Public EC2 = Public IP + Route to IGW**

And remember the difference:

**IGW → Internet** 🌐
**CGW → Customer/on-premises** 🏢

So whenever an exam asks **"EC2 cannot access/be accessed from Internet"**, immediately check:

**1. Public IP?**
**2. Route table → IGW?**
**3. Security Group/NACL?** (if those are among the options)

That mental checklist will solve many SAA questions.
