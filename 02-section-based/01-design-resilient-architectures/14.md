14. Question

Category: CSAA – Design Resilient Architectures

A tech company is currently using Auto Scaling for their web application. A new AMI now needs to be used for launching a fleet of EC2 instances. Which of the following changes needs to be done?

- Create a new target group.
- `Create a new launch template.`
- Do nothing. You can start directly launching EC2 instances in the Auto Scaling group with the same launch template.
- Create a new target group and launch template.

Yes — this one is straightforward. Since you already know the answer, I'll keep it short.

### Question 14 — Core idea

The **AMI is specified inside the Launch Template**.

Think:

```text
Launch Template
├── AMI ID
├── Instance type
├── Security groups
├── Key pair
└── Storage settings
```

Your Auto Scaling Group uses that template to launch EC2 instances.

So if you want to use a **new AMI**:

**Old AMI → new AMI**

You need a **new Launch Template** (or a new version of the launch template in real-world AWS usage), then update the ASG to use it.

### Why not Target Group?

A **Target Group** belongs to the load-balancing layer:

```text
ALB → Target Group → EC2
```

It has nothing to do with which AMI is used to launch the EC2 instances.

### 🧠 SAA memory trick

> **AMI change → Launch Template**

> **Traffic distribution → Target Group / Load Balancer**

That's all you need from this question.
