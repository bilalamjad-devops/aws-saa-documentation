6. Question

Category: CSAA – Design High-Performing Architectures

A leading e-commerce company is in need of a storage solution that can be simultaneously accessed by 1000 Linux servers in multiple availability zones. The servers are hosted in EC2 instances that use a hierarchical directory structure via the NFSv4 protocol. The service should be able to handle the rapidly changing data at scale while still maintaining high performance. It should also be highly durable and highly available whenever the servers will pull data from it, with little need for management.

As the Solutions Architect, which of the following services is the most cost-effective choice that you should use to meet the above requirement?

- Amazon S3
- `Amazon EFS`
- Amazon FSx for Windows File Server
- Amazon EBS

This is another **storage selection** question. The biggest clue is the combination of **Linux + NFSv4 + 1,000 servers + shared filesystem**.

### Q6 — Answer: Amazon EFS ✅

Think:

```text
1000 Linux EC2 instances
        │
        │ NFSv4
        ↓
     Amazon EFS
```

EFS is a **shared file system** that many EC2 instances can access simultaneously, including instances across Availability Zones.

### 🧠 The important keywords

> **Linux** → EFS
> **NFS** → EFS
> **Shared by many EC2 instances** → EFS
> **Hierarchical directory structure** → File system → EFS
> **Rapidly changing files** → EFS
> **Highly available + managed** → EFS

---

### Don't confuse EFS, EBS and S3

| Service         | Mental picture               | Best clue                             |
| --------------- | ---------------------------- | ------------------------------------- |
| **EBS**         | 💾 Disk attached to EC2      | **Single EC2 / block storage**        |
| **EFS**         | 📁 Shared network filesystem | **Linux + NFS + many EC2s**           |
| **S3**          | 🪣 Object bucket             | **Objects/files via API, huge scale** |
| **FSx Windows** | 🪟 Windows file server       | **Windows + SMB + AD**                |

### Very useful exam rule

If the question says:

> **"1000 Linux servers need to access the same files"**

→ **EFS**

If it says:

> **"Windows servers + SMB + Active Directory"**

→ **FSx for Windows**

If it says:

> **"One EC2 needs very low-latency block storage"**

→ **EBS**

If it says:

> **"Store objects/files cheaply and durably at massive scale"**

→ **S3**

---

### One correction to the explanation you pasted

Don't memorize:

> ❌ "S3 is not suitable because data is rapidly changing."

That's **too broad**.

S3 absolutely can handle frequently changing objects. The **stronger reason EFS wins here** is that the application requires a **shared hierarchical filesystem through NFSv4**, which is exactly what EFS provides.

So your real mental model should be:

> **NFS + Linux + shared filesystem → EFS**

That's the part worth memorizing.
