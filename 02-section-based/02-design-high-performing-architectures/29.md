29. Question

Category: CSAA – Design High-Performing Architectures

A company has developed public APIs hosted in Amazon EC2 instances behind an Elastic Load Balancer. The APIs will be used by various clients from respective on-premises data centers. A Solutions Architect received a report that the web service clients can only access trusted IP addresses whitelisted on the web service’s firewalls.

What should be done to accomplish the above requirement?

- Create an Amazon CloudFront distribution whose origin points to the private IP addresses of your web servers.
- `Associate an Elastic IP address to a Network Load Balancer.`
- Configure General Purpose SSD volumes on the load balancer nodes to provide static IP addresses.
- Associate an Elastic IP address to an Application Load Balancer.

Yes. This one is a classic **ALB vs NLB** question.

### The key requirement

The clients' firewalls only allow connections from **trusted/whitelisted IP addresses**.

So we need a load balancer with **static IP addresses** that the clients can whitelist.

| Load Balancer | Static IP?           | Elastic IP?         | Main use                                  |
| ------------- | -------------------- | ------------------- | ----------------------------------------- |
| **ALB**       | ❌ No fixed public IP | ❌ Cannot attach EIP | HTTP/HTTPS, path/host routing             |
| **NLB**       | ✅ Yes                | ✅ Can associate EIP | TCP/UDP, static IP, very high performance |
| **GWLB**      | Depends on design    | Different purpose   | Network/security appliances               |

### Why NLB?

A **Network Load Balancer** operates at **Layer 4** and can have a static IP address per Availability Zone. You can also associate Elastic IP addresses with it.

So the architecture can be:

```text
On-Premises Clients
       |
       | HTTPS/TCP
       ↓
Trusted / Whitelisted IP
       |
       ↓
    NLB
       |
   ┌───┴────┐
   ↓        ↓
 EC2       EC2
```

The firewall team can say:

> "Allow traffic only from these NLB IP addresses."

If the requirement involves **BYOIP** (Bring Your Own IP), you can use your organization's existing trusted IP addresses with AWS where supported.

### Why not ALB?

This is important for your SAA exam:

**ALB = application-level routing**

For example:

```text
/api/android → Android target group
/api/ios     → iOS target group
```

That's why your **Question 10** used ALB.

But ALB **cannot have an Elastic IP directly attached to it**.

**NLB = network-level + static IP**

So remember:

> **ALB → HTTP/HTTPS intelligence → Host/path/header routing**
>
> **NLB → TCP/UDP + static IP/EIP + extreme performance**

---

### 🔥 One-line exam trick

When you see:

**"Clients have firewalls that whitelist specific IP addresses"**

Think:

**NLB + static IP/EIP**

When you see:

**"/api/*", hostname, HTTP header, HTTP method**

Think:

**ALB**

When you see:

**"route users based on country"**

Think:

**Route 53 Geolocation**

When you see:

**"send 20% here and 80% there"**

Think:

**Route 53 Weighted**

You're actually seeing a pattern across Questions **10, 24, 28, and 29**: AWS often gives you a scenario where the wording tells you which networking component to choose.
