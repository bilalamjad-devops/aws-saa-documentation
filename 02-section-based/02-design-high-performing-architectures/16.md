16. Question

Category: CSAA – Design High-Performing Architectures

A company plans to launch an Amazon EC2 instance in a private subnet for its internal corporate web portal. For security purposes, the EC2 instance must send data to Amazon DynamoDB and Amazon S3 via private endpoints that don’t pass through the public Internet, which does not involve NAT Instances.

Which of the following can meet the above requirements?

- Use AWS VPN CloudHub to route all access to S3 and DynamoDB via private endpoints.
- Use AWS Direct Connect to route all access to S3 and DynamoDB via private endpoints.
- `Use a DynamoDB VPC endpoint and an S3 VPC endpoint to route all access to these services via private endpoints.`
- Enable DynamoDB Encryption at Rest with the default AWS-managed key and S3 Server-Side Encryption with the default AWS KMS key to route all traffic to DynamoDB and S3 via private endpoints.

Exactly. This question is testing **VPC Endpoints**. The easiest way to understand it is to compare it with NAT Gateway.

### The situation

Your EC2 is in a **private subnet**:

```text
Private EC2
    │
    │ wants to access
    ▼
S3 / DynamoDB
```

You don't want traffic going through the public Internet.

The solution:

```text
Private EC2
    │
    ▼
VPC Endpoint
    │
    ├──→ S3
    │
    └──→ DynamoDB
```

No Internet Gateway.
No NAT Gateway.
No public IP required.

---

## 🧠 The important distinction

### Without VPC Endpoint

A private EC2 normally needs a NAT Gateway to reach AWS services such as S3:

```text
Private EC2
     ↓
 NAT Gateway
     ↓
Internet Gateway
     ↓
    S3
```

This works, but you're paying for NAT Gateway and routing traffic through it.

### With VPC Endpoint

```text
Private EC2
     ↓
VPC Endpoint
     ↓
S3 / DynamoDB
```

Traffic stays within the AWS network.

---

# S3 and DynamoDB are especially important

For SAA, remember:

### S3

You can use an **S3 VPC endpoint**.

Traditionally, this is a **Gateway Endpoint**.

```text
EC2 → S3 VPC Gateway Endpoint → S3
```

### DynamoDB

You can use a **DynamoDB VPC endpoint**.

Also traditionally a **Gateway Endpoint**.

```text
EC2 → DynamoDB Gateway Endpoint → DynamoDB
```

So when you see:

> Private subnet → S3/DynamoDB → no NAT/Internet

Think:

> **VPC Endpoint**

---

## Don't confuse endpoint with encryption

The question deliberately gives:

> S3 encryption + DynamoDB encryption

That's security **of the data**.

It doesn't determine **how the network traffic travels**.

Think of two separate concepts:

```text
Encryption
   ↓
"Can someone read my data?"

VPC Endpoint
   ↓
"How does my traffic reach the service?"
```

---

## 🔥 SAA shortcut

Memorize these patterns:

| Requirement                                  | Think                 |
| -------------------------------------------- | --------------------- |
| Private EC2 → Internet                       | NAT Gateway           |
| Private EC2 → S3 privately                   | S3 VPC Endpoint       |
| Private EC2 → DynamoDB privately             | DynamoDB VPC Endpoint |
| On-premises → AWS dedicated connection       | Direct Connect        |
| On-premises → AWS encrypted connection       | Site-to-Site VPN      |
| Multiple offices/sites connected through VPN | VPN CloudHub          |

### One sentence to remember:

> **VPC Endpoint = privately access supported AWS services without sending traffic through the public Internet.**

And this question is a good example of why you should study **architecture patterns**, not just individual services.
