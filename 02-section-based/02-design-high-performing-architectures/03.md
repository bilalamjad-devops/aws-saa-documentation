3. Question

Category: CSAA – Design High-Performing Architectures

A company has a highly available architecture consisting of an Elastic Load Balancer and multiple Amazon EC2 instances configured with Auto Scaling across three Availability Zones. The company needs to monitor EC2 instances based on a specific metric that is not readily available in Amazon CloudWatch.

Which of the following is a custom metric in CloudWatch that requires manual setup?


- CPU Utilization of an EC2 instance
- `Memory Utilization of an EC2 instance`
- Network packets out of an EC2 instance
- Disk Read activity of an EC2 instance

Yes — this is a **very important distinction for SAA**.

### Question 3 — remember it like this

For EC2, CloudWatch gives you several metrics **automatically**, such as:

* **CPU utilization** ✅
* **Network traffic/packets** ✅
* **Disk I/O activity** ✅

But CloudWatch does **not** automatically know what's happening **inside the operating system**.

So:

> **Memory utilization = Custom metric** ❗

Why? Because AWS can easily see how much network traffic or CPU the EC2 infrastructure is generating, but **RAM usage is inside the OS**. You need the **CloudWatch Agent** (or older monitoring scripts) to collect it.

### Easy exam rule 🧠

**EC2 default CloudWatch → outside/infrastructure metrics**

**CloudWatch Agent → inside/OS metrics**

| Metric                     | Default? |
| -------------------------- | -------- |
| CPU Utilization            | ✅        |
| Network traffic            | ✅        |
| Disk read/write I/O        | ✅        |
| **Memory utilization**     | ❌ Custom |
| **Disk space utilization** | ❌ Custom |
| **Swap utilization**       | ❌ Custom |

So if the exam asks:

> "Which EC2 metric requires additional configuration/custom metric?"

Think immediately:

**RAM / Memory → CloudWatch Agent → Custom metric.**

Also, don't confuse **Disk I/O** with **Disk space**:

* **Disk Read/Write** → available
* **How much disk space is actually used (%)** → requires CloudWatch Agent.
