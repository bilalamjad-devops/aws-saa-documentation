14. Question

Category: CSAA – Design High-Performing Architectures

A new online banking platform has been re-designed to have a microservices architecture in which complex applications are decomposed into smaller, independent services. The new platform uses Kubernetes, and the application containers are optimally configured for running small, decoupled services.

The new solution should remove the need to provision and manage servers, allow resources to be specified and paid for per application, and improve security through application isolation by design.

Which of the following is the MOST suitable solution to implement to launch this new platform on AWS?

- Host the application in Amazon EMR Serverless and Amazon EBS storage with the fast snapshot restore feature enabled.
- Use Amazon ECS to run the Kubernetes cluster on AWS Fargate.
- Deploy an Amazon EKS Cluster on AWS Outposts with Kubernetes Cluster Autoscaler and sync any orphaned pods with Amazon AppFlow.
- `Use AWS Fargate on Amazon EKS with Kubernetes Cluster Autoscaler to run the containerized banking platform.`

This question is testing a **very important EKS concept**. Let's break it down simply.

## Q14 — Correct answer ✅

> **Use AWS Fargate on Amazon EKS with Kubernetes Cluster Autoscaler**

The key is that the question gives you **three clues**:

### 1. "The application uses Kubernetes"

That immediately points to:

**Amazon EKS**

because:

* **EKS = managed Kubernetes**
* **ECS = AWS's own container orchestration service**

So don't choose ECS when the requirement explicitly says **Kubernetes**.

---

### 2. "Remove the need to provision and manage servers"

That points to:

**AWS Fargate**

Fargate is **serverless compute for containers**.

Normally:

```text
EKS
 │
 ├── EC2 Node
 ├── EC2 Node
 └── EC2 Node
       ↑
    You manage
```

With Fargate:

```text
EKS
 │
 ├── Pod → Fargate
 ├── Pod → Fargate
 └── Pod → Fargate

       ↑
   AWS manages
   the servers
```

You don't have to manage the underlying EC2 worker nodes.

---

### 3. "Application isolation"

Fargate provides strong workload isolation because each EKS pod runs in its own isolated compute environment.

So:

**Kubernetes + serverless + isolation**

→ **EKS + Fargate**

---

# 🧠 The most important distinction

You should memorize this:

### EKS + EC2

You manage the worker nodes.

```text
EKS
 ↓
EC2 Worker Nodes
 ↓
Pods
```

### EKS + Fargate

AWS manages the underlying compute.

```text
EKS
 ↓
Fargate
 ↓
Pods
```

So:

> **EKS tells you HOW Kubernetes is managed.**
> **Fargate tells you HOW the compute is provided.**

---

# What about Cluster Autoscaler?

This is the slightly confusing part of the question.

**Cluster Autoscaler** manages the number of **nodes** in a Kubernetes cluster.

For example:

```text
Pods need more capacity
        ↓
Cluster Autoscaler
        ↓
Add EC2 worker node
```

However, with **EKS on Fargate**, Fargate itself handles the underlying compute capacity for Fargate pods, so the question's explanation is somewhat dated/mixed in its treatment of Cluster Autoscaler.

For your **exam preparation**, follow the answer key you're using:

> **EKS + Fargate + Cluster Autoscaler**

But conceptually, remember:

**Cluster Autoscaler → nodes**

**Horizontal Pod Autoscaler → pods**

**Fargate → serverless container compute**

---

# 🔥 Very important EKS autoscaling map

This will help you with your earlier Question 21:

```text
                    EKS
                     │
          ┌──────────┴──────────┐
          │                     │
       PODS                   NODES
        │                       │
        ▼                       ▼
      HPA                 Cluster Autoscaler
        │                       │
        ▼                       ▼
 Scale number of            Scale number of
    Pods                      EC2 nodes
```

And:

```text
Karpenter
    ↓
Provision right-sized compute
    ↓
EC2 nodes
```

So remember:

> **HPA = Pods**

> **Cluster Autoscaler = Nodes**

> **Karpenter = Nodes/compute provisioning**

> **Fargate = Serverless compute for containers**

---

## Why the other answers are wrong

### ❌ ECS + Fargate

Fargate is correct, but **ECS isn't Kubernetes**.

```text
ECS → AWS container orchestration
EKS → Kubernetes
```

The question explicitly says Kubernetes → **EKS**.

---

### ❌ EKS on Outposts

Outposts brings AWS infrastructure into your own data center.

That means you're still dealing with physical infrastructure.

The requirement says:

> **remove the need to provision and manage servers**

So Outposts isn't the best fit.

---

### ❌ EMR Serverless

EMR is primarily for:

> **Big Data processing → Spark/Hadoop**

Not for running your Kubernetes banking platform.

---

# ⭐ Exam shortcut

When you see:

**"Kubernetes"**

→ **EKS**

Then ask:

**Do they want to manage EC2 worker nodes?**

* Yes → **EKS + EC2**
* No → **EKS + Fargate**

And if you see:

**"serverless containers + no servers + pay per application + isolation"**

→ **Fargate**

So this question can be compressed to:

> **Kubernetes + serverless containers = EKS + Fargate.**
