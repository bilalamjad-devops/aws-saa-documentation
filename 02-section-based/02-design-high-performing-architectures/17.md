17. Question


Category: CSAA – Design High-Performing Architectures

A company requires corporate IT governance and cost oversight of all of its AWS resources across its divisions around the world. Their corporate divisions want to maintain administrative control of the discrete AWS resources they consume and ensure that those resources are separate from other divisions.

Which of the following options will support the autonomy of each corporate division while enabling the corporate IT to maintain governance and cost oversight? (Select TWO.)

- `Use AWS Consolidated Billing by creating AWS Organizations to link the divisions’ accounts to a parent corporate account.`
- `Enable IAM cross-account access for all corporate IT administrators in each child account.`
- Use AWS Trusted Advisor and AWS Resource Groups Tag Editor
- Create separate VPCs for each division within the corporate IT AWS account. Launch an AWS Transit Gateway with equal-cost multipath routing (ECMP) and VPN tunnels for intra-VPC communication.
- Create separate Availability Zones for each division within the corporate IT AWS account. Improve communication between the two AZs using the AWS Global Accelerator.

This one is **very important for SAA** because it tests the difference between **AWS accounts, IAM, Organizations, and VPCs**.

### First understand the requirement

The company has:

```text
Corporate IT
     │
     ├── Finance
     ├── HR
     ├── Engineering
     └── Marketing
```

Each division wants:

* its own resources
* administrative autonomy
* separation from other divisions

But Corporate IT wants:

* centralized governance
* centralized cost visibility

The best architecture is:

```text
             AWS Organizations
                    │
              Corporate IT
                    │
       ┌────────────┼────────────┐
       ↓            ↓            ↓
   Finance       HR          Engineering
   Account      Account         Account
       │            │            │
     IAM          IAM           IAM
```

## 1. AWS Organizations + Consolidated Billing ✅

This gives Corporate IT a central view of costs across accounts.

For example:

```text
Finance       $5,000
HR            $2,000
Engineering   $8,000
--------------------
Total        $15,000
```

Each division still has its **own AWS account** and resources.

This is much better than putting everything into one account.

---

## 2. IAM Cross-Account Access ✅

Corporate IT administrators can assume IAM roles in the individual accounts.

For example:

```text
Corporate IT Admin
       │
       ├── AssumeRole → Finance Account
       │
       ├── AssumeRole → HR Account
       │
       └── AssumeRole → Engineering Account
```

They don't need separate IAM users everywhere.

---

# The BIG SAA concept

Remember:

> **AWS Account = security + administrative + billing boundary**

Whereas:

> **VPC = networking boundary**

This is why this answer is wrong:

> "Create separate VPCs for each division within one corporate account."

You could have:

```text
One AWS Account
   │
   ├── VPC Finance
   ├── VPC HR
   └── VPC Engineering
```

They're separate **networks**, but they're still inside the **same AWS account**.

The requirement is stronger: each division needs autonomy and resource separation.

So:

```text
Separate AWS Accounts ✅
Separate VPCs only ❌
```

---

# 🔥 Very important SAA distinction

When you see:

### "Multiple departments/divisions need separate accounts"

Think:

**AWS Organizations**

### "Centralized billing"

Think:

**Consolidated Billing**

### "Central administrators need access to member accounts"

Think:

**IAM Cross-Account Roles**

### "Separate networks"

Think:

**VPC**

### "Connect multiple VPCs"

Think:

**Transit Gateway**

---

And one correction to the provided explanation: **AWS Organizations + SCPs** are specifically for centralized governance/permission guardrails, while **Consolidated Billing** handles cost aggregation. In *this* question, the two selected answers are about **billing oversight + administrative access**, so the provided pair makes sense.
