28. Question

Category: CSAA – Design High-Performing Architectures

A company plans to use Route 53 instead of an ELB to load balance the incoming request to the web application. The system is deployed to two EC2 instances to which the traffic needs to be distributed. You want to set a specific percentage of traffic to go to each instance.

Which routing policy would you use?

- Geolocation
- Latency
- Failover
- `Weighted`

Yes — **Weighted Routing = “what percentage of traffic goes where?”**

### Route 53 routing policies — remember them like this:

| Policy          | Simple meaning              | Example                           |
| --------------- | --------------------------- | --------------------------------- |
| **Weighted**    | **Percentage**              | 90% → EC2-A, 10% → EC2-B          |
| **Geolocation** | **Where user is located**   | Japan → Tokyo, Sweden → Ireland   |
| **Latency**     | **Which region is fastest** | User → lowest-latency AWS Region  |
| **Failover**    | **Primary/backup**          | Primary → Backup if primary fails |

For this question:

> “You want to set a **specific percentage** of traffic to each instance.”

Immediately think:

**Percentage → Weighted Routing.** ✅

### Easy memory trick

**W = Weight = Percentage**

For example:

```text
example.com
     |
 Route 53
     |
 ┌───┴────────┐
 │            │
90%          10%
 │            │
EC2-A        EC2-B
```

One important point: **Route 53 Weighted Routing is DNS-based traffic distribution**, not the same thing as an ALB distributing individual requests. Route 53 returns DNS answers according to the configured weights.

Also, the four policies you're seeing repeatedly in these SAA questions are worth memorizing:

> **Weighted = percentage**
> **Geolocation = user's location**
> **Latency = lowest latency**
> **Failover = primary/secondary**

This question is basically testing that one distinction.
