8. Question

Category: CSAA – Design High-Performing Architectures

A company receives semi-structured and structured data from different sources, which are eventually stored in the Amazon S3 data lake that uses client-side encryption with a custom client-side root key (CSE-Custom). The Solutions Architect plans to use big data processing frameworks to analyze data and access it using various business intelligence tools and standard SQL queries.

Which of the following provides the MOST high-performing solution that fulfills this requirement?

- Use Amazon Managed Service for Apache Flink Studio and store the processed data in Amazon DynamoDB.
- Create an Amazon EC2 instance and store the processed data in Amazon EBS.
- `Create an Amazon EMR cluster and store the processed data in Amazon Redshift.`
- Use AWS Batch jobs to process the data and store the processed data in S3.

This question is mainly testing **EMR vs Redshift**. Don't overcomplicate it.

## Q8 — Answer: EMR + Redshift ✅

There are **two different jobs** in the question:

### 1. "Big data processing frameworks"

The clue is:

> **Hadoop / Spark / big data processing**

Think:

**Amazon EMR**

EMR is where you run big-data processing frameworks such as Hadoop and Spark.

### 2. "Business intelligence tools + standard SQL"

The clue is:

> **SQL + BI tools + analytics**

Think:

**Amazon Redshift**

Redshift is a **data warehouse** designed for analytical queries and BI workloads.

So:

```text
S3 Data Lake
     ↓
Amazon EMR
(Hadoop / Spark)
     ↓
Transform / Process
     ↓
Amazon Redshift
     ↓
SQL + BI Tools
```

### 🧠 Memorize this distinction

| Requirement                      | Service           |
| -------------------------------- | ----------------- |
| Big-data processing              | **EMR**           |
| Hadoop / Spark                   | **EMR**           |
| Data transformation at big scale | **EMR**           |
| Data warehouse                   | **Redshift**      |
| Complex SQL analytics            | **Redshift**      |
| BI tools                         | **Redshift**      |
| Data lake/object storage         | **S3**            |
| Real-time streaming processing   | **Flink/Kinesis** |
| Batch computing                  | **AWS Batch**     |

### One important exam pattern

If you see:

> **"Process huge amounts of data using Hadoop/Spark"**

→ **EMR**

If you see:

> **"Analyze data using SQL and BI tools"**

→ **Redshift**

If you see **both**:

> **Hadoop/Spark → SQL/BI**

→ **EMR → Redshift** ✅

That's exactly what this question is testing.

## 1. What is EMR?

**Amazon EMR = Amazon Elastic MapReduce**

Think of EMR as:

> **AWS's managed platform for running big-data processing frameworks.**

Instead of manually creating many EC2 servers and installing/configuring Hadoop or Spark yourself, AWS manages much of the cluster setup for you.

Example:

```text
Huge dataset
     ↓
    S3
     ↓
    EMR
     ↓
Hadoop / Spark
     ↓
Processed data
```

### Why do we need EMR?

Imagine you have **10 TB of log data**.

Processing 10 TB on one server could take a very long time.

Instead:

```text
10 TB
  ↓
┌──────┬──────┬──────┬──────┐
Server  Server  Server  Server
   ↓       ↓       ↓       ↓
  Part    Part    Part    Part
   └───────┴───────┴───────┘
             ↓
       Combined result
```

Multiple machines process different portions of the data **in parallel**.

That's the basic idea behind big-data processing.

---

# 2. What is Hadoop?

**Hadoop is an open-source framework for distributed big-data processing.**

The important idea is:

> **Hadoop allows you to distribute huge amounts of data and processing across multiple machines.**

Hadoop has several components, but for SAA you mainly need to recognize:

### HDFS

**Hadoop Distributed File System**

It distributes large files across multiple machines.

```text
10 TB file
   ↓
Hadoop
   ↓
Server 1 → Part 1
Server 2 → Part 2
Server 3 → Part 3
Server 4 → Part 4
```

### MapReduce

A programming model for processing data in parallel.

You don't need to deeply learn MapReduce for SAA. Just remember:

> **Hadoop = distributed big-data framework**

---

# 3. What is Spark?

**Apache Spark** is another open-source distributed data-processing framework.

It is generally much faster and more flexible than traditional MapReduce for many workloads because Spark can keep intermediate data in memory.

Spark can be used for:

* Big-data processing
* ETL
* Analytics
* Machine learning
* Streaming

Think:

> **Spark = fast distributed data processing**

---

# 4. So what's the relationship?

This is the part I really want you to remember:

```text
                    AWS
                     │
                    EMR
                     │
          ┌──────────┴──────────┐
          │                     │
       Hadoop                 Spark
          │                     │
   Big-data processing    Big-data processing
```

**EMR isn't Hadoop or Spark.**

EMR is the **AWS managed service/platform** where you can run frameworks such as Hadoop and Spark.

# 5. Simple real-world example

Suppose Amazon has billions of customer transactions and wants to answer:

> "What were the top 100 products purchased last month?"

You could have:

```text
Transaction Data
       ↓
       S3
       ↓
      EMR
       ↓
     Spark
       ↓
Process billions of records
       ↓
   Results
```

Then perhaps store the processed results in:

```text
Redshift
    ↓
BI Dashboard
```

So:

**S3 → EMR/Spark → Redshift → BI**
