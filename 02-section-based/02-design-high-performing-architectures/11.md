11. Question

Category: CSAA – Design High-Performing Architectures

A Solutions Architect needs to set up the required compute resources for the application which have workloads that require high, sequential read and write access to very large data sets on local storage.

Which of the following instance type is the most suitable one to use in this scenario?

- General Purpose Instances
- Compute Optimized Instances
- `Storage Optimized Instances`
- Memory Optimized Instances

This is mainly testing **EC2 instance families**. The key phrase is:

> **"high sequential read and write access to very large data sets on local storage"**

### ✅ Answer: Storage Optimized

Think:

> **Storage Optimized = lots of data + very fast disk I/O**

For example:

```text
Huge Dataset
     ↓
Very fast local storage
     ↓
High read/write IOPS
     ↓
Storage Optimized EC2
```

### 🧠 Memorize the 4 major families

| Instance type         | Think       | Typical workload                  |
| --------------------- | ----------- | --------------------------------- |
| **General Purpose**   | ⚖️ Balance  | Web servers, normal applications  |
| **Compute Optimized** | 🧠 CPU      | Batch processing, video encoding  |
| **Memory Optimized**  | 🧠 RAM      | Large in-memory datasets, caching |
| **Storage Optimized** | 💾 Disk/I/O | Very high disk read/write         |

### Super-simple memory trick

**General → Everything balanced**

**Compute → CPU**

**Memory → RAM**

**Storage → Disk**

So when the question says:

> **"high read/write + very large data + local storage"**

Immediately choose:

**💾 Storage Optimized EC2** ✅

Don't get distracted by **"large data sets"**. If the question emphasizes **processing large data *in memory*** → Memory Optimized.

If it emphasizes **reading/writing large data on storage** → Storage Optimized.

But we can use EBS?

Yes — **you absolutely can use EBS**. The question is testing a slightly different concept.

### The key difference

**EBS = separate network-attached block storage**

**Storage-optimized instance = EC2 instance designed with very fast local storage (instance store/NVMe)**.

Think:

```text
EBS approach

EC2 ─────── network ─────── EBS
                              💾
```

versus:

```text
Storage-optimized

EC2
└── ⚡ Local NVMe / instance storage
```

### Why choose Storage Optimized here?

The question specifically says:

> **"high, sequential read and write access to very large data sets on local storage"**

That word **local** is the clue.

Storage-optimized instances are designed for workloads requiring **very high local-storage I/O performance**, such as:

* high-performance databases
* data warehousing
* distributed file systems
* log processing
* very high I/O workloads

### But when would I use EBS?

If the question says something like:

> "The application needs persistent block storage that can be detached and attached to another EC2 instance."

→ **EBS** ✅

EBS persists independently of the EC2 instance.

Whereas instance-store/local NVMe is tied to the physical host and generally **doesn't persist when the instance is stopped/terminated**.

### 🧠 SAA exam shortcut

Remember:

**EBS → persistent block storage**

**Instance Store → temporary, extremely fast local storage**

**Storage Optimized EC2 → EC2 family designed for very high local-storage I/O**

So don't think:

> "Storage Optimized means EBS."

Instead think:

> **Storage Optimized = the EC2 itself is optimized for storage-heavy workloads.**
