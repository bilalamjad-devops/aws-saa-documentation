7. Question

Category: CSAA – Design High-Performing Architectures

A Solutions Architect needs to deploy a mobile application that collects votes for a singing competition. Millions of users from around the world will submit votes using mobile phones. These votes must be collected and stored in a highly scalable and highly available database, which will be queried for real-time ranking. The database is expected to undergo frequent schema changes throughout the voting period.

Which of the following combinations of services should the architect use to meet this requirement, with read capacity units (RCU) that scale for live rankings?

- Amazon Relational Database Service (Amazon RDS) and Amazon MQ
- Amazon DocumentDB (with MongoDB compatibility) and Amazon AppFlow
- `Amazon DynamoDB and AWS AppSync`
- Amazon Aurora and Amazon Cognito

This question combines **three clues**, and once you recognize them, the answer becomes easy.

## Q7 — DynamoDB + AppSync ✅

### 1. Millions of users → DynamoDB

The application needs:

* Millions of users
* Very high request volume
* Highly scalable
* Highly available
* Real-time rankings

**DynamoDB** is designed for this kind of high-scale NoSQL workload.

---

### 2. Frequent schema changes → DynamoDB

This is probably the **most important exam clue**.

A relational database has a defined schema:

```text
Users
----------------
id
name
age
country
```

Adding/changing columns requires schema changes.

DynamoDB is **schemaless except for the primary key**:

```text
Item 1:
id, name, country

Item 2:
id, name, country, favoriteSinger

Item 3:
id, name, votes, region, device
```

So:

> **Frequently changing schema → NoSQL → DynamoDB**

---

### 3. Real-time application → AppSync

AWS AppSync makes it easier to build applications where data needs to be **updated in real time**.

So the architecture is:

```text
📱 Millions of mobile users
          ↓
      AWS AppSync
          ↓
      DynamoDB
          ↓
   Live vote rankings
```

### 🧠 Memorize this pattern

**DynamoDB + AppSync = scalable real-time application**

Especially when you see:

> **Mobile app + millions of users + real-time data + rapidly changing schema**

Think:

**DynamoDB + AppSync** ✅

---

### One subtle point

The question mentions **RCUs**:

> "read capacity units (RCU) that scale for live rankings"

DynamoDB uses:

* **RCU** → Read Capacity Units
* **WCU** → Write Capacity Units

For millions of users submitting votes:

**Writes → WCU**

For users checking rankings:

**Reads → RCU**

And DynamoDB can use **On-Demand capacity** or **Auto Scaling** to handle changing traffic.

So don't get distracted by RCU—the main architectural clues are:

> **Massive scale + NoSQL/flexible schema + real-time → DynamoDB + AppSync.**
