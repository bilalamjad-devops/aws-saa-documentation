13. Question

Category: CSAA – Design High-Performing Architectures

An AI-powered Forex trading application consumes thousands of data sets to train its machine learning model. The application’s workload requires a high-performance, parallel hot storage to process the training datasets concurrently. It also needs cost-effective cold storage to archive those datasets that yield low profit.

Which of the following Amazon storage services should the developer use?

- `Use Amazon FSx For Lustre and Amazon S3 for hot and cold storage respectively.`
- Use Amazon Elastic File System and Amazon S3 for hot and cold storage respectively.
- Use Amazon FSx For Lustre and the Provisioned IOPS SSD (io1) volumes of Amazon EBS for hot and cold storage respectively.
- Use Amazon FSx For Windows File Server and Amazon S3 for hot and cold storage respectively.

This is a **very important High-Performing Architecture question** because it teaches you how AWS chooses storage based on **performance + access pattern**.

## Q13 — Correct answer ✅

> **Amazon FSx for Lustre + Amazon S3**

The architecture is:

```text
             ML Training
                 │
                 ▼
        ┌─────────────────┐
        │ FSx for Lustre  │
        │  HOT DATA       │
        │ High Performance│
        │ Parallel Access │
        └────────┬────────┘
                 │
        Training datasets
                 │
                 ▼
             ML Model
                 │
        Low-profit datasets
                 │
                 ▼
        ┌─────────────────┐
        │       S3        │
        │  COLD STORAGE   │
        │ Glacier /        │
        │ Glacier DA       │
        └─────────────────┘
```

### Why FSx for Lustre?

The keywords are:

> **AI/ML + high performance + parallel + datasets + concurrently**

Those words should immediately trigger:

### 🚀 FSx for Lustre

Lustre is a **parallel file system** designed for workloads such as:

* Machine learning
* HPC
* Big data processing
* EDA
* Media processing

The important idea is that data can be processed **in parallel**, rather than relying on a traditional file system architecture.

---

# Why S3 for cold data?

The question says:

> datasets that yield low profit

Meaning they're not frequently accessed and need to be archived cheaply.

So:

**S3 → appropriate storage class**

For very cold archival data:

```text
S3
 ├── Standard
 ├── Standard-IA
 ├── Glacier Instant Retrieval
 ├── Glacier Flexible Retrieval
 └── Glacier Deep Archive
```

For **long-term, rarely accessed archival data**, think:

> **S3 Glacier / Glacier Deep Archive**

---

# 🧠 Hot vs Warm vs Cold

This is worth memorizing:

| Data     | Meaning               | AWS examples                          |
| -------- | --------------------- | ------------------------------------- |
| 🔥 Hot   | Frequently accessed   | FSx for Lustre, EFS, EBS, S3 Standard |
| 🌤️ Warm | Occasionally accessed | S3 Standard-IA                        |
| ❄️ Cold  | Rarely accessed       | S3 Glacier / Glacier Deep Archive     |

The colder the data:

**Storage cost ↓**

but generally:

**Retrieval time/cost ↑**

---

# Why not EFS?

EFS is excellent for:

> **Shared Linux file storage**

For example:

```text
EC2-1 ─┐
EC2-2 ─┤
EC2-3 ─┼──► EFS
EC2-4 ─┤
EC2-5 ─┘
```

But the question isn't merely asking:

> "Can many machines access the files?"

It's asking for:

> **high-performance parallel processing for ML datasets**

That's where **FSx for Lustre** becomes the stronger answer.

> **ML + HPC + parallel → FSx for Lustre**

## One subtle point about this question

The answer says:

> FSx for Lustre for hot + S3 for cold.

Don't interpret that as **S3 itself always being "cold."**

S3 is actually a **family of storage classes** with different access patterns.

The better mental model is:

```text
                  S3
                   │
        ┌──────────┼───────────┐
        ▼          ▼           ▼
      Hot        Warm         Cold
    Standard   Standard-IA   Glacier
                              Glacier DA
```

So the exam is really testing:

> **Use the right storage service/class according to the workload.**

Absolutely. The easiest way to understand **Amazon FSx for Windows** and **Amazon FSx for Lustre** is to think of them as **two different specialized file systems**.

## First: What is Amazon FSx?

**Amazon FSx = managed file storage.**

AWS manages the underlying file servers, so you don't have to build and maintain your own file server.

But AWS offers different FSx types for different workloads.

The two you need to remember here are:

```text
                 Amazon FSx
                    │
          ┌─────────┴─────────┐
          │                   │
   FSx for Windows      FSx for Lustre
          │                   │
     Windows apps        HPC / ML
     SMB / NTFS          Parallel
     Active Directory    High performance
```

---

# 1. FSx for Windows File Server 🪟

Think:

> **"I have a Windows file server, but I don't want to manage the Windows file server myself."**

It gives you a **managed Windows file system**.

It supports things that Windows applications expect:

* **SMB** protocol
* **NTFS**
* **Active Directory**
* Windows file shares
* DFS (Distributed File System)

For example:

```text
Windows EC2 #1 ──┐
Windows EC2 #2 ──┤
Windows EC2 #3 ──┼──► FSx for Windows
Windows EC2 #4 ──┘
                       │
                    File Share
```

Your Windows applications can access it like a normal Windows network file share.

### Exam trigger

If the question says:

> Windows + SMB + NTFS + Active Directory

Immediately think:

**FSx for Windows File Server** ✅

---

# 2. FSx for Lustre 🚀

Now forget Windows.

Think:

> **"I have huge datasets and need extremely fast parallel processing."**

Lustre is a **high-performance parallel file system**.

It's commonly associated with:

* HPC
* Machine Learning
* Big Data
* EDA
* Media processing

Example:

```text
             Huge Dataset
                  │
                  ▼
        ┌──────────────────┐
        │  FSx for Lustre  │
        │                  │
        │ Parallel File    │
        │ System           │
        └───────┬──────────┘
                │
       ┌────────┼────────┐
       ▼        ▼        ▼
     EC2-1    EC2-2    EC2-3
       │        │        │
       └────────┼────────┘
                ▼
          ML / HPC Job
```

Instead of having one machine process everything sequentially, the workload can access/process data **in parallel**.

FSx for Lustre can also integrate with **S3**, which is particularly useful for large datasets.

# The BIG difference

|                     | FSx for Windows        | FSx for Lustre             |
| ------------------- | ---------------------- | -------------------------- |
| Main purpose        | Windows file storage   | High-performance computing |
| Think               | 🪟 Windows File Server | 🚀 HPC/ML                  |
| Protocol            | SMB                    | Lustre                     |
| Windows             | ✅                      | ❌ Not the focus            |
| Active Directory    | ✅                      | ❌                          |
| NTFS                | ✅                      | ❌                          |
| Parallel processing | Not the main purpose   | ✅                          |
| ML                  | Not the main choice    | ✅                          |
| HPC                 | Not the main choice    | ✅                          |
| S3 integration      | Possible               | ⭐ Very important use case  |

## 🧠 Memorize this for SAA

Don't memorize the entire table.

Just memorize:

### **FSx Windows**

> **Windows → SMB → AD → NTFS**

### **FSx Lustre**

> **Lustre → Linux/HPC → ML → Parallel → High Performance**

And compare with the other storage services you've already encountered:

```text
EBS
↓
One EC2 → Block storage

EFS
↓
Many Linux EC2 → Shared NFS file system

FSx Windows
↓
Windows → SMB → AD/NTFS

FSx Lustre
↓
HPC/ML → Parallel → High performance

S3
↓
Object storage → Massive scale → Data lake/archive
```

### One-line exam rule

> **Windows file sharing = FSx Windows.**
> **HPC/ML parallel processing = FSx Lustre.**
> **Shared Linux files = EFS.**
> **EC2 block disk = EBS.**
> **Objects/data lake = S3.**

That distinction will answer a **lot** of SAA storage questions.
