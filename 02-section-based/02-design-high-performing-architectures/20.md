20. Question

Category: CSAA – Design High-Performing Architectures

A company has hundreds of VPCs with multiple VPN connections to their data centers spanning 5 AWS Regions. As the number of its workloads grows, the company must be able to scale its networks across multiple accounts and VPCs to keep up. A Solutions Architect is tasked to interconnect all of the company’s on-premises networks, VPNs, and VPCs into a single gateway, which includes support for inter-region peering across multiple AWS regions.

Which of the following is the BEST solution that the architect should set up to support the required interconnectivity?

- `Set up an AWS Transit Gateway in each region to interconnect all networks within it. Then, route traffic between the transit gateways through a peering connection.`
- Enable inter-region VPC peering that allows peering relationships to be established between multiple VPCs across different AWS regions. Set up a networking configuration that ensures that the traffic will always stay on the global AWS backbone and never traverse the public Internet.
- Set up an AWS VPN CloudHub for inter-region VPC access and a Direct Connect gateway for the VPN connections to the on-premises data centers. Create a virtual private gateway in each VPC, then create a private virtual interface for each AWS Direct Connect connection to the Direct Connect gateway.
- Set up an AWS Direct Connect Gateway to achieve inter-region VPC access to all of the AWS resources and on-premises data centers. Set up a link aggregation group (LAG) to aggregate multiple connections at a single AWS Direct Connect endpoint in order to treat them as a single, managed connection. Launch a virtual private gateway in each VPC and then create a public virtual interface for each AWS Direct Connect connection to the Direct Connect Gateway.

Yes — this question is testing **Transit Gateway**, and it's an important SAA networking concept.

## The core idea

The company has:

* Hundreds of VPCs
* Multiple AWS accounts
* Multiple AWS Regions
* VPN connections
* On-premises data centers
* Need to connect everything together

Imagine doing this with VPC Peering:

```text
VPC A ─── VPC B
 │ ╲       │
 │  ╲      │
 VPC C ─── VPC D
```

As the number of VPCs grows, this becomes a **mess of point-to-point connections**.

### Transit Gateway solves this with a hub-and-spoke model:

```text
             VPC
              │
              │
VPC ─── Transit Gateway ─── VPN ─── On-Prem
              │
              │
             VPC
              │
              │
       Transit Gateway
          Region B
```

Each VPC/network connects to the Transit Gateway rather than connecting directly to every other VPC.

---

## But this question has MULTIPLE regions

A Transit Gateway is **regional**.

So:

```text
Region A                         Region B

VPC ─┐                           ┌─ VPC
VPC ─┼─ TGW A ═══════════════ TGW B ─┼─ VPC
VPC ─┘      TGW Peering           └─ VPC
```

You create:

**Transit Gateway in each Region → connect local VPCs/VPNs → peer the Transit Gateways across Regions.**

That's why the first answer is correct.

---

# Why not VPC Peering?

VPC Peering works:

```text
VPC A ←→ VPC B
```

It can work across Regions, but with **hundreds of VPCs**, you end up managing a huge number of individual connections and routes.

Transit Gateway:

```text
       VPC
        │
VPC ─── TGW ─── VPC
        │
       VPN
        │
    On-Prem
```

Much easier to scale.

### SAA keyword

> **Hundreds of VPCs / many accounts / centralized connectivity / hub-and-spoke**

➡️ **Transit Gateway**

---

# Transit Gateway vs Direct Connect Gateway

This is another exam trap.

### Transit Gateway

Think:

> **"Connect lots of VPCs + VPNs + networks."**

```text
VPCs
 │
 │
Transit Gateway
 │
 ├── VPN
 ├── VPC
 ├── VPC
 └── Direct Connect Gateway
```

### Direct Connect Gateway

Think:

> **"Connect my on-premises network to AWS through Direct Connect."**

It is primarily about **Direct Connect connectivity**, not replacing Transit Gateway as your central multi-VPC routing hub.

---

# One more important concept

You might see:

**Transit Gateway Peering**

This means:

```text
TGW us-east-1
      ║
      ║ TGW Peering
      ║
TGW eu-west-1
```

This is how you connect **Transit Gateways in different Regions**.

So remember:

> **VPCs within a Region → attach to regional TGW.**
> **TGWs in different Regions → Transit Gateway peering.**

---

## 🧠 Your SAA memory shortcut

When you see:

**2 VPCs** → VPC Peering may be appropriate.

**Many VPCs** → Transit Gateway.

**Many VPCs + multiple Regions** → Transit Gateway in each Region + TGW peering.

**On-premises + dedicated network connection** → Direct Connect.

**VPN connections + centralized VPC connectivity** → Transit Gateway.

**Multiple VPN sites communicating with each other** → VPN CloudHub.

This distinction will help you answer a LOT of the networking questions in the SAA exam.
