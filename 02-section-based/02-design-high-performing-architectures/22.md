22. Question

Category: CSAA – Design Cost-Optimized Architectures

A financial services company plans to migrate its trading application from on-premises Microsoft Windows Server to Amazon Web Services (AWS).
The solution must ensure high availability across multiple Availability Zones and offer low-latency access to block storage.

Which of the following solutions will fulfill these requirements?

- Configure the trading application on Amazon EC2 Windows instances across two Availability Zones. Use Amazon Simple Storage Service (Amazon S3) for storage and configure cross-region replication to sync data between S3 buckets in each Availability Zone.
- Deploy the trading application on Amazon EC2 Windows Server instances across two Availability Zones. Use Amazon Elastic File System (Amazon EFS) to provide shared storage between the instances. Configure Amazon EFS with cross-region replication to sync data across Availability Zones.
- `Configure the trading application on Amazon EC2 Windows Server instances across two Availability Zones. Use Amazon FSx for NetApp ONTAP to create a Multi-AZ file system and access the data via iSCSI protocol.`
- Deploy the trading application on Amazon EC2 Windows Server instances across two Availability Zones. Use Amazon FSx for Windows File Server for shared storage.

This is a **storage-selection question**, and the key is to identify the combination of requirements.

### First extract the keywords

The application needs:

1. **Windows Server**
2. **High availability across multiple AZs**
3. **Block storage**
4. **Low latency**
5. Specifically, the answer says **iSCSI**

That combination points to:

> **Amazon FSx for NetApp ONTAP + iSCSI + Multi-AZ**

**FSx for NetApp ONTAP** supports:

* SMB → Windows file access

* **iSCSI → block storage**
* Multi-AZ deployment
* Low-latency SSD storage

        │                     │

        │   │           │     │

### Why the other answers fail

**S3** ❌
Object storage, not block storage. Great durability/scalability, but not the low-latency block storage this application requires.

**EFS** ❌
EFS is primarily for **Linux/NFS** workloads. It isn't the right choice for Windows + block storage.

**FSx for Windows File Server** ❌
This is actually a very important distinction.

FSx for Windows gives you:

> **Windows + SMB + shared file storage**

But the question requires:

> **Windows + block storage + iSCSI**

Therefore, **FSx for NetApp ONTAP** wins.

Instead ask:

> **What type of storage does the workload require?**

Here it's **block storage through iSCSI**, which pushes you toward **FSx for NetApp ONTAP**.

Exactly — **FSx for NetApp ONTAP is a third major FSx option you should know for SAA.** You don't need to go extremely deep into it.

### First: What is NetApp ONTAP?

**ONTAP** is a storage operating system developed by **NetApp**.

AWS basically gives you a **managed NetApp storage system** through:

> **Amazon FSx for NetApp ONTAP**

You don't manage the underlying NetApp hardware/software yourself.

### Compare the FSx family

Think of the three you've encountered like this:

| Service                         | Main purpose                        | Key protocol/feature      |
| ------------------------------- | ----------------------------------- | ------------------------- |
| **FSx for Windows File Server** | Windows applications                | **SMB**, Active Directory |
| **FSx for Lustre**              | HPC, ML, high-performance computing | **Parallel file system**  |
| **FSx for NetApp ONTAP**        | Flexible enterprise storage         | **NFS, SMB, iSCSI**       |

The easiest mental model:

```text
FSx
│
├── Windows File Server
│      → Windows
│      → SMB
│      → Active Directory
│
├── Lustre
│      → HPC
│      → ML
│      → Parallel processing
│      → Very high throughput
│
└── NetApp ONTAP
       → Enterprise storage
       → NFS
       → SMB
       → iSCSI
       → Multi-AZ options
```

### The big thing to remember for your exam

**iSCSI = block storage**

So when you see something like:

> Windows application + Multi-AZ + low-latency **block storage** + iSCSI

🚨 Think:

**FSx for NetApp ONTAP**

Whereas:

> Windows + SMB + Active Directory

→ **FSx for Windows File Server**

And:

> HPC + ML + parallel file system + massive throughput

→ **FSx for Lustre**

### One correction to keep your mental model clean

Don't think:

> "FSx = Windows"

Think:

> **FSx = AWS managed file-system family, with different implementations for different workloads.**

That's why SAA questions can give you **FSx for Windows, Lustre, and NetApp ONTAP** as separate choices.
