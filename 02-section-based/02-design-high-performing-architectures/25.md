25. Question

Category: CSAA – Design High-Performing Architectures

A data analytics company is setting up an innovative checkout-free grocery store. The Solutions Architect developed a real-time monitoring application that uses smart sensors to collect the items that the customers are getting from the grocery’s refrigerators and shelves, then automatically deduct those items from customer accounts. The company wants to analyze the items that are frequently being bought and store the results in Amazon S3 for durable storage to determine the purchase behavior of its customers.

Which of the following must be used to easily capture, transform, and load streaming data into S3, Amazon OpenSearch Service, and Splunk?

- Amazon DynamoDB Streams
- `Amazon Data Firehose`
- Amazon SQS
- Amazon Redshift

Yes. Q25 is a very important **streaming-data architecture** question. The key is understanding what **Amazon Data Firehose** actually does.

## 🔥 Amazon Data Firehose

Think of Firehose as:

> **"Take streaming data → optionally transform it → deliver it to a destination."**

For this question:

```text
Smart Sensors
     │
     │ streaming data
     ▼
Amazon Data Firehose
     │
     ├──────────► S3
     │
     ├──────────► OpenSearch
     │
     └──────────► Splunk
```

That's exactly what the question is describing.

### Why Firehose?

The question literally says:

> **capture, transform, and load streaming data**

That should immediately make you think:

**Amazon Data Firehose** 🔥

It is managed and automatically handles scaling, buffering, batching, compression, and delivery.

---

# Firehose vs Kinesis Data Streams

This is where SAA questions can become confusing.

### Kinesis Data Streams

Think:

> **"I need to process the stream myself."**

```text
Producers
   │
   ▼
Kinesis Data Streams
   │
   ├──► Consumer 1
   ├──► Consumer 2
   └──► Consumer 3
```

You can have multiple consumers reading the same stream.

Useful when you need:

* real-time processing
* ordering
* replay
* multiple consumers
* custom stream-processing applications

---

### Data Firehose

Think:

> **"I just need to get streaming data into a destination."**

```text
Streaming Data
      │
      ▼
   Firehose
      │
      ├──► S3
      ├──► Redshift
      ├──► OpenSearch
      └──► Splunk
```

Firehose is much more of a **delivery pipeline**.

---

## Very useful exam distinction

| Requirement                         | Think                    |
| ----------------------------------- | ------------------------ |
| Stream data into S3                 | **Firehose**             |
| Stream data into OpenSearch         | **Firehose**             |
| Stream data into Splunk             | **Firehose**             |
| Capture → transform → load          | **Firehose**             |
| Need multiple consumers             | **Kinesis Data Streams** |
| Need replay records                 | **Kinesis Data Streams** |
| Need custom real-time processing    | **Kinesis Data Streams** |
| Queue messages between applications | **SQS**                  |
| Capture changes to DynamoDB items   | **DynamoDB Streams**     |

---

### One important correction to keep in your notes

You may see older material call it **Kinesis Data Firehose** or **Amazon Kinesis Data Firehose**.

AWS renamed it to **Amazon Data Firehose**.

So if Tutorials Dojo says:

> Amazon Data Firehose

and you see:

> Kinesis Data Firehose

they're referring to the same service.

### 🧠 Your SAA memory trick

**Firehose = delivery**

**Kinesis Data Streams = stream processing**

**SQS = queue**

**DynamoDB Streams = DynamoDB changes**

This distinction will help you answer a lot of the upcoming questions.
