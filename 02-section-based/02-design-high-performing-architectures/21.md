21. Question

Category: CSAA – Design High-Performing Architectures

A technology company is building a new cryptocurrency trading platform that allows the buying and selling of Bitcoin, Ethereum, Ripple, Tether, and many others. A Cloud Engineer was hired to build the infrastructure required for this platform. During the first week, the engineer began creating CloudFormation YAML scripts to define all of the AWS resources needed for the application. The manager was shocked that the engineer hadn’t set up the EC2 instances, S3 buckets, and other AWS resources immediately. He doesn’t understand the purpose of the text-based scripts the engineer has written and has asked for clarification.

In this scenario, what are the benefits of using Amazon CloudFormation that the manager should know to address his concerns? (Select TWO.)

- A storage location for the code of your application
- `Enables modeling, provisioning, and version-controlling of your entire AWS infrastructure`
- Provides highly durable and scalable data storage
- Using CloudFormation itself is free, including the AWS resources that have been created.
- `Allows you to model your entire infrastructure in a text file`


Yes — and that's actually a **good thing**, because what you already know from Terraform transfers very directly to CloudFormation.

One correction first: the question is about **CloudFormation**, not CloudFront.

### Terraform vs CloudFormation

You can think of them like this:

| Terraform              | CloudFormation                          |
| ---------------------- | --------------------------------------- |
| Infrastructure as Code | Infrastructure as Code                  |
| `.tf` files            | YAML/JSON templates                     |
| `terraform plan`       | Change Sets / stack preview             |
| `terraform apply`      | Create/update stack                     |
| `terraform destroy`    | Delete stack                            |
| Terraform state        | CloudFormation manages stack state      |
| Multi-cloud            | AWS-focused                             |
| Providers              | AWS resources built into CloudFormation |

So if you've already done things like:

```text
Terraform
   ↓
VPC
EC2
S3
IAM
ALB
RDS
```

you already understand the **fundamental idea** behind CloudFormation.

---

### What CloudFormation is doing in this question

The manager is thinking:

> "Why are you writing YAML instead of creating the EC2 instances now?"

The engineer is actually doing:

```text
CloudFormation template
        ↓
   CloudFormation
        ↓
   AWS resources
 ┌──────┼──────┐
 EC2    S3     IAM
        ↓
   Infrastructure
```

For example, conceptually:

```yaml
Resources:
  MyBucket:
    Type: AWS::S3::Bucket

  MyInstance:
    Type: AWS::EC2::Instance
```

CloudFormation reads that template and creates the resources.

The **big advantage** is that the YAML becomes the **definition of your infrastructure**.

You can put it in Git:

```text
GitHub
   │
   └── infrastructure.yaml
             │
             ↓
       CloudFormation
             │
       ┌─────┼─────┐
       EC2   S3    IAM
```

Someone can review the infrastructure changes before they are deployed.

---

## The two exam answers

### 1. Enables modeling, provisioning, and version-controlling your entire AWS infrastructure

Think:

> **IaC + Git + automated provisioning**

### 2. Allows you to model your entire infrastructure in a text file

Think:

> **Infrastructure → YAML/JSON template**

---

### And one important exam trap

> "Using CloudFormation itself is free, including the AWS resources that have been created."

❌ Wrong.

CloudFormation itself has **no additional charge**, but the resources it creates aren't free.

For example:

```text
CloudFormation → $0
EC2 → 💰
RDS → 💰
NAT Gateway → 💰
S3 → 💰
```

---

## For your learning

Since you've already learned Terraform, **don't spend weeks learning CloudFormation from scratch**.

For SAA, understand the concept:

> **CloudFormation = AWS-native Infrastructure as Code.**

Know what **templates, stacks, change sets, drift detection, parameters, outputs, and nested stacks** mean.

But your main DevOps IaC tool can remain **Terraform**. You don't need to replace Terraform just because SAA questions mention CloudFormation.
