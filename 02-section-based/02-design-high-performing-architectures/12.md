12. Question

Category: CSAA – Design High-Performing Architectures

A company is running a multi-tier web application farm in a virtual private cloud (VPC) that is not connected to their corporate network. They are connecting to the VPC over the Internet to manage the fleet of Amazon EC2 instances running in both the public and private subnets. The Solutions Architect has added a bastion host with Microsoft Remote Desktop Protocol (RDP) access to the application instance security groups, but the company wants to further limit administrative access to all of the instances in the VPC.

Which of the following bastion host deployment options will meet this requirement?

- Deploy a Windows Bastion host on the corporate network that has RDP access to all EC2 instances in the VPC.
- `Deploy a Windows Bastion host with an Elastic IP address in the public subnet and allow RDP access to bastion only from the corporate IP addresses.`
- Deploy a Windows Bastion host with an Elastic IP address in the public subnet and allow SSH access to the bastion from anywhere.
- Deploy a Windows Bastion host with an Elastic IP address in the private subnet, and restrict RDP access to the bastion from only the corporate public IP addresses.

Yes. This question is testing **how a Bastion Host works**, and there are 3 clues you should memorize.

## Q12 — Correct answer ✅

> **Windows Bastion Host + Elastic IP + Public Subnet + RDP allowed only from corporate IPs**

Architecture:

```text
                 Internet
                    │
          Corporate Public IP
                    │
                 RDP 3389
                    │
                    ▼
        ┌──────────────────────┐
        │  Public Subnet       │
        │                      │
        │  Windows Bastion     │
        │  Elastic IP          │
        └──────────┬───────────┘
                   │
              RDP / management
                   │
        ┌──────────▼───────────┐
        │ Private Subnet       │
        │                      │
        │ EC2 App Servers      │
        └──────────────────────┘
```

### Why public subnet?

The administrators are connecting **from outside the VPC over the Internet**.

Therefore, the Bastion needs a path to the Internet:

**Internet → Internet Gateway → Bastion**

So:

> **Bastion = Public Subnet** ✅

### Why Elastic IP?

The Bastion needs a stable public IP address that administrators can connect to.

And even better, the security group can say:

```text
RDP 3389
Source: Corporate-Public-IP/32
```

rather than:

```text
RDP 3389
Source: 0.0.0.0/0   ❌
```

This is the **least-privilege** idea.

---

## 🧠 Memorize Bastion Host

Think:

> **Bastion = controlled doorway into private servers**

For a Windows environment:

**Bastion**
→ Public subnet
→ Public/EIP
→ RDP 3389
→ Source restricted to trusted IPs

For Linux:

**Bastion**
→ Public subnet
→ Public/EIP
→ SSH 22
→ Source restricted to trusted IPs

### Very important

The private EC2 instances **do not need to be directly exposed to the Internet**.

Instead:

```text
Admin
  ↓
Bastion
  ↓
Private EC2
```

That's the whole purpose of the Bastion.

### Exam shortcut

When you see:

> **"Administrators need to access private EC2 instances from the Internet"**

Think:

**Bastion Host → Public Subnet → Public/EIP → Restrict SSH/RDP source IP**

And if the question says **Windows** → **RDP**.
If it says **Linux** → **SSH**.
