aA26. Question
Category: CSAA – Design High-Performing Architectures
A startup needs to use a shared file system for its .NET web application running on an Amazon EC2 Windows instance. The file system must provide a high level of throughput and IOPS that can also be integrated with Microsoft Active Directory.

Which is the MOST suitable service that you should use to achieve this requirement?

- AWS Storage Gateway – File Gateway
- Amazon EBS Provisioned IOPS SSD volumes
- Amazon Elastic File System
- Amazon FSx for Windows File Server

Exactly. **Q26 is mainly testing your ability to distinguish AWS file-storage services.**

### The key clues

The question gives you:

* **Windows EC2**
* **Shared file system**
* **SMB**
* **Microsoft Active Directory**
* **High throughput + IOPS**

That combination strongly points to:

> ✅ **Amazon FSx for Windows File Server**

### 🧠 Build this mental map

| Service                  | Think                                                          |
| ------------------------ | -------------------------------------------------------------- |
| **EBS**                  | Block storage → usually attached to EC2                        |
| **EFS**                  | Shared **Linux** file system → NFS                             |
| **FSx for Windows**      | Shared **Windows** file system → SMB + Active Directory        |
| **FSx for Lustre**       | High-performance **parallel** file system → HPC/ML             |
| **FSx for NetApp ONTAP** | Enterprise file + block storage → NFS/SMB/iSCSI                |
| **S3**                   | Object storage                                                 |
| **File Gateway**         | On-premises apps access cloud storage through a file interface |

### The most important distinction

Think:

**Windows → FSx Windows**

```text
Windows EC2
     │
     │ SMB
     ▼
FSx for Windows File Server
     │
     └── Active Directory
```

Whereas:

**Linux → EFS**

```text
Linux EC2
    │
    │ NFS
    ▼
Amazon EFS
```

And:

**High-performance parallel processing → FSx for Lustre**

```text
EC2 / HPC / ML
       │
       ▼
FSx for Lustre
       │
       └── Parallel file system
```

### One thing to be careful about

Don't memorize **"FSx = Windows."**

There are multiple FSx variants:

* **FSx for Windows File Server** → Windows/SMB/AD
* **FSx for Lustre** → HPC/ML/high-performance parallel workloads
* **FSx for NetApp ONTAP** → enterprise storage, NFS/SMB/iSCSI
* **FSx for OpenZFS** → high-performance file storage, primarily NFS

So in an exam, look at the **protocol + operating system + workload**, not just the word FSx.

For **Q26**, the giveaway is:

> **Windows + shared file system + Active Directory + high performance = FSx for Windows File Server.**
