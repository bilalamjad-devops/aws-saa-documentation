14. Question

Category: CSAA – Design Cost-Optimized Architectures

A few easily reproducible files must be stored in AWS without concerns about storage capacity. During the first month, all files will be accessed frequently, but after that period, access will become infrequent. Older files will only be accessed by developers, and no specific retrieval time requirement is defined. However, files under a specific <code>tdojo-finance</code> prefix in the Amazon S3 bucket will be used for post-processing that requires millisecond retrieval time.

Given these conditions, which of the following options would be the most cost-effective solution for the storage requirements?


- `Store the files in S3, then after a month, change the storage class of the tdojo-finance prefix to S3 One Zone-Infrequent Access (One-Zone IA), while the remaining go to Glacier using a lifecycle policy.`

- Store the files in S3, then after a month, change the storage class of the tdojo-finance prefix to S3 Standard-Infrequent Access (Standard-IA) while the remaining go to Glacier using a lifecycle policy.
- Store the files in S3, then after a month, change the storage class of the bucket to S3 Standard-Infrequent Access (Standard-IA) using a lifecycle policy.
- Store the files in S3, then after a month, change the storage class of the bucket to S3 Intelligent-Tiering using a lifecycle policy.

Yes — this question exposes exactly where you need to strengthen S3 Storage Classes. The key isn't memorizing names; it's learning to ask **3 questions: access frequency, retrieval speed, and whether data can be recreated**.

Let's build the concept from scratch.

## 1. First understand the S3 storage-class family

Think of S3 storage classes like this:

```text
                    S3 Storage
                        │
        ┌───────────────┼────────────────┐
        │               │                │
   Frequently       Infrequently       Archive
    accessed          accessed
        │               │                │
   S3 Standard     Standard-IA       Glacier classes
                    One Zone-IA
```

And there's also:

```text
S3 Intelligent-Tiering
        ↓
AWS automatically moves objects
between access tiers based on usage
```

---

# 2. S3 Standard

### Think: **"I need this data regularly."**

Characteristics:

* Frequent access
* High availability
* Multi-AZ
* Fast/millisecond access
* No retrieval delay

Example:

> Website images, active application data, frequently accessed files.

For this question:

> **First month = frequent access**

So initially:

### **S3 Standard** ✅

---

# 3. S3 Standard-IA

IA = **Infrequent Access**

Think:

> "I don't access this often, but when I do, I need it immediately."

Characteristics:

* Multi-AZ
* Millisecond access
* Cheaper storage than Standard
* Retrieval charges apply

Example:

> Backups that are rarely accessed but must be immediately available when needed.

So:

```text
Rare access
+
Immediate retrieval
+
Need multi-AZ
        ↓
   Standard-IA
```

---

# 4. S3 One Zone-IA ⭐

This is the important one for your question.

Think:

> **"Rarely accessed + immediately available + data can be recreated."**

One Zone-IA stores data in **one Availability Zone**.

Therefore it is cheaper than Standard-IA.

```text
Standard-IA
Multi-AZ
💰💰

One Zone-IA
Single AZ
💰
```

But there's a trade-off:

> If that Availability Zone is destroyed, you can lose the data.

Therefore, One Zone-IA is appropriate for:

* Easily reproducible data
* Secondary copies
* Data that can be recreated
* Infrequently accessed data

### This question literally tells you:

> **"A few easily reproducible files"**

🚨 That's the clue for **One Zone-IA**.

---

# 5. S3 Glacier

Think:

> **"I almost never need this data, and I can tolerate retrieval time."**

It's designed for archival.

For example:

```text
Old financial records
Compliance archives
Old backups
Historical data
```

You don't need millisecond access.

Therefore:

```text
Rarely accessed
+
Can tolerate retrieval time
+
Want cheap storage
        ↓
      Glacier
```

---

# 6. Glacier Deep Archive

This is the **"I almost never touch this"** storage class.

Think:

> **Long-term archive + lowest storage cost + retrieval can take longer**

Examples:

* 7-year compliance records
* Historical records
* Regulatory archives
* Old backups

If the question says:

> "Access once a year"

or

> "Long-term retention"

or

> "10-year archive"

Think:

### **Glacier Deep Archive**

---

# 7. Intelligent-Tiering

This one is different.

Think:

> **"I don't know how often this data will be accessed."**

AWS automatically moves objects between access tiers based on changing access patterns.

For example:

```text
Month 1
Frequently accessed
        ↓
Frequent tier

Month 2
Nobody accesses it
        ↓
Infrequent tier

Later
Still no access
        ↓
Archive tier
```

Use Intelligent-Tiering when:

> **Access patterns are unpredictable or unknown.**

But your question explicitly tells you the pattern:

```text
First month
    ↓
Frequently accessed

After month 1
    ↓
Infrequent

tdojo-finance
    ↓
Still needs millisecond retrieval
```

So you already know what to do.

No need for Intelligent-Tiering.

---

# Now let's solve Question 14

The question gives us **two different types of files**.

### Group 1 — `tdojo-finance`

Requirements:

* First month: frequently accessed
* After month: infrequent
* Must have **millisecond retrieval**
* Easily reproducible

Therefore:

```text
First month
     ↓
S3 Standard
     ↓
After 1 month
     ↓
S3 One Zone-IA
```

Why One Zone-IA?

Because:

> Infrequent + millisecond retrieval + reproducible data.

---

### Group 2 — Everything else

Requirements:

* First month: frequently accessed
* After month: infrequent
* No specific retrieval-time requirement
* Easily reproducible

Therefore:

```text
First month
     ↓
S3 Standard
     ↓
After 1 month
     ↓
S3 Glacier
```

Because they don't require immediate retrieval.

---

# The entire architecture

```text
                     S3 Standard
                   First 30 days
                         │
                 Lifecycle Policy
                         │
             ┌───────────┴───────────┐
             │                       │
      tdojo-finance              Everything else
             │                       │
             ↓                       ↓
      S3 One Zone-IA             S3 Glacier
             │                       │
       Millisecond               Archive
        retrieval              retrieval okay
```

That's why the first answer wins.

---

# 🚨 The biggest clue in this question

When you see:

### "easily reproducible"

Think:

> **One Zone-IA**

Because you're accepting the risk of storing it in one AZ because you can recreate it.

When you see:

### "millisecond retrieval"

Think:

> **Standard / Standard-IA / One Zone-IA**

NOT Glacier.

When you see:

### "retrieval time doesn't matter / can wait"

Think:

> **Glacier**

When you see:

### "unknown or unpredictable access pattern"

Think:

> **Intelligent-Tiering**

# Your S3 Storage Class Cheat Sheet

| Storage class                     | Access           | Retrieval         | AZs      | Main use                             |
| --------------------------------- | ---------------- | ----------------- | -------- | ------------------------------------ |
| **S3 Standard**                   | Frequent         | Milliseconds      | Multiple | Active data                          |
| **S3 Standard-IA**                | Infrequent       | Milliseconds      | Multiple | Important infrequently accessed data |
| **S3 One Zone-IA**                | Infrequent       | Milliseconds      | **One**  | Reproducible/non-critical data       |
| **S3 Intelligent-Tiering**        | Unknown/changing | Automatic tiering | Multiple | Unpredictable access                 |
| **S3 Glacier Instant Retrieval**  | Rare             | **Milliseconds**  | Multiple | Archive + immediate retrieval        |
| **S3 Glacier Flexible Retrieval** | Rare             | Minutes–hours     | Multiple | Archive where retrieval can wait     |
| **S3 Glacier Deep Archive**       | Very rare        | Hours             | Multiple | Long-term archival                   |

### One very important correction to your mental model

Don't memorize:

> "Glacier = slow."

That's **too broad**.

There are different Glacier classes:

**Glacier Instant Retrieval** → milliseconds
**Glacier Flexible Retrieval** → minutes to hours
**Glacier Deep Archive** → hours

So always look at the **specific Glacier class**.

---

## 🧠 SAA decision tree

When you get an S3 storage question, ask these in order:

**1. Frequently accessed?**

→ **S3 Standard**

**2. Infrequently accessed but immediate/millisecond retrieval?**

→ **Standard-IA**

**3. Same as above, but data is reproducible and single-AZ is acceptable?**

→ **One Zone-IA**

**4. Access pattern unknown/unpredictable?**

→ **Intelligent-Tiering**

**5. Archive but millisecond retrieval required?**

→ **Glacier Instant Retrieval**

**6. Archive and can wait minutes/hours?**

→ **Glacier Flexible Retrieval**

**7. Very long-term archive and rarely accessed?**

→ **Glacier Deep Archive**

That decision tree is much more useful for SAA than simply memorizing the names.
