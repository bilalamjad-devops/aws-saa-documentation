20. Question

Category: CSAA – Design Cost-Optimized Architectures

The media company that you are working for has a video transcoding application running on Amazon EC2. Each EC2 instance polls a queue to find out which video should be transcoded, and then runs a transcoding process. If this process is interrupted, the video will be transcoded by another instance based on the queuing system. This application has a large backlog of videos which need to be transcoded. Your manager would like to reduce this backlog by adding more EC2 instances, however, these instances are only needed until the backlog is reduced.

In this scenario, which type of Amazon EC2 instance is the most cost-effective type to use?

- `Spot instances`
- Dedicated instances
- Reserved instances
- On-demand instances

Exactly — **Q20 is a classic Spot Instance question.** The key is not simply "temporary workload"; there is another very important clue.

## What is the question really saying?

The company has:

* A **large backlog** of videos
* EC2 instances process videos from a queue
* More instances are needed **temporarily**
* Once the backlog is gone, the extra instances can be terminated
* If an instance suddenly disappears, **another instance can process the same video**

That last point is the biggest clue.

### Architecture

```text
              Video Queue
                  │
       ┌──────────┼──────────┐
       ↓          ↓          ↓
    Spot EC2   Spot EC2   Spot EC2
       │          │          │
       ↓          ↓          ↓
   Transcode   Transcode   Transcode

          ↑
          │
   If one is interrupted
          │
          ↓
   Another instance
   processes the job
```

Because the workload is **fault-tolerant**, Spot Instances are ideal.

---

# Why Spot? ⭐

Spot Instances use AWS's **spare EC2 capacity** at a substantial discount compared with On-Demand.

The trade-off is:

> **AWS can interrupt a Spot Instance when it needs the capacity back.**

For a workload like this, that's acceptable because:

```text
Spot instance interrupted
        ↓
Video remains/reappears in queue
        ↓
Another worker picks it up
        ↓
Video gets transcoded
```

So you're trading **availability of an individual instance** for **much lower cost**.

---

# The most important SAA pattern

Whenever you see:

> "The workload can tolerate interruption."

Think:

### **Spot Instance** ✅

Examples:

* Batch processing
* Video transcoding
* Image processing
* Big data processing
* Background jobs
* CI/CD build workers
* Stateless workers
* Queue-based workloads

---

# Compare the four options

| EC2 pricing option | Think                            | Q20?                    |
| ------------------ | -------------------------------- | ----------------------- |
| **On-Demand**      | Flexible, no long commitment     | Possible, but expensive |
| **Reserved**       | Steady workload for long period  | ❌                       |
| **Spot** ⭐         | Interruptible/flexible workloads | ✅                       |
| **Dedicated**      | Dedicated physical hardware      | ❌                       |

### Reserved Instance

Good when:

> "We know we'll need these instances continuously for 1–3 years."

But here:

> "Only needed until backlog is reduced."

So RI doesn't make sense.

### Dedicated Instance

Used when you have specific **physical isolation/compliance/licensing** requirements.

Nothing like that exists here.

### On-Demand

Would work technically, but you're paying more when **Spot can safely handle the workload**.

---

# 🧠 One sentence to memorize

> **If a workload is temporary AND can tolerate interruption → Spot Instances.**

And Q20 gives you both clues:

**Temporary backlog + queue can recover interrupted work = Spot.** ✅
