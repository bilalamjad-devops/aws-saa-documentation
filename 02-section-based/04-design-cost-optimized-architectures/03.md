3. Question

Category: CSAA – Design Cost-Optimized Architectures

A solutions architect is designing a secure, cost-effective, and highly available storage solution for a company’s data. One of the requirements is to ensure that the previous version of a file is preserved and can be retrieved if a modified version is uploaded. Additionally, the company must comply with strict regulatory requirements that mandate data retention in an immutable state for at least 3 years before being moved to an archive. Once archived, the data will only be accessed once a year.

How should the solutions architect build the solution?

- Create a One-Zone-IA bucket with object-level versioning enabled and configure a lifecycle rule that transfers files to Amazon S3 Glacier Deep Archive after 3 years.
- Create an Amazon S3 Standard bucket with object-level versioning enabled and configure a lifecycle rule that transfers files to S3 Glacier Deep Archive after 3 years.
- Create an Amazon S3 Standard bucket and enable S3 Object Lock in governance mode.
- `Create an Amazon S3 Standard bucket, enable object-level versioning, and then enable S3 Object Lock in compliance mode. After that, configure a lifecycle rule to move the files to S3 Glacier Deep Archive after 3 years.`

Yes, this is an important one because it combines **3 S3 concepts**: Versioning, Object Lock, and Lifecycle.

## First: What is the question asking?

The company has **three requirements**:

### Requirement 1 — Keep previous versions

Suppose:

```text
report.pdf → Version 1
       ↓
user uploads modified report.pdf
       ↓
report.pdf → Version 2
```

They still need to retrieve **Version 1**.

➡️ **S3 Versioning**

---

### Requirement 2 — Nobody can delete/modify it for 3 years

This is stronger than just Versioning.

They have a **regulatory requirement** saying:

> "The data must remain immutable for 3 years."

Immutable means:

> **Cannot be changed or deleted.**

➡️ **S3 Object Lock**

And because this is a strict regulatory requirement:

➡️ **Compliance mode**

---

### Requirement 3 — After 3 years, archive it cheaply

After 3 years:

```text
S3 Standard
     ↓
3 years
     ↓
S3 Glacier Deep Archive
     ↓
Access ~ once per year
```

➡️ **S3 Glacier Deep Archive**

This is ideal for very long-term archival where data is accessed rarely.

---

# Therefore the answer is:

**S3 Standard + Versioning + Object Lock Compliance Mode + Lifecycle → Glacier Deep Archive**

The complete architecture:

```text
                Upload
                  ↓
          ┌───────────────┐
          │  S3 Standard  │
          │ + Versioning  │
          │ + Object Lock │
          │ Compliance    │
          └───────┬───────┘
                  │
             3 years
                  ↓
        ┌───────────────────┐
        │ Glacier Deep      │
        │ Archive           │
        └───────────────────┘
```

---

## 🧠 The important difference: Versioning vs Object Lock

This is the part I want you to remember for the exam.

### Versioning

Protects **previous versions**.

```text
file.txt
 ├── Version 1
 ├── Version 2
 └── Version 3
```

If somebody uploads a new version, the old version remains available.

But **Versioning alone does NOT mean immutable**.

---

### Object Lock

Protects against **deletion/overwriting**.

It provides a WORM model:

> **Write Once, Read Many**

And there are two important modes:

| Mode           | Can authorized users bypass/remove protection?    |
| -------------- | ------------------------------------------------- |
| **Governance** | Yes, users with special permissions can bypass    |
| **Compliance** | **No** — even root cannot bypass during retention |

So when you see:

> **Regulatory compliance + immutable + cannot delete/modify**

🚨 Think:

### **S3 Object Lock → Compliance Mode**

---

## Why Option 2 is tempting but wrong

> S3 Standard + Versioning + Lifecycle → Glacier Deep Archive

It handles:

✅ previous versions
✅ cheap archival

But doesn't guarantee:

❌ immutable for 3 years

That's why **Object Lock Compliance Mode** is required.

---

## Why Governance Mode is wrong

Governance is less strict.

Some users with appropriate permissions can bypass the protection.

For a regulatory requirement, AWS expects the stronger:

> **Compliance Mode**

---

## Why One Zone-IA is wrong

One Zone-IA stores data in **one Availability Zone**.

It's designed for data that can tolerate the loss of that AZ and is cheaper than Standard.

For critical regulatory records, you don't want to introduce unnecessary availability risk.

---

# 🎯 SAA Exam Pattern

Memorize this combination:

**Previous versions → Versioning**

**Immutable/WORM → Object Lock**

**Regulatory/legal retention → Object Lock Compliance Mode**

**Old data → Lifecycle**

**Very cheap, rarely accessed archive → Glacier Deep Archive**

So if you see a question containing:

> **"previous versions + regulatory compliance + cannot delete/modify + years + rarely accessed"**

your brain should immediately go:

> **S3 Versioning + Object Lock Compliance + Lifecycle → Glacier Deep Archive**.
