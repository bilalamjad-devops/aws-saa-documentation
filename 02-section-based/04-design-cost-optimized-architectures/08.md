8. Question

Category: CSAA – Design Cost-Optimized Architectures

A company has 10 TB of infrequently accessed financial data files that would need to be stored in AWS. These data would be accessed infrequently during specific weeks when they are retrieved for auditing purposes. The retrieval time is not strict as long as it does not exceed 24 hours.

Which of the following would be a secure, durable, and cost-effective solution for this scenario?

- Upload the data to S3 then use a lifecycle policy to transfer data to S3 One Zone-IA.
- Upload the data to S3 and set a lifecycle policy to transition data to Glacier after 0 days.
- Upload the data to S3 then use a lifecycle policy to transfer data to S3-IA.
- Upload the data to Amazon FSx for Windows File Server using the Server Message Block (SMB) protocol.

Yes — this question is mainly testing **choosing the right S3 storage class based on access frequency, retrieval time, durability, and cost**.

Let's first translate the question into simple language.

## What is the question saying?

The company has:

> **10 TB of financial files**

These files are:

* accessed **very rarely**
* only needed during certain **audit weeks**
* retrieval does **not need to be immediate**
* they are okay waiting **up to 24 hours**
* they want a **secure, durable, cost-effective** solution

So essentially:

> **"We have a huge amount of data that we almost never use. We just need to keep it safely for audits, and we're okay waiting several hours when we need it. Where should we store it?"**

That screams:

### 🧠 **S3 Glacier**

---

# Why Glacier?

Think about the relationship:

```text
Frequently accessed
       ↓
   S3 Standard

Infrequently accessed
       ↓
   S3 Standard-IA

Rarely accessed + willing to wait
       ↓
   S3 Glacier

Very rarely accessed + long-term archive
       ↓
   S3 Glacier Deep Archive
```

Here:

**10 TB + rarely accessed + up to 24 hours retrieval**

➡️ **Glacier**

---

# Why does the question mention "24 hours"?

This is the biggest clue.

Different storage classes have different retrieval characteristics.

The question essentially says:

> "We don't care if retrieving the data takes several hours."

That makes an archival storage class appropriate.

For the **classic S3 Glacier retrieval model used by older SAA questions**, Bulk Retrieval can take several hours and is designed for large amounts of data at low retrieval cost.

So when you see:

> **Large amount + rarely accessed + retrieval can take hours**

think:

**Glacier**

---

# Why lifecycle policy?

The company doesn't necessarily want to manually move the data.

Instead:

```text
Upload
  ↓
S3
  ↓
Lifecycle Rule
  ↓
Glacier
```

And the question says **after 0 days**.

That means:

> Move the objects to Glacier essentially immediately after they're uploaded.

For example:

```text
Day 0
  ↓
Upload financial data to S3
  ↓
Lifecycle rule
  ↓
Glacier
```

So the correct answer is:

> **Upload the data to S3 and set a lifecycle policy to transition the data to Glacier after 0 days.**

---

# Why not S3 Standard-IA?

S3 Standard-IA is designed for:

> **Data that is accessed less frequently, but when accessed needs relatively quick access.**

For example:

```text
Access occasionally
      ↓
Need it relatively quickly
      ↓
S3 Standard-IA
```

But this question says:

> **"We don't care if retrieval takes up to 24 hours."**

That tells you:

> **We can use cheaper archival storage.**

So Glacier is a better fit.

---

# Why not One Zone-IA?

One Zone-IA stores data in **one Availability Zone**.

Think:

```text
S3 Standard-IA
AZ-A ─── AZ-B ─── AZ-C
       multiple AZs

One Zone-IA
AZ-A only
```

One Zone-IA is cheaper, but it is designed for data that can tolerate the loss of an Availability Zone.

For important **financial records**, the question emphasizes secure and durable storage, so Glacier is the better choice.

---

# Why not FSx?

FSx for Windows File Server is:

> **File storage**

It's useful when applications need things like:

```text
SMB
Windows file shares
File system semantics
```

But the requirement is basically:

> **Archive 10 TB of rarely accessed data cheaply.**

You don't need a file system.

Use **S3 Glacier**.

---

# ⭐ The SAA thought process

When you see an S3 storage question, ask yourself **three things**:

### 1. How often is the data accessed?

```text
Frequently → Standard
Infrequently → IA
Rarely → Glacier
```

### 2. How quickly must it be retrieved?

```text
Immediately
    ↓
Standard / IA

Can wait minutes-hours
    ↓
Glacier options

Can wait much longer
    ↓
Deep Archive
```

### 3. How much does cost matter?

If the question says:

> **"10 TB, rarely accessed, retrieval isn't urgent, most cost-effective"**

Your brain should immediately go:

**S3 Glacier / archival storage.**

---

## One important modern-AWS caveat

Your question is from a **Tutorials Dojo-style exam bank**, and its explanation uses the older terminology **"S3 Glacier"** and the older retrieval-time characteristics.

Today, AWS has multiple Glacier storage classes under S3, including **S3 Glacier Flexible Retrieval** and **S3 Glacier Deep Archive**. So for your SAA preparation, follow the **storage-class clues in the question**, while remembering that AWS's current product names differ somewhat from older exam material.

For **this exact question**, the intended answer is:

> ✅ **S3 → Lifecycle Policy → Glacier after 0 days**

### The one-line memory trick:

**Rarely accessed + huge data + okay waiting hours = Glacier.**
