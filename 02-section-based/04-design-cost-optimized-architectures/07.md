7. Question

Category: CSAA – Design Cost-Optimized Architectures

A company is hosting an application on EC2 instances that regularly pushes and fetches data in Amazon S3. Due to a change in compliance, the instances need to be moved on a private subnet. Along with this change, the company wants to lower the data transfer costs by configuring its AWS resources.

How can this be accomplished in the MOST cost-efficient manner?

- `Create an Amazon S3 gateway endpoint to enable a connection between the instances and Amazon S3.`
- Set up an AWS Transit Gateway to access Amazon S3.
- Set up a NAT Gateway in the public subnet to connect to Amazon S3.
- Create an Amazon S3 interface endpoint to enable a connection between the instances and Amazon S3.

Exactly — this is a **classic SAA question**, and it connects directly to the VPC endpoint concepts we discussed.

## What is the question asking?

The company has:

```text
EC2 instances
      ↓
   S3
```

The EC2 instances currently need to **upload and download data from S3**.

But there are two new requirements:

1. EC2 must move to a **private subnet**.
2. They want to **reduce data-transfer/networking costs**.

So we need a private and cheap path:

```text
Private EC2
     │
     ▼
S3 Gateway Endpoint
     │
     ▼
Amazon S3
```

✅ **Answer: S3 Gateway VPC Endpoint**

---

# Why Gateway Endpoint?

A **Gateway Endpoint** provides private access from your VPC to:

* **Amazon S3**
* **Amazon DynamoDB**

without requiring:

* Internet Gateway
* NAT Gateway
* public IP
* Internet connection

And the biggest clue in this question is:

> **MOST cost-efficient**

Gateway endpoints have **no additional endpoint charge**.

So:

```text
Private EC2
    │
    ▼
Gateway Endpoint
    │
    ▼
S3
```

Very cheap and very simple.

---

# Compare the options

### 1. S3 Gateway Endpoint ✅

```text
Private EC2
     ↓
Gateway Endpoint
     ↓
S3
```

✅ Private
✅ No NAT required
✅ No Internet Gateway required
✅ **No additional endpoint charge**
✅ Best choice for S3 from a VPC

---

### 2. NAT Gateway ❌

You could technically do:

```text
Private EC2
     ↓
NAT Gateway
     ↓
Internet Gateway
     ↓
S3
```

It works, but you're paying for the NAT Gateway.

NAT Gateway has:

* hourly charges
* data processing charges

So if the requirement says **cost-efficient access to S3**, don't choose NAT when a Gateway Endpoint is available.

---

### 3. S3 Interface Endpoint ❌

This also provides private access.

But:

```text
Gateway Endpoint → No additional endpoint charge
Interface Endpoint → Hourly + data processing charges
```

Therefore, if the question specifically asks:

> **MOST cost-efficient**

➡️ **Gateway Endpoint**

### When might Interface Endpoint be useful?

Interface endpoints are useful when you need things such as:

* access to S3 from **on-premises**
* access from another network through PrivateLink-related connectivity
* private DNS/interface-based access

But for the straightforward:

> **EC2 in VPC → S3**

use the **Gateway Endpoint** when cost is the deciding factor.

---

### 4. Transit Gateway ❌

Transit Gateway is primarily:

> **VPC-to-VPC / VPC-to-on-premises connectivity**

Think:

```text
VPC A ─┐
VPC B ─┼── Transit Gateway
VPC C ─┘
          │
       On-premises
```

It isn't the normal tool for:

```text
EC2 → S3
```

---

# ⭐ Memorize this for SAA

This is one of those rules worth memorizing:

> **S3/DynamoDB + private subnet + cheapest private access = Gateway VPC Endpoint**

### The two endpoint types:

|                         | Gateway Endpoint   | Interface Endpoint  |
| ----------------------- | ------------------ | ------------------- |
| S3                      | ✅                  | ✅                   |
| DynamoDB                | ✅                  | ❌                   |
| Private access          | ✅                  | ✅                   |
| Endpoint hourly charge  | **No**             | **Yes**             |
| Data processing charge  | No endpoint charge | **Yes**             |
| Uses route table        | **Yes**            | ENI/private IP      |
| Best for basic EC2 → S3 | ⭐ **Yes**          | Usually unnecessary |

### Your exam shortcut

If you see:

**"EC2 private subnet → S3"**

first think:

> **S3 Gateway Endpoint**

Then look at the wording:

* **Most cost-effective** → Gateway Endpoint
* **Need private IP/ENI or on-premises access to S3** → Interface Endpoint may be relevant
* **Need general Internet access from private subnet** → NAT Gateway

This question is basically testing whether you can distinguish **Gateway Endpoint vs NAT Gateway vs Interface Endpoint**.
