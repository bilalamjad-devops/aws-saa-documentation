10. Question

Category: CSAA – Design Cost-Optimized Architectures

A wellness company is currently working on a wearable device that monitors key health metrics such as heart rate, sleep, and steps per day. The device is designed to send data to an Amazon S3 bucket for storage and analysis. On a daily basis, the device produces 1 MB of data. In order to quickly process and summarize this data, the company requires 512 MB of memory and must complete the task within a maximum of 10 seconds.

Which solution can fulfill these requirements in the MOST cost-effective manner?

- Store the data in Amazon Redshift and process it with AWS Lambda.
- `Use AWS Lambda with a Python library for processing.`
- Create an AWS Glue PySpark job to process the data.
- Use Amazon Data Firehose to send the data from the device to Amazon S3. Process the data on an EC2 instance with at least 512 MB of memory.


Yes — this question is testing **"small workload + short execution time + minimum infrastructure = Lambda."**

## What is the question asking?

The wearable device generates only:

> **1 MB of data per day**

And the company needs to:

* process/summarize the data
* use **512 MB memory**
* finish within **10 seconds**
* do it **cost-effectively**

So the real question is:

> **"We have a tiny amount of data and a very short processing job. What is the cheapest way to run this processing without managing servers?"**

➡️ **AWS Lambda** ✅

---

## Why Lambda?

Lambda is **serverless**.

You don't have to create:

* EC2 instance
* operating system
* patches
* scaling configuration
* server monitoring

You simply give Lambda:

```text
Memory: 512 MB
Code: Python
Trigger: event
```

Then:

```text
Wearable
   ↓
S3
   ↓
Lambda
   ↓
Process 1 MB
   ↓
Summary
```

And you're charged based mainly on:

> **requests + execution duration + memory allocated**

For a function that runs for only a few seconds and handles 1 MB/day, that's extremely small.

---

# Why Python?

The question specifically says:

> **"Use AWS Lambda with a Python library for processing."**

Python has many libraries useful for:

* data processing
* calculations
* parsing
* summarization

So you can write something like:

```text
S3 object
   ↓
Lambda triggered
   ↓
Python reads data
   ↓
Calculate:
Heart rate
Sleep
Steps
   ↓
Store summary
```

No EC2 server required.

---

# Why NOT Glue?

AWS Glue is excellent for:

> **Large-scale ETL / data engineering**

For example:

```text
TBs of data
   ↓
Glue / PySpark
   ↓
Transform
   ↓
Data warehouse/data lake
```

But here:

> **1 MB/day**

Using Glue is overkill.

It's like hiring a moving truck to move one small box. 😄

---

# Why NOT EC2?

EC2 could absolutely process 1 MB.

But you would need to manage:

```text
EC2
├── Instance
├── OS
├── Patching
├── Security
├── Monitoring
├── Scaling
└── Cost while running
```

Lambda:

```text
Lambda
└── Just upload your code
```

For a tiny, short-lived workload:

➡️ **Lambda is more cost-effective and has less operational overhead.**

---

# Why NOT Redshift?

Redshift is a **data warehouse**.

Think:

```text
Huge analytical dataset
        ↓
    Redshift
        ↓
Complex analytics
```

This company has:

> **1 MB/day**

Redshift would be massive overkill.

---

# Why NOT Firehose + EC2?

Firehose is useful for:

> **Streaming data → delivery to S3/Redshift/etc.**

For example:

```text
Thousands of events
      ↓
Kinesis Data Firehose
      ↓
S3
```

But here:

> **Only 1 MB per day**

You don't need a streaming-delivery architecture for such a tiny workload.

And then adding EC2 just to process it introduces unnecessary infrastructure.

---

# 🧠 SAA exam pattern

This is the important part to memorize:

| Scenario                     | Think                     |
| ---------------------------- | ------------------------- |
| Tiny data + short processing | **Lambda**                |
| Event-driven processing      | **Lambda**                |
| No server management         | **Lambda**                |
| Large ETL workload           | **Glue**                  |
| Large-scale data warehouse   | **Redshift**              |
| Long-running processing      | **EC2**                   |
| Streaming data delivery      | **Kinesis Data Firehose** |

### One-line memory trick:

> **Small + short + event-driven + serverless → Lambda.**

So Question 10 is essentially asking:

**"Do I really need a server or big data service for 1 MB/day and 10 seconds?"**

No.

➡️ **AWS Lambda + Python** ✅
