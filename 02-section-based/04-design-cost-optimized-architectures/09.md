9. Question

Category: CSAA – Design Cost-Optimized Architectures

A company has an e-commerce application that saves the transaction logs to an S3 bucket. You are instructed by the CTO to configure the application to keep the transaction logs for one month for troubleshooting purposes, and then afterward, purge the logs.

What should you do to accomplish this requirement?

- `Configure the lifecycle configuration rules on the Amazon S3 bucket to purge the transaction logs after a month`
- Create a new IAM policy for the Amazon S3 bucket that automatically deletes the logs after a month
- Add a new bucket policy on the Amazon S3 bucket.
- Enable CORS on the Amazon S3 bucket which will enable the automatic monthly deletion of data

This one is **very easy once you distinguish S3 Lifecycle from IAM policies and bucket policies**.

## What is the question asking?

The application creates transaction logs:

```text
E-commerce application
        ↓
    S3 bucket
        ↓
Keep logs for 30 days
        ↓
Delete automatically
```

The requirement is:

> **Keep logs for one month, then automatically delete them.**

So you need an **automatic time-based action on S3 objects**.

➡️ **S3 Lifecycle Rule**

---

## Why Lifecycle?

S3 Lifecycle rules can perform two major types of actions:

### 1. Transition

Move objects to another storage class.

```text
S3 Standard
    ↓ 30 days
S3 Standard-IA
    ↓ 90 days
Glacier
```

### 2. Expiration

Delete objects after a specified period.

```text
S3
 ↓
30 days
 ↓
DELETE
```

This question is asking for **Expiration**.

So:

> ✅ Configure an S3 Lifecycle rule to expire/delete the transaction logs after one month.

---

# Don't confuse these 4 things

### S3 Lifecycle

**"What should happen to objects after X days?"**

Examples:

* Move to IA
* Move to Glacier
* Delete after 30 days

➡️ **Time-based object management**

---

### IAM Policy

**"What is this user/role allowed to do?"**

Example:

```text
User → Can GetObject
User → Can PutObject
User → Cannot DeleteObject
```

➡️ **Permissions**

It doesn't mean:

> "Delete these files automatically after 30 days."

---

### Bucket Policy

**"Who can access this bucket and what can they do?"**

Example:

```text
Allow Account B
        ↓
GetObject
        ↓
My S3 bucket
```

➡️ **Resource-based access control**

---

### CORS

**"Can a web application from another origin make requests to my S3 resources?"**

Example:

```text
website.com
     ↓
JavaScript request
     ↓
S3 bucket
```

➡️ **Cross-origin browser access**

It has nothing to do with automatic deletion.

---

# 🧠 Quick exam rule

Whenever you see:

> **"After X days/months, automatically move/delete S3 objects"**

Immediately think:

### **S3 Lifecycle**

Then determine the action:

| Requirement          | Lifecycle action                  |
| -------------------- | --------------------------------- |
| Move to IA           | **Transition**                    |
| Move to Glacier      | **Transition**                    |
| Delete after 30 days | **Expiration**                    |
| Delete old versions  | **Noncurrent version expiration** |

So for Question 9:

**Keep transaction logs for 1 month → automatically purge them**

➡️ **S3 Lifecycle → Expiration after 30 days** ✅
