29. Question

Category: CSAA – Design Cost-Optimized Architectures

A company plans to use a cloud storage service to temporarily store its log files. The number of files to be stored is still unknown, but it only needs to be kept for 12 hours.

Which of the following is the most cost-effective storage class to use in this scenario?

- Amazon S3 Standard-IA
- Amazon S3 Glacier Deep Archive
- `Amazon S3 Standard`
- Amazon S3 One Zone-IA

<img width="913" height="785" alt="amazon-s3-minimum-duration-charge-chart" src="https://github.com/user-attachments/assets/d8b11b1d-6d57-406b-906a-439709a71af6" />

Yes — this is another **important S3 storage-class question**, and it connects directly to the weakness you identified in Q14.

The trick here is **not simply “which class has the cheapest GB/month?”**. You must consider **minimum storage duration**.

## What is the question really asking?

The company says:

> "Store log files temporarily for only **12 hours**."

So:

```text
Upload logs
    ↓
Keep for 12 hours
    ↓
Delete
```

The question asks: **Which S3 storage class is economical when objects exist for only 12 hours?**

### Answer: S3 Standard

Why?

**S3 Standard has no minimum storage duration.**

So you're not forced to pay for 30, 90, or 180 days when you delete the objects after 12 hours.

---

# 🔥 The S3 concept you need to memorize

Don't just memorize which class is "cheapest."

Think about **three things**:

1. **How frequently is the data accessed?**
2. **How quickly must it be retrieved?**
3. **How long will the object remain stored?**

That third one is extremely important.

---

## S3 Standard

Think:

> **Short-lived OR frequently accessed data**

Examples:

* temporary logs
* website assets
* active application data
* data accessed frequently
* objects that might be deleted quickly

### Minimum duration

**No minimum storage duration.**

Therefore:

> **12 hours → S3 Standard**

---

## S3 Standard-IA

IA = **Infrequent Access**

Think:

> **Data is important and needs quick access, but isn't accessed often.**

Examples:

* monthly reports
* backups accessed occasionally
* older application data

But there is a **minimum storage duration**.

So if you do:

```text
Store → 12 hours → Delete
```

you're wasting money because the storage class has a minimum billing duration.

Therefore:

❌ Don't use Standard-IA for temporary 12-hour data.

---

## S3 One Zone-IA

Think:

> **Infrequently accessed + data can be recreated**

It's cheaper than Standard-IA because data is stored in **one Availability Zone** rather than multiple AZs.

Good example:

> Temporary/re-creatable data that doesn't justify multi-AZ storage.

But again:

**minimum storage duration applies.**

So:

```text
12 hours
↓
Delete
```

❌ Bad choice.

This connects directly to your **Q14**.

In Q14, the files were:

* easily reproducible
* accessed infrequently after one month
* `tdojo-finance` needed millisecond retrieval

Therefore One Zone-IA could make sense **after the first month**.

---

# S3 Glacier classes

Think:

> **Archive**

They're designed for data you intend to retain for a long time.

For example:

```text
Compliance records
       ↓
5 years
       ↓
Occasional retrieval
```

Not:

```text
Logs
 ↓
12 hours
 ↓
Delete
```

😂

That's why Glacier Deep Archive is completely inappropriate for Q29.

---

# Your S3 mental map

This is what I'd memorize for SAA:

| Storage class                     | Think                             | Typical use                                    |
| --------------------------------- | --------------------------------- | ---------------------------------------------- |
| **S3 Standard**                   | Frequently accessed / short-lived | Active data, temporary logs                    |
| **S3 Intelligent-Tiering**        | Access pattern unknown/changing   | Data whose access pattern isn't predictable    |
| **S3 Standard-IA**                | Infrequent + quick access         | Backups, older data                            |
| **S3 One Zone-IA**                | Infrequent + reproducible         | Re-creatable data                              |
| **S3 Glacier Instant Retrieval**  | Archive + millisecond retrieval   | Rarely accessed archive needing instant access |
| **S3 Glacier Flexible Retrieval** | Archive + minutes/hours retrieval | Backups, archives                              |
| **S3 Glacier Deep Archive**       | Very long-term archive            | Compliance, 7–10+ year archives                |

---

# 🚨 Exam trap: "cheapest storage" ≠ "cheapest solution"

This is the exact lesson from Q29.

Suppose:

**Deep Archive = cheapest per GB/month**

You might think:

> "Logs → Deep Archive because it's cheapest."

Wrong.

If the logs live for only **12 hours**, minimum-duration charges can make Deep Archive much more expensive than Standard.

So always ask:

> **How long will these objects actually stay there?**

---

## Quick decision tree

When you see an S3 question, think:

```text
How long will data exist?
        │
        ├── Hours / days
        │       ↓
        │   S3 Standard
        │
        ├── Months/years + infrequent
        │       ↓
        │   Standard-IA / One Zone-IA
        │
        └── Long-term archive
                ↓
          Glacier classes
```

Then ask:

```text
Does it need immediate retrieval?
        │
        ├── Yes → Glacier Instant Retrieval
        │
        └── No
             ↓
       Flexible Retrieval
             ↓
       Deep Archive
```

### One correction to your study notes

The **exact minimum-duration rules and Glacier terminology have changed over time**, so for the exam, use the current AWS documentation if a question depends on a specific number of days. The conceptual rule remains solid:

> **Short-lived objects → avoid storage classes with minimum-duration charges.**

For Q29, the important answer is simply:

**12 hours → S3 Standard.**
