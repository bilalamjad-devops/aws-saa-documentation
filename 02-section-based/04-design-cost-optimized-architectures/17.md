17. Question

Category: CSAA – Design Cost-Optimized Architectures

In Amazon EC2, you can manage your instances from the moment you launch them up to their termination. You can flexibly control your computing costs by changing the EC2 instance state.

Which of the following statements is true regarding EC2 billing? (Select TWO.)


- You will be billed when your Spot instance is preparing to stop with a stopping state.
- You will not be billed for any instance usage while an instance is not in the running state.
- `You will be billed when your Reserved instance is in terminated state.`
- You will be billed when your On-Demand instance is in pending state.
- `You will be billed when your On-Demand instance is preparing to hibernate with a stopping state.`

Yes — this one is testing a **small but important EC2 billing detail**.

### The two correct answers

1. **Reserved Instance in `terminated` state → still billed**

   * A Reserved Instance is essentially a **billing commitment**, not a physical EC2 instance.
   * If you terminate the EC2 instance, your Reserved Instance commitment **does not disappear**.
   * You continue paying according to the RI term/payment option.

2. **On-Demand instance in `stopping` while hibernating → billed**

   * Normally, when an On-Demand instance is **stopped**, you don't pay for EC2 compute.
   * **Exception:** while it is preparing to hibernate, you can still incur instance usage charges.

### EC2 state quick revision

| State                        | EC2 compute billing? | Remember                                            |
| ---------------------------- | -------------------- | --------------------------------------------------- |
| `pending`                    | ❌                    | Launching/preparing                                 |
| `running`                    | ✅                    | Normal compute billing                              |
| `stopping` → normal stop     | ❌                    | No compute charge                                   |
| `stopping` → hibernation     | ✅                    | **Important exception**                             |
| `stopped`                    | ❌                    | EBS still costs money                               |
| `shutting-down`              | ❌                    | Terminating                                         |
| `terminated`                 | ❌                    | EC2 gone                                            |
| Reserved Instance commitment | ✅                    | **Can continue billing after instance termination** |

### 🔥 SAA exam trick

Don't memorize:

> **"If instance isn't running, I don't pay."**

That's **not always true**.

Instead remember:

> **Running = compute charge**
> **Stopped = no compute charge, but EBS costs remain**
> **Hibernating = special stopping-state billing**
> **Reserved Instance = commitment continues even if the instance is terminated**

Also connect this with your previous Q13:

**Terminating EC2 does NOT delete your EBS snapshots, and stopping EC2 does NOT eliminate EBS storage charges.**

So for cost questions, always ask yourself:

**"Am I paying for compute, storage, or a pricing commitment?"**

That distinction will solve a lot of these Cost-Optimized Architecture questions.
