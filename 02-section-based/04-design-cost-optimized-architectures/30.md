30. Question

Category: CSAA – Design Cost-Optimized Architectures

A media company stores approximately 250 TB of archived video and audio assets on portable storage systems in an on-premises facility. The company needs to import the archive into Amazon S3 for long-term storage, durability, and redundancy. The company currently has a 100 Mbps dedicated line connecting its head office to the Internet. The team considered using AWS Storage Gateway Volume Gateway, but determined that the 100 Mbps connection would take weeks to transfer the full dataset.

Which of the following is the FASTEST and MOST COST-EFFECTIVE way to import all this data to S3?

- `Import the archived dataset to S3 through AWS Data Transfer Terminal.`
- Establish a direct connection using AWS Direct Connect, then transfer the data over to S3.
- Use S3 Transfer Acceleration to speed up the upload.
- Upload it directly to S3


Absolutely. This question is mainly testing **AWS data transfer methods**, and the key is to recognize that **250 TB + only 100 Mbps + one-time migration** changes the answer.

## 1. What is the problem?

The company has:

* **250 TB** of data
* Data is currently on **physical/portable storage**
* Wants to move it **into S3**
* Existing Internet connection = only **100 Mbps**
* This is basically a **one-time bulk migration**
* They want **FASTEST + MOST COST-EFFECTIVE**

The problem is the **100 Mbps bottleneck**.

Think of it like this:

```text
250 TB
  │
  │ 100 Mbps Internet
  ↓
AWS S3
```

250 TB is enormous. A 100 Mbps connection would take **months**, not merely days.

So AWS gives you a way to **physically bring the data close to AWS instead of sending all 250 TB over the Internet**.

### Answer: AWS Data Transfer Terminal

---

# 2. What is Data Transfer Terminal?

Think of **Data Transfer Terminal** as:

> "Don't upload this enormous dataset from your slow office Internet. Bring your storage device to an AWS-connected physical facility and transfer the data using high-speed AWS connectivity."

Conceptually:

```text
Your portable storage
       │
       │ physically transport
       ↓
AWS Data Transfer Terminal
       │
       │ High-speed AWS network
       ↓
     Amazon S3
```

The important thing is:

**The 100 Mbps office Internet connection is no longer the bottleneck.**

That's why this is ideal for a **huge, one-time data import**.

---

# 3. Why not Direct Upload?

Option:

> Upload it directly to S3.

You would have:

```text
Portable storage
      ↓
Your office
      ↓
100 Mbps Internet
      ↓
     S3
```

The entire 250 TB has to travel through your 100 Mbps connection.

❌ Too slow.

---

# 4. Why not Direct Connect?

This is a very important distinction for your SAA exam.

### Direct Connect

Think:

> **Dedicated, private network connection between on-premises and AWS.**

For example:

```text
Company Data Center
       │
       │ Direct Connect
       │
       ↓
      AWS
```

It's excellent when you have **ongoing hybrid connectivity**.

For example:

> "Our company permanently uses AWS and needs a dedicated private connection between our data center and AWS."

That's a great Direct Connect use case.

But here:

> "I have 250 TB sitting on portable storage and I need to import it once."

Creating a dedicated network connection just for this migration is unnecessary.

❌ More setup
❌ More operational overhead
❌ Not the best choice for a one-time bulk transfer

So:

**One-time huge migration → Data Transfer Terminal**

**Long-term hybrid connectivity → Direct Connect**

---

# 5. Why not S3 Transfer Acceleration?

This one is a common exam trap.

S3 Transfer Acceleration:

```text
Your location
     ↓
AWS Edge Location
     ↓
AWS network
     ↓
S3
```

It can improve the route between your users and S3.

But your company still has:

> **100 Mbps Internet**

You cannot magically turn a 100 Mbps connection into a 10 Gbps connection just by using Transfer Acceleration.

It's like having:

```text
Small pipe → AWS Edge → S3
```

The pipe going **into the AWS Edge** is still limited.

So for **250 TB**, it doesn't solve the fundamental problem.

---

# 6. The key concept: Online vs Offline transfer

This is what I want you to remember.

### Online transfer

Data travels through a network:

```text
On-premises
    ↓
Internet / DX
    ↓
AWS
    ↓
S3
```

Examples:

* Direct S3 upload
* AWS DataSync
* Direct Connect
* S3 Transfer Acceleration

### Physical transfer

You physically move the storage/data closer to AWS:

```text
Portable storage
      ↓
Physical transportation
      ↓
AWS Data Transfer Terminal
      ↓
S3
```

For **massive one-time datasets**, physical transfer can be dramatically faster.

---

# 7. Compare the important services

This will help connect many of your previous questions:

| Service                      | Think                                                                                                  |
| ---------------------------- | ------------------------------------------------------------------------------------------------------ |
| **DataSync**                 | Move data **online** between on-premises/file systems and AWS                                          |
| **Storage Gateway**          | Give on-premises applications **AWS cloud storage/hybrid access**                                      |
| **Direct Connect**           | Dedicated/private **ongoing network connection** to AWS                                                |
| **S3 Transfer Acceleration** | Speed up **Internet uploads to S3** using AWS edge locations                                           |
| **Data Transfer Terminal**   | **Huge physical bulk data import** into AWS                                                            |
| **S3**                       | Object storage                                                                                         |
| **Snowball**                 | Historically, physical bulk data transfer device; availability depends on current AWS offerings/region |

---

# 8. Your exam shortcut 🧠

When you see:

### **"Huge amount + one-time migration + Internet too slow"**

Think:

> 🟢 **Physical data transfer solution**

In this question:

**250 TB + 100 Mbps + one-time import → Data Transfer Terminal**

---

### And compare with Q25 you just did

Q25:

> 200 TB already in S3 → need to process it → minimize transfer costs.

Answer:

**EC2 in the SAME REGION as S3**

Because you don't want:

```text
S3
 ↓
Internet / on-prem
 ↓
S3
```

Instead:

```text
S3
 ↓
EC2 (same Region)
 ↓
S3
```

Very little/no standard data-transfer charge between S3 and EC2 in the same Region.

So you're now seeing a broader pattern:

> **AWS architecture questions often ask you to identify where the data is, where it needs to go, and whether moving that data unnecessarily costs money/time.**
