22. Question

Category: CSAA – Design Cost-Optimized Architectures

An organization is currently using a tape backup solution to store its application data on-premises. Plans are in place to use a cloud storage service to preserve the backup data for up to 10 years, which may be accessed about once or twice a year.

Which of the following is the most cost-effective option to implement this solution?

- Use Amazon S3 to store the backup data and add a lifecycle rule to transition the current version to S3 Glacier Flexible Retrieval.
- Use AWS Storage Gateway to backup the data directly to Amazon S3 Glacier Flexible Retrieval.
- Use AWS Data Transfer Terminal to physically transfer the backup data into Amazon S3 Glacier Flexible Retrieval.
- `Use AWS Storage Gateway to backup the data and transition it to Amazon S3 Glacier Deep Archive.`

Yes. **Q22 is testing two concepts together:**

1. **How do you move an existing on-premises tape backup workflow to AWS?**
2. **Which S3 storage class is best for 10-year archival with access only 1–2 times/year?**

The answer is:

> ✅ **AWS Storage Gateway (Tape Gateway) → S3 Glacier Deep Archive**

### First clue: "They already use tapes"

This is the biggest clue.

AWS has **Storage Gateway – Tape Gateway**, which is specifically designed to replace physical tapes with **virtual tapes in AWS**.

Think:

```text
ON-PREMISES
Backup Application
       ↓
   Tape Gateway
       ↓
 Virtual Tape
       ↓
    AWS S3
       ↓
Glacier / Deep Archive
```

The company can continue using its existing backup software/workflow rather than redesigning everything around S3.

---

## Second clue: 10 years + only 1–2 accesses/year

This screams:

### **S3 Glacier Deep Archive** ⭐

Think of the storage classes like this:

```text
Frequently accessed
        ↓
   S3 Standard

Infrequently accessed
        ↓
   S3-IA / One Zone-IA

Archive
        ↓
Glacier Flexible Retrieval

Very long-term archive
rarely accessed
        ↓
Glacier Deep Archive ⭐
```

For **10-year retention** and **only once or twice per year retrieval**, Deep Archive is the natural cost-optimization choice.

---

## Why not Glacier Flexible Retrieval?

Flexible Retrieval is also archival storage, but it makes more sense when you need somewhat more frequent/faster retrieval.

Deep Archive is designed for things like:

* Compliance archives
* Long-term backups
* Regulatory records
* 7–10+ year retention
* Data accessed very rarely

So:

> **10 years + 1–2 accesses/year → Deep Archive**

# Important: Storage Gateway vs DataSync

This distinction is very useful for your exam.

### Storage Gateway

Think:

> **"I want AWS to work with my existing on-premises storage/backup environment."**

Especially:

**Tape backup → Tape Gateway**

### DataSync

Think:

> **"I need to transfer/migrate lots of files between on-premises and AWS."**

For example:

```text
On-premises NAS
      ↓
   DataSync
      ↓
      S3
```

So Q4 from earlier:

> Historical records → move from on-premises to AWS

→ **DataSync**

Q22:

> Existing tape backup system → cloud backup replacement

→ **Tape Gateway**

That's an important distinction.

> **Tape Gateway + Glacier Deep Archive** ✅

And remember:

**DataSync = data migration/transfer**

### 🟢 DataSync = MOVE/MIGRATE data

Typical clues:

* Transfer large amounts of data
* On-premises → AWS
* File migration
* Data replication
* One-time or scheduled transfers

**Shortcut:**
👉 **DataSync = MOVE data**

---

### 🔵 Storage Gateway = CONNECT on-premises to AWS storage

Think:

> **"I want my existing on-premises applications/storage to use AWS storage without completely changing my environment."**

There are three important types:

| Storage Gateway    | Think                                           |
| ------------------ | ----------------------------------------------- |
| **File Gateway**   | On-prem apps → S3 files                         |
| **Volume Gateway** | On-prem applications → AWS-backed block storage |
| **Tape Gateway**   | Replace physical tapes → virtual tapes in AWS   |

For your Q22:

```text
Existing Tape Backup
       ↓
   Tape Gateway
       ↓
Virtual Tape in AWS
       ↓
S3 / Glacier Deep Archive
```

**Shortcut:**
👉 **Storage Gateway = hybrid storage / backup integration**

---

### ⭐ The distinction I want you to remember

**"Move my existing data to AWS"**

→ **DataSync**

**"Keep my existing on-premises environment but use AWS storage"**

→ **Storage Gateway**

**"Replace my physical tape backup with cloud virtual tapes"**

→ **Tape Gateway**

So your statement:

> **DataSync = migration data from on-premises to AWS** ✅

> **Storage Gateway = backup on cloud** 🟡 **Mostly right, but broader:** it's really **hybrid storage integration**, and Tape Gateway is specifically the backup/tape use case.
