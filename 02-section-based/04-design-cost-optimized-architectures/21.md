21. Question

Category: CSAA – Design Cost-Optimized Architectures

A solutions architect is managing an application that runs on a Windows EC2 instance with an attached Amazon FSx for Windows File Server. To save cost, management has decided to stop the instance during off-hours and restart it only when needed. It has been observed that the application takes several minutes to become fully operational which impacts productivity.

How can the solutions architect speed up the instance’s loading time without driving the cost up?

- Disable the Instance Metadata Service to reduce the things that need to be loaded at startup.
- Migrate the application to a Linux-based EC2 instance.
- `Migrate the application to an EC2 instance with hibernation enabled.`
- Enable the hibernation mode on the EC2 instance.

Yes — Q21 is testing **EC2 Hibernation**, and there is one subtle wording trap.

## What is the problem?

The company wants to:

* Stop the EC2 instance during off-hours → **save money**
* Start it again when needed
* But the application takes several minutes to become ready
* They want to make startup faster **without increasing cost**

Normally:

```text
Stop EC2
   ↓
Memory is lost
   ↓
Start EC2
   ↓
OS boots
   ↓
Application starts
   ↓
Application becomes ready
```

With **hibernation**:

```text
Hibernate EC2
      ↓
RAM contents saved to EBS
      ↓
Instance stopped
      ↓
No normal EC2 compute charge
      ↓
Resume
      ↓
RAM restored
      ↓
Application continues where it left off
```

So startup/resume can be much faster.

### Why is the answer worded strangely?

The correct answer given is:

> **Migrate the application to an EC2 instance with hibernation enabled.**

The other option says:

> **Enable hibernation mode on the EC2 instance.**

That one is considered incorrect because **you generally need to launch the EC2 instance with hibernation enabled**; you don't simply turn hibernation on for an already-running instance afterward.

So for the exam, remember:

> **Hibernation must be configured when launching the instance.**

---

## 💰 Why is this cost-effective?

This is the beautiful part.

During hibernation, the instance is effectively stopped from a compute-billing perspective.

You still pay for things such as:

* EBS storage
* Elastic IP, if applicable

But you don't keep paying normal running-instance compute charges.

So:

**Normal stop:**

```text
RAM ❌
Application state ❌
Resume → boot everything again
```

**Hibernate:**

```text
RAM → EBS ✅
Application state preserved ✅
Resume → continue from previous state
```

---

# Hibernation vs Stop

This is very important for SAA:

|                                      | Stop        | Hibernate     |
| ------------------------------------ | ----------- | ------------- |
| EC2 compute charges                  | ❌           | ❌             |
| EBS charges                          | ✅           | ✅             |
| RAM preserved                        | ❌           | ✅             |
| Application state preserved          | ❌           | ✅             |
| Faster resume                        | Normal boot | ⭐ Faster      |
| Useful for long startup applications | Less useful | ⭐ Very useful |

### Easy memory trick

> **Stop = shut down**

> **Hibernate = freeze the running state and resume later**

---

## When should you think "Hibernate"?

Look for wording such as:

> "Application takes a long time to start."

> "Need to save costs by stopping the instance."

> "Need to resume quickly."

> "Preserve in-memory state."

→ **EC2 Hibernation** ⭐

And one more important distinction:

**Stop + start** → application starts from scratch.

**Hibernate + resume** → memory/state is restored.

So Q21 is essentially:

**"We want the cost savings of stopping but the faster recovery of preserving memory."**

→ **EC2 Hibernation** ✅
