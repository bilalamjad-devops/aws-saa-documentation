15. Question

Category: CSAA – Design Cost-Optimized Architectures

A start-up company that offers an intuitive financial data analytics service has consulted about its AWS architecture. The company has a fleet of Amazon EC2 worker instances that process financial data and then output reports used by its clients. The reports must be stored in a durable storage. The number of files to be stored can grow over time as the start-up company is expanding rapidly overseas, and thus, it also needs a way to distribute the reports faster to clients located across the globe. Although Amazon S3 One Zone-IA saves storage cost, it does not support global distribution.

Which of the following is a cost-efficient and scalable storage option for this scenario?

- Use S3 Glacier as the data storage and Amazon ElastiCache as the CDN.
- `Use S3 as the data storage and Amazon CloudFront as the CDN.`
- Use multiple EC2 instance stores for data storage and Amazon ElastiCache as the CDN.
- Use Amazon Redshift as the data storage and Amazon CloudFront as the CDN.


Exactly. This question is mainly testing whether you can distinguish **durable storage** from **caching/CDN**.

## What is the question asking?

There are three requirements:

1. EC2 workers generate reports.
2. Reports must be stored **durably**.
3. Clients are distributed **globally**, so reports should be delivered quickly around the world.

The architecture should therefore be:

```text
EC2 Workers
    ↓
   S3
 Durable storage
    ↓
CloudFront
 Global distribution
    ↓
Clients worldwide
```

### ✅ Answer: **S3 + CloudFront**

---

## Why S3?

S3 is ideal for storing these reports because it is:

* Highly durable
* Highly scalable
* Object storage
* Designed to store huge numbers of files
* Doesn't require you to manage servers

The question says:

> "The number of files can grow over time."

That's a big S3 clue.

You don't need to worry about provisioning more storage capacity.

---

## Why CloudFront?

CloudFront is a **CDN — Content Delivery Network**.

Think:

```text
              S3
               │
          CloudFront
        ┌──────┼──────┐
        ↓      ↓      ↓
      USA    Europe   Asia
      Edge   Edge     Edge
```

A client in Europe can receive a cached report from a nearby CloudFront edge location instead of repeatedly going all the way back to the S3 origin.

### Result:

**Lower latency + faster global delivery + less load on S3/origin.**

---

# Don't confuse CloudFront and ElastiCache

This is an important SAA distinction.

### CloudFront

**CDN for content delivery to users globally.**

```text
User → CloudFront → S3
```

Common use:

* Images
* Videos
* CSS/JS
* PDFs
* Static files
* Reports
* APIs

---

### ElastiCache

**In-memory cache for applications/databases.**

```text
Application
     ↓
ElastiCache
     ↓
Database
```

Common use:

* Redis
* Memcached
* Frequently queried application data
* Database query caching
* Session data

So:

> **Global users + faster static content delivery → CloudFront**

not ElastiCache.

---

# Why the other answers fail

### ❌ Glacier + ElastiCache

Glacier is designed for **archival storage**, not normal client-facing report delivery.

And ElastiCache isn't a CDN.

---

### ❌ EC2 Instance Store + ElastiCache

Instance Store is **ephemeral**.

If the underlying EC2 instance is stopped/terminated or suffers certain failures, instance-store data can be lost.

The question explicitly requires:

> **Durable storage**

So this is immediately wrong.

---

### ❌ Redshift + CloudFront

CloudFront is fine for distribution, but Redshift is a **data warehouse**, not general-purpose durable file storage.

Reports/files → **S3**

Analytics/data warehouse → **Redshift**

---

# 🧠 Exam pattern to memorize

When you see:

> **Store files + scalable + durable**

Think:

### **S3**

When you see:

> **Global users + low latency + distribute static content**

Think:

### **CloudFront**

Put them together:

> **S3 + CloudFront = durable global content delivery** ✅

And remember:

> **S3 stores the content; CloudFront delivers/caches the content globally.**
